# Part 4 챕터 연결과 실행 기록

Ch 13 → Ch 14 → Ch 15 → Ch 16 순서로 학습합니다. 각 절은 새 커널에서 시작하며 앞 절의 변수를 사용하지 않습니다. 앞에서 만든 자료가 필요하면 준비 셀에서 파일을 읽습니다. 묶음의 폴더 구조를 유지한 상태에서 해당 챕터의 환경을 준비합니다.

## Ch 12의 검색 흐름을 Ch 13으로 옮기기

Ch 12의 `labs/part3/ch12-retrieval-tuning/data/advanced-documents.json`과 `advanced-queries.json`은 제공 문서와 질문을 담고 있습니다. 실제 검색 결과·답변을 기록한 파일은 같은 챕터의 `runs/advanced-continuity-integrated-result.json`입니다. 질문 ID만 보고 내용을 추정하지 말고 파일에 함께 저장한 질문과 정답 문서 ID를 확인합니다.

Ch 13의 마지막 절은 임베딩 검색·BM25·RRF 병합·리랭킹·답변 생성의 입출력을 그래프 노드에 대응시킵니다. 노드가 상태에서 어떤 값을 읽고 어떤 값을 반환하는지 비교합니다. 그래프 그림은 선언한 연결을 보여 주며, 실제 실행 순서는 실행 기록으로 따로 확인합니다. 파일에서 읽은 이전 답변과 이번에 모델을 호출해 받은 답변을 구분합니다.

## Ch 14에서 패턴을 비교하기

Ch 14는 `labs/part4/ch14-rag-patterns/data/documents.json`과 `queries.json`을 사용합니다. 이 작은 학습용 자료에서 질문을 재작성하거나 여러 질문으로 검색하는 방법을 비교합니다. 해당 실험의 문서 수와 질문 수를 함께 확인합니다. Ch 12의 전체 실험과 표본이 다르면 점수만 나란히 놓고 개선 여부를 판단할 수 없습니다.

검색 후보에 정답 문서가 들어 있는지와 생성한 답변의 내용이 맞는지는 별도로 확인합니다. 원 질문·정답·문서·모델을 유지하고 패턴을 바꾸어 비교합니다. 가상 문서나 요약은 검색을 돕는 중간 자료이며, 최종 답변의 출처는 실제 원문으로 확인합니다. 비교를 다시 실행하면 모델이 만든 검색 질문과 시간·토큰 사용량이 달라질 수 있습니다.

## Ch 15에서 실제 실패를 평가하기

`labs/part3/ch12-retrieval-tuning/runs/advanced-continuity-experiment-log.jsonl`의 36행은 TF-IDF와 MMR의 검색 설정을 비교한 기록입니다. 한 행은 한 설정의 평가 결과이며, 36개의 생성 답변을 뜻하지 않습니다. 각 행 안의 질문별 검색 결과와 정답 문서 ID를 읽어 어떤 질문에서 근거를 놓쳤는지 확인합니다.

`labs/part4/ch15-evaluation-advanced/data/evaluation-cases.json`은 답변 평가에 사용하는 제공 자료입니다. 생성 시점·모델·질문·전달 문서·답변을 확인하고, 파일을 읽는 셀을 새 모델 호출로 오해하지 않습니다. 답변과 정답을 비교하는 정답 일치도(Correctness)에는 정답 답변이 필요합니다. 답변의 주장을 문서가 뒷받침하는지 보는 근거 충실도(Groundedness)는 실제로 모델에 전달한 문서를 사용합니다.

교재가 제시한 기준 라벨은 계산 방법을 익히기 위한 것입니다. 실제 사람이 여러 답변을 검토해 수집한 라벨과 구분합니다. 운영할 평가자는 사람이 검토한 자료로 일치율을 다시 측정합니다. Batch 실습에서는 요청 파일의 형식과 식별자를 확인하고, 로컬에서 준비한 파일과 실제 제출·완료된 Batch 결과를 구분합니다. 실제로 제출했다면 제공자가 표시한 처리 상태도 확인합니다.

## Ch 16의 제한을 중간 프로젝트에 적용하기

Ch 16에서는 질문과 출처 검사, 개인정보 가리기, 대화 기록 자르기와 요약, 호출 한도와 비용 상한, 다시 부르기와 감사 기록, 문서 속 지시 끼워 넣기 검사를 파이썬 함수로 작성합니다. 함수를 처음 배우는 절은 노트북 셀에 직접 적고, 뒤 절은 같은 함수를 실습 폴더의 도구 파일 `notebooks/guardrails.py`에서 가져옵니다. 실습 폴더의 테스트도 이 파일을 확인합니다. 프로젝트에 옮겨 쓸 때는 자신의 입력 형식·예산·오류 처리 조건에 맞게 값을 고치고 다시 확인합니다.

출처 표시를 허용 목록과 대조해도 문장 전체가 원문과 맞는지까지 확인되는 것은 아닙니다. 말 목록으로 특정 공격 문구를 찾아도 다른 표현의 공격까지 모두 찾은 결과는 아닙니다. 예상 비용의 누적값은 실제 청구액과 구분하고, 모델 제공자가 내놓은 사용량과 단가를 따로 확인합니다.

중간 프로젝트에서는 파이프라인 전체를 자신의 평가 질문 50문항으로 실행합니다. 검색 지표와 생성 지표를 나누고, 대화 한 건에 포함된 모든 모델 호출을 합쳐 비용을 계산합니다. 작은 예제의 성공·실패 횟수와 비용 분포를 프로젝트 전체의 결과로 대신하지 않습니다. 이후 Ch 21에서는 코드로 정한 흐름과 모델이 선택하는 흐름을 비교하고, Ch 22에서는 직접 만든 제한을 Middleware로 구성합니다.
