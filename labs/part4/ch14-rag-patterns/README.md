# Ch 14 RAG 패턴 확장 실습

Python 3.12와 uv를 사용합니다. 각 노트북은 빈 커널에서 독립 실행됩니다. 프로젝트 루트 `.env`의 `OPENAI_API_KEY`가 필요하며 키 값은 출력하지 않습니다.

```bash
uv sync --locked --project labs/part4/ch14-rag-patterns
```

앞 절과 Ch11·Ch12에서 배운 함수는 `notebooks/rag_tools.py`에 모아 두었고, 각 노트북은 준비 셀에서 `from rag_tools import …` 한 줄로 가져옵니다(벡터 계산은 NumPy 2.5.3).

실습은 Ch12의 교육용 문서 12건과 질문 8건을 그대로 복제해 사용합니다. 원본은 `labs/part3/ch12-retrieval-tuning/data/core-*.json`입니다. Ch11에서 쓴 정답 문서 ID로 순위 목록에서 정답 문서가 몇째 자리인지 셉니다. 이 축소 표본은 패턴의 중간 결과를 읽기 위한 자료이며 실제 서비스 품질을 대표하지 않습니다.

모든 생성 호출은 `gpt-5.4-mini`, 임베딩은 `text-embedding-3-small` 256차원을 사용합니다. 열 노트북을 한 번씩 실행하면 서비스 요청이 모두 102번입니다(임베딩 69번과 답 모델 33번, 절별 8·11·9·7·7·12·9·7·22·10). 예상 비용은 미화 0.10달러 미만이고 절마다 0.01달러 아래입니다. 각 절은 변형 질문 수와 다시 검색할 수 있는 횟수를 코드에 값으로 적어 둡니다. 실행 시간은 네트워크와 API 상태에 따라 달라집니다.

06절은 CRAG 논문의 학습된 검색 평가기와 웹 검색을 재현하지 않고, 첫 자리 거리를 기준값과 견주어 한 번만 보정 검색하는 흐름을 적습니다. 07절은 reflection token을 학습한 Self-RAG 모델을 재현하지 않고, 답을 만든 뒤 근거 점수를 확인하는 교육용 흐름입니다. 08절은 갈래 이름이 이미 적힌 작은 자료에서 갈래마다 요약을 한 단계만 만듭니다. RAPTOR 논문처럼 문서를 되풀이해 묶고 여러 층을 쌓는 구현이 아닙니다.

10절은 이 챕터의 실습 절입니다. 01절 질문 재작성과 06절 보정 검색과 01절 답 만들기를 한 흐름으로 잇고, 후속 질문 하나만 바꿔 두 번 실행합니다. 앞 아홉 절에서 쓴 이름과 문법만 쓰고 새 파일은 만들지 않습니다. 이 노트북 한 번에 드는 서비스 요청은 열 번이고 답 모델 다섯 번과 임베딩 다섯 번입니다. 실습 30분 분량이며 챕터 시수에는 더하지 않습니다.
