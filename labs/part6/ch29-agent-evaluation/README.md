# Ch 29 Agent 평가 실습

노트북 다섯 개(`notebooks/01~05-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 다만 다섯 노트북 모두 앞에서 배운 함수를 같은 폴더의 도구 파일 `notebooks/eval_tools.py`에서 가져오므로, 노트북은 `notebooks/` 폴더에서 엽니다.

## 준비

실습 폴더(`labs/part6/ch29-agent-evaluation`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다. 노트북 파일만 다른 폴더로 옮기거나 다른 폴더에서 커널을 시작하면, 도구 파일을 가져오는 셀이 `ModuleNotFoundError`로 멈춥니다.

노트북의 첫 코드 셀은 그 절에서 쓰는 패키지를 설치하고 판 번호를 출력합니다. 모두 실습 폴더 잠금(`uv.lock`)과 같은 판입니다.

- 01·02절은 `agentevals` 0.0.9와 `langchain` 1.4.0을 설치합니다.
- 03·05절은 그 둘에 모델을 부르는 `langchain-openai` 1.6.0과 키를 읽는 `python-dotenv` 1.2.3을 더합니다.
- 04절은 `langchain` 1.4.0 하나를 설치합니다. 도구 파일이 메시지 클래스를 가져올 때 쓰는 패키지입니다.

## 모델 요청과 API 키

01·02·04절은 모델을 부르지 않아 API 키 없이 실행합니다. 03·05절은 과정 표준 모델(`gpt-5.4-mini`, temperature 0)에 요청을 보내므로 키가 있어야 합니다. 노트북을 처음부터 끝까지 한 번 실행하면, 모델 요청 수는 아래와 같습니다.

- 01·02절은 0번입니다. 궤적은 모두 코드로 적은 메시지 목록이고, 판정은 라이브러리의 궤적 맞춰 보기가 규칙대로 냅니다.
- 03절은 5번입니다. 2~3절은 모델을 부르지 않고, 4절에서 평가받는 에이전트가 3번, 5~6절에서 평가 모델이 2번 요청합니다.
- 04절은 0번입니다. 앞 챕터가 남긴 기록 두 개를 읽기만 합니다(아래).
- 05절은 5번입니다. 실습 절이고, 실행 1에서 3번, 실행 2에서 2번 요청합니다. 평가 모델은 부르지 않습니다.

과정 요금표(2026-09-17)로 어림한 예상 비용은 03절 약 0.003달러, 05절 0.002달러 아래입니다. 예상 비용은 요금표로 셈한 값이고, 청구 금액이 아닙니다. 모델이 쓰는 검색어와 답 글, 평가 모델의 판정 까닭, 토큰 수는 실행마다 달라질 수 있습니다. 에이전트에는 호출 한도를 붙여, 요청이 끝없이 늘지 않게 막습니다. 걸린 시간은 재지 않았습니다.

API 키는 `.env` 파일의 `OPENAI_API_KEY`에서만 읽습니다. 노트북은 커널이 시작한 폴더에서 위로 올라가며 처음 찾은 `.env` 파일을 읽습니다. 그래서 키는 프로젝트 맨 위(학생 묶음이면 `part6-practice/`)의 `.env`에 적어 둡니다. 노트북은 키가 있는지만 확인하고, 키 값은 출력하거나 파일에 저장하지 않습니다.

- `labs/part6/ch21-create-agent/data/rag-comparison.json` — Ch 21 06절이 쓴 비교 기록 파일입니다.

04절의 파일 위치 셀은 프로젝트 맨 위·실습 폴더 맨 위·`notebooks/` 폴더 세 자리에서 두 파일을 찾습니다. Ch 18 06절이나 Ch 21 06절을 다시 실행하면 두 파일이 바뀌어, 04절의 표와 평균도 따라 바뀝니다. 교재 출력과 같은 값을 보려면 두 절은 다시 실행하지 않습니다.

## 도구 파일 `notebooks/eval_tools.py`

앞에서 배운 함수는 `eval_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 01~05절 노트북이 `from eval_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다.

함수 열한 개마다 어느 절에서 배웠는지 바로 위 주석에 적었습니다. 함수를 처음 가르치는 절은 노트북 안에 함수를 적고 설명하며, 다음 절부터 이 파일에서 가져옵니다. 함수는 노트북에서 만든 이름을 바로 읽지 않고, 필요한 값을 모두 인자로 받습니다. 이 파일은 패키지 `langchain`의 메시지 클래스와 표준 라이브러리 `math`를 가져오므로, 이 파일을 가져오는 절의 첫 셀은 `langchain`을 설치합니다.

- `tool_call_names` — Ch 19 04절에서 배웠습니다. 응답 하나의 도구 호출 요청 이름을 목록으로 내놓습니다. 01·03·05절이 가져옵니다.
- `show_messages` — Ch 19 06절에서 배웠습니다. 메시지 목록을 한 줄에 하나씩 출력합니다. 01·03·05절이 가져옵니다.
- `make_trajectory` — 이 챕터 01절에서 배웠습니다. 질문·도구 요청 목록·결과 글·답 글로 궤적(메시지 목록)을 만듭니다. 02·03·05절이 가져옵니다.
- `called_tool_names` — 이 챕터 01절에서 배웠습니다. 궤적에서 도구 이름만 차례대로 모읍니다. 02·03·05절이 가져옵니다.
- `trajectory_pass` — 이 챕터 01절에서 배웠습니다. 평가 함수의 결과에서 칸 `score`만 꺼냅니다. 02·03절이 가져옵니다.
- `four_modes` — 이 챕터 02절에서 배웠습니다. 한 궤적을 네 모드의 평가 함수로 견줘 모드마다 점수를 모읍니다. 03·05절이 가져옵니다.
- `sum_usage` — Ch 19 05절에서 배웠습니다. 목록 안의 응답마다 요청 하나로 세고 토큰을 더합니다. 03·05절이 가져옵니다.
- `estimate_cost` — Ch 6 06절에서 배웠습니다. 사용량과 요금으로 예상 비용을 셉니다. 03절이 가져옵니다.
- `average` — Ch 15 06절에서 배웠습니다. 값 목록의 평균을 냅니다. 04절이 가져옵니다.
- `nearest_rank` — Ch 15 06절에서 배웠습니다. 가장 가까운 자리 방식으로 백분위수 하나를 냅니다. 04절이 가져옵니다.
- `show_row` — 이 챕터 04절에서 배웠습니다. 공통 칸 딕셔너리 한 줄을 표 한 줄로 출력합니다. 05절이 가져옵니다.

앞 챕터 도구 파일(Ch 21 `runner_tools.py`)은 이 실습 폴더에 없는 패키지를 가져와서, 파일째 가져오지 않고 이 챕터 노트북이 쓰는 함수만 옮겼습니다.

## 절마다 하는 일

- 01절은 질문 하나와 기준 궤적 하나를 코드로 적고, 최종 답 평가·한 단계 평가·궤적 평가로 궤적 넷을 견줍니다. 평가마다 거짓을 낸 궤적이 다른 것을 보고, 답 글 하나만 바꿔 다시 견줍니다.
- 02절은 궤적 맞춰 보기의 모드 넷(`strict`·`unordered`·`subset`·`superset`)으로 궤적 다섯을 견줍니다. 짝짓기가 요청 횟수까지 세는 것을 보고, 인자 비교 방식과 도구별 덮어쓰기를 바꿔 봅니다.
- 03절은 평가 모델이 궤적을 어떤 글로 받는지 모델 없이 보고, 도구 둘을 붙인 에이전트를 실제 모델로 한 번 실행합니다. 그 궤적을 네 모드와 평가 모델로 함께 판정하고, 답 글 하나만 바꿔 두 판정을 견줍니다.
- 04절은 앞 챕터 기록 두 개를 같은 칸 이름의 딕셔너리로 옮겨 담고, 요청 수와 성공 여부를 셉니다. 칸마다 평균과 95 백분위수를 보고, 백분위 하나만 바꿔 봅니다.
- 05절은 챕터 끝 실습 절입니다(아래).

## 05절 실습 — 호출 한도를 줄인 실행을 궤적과 운영 지표로 견주기

노트북 `notebooks/05-Agent-평가-실습.ipynb`는 챕터 끝 실습 절입니다. 30분 안팎의 분량이고, 따로 내는 과제와 새 API는 없습니다. 03절의 평가받는 에이전트, 02절의 네 모드와 도구별 덮어쓰기, 04절의 공통 칸을 도서관 규정 질문 하나에 모읍니다.

호출 한도를 4로 둔 실행 1과 2로 줄인 실행 2를 한 번씩 하고, 모델 요청은 모두 5번입니다. 두 궤적을 네 모드로 판정하고, 두 실행을 공통 칸 두 줄로 모아 요청 수 셈과 끝 메시지로 견줍니다. 도구 파일에서 함수 일곱(`called_tool_names`·`four_modes`·`make_trajectory`·`show_messages`·`show_row`·`sum_usage`·`tool_call_names`)을 가져옵니다. 답 글과 토큰 수는 실행마다 달라질 수 있습니다. 쓰는 파일은 없습니다.
