# Ch 28 MCP 실습

노트북 여섯 개(`notebooks/01~06-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 다만 03~06절 노트북은 앞에서 배운 함수를 같은 폴더의 도구 파일 `notebooks/connect_tools.py`에서 가져오므로, 노트북은 `notebooks/` 폴더에서 엽니다.

## 준비

실습 폴더(`labs/part6/ch28-mcp`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다. 노트북 파일만 다른 폴더로 옮기거나 다른 폴더에서 커널을 시작하면, 도구 파일을 가져오는 셀이 `ModuleNotFoundError`로 멈춥니다.

노트북의 첫 코드 셀은 그 절에서 쓰는 패키지를 설치하고 판 번호를 출력합니다. 모두 실습 폴더 잠금(`uv.lock`)과 같은 판입니다.

- 01·02절은 `fastmcp` 4.0.3과 `mcp` 2.2.0을 설치합니다.
- 03절은 그 둘에 `httpx` 0.28.1·`psutil` 7.2.2·`langchain-core` 1.6.2를 더합니다. `langchain-core`는 도구 파일이 가져오는 패키지입니다.
- 04절은 `langchain[mcp]` 1.4.0·`langchain-core` 1.6.2·`langchain-openai` 1.6.0·`langgraph` 1.2.11·`fastmcp` 4.0.3·`mcp` 2.2.0·`psutil` 7.2.2·`python-dotenv` 1.2.3을 설치합니다.
- 05·06절은 04절 목록에서 `langgraph`와 `psutil`을 뺀 여섯을 설치합니다.

## 모델 요청과 API 키

01~03절은 모델을 부르지 않아 API 키 없이 실행합니다. 04~06절은 과정 표준 모델(`gpt-5.4-mini`, temperature 0)에 요청을 보내므로 키가 있어야 합니다. 노트북을 처음부터 끝까지 한 번 실행하면, 모델 요청 수는 아래와 같습니다.

- 01·02·03절은 0번입니다. 출력은 모두 서버와 클라이언트가 주고받은 값입니다.
- 04절은 2번입니다. 2~4절은 모델을 부르지 않고, 5절에서 에이전트가 MCP 도구를 한 번 부르고 답합니다.
- 05절은 5번입니다. 2~4절은 모델을 부르지 않고, 5절에서 조건 다섯에 첫 요청을 한 번씩 보냅니다. 도구는 알리기만 하고 부르지 않습니다.
- 06절은 4번입니다. 실습 절이고, 두 실행에서 2번씩 요청합니다.

01절은 Part 6 학생 묶음을 풀어 키 없이 새 커널로 실행해 보는 묶음 실행 검사의 대상입니다. 그래서 01절은 키와 모델, 도구 파일, 자식 프로세스 없이 같은 커널 안의 메모리 연결로만 서버에 붙습니다.

과정 요금표(2026-09-17)로 어림한 예상 비용은 04절 0.001달러 아래, 05절과 06절은 절마다 0.002달러 아래입니다. 예상 비용은 요금표로 셈한 값이고, 청구 금액이 아닙니다. 모델이 쓰는 도구 인자와 답 글, 출력 토큰은 실행마다 달라질 수 있습니다. 에이전트를 실행하는 04·06절은 호출 한도 3을 붙여, 요청이 끝없이 늘지 않게 막습니다. 걸린 시간은 재지 않았습니다.

API 키는 `.env` 파일의 `OPENAI_API_KEY`에서만 읽습니다. 노트북은 커널이 시작한 폴더에서 위로 올라가며 처음 찾은 `.env` 파일을 읽습니다. 그래서 키는 프로젝트 맨 위(학생 묶음이면 `part6-practice/`)의 `.env`에 적어 둡니다. 노트북은 키가 있는지만 확인하고, 키 값은 출력하거나 파일에 저장하지 않습니다.

## 서버 파일 셋

실습 폴더 맨 위에 MCP 서버 파일 셋이 있습니다. 노트북은 서버 파일을 고치지 않고, 파일 위치 셀이 `notebooks/` 폴더에서 `../course_server.py`를 찾아 씁니다.

- `course_server.py` — 교육센터 자료실 규정을 알려 주는 서버입니다. 도구 `lookup_policy`, 자료 `policy://handbook`, 메시지 틀 `explain_policy`를 하나씩 붙였습니다. 01·02·05·06절은 이 파일을 커널 안에서 읽어 메모리 연결로 붙고, 03·04·05절은 자식 프로세스로 띄워 stdio로 붙습니다.
- `env_server.py` — 03절의 환경 확인 서버입니다. 서버 프로세스의 환경 변수를 알려 주는 연습용 도구 둘이 있습니다. 실제 서버에는 이런 도구를 두지 않습니다.
- `auth_server.py` — 03절의 권한 연습 서버입니다. 교재용 가짜 접근 토큰 둘로 부르는 쪽을 확인하고, 쓰기 도구는 범위 `admin`이 있는 접근 토큰에게만 보입니다. 개발·시험용 인증 도구를 써서, 실제 서비스에는 쓰지 않습니다.

## 자식 프로세스와 포트

노트북이 띄운 서버는 그 절이 끝나기 전에 모두 끝냅니다. stdio 설정은 칸 `keep_alive`를 `False`로 두어 연결을 닫을 때 서버도 끝나고, 03절의 HTTP 서버는 마지막 셀에서 끕니다. stdio 서버에는 FastMCP의 시작 안내·새 판 확인을 끄고 기록 수준을 올리는 설정 이름 셋만 적어 넘기고, 노트북 환경을 통째로 넘기지 않습니다.

03절은 권한 연습 서버를 이 컴퓨터 안의 주소 `127.0.0.1`에 HTTP 서버로 띄웁니다. 포트는 셀에 적어 둔 58028이고, 띄우기 전에 그 포트가 비었는지 봅니다. 다른 프로그램이 그 포트를 쓰고 있으면 셀이 멈추니, 셀의 포트 번호를 바꿔 그 셀부터 다시 실행합니다. 04·05절은 도구를 부를 때마다 서버가 떴다가 끝나고, 06절은 메모리 연결이라 자식 프로세스를 띄우지 않습니다. 노트북이 쓰는 파일은 없습니다. 교재 출력은 Linux의 Python 3.12.13으로 만들었고, 다른 판과 Windows·macOS에서는 실행하지 않았습니다.

## 도구 파일 `notebooks/connect_tools.py`

앞에서 배운 함수는 `connect_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 03~06절 노트북이 `from connect_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다. 01·02절은 이 파일을 가져오지 않습니다.

함수 일곱 개마다 어느 절에서 배웠는지 바로 위 주석에 적었습니다. 함수를 처음 가르치는 절은 노트북 안에 함수를 적고 설명하며, 다음 절부터 이 파일에서 가져옵니다. 함수는 노트북에서 만든 이름을 바로 읽지 않고, 필요한 값을 모두 인자로 받습니다. 이 파일은 패키지 `fastmcp`와 `langchain-core`를 가져오므로, 이 파일을 가져오는 절의 첫 셀은 두 패키지를 설치합니다. 서버 파일은 이 파일을 가져오지 않습니다.

- `names_of` — 이 챕터 01절 노트북 4절에서 배웠습니다. 목록의 항목마다 이름을 모읍니다. 03~06절이 가져옵니다.
- `call_tool_row` — 이 챕터 02절 노트북 2절에서 배웠습니다. 도구 하나를 부르고, 결과나 오류를 딕셔너리로 담습니다. 03절이 가져옵니다.
- `stdio_config` — 이 챕터 03절 노트북 2절에서 배웠습니다. 서버 파일 하나를 stdio로 띄우는 설정 한 벌을 만듭니다. 04·05절이 가져옵니다.
- `tool_call_names` — Ch 19 04절에서 배웠습니다. 응답 하나의 도구 호출 요청 이름을 목록으로 내놓습니다. 04~06절이 가져옵니다.
- `sum_usage` — Ch 19 05절에서 배웠습니다. 목록 안의 응답마다 요청 하나로 세고 토큰을 더합니다. 04·06절이 가져옵니다.
- `estimate_cost` — Ch 6 06절에서 배웠습니다. 사용량과 요금으로 예상 비용을 셉니다. 04~06절이 가져옵니다.
- `spec_length` — Ch 19 03절에서 배웠습니다. 모델에게 보낼 도구 명세의 글자 수를 셉니다. 05·06절이 가져옵니다.

앞 챕터 도구 파일(Ch 21 `runner_tools.py`)은 이 실습 폴더에 없는 패키지를 가져와서, 파일째 가져오지 않고 이 챕터 노트북이 쓰는 함수만 옮겼습니다.

## 절마다 하는 일

- 01절은 서버 파일을 커널 안에서 읽어 메모리 연결로 붙고, 판 번호와 기능 목록, 도구·자료·메시지 틀을 봅니다. 인자 `mode`만 다른 두 연결(현재 판 2026-07-28과 옛 판 2025-11-25)을 견주고, 빈 서버의 기능 목록도 봅니다.
- 02절은 노트북에서 만든 서버 객체에 데코레이터 줄로 도구를 붙입니다. 매개변수 힌트와 독스트링이 없는 도구(Before)와 있는 도구(After)에 같은 값을 넣어, 입력 검사가 몸통 전에 거절하는지 봅니다.
- 03절은 서버 파일을 자식 프로세스로 띄워 stdio로 붙습니다. 노트북 환경을 통째로 넘긴 서버(Before)와 필요한 이름만 넘긴 서버(After)를 교재용 가짜 이름으로 견주고, HTTP 서버에서 접근 토큰과 범위로 도구가 갈리는 것을 봅니다.
- 04절은 클래스 `MCPAdapter`로 MCP 도구를 LangChain 도구로 바꾸고, `ainvoke`로 부르며 서버가 떴다가 끝나는지 봅니다. 도구 실행 노드에 손으로 만든 요청을 넣고, 에이전트를 실제 모델로 한 번 실행합니다.
- 05절은 도구 정의가 모델에게 보낼 도구 명세가 되는 모양과 글자 수를 모델 없이 봅니다. 그다음 조건 다섯의 첫 요청 입력 토큰을 셉니다.

## 06절 실습 — 에이전트에 붙이는 MCP 도구를 하나에서 셋으로 늘리기

노트북 `notebooks/06-MCP-실습.ipynb`는 챕터 끝 실습 절입니다. 30분 안팎의 분량이고, 따로 내는 과제와 새 API는 없습니다. 02절 서버에 도구 붙이기, 04절 에이전트 연결, 05절 명세 글자 수와 입력 토큰 세기를 자료실 규정에 답하는 에이전트 하나에 모읍니다. 서버 파일 `course_server.py`는 커널 안에서 읽기만 하고, 도구 둘은 커널 안의 서버 객체에만 붙입니다.

에이전트에 붙이는 도구 수를 1로 둔 실행 1과 3으로 바꾼 실행 2를 한 번씩 하고, 모델 요청은 모두 4번입니다. 도구 파일에서 함수 다섯(`estimate_cost`·`names_of`·`spec_length`·`sum_usage`·`tool_call_names`)을 가져옵니다. 답 글과 출력 토큰, 예상 비용은 실행마다 달라질 수 있습니다.
