# Ch 21 create_agent 실습

노트북 일곱 개(`notebooks/01~07-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 다만 앞에서 배운 함수는 같은 폴더의 도구 파일 `notebooks/runner_tools.py`에서 가져오므로, 노트북은 `notebooks/` 폴더에서 엽니다.

## 준비

실습 폴더(`labs/part6/ch21-create-agent`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다. 노트북 파일만 다른 폴더로 옮기거나 다른 폴더에서 커널을 시작하면, 도구 파일을 가져오는 셀이 `ModuleNotFoundError`로 멈춥니다.

노트북 일곱 개 모두 API 키가 필요합니다. 04절은 모델 요청을 보내지 않지만, 모델 객체를 만들 때 키를 읽으므로 키가 있어야 합니다. 노트북은 커널이 시작한 폴더에서 위로 올라가며 처음 찾은 `.env` 파일의 `OPENAI_API_KEY`를 읽습니다. 프로젝트 맨 위(학생 묶음이면 `part6-practice/`) `.env`에 적어 두면 됩니다. 노트북은 키가 있는지만 확인하고, 키 값은 출력하거나 파일에 저장하지 않습니다.

노트북의 첫 코드 셀은 그 절에서 쓰는 패키지를 설치하고 판 번호를 출력합니다. 판은 `langchain` 1.4.0 · `langchain-core` 1.6.2 · `langchain-openai` 1.6.0 · `langgraph` 1.2.11 · `numpy` 2.5.3 · `python-dotenv` 1.2.3이고, 02·04·07절은 `pydantic` 2.13.5를, 04절은 `langgraph-prebuilt` 1.1.0을 더 설치합니다. 모두 실습 폴더 잠금(`uv.lock`)과 같은 판입니다. 도구 파일이 NumPy를 가져오므로 일곱 절 모두 `numpy`를 설치합니다.

## 모델 설정

모든 절은 `init_chat_model("openai:gpt-5.4-mini", temperature=0, reasoning_effort="none")`로 만든 모델 객체를 함수 `create_agent`에 넘깁니다. 05·06절은 임베딩 모델 `text-embedding-3-small`(벡터 크기 256)도 부릅니다. temperature 값을 0으로 두어도 모델이 도구를 부를지, 어떤 검색어를 쓸지, 답 글이 매번 같다고 보장하지는 않습니다.

## 도구 파일 `notebooks/runner_tools.py`

앞에서 배운 함수는 `notebooks/runner_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 노트북이 `from runner_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다.

## 절마다 하는 일

- 01절은 Ch 20에서 손으로 이은 모델·도구 반복 그래프를 함수 `create_agent` 한 줄로 만들고, 노드·조건 함수·메시지 칸을 Ch 20 그래프와 견줍니다.
- 02절은 인자 `response_format`에 도구 전략(`ToolStrategy`)과 제공자 전략(`ProviderStrategy`)을 붙여, 양식 값이 칸 `structured_response`에 담기는 자리와 메시지 수를 견줍니다.
- 03절은 라이브러리 상태 형식 `AgentState`에 칸 하나를 더하고, 실행 정보(`context`)를 도구에 넘겨 결과에 남는 값과 남지 않는 값을 봅니다.
- 04절은 옛 함수 `create_react_agent`와 `create_agent`로 같은 재료의 그래프를 만들어, 옮길 때 바뀌는 인자 이름과 그래프 모양을 출력으로 봅니다. 그래프를 만들기만 하고 실행하지 않습니다.
- 05절은 Ch 14 검색 함수를 검색 도구로 감싸 에이전트에 넘기고, 모델이 적은 검색어와 검색 횟수를 셉니다.
- 06절은 같은 평가 질문 셋을 고정 흐름과 에이전트 흐름으로 보내, 모델 요청 수·입력 토큰·정답 문서 자리·근거 충실도를 견주고 비교 기록 파일을 씁니다.

## 읽고 쓰는 파일

01~04절과 07절은 노트북 안 규정 딕셔너리만 읽고, 파일을 읽거나 쓰지 않습니다.

05·06절은 Ch 14 실습 폴더의 `labs/part4/ch14-rag-patterns/data/documents.json`(문서 열두 건)과 `queries.json`(질문 여덟 건)을 읽기만 합니다. 노트북은 먼저 프로젝트 맨 위 폴더를 찾고, 그 아래의 Ch 14 폴더에서 두 파일을 엽니다. 학생 묶음에는 두 파일이 같은 자리에 들어 있습니다. 문서 벡터는 노트북에서 한 번 만들고 파일로 쓰지 않습니다.

**06절은 이 실습 폴더의 `data/rag-comparison.json`을 씁니다.** 이 파일은 Ch 29 04절이 읽는 파일입니다. Ch 29 04절은 줄이 셋인지와 줄마다 도구 호출 수가 1 이상인지를 확인하고, 모델 요청 수·토큰·걸린 초 칸을 읽어 평균을 냅니다. 06절을 다시 실행하면 이 파일을 덮어쓰고, 토큰과 걸린 초가 달라져 Ch 29 04절 출력도 따라 바뀝니다. 모델이 한 질문에서 검색을 건너뛰면 06절 10절 셀이 파일을 쓰기 전에 멈춥니다. 그때는 셀을 다시 실행하기 전에 강사와 확인합니다.
