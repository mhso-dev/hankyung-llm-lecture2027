# Ch 26 위임 구조 실습

노트북 다섯 개(`notebooks/01~05-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 다만 다섯 노트북 모두 앞에서 배운 함수를 같은 폴더의 도구 파일 `notebooks/delegation_tools.py`에서 가져오므로, 노트북은 `notebooks/` 폴더에서 엽니다.

## 준비

실습 폴더(`labs/part6/ch26-delegation`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다. 노트북 파일만 다른 폴더로 옮기거나 다른 폴더에서 커널을 시작하면, 도구 파일을 가져오는 셀이 `ModuleNotFoundError`로 멈춥니다.

노트북의 첫 코드 셀은 그 절에서 쓰는 패키지를 설치하고 판 번호를 출력합니다. 다섯 절 모두 `langchain` 1.4.0·`langchain-openai` 1.6.0·`langgraph` 1.2.11·`python-dotenv` 1.2.3을 설치합니다. 03·04절은 `pydantic` 2.13.5도 함께 설치합니다. 모두 실습 폴더 잠금(`uv.lock`)과 같은 판입니다.

## 모델 요청과 API 키

다섯 절 모두 실제 OpenAI 모델 `gpt-5.4-mini`를 temperature 0으로 부릅니다. 노트북을 처음부터 끝까지 한 번 실행하면, 모델 요청 수는 아래와 같습니다.

- 01절은 6번입니다. 중앙 에이전트가 한 번 맡기는 실행을 두 번 하고, 실행마다 3번씩 요청합니다.
- 02절은 3번입니다. 2~5절은 모델을 부르지 않아 요청이 0번이고, API 키가 없어도 실행됩니다. 6~7절에서 3번 요청합니다.
- 03절은 3번입니다. 2~4절은 모델을 부르지 않아 요청이 0번이고, API 키가 없어도 실행됩니다. 5~6절에서 3번 요청합니다.
- 04절은 11번입니다. 4절 핸드오프 칸은 서비스가 거절한 요청의 오류를 받아 출력합니다. 거절된 요청 1번은 11번에 넣지 않았습니다.
- 05절은 5번입니다. 실습 절이고, 두 실행에서 3번과 2번 요청합니다.

과정 요금표(2026-09-17)로 어림한 예상 비용은 01절 0.003달러 아래, 02절 0.002달러 아래, 03절 0.001달러 아래입니다. 04절은 0.005달러 아래, 05절은 0.002달러 아래입니다. 예상 비용은 요금표로 셈한 값이고, 청구 금액이 아닙니다.

모델이 맡기는 모양·넘기는 수·고르는 분야와 답 글, 토큰 수는 실행마다 달라질 수 있습니다. 모델이 맡기는 모양이 달라지면 요청 수도 달라질 수 있습니다. 걸린 시간은 재지 않았습니다.

API 키는 `.env` 파일의 `OPENAI_API_KEY`에서만 읽습니다. 노트북은 커널이 시작한 폴더에서 위로 올라가며 처음 찾은 `.env` 파일을 읽습니다. 그래서 키는 프로젝트 맨 위(학생 묶음이면 `part6-practice/`)의 `.env`에 적어 둡니다. 노트북은 키가 있는지만 확인하고, 키 값은 출력하거나 파일에 저장하지 않습니다.

다섯 노트북 모두 파일을 읽거나 쓰지 않습니다. 02~04절의 체크포인트는 프로그램 메모리에만 둡니다. 교재 출력은 Linux의 Python 3.12.13으로 만들었고, 다른 판과 Windows·macOS에서는 실행하지 않았습니다.

## 도구 파일 `notebooks/delegation_tools.py`

앞에서 배운 함수는 `delegation_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 노트북이 `from delegation_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다.

함수 열 개마다 어느 절에서 배웠는지 바로 위 주석에 적었습니다. 함수를 처음 가르치는 절은 노트북 안에 함수를 적고 설명하며, 다음 절부터 이 파일에서 가져옵니다. 함수는 노트북에서 만든 이름을 바로 읽지 않고, 필요한 값을 모두 인자로 받습니다. 파일이 가져오는 이름은 `langgraph.types`의 `Send` 하나이고, 함수 `send_to_desks`가 씁니다.

- `tool_call_names` — Ch 19 04절에서 배웠습니다. 응답 하나의 도구 요청 이름을 목록으로 내놓습니다. 01절이 가져오고, `show_messages` 안에서도 씁니다.
- `show_messages` — Ch 19 06절에서 배웠습니다. 메시지 목록을 한 줄씩 출력합니다. 01·02절이 가져옵니다.
- `sum_usage` — Ch 19 05절에서 배웠습니다. 목록 안의 응답마다 요청 하나로 세고 토큰을 더합니다. 01~04절이 가져옵니다.
- `estimate_cost` — Ch 6 06절에서 배웠습니다. 사용량과 요금으로 예상 비용을 셉니다. 01·04·05절이 가져옵니다.
- `message_kinds` — 이 챕터 01절 노트북 4절에서 배웠습니다. 메시지 목록의 종류 이름을 차례로 모읍니다. 04·05절이 가져옵니다.
- `usage_with_specialists` — 이 챕터 01절 노트북 5절에서 배웠습니다. 중앙 에이전트가 이번 실행에 더한 메시지와 전문 에이전트의 목록을 함께 세어, 요청 수와 토큰을 더합니다. 04·05절이 가져옵니다.
- `writer_names` — 이 챕터 02절 노트북 7절에서 배웠습니다. 응답마다 그 응답을 쓴 에이전트 이름을 모읍니다. 04절이 가져옵니다.
- `send_to_desks` — 이 챕터 03절 노트북 2절에서 배웠습니다. 분야 칸의 이름마다 `Send`를 하나씩 만듭니다. 04절이 가져옵니다.
- `answered_desks` — 이 챕터 04절 노트북 3절에서 배웠습니다. 전문 에이전트의 마지막 응답을 보고, 답한 분야 이름을 모읍니다. 05절이 가져옵니다.
- `is_complete` — 이 챕터 04절 노트북 8절에서 배웠습니다. 필요한 분야가 모두 모였고 마지막 답도 있는지 보는 완료 조건입니다. 05절이 가져옵니다.

앞 챕터 도구 파일과는 따로 둔, 이 챕터만의 파일입니다. 앞 챕터 도구 파일은 이 실습 폴더에 없는 패키지를 가져오거나 그 챕터 폴더에 묶여 있어, 파일째 가져오지 않고 이 챕터 노트북이 쓰는 함수만 옮겼습니다.

## 절마다 하는 일

- 01절은 전문 에이전트를 도구 함수 안에서 부르게 감싸, 중앙 에이전트가 일을 맡기게 합니다. 중앙 에이전트의 목록과 전문 에이전트의 목록을 나란히 보고, 두 목록의 요청을 함께 셉니다.
- 02절은 노드와 도구가 `Command`로 다음 차례의 담당을 넘기는 그래프를 만듭니다. 앞 절반은 모델 없이 담당 칸과 체크포인터를 보고, 뒤 절반은 모델이 넘기기 도구를 부르는 두 차례 대화를 봅니다.
- 03절은 문의를 분류해 고른 분야 노드로 `Send`를 보내고, 답을 한 칸에 모읍니다. 앞 절반은 글자 규칙으로 분류하고, 뒤 절반은 모델이 분야를 고릅니다.
- 04절은 같은 문의를 세 구조에 보내 모델 요청 수를 셈으로 견줍니다. 실행 한도·호출 한도로 멈춘 실행을 만들고, 완료 조건 함수로 일이 끝났는지 봅니다.

## 05절 실습 — 요청 수 셈으로 호출 한도를 정하고 완료 조건으로 확인하기

노트북 `notebooks/05-위임-구조-실습.ipynb`는 챕터 끝 실습 절입니다. 30분 안팎의 분량이고, 따로 내는 과제와 새 API는 없습니다. 01절 요청 수 셈, 04절 호출 한도, 04절 완료 조건을 자료실 문의 창구 흐름 하나에 모읍니다. 모델 요청은 모두 다섯 번입니다.
