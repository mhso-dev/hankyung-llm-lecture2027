# Ch 27 DeepAgents 실습

노트북 아홉 개(`notebooks/01~09-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 다만 02~09절 노트북은 앞에서 배운 함수를 같은 폴더의 도구 파일 `notebooks/harness_tools.py`에서 가져오므로, 노트북은 `notebooks/` 폴더에서 엽니다.

## 준비

실습 폴더(`labs/part6/ch27-deepagents`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다. 노트북 파일만 다른 폴더로 옮기거나 다른 폴더에서 커널을 시작하면, 도구 파일을 가져오는 셀이 `ModuleNotFoundError`로 멈춥니다.

노트북의 첫 코드 셀은 그 절에서 쓰는 패키지를 설치하고 판 번호를 출력합니다. 아홉 절 모두 `deepagents` 0.7.0·`langchain` 1.4.0·`langchain-openai` 1.6.0·`python-dotenv` 1.2.3을 설치합니다. 02·03절을 뺀 일곱 절은 `langgraph` 1.2.11도 함께 설치합니다. 모두 실습 폴더 잠금(`uv.lock`)과 같은 판입니다.

## 모델 요청과 API 키

아홉 절 모두 과정 표준 모델 객체(`gpt-5.4-mini`, temperature 0)를 만듭니다. 모델 객체를 만들려면 API 키가 있어야 해서, 모델에게 요청을 보내지 않는 01절도 키가 필요합니다. 노트북을 처음부터 끝까지 한 번 실행하면, 모델 요청 수는 아래와 같습니다.

- 01절은 0번입니다. 에이전트를 조립해 노드와 도구 이름만 보고, 모델에게 요청을 보내지 않습니다.
- 02절은 2번입니다. 2~5절은 모델을 부르지 않고, 6절 실행에서 모델이 우리 도구를 한 번 부르고 답합니다.
- 03절은 교재 출력에서 7번입니다. 할 일 목록 없이 실행한 5절이 2번, 할 일 목록을 켠 6절이 5번 요청했습니다. 6절은 할 일 목록을 고쳐 적는 횟수에 따라 4번이 되기도 합니다.
- 04절은 3번입니다. 앞 절반은 모델을 부르지 않고, 5절 실행이 3번 요청합니다.
- 05절은 3번입니다. 앞 절반은 모델을 부르지 않고, 6절 실행이 3번 요청합니다.
- 06절은 5번입니다. 바깥 에이전트 2번과, 일을 맡은 서브에이전트 3번을 더한 수입니다.
- 07절은 3번입니다. 5절에서 조사 에이전트를 한 번 실행합니다.
- 08절은 교재 출력에서 4번입니다. 6절 실행이 승인 자리에서 한 번 멈췄다가 이어 갑니다. 이어 간 뒤 모델이 방금 적은 파일을 다시 읽으면 5번이 됩니다.
- 09절은 4번입니다. 실습 절이고, 두 실행에서 2번씩 요청합니다.

과정 요금표(2026-09-17)로 어림한 예상 비용은 02절 0.004달러 아래, 03절 두 실행을 합쳐 0.02달러 아래입니다. 04~09절은 절마다 0.01달러 아래입니다. 예상 비용은 요금표로 셈한 값이고, 청구 금액이 아닙니다.

모델이 고르는 도구와 적는 글, 답 글, 토큰 수는 실행마다 달라질 수 있습니다. 모델이 도구를 더 요청하면 요청 수도 달라집니다. 모델을 부르는 절은 바깥 에이전트와 서브에이전트 명세에 호출 한도를 함께 주어, 요청이 끝없이 늘지 않게 막습니다. 걸린 시간은 재지 않았습니다.

API 키는 `.env` 파일의 `OPENAI_API_KEY`에서만 읽습니다. 노트북은 커널이 시작한 폴더에서 위로 올라가며 처음 찾은 `.env` 파일을 읽습니다. 그래서 키는 프로젝트 맨 위(학생 묶음이면 `part6-practice/`)의 `.env`에 적어 둡니다. 노트북은 키가 있는지만 확인하고, 키 값은 출력하거나 파일에 저장하지 않습니다.

## 파일을 쓰는 곳

디스크에 파일을 쓰는 절은 04절 하나입니다. 실행할 때마다 새로 만드는 임시 폴더에만 쓰고, 실습 폴더에는 쓰지 않습니다. 노트북은 그 임시 폴더를 지우지 않습니다.

나머지 절에서 에이전트가 만든 파일은 에이전트 상태의 칸 `files`에만 있고, 디스크에는 남지 않습니다. 08·09절은 멈춘 자리를 메모리에 두는 체크포인터 `InMemorySaver`에 저장하므로, 커널을 끄면 사라집니다. 교재 출력은 Linux의 Python 3.12.13으로 만들었고, 다른 판과 Windows·macOS에서는 실행하지 않았습니다.

## 도구 파일 `notebooks/harness_tools.py`

앞에서 배운 함수는 `harness_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 02~09절 노트북이 `from harness_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다. 01절은 앞에서 배운 함수를 쓰지 않아, 이 파일을 가져오지 않습니다.

함수 아홉 개마다 어느 절에서 배웠는지 바로 위 주석에 적었습니다. 함수를 처음 가르치는 절은 노트북 안에 함수를 적고 설명하며, 다음 절부터 이 파일에서 가져옵니다. 함수는 노트북에서 만든 이름을 바로 읽지 않고, 필요한 값을 모두 인자로 받습니다. 이 파일은 다른 패키지를 가져오지 않습니다.

- `tool_call_names` — Ch 19 04절에서 배웠습니다. 응답 하나의 도구 요청 이름을 목록으로 내놓습니다. 02~05절이 가져오고, `show_messages` 안에서도 씁니다.
- `show_messages` — Ch 19 06절에서 배웠습니다. 메시지 목록을 한 줄씩 출력합니다. 02·03·04·06·07·08·09절이 가져옵니다.
- `sum_usage` — Ch 19 05절에서 배웠습니다. 목록 안의 응답마다 요청 하나로 세고 토큰을 더합니다. 02~09절이 가져옵니다.
- `estimate_cost` — Ch 6 06절에서 배웠습니다. 사용량과 요금으로 예상 비용을 셉니다. 02~09절이 가져옵니다.
- `tool_names` — 이 챕터 01절 노트북 3절에서 배웠습니다. 에이전트 그래프의 도구 실행 노드에 등록된 도구 이름을 알파벳 차례로 모읍니다. 02~09절이 가져옵니다.
- `names_only_in` — 이 챕터 01절 노트북 3절에서 배웠습니다. 둘째 목록에만 있는 이름을 모읍니다. 02·03절이 가져옵니다.
- `find_source_marks` — Ch 16 01절에서 배웠습니다. 답 글에서 대괄호로 묶은 출처 표시를 모읍니다. 07절이 가져오고, `check_citations` 안에서도 씁니다.
- `check_citations` — 이 챕터 07절 노트북 4절에서 배웠습니다. 출처 표시마다 인용한 파일이 주어진 파일 목록에 있는지 판정합니다. 08절이 가져옵니다.
- `call_args` — 이 챕터 07절 노트북 5절에서 배웠습니다. 이름이 같은 도구 요청마다 인자 하나의 값을 차례로 모읍니다. 08·09절이 가져옵니다.

앞 챕터 도구 파일과는 따로 둔, 이 챕터만의 파일입니다. 앞 챕터 도구 파일은 이 실습 폴더에 없는 패키지를 가져오거나 그 챕터 폴더에 묶여 있어, 파일째 가져오지 않고 이 챕터 노트북이 쓰는 함수만 옮겼습니다.

## 절마다 하는 일

- 01절은 `create_agent`와 `create_deep_agent`로 만든 그래프의 노드와 도구를 견주고, 인자를 하나씩 바꿔 무엇이 더해지는지 봅니다. general-purpose 서브에이전트에 호출 한도를 넣은 명세를 만들고, 모델 없이 한도를 확인합니다.
- 02절은 자료실 규정 도구를 더한 Deep Agent를 만듭니다. 앞 절반은 모델 없이 백엔드와 모델이 받는 도구 목록을 보고, 뒤 절반은 실제 모델이 도구를 고르는 실행의 요청 수를 두 방법으로 셉니다.
- 03절은 할 일 목록 미들웨어가 요청에 더하는 도구·할 일 설명 글·상태 칸을 봅니다. 할 일 목록 없이 한 번, 켜고 한 번 실행해 두 요청을 견줍니다.
- 04절은 디스크에 쓰는 백엔드와 상태 칸에 두는 백엔드를 견주고, 모델이 중간 결과를 파일에 적는 실행을 봅니다.
- 05절은 아주 긴 도구 결과를 파일로 옮기고 짧은 안내 글만 남기는 옮겨 두기를 모델 없이 봅니다. 뒤 절반은 모델이 옮겨 둔 파일에서 필요한 줄을 다시 찾는 실행입니다.
- 06절은 조회 도구를 가진 서브에이전트 명세를 만들어 바깥 에이전트가 일을 맡기게 하고, 바깥과 서브에이전트의 요청을 기록 훅으로 나눠 셉니다.
- 07절은 교재가 정한 자료 셋을 상태 칸에 넣고, 모델이 파일 도구로 찾아 답하게 합니다. 답에 붙인 출처가 실제로 있는 자료를 가리키는지는 코드로 판정하고, 웹 검색은 하지 않습니다.
- 08절은 권한 규칙과 사람 승인을 붙인 보고 에이전트를 만듭니다. 승인 자리에서 멈췄다가 결정 목록으로 이어 가는 흐름과 운영 한계를 봅니다.
- 09절은 챕터 끝 실습 절입니다(아래).

## 09절 실습 — 메모 파일 쓰기에 사람 승인을 켜고 끄기

노트북 `notebooks/09-DeepAgents-실습.ipynb`는 챕터 끝 실습 절입니다. 30분 안팎의 분량이고, 따로 내는 과제와 새 API는 없습니다. 04절 파일 도구, 08절 사람 승인, 02절부터 쓴 요청 수 셈을 자료실 안내 도우미 하나에 모읍니다. 도우미는 사용자가 보낸 공지 글을 이용자용 한 문장으로 다듬어 메모 파일에 적습니다.

사람 승인 설정을 `{"write_file": True}`로 켠 실행 1과 `{}`로 끈 실행 2를 한 번씩 하고, 모델 요청은 모두 4번입니다. 도구 파일에서 함수 다섯(`call_args`·`estimate_cost`·`show_messages`·`sum_usage`·`tool_names`)을 가져옵니다. 메모 파일은 상태 칸에만 생기고, 메모 글과 답 글, 토큰 수는 실행마다 달라질 수 있습니다.
