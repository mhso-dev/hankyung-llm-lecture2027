# Ch 23 Persistence와 Durable Execution 실습

노트북 일곱 개(`notebooks/01~07-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 다만 04절과 06절에서 배운 함수는 같은 폴더의 도구 파일 `notebooks/checkpoint_tools.py`에서 가져오므로, 노트북은 `notebooks/` 폴더에서 엽니다.

## 준비

실습 폴더(`labs/part6/ch23-persistence`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다. 노트북 파일만 다른 폴더로 옮기거나 다른 폴더에서 커널을 시작하면, 06·07절의 도구 파일 가져오기 셀이 `ModuleNotFoundError`로 멈춥니다.

일곱 노트북 모두 모델을 부르지 않습니다. 모델 요청은 0번이고, API 키가 없어도 실행됩니다. 이 챕터는 상태를 저장하고 이어 가는 일이 주제라, 매번 같은 값을 내는 우리 노드로 그래프를 만들어 저장된 값이 맞는지 출력으로 가립니다. 03절과 07절의 대화·처리 글도 모델이 쓴 글이 아니라 노드 함수가 만든 글입니다.

노트북의 첫 코드 셀은 그 절에서 쓰는 패키지를 설치하고 판 번호를 출력합니다. 모든 절이 `langgraph` 1.2.11을 설치합니다. 01절은 `langgraph-checkpoint` 4.2.0을, 02절은 `langgraph-checkpoint-postgres` 3.0.5와 `psycopg[binary,pool]` 3.3.3을, 03~07절은 `langgraph-checkpoint-sqlite` 3.0.3을 더 설치합니다. 03절은 메시지 클래스를 쓰려고 `langchain-core` 1.6.2도 설치합니다. 모두 실습 폴더 잠금(`uv.lock`)과 같은 판입니다.

## 파일은 임시 폴더에만 씁니다

모든 노트북은 준비 셀에서 운영체제 임시 폴더 안에 빈 폴더를 새로 만들고, 그 폴더로 작업 위치를 옮깁니다. 03~07절의 SQLite 파일·신호 파일·기록 파일은 모두 이 임시 폴더에 생기고, 실습 폴더에는 파일을 남기지 않습니다. 01절은 메모리 체크포인터라 파일을 쓰지 않고, 02절은 데이터베이스 서버의 표에 씁니다. 노트북 전체를 처음 값으로 다시 보려면 1절 임시 폴더 셀부터 다시 실행합니다.

## 02절 PostgreSQL 서버

02절은 PostgreSQL 서버가 `127.0.0.1:55432`에서 켜져 있어야 합니다. Ch 12 02절에서 만든 Docker 컨테이너 `hankyung-part3-pgvector`를 그대로 쓰고, 접속 글도 Ch 12와 같은 `postgresql://student:local-practice-only@127.0.0.1:55432/rag_lab`입니다. 이 암호는 로컬 수업 전용이며 다른 환경에 쓰지 않습니다.

컨테이너가 꺼져 있으면 `docker start hankyung-part3-pgvector`로 켭니다. 컨테이너가 없으면 Ch 12와 같은 아래 명령으로 먼저 만듭니다. 이 명령은 02절 노트북 첫 셀에도 있습니다.

```bash
docker run --name hankyung-part3-pgvector \
  -e POSTGRES_USER=student \
  -e POSTGRES_PASSWORD=local-practice-only \
  -e POSTGRES_DB=rag_lab \
  -p 127.0.0.1:55432:5432 \
  -d pgvector/pgvector:0.8.2-pg17
```

노트북은 데이터베이스 `rag_lab` 안에 이름 공간 `ch23_lab`을 만들어 체크포인터의 표를 둡니다. 다시 실행하면 그 이름 공간만 지우고 처음부터 만들며, Ch 12 표는 건드리지 않습니다. 이 이름 공간에는 다른 표를 두지 않습니다. 실습 뒤에는 `docker stop hankyung-part3-pgvector`로 컨테이너를 멈춥니다. 교재 출력은 Docker 컨테이너가 아니라 같은 접속 글로 켠 PostgreSQL 17.11 서버에서 만들었고, 판 번호 줄은 서버에 따라 다르게 나올 수 있습니다.

## 도구 파일 `notebooks/checkpoint_tools.py`

앞에서 배운 함수는 `notebooks/checkpoint_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 노트북이 `from checkpoint_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다.

함수 열 개마다 어느 절에서 배웠는지 바로 위 주석에 적었습니다. 함수를 처음 가르치는 절(04절·06절)은 노트북 안에 함수를 적고 설명하며, 다음 절부터 이 파일에서 가져옵니다. 함수는 노트북에서 만든 이름을 바로 읽지 않고, 필요한 값을 모두 인자로 받습니다.

- `start_worker` — 04절 노트북 3절에서 배웠습니다. 스크립트를 자식 프로세스로 띄웁니다. 06절이 가져옵니다.
- `wait_for_signal` — 04절 노트북 3절에서 배웠습니다. 신호 파일이 생길 때까지 기다립니다. `kill_at_second`가 안에서 부릅니다.
- `stop_worker` — 04절 노트북 3절에서 배웠습니다. 자식 프로세스를 강제로 끝내고 종료 코드를 내놓습니다. `kill_at_second`가 안에서 부릅니다.
- `read_saved` — 04절 노트북 3절에서 배웠습니다. 새 연결로 SQLite 파일을 열어 칸 값·다음 노드·체크포인트 수를 읽습니다. 06·07절이 가져옵니다.
- `read_record` — 04절 노트북 3절에서 배웠습니다. 기록 파일의 줄을 목록으로 내놓습니다. 06·07절이 가져옵니다.
- `new_prefix` — 04절 노트북 3절에서 배웠습니다. 작업 폴더에서 아직 쓰지 않은 파일 앞머리(이름 뒤에 번호)를 고릅니다. 06·07절이 가져옵니다.
- `kill_at_second` — 04절 노트북 6절에서 배웠습니다. 스크립트를 띄워 둘째 노드에서 끊고, 파일에 남은 것을 읽습니다. 06절이 가져옵니다.
- `append_key`·`append_key_once` — 06절 노트북 2절에서 배웠습니다. 기록 파일에 키 한 줄을 적고, 뒤 함수는 이미 적힌 키면 건너뜁니다. 07절이 가져옵니다.
- `kill_then_resume` — 06절 노트북 6절에서 배웠습니다. 끊은 뒤 새 자식 프로세스로 다시 실행하고, 기록 파일의 키 목록을 내놓습니다. 지금은 이 함수를 가져오는 절이 없습니다.

## 자식 프로세스 스크립트 둘

04절과 06절은 실습 폴더 맨 위의 스크립트를 자식 프로세스로 실행합니다. 노트북은 준비 셀에서 스크립트 자리를 찾은 뒤 임시 폴더로 옮기고, 파일 이름은 모두 그 임시 폴더 안의 이름으로 넘깁니다. 두 스크립트 모두 명령줄에서 글 다섯을 받습니다. SQLite 파일 이름·신호 파일 이름·기록 파일 이름·넷째 글·단계(`first-run` 또는 `resume`)입니다.

- `durability_worker.py`(04절) — 노드 `first` → `second` 두 개짜리 그래프를, 넷째 글로 받은 저장 시점(`exit`·`async`·`sync`)으로 실행합니다. 둘째 노드는 신호 파일을 만든 뒤, 첫 실행 단계에서 30초를 쉽니다.
- `idempotency_worker.py`(06절) — 노드 `receive_order` → `charge` 그래프를 저장 시점 `sync`로 실행합니다. 넷째 글은 쓰기 방식(`naive`·`idempotent`)이고, `charge`는 결제 기록 파일에 주문 키 `order-2306`을 적은 뒤 신호 파일을 만들고 쉽니다. 실제 결제 서비스는 부르지 않습니다.

다시 실행 단계(`resume`)는 저장된 다음 노드가 있으면 새 입력 없이 그 체크포인트부터 이어 가고, 없으면 처음 입력으로 다시 시작합니다. 04·06절 노트북은 신호가 온 그 셀에서 바로 끊습니다. 끊는 셀마다 함수 `new_prefix`로 새 파일 이름을 골라, 셀을 다시 실행해도 같은 결과가 나옵니다.

**Windows에서는 강제 종료와 종료 코드가 다를 수 있습니다.** 교재 출력은 Linux에서 만들었고, 강제로 끝낸 프로세스의 종료 코드는 `-9`였습니다. 설치판 Python 소스에서 Windows의 `kill()`은 종료 코드 1로 끝내므로, Windows에서는 1이 찍힐 것입니다. 04절 노트북의 확인 줄은 종료 코드가 0이 아닌지만 봅니다. Windows·macOS에서는 실행하지 않았습니다.

## 절마다 하는 일

- 01절은 메모리 체크포인터(`InMemorySaver`)를 붙인 그래프를 스레드 이름(`thread_id`)으로 나눠 실행하고, `get_state`·`get_state_history`로 저장된 체크포인트를 읽습니다.
- 02절은 PostgreSQL 체크포인터(`PostgresSaver`)를 표 만들기 `setup()` 전과 뒤에 실행해, 받은 오류와 생긴 표 넷을 견줍니다.
- 03절은 SQLite 체크포인터(`SqliteSaver`)로 대화를 파일에 저장하고, 연결을 닫은 뒤 새 연결·새 그래프로 같은 스레드의 대화를 이어 갑니다.
- 04절은 저장 시점(`durability`) 셋을 견주고, 자식 프로세스를 둘째 노드에서 강제로 끝낸 뒤 파일에 남은 것과 다시 실행한 노드를 봅니다.
- 05절은 같은 단계의 두 노드 가운데 하나만 실패 흉내로 멈추게 하고, 남은 쓰기(표 `writes`)와 `invoke(None, config)`로 이어 간 뒤를 봅니다.
- 06절은 결제 기록을 적는 노드를 끊고 다시 실행해, 검사 없이 적는 쪽과 이미 적힌 키를 건너뛰는 쪽(멱등 키)을 견줍니다.

## 07절 실습 — 멈춘 대출 처리를 이어 가고 기록은 한 번만 남기기

`notebooks/07-Persistence-실습.ipynb`는 챕터 끝 실습 절입니다(30분 안팎, 따로 내는 과제 없음, 새 API 없음). 03절 SQLite 체크포인터, 05절 실패 흉내와 `invoke(None, config)`, 06절 멱등 키 확인(`append_key_once`)을 자료실 대출 처리 한 건에 모아, 쓰기 방식 `idempotent`와 `naive`로 두 번 실행합니다. 두 실행에서 바뀌는 것은 쓰기 방식 하나이고, 파일 앞머리는 쓰기 방식 이름을 따라 새로 고릅니다. 모델은 부르지 않고 자식 프로세스도 띄우지 않으며, 도구 파일의 함수 다섯(`append_key`·`append_key_once`·`new_prefix`·`read_record`·`read_saved`)을 가져옵니다. SQLite 파일과 대출 기록 파일은 노트북이 만든 임시 폴더에만 생기고, 걸린 시간은 재지 않습니다.
