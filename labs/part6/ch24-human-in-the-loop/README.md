# Ch 24 Human-in-the-Loop와 Time Travel 실습

노트북 네 개(`notebooks/01~04-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 다만 앞에서 배운 함수는 같은 폴더의 도구 파일 `notebooks/approval_tools.py`에서 가져오므로, 노트북은 `notebooks/` 폴더에서 엽니다.

## 준비

실습 폴더(`labs/part6/ch24-human-in-the-loop`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다. 노트북 파일만 다른 폴더로 옮기거나 다른 폴더에서 커널을 시작하면 도구 파일을 찾지 못합니다. 그러면 01·03·04절의 가져오기 셀이 `ModuleNotFoundError`로 멈춥니다.

네 노트북 모두 모델을 부르지 않습니다. 모델 요청은 0번이고, API 키가 없어도 실행됩니다. 사람의 답은 셀에 적어 넣는 값(`approve`·`reject` 등)이고, 실제 서비스라면 화면에서 사람이 고른 값을 같은 자리에 넣습니다. 01절 노트북은 교재 묶음을 검사할 때 API 키 없이 새 커널로 끝까지 실행해 보는 노트북이기도 합니다.

노트북의 첫 코드 셀은 `langgraph` 1.2.11과 `langgraph-checkpoint` 4.2.0을 설치하고 판 번호를 출력합니다. 두 판 모두 실습 폴더 잠금(`uv.lock`)과 같습니다. 체크포인트는 메모리 체크포인터(`InMemorySaver`)에만 저장합니다.

## 파일은 임시 폴더에만 씁니다

모든 노트북은 준비 셀에서 운영체제 임시 폴더 안에 빈 폴더를 새로 만들고, 그 폴더로 작업 위치를 옮깁니다. 01절의 결제 기록 파일과 04절의 연장 기록 파일은 이 임시 폴더에만 생기고, 실습 폴더에는 파일을 남기지 않습니다. 02·03절은 파일을 쓰지 않고, 마지막 셀에서 임시 폴더가 비어 있는지 봅니다. 노트북 전체를 처음 값으로 다시 보려면 1절 임시 폴더 셀부터 다시 실행합니다.

## 도구 파일 `notebooks/approval_tools.py`

앞에서 배운 함수는 `approval_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 노트북이 `from approval_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다.

함수 다섯 개마다 어느 절에서 배웠는지 바로 위 주석에 적었습니다. 함수를 처음 가르치는 절은 노트북 안에 함수를 적고 설명하며, 다음 절부터 이 파일에서 가져옵니다. 함수는 노트북에서 만든 이름을 바로 읽지 않고, 필요한 값을 모두 인자로 받습니다. 파일이 가져오는 모듈은 `os` 하나입니다.

- `read_record` — Ch 23 04절 노트북 3절에서 배웠습니다. 기록 파일의 줄을 목록으로 내놓습니다. 01·04절이 가져옵니다.
- `append_key` — Ch 23 06절 노트북 2절에서 배웠습니다. 기록 파일 끝에 키 한 줄을 적습니다. 01·04절이 가져옵니다.
- `append_key_once` — Ch 23 06절 노트북 2절에서 배웠습니다. 같은 키가 이미 적혀 있으면 건너뛰고, 없을 때만 한 줄을 적습니다. 01절이 가져옵니다.
- `print_history` — Ch 23 01절 노트북 8절에서 배웠습니다. 체크포인트 목록을 단계 번호·만든 자리·다음 노드·칸 값으로 한 줄씩 출력합니다. 03·04절이 가져옵니다.
- `find_before` — 이 챕터 03절 노트북 4절에서 배웠습니다. 체크포인트 목록을 최신 것부터 보며, 다음 노드에 주어진 노드 이름이 든 첫 체크포인트를 고릅니다. 04절이 가져옵니다.

## 절마다 하는 일

- 01절은 노드 안에서 함수 `interrupt`로 그래프를 멈추고, `Command(resume=…)`에 사람의 답을 넣어 같은 스레드를 이어 갑니다. 결제 기록을 먼저 적고 묻는 노드와, 묻고 나서 승인일 때만 적는 노드를 같은 거절로 견줍니다.
- 02절은 사람의 답을 허용 답 목록으로 검사하고, 목록에 없는 답이면 조건부 엣지로 같은 자리에서 다시 묻습니다. 공식 문서가 권하지 않는 노드 안 `while True` 모양과 부른 횟수를 견줍니다. 체크포인터가 없거나 스레드 이름이 다를 때 받는 오류도 봅니다.
- 03절은 끝난 실행의 체크포인트 목록에서 지난 체크포인트를 고르고, `update_state`로 값을 고쳐 넣어 그 자리부터 다시 실행합니다. 원래 가지와 새 가지가 한 목록에 함께 남는지 봅니다.

## 04절 실습 — 연장 일수를 고쳐 다시 묻고 승인일 때만 기록하기

노트북 `notebooks/04-Human-in-the-Loop-실습.ipynb`는 챕터 끝 실습 절입니다. 30분 안팎의 분량이고, 따로 내는 과제와 새 API는 없습니다. 01절 승인 지점, 02절 다시 묻기, 03절 값 고쳐 넣기와 새 가지를 대출 연장 신청 한 건에 모읍니다. 사람의 답 차례 `change`·`approve`와 `change`·`reject`로 두 번 실행합니다.

두 실행에서 바뀌는 것은 사람의 마지막 답 하나입니다. 도구 파일의 함수 넷(`append_key`·`find_before`·`print_history`·`read_record`)을 가져오고, 연장 기록 파일은 노트북이 만든 임시 폴더에만 생깁니다.
