# Ch 19 모델과 도구 실습

노트북 일곱 개(`notebooks/01~07-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 다만 앞 절에서 배운 함수는 같은 폴더의 도구 파일 `notebooks/order_tools.py`에서 가져오므로, 노트북은 `notebooks/` 폴더에서 엽니다.

## 준비

실습 폴더(`labs/part5/ch19-model-tools`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다. 노트북 파일만 다른 폴더로 옮기거나 다른 폴더에서 커널을 시작하면, 도구 파일을 가져오는 셀이 `ModuleNotFoundError`로 멈춥니다.

01~03절은 모델을 부르지 않아 API 키가 필요 없습니다. 04~07절은 API 키가 필요합니다. 노트북은 커널이 시작한 폴더에서 위로 올라가며 처음 찾은 `.env` 파일의 `OPENAI_API_KEY`를 읽습니다. 프로젝트 맨 위 `.env`에 적어 두면 됩니다. 노트북은 키가 있는지만 확인하고, 키 값은 출력하거나 파일에 저장하지 않습니다.

노트북의 첫 코드 셀은 그 절에서 쓰는 패키지를 설치하고 판 번호를 출력합니다. 판은 `langchain` 1.4.0 · `langchain-core` 1.6.2 · `langchain-openai` 1.6.0 · `pandas` 3.0.5 · `pydantic` 2.12.5 · `python-dotenv` 1.2.3이고, 실습 폴더 잠금과 같습니다.

`data/orders.csv`는 Ch 4 실습 폴더의 `data/orders.csv`와 같은 주문 네 줄입니다. 노트북은 이 파일을 읽기만 하고, 새 파일을 쓰지 않습니다.

## 모델 설정

04~07절은 `init_chat_model("openai:gpt-5.4-mini", temperature=0, reasoning_effort="none")`로 만든 모델 하나에 메서드 `bind_tools`로 도구를 알려 주고 요청을 보냅니다. temperature 값을 0으로 두어도 모델이 고르는 도구와 답 글이 매번 같다고 보장하지는 않습니다.

## 도구 파일 `notebooks/order_tools.py`

앞에서 배운 함수는 `notebooks/order_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 01~07절 노트북이 `from order_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다. Ch 2 07절에서 임시 폴더에 만든 같은 이름의 모듈과는 다른 파일입니다.

함수 열넷마다 어느 절에서 배웠는지 주석으로 적었습니다. Ch 4 01절 `fetch_orders`와 Ch 6 06절 `estimate_cost`가 하나씩이고, 이 챕터에서는 03절 둘, 04절 셋, 05절 셋, 06절 넷입니다. 함수를 처음 가르치는 절은 노트북 안에 함수를 적고 설명하며, 다음 절부터 이 파일에서 가져옵니다. 함수를 도구로 감싸는 `@tool` 줄은 이 파일에 두지 않고 노트북에 둡니다. 이 파일은 `pandas`만 씁니다.

## 절마다 하는 일

- 01절은 Ch 4 함수 `fetch_orders`를 `@tool` 줄로 도구로 감싸고, 도구 이름·설명·입력 형식과 도구 명세를 봅니다.
- 02절은 양식 클래스(`BaseModel`·`Field`·`Literal`)로 도구의 입력 형식을 적어, 정해 둔 값 밖의 인자를 몸통이 실행되기 전에 막습니다.
- 03절은 같은 몸통 함수에 설명만 다른 두 판을 붙이고, 이 절에서 정한 기준 넷과 명세 글자 수로 견줍니다.
- 04절은 공개 이름을 가린 두 판을 `bind_tools`로 모델에게 알려 주고, 질문 셋에서 모델이 고른 도구를 기대 도구와 견줍니다.
- 05절은 한 응답에 담긴 도구 호출 요청을 프로그램이 차례로 실행해 도구 메시지로 모델에게 보내고, 인자 `parallel_tool_calls`를 바꿔 요청 수를 견줍니다.
- 06절은 도구 오류를 도구 메시지에 담고, 사람 확인 전에는 쓰기 도구를 모델에게 알려 줄 목록에서 뺍니다.

## 07절 실습 — 주문 취소 문의를 도구 둘로 처리하기

`notebooks/07-모델과-도구-실습.ipynb`는 챕터 끝 실습 절입니다(30분 안팎, 따로 내는 과제 없음, 새 문법·새 API 없음). 06절 읽기 도구와, 02절 입력 검사(취소 까닭 셋)를 붙인 쓰기 도구를 조립 함수 하나로 이어 주문 취소 문의 하나를 처리합니다. 사람 확인 값 하나만 바꿔 두 번 실행하고, 두 실행의 명세·요청한 도구·결과 상태·요청 수를 견줍니다. 쓰기 도구는 흉내라 `data/orders.csv`를 바꾸지 않습니다. 모델 요청은 노트북 한 번에 4~5번이고, 교재 출력에서는 5번이었습니다.
