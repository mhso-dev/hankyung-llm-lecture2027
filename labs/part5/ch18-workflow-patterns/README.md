# Ch 18 워크플로우 5패턴 실습

노트북 일곱 개(`notebooks/01~07-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 일곱 노트북 모두 OpenAI 파이썬 SDK로 실제 모델 `gpt-5.4-mini`를 부릅니다. LangChain은 쓰지 않습니다.

## 준비

실습 폴더(`labs/part5/ch18-workflow-patterns`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다.

일곱 노트북 모두 API 키가 필요합니다. 프로젝트 맨 위 `.env` 파일에 `OPENAI_API_KEY`를 적어 두면 노트북이 읽습니다. 키 값은 출력하거나 파일에 저장하지 않습니다. 노트북의 첫 코드 셀은 `openai` 2.29.0과 `python-dotenv` 1.2.3을 설치하고 판 번호를 출력합니다. 실습 폴더 잠금과 같은 판입니다.

## 모델 설정

모든 요청은 `client.responses.create`로 보내고, 설정은 일곱 노트북이 같습니다.

- 모델 `gpt-5.4-mini`, `temperature=0`, `reasoning={"effort": "none"}`입니다. temperature 값을 0으로 두어도 모델이 쓴 문장이 매번 같다고 보장하지는 않습니다.
- 답은 JSON 글 하나로 받습니다(`text={"format": {"type": "json_object"}}`). 이 형식은 요청 글에 「JSON」이라는 말이 있어야 해서, 모든 요청 글에 그 말을 적었습니다.
- 클라이언트는 `OpenAI()` 기본값 그대로 씁니다. 설치한 SDK 소스로 보면, 연결 오류나 일부 서비스 오류에서 요청을 두 번까지 다시 보냅니다. 노트북은 이 값을 바꾸지 않고, 요청 수는 받은 응답의 기록 줄 수로 셉니다.

## 도구 파일 `notebooks/workflow_tools.py`

앞에서 배운 함수는 `notebooks/workflow_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 02~07절 노트북이 `from workflow_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다.

함수 서른하나마다 어느 절에서 배웠는지 주석으로 적었습니다(01절 여섯, 02절 둘, 03절 일곱, 04절 여섯, 05절 일곱, 06절 셋). 함수를 처음 가르치는 절은 노트북 안에 함수를 적고 설명하며, 다음 절부터 이 파일에서 가져옵니다. 이 파일은 `asyncio`·`json`·`re`만 씁니다.

## 절마다 하는 일

- 01절은 두 요청 사이에 게이트를 두는 단계 잇기를 만듭니다. 기획이 약속한 칸이 없으면 둘째 요청을 보내지 않고 멈춥니다.
- 02절은 모델이 쓴 문의 종류를 보고 코드가 갈래를 고르는 라우팅을 만듭니다. 허용 목록과 기준값으로 분류를 검사하고, 지나지 못한 문의는 되묻습니다.
- 03절은 서로 기다릴 필요가 없는 요청 셋을 `asyncio.to_thread()`와 `asyncio.gather()`로 함께 보냅니다(나눠 쓰기와 투표).
- 04절은 계획 모델이 작업 목록을 쓰고, 작업마다 요청을 함께 보낸 뒤 결과를 하나로 엮습니다(작업 나눠 맡기기).
- 05절은 쓰는 요청과 평가하는 요청을 번갈아 보내고, 코드가 기준값과 바퀴 한도로 멈춤을 고릅니다(쓰고 평가하기 반복).
- 06절은 01~05절 흐름 다섯을 같은 과제 글로 실행해 요청 수·토큰 수·걸린 초·품질 칸을 한 표로 견줍니다.
- 07절은 챕터 끝 실습 절입니다(아래).

노트북은 자료 파일을 읽지 않고, 새 파일도 쓰지 않습니다. 걸린 초는 03절과 06절에서만 잽니다.
