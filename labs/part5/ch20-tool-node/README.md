# Ch 20 ToolNode 실습

노트북 다섯 개(`notebooks/01~05-*.ipynb`)는 Python 3.12 새 커널에서 절마다 따로 실행할 수 있습니다. 앞 절 노트북의 변수는 쓰지 않습니다. 다만 앞에서 배운 함수는 같은 폴더의 도구 파일 `notebooks/graph_tools.py`에서 가져오므로, 노트북은 `notebooks/` 폴더에서 엽니다.

## 준비

실습 폴더(`labs/part5/ch20-tool-node`)에서 `uv sync --locked`를 실행하고, 이 폴더의 `.venv` 커널을 고릅니다. 그다음 `notebooks/` 폴더의 노트북을 열어 첫 셀부터 차례로 실행합니다. VS Code와 Jupyter는 노트북이 있는 폴더에서 커널을 시작합니다. 노트북 파일만 다른 폴더로 옮기거나 다른 폴더에서 커널을 시작하면, 도구 파일을 가져오는 셀(01·02·04·05절)이 `ModuleNotFoundError`로 멈춥니다.

03절은 모델을 부르지 않아 API 키가 필요 없습니다. 01·02·04·05절은 API 키가 필요합니다. 노트북은 커널이 시작한 폴더에서 위로 올라가며 처음 찾은 `.env` 파일의 `OPENAI_API_KEY`를 읽습니다. 프로젝트 맨 위 `.env`에 적어 두면 됩니다. 노트북은 키가 있는지만 확인하고, 키 값은 출력하거나 파일에 저장하지 않습니다.

노트북의 첫 코드 셀은 그 절에서 쓰는 패키지를 설치하고 판 번호를 출력합니다. 판은 `langgraph` 1.2.11 · `langchain` 1.4.0 · `langchain-core` 1.6.2 · `langchain-openai` 1.6.0 · `python-dotenv` 1.2.3이고, 실습 폴더 잠금과 같습니다. 03절은 앞의 셋만 설치합니다.

규정 자료는 노트북 안의 딕셔너리(주제어 대출·운영·연체)이고, 도구는 이 딕셔너리를 읽기만 합니다. 노트북은 파일을 읽거나 새로 쓰지 않습니다.

## 모델 설정

01·02·04·05절은 `init_chat_model("openai:gpt-5.4-mini", temperature=0, reasoning_effort="none")`로 모델을 만듭니다. 모델 노드는 메서드 `bind_tools`로 도구를 알려 준 모델에 요청을 보내고, 인자 `parallel_tool_calls=False`로 한 응답에 도구 호출 요청을 하나까지만 받습니다. temperature 값을 0으로 두어도 모델이 도구를 부를지와 답 글이 매번 같다고 보장하지는 않습니다.

## 도구 파일 `notebooks/graph_tools.py`

앞에서 배운 함수는 `notebooks/graph_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일이고, 01·02·04·05절 노트북이 `from graph_tools import …` 한 줄로 가져옵니다. 커널이 `notebooks/` 폴더에서 시작해야 이 파일을 가져올 수 있습니다. 03절은 이 파일을 쓰지 않습니다. Ch 19 실습 폴더의 도구 파일 `order_tools.py`와는 다른 파일입니다.

함수 여섯마다 어느 절에서 배웠는지 바로 위 주석에 적었습니다.

- `tool_call_names` — Ch 19 04절에서 배웠습니다. 01·02절이 가져옵니다.
- `show_messages` — Ch 19 06절에서 배웠습니다. 01·02·04·05절이 가져옵니다.
- `sum_usage` — Ch 19 05절에서 배웠습니다. 04·05절이 가져옵니다.
- `estimate_cost` — Ch 6 06절에서 배웠습니다(Ch 19 판). 04·05절이 가져옵니다.
- `call_id_lists` — 이 챕터 01절에서 배웠습니다. 함수 `run_row`가 안에서 부릅니다.
- `run_row` — 이 챕터 01절에서 배웠습니다. 05절이 가져옵니다.

함수를 처음 가르치는 절은 노트북 안에 함수를 적고 설명하며, 다음 절부터 이 파일에서 가져옵니다. 도구를 만드는 `@tool` 줄과 그래프의 노드 함수는 이 파일에 두지 않고 노트북에 둡니다. 이 파일은 다른 패키지를 가져오지 않습니다.

## 절마다 하는 일

- 01절은 모델 노드와 도구 실행 노드(`ToolNode`)를 한 그래프에 넣고, 도구 조건 함수(`tools_condition`)와 되돌아가는 엣지로 잇습니다. 질문 셋으로 실행 흔적과 도구 메시지 수를 셉니다.
- 02절은 손으로 만든 도구 호출 요청으로, 도구 실행 노드의 기본값과 오류 처리 함수를 넘긴 노드(`handle_tool_errors`)를 견줍니다.
- 03절은 모델 없이 도는 그래프로 실행 한도(`recursion_limit`)와 명시적 종료를 보고, 노드 실행 수와 한도의 경계를 출력으로 찾습니다.
- 04절은 질문 낱말로 코드가 고르는 규칙 갈래 그래프와 모델이 고르는 모델 선택 그래프를 같은 질문으로 실행해, 모델 요청 수·입력 토큰·예상 비용을 견줍니다.
- 05절은 챕터 끝 실습 절입니다(아래).

## 05절 실습 — 자료실 문의 그래프에 오류 처리 함수와 실행 한도 붙이기

`notebooks/05-ToolNode-실습.ipynb`는 챕터 끝 실습 절입니다(30분 안팎, 따로 내는 과제 없음, 새 문법·새 API 없음). 01절 그래프에 02절 오류 처리 함수와 03절 설정 딕셔너리(실행 한도)를 붙여 대출 문의 하나를 처리하고, 실행 한도 하나만 노드 실행 수와 같게 줄여 한 번 더 실행합니다. 두 번째 실행은 `GraphRecursionError`로 멈추고, 셀은 그 오류를 받아 출력합니다. 대출은 규정에 있는 주제라 도구 오류가 나지 않아, 붙여 둔 오류 처리 함수는 두 실행 모두에서 쓰이지 않습니다. 모델 요청은 첫 번째 실행이 2번입니다. 두 번째 실행은 결과를 받지 못해 노트북에서는 요청 수를 셀 수 없고, 노트북 밖 다섯 번에서는 2번이었습니다.
