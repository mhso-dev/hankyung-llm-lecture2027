# RAG 실습 문서 세트 (한경 KDT · LLM Agent 개발 & 바이브코딩)

Chapter 9~12(RAG 첫 완주 → 문서 처리 → 평가 기초 → 검색 튜닝)와 중간 프로젝트에서 쓰는 **합성 문서 세트**입니다. 모든 문서는 이 과정을 위해 새로 만든 가상 기관의 자료이며, 실제 기관·인물·제품과 관계가 없습니다. 라이선스 제약 없이 수업·과제·배포에 쓸 수 있습니다.

## 구성

| 폴더·파일 | 내용 |
|---|---|
| `pdf/easy/` E01~E06 | 쉬움 6종 — 단일 단, 문단당 사실 1개, 단순 표 |
| `pdf/medium/` M01~M06 | 중간 6종 — 표 다수, 조문 상호참조, 각주, 신구 대비(시점), 유사 상품 |
| `pdf/hard/` H01~H06 | 어려움 6종 — 2단 레이아웃, 예외의 예외, 회의록, 차트 이미지·병합 셀·가로 페이지, 스캔본, 머리글 오염·부록 우선 |
| `pdf/scanned/` S01~S03 | 스캔 변형본 3종 — 텍스트 레이어 없음(OCR 필수) |

| `manifest.json` | 문서별 메타(기관·장르·쪽수·난이도 사유) |

총 21개 PDF, 약 110쪽. 512토큰 청킹 기준 300~400 청크가 나옵니다(Ch 10 "문서 100건 × 3 청킹 × 2 임베딩" 실습에는 이 세트 + `public_pdfs.md`의 공개 문서를 더해 쓰세요).

## 난이도가 뜻하는 것

**쉬움**은 "청킹만 제대로 하면 top-1에 정답이 온다"는 뜻입니다. **중간**은 표·각주·조문 참조 때문에 청크 하나에 답이 온전히 들어오지 않거나, 시점·조건을 묻지 않으면 답이 둘인 경우입니다. **어려움**은 파서 단계에서 이미 깨지는 형식(2단, 병합 셀, 이미지 속 숫자, 스캔), 대화 구조(회의록), 문서 규칙 자체를 읽어야 하는 경우(부록 우선, 예외의 예외)입니다. `manifest.json`의 `difficulty_reason`에 문서별로 적어 두었습니다.

## 질의셋 사용법

```jsonl
{"qid":"Q037","tier":"medium","doc_id":"M01","question":"R2가 3kg을 싣고 0.7m/s로 50% 주행할 때 연속 동작 시간은?","answer":"4.5시간","type":"table","gold_pages":[3],"anchor":"§4.3 표","answerable":true}
```

`doc_id`가 검색 지표(Recall@k)의 정답이고, `gold_pages`는 정답 토큰 매칭으로 자동 산정한 **힌트**이므로 페이지 단위 지표를 쓰려면 한 번 눈으로 확인하세요. `type`은 실패 원인을 군집화할 때 씁니다.

| type | 수 | 뜻 |
|---|---|---|
| single | 73 | 한 문단·한 셀에 답 |
| table | 13 | 표 셀↔헤더 매핑 필요 |
| reasoning | 10 | 문서 값으로 계산·조건 판단 |
| multi_hop | 7 | 같은 문서의 두 곳을 결합 |
| temporal | 7 | 시점(개정 전후)에 따라 답이 다름 |
| multi_doc | 8 | 두 문서를 함께 봐야 함 (`X01`~) |
| ocr / image | 9 | 스캔본·차트 이미지에만 답이 있음 |
| dialogue | 5 | 회의록 — 누가 말했는지가 답의 일부 |
| precedence / disambiguation / aggregation | 6 | 우선 규칙·유사명 구분·전체 스캔 |
| unanswerable | 10 | 문서에 없음 — "모른다"가 정답 (`N01`~) |

Ch 11에서는 쉬움·중간의 `single`·`table`부터 30개를 골라 시작하고, Ch 12 Day 3(한국어 sparse)에서 `temporal`·`multi_hop`, Day 4(리랭커)에서 `multi_doc`·`disambiguation`을 추가하는 순서를 권합니다. `unanswerable`은 Ch 9 "첫 실패를 일부러 보기"와 Ch 16 가드레일에서 씁니다.

## 다시 만들기

```bash
cd build && uv run --with weasyprint,pypdf,img2pdf,pillow,numpy python easy.py && python medium.py && python hard.py && python finalize.py && python scan.py
```

폰트는 Noto Sans CJK(`/usr/share/fonts/opentype/noto/`)를 씁니다. 내용을 바꾸려면 각 `*.py`의 본문 HTML과 `q(...)` 질의를 함께 고치세요 — 질의의 정답 페이지는 `finalize.py`가 다시 계산합니다.

## 알려진 한계

- 문서 분량이 실제 공공 문서보다 짧습니다(3~7쪽). 긴 문서에서의 context rot 실험은 `public_pdfs.md`의 백서·법령을 쓰세요.
- `gold_pages`는 자동 산정이라 표가 페이지에 걸친 경우 두 페이지가 나올 수 있습니다.
- 스캔본의 OCR 난이도는 중간 정도(기울기 ≤2°, JPEG 40~60)입니다. 더 어렵게 하려면 `scan.py`의 `skew`·`noise`·`quality`를 조정하세요.
