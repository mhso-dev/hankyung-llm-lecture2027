# Part 6 실습 시작하기

이 묶음에는 Ch 21–29의 노트북과 실행에 필요한 공개 자료가 들어 있습니다. HTML 교재는 설명을 읽고 코드를 복사하는 화면입니다. 코드는 Jupyter에서 실행합니다.

## 실행 환경 준비

압축을 풀어 만든 `part6-practice` 폴더의 구조를 유지합니다. 노트북만 다른 위치로 옮기면 제공 자료를 찾지 못할 수 있습니다. 각 챕터의 README에서 추가 준비와 사용하는 파일을 확인합니다.

Ch 1에서 준비한 uv와 Python 3.12를 사용합니다. 학습할 챕터 폴더에서 `uv sync --locked`를 실행하고, VS Code의 Python·Jupyter 확장에서 그 폴더의 `.venv`를 커널로 선택합니다. 예를 들어 Ch 21의 폴더는 `labs/part6/ch21-create-agent`입니다. `uv run python --version`으로 Python 3.12인지 확인합니다. JupyterLab을 사용하면 같은 폴더에서 `uv run --with jupyterlab==4.4.9 jupyter lab`으로 시작할 수 있습니다.

모델 API를 호출하는 실습에서는 묶음 최상위의 `env.example`을 `.env`로 복사합니다. `OPENAI_API_KEY=` 오른쪽에 자신의 키를 넣습니다. 노트북은 현재 폴더와 상위 폴더에서 `.env`를 찾습니다. 키 값은 코드·출력·질문에 붙여 넣지 않습니다. 제공된 묶음에는 실제 키가 들어 있지 않습니다.

## 학습 순서

Ch 21에서 에이전트를 만들고 Ch 22에서 호출 전후의 처리를 추가합니다. Ch 23과 Ch 24에서는 저장·재개·승인을 실습합니다. Ch 25에서 스트리밍을 관찰한 뒤 Ch 26의 위임, Ch 27의 DeepAgents, Ch 28의 MCP로 연결 범위를 넓힙니다. Ch 29에서는 답변과 실행 과정을 평가합니다.

노트북마다 새 커널을 시작하고 준비 셀부터 순서대로 실행합니다. 설치 셀도 실행하고 완료될 때까지 기다립니다. 셀의 출력에서 안내한 값을 확인한 뒤 다음 셀로 이동합니다. 이전 노트북에서 만든 변수가 남아 있다고 가정하지 않습니다. 데이터베이스나 별도 프로세스가 필요한 실습은 해당 챕터의 준비 절차를 먼저 따릅니다.

## 결과 비교와 오류 확인

API 셀을 다시 실행하면 비용이 발생합니다. 각 절의 기본 호출 횟수부터 실행하고, 반복 횟수를 늘리기 전에 비용 안내를 확인합니다. 모델의 답변·도구 선택·처리 시간은 실행마다 달라질 수 있습니다. 교재의 작은 표본에서 관찰한 결과를 자신의 프로젝트 전체에 그대로 적용하지 않습니다.

`NameError`가 나오면 준비 셀을 빠뜨렸는지 확인합니다. `ModuleNotFoundError`는 현재 챕터의 설치 환경과 선택한 커널을 확인합니다. `FileNotFoundError`는 제공된 폴더 구조와 자료 위치를 확인합니다. 키 관련 오류는 `.env`의 위치와 변수 이름을 확인하되 키 값은 출력하지 않습니다. 변수 상태가 불분명하면 새 커널에서 첫 셀부터 다시 실행합니다.

제공된 작은 자료로 확인한 결과와 실제 서비스 운영 결과를 구분합니다. 예를 들어 로컬 프로세스 중단 실험에서 복구한 범위는 모든 데이터베이스 장애의 복구 범위를 뜻하지 않습니다. 한 질문에서 얻은 도구 선택이나 비용 차이는 같은 조건으로 반복 측정한 뒤 판단합니다.

기본 패키지는 각 챕터의 `pyproject.toml`과 `uv.lock`에 고정합니다. 챕터마다 환경을 준비하고 해당 환경의 커널을 선택합니다. 데이터베이스·MCP 서버 등 별도 실행이 필요한 구성은 해당 README의 준비 절차를 따릅니다.
