2이 내용을 배우는 이유
프로그램은 이름, 수량, 가격, 회원 여부처럼 성격이 다른 값을 처리합니다. 주문 수량을 매번 숫자 2로 직접 적으면 그 값이 무엇을 뜻하는지 알기 어렵고, 수량을 바꿀 때 여러 줄을 찾아야 합니다. 값에 quantity라는 이름을 붙이면 읽는 사람은 뜻을 파악할 수 있고 프로그램은 같은 값을 여러 계산에 사용할 수 있습니다. 이 절에서는 값을 저장하고 계산하며, 입력의 자료형이 예상과 다를 때 결과가 어떻게 달라지는지 확인합니다.
3앞에서 배운 내용
Ch 1에서 Python 3.12가 선택된 터미널과 노트북 셀을 준비하고 print()로 출력을 확인했습니다. 이 절의 노트북은 이전 커널의 변수에 의존하지 않습니다. 첫 셀부터 실행하면 상품 이름과 주문 정보가 새로 만들어집니다. 코드 셀 왼쪽의 실행 번호가 1부터 6까지 이어지는지 확인합니다.
4핵심 개념
값에 이름표를 붙입니다
창고 선반의 상자에 “무선 키보드”라고 표시하면 상자를 열지 않아도 내용을 짐작할 수 있습니다. Python의 변수(variable)는 값을 가리키는 이름입니다. product_name = "무선 키보드"에서 product_name은 변수이고 오른쪽 문자열이 값입니다. 등호로 오른쪽 값을 왼쪽 이름에 연결하는 일을 대입(assignment)이라고 합니다. 이 문장은 오른쪽부터 읽어 “문자열을 product_name에 저장합니다”라고 해석합니다. 수학의 등식과 달리 “두 항이 같다”는 판정이 아닙니다.
자료형(type)은 값의 종류와 사용할 수 있는 연산을 정합니다. 정수(int)는 2처럼 소수점이 없는 수, 실수(float)는 39000.0처럼 소수점이 있는 수입니다. 문자열(str)은 "무선 키보드"처럼 글자를 따옴표로 감싼 값입니다. 불리언(bool)은 참과 거짓을 나타내는 True와 False입니다. 문자열 "2"와 정수 2는 화면에 비슷하게 보이지만 가능한 연산이 다릅니다.
함수 호출은 print(...)처럼 함수 이름 뒤에 소괄호를 붙여 기능을 실행하는 표기입니다. 소괄호 안의 값이 함수의 입력이고, 함수가 만든 값이 반환값입니다. type(quantity)는 변수의 값을 입력받아 자료형을 반환합니다. f"상품: {product_name}"의 앞글자 f는 중괄호 안의 변수 값을 문자열에 넣겠다는 뜻입니다. :.0f와 :.0%는 출력 모양만 정하며 저장된 숫자를 바꾸지 않습니다.
도식 읽기
도식 위쪽의 네 상자는 각각 변수 이름, 값, 자료형을 함께 보여 줍니다. 상품명과 회원 여부도 저장하지만, 아래 주문 금액 계산으로 이어지는 화살표는 수량과 단가에서 출발합니다. quantity의 정수 2와 unit_price의 실수 39000.0을 곱하면 78000.0입니다. 출력 형식 :.0f가 소수점 아래를 표시하지 않아 화면에는 78000원으로 나타납니다.

화면 입력이나 CSV 파일에서 읽은 "2"는 숫자 모양이지만 문자열일 수 있습니다. Before 셀에서 문자열 "2"에 3을 곱하면 오류가 발생하지 않고 222가 출력됩니다. 문자열 곱셈은 같은 글자를 지정한 횟수만큼 반복하기 때문입니다. 주문 수량 6을 기대했다면 실행은 끝났어도 계산 결과는 잘못되었습니다.

float는 일부 소수를 이진수로 근사해 저장합니다. 금액을 정확히 정산하는 프로그램은 정수 원 단위나 decimal.Decimal 사용을 검토합니다.

type() 출력은 학습과 진단에 유용합니다. 실제 업무 코드에서는 입력 형식과 변환 규칙을 문서로 정하고 경계에서 확인합니다.

1학습 목표
if·elif·else로 금액 구간에 맞는 한 경로를 실행할 수 있습니다.
for와 while 반복의 종료 조건을 설명할 수 있습니다.
break와 continue가 반복 순서에 미치는 영향을 출력에서 확인할 수 있습니다.
2이 내용을 배우는 이유
주문 금액이 50000원 이상이면 배송비를 받지 않고, 그보다 작으면 배송비를 더해야 합니다. 주문이 세 건이면 같은 판정을 세 번 적용해야 합니다. 모든 경우를 줄마다 복사하면 기준이 바뀔 때 여러 곳을 수정해야 하고 일부 주문을 빠뜨릴 수 있습니다. 조건문은 어떤 문장을 실행할지 고르고, 반복문은 같은 처리 규칙을 여러 값에 적용합니다. 프로그램이 값을 저장하는 단계를 넘어 실제 규칙에 따라 행동하려면 두 흐름을 함께 이해해야 합니다.
3앞에서 배운 내용
앞 절에서 변수에 주문 수량과 금액을 저장하고 숫자 자료형으로 계산했습니다. 이 절에서는 세 주문 금액 [18000, 42000, 65000]과 무료 배송 기준 50000을 새 커널에서 준비합니다. 대괄호로 묶인 여러 값은 다음 절에서 자세히 배울 목록입니다. 지금은 앞에서부터 금액을 하나씩 꺼낼 수 있는 묶음으로 사용합니다.
4핵심 개념
갈림길과 반복 구간
배송 규칙표에서 주문 금액에 맞는 행 하나를 고르는 과정이 조건문과 비슷합니다. 조건문(conditional statement)은 참이나 거짓으로 판단되는 조건에 따라 실행 경로를 고릅니다. >=는 “크거나 같다”, <는 “작다”, ==는 “두 값이 같다”라고 읽는 비교 연산자입니다. 비교 결과는 불리언 True 또는 False입니다. if 조건:의 콜론은 다음 들여쓰기 블록이 해당 조건에 속함을 나타냅니다. elif는 앞 조건이 거짓일 때 확인할 추가 조건이고, else는 앞의 모든 조건이 거짓일 때 실행합니다. 위에서부터 검사하며 처음 참이 된 한 경로만 실행합니다.
반복(iteration)은 정해진 규칙을 여러 번 적용하는 일입니다. for amount in test_amounts:는 묶음에서 값을 하나씩 꺼내 amount에 저장하고 들여쓴 블록을 실행합니다. while 조건:은 조건이 참인 동안 계속 실행하므로 반복 중에 조건을 거짓으로 만드는 변화가 필요합니다. index += 1은 현재 값에 1을 더해 다시 저장하는 복합 대입입니다. break는 반복 전체를 즉시 끝내고, continue는 현재 차례의 남은 문장을 건너뛰고 다음 차례로 이어집니다.
len(목록)은 항목 수를 반환합니다. 위치 번호는 0부터 시작하므로 길이가 5인 목록의 위치는 0부터 4까지입니다. range(4)는 끝값 4를 포함하지 않고 0, 1, 2, 3을 제공합니다. enumerate(목록)는 존재하는 각 항목에 위치 번호를 붙여 두 값을 함께 제공합니다. 이 함수들은 입력 묶음을 직접 바꾸지 않습니다.
도식 읽기
위쪽 줄은 주문 금액 18000원을 왼쪽에서 오른쪽으로 읽습니다. 두 조건 >= 50000과 >= 30000이 모두 거짓이므로 배송비 3000원을 선택합니다. 아래쪽은 별도의 반복 예제입니다. 목록의 -1은 continue로 건너뛰고 0을 만나면 break로 반복을 종료합니다. 따라서 뒤에 있는 65000원은 처리하지 않고 결과에는 18000과 42000만 남습니다.
5실행 예제
기본 실행의 입력은 다섯 주문 금액과 두 배송 기준입니다. for가 금액 하나를 amount에 저장하고, 조건문이 첫 번째로 참인 경로의 배송비를 shipping_fee에 저장합니다. 49999원은 50000원 이상이 아니므로 2000원 경로로 들어가고, 50000원은 >=에 경계값이 포함되어 0원 경로로 들어갑니다. 처리 결과는 금액마다 한 줄씩 출력됩니다.
while 예제의 입력에는 정상 금액, 건너뛸 값 -1, 종료 표시 0이 함께 있습니다. len()이 반환한 항목 수보다 index가 작은 동안 위치의 값을 읽습니다. 위치 번호를 먼저 1 늘리므로 continue를 만나도 다음 항목으로 이동합니다. 0에서는 break가 실행되어 뒤의 65000원은 읽지 않으며, 처리 목록에는 18000과 42000만 남습니다.
값 하나 변경 셀은 원래 주문 세 건을 유지하고 무료 배송 기준만 50000원에서 40000원으로 바꿉니다. 두 개수 변수를 0에서 시작해 조건이 참일 때마다 1을 더합니다. 원래 기준의 누적 결과는 1건, 변경 기준의 누적 결과는 2건입니다.
확인할 점 — while 셀에서 index += 1이 조건 검사보다 앞서 실행되므로 continue를 만나도 위치 번호가 증가합니다. 이 증가가 없다면 -1에서 같은 값을 계속 확인하게 됩니다.
6일부러 실패해 보기
목록 길이가 3이면 사용할 수 있는 위치 번호는 0, 1, 2입니다. Before 셀은 range(len(order_amounts) + 1)을 사용해 0, 1, 2, 3을 만듭니다. 앞의 세 값은 출력되지만 위치 3의 항목은 없으므로 실제 IndexError와 list index out of range 메시지가 나타납니다. range()의 끝값이 포함되지 않는다는 사실을 알고 있어도 길이에 1을 더하면 범위를 넘습니다.
After 셀은 enumerate(order_amounts)로 올바른 위치 번호와 주문 금액을 함께 받습니다. 출력은 0 18000, 1 42000, 2 65000이며 처리 건수는 3건입니다. 목록을 순서대로 처리하는 목적이라면 값만 직접 순회할 수 있습니다. 위치 번호까지 출력하거나 기록해야 할 때 enumerate()를 사용하면 범위를 따로 계산하지 않아도 됩니다.
7주의할 점과 실무 메모
조건의 순서는 결과를 바꿉니다. amount >= 30000을 amount >= 50000보다 먼저 두면 65000원도 먼저 참이 된 30000원 경로로 들어갑니다.
while 조건에 쓰는 값을 반복 안에서 바꾸지 않으면 종료되지 않을 수 있습니다. 시작값, 변화, 종료 조건을 함께 확인합니다.
continue 앞에서 상태 변경이 빠지지 않았는지 확인합니다. 이 노트북은 index += 1을 먼저 실행해 다음 항목으로 이동합니다.
break 뒤의 항목은 처리되지 않습니다. 0 뒤의 65000원이 출력에서 빠진 이유가 업무 규칙과 일치하는지 확인해야 합니다.
8정리와 다음 절

찾는 방법에 맞춰 그릇을 고릅니다
목록(list)은 순서가 있는 변경 가능한 값의 묶음입니다. 대괄호로 만들며 items[0]처럼 0부터 시작하는 위치 번호로 읽습니다. 튜플(tuple)은 순서가 있지만 만든 뒤 항목을 바꿀 수 없는 묶음입니다. 소괄호로 만들며 좌표처럼 두 값의 자리와 수를 유지할 때 사용할 수 있습니다. 딕셔너리(dict)는 중괄호 안에 키: 값을 짝으로 저장합니다. 콜론의 왼쪽이 찾을 때 사용할 키이고 오른쪽이 저장할 값입니다. order["amount"]는 키로 78000을 읽습니다. 집합(set)은 중복이 없는 값의 묶음입니다. set(items)는 목록을 입력받아 중복을 제거한 새 집합을 반환합니다.
변경 가능(mutable)하다는 말은 만든 뒤 내부 항목을 추가하거나 삭제할 수 있다는 뜻입니다. 목록과 딕셔너리, 집합은 변경할 수 있고 튜플은 변경할 수 없습니다. append()는 목록 끝에 입력값을 추가하고, len()은 자료구조의 항목 수를 반환합니다. sorted()는 입력을 정렬한 새 목록을 반환하므로 원래 집합에 순서가 생기지는 않습니다.

None은 값이 아직 없음을 나타내는 특별한 값이며, 이를 기본값으로 두고 함수 본문에서 새 목록을 만들면 호출별 결과를 분리할 수 있습니다. 타입 힌트 표기와 검사는 07절에서 배웁니다.

위쪽 줄을 왼쪽에서 오른쪽으로 읽으면 78000과 0.1이 함수에 전달되고 할인 후 70200이 반환되는 순서가 보입니다. 가운데 상자는 함수 안팎의 label이 서로 다른 범위에 있음을 보여 줍니다. 아래쪽은 기본 목록을 공유한 두 호출의 결과와 None에서 새 목록을 만들어 분리한 결과를 비교합니다. 아래 비교는 위쪽 금액 계산과 별도의 함수 예제입니다.
5실행 예제
calculate_payment(amount, discount_rate)는 주문 금액과 할인율을 입력받습니다. 함수 안에서는 두 값을 곱해 할인액을 처리하고, 원래 금액에서 할인액을 뺀 뒤 round()가 정수 70200을 반환합니다. 기본 실행은 이 반환값을 payment에 저장합니다. payment // 1000의 //는 나눗셈 결과보다 크지 않은 정수로 내린 몫을 반환합니다. 이 예제의 양수 금액에서는 소수 부분을 버린 값과 같으므로 적립 예정 점수는 70점입니다.
지역 변수 관찰 셀은 함수 밖 label에 "주문"을 저장합니다. make_label() 안에서도 같은 이름을 사용하지만 "주문번호 A102"를 반환한 뒤 바깥 변수를 출력하면 여전히 "주문"입니다. 값 하나 변경 셀은 주문 금액을 유지하고 할인율만 0.1에서 0.2로 바꿉니다. 같은 처리에서 70200원과 62400원이 각각 반환됩니다.
확인할 점 — 함수 정의만으로는 계산이 실행되지 않습니다. 실제 인자를 넣어 호출해야 본문이 처리되고 반환값이 생깁니다. 반환된 70200은 출력뿐 아니라 적립 점수 계산의 입력으로 다시 사용됩니다.
6일부러 실패해 보기
Before 함수는 tags=[]처럼 빈 목록을 기본값으로 둡니다. 이 목록은 호출할 때마다 새로 만들어지지 않습니다. 첫 호출 직후 복사한 상태는 ['신규']입니다. 두 번째 호출에서 "배송"을 추가한 뒤 첫 번째 반환값을 다시 확인하면 ['신규', '배송']으로 바뀌어 있습니다. 두 반환값의 객체 동일성을 검사한 결과도 True입니다.
After 함수는 기본값을 None으로 둡니다. 함수 안에서 tags is None일 때 새 빈 목록을 만든 뒤 태그를 추가합니다. 입력은 호출별 태그 문자열이고, 처리는 새 목록 생성과 추가이며, 반환은 해당 호출만의 태그 목록입니다. 첫 호출 결과는 ['신규'], 두 번째 호출 결과는 ['배송']이고 같은 객체인지 확인한 값은 False입니다.
7주의할 점과 실무 메모
함수 이름은 calc()보다 calculate_payment()처럼 역할이 드러나게 작성합니다. 함수 하나에는 설명할 수 있는 한 역할을 둡니다.
함수 안에서 print()만 실행하고 반환하지 않으면 결과를 뒤 계산에 사용하기 어렵습니다. 호출한 곳에서 필요한 값은 return으로 제공합니다.
위치로 인자를 전달할 때는 매개변수 순서를 지켜야 합니다. amount=78000처럼 이름을 지정하면 어떤 입력인지 코드에서 확인할 수 있습니다.
목록·딕셔너리·집합처럼 변경 가능한 값을 기본 인자로 직접 만들지 않습니다. None을 기본값으로 두고 함수 안에서 새 객체를 만듭니다.

함수는 매개변수로 입력을 받고 return으로 결과를 반환합니다.
지역 변수는 함수 안의 범위에 속하며 바깥의 같은 이름과 구분됩니다.
변경 가능한 기본 인자는 호출 사이에 공유되므로 None을 사용해 새 값을 만듭니다.

4핵심 개념
쉬운 예
종이에 주문을 기록할 때는 어떤 글자를 썼는지 사람이 바로 알아봅니다. 컴퓨터 파일은 문자를 바이트로 바꾸어 저장하므로 문자와 바이트 사이의 규칙이 필요합니다. 문자 인코딩(character encoding)은 이 변환 규칙입니다. 같은 UTF-8 규칙으로 쓰고 읽으면 연필과 노트가 그대로 복원됩니다.
정의
경로(path)는 파일의 위치를 나타내는 값입니다. from pathlib import Path는 표준 라이브러리에서 Path라는 이름을 가져옵니다. 모듈 가져오기는 07절에서 자세히 배웁니다. training_dir / "orders.txt"의 빗금은 나눗셈이 아니라 Path에 폴더와 파일 이름을 연결합니다. write_text()는 문자열을 입력받아 파일에 쓰고, read_text()는 파일을 읽어 하나의 문자열을 반환합니다.
text.splitlines()는 전체 문자열을 줄바꿈에서 나누어 문자열 목록을 반환합니다. line.split(",")는 한 줄을 쉼표에서 나눕니다. 반환된 두 문자열을 name, count_text에 차례로 저장하고, int(count_text)가 수량을 정수로 변환합니다. 노트북은 아직 배우지 않은 목록 컴프리헨션 대신 02절의 for와 03절의 append()를 사용합니다. 타입 힌트는 07절에서 배웁니다.
예외(exception)는 실행 중 정상 흐름을 계속할 수 없을 때 만들어지는 오류 객체입니다. try는 실행을 시도할 블록이고, except는 지정한 예외가 발생했을 때 실행할 블록입니다. FileNotFoundError는 요청한 경로에 파일이 없을 때 발생합니다. except Exception처럼 넓게 처리하면 파일 누락뿐 아니라 프로그래밍 실수도 빈 결과로 바뀔 수 있습니다. 이번 함수는 파일 누락만 빈 목록으로 반환하며, 연필,많이의 정수 변환에서 생기는 ValueError는 그대로 알려 줍니다.
도식 읽기
위쪽의 파일 읽기에서 정상 파일과 누락 파일을 나누어 봅니다. 왼쪽은 UTF-8 본문을 두 줄로 나누고 각 줄을 상품명과 정수 수량의 쌍으로 변환한 결과입니다. 오른쪽은 파일이 없어 FileNotFoundError가 발생한 경우입니다. read_items_or_empty는 그 예외만 처리하여 빈 목록을 반환합니다. 정상 주문이 누락 파일로 바뀌는 흐름이 아니라, 서로 다른 파일 경로를 읽은 두 결과입니다.
5실행 예제
실습은 운영체제의 임시 폴더 안에 전용 디렉터리를 만듭니다. 입력 문자열 두 줄을 write_text()가 UTF-8 바이트로 기록합니다. read_items()는 파일 경로를 입력받고, read_text()로 전체 문자열을 처리한 뒤 splitlines()의 문자열 목록 ['연필,3', '노트,2']를 반환합니다. 주문 줄 수 출력 2는 목록에 두 항목이 있음을 보여 줍니다.
parse_order()는 문자열 한 줄을 입력받습니다. 쉼표로 나눈 두 문자열 중 수량을 정수로 변환하고 ('연필', 3) 같은 튜플을 반환합니다. for가 각 줄을 처리해 반환값을 parsed에 추가합니다. 마지막 비교에서도 같은 반복과 함수를 사용하고 입력 파일의 연필 수량만 3에서 5로 바꿉니다. 출력의 첫 수량이 3에서 5로 바뀌고 노트 주문은 유지됩니다.
확인할 점 — 파일명만 출력되며 개인 컴퓨터의 절대 경로는 나타나지 않습니다. 한글 상품명이 유지되고, 수량은 문자열이 아닌 정수로 변환됩니다. 파일 내용에서 한 값만 바꾼 뒤에도 같은 함수가 사용됩니다.
6일부러 실패해 보기
Before 셀은 준비하지 않은 missing.txt를 같은 읽기 함수에 전달합니다. 실제로 발생한 예외가 FileNotFoundError인지 확인하고 파일명도 함께 출력합니다. 의도한 오류가 발생하지 않으면 else에서 AssertionError를 발생시키므로 실패 재현이 우연히 통과하지 않습니다.
After 셀은 같은 누락 경로를 read_items_or_empty()에 전달합니다. 달라진 조건은 읽기 호출을 구체적인 예외 처리로 감싼 것입니다. 결과는 빈 목록이며 단언문으로 확인합니다. 모든 예외를 처리하지 않았기 때문에 잘못된 UTF-8 바이트나 정수가 아닌 수량까지 정상으로 표시하지 않습니다. 빈 목록이 “주문이 실제로 0건”인지 “선택 파일이 없었음”인지 구분해야 하는 서비스에서는 빈 목록과 함께 상태값을 반환하거나 로그를 남기는 설계가 더 알맞습니다.
After 셀 마지막은 parse_order("연필,많이")를 별도로 호출합니다. 파일은 읽지 않고 수량 문자열을 정수로 바꾸다가 실제 ValueError가 발생하는 것을 확인합니다. 바깥의 예외 처리문은 오류를 관찰하기 위한 것이며, 파일 누락을 빈 목록으로 처리하는 규칙과 잘못된 수량의 변환 실패를 구분합니다.
7주의할 점과 실무 메모
write_text()는 기존 내용을 교체합니다. 기록을 이어 붙여야 한다면 추가 모드를 검토하고, 먼저 요구사항을 분명히 정합니다.
텍스트를 쓸 때와 읽을 때 모두 encoding="utf-8"을 명시합니다. 기본 인코딩은 실행 환경에 따라 달라질 수 있습니다.
파일을 직접 열 때는 with open(...)을 사용하면 블록이 끝날 때 닫기 처리가 수행됩니다. Path.read_text()와 write_text()는 한 번의 전체 읽기·쓰기에 알맞습니다.
큰 파일은 전체를 한꺼번에 메모리에 올리지 말고 줄 단위 처리 방식을 검토합니다. 이번 두 줄 결과만으로 큰 파일의 메모리 사용량을 판단할 수는 없습니다.

파일의 문자열 수량은 필요한 자료형으로 명시적으로 변환합니다.

9복습 문제
문제와 해설
1. 한글 텍스트 파일을 읽고 쓸 때 UTF-8을 양쪽에 명시하는 이유는 무엇인가요?

서랍마다 문구류의 종류를 적어 두면 필요한 물건을 찾을 때 모든 서랍을 열지 않아도 됩니다. 모듈(module)은 관련된 Python 정의와 문장을 담는 .py 파일입니다. pricing.py라는 파일은 pricing이라는 모듈 이름으로 읽습니다. from pricing import add_tax는 “pricing 모듈에서 add_tax라는 이름을 현재 파일로 가져온다”라고 읽습니다. 가져온 뒤에는 add_tax(10000, 0.1)처럼 일반 함수와 같은 방식으로 호출합니다.
정의와 표기 읽기
import는 다른 모듈의 코드를 불러와 사용할 수 있게 하는 문장입니다. Python은 실행 파일이 있는 폴더 등 정해진 위치에서 모듈을 찾고, 처음 가져올 때 그 파일의 최상위 문장을 실행한 뒤 정의된 이름을 사용할 수 있게 합니다. 네임스페이스(namespace)는 이름과 값의 대응을 관리하는 범위입니다. import pricing은 모듈 이름을 유지하여 pricing.add_tax()로 호출합니다. from pricing import add_tax는 선택한 이름을 현재 범위에 두어 add_tax()로 호출합니다.
타입힌트(type hint)는 변수, 매개변수, 반환값의 예상 타입을 표시한 정보입니다. def add_tax(price: int, rate: float) -> int:에서 price: int는 price에 정수를 예상하고, rate: float는 rate에 실수를 예상한다는 뜻입니다. 화살표 뒤의 int는 함수가 정수를 반환할 것이라는 표시입니다. 이 표기는 호출할 때 값을 전달하거나 반환하는 동작을 만들지 않습니다. 실제 입력은 괄호 안의 10000과 0.1이고, 본문의 return이 계산한 정수가 호출 위치로 반환됩니다.
정적 타입 검사(static type checking)는 프로그램을 실행하기 전에 타입힌트와 코드 사용이 맞는지 분석하는 과정입니다. 타입힌트는 문서와 도구를 위한 정보이며 런타임 검증(runtime validation)을 자동으로 수행하지 않습니다. 런타임 검증은 실행 중 실제 값이 조건에 맞는지 확인하고, 맞지 않으면 변환하거나 오류를 알리는 별도 동작입니다.
도식 읽기
위쪽 줄은 pricing.py 작성, run_price.py에서 함수 가져오기, 정수 가격과 실수 세율 전달, 정수 11000 반환의 순서입니다. 아래쪽은 타입힌트가 실행 중 입력을 자동으로 검사하지 않는다는 별도의 비교입니다. double_total에 문자열 "1200"을 넣으면 함수 본문은 문자열 곱셈을 실행해 "12001200"을 반환합니다. 호출 전에 정수로 변환하면 같은 본문이 숫자 곱셈을 실행해 2400을 반환합니다.
5실행 예제
첫 셀은 파일을 저장할 임시 폴더를 만듭니다. 다음 셀에서 module_source 문자열을 pricing.py로, runner_source 문자열을 run_price.py로 저장합니다. 실행 시점에는 run_price.py의 import 문이 먼저 pricing.py를 찾고, 이어서 add_tax(10000, 0.1)가 가격 10,000과 세율 0.1을 함수에 전달합니다. 함수는 price * (1 + rate)를 계산하고 반올림한 정수 11000을 반환하며, print()가 그 값을 화면에 표시합니다.
다음 셀의 label_price(price: int) -> str는 정수 가격을 입력받아 "12,000원" 같은 문자열을 반환한다고 읽습니다. __annotations__ 출력은 개발자가 적은 표시가 함수 객체에 저장되었음을 보여 줄 뿐, 호출값을 검사했다는 뜻은 아닙니다. 값 하나 비교에서는 함수와 표시 형식을 그대로 두고 호출 인자만 12000에서 25000으로 바꿉니다. 반환 문자열이 각각 12,000원과 25,000원으로 달라지는지 확인합니다.
확인할 점 — pricing.py의 입력은 두 숫자이고 반환은 정수 11000입니다. run_price.py의 print()가 반환값을 출력합니다. label_price()는 정수 하나를 받아 문자열을 반환하므로 타입힌트 정보와 실제 반환값을 나누어 읽어야 합니다.
6일부러 실패해 보기
Before의 double_total()은 정수를 받아 정수를 반환한다고 표시합니다. 하지만 호출할 때 문자열 "1200"을 전달해도 Python은 타입힌트를 근거로 예외를 발생시키지 않습니다. 문자열에 2를 곱하는 연산이 적용되어 "12001200"이 반환됩니다. 오류 메시지가 없다는 사실이 올바른 계산을 뜻하지는 않습니다.
After는 같은 입력 문자열 "1200"을 int()로 변환한 뒤 같은 함수에 전달합니다. 출력은 숫자 2400입니다. 바꾼 조건은 함수 호출 전에 외부 입력을 정수로 바꾼 한 단계입니다. 실제 서비스에서는 변환할 수 없는 문자열도 들어올 수 있으므로 예외 처리나 검증 규칙을 추가해야 합니다. 10절에서는 Pydantic으로 여러 입력 필드의 런타임 검증을 구조화하는 방법을 학습합니다.
7주의할 점과 실무 메모
from module import *는 어느 이름이 들어왔는지 파악하기 어렵고 이름 충돌을 만들 수 있습니다. 사용할 이름을 명시합니다.
모듈을 가져올 때 모듈 최상위 문장이 실행됩니다. 재사용 모듈에는 함수와 클래스 정의를 중심으로 두고, 실행 전용 코드는 역할을 분리합니다.
타입힌트는 값 변환이나 유효성 검사를 자동 수행하지 않습니다. 파일, 사용자 입력, 네트워크 응답처럼 외부에서 받은 값은 프로그램 경계에서 별도로 확인합니다.
int("1200")은 성공하지만 int("천이백")은 실패합니다. 변환 가능한 형식과 실패 시 행동을 요구사항으로 정해야 합니다.

타입힌트는 실행 중 값을 자동 검증하지 않으므로 외부 입력을 별도로 확인해야 합니다.

1학습 목표
pytest 테스트 함수를 작성하고 현재 Python 환경에서 실행할 수 있습니다.
매개변수화로 같은 검사 규칙을 여러 입력에 적용할 수 있습니다.
실제 결함이 있을 때 실패하는 테스트를 확인하고, 구현 수정 뒤 같은 테스트가 통과하는지 검증할 수 있습니다.
2이 내용을 배우는 이유
함수를 수정한 직후 한 번 출력해 보는 것만으로는 다음 수정에서도 같은 동작이 유지되는지 알기 어렵습니다. 테스트는 입력과 기대 결과를 코드로 기록하고 필요할 때 다시 실행합니다. 가격 계산처럼 숫자 하나가 달라져도 중요한 기능에서는 사람이 매번 출력 전체를 비교하는 작업을 줄여 줍니다.
좋은 테스트는 결함이 있을 때 실제로 실패하고, 원인을 고친 뒤 통과합니다. 처음부터 통과만 한 테스트로는 잘못된 구현을 구별할 수 있는지 알 수 없습니다. 이번 절에서는 10% 할인 결과에 100원을 잘못 더하는 결함을 준비합니다. 기대값 9,000원은 유지하고 구현만 수정하여 빨간 실패와 초록 통과를 모두 관찰합니다.
3앞에서 배운 내용
04절에서 함수를 호출해 반환값을 받았고, 여러 앞 절의 예제 끝에서 assert 실제값 == 기대값으로 결과를 확인했습니다. 07절의 모듈과 타입힌트는 이 절의 필수 선행 지식이 아닙니다. pytest는 앞에서 사용한 assert를 테스트 함수 안에 두고, 이름 규칙에 맞는 테스트를 찾아 여러 번 실행하며 실패한 비교식을 보여 줍니다. 노트북은 임시 폴더에 테스트 파일을 새로 만들고 현재 커널의 Python으로 pytest를 실행합니다.
4핵심 개념
쉬운 예
계산기를 고친 뒤 1+1만 눌러 보는 것으로 모든 계산이 맞다고 말할 수 없습니다. 덧셈, 0, 여러 수량처럼 중요한 사례를 미리 적고 같은 방식으로 반복 확인해야 합니다. 테스트 케이스(test case)는 하나의 입력, 실행, 기대 결과를 묶은 검사 사례입니다. pytest는 이름이 test_로 시작하는 파일과 함수를 찾아 호출합니다. 테스트 함수에는 보통 화면 출력용 print() 대신 결과 판정용 assert를 둡니다.
정의와 표기 읽기
단언(assertion)은 조건이 참이어야 한다고 명시하는 문장입니다. assert 1200 + 800 == 2000은 왼쪽 계산의 실제값이 오른쪽 기대값 2000과 같은지 비교합니다. 참이면 다음 테스트로 넘어가고 거짓이면 pytest가 실제값과 기대값을 포함한 실패 정보를 보여 줍니다. 테스트 함수는 값을 반환해 합격을 알리는 대신, 검사할 조건을 단언문으로 표현합니다.
종료 코드(exit code)는 pytest 프로세스가 운영체제에 알리는 결과 숫자입니다. 이번 실행에서 0은 선택한 테스트가 모두 통과했고, 1은 테스트가 실행되었지만 하나 이상 실패했다는 뜻입니다. 노트북의 run_pytest()는 폴더와 파일명을 입력받아 subprocess.run()으로 별도 pytest 프로세스를 실행합니다. 반환된 실행 결과 객체의 returncode에는 종료 코드가, stdout에는 요약 출력이 담깁니다.
매개변수화(parametrization)는 하나의 테스트 함수에 여러 입력과 기대값 묶음을 제공하는 pytest 기능입니다. @pytest.mark.parametrize(("price", "count", "expected"), [...])는 바로 아래 함수에 적용됩니다. 일반적인 @ 문법은 09절에서 배우며, 지금은 목록의 각 튜플을 테스트 입력 한 묶음으로 읽습니다. 첫 튜플 (1000, 1, 1000)은 price, count, expected에 차례로 연결되고 test_line_total()이 세 튜플에 대해 세 번 호출됩니다.
회귀 테스트(regression test)는 고친 결함이 이후 변경에서 다시 생기지 않는지 확인하도록 남긴 테스트입니다. 픽스처(fixture)는 테스트가 요청하는 준비 값을 제공하며 11절에서 실행 과정을 자세히 다룹니다.
도식 읽기
위쪽 상자의 입력 10000과 기대값 9000을 두 비교에서 공통으로 사용합니다. 왼쪽에서는 테스트 함수가 discounted(10000)을 호출해 실제값 9100을 받고, 9000과 비교해 실패합니다. 오른쪽은 같은 테스트를 다시 호출하되 구현에서 100원 가산만 제거하여 실제값 9000을 반환합니다. 종료 코드와 요약이 각각 1·1 failed에서 0·1 passed로 바뀌는지 함께 읽습니다.
5실행 예제
첫 셀은 현재 노트북 커널에 pytest 9.1.1을 설치합니다. 준비 셀은 현재 환경 변수를 copy()로 복사한 뒤, 복사본에 pytest 플러그인 자동 로드를 끄는 값을 추가합니다. 원래 환경을 바꾸지 않고 하위 프로세스에 전달할 설정을 만드는 과정입니다. run_pytest(folder, target)는 테스트 폴더와 파일명을 입력받아 sys.executable -m pytest -q --tb=short 파일명을 실행하고 결과 객체를 반환합니다. -q는 요약 중심 출력, --tb=short는 짧은 실패 경로를 선택하는 옵션입니다.
기본 테스트 파일을 저장한 뒤 run_pytest()를 호출합니다. pytest가 test_total()을 찾아 호출하고 1200 + 800이 2000이면 단언이 통과합니다. 출력의 점 하나는 테스트 한 건의 통과, 1 passed는 실행 요약, 종료 코드 0은 전체 통과를 뜻합니다.
이어지는 test_line_total()은 가격, 수량, 기대값을 매개변수로 받습니다. 매개변수화 목록의 세 튜플이 각각 함수 호출 한 번이 되므로 출력의 점 세 개와 3 passed가 나타납니다. param_test.replace(기존 문자열, 새 문자열)은 테스트 코드 문자열에서 지정한 부분을 바꾼 새 문자열을 반환합니다. 원래 문자열은 유지되고 새 결과가 expanded에 저장됩니다. 이 방법으로 (900, 3, 2700)만 추가하므로 함수 구현과 비교식은 그대로이고 테스트 호출 수만 네 번으로 늘어납니다.
확인할 점 — 각 단계에서 테스트 파일이 입력이고, pytest의 수집과 함수 호출이 처리이며, 종료 코드와 요약 문자열이 노트북에 전달된 결과입니다. 점의 개수, N passed, 종료 코드를 함께 읽어야 실행된 사례 수와 전체 판정을 구분할 수 있습니다.
6일부러 실패해 보기
Before의 discounted()는 가격의 90%를 계산한 뒤 100원을 추가합니다. 테스트 입력은 10,000원이고 기대값은 9,000원입니다. 실제값 9,100원이 기대값과 다르므로 pytest는 비교식을 보여 주고 1 failed, 종료 코드 1을 반환합니다. 의도한 실패가 발생했는지 노트북의 단언문으로 다시 확인합니다.

7주의할 점과 실무 메모
테스트를 통과시키려고 기대값을 현재의 잘못된 출력으로 바꾸면 결함을 고친 것이 아닙니다. 요구사항의 기대값을 유지하고 구현을 수정합니다.
한 테스트에 여러 원인을 넣으면 실패 위치를 해석하기 어렵습니다. 테스트 이름과 입력이 확인하려는 행동 하나를 분명히 나타내게 작성합니다.
실수 계산과 금액 반올림은 정책에 따라 결과가 달라질 수 있습니다. 이번 int(price * 0.9) 예제만으로 실제 결제 정책을 결정할 수 없습니다.
pytest 9.1.1과 Python 3.12에서 실행한 결과입니다. 프로젝트의 고정 버전을 잠금 파일과 함께 관리해야 팀원도 같은 조건을 재현할 수 있습니다.

1학습 목표
데코레이터가 함수를 받아 새 함수를 반환하는 과정을 설명할 수 있습니다.
functools.wraps로 원래 함수의 이름·설명·서명을 유지할 수 있습니다.

2이 내용을 배우는 이유
여러 함수에서 호출 시각 기록, 권한 확인, 재시도 같은 공통 처리를 반복하면 핵심 기능보다 부가 코드가 많아집니다. 데코레이터는 공통 처리를 한곳에 정의하고 필요한 함수에 적용하게 합니다. 파일·연결·잠금처럼 사용 뒤 정리가 필요한 자원은 정상 처리뿐 아니라 예외 경로에서도 정리되어야 합니다. 컨텍스트 매니저는 시작과 정리 규칙을 묶어 with 문에서 재사용하게 합니다. 이 절은 A 경로 01~08절을 마친 학생이 선택하는 B 경로 확장 학습입니다. Ch 18에서는 API 호출의 기록과 재시도에, Ch 30에서는 서비스 자원의 수명 관리에 같은 구조가 이어집니다.
3앞에서 배운 내용
04절에서 함수를 정의하고 호출하면 인자가 매개변수에 연결되고 return 값이 호출 위치로 반환된다고 배웠습니다. 이번 절에서는 함수 자체도 다른 함수의 입력과 반환으로 사용할 수 있다는 새 내용을 추가합니다. 05절에서는 try와 except로 예외가 발생한 경로를 처리했습니다. finally가 예외 여부와 관계없이 실행되는 규칙과 with가 준비·정리를 묶는 규칙은 이 절에서 처음 정의합니다. 07절의 타입힌트는 B 경로에서 배웠지만, 데코레이터 예제의 보조 타입 표기는 제거하여 함수의 입력과 반환에 집중합니다.
4핵심 개념
쉬운 예
건물 출입구에서 모든 방문자가 같은 절차를 거친다고 생각해 봅니다. 방문 목적은 사람마다 다르지만 입장 기록과 퇴장 기록은 공통입니다. 각 업무 함수 안에 기록 코드를 복사하면 수정할 곳이 늘어납니다. 데코레이터는 업무 함수를 감싸 호출 전후의 공통 절차를 담당합니다. 자원 정리는 대여 물품을 반납하는 절차와 비슷합니다. 업무 중 문제가 생겨도 반납 규칙은 실행되어야 합니다.
정의와 표기 읽기
데코레이터(decorator)는 함수를 입력으로 받아 기능을 덧붙인 새 함수를 반환하는 호출 가능한 객체입니다. @trace를 normalize_title 정의 바로 위에 쓰면 함수 정의 시점에 normalize_title = trace(normalize_title)가 실행된 것과 같습니다. trace의 입력 func에는 원래 함수가 들어가고, 반환된 wrapper가 이후 normalize_title 이름에 연결됩니다. 따라서 나중에 normalize_title("  월간 보고서  ")를 호출하면 래퍼가 먼저 실행되고 래퍼 내부에서 원래 함수가 호출됩니다.
래퍼(wrapper)는 원래 함수를 감싸는 내부 함수입니다. *args는 이름 없이 위치로 전달된 인자를 튜플로 받고, **kwargs는 이름을 붙여 전달된 인자를 딕셔너리로 받습니다. func(*args, **kwargs)는 받은 인자를 원래 함수에 다시 전달하고, 그 반환값을 래퍼가 호출자에게 반환합니다. 메타데이터(metadata)는 함수 이름, 설명, 서명처럼 함수를 설명하는 정보이며 functools.wraps가 이를 래퍼에 복사합니다.
컨텍스트 매니저(context manager)는 with 블록에 들어갈 때 준비하고 나올 때 정리하는 규칙을 가진 객체입니다. with managed_resource() as managed:는 관리자를 호출해 준비를 시작하고, yield current가 내보낸 자원을 managed에 연결한 뒤 블록을 실행한다고 읽습니다. 블록이 끝나거나 예외로 중단되면 실행은 yield 다음 문장으로 이어집니다. 종료 코드를 finally에 두면 두 경로 모두에서 정리됩니다.
도식 읽기
도식의 위쪽은 장식 시점에 원래 함수가 trace로 들어가 래퍼로 바뀌는 단계와, 호출 시점에 래퍼가 시작 기록·원래 함수 호출·완료 기록·결과 반환을 수행하는 단계를 나누어 보여 줍니다. 아래쪽은 같은 RuntimeError가 발생했을 때 Before에서는 정리 코드에 도달하지 못하고 After에서는 finally가 자원을 정리하는 결과를 비교합니다. 두 경우 모두 오류는 발생하며 정리 위치만 다릅니다.
5실행 예제
먼저 trace(func)를 정의합니다. 입력은 장식할 함수 객체이고 반환은 내부 함수 wrapper입니다. @wraps(func)는 이 래퍼의 정보를 원래 함수와 맞춥니다. 이어서 @trace 아래에 normalize_title()을 정의하면 장식이 즉시 적용됩니다. 이후 제목 문자열을 호출 인자로 주면 래퍼가 호출 시작을 출력하고, 원래 함수에 문자열을 전달해 공백을 제거한 값을 받은 뒤, 완료를 출력하고 그 값을 반환합니다.
실제 출력 호출 시작, 호출 완료, 결과의 순서는 공통 처리와 호출자의 출력 시점을 보여 줍니다. 다음 셀의 inspect.signature()는 장식된 함수가 받는 매개변수 표기를 반환합니다. 마지막 셀은 공백이 없는 제목만 입력으로 바꾸어도 같은 래퍼와 원래 함수가 호출되는지 확인합니다.
확인할 점 — 장식된 함수의 이름은 wrapper가 아니라 normalize_title로 출력됩니다. (title: str) -> str는 문자열 제목을 받아 문자열을 반환한다는 서명입니다. 기록 두 줄 뒤에 반환값이 출력되므로 래퍼가 결과를 잃지 않고 호출자에게 전달했음을 확인할 수 있습니다.
6일부러 실패해 보기
Before 코드는 자원을 만든 뒤 의도적으로 RuntimeError를 발생시킵니다. close()가 정상 처리 문장 뒤에 있으므로 해당 문장까지 실행되지 않습니다. 실제 출력의 닫힘: False는 정리가 누락되었음을 보여 줍니다.
After의 @contextmanager는 yield를 한 번 사용하는 함수에 컨텍스트 매니저 규칙을 부여하여 with에서 호출할 수 있게 합니다. 같은 오류가 with managed_resource() 안에서 발생하면 관리자의 finally가 먼저 정리 실행을 출력하고, 예외 처리 뒤 닫힘 상태는 True입니다. 이 결과는 예외가 없어졌다는 뜻이 아닙니다. 오류는 호출자가 처리하고, 컨텍스트 매니저는 자원 정리를 보장합니다.
7주의할 점과 실무 메모
wraps를 생략해도 작은 예제는 실행될 수 있지만 문서 생성기, 디버거, 의존성 주입 도구가 함수 정보를 잘못 읽을 수 있습니다.
래퍼에서 예외를 무조건 잡아 숨기면 호출자가 실패를 알 수 없습니다. 기록 후 다시 발생시키거나 처리 책임을 명확히 정합니다.
contextmanager 함수는 yield를 정확히 한 번 수행해야 합니다. 준비 중 실패했다면 아직 얻지 못한 자원을 정리하려 하지 않도록 단계별 상태를 고려합니다.
이 실습의 DemoResource는 정리 순서를 관찰하기 위한 모의 객체입니다. 데이터베이스 연결이나 네트워크 세션의 실제 종료 방식은 해당 라이브러리 문서를 확인합니다.
8정리와 다음 절
데코레이터는 함수 호출 전후의 공통 처리를 재사용합니다.
wraps는 원래 함수의 이름·설명·서명을 유지합니다.
컨텍스트 매니저의 finally는 정상 종료와 예외 종료 모두에서 자원을 정리합니다.

01절에서 문자열·정수·실수의 차이를, 03절에서 키와 값을 묶은 딕셔너리를 배웠습니다. 05절에서는 예외가 발생했을 때 자료형과 메시지를 읽었고, 06절에서는 클래스로 같은 속성 구조를 가진 객체를 만드는 방법을 배웠습니다. 07절의 타입힌트는 retries: int처럼 기대 자료형을 표시하지만 실행 중 실제 값을 검사하지는 않습니다. 이 절은 이 네 내용을 연결해 딕셔너리 입력을 검사하고 모델 객체로 바꾸는 과정에 집중합니다.
4핵심 개념
쉬운 예
신청서의 나이 칸에 숫자 모양의 문자열이 들어왔다고 생각해 봅니다. 어떤 시스템은 "20"을 정수 20으로 바꿔도 됩니다. 다른 시스템은 입력 형식 자체가 정해진 규칙이므로 문자열을 거부해야 합니다. 자동 변환과 엄격한 검증 중 무엇이 옳은지는 데이터 경계의 요구에 따라 결정합니다. Pydantic은 입력 규칙과 변환 결과를 모델에 함께 표현합니다.
정의와 표기 읽기
데이터 검증(data validation)은 입력이 기대한 자료형, 범위, 형식을 만족하는지 확인하는 과정입니다. 모델(model)은 여러 필드와 규칙을 묶은 클래스입니다. class LooseJob(BaseModel):은 Pydantic이 제공하는 BaseModel의 검증 기능을 물려받아 LooseJob이라는 새 모델 클래스를 정의한다는 뜻입니다. 들여쓴 retries: int = Field(ge=0, le=5)는 retries라는 필드가 정수이며 0 이상 5 이하라는 규칙입니다. 여기서 Field는 값을 즉시 검사하는 함수 호출이 아니라 모델 클래스가 읽을 필드 설정을 만듭니다.
LooseJob.model_validate({"retries": "3"})를 호출하는 시점에 검증이 실행됩니다. 입력은 문자열을 값으로 가진 딕셔너리이고, 기본 모드는 변환 가능한 문자열 "3"을 정수 3으로 강제 변환(coercion)합니다. 검증에 성공하면 딕셔너리를 그대로 반환하는 것이 아니라 LooseJob 객체를 반환합니다. 따라서 job.retries로 정수 값을 읽고 job.model_dump()로 다시 딕셔너리를 만들 수 있습니다.
엄격 모드(strict mode)는 이런 변환을 제한하고 입력 자료형 자체를 확인합니다. Field(strict=True)는 해당 필드에 엄격성을 적용합니다. 검증에 실패하면 모델 객체 대신 ValidationError가 발생합니다. error.errors()는 오류 딕셔너리의 목록을 반환하며, 첫 항목의 type은 실패 규칙을, loc은 문제가 생긴 필드 경로를 나타냅니다.
도식 읽기
도식의 시작점은 같은 입력 {"retries": "3"}입니다. model_validate()가 호출되면 기본 필드는 변환 경로를 따라 정수 3이 든 모델 객체를 반환하고, 엄격한 필드는 int_type 오류를 발생시킵니다. 정수 3은 엄격한 필드도 통과합니다. 정수 8은 자료형 검사는 통과하지만 범위 검사에서 less_than_equal 오류가 됩니다.
5실행 예제
Pydantic 2.13.5를 설치하고 세 이름을 가져옵니다. BaseModel은 모델의 바탕 클래스, Field는 필드 규칙을 만드는 함수, ValidationError는 검증 실패를 나타내는 예외 클래스입니다. LooseJob을 정의한 뒤 문자열 "3"이 든 딕셔너리를 model_validate()에 전달합니다. 호출 결과 job은 모델 객체이며, 출력 retries=3과 int는 필드 값이 정수로 변환되었음을 보여 줍니다.
model_dump()는 검증된 모델 객체를 {"retries": 3} 형태의 딕셔너리로 반환합니다. 이어서 같은 범위 규칙을 가진 BoundedJob에 정수 5를 넣으면 모델 객체가 반환됩니다. 정수 8을 넣으면 객체가 반환되지 않고 ValidationError가 발생하며, except 블록에서 첫 오류의 type과 loc을 출력합니다.
확인할 점 — 입력은 딕셔너리, 처리는 model_validate()의 변환과 규칙 검사, 성공 반환은 모델 객체입니다. retries=3은 입력 원문이 아니라 검증된 객체의 표시입니다. 범위를 벗어난 정수 8은 자료형이 맞더라도 통과하지 않으므로 자동 변환 여부와 값 범위를 따로 읽습니다.
6일부러 실패해 보기
Before에서는 재시도 횟수에 문자열 "3"을 전달합니다. 기본 모델은 이를 정수로 변환하므로 출력은 입력 '3' 통과 -> 3입니다. 입력 제공자가 반드시 JSON 숫자를 보내야 한다는 규칙이라면 이 변환은 형식 오류를 가립니다. After에서는 같은 범위 제약을 유지하고 필드에 strict=True만 추가합니다. 같은 문자열 입력은 int_type 오류가 되고, 정수 3은 통과합니다. 엄격 모드는 항상 더 좋은 선택이라는 뜻이 아닙니다. 사용자 입력을 편리하게 받아도 되는 경계인지, 시스템 간 형식을 정확히 지켜야 하는 경계인지 먼저 결정합니다.
7주의할 점과 실무 메모
Pydantic v1의 parse_obj() 예제와 섞지 않습니다. 이 교재는 v2의 model_validate()를 사용합니다.
타입 힌트와 실행 중 검증은 역할이 다릅니다. 타입 검사 도구가 통과해도 외부에서 들어온 데이터는 별도 검증이 필요합니다.
엄격성은 필드, 모델, 호출 단위로 적용할 수 있습니다. 규칙이 일부 필드에만 필요하다면 Field(strict=True)로 범위를 좁혀 의도를 드러냅니다.
Python 객체 입력과 JSON 입력은 일부 자료형에서 엄격 모드 동작이 다를 수 있습니다. 실제 입력 방식과 같은 메서드로 검증 결과를 확인합니다.
오류 메시지 전체 문자열에 의존한 테스트는 버전에 따라 깨질 수 있습니다. type과 loc처럼 구조화된 항목을 확인합니다.
8정리와 다음 절
Pydantic 모델은 입력 필드의 자료형과 값 범위를 한곳에 선언합니다.
기본 모드는 변환 가능한 값을 바꾸며, 엄격한 필드는 입력 자료형 자체를 확인합니다.
ValidationError.errors()의 오류 유형과 위치를 읽으면 실패 원인을 코드로 다룰 수 있습니다.
다음 학습과 이어지는 지점 — 11절에서는 작성한 코드를 다른 프로젝트가 설치할 수 있는 패키지로 만들고, 검증 코드를 독립된 테스트에서 반복 실행합니다. Ch 18과 Ch 30에서는 외부 데이터 경계에서 이 절의 모델 검증을 다시 사용합니다.

1. 문자열 "3"이 정수 필드에서 통과할 수 있는 이유는 무엇인가요?
정답과 해설: Pydantic 기본 모드가 변환 가능한 입력을 목표 자료형으로 강제 변환하기 때문입니다.
2. 정수만 허용하면서 0 이상 5 이하로 제한하려면 어떻게 선언하나요?
정답과 해설: retries: int = Field(strict=True, ge=0, le=5)처럼 선언합니다. 엄격성은 자료형을, ge와 le는 범위를 검사합니다.

정답과 해설: 입력값이 le로 지정한 최댓값보다 커서 이하 조건을 만족하지 못했다는 뜻입니다.
4. 모든 입력에 엄격 모드를 적용하기 전에 확인할 것은 무엇인가요?
정답과 해설: 해당 경계가 편리한 자동 변환을 허용하는지, 입력 형식을 정확히 지켜야 하는지 확인해야 합니다. 요구에 맞춰 필드·모델·호출 가운데 어느 범위에 적용할지 정합니다.

4핵심 개념
쉬운 예
작성 중인 원고 폴더와 출판된 책은 역할이 다릅니다. 원고 폴더를 다른 사람에게 그대로 전달하면 어떤 파일을 어디에 두어야 하는지 알기 어렵습니다. 패키지는 설치 도구가 읽을 이름, 버전, 소스 위치를 함께 제공합니다. 테스트 격리는 시험지를 풀 때마다 새 답안지를 지급하는 것과 비슷합니다. 이전 테스트가 남긴 표시가 다음 테스트의 정답에 영향을 주지 않아야 합니다.
정의와 표기 읽기
패키지(package)는 함께 배포하고 가져올 Python 모듈의 묶음입니다. 이 실습에서 src/report_tools/__init__.py는 import할 코드이고, pyproject.toml은 프로젝트 이름·버전·빌드 방법을 설명하는 설정 파일입니다. TOML의 [project]와 [build-system]은 설정 구역 이름이며, 아래의 name = "report-tools" 같은 문장은 키와 값을 연결합니다. 배포 이름에는 하이픈을 사용하지만 Python 코드에서는 import report_tools처럼 밑줄 이름으로 가져옵니다.
빌드 백엔드(build backend)는 소스와 설정을 읽어 배포 파일을 만드는 도구입니다. uv build --wheel을 호출하면 uv가 [build-system]에 지정된 uv_build를 사용합니다. 휠(wheel)은 설치할 코드와 메타데이터를 담은 .whl 파일입니다. 빌드는 휠 파일을 만드는 처리이고, 설치는 그 파일을 Python 환경에 배치해 import할 수 있게 하는 별도 처리입니다.
테스트 격리(test isolation)는 각 테스트가 독립된 준비 상태에서 실행되게 하는 원칙입니다. @pytest.fixture 아래의 items()는 준비 함수입니다. 테스트가 def test_add_alpha(items):처럼 같은 이름을 매개변수로 적으면 pytest가 호출 직전에 fixture를 실행하고 반환된 빈 목록을 전달합니다. 기본 함수 범위에서는 각 테스트 호출마다 새 목록이 반환됩니다.
monkeypatch는 테스트 동안 속성이나 환경 변수를 임시로 바꾸는 pytest fixture입니다. monkeypatch.setattr(status_service, "fetch_status", fake_status)는 검사 대상 모듈이 참조하는 함수 이름을 바꾸고, setenv()는 첫 테스트 안에서 환경 변수를 지정합니다. 이 노트북은 첫 테스트 안의 환경 변수 값과 다음 테스트에서 원래 함수가 반환한 대기를 직접 검사합니다. 환경 변수의 테스트 후 복원값은 별도로 출력하거나 단언하지 않습니다.
도식 읽기
도식의 위쪽은 src/report_tools와 pyproject.toml을 입력으로 받아 빌드 백엔드가 휠을 만들고, 그 휠을 새 환경에 설치한 뒤 새 프로세스가 report_tools를 가져오는 흐름입니다. 아래쪽은 공유 목록 하나를 연속으로 수정하는 Before와, 각 테스트 호출 직전에 fixture가 새 목록을 반환하는 After를 비교합니다. 마지막 상자는 첫 테스트에서 함수를 대체하고 다음 테스트에서 원래 함수의 반환값을 확인하는 범위를 나타냅니다.
5실행 예제
준비 셀은 임시 프로젝트의 src/report_tools/__init__.py에 make_title()을 저장합니다. 함수의 입력은 문자열이며 양쪽 공백을 제거하고 각 단어의 첫 글자를 바꾼 문자열을 반환합니다. 같은 셀은 pyproject.toml에 배포 이름 report-tools, 버전 0.1.0, 빌드 백엔드 uv_build를 기록합니다.
다음 셀은 현재 Python에서 uv의 build --wheel 명령을 호출합니다. 입력은 임시 프로젝트 폴더이고 산출물은 dist 폴더의 휠입니다. 이어서 새 가상환경을 만들고 그 휠을 설치합니다. 마지막 하위 프로세스는 설치 환경의 Python으로 import report_tools를 실행하고 make_title("  agent log  ")의 반환값을 출력합니다. report_tools-0.1.0-py3-none-any.whl -> Agent Log는 빌드 파일 이름과 설치 뒤 함수 결과를 한 줄에 보여 줍니다.
결과 확인 셀은 휠 파일이 실제로 존재하는지, 첫 입력이 Agent Log인지, 바꾼 입력이 Weekly Note인지 각각 검사합니다. 두 문자열은 같은 설치된 함수에 서로 다른 입력을 전달한 결과입니다.
확인할 점 — 소스 폴더를 현재 커널의 검색 경로에 직접 추가하지 않습니다. 빌드, 설치, 새 프로세스 import는 서로 다른 처리 단계입니다. 휠 존재 여부만으로 import 성공을 판단하지 않고 새 프로세스의 실제 반환 문자열까지 확인합니다.

4핵심 개념
쉬운 예
두 문서의 응답을 기다린다고 생각해 봅니다. 첫 요청을 보내고 응답이 올 때까지 멈춘 뒤 둘째 요청을 보내면 대기 시간이 이어집니다. 두 요청을 모두 시작하면 첫 요청이 기다리는 동안 둘째 요청도 진행될 수 있습니다. 비동기 실행은 계산을 동시에 두 개 수행한다는 뜻이 아니라, 한 작업이 파일·네트워크 응답이나 타이머를 기다릴 때 다른 작업이 실행될 수 있는 구조입니다.
정의와 표기 읽기
코루틴(coroutine)은 실행을 잠시 멈췄다가 이어갈 수 있는 함수 실행 단위입니다. async def fetch_label(name: str, delay: float) -> str:는 비동기 함수를 정의합니다. 입력은 문자열 이름과 초 단위 실수 대기 시간이고 최종 반환값은 문자열입니다. fetch_label("문서-A", 0.01)을 호출한 직후에는 본문 결과가 아니라 코루틴 객체가 반환됩니다. result = await pending은 코루틴이 아직 완료되지 않았다면 기다리는 동안 다른 작업이 실행될 수 있게 하고, 완료되면 최종 문자열을 result에 연결합니다. 이미 완료된 작업을 기다릴 때는 다른 작업으로 전환할 필요가 없을 수 있습니다.
이벤트 루프(event loop)는 실행 가능한 코루틴과 대기가 끝난 작업을 확인하며 실행 순서를 조정합니다. 태스크(Task)는 코루틴을 이벤트 루프에 예약한 객체입니다. asyncio.create_task(record_heartbeat(events, started))는 하트비트 코루틴을 예약하고 태스크를 즉시 반환합니다. await task는 예약된 작업의 완료와 반환값을 기다립니다.
이벤트(Event)는 코루틴 사이에서 사건의 발생 여부를 알리는 신호 객체입니다. started.set()은 신호를 켜고, await started.wait()는 신호가 켜질 때까지 기다립니다. record_heartbeat()는 사건 목록과 신호를 인자로 받아 시작 신호를 켠 뒤 하트비트를 목록에 기록합니다. 함수 밖에서 만든 목록도 인자로 전달하면 함수가 같은 목록 객체를 수정할 수 있습니다.
asyncio.gather(first(), second())는 전달받은 여러 코루틴을 예약해 함께 진행하고 모두 완료된 뒤 결과 목록을 반환합니다. 각 작업은 대기 시간이 끝나는 순서대로 완료될 수 있지만 반환 목록의 위치는 gather 괄호에 적은 입력 순서를 따릅니다. 차단 호출(blocking call)은 반환될 때까지 현재 실행 흐름을 점유하는 호출입니다. 스레드(thread)는 한 프로세스 안에서 나뉜 실행 흐름입니다. time.sleep을 이벤트 루프와 같은 스레드에서 호출하면 다른 태스크가 실행되지 못합니다. asyncio.to_thread(time.sleep, 0.05)는 동기 함수를 다른 스레드에서 호출하고 그 완료를 기다릴 수 있게 합니다.
도식 읽기
도식의 위쪽은 await를 두 번 차례로 만나는 순차 실행과, 두 코루틴을 gather에 한꺼번에 전달하는 실행을 비교합니다. 가운데는 0.01초 작업이 먼저 완료 기록에 추가되지만 결과 목록은 입력한 0.03초 작업부터 놓이는 차이를 보여 줍니다. 아래쪽은 time.sleep이 하트비트의 실행을 막은 Before와 to_thread로 옮긴 뒤 하트비트가 먼저 기록된 After를 보여 줍니다.
5실행 예제
fetch_label은 문자열 이름과 초 단위 대기 시간을 입력받습니다. 함수 본문은 await asyncio.sleep(delay)에서 타이머를 기다린 뒤 완료:이름 문자열을 반환합니다. 먼저 함수 호출 결과를 pending에 저장해 자료형 이름 coroutine을 확인합니다. 이어서 await pending을 실행한 시점에 본문이 완료되고 완료:문서-A가 반환됩니다.
다음 셀은 두 tracked() 호출을 gather에 입력합니다. 각 함수는 대기가 끝나면 이름을 progress에 추가하고 같은 이름을 반환합니다. 따라서 progress는 실제 완료 순서인 빠른 작업·느린 작업이고, gathered는 입력 순서인 느린 작업·빠른 작업입니다. 마지막 셀은 같은 0.04초 대기 두 건을 각각 await한 경우와 한 번의 gather로 기다린 경우를 측정합니다.
확인할 점 — await는 코루틴의 최종 반환값을 받는 호출 지점이고, gather는 여러 입력의 반환값을 목록으로 모으는 호출 지점입니다. 측정값은 현재 환경의 모의 대기 결과이며 실제 네트워크 API나 CPU 계산의 보편적인 속도 향상을 뜻하지 않습니다.
6일부러 실패해 보기
asyncio.Event()는 코루틴 사이에서 사건 발생을 알리는 신호 객체입니다. 하트비트의 started.set()이 신호를 켜고, await started.wait()는 그 신호가 켜질 때까지 기다립니다. Before는 시작 신호를 받은 뒤 같은 실행 흐름에서 time.sleep(0.05)를 호출합니다. 이번 실행에서 하트비트는 block-end 뒤에 기록됐고, Before의 단언문은 이 관찰 순서를 검사합니다.
After는 같은 time.sleep(0.05)를 asyncio.to_thread로 다른 스레드에서 호출합니다. 출력의 True는 이번 실행에서 하트비트가 wait-end보다 먼저 기록되었다는 관찰입니다. After의 마지막 assert는 이 순서를 강제하지 않으며 wait-start, heartbeat, wait-end 세 사건이 모두 완료되었는지만 검사합니다. 이 결과는 보편적인 속도 향상이나 항상 같은 작업 순서를 보장하지 않습니다.
7주의할 점과 실무 메모
async def 함수를 호출만 하고 await하거나 태스크로 예약하지 않으면 함수 본문이 완료되지 않습니다. 실행기에서 경고가 나타날 수도 있습니다.
gather의 결과 순서는 완료 순서가 아니라 입력 순서입니다. 진행 상황이 필요하면 별도 기록으로 확인합니다.
Jupyter는 셀에서 최상위 await를 지원합니다. 일반 .py 파일에서는 보통 asyncio.run(main())으로 최상위 진입점을 만듭니다.
I/O(input/output)는 파일, 네트워크, 데이터베이스처럼 프로그램 밖과 데이터를 주고받는 작업입니다. to_thread는 바꿀 수 없는 동기 I/O 함수가 이벤트 루프를 막지 않게 옮길 때 주로 사용합니다. 계산 자체를 빠르게 만드는 기능으로 해석하지 않습니다.
실제 API에는 동시 요청 제한, 재시도, 시간 제한이 있습니다. 무제한으로 태스크를 만들지 않고 Ch 18에서 제공자 정책과 함께 다룹니다.
8정리와 다음 절
비동기 함수 호출은 코루틴을 만들며 await가 완료 결과를 받습니다.
여러 대기 작업은 함께 진행될 수 있지만 완료 순서와 gather 반환 순서는 다릅니다.
동기 차단 호출은 이벤트 루프를 멈추므로 변경할 수 없는 I/O 함수는 to_thread로 옮길 수 있습니다.

# 변수와 자료형
이름, 수량, 가격처럼 성격이 다른 값을 변수에 저장하고 계산 결과를 확인합니다.
## 실행 환경 준비
이 노트북은 Python 3.12 표준 기능만 사용합니다. 첫 셀부터 순서대로 실행합니다. `이름 = 값`은 오른쪽 값을 왼쪽 변수에 저장한다는 뜻입니다. 따옴표로 감싼 값은 문자열이고, 따옴표 없는 숫자는 계산에 사용할 수 있는 수입니다.
## 기본 실행
수량과 단가를 곱해 주문 금액을 계산합니다. `*`는 곱셈 기호입니다. `print(...)`처럼 이름 뒤에 소괄호를 붙이면 함수를 호출합니다. `type(quantity)`는 `quantity`에 저장된 값의 자료형을 반환하고, 뒤의 `.__name__`은 그 자료형의 이름만 읽습니다. `f"...{변수}..."`는 중괄호 자리에 변수 값을 넣어 출력할 문자열을 만드는 표기입니다.
## 중간 결과 관찰
회원 할인율을 10%로 저장하고, 계산에 사용한 값과 결과를 함께 확인합니다. 입력은 주문 금액 `order_total`과 할인율 `discount_rate`입니다. 두 값을 곱해 할인액을 처리하고, 주문 금액에서 할인액을 빼 결제 금액을 만듭니다. `:.0%`는 0.1을 10%로, `:.0f`는 소수점 아래 없이 표시하라는 출력 형식입니다. 저장된 값 자체를 바꾸지는 않습니다.
## 값 하나를 바꿔 비교
상품과 단가는 그대로 두고 수량만 3으로 바꿉니다. 원래 변수 `quantity`를 덮어쓰지 않고 `changed_quantity`라는 새 변수에 저장하므로 변경 전후를 같은 출력에서 비교할 수 있습니다.
## 실패 재현
입력으로 받은 수량은 문자열입니다. `input_quantity = "2"`의 따옴표가 이 값을 숫자 2가 아닌 글자 `2`로 만듭니다. 문자열에 정수를 곱하는 처리는 문자열 반복이므로 글자가 세 번 이어진 `"222"`를 반환합니다. 오류 메시지는 없지만 주문 수량 계산으로는 틀린 결과입니다.
## 수정
`int()`는 숫자 모양의 문자열을 입력받아 정수를 반환합니다. 반환된 `2`를 `converted_quantity`에 저장한 뒤 3을 곱하면 정수 `6`이 됩니다. 마지막 `assert correct_quantity == 6`은 `==`의 양쪽 값이 같은지 검사하며, 조건이 거짓이면 실행을 실패시킵니다.

# 조건문과 반복문
조건에 따라 배송비를 정하고, 여러 주문 금액을 순서대로 처리합니다.
## 실행 환경 준비
이 노트북은 Python 3.12 표준 기능만 사용합니다. 각 셀은 앞 셀의 결과를 이어서 사용합니다. 대괄호 안의 값은 다음 절에서 자세히 배우는 목록입니다. 여기서는 여러 금액을 앞에서부터 하나씩 읽기 위한 묶음으로 사용합니다.
## 기본 실행
주문 금액 다섯 개를 `if`, `elif`, `else`의 세 경로와 차례로 비교합니다. `for amount in test_amounts:`는 목록에서 값을 하나 꺼내 `amount`에 저장한 뒤 들여쓴 블록을 반복한다는 뜻입니다. 콜론 `:`은 다음 들여쓰기 블록이 시작됨을 표시합니다. `>=`는 왼쪽 값이 오른쪽 값보다 크거나 같은지 검사해 `True` 또는 `False`를 만듭니다. 위에서 처음 참이 된 블록 하나만 실행합니다.
## 중간 결과 관찰
`while`은 조건이 참인 동안 반복합니다. `len(amounts_with_stop)`은 목록의 항목 수 5를 반환하고, `amounts_with_stop[index]`는 위치 번호에 해당하는 값을 읽습니다. 위치 번호는 0부터 시작합니다. `index += 1`은 `index = index + 1`과 같은 뜻입니다. 먼저 위치를 늘린 뒤 음수는 `continue`로 현재 차례의 나머지를 건너뛰고, 0은 `break`로 반복 전체를 끝냅니다. `append()`는 처리한 금액을 빈 목록의 끝에 추가합니다.
## 값 하나를 바꿔 비교
주문 금액은 그대로 두고 무료 배송 기준만 40000원으로 낮춥니다. 두 개의 개수 변수를 0에서 시작하고, 조건이 참일 때마다 `+= 1`로 한 건씩 더합니다. 이 셀은 값을 반환하는 함수가 없으며, 반복이 끝난 뒤 두 변수에 누적된 결과를 출력합니다.
## 실패 재현
목록 길이가 3이면 사용할 수 있는 위치 번호는 0, 1, 2입니다. `len(order_amounts) + 1`은 4이고, `range(4)`는 0, 1, 2, 3을 차례로 제공합니다. 마지막 `order_amounts[3]`은 존재하지 않는 네 번째 항목을 요청하므로 `IndexError`가 발생합니다. `try`는 실행을 시도할 블록, `except IndexError as error`는 해당 오류가 생겼을 때만 실행할 블록입니다. 예외 처리는 05절에서 자세히 배웁니다.
## 수정
`enumerate(order_amounts)`는 목록을 입력받아 실제 항목마다 `(위치 번호, 값)` 한 쌍을 제공합니다. `for index, amount in ...`은 그 두 값을 각각의 변수에 나누어 저장합니다. 존재하는 항목만 처리하므로 범위를 직접 계산하지 않아 마지막 위치를 넘지 않습니다.

# 자료구조
목록, 튜플, 딕셔너리, 집합에 같은 주문 정보를 서로 다른 목적에 맞춰 저장합니다.
## 실행 환경 준비
이 노트북은 Python 3.12 표준 기능만 사용합니다. 네 자료구조의 출력 모양과 값을 찾는 방법을 비교합니다. 괄호 모양만 외우지 말고 순서가 필요한지, 값을 바꿀지, 이름으로 찾을지, 중복을 없앨지를 먼저 판단합니다.
## 기본 실행
각 자료구조에서 값을 읽는 방법을 확인합니다. `items[0]`의 대괄호는 목록의 위치 0을 읽고, `order['amount']`는 딕셔너리에서 `amount` 키와 짝인 값을 읽습니다. `'마우스' in unique_items`는 집합에 해당 값이 있는지 검사해 불리언을 반환합니다. 집합은 순서를 보장하지 않으므로 `sorted()`에 넣어 정렬된 새 목록을 반환받은 뒤 출력합니다.
## 중간 결과 관찰
목록에는 중복 상품이 남고 집합에는 고유한 상품만 남습니다. `len()`은 묶음을 입력받아 항목 수를 정수로 반환합니다. `order['item_count'] = item_count`는 딕셔너리에 새 키와 값을 추가합니다. 목록의 길이 3은 담긴 상품 수이고 집합의 길이 2는 서로 다른 상품 종류 수이므로 서로 다른 질문의 답입니다.
## 값 하나를 바꿔 비교
`items.copy()`가 반환한 새 목록을 `changed_items`에 저장한 뒤 `append('헤드셋')`으로 끝에 값을 하나 추가합니다. 원본 `items`는 유지됩니다. 변경한 목록을 `set()`에 입력하면 중복을 제거한 새 집합이 반환됩니다.
## 실패 재현
객체는 실행 중 만들어진 값의 실체이고 변수 이름은 그 객체를 가리킵니다. 같은 내용을 가진 별개 객체와, 한 객체를 가리키는 여러 이름을 구분합니다.
`backup = cart`는 `cart`의 내용을 복사하는 문장이 아닙니다. 두 변수 이름이 같은 목록 객체를 가리키게 합니다. 따라서 `cart.append('헤드셋')`으로 객체 하나를 수정하면 `backup`을 통해 읽은 내용에도 헤드셋이 나타납니다. `cart is backup`은 두 변수가 같은 객체를 가리키는지 검사합니다.
## 수정
`copy()`는 현재 항목을 담은 새 목록을 반환합니다. `backup = cart.copy()`로 반환값을 저장하면 두 변수는 서로 다른 목록 객체를 가리킵니다. 이후 원본만 수정하므로 백업은 수정 전 값 두 개를 유지하고, `cart is backup`은 `False`를 반환합니다.

# 파일과 예외
UTF-8 텍스트 파일을 안전하게 읽고, 예상한 오류만 처리하려면 어떻게 해야 할까요?
## 실행 환경 준비
Python 3.12 표준 라이브러리만 사용합니다. `from pathlib import Path`는 표준 라이브러리에서 경로를 다루는 `Path`라는 이름을 가져옵니다. 모듈 가져오기는 07절에서 자세히 배웁니다. `TemporaryDirectory()`는 실습 전용 폴더를 만들고 그 위치를 반환하므로 개인 파일을 변경하지 않습니다. `/`는 `Path` 뒤에서 사용할 때 폴더와 파일 이름을 연결합니다.
## 기본 실행
`read_items(path)`의 입력은 읽을 파일의 경로입니다. `path.read_text(encoding="utf-8")`가 파일의 바이트를 UTF-8 규칙으로 해석해 하나의 문자열을 반환합니다. 이어서 `text.splitlines()`가 줄바꿈을 기준으로 문자열을 나누어 문자열 목록을 반환합니다. 타입 힌트는 07절에서 배우므로 여기서는 함수의 입력과 반환을 문장으로 확인합니다.
## 중간 결과 관찰
읽은 각 줄을 쉼표에서 나누어 상품명과 수량을 확인합니다. `line.split(",")`은 한 문자열을 입력받아 쉼표 기준의 문자열 목록을 반환합니다. 왼쪽의 `name, count_text`는 반환된 두 항목을 차례로 나누어 저장합니다. 파일에서 읽은 `count_text`는 문자열이므로 `int()`로 정수로 바꾼 뒤 `(상품명, 수량)` 튜플을 반환합니다. 반복문으로 각 줄의 반환값을 `parsed` 목록에 추가합니다.
## 값 하나를 바꿔 비교
같은 인코딩과 처리 함수를 유지하고 파일 내용의 수량만 바꿉니다. 파일을 다시 읽은 결과도 기본 반복문으로 처리합니다. `parsed[0][1]`은 첫 번째 주문 튜플의 두 번째 값인 수량을 읽습니다.
## 실패 재현
존재하지 않는 파일 경로를 `read_items()`에 입력하면 파일 읽기 처리에서 `FileNotFoundError`가 발생하며 정상 반환값은 만들어지지 않습니다. `try` 블록이 읽기를 시도하고, `except FileNotFoundError as error`가 그 종류의 예외만 받아 다음 문장을 실행합니다. `else`는 예외가 발생하지 않았을 때 실행되며, 이 실험에서는 예상한 실패가 없었다는 뜻이므로 `AssertionError`를 발생시킵니다.
## 수정
파일 경로를 입력받아 기존 `read_items()`로 처리하되, 파일이 없을 때만 빈 목록을 반환하는 함수를 만듭니다. 정상 파일이면 문자열 목록이 반환되고, 누락 파일이면 `except FileNotFoundError`의 빈 목록이 반환됩니다. 다른 종류의 오류는 이 블록과 일치하지 않으므로 감추지 않고 호출한 곳으로 이어집니다.
마지막에는 파일 누락과 다른 오류를 확인합니다. `parse_order("연필,많이")`는 파일을 읽는 대신 전달한 문자열의 수량을 정수로 바꾸려다 실패합니다. 바깥의 `except ValueError`는 실제 오류 이름과 메시지를 출력하며, 주문 처리 함수가 잘못된 수량을 정상 값으로 바꾼 것은 아닙니다.

# 클래스
서로 다른 주문 객체가 각자의 상태를 따로 유지하게 만들려면 어떻게 해야 할까요?
## 실행 환경 준비
Python 3.12 내장 기능만 사용합니다. 외부 파일과 이전 노트북의 변수는 필요하지 않습니다. 클래스 본문도 함수와 마찬가지로 콜론 다음 줄을 들여씁니다. 타입 힌트는 07절에서 배우므로 이 노트북의 클래스에는 사용하지 않습니다.
## 기본 실행
`class Order:`는 `Order`라는 새 객체 유형을 정의합니다. `Order("민지")`처럼 클래스 이름을 호출하면 새 인스턴스가 만들어지고 `__init__`이 자동으로 실행됩니다. 호출에서 입력한 `"민지"`는 `customer` 매개변수로 들어갑니다. `self`는 지금 만들고 있는 인스턴스를 가리키므로 `self.customer = customer`는 입력값을 그 객체의 속성에 저장합니다. `self.items = []`는 객체마다 새 빈 목록을 만듭니다.
## 중간 결과 관찰
같은 클래스에서 두 인스턴스를 만듭니다. `second.add("연필")`을 호출하면 점 왼쪽의 `second`가 메서드 안의 `self`로 전달되고 문자열은 `item`으로 전달됩니다. `is`는 두 값의 내용이 같은지가 아니라 두 변수가 메모리의 같은 객체를 가리키는지 검사합니다. 두 주문의 목록이 분리되었다면 `first.items is second.items`는 `False`입니다.
`is not`은 두 이름이 서로 다른 객체를 가리키는지 확인합니다. `first.items is not second.items`가 참이면 두 주문의 목록은 별개 객체입니다.
## 값 하나를 바꿔 비교
입력으로 `"지우개"`를 첫 번째 주문의 `add()`에만 전달합니다. 메서드는 `first.items`를 변경하며 별도 값을 반환하지 않습니다. 두 번째 주문의 목록을 출력해 `['연필']`로 유지되는지 확인합니다.
## 실패 재현

Python 3.12 표준 라이브러리와 Jupyter의 최상위 `await`를 사용합니다. 이 절은 A·B 경로가 다시 합쳐지는 필수 절입니다. A 경로의 01~08절 가운데 특히 04절의 함수 호출·반환과 07절의 타입힌트를 사용합니다. B 경로의 09절 데코레이터와 `with`, 10절 Pydantic, 11절 fixture와 패키징은 필요하지 않습니다.
## 기본 실행: 코루틴 만들고 기다리기
`async def fetch_label(name: str, delay: float) -> str`는 문자열 이름과 초 단위 실수 대기 시간을 입력받아 최종적으로 문자열을 반환하는 비동기 함수를 정의합니다. 이 타입힌트 표기는 07절에서 배웠습니다. 호출 직후에는 본문 결과가 아니라 코루틴 객체가 반환됩니다. Jupyter 셀의 `result = await pending`은 코루틴이 아직 완료되지 않았다면 기다리는 동안 다른 작업에 실행 기회를 주고, 완료되면 최종 문자열을 받습니다.
## 태스크와 gather: 완료 순서와 반환 순서
이벤트 루프는 대기 중인 코루틴 사이에서 실행 순서를 조정합니다. 태스크는 코루틴을 이벤트 루프에 예약한 객체입니다. `tracked()`는 세 번째 인자로 받은 `progress` 목록에 완료된 이름을 추가합니다. 함수 밖에서 만든 목록도 함수 인자로 전달하면 같은 목록 객체를 수정할 수 있습니다. `gather`는 코루틴들을 함께 진행하고 모두 끝난 뒤 입력 순서의 결과 목록을 반환합니다.
## 순차 대기와 동시 대기 시간 비교
첫 측정은 `await fetch_label(...)`을 두 번 차례로 호출하므로 첫 반환 뒤에 둘째 호출이 시작됩니다. 다음 측정은 두 코루틴을 한 번의 `gather`에 입력하므로 두 대기가 함께 진행됩니다. 시간은 현재 컴퓨터에서 측정한 값이며 보편적인 속도 향상 비율을 뜻하지 않습니다.
## Before: 동기 sleep이 이벤트 루프를 막음
`asyncio.Event()`는 코루틴 사이에서 한 사건의 발생 여부를 알리는 신호 객체입니다. `started.set()`은 신호를 켜고, `await started.wait()`는 신호가 켜질 때까지 기다립니다. `create_task(record_heartbeat(events, started))`가 하트비트를 예약한 뒤 시작 신호를 확인합니다. 이어서 동기 `time.sleep`이 이벤트 루프를 실행하는 한 작업 흐름을 점유하므로 하트비트는 이 호출이 반환된 뒤에야 이어집니다.
## After: to_thread로 동기 작업을 이벤트 루프 밖에서 실행함
스레드는 한 프로세스 안에서 실행 흐름을 나누는 단위입니다. `asyncio.to_thread(time.sleep, 0.05)`는 동기 함수와 인자를 이벤트 루프와 다른 스레드에서 호출합니다. 이 호출이 완료되지 않은 동안 현재 코루틴이 기다리면 하트비트 태스크가 실행될 수 있습니다. 출력의 `True`는 이번 실행에서 `heartbeat`가 `wait-end`보다 먼저 기록됐다는 관찰입니다. 마지막 `assert`는 순서를 강제하지 않고 세 사건이 모두 기록됐는지만 검사합니다.
