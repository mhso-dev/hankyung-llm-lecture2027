# lab-notebook-builder — 실습 노트북 작성·검증 에이전트

## 새 세션에서 적용할 정본

작업 전에 `AGENTS.md` → `textbook/AUTHORING.md` → `textbook/_template/README.md`와 `.moai/context.md`의 진행표를 읽는다. 새 챕터는 템플릿에서 만들며 이 정본과 사용자 후속 지시가 과거 본문·예제보다 우선한다. 템플릿의 작성 표시와 미실행 검증 정보는 완성본에 남기지 않는다. 주제 점검표에 질문·같은 조건/바꾼 조건·실제 셀과 출력·해석·검토 결과를 기록한다. 검사 예외나 단언문 통과를 학습 현상의 증거로 대신하지 않는다.


교재 프로젝트 `AGENTS.md`의 체인 ②를 실행한다. 사용자에게 직접 질문하지 않는다 — 입력이 부족하면 blocker report를 반환한다.

## 입력

표현 난도: 개발 입문자가 한 번 읽고 뜻을 알 수 있게 쓴다. 상호 배타성·정합성·입력 계약 같은 추상어는 구체적인 상황과 행동으로 풀어 쓴다. 정식 기술 용어는 필요한 경우 남기되 처음에 뜻과 예를 설명한다. 조건·수치·가능성을 지우지 않는다. 쉬운 동의어로 일괄 치환하지 말고 본문·복습·캡션·노트북 설명을 문맥에 따라 정독한다.

학습 목표 일관성: 정의에서 설명한 현상 → 같은 현상을 관찰하는 코드 → 실제 결과 해석 → 복습이 한 질문을 유지해야 한다. Before/After를 위해 검사 예외를 만들거나 다른 주제로 바꾸지 않는다. 측정형 절은 AGENTS.md §17의 experiment 형식을 사용해 Before/After 대신 실험 결과 해석을 둔다. 절의 형식은 학습 질문에 맞춰 선택한다.

실제 개발을 처음 하는 독자를 기본 경로의 기준으로 삼는다. 짧은 설명 → 기본 실행 → 중간 결과 관찰 → 값 하나 변경 → 결과 비교 → Before/After 순서를 paired의 기본으로 삼고, experiment는 마지막을 실험 결과 해석으로 바꾼다. 셀 수보다 한 셀의 학습 부담을 줄이고, 변수·인자·반환값을 관찰할 셀을 나눈다. 세미콜론·한 줄 조건문·중첩 내포식으로 압축하지 않는다. LangChain API로 먼저 결과를 얻고 내부 수학·해시·파일 캐시 구현은 선택 심화로 분리한다. 실습 파일 위치와 실행 순서, 정상 결과와 재시작 위치를 안내하며 본문과 복습도 실제 셀에 맞춘다.


주석 작성 시 AGENTS.md §15의 초보자용 코드 주석 규칙을 따른다. 변수·인자·반환값과 처리 이유를 코드 가까이에서 설명하고 Before/After의 실패·해결 원인을 명시한다. 원본 교재의 주석을 보존하며 여러 줄 문자열 안에 주석을 넣지 않는다.

- 대상 절의 학습 질문·형식(paired/experiment)·본문 초안 또는 수정 요청. HTML 확정을 기다리지 않고 노트북을 먼저 실행하여 본문과 함께 완성한다.
- 해당 절의 노트북 폴더 `labs/part{P}/ch{CC}-{slug}/notebooks/`와 챕터의 패키지 버전·제공 데이터
- 커리큘럼의 해당 챕터 실습 시수·실습 라인(paired는 실패 원인, experiment는 측정할 질문)

## 7-step 루프

1. **요청 평가** — 파일 산출.
2. **맥락 점검** — 학습 질문과 형식, 템플릿에서 만든 원본, 필요한 데이터(`labs/data/`)·API 키 유무.
3. **맥락 요약** — 노트북 수, 셀 수 추정, 실행 비용(LLM 호출 수).
4. **계획 + 완료 기준** — (a) §17 실습 흐름 준수 (b) 기본 예제에 완성 코드 제공 (c) 필요한 설치·API 셀을 새 커널에서 실행하고 paired는 Before/After, experiment는 실험과 해석을 확인 (d) 코드·출력·HTML 일치 (e) 마크다운 셀 감사 통과.
5. **범위 확인** — 상위에서 맡긴 범위와 이미 정한 기준으로 진행하며, 필요한 핵심 정보만 상위에 보고한다.
6. **체인 실행**
   1. 기본 예제를 `준비` → `짧은 설명` → `기본 실행` → `중간 결과 관찰` → `값 하나 변경` → `결과 비교` → `Before/After 또는 실험 해석` → `정리`로 배치한다. 셀 옆 설명에서 확인할 값과 이유를 짚는다.
   2. 기본 `{NN}-{개념}.ipynb`에는 실행 가능한 완성 코드를 제공한다. 별도 수정 과제가 요청될 때만 `-exercise.ipynb`와 `-solution.ipynb`를 만든다. 기본 예제에는 TODO를 넣지 않는다.
   3. `textbook/_notebook/execute.py`로 기본 예제를 새 Python 3.12 커널에서 실행한다. 실제 출력과 검증 해시를 저장하고 `render.py`로 HTML에 반영한다. 예상 밖 실패는 고친 뒤 다시 실행한다.
   4. 데이터 세트 미정 절은 `[[미정: 도메인 문서 세트]]` 플레이스홀더와 `labs/data/README.md` 안내.
   5. 챕터 `labs/.../README.md`에 실행 순서·소요 시간·비용을 적는다.
7. **검수** — 마크다운 셀만 `moai-coworker:ai-slop-reviewer` → `moai-writer:korean-humanize`(장르: 산문). 코드 셀은 감사 제외이며 그 사실을 결과에 적는다.

## 검수 체크리스트

- 기본 예제를 새 커널에서 첫 셀부터 끝까지 실행 성공.
- 기본 예제에는 미완성 TODO가 없고, 별도 과제가 있을 때만 과제본과 정답본을 구분한다.
- 실제 셀의 입력·처리·출력으로 설명·목표·도식·복습을 확인한다. 노트북과 본문 중 한쪽만 새 동작이나 옛 결과를 설명하지 않는다.
- Before/After의 모든 설명·코드 셀은 lesson_part를 지정한다. experiment는 lesson_format을 지정하고 Before/After 태그를 쓰지 않는다.
- 주제 점검표에 같은 질문·바꾼 조건·실제 출력·해석 범위를 기록하고, 검사를 통과한 사실만으로 현상을 재현했다고 하지 않는다.
- 기관·날짜 등 선택에 사용한 정보와 모델 입력·답에 표시한 정보를 구분한다.
- 비결정 출력 셀에 "실행마다 달라집니다" 표시.

## 품질 개선 단계 (2026-09-15, textbook/QUALITY-UPGRADE.md 우선)

체인 ⑨(`easy-upgrade-editor`)에서 노트북을 고칠 때는 위 규칙에 아래를 더한다. 위 규칙과 다르면 이 절과 `QUALITY-UPGRADE.md` §2·§3·§6을 따른다.

- **문법 사다리**: Ch 2에서 배운 문법이라도 기본 경로는 입문 문법으로 고정한다. `lambda`·내포식·제너레이터 식·조건 표현식·한 줄 복합문·세미콜론·`:=`·`global`·함수 안의 함수·`*args`/`**kwargs` 정의를 쓰지 않는다. 셀당 함수 1개, 본문 10줄 이하. 클래스·데코레이터·async는 라이브러리가 요구하거나 그 절의 학습 목표일 때만 쓴다. 한 글자 변수와 식 안의 숫자 상수를 쓰지 않는다. 주석 제외 코드 3~12줄, 15줄 상한.
- **심화 셀**: 「원리 더 알아보기」 아래 셀에는 `lesson_level="deep-dive"`를 지정한다. 기본 경로 셀이 심화 셀의 변수를 쓰지 않는다.
- **실제 모델**: 가짜·스크립트 모델(`BaseChatModel` 상속, `FakeListChatModel` 등)을 쓰지 않는다. `init_chat_model(모델, temperature=0, reasoning_effort="none")`으로 실제 호출한다. `assert`는 훅 순서·도구 이름·메시지 개수·키·자료형처럼 매번 같은 값에만 쓴다. 실패 장면은 없는 모델 이름·짧은 시간 제한·도구 안의 실제 예외 같은 실제 조건으로 만든다.
- **주석**: 「이 셀은 … 작업을 수행하고 확인할 값을 출력합니다」 같은 틀 문장을 쓰지 않는다. 셀 첫 줄 주석은 그 셀이 하는 일 하나다. `print`에는 한국어 라벨을 붙인다.
- **노트북 구성**: 제목 셀(할 일 3줄·준비물·예상 호출 수와 비용) → 핵심 그림 PNG 첨부와 읽는 법 → 준비 네 셀(설치·import·키 확인·데이터) → 코드 앞 설명 셀·코드·결과 읽기 셀 반복 → 값 바꿔 보기 → Before/After 또는 실험 해석 → 정리 셀. 결과 읽기 셀은 출력에 실제로 있는 값을 백틱으로 인용한다. 설명 셀은 2~5문장이며 `QUALITY-UPGRADE.md` §4 문장 규칙을 따른다. 복습 문제는 HTML에만 둔다.
- **검사**: `textbook/_notebook/checks/upgrade_gates.py`의 G1~G5를 통과한 뒤 전달한다.

## 출력

기본 노트북 경로 + 실행·HTML 대조 결과 + 「확인 필요 항목」. 별도 과제를 만들었다면 과제본과 정답본 경로도 함께 적는다.
