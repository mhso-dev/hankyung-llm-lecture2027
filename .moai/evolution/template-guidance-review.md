# 새 세션·템플릿 집필 지침 독립 검토

- 검토일: 2026-09-09
- 판정: **APPROVE**
- 범위: `AGENTS.md`의 새 세션 절과 §14~17, `textbook/AUTHORING.md`, `textbook/_notebook/README.md`, Claude/Codex용 `textbook-writer`·`lab-notebook-builder`·`figure-maker` 지침
- 제외: 작성 중인 `textbook/_template` 구현과 도구 동작 검증은 이번 검토 범위가 아니다.

## 판정 근거

새 세션에서 읽을 문서와 우선순위가 명시되어 있고, HTML을 먼저 확정한 뒤 노트북으로 나누던 과거 절차보다 노트북과 본문을 함께 만드는 규칙이 우선한다고 분명히 적혀 있다. 개발 입문자는 준비 위치와 파일, 패키지와 키, 셀 실행 순서, 정상 결과, 오류 뒤 다시 시작할 위치를 안내받는다.

기본 실습은 짧은 설명, 기본 실행, 중간 결과 관찰, 값 하나 변경과 비교 순서로 진행한다. 모든 코드 셀의 한국어 주석, 주요 변수·인자·반환값과 낯선 문법 설명, 여러 줄 문자열의 삼중 큰따옴표, 코드 셀 첫 줄 위의 불필요한 빈 줄 금지 조건도 집필 지침과 에이전트 지침에 함께 반영되어 있다.

Ch 6 이후 생성·임베딩의 LangChain 기본 경로와 Ch 18 직접 SDK 실습의 예외 범위가 구분되어 있다. API를 사용하는 절만 실제 API 호출까지 검증하게 하여 로컬 처리 절에 불필요한 호출을 강제하지 않는다. 실행하지 못한 코드는 초안에서만 표시할 수 있고 학생 발행본에는 넣을 수 없다.

`paired`는 같은 질문과 조건을 유지한 실제 Before/After를 요구한다. 측정형 `experiment`는 억지 실패를 만들지 않고 실제 관찰과 한계를 설명하게 한다. 정적 검증은 실행·메타데이터·HTML 일치를 확인하고, 학습 질문과 코드·출력·해석·복습·도식의 연결은 사람이 별도로 정독하도록 구분되어 있다.

도식은 축·색·점·칸의 뜻과 실제 예제 한 값을 읽는 방법을 설명한다. 한 줄 요약 캡션과 필요한 읽는 법 설명을 분리해 문장 수를 고정하지 않는다. 공통 `chapter.css`·`theme.css`를 사용하므로 과거 챕터의 CSS나 요소를 그대로 복제하도록 유도하지 않는다.

## 반영 확인

초기 검토에서 발견한 LangChain 범위 충돌, Ch 9 빌더·도식 복제 지시, `paired` 실패 블록의 무조건 적용, 모든 절의 API 호출 강제, 미실행 코드의 학생 발행 가능성, 그림 설명 한 문장 고정, 캡션의 한국어 최종 정독 누락은 수정되었다. 추가 대조에서 확인한 오래된 `_build.py` CSS 지시, 에이전트의 무조건 API 실행 문구, 그림 설명 문장 수의 모호함, 모든 챕터에 백업 폴더가 있다는 단정도 해결되었다.

Claude Markdown 지침과 Codex TOML의 `developer_instructions`는 세 에이전트 모두 본문이 일치한다. 세 TOML 파일은 `tomllib`로 정상 파싱된다. 과거 상충 문구를 표적으로 다시 검색해 잔존 항목이 없음을 확인했다. 연결된 문서용 LSP가 없어 별도 LSP 진단은 수행할 수 없었으며, 구문 검증은 TOML 파싱으로 대신했다.

한국어 산문은 `ai-slop-reviewer`와 `korean-humanize`의 문맥 정독 기준으로 검토했다. 조건과 예외, 수치의 의미를 보존했고 내부 운영 문서의 행동 지침을 모호한 구호로 바꾸지 않았다. 외부 맞춤법 서비스에는 전송하지 않았다.

## 후속 검토 범위

`textbook/_template` 구현이 확정되면 이 지침의 생성 명령, 메타데이터, `paired`/`experiment` 렌더링, 복사·다운로드, 실행·주제 점검표가 실제 도구 동작과 일치하는지만 별도로 대조하면 된다.
