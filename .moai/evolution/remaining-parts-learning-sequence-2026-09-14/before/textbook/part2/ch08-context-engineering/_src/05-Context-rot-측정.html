1학습 목표

  • 입력이 길어졌다는 사실과 정답을 활용하는 성능이 낮아졌다는 사실을 구분할 수 있습니다.
  • 같은 질문과 근거에서 주변 문장 수만 늘려 세 길이의 입력을 만들 수 있습니다.
  • 각 길이를 세 번 호출하고 입력 토큰·실제 답·정답 확인 결과를 비교할 수 있습니다.
  • 성능 저하가 관찰되었는지 실행 결과에 근거해 설명하고, 이 작은 실험의 한계를 말할 수 있습니다.

2이 내용을 배우는 이유

04절에서는 입력에 포함된 정보가 답을 어떻게 바꾸는지 살펴보았습니다. 이번 절의 질문은 하나입니다. 같은 정답 근거를 넣었을 때, 입력이 길어지면 모델이 그 근거를 덜 정확하게 활용할까요? 이를 확인하려면 입력 토큰 수와 답의 정확성을 함께 비교해야 합니다. 토큰 수만 출력해서는 성능이 낮아졌는지 알 수 없습니다.

입력이 길어지면 모델이 그 안에서 필요한 문장을 찾고 답에 적용하는 능력이 낮아질 수 있습니다. 이 현상을 컨텍스트 로트(context rot)라고 부릅니다. 입력을 조금 늘리기만 하면 모든 질문에서 오답이 생긴다는 뜻은 아닙니다. 이 실습은 성능 저하가 일어났다고 미리 가정하지 않습니다. 길이에 따라 정답 확인 결과가 달라지는지 실제 답으로 확인합니다.

아래 코드는 하나의 휴관일 질문을 세 길이에서 반복합니다. 결과가 낮아지면 답 원문에서 어떤 오류가 생겼는지 확인합니다. 결과가 같으면 이번 조건에서는 저하를 관찰하지 못했다고 설명합니다. 두 경우 모두 실험의 결과이며, 관찰하지 않은 현상을 재현했다고 쓰지 않습니다.

3앞에서 배운 내용

  • 컨텍스트와 토큰 — 모델은 지시문과 자료, 질문을 입력으로 받습니다. 글자 수와 토큰 수는 다르며, 실제 입력 토큰은 호출 결과의 usage_metadata에서 확인합니다.
  • LangChain 모델 호출 — 앞 절에서 준비한 방식과 같은 init_chat_model()과 invoke()를 사용합니다. 응답 본문은 AIMessage.text에서 읽습니다.
  • 반복문과 딕셔너리 — 조건별 입력을 딕셔너리에 담고 반복문으로 호출합니다. 각 실행의 답과 토큰 수를 목록에 보관합니다.

4핵심 개념

입력의 양과 정답을 활용하는 성능

긴 회의록 가운데 “정기 휴관일은 월요일”이라는 문장이 있다고 생각해 봅니다. 회의록이 길어져도 그 문장은 그대로입니다. 모델이 계속 월요일이라고 답한다면, 자료가 늘었어도 이 문제의 정답은 유지한 것입니다. 긴 조건에서 화요일이라고 답하거나 필요한 정보를 찾지 못한다면, 그 실행에서는 정답 활용에 실패한 것입니다.

이 예에서는 입력 길이만 바꾸고, 모델이 정답을 맞혔는지 확인합니다. 입력이 길어서 비용이 늘어난 일, 질문을 잘못 입력한 일, 파이썬 코드가 오류로 멈춘 일은 정답 성능 저하와 다른 문제입니다. 이번 실습은 입력 길이와 정답 확인 결과만 비교합니다.

컨텍스트 로트 (context rot)
입력이 길어질 때 모델이 필요한 정보를 찾아 적용하는 성능이 낮아지는 현상입니다. 모델·과제·자료 구성에 따라 관찰 여부와 정도가 달라질 수 있습니다.
통제 조건 (controlled condition)
입력 길이의 영향만 비교하려고 바꾸지 않고 그대로 두는 항목입니다. 질문, 근거 문장, 모델, 지시문, 출력 상한, 근거를 자료 가운데에 두는 규칙을 같게 유지합니다.
반복 실행 (repeated run)
같은 입력을 다시 호출하는 것입니다. 한 번의 우연한 응답을 전체 경향으로 해석하지 않도록 각 길이를 세 번 실행합니다. 세 번은 통계적 결론을 내리기에 충분한 표본을 뜻하지 않습니다.
정답 확인 기준
코드는 답에 ‘월요일’과 출처 ‘E01 p.2’가 모두 들어 있는지 확인합니다. 이 검사는 두 문자열의 포함 여부만 판단하므로 답의 뜻까지 이해하지는 못합니다. 예를 들어 ‘월요일이 아닙니다’에도 ‘월요일’이 들어 있습니다. 따라서 자동 검사 결과와 답 원문을 함께 읽습니다.

도식 — 같은 문제에서 입력 길이만 늘려 비교하기

아래 세 상자는 모델에 보낼 입력 세 개입니다. 각 입력의 가운데에는 동일한 휴관일 근거가 있습니다. 짧은 입력에는 주변 문장을 넣지 않고, 중간 입력에는 근거 앞뒤로 같은 문장을 각각 120번, 긴 입력에는 각각 1,200번 넣습니다. 여기서 숫자는 문장 반복 수이며 토큰 수가 아닙니다.

‘가운데’는 정답 문장을 입력 자료의 앞뒤 주변 문장 사이에 둔다는 뜻입니다. 원본 PDF의 페이지 번호를 뜻하지 않습니다. 입력이 늘어나면 근거 앞의 문자 수는 늘지만, 자료 가운데에 둔다는 배치 규칙은 같습니다. 이번 실습에서 근거를 앞·가운데·뒤로 이동하는 별도 위치 실험은 하지 않습니다.

6실험 결과 해석

아래 표는 2026-09-09에 gpt-5.4-mini로 실행한 노트북의 실제 결과입니다. 각 조건의 세 호출에서 입력 토큰 수가 같아 한 값으로 표시했습니다.

입력 길이입력 토큰 수핵심어·출처 자동 확인답 원문 확인
short643 / 3세 답 모두 월요일과 E01 p.2를 올바르게 제시
medium2,2243 / 3세 답 모두 월요일과 E01 p.2를 올바르게 제시
long21,6643 / 3세 답 모두 월요일과 E01 p.2를 올바르게 제시

이번 실행에서는 성능 저하를 관찰하지 못했습니다. 입력 토큰은 늘었지만, 아홉 개의 답 모두 휴관일과 출처를 올바르게 답했습니다. 따라서 이 결과를 context rot의 발생 사례로 제시할 수 없습니다. 이 노트북은 같은 과제에서 입력 길이와 정답 활용 성능을 함께 측정하고 결과를 해석하는 실습입니다.

긴 입력에서 기준 충족 횟수가 줄었다면 해당 답을 먼저 읽습니다. 요일을 틀렸는지, 근거를 찾지 못했는지, 출처 형식만 달라졌는지를 구분합니다. 출처 표기 한 번이 빠진 것을 곧바로 모든 정보 활용 능력의 저하로 해석하지 않습니다. 같은 문제가 더 많은 반복과 다른 질문에서도 나타나는지 추가 측정해야 합니다.

세 길이의 결과가 같다면 “이번 모델, 질문, 자료 구성, 입력 길이 범위에서는 이 기준으로 저하를 관찰하지 못했다”고 정리합니다. “입력 토큰이 늘었으므로 context rot가 발생했다”거나 “이번에 모두 맞았으므로 context rot는 없다”는 결론은 모두 실행 결과를 넘어섭니다.

7주의할 점과 실무 메모

  • 작은 실험의 범위를 지킵니다. 정답 문장이 하나이고 주변 문장은 같은 문장의 반복입니다. 실제 긴 문서에서 여러 근거를 연결하는 과제의 난이도를 대표하지 않습니다.
  • 자동 검사와 의미 판단을 구분합니다. ‘월요일이 아닙니다’에도 ‘월요일’이 들어 있습니다. 자동 확인을 통과한 답도 원문을 읽어야 합니다. 이 문자열 검사를 완전한 정확도 지표로 사용하지 않습니다.
  • 반복 세 번으로 성능 순위를 만들지 않습니다. 응답은 실행마다 달라질 수 있습니다. 여러 질문과 충분한 반복을 사용한 평가는 Ch 11·15에서 다룹니다.
  • 입력이 길어지면 호출량도 늘어납니다. 전체 실습을 다시 실행하면 아홉 번의 API 호출이 추가됩니다. 길이를 더 늘리기 전에 입력 토큰과 모델의 한도를 확인합니다.
  • 같은 위치 규칙을 유지합니다. 이번 결과는 자료 가운데에 근거를 둔 조건의 결과입니다. 다른 위치에서도 같을 것이라고 가정하지 않습니다.

8정리와 다음 절

  • context rot를 살펴보려면 입력 토큰 증가와 정답 활용 성능의 변화를 함께 확인해야 합니다.
  • 같은 질문과 근거에서 주변 문장의 양만 바꾸고, 세 길이를 각각 세 번 호출했습니다.
  • 관찰된 답과 확인 기준으로 결론을 제한합니다. 저하가 나오지 않았다면 미관찰 결과로 기록합니다.

다음 학습과 이어지는 지점 — 06절에서는 필요한 자료만 전달하는 설계를 비교합니다. 이번 결과에서 성능 저하가 나왔는지와 별개로, 각 설계가 필요한 근거를 보존하면서 입력량을 어떻게 바꾸는지 살펴봅니다. 여러 질문을 사용하는 평가와 더 정교한 채점은 Ch 11·15에서 이어집니다.

9복습 문제

문제 4개 · 해설 포함

1. 입력 토큰 수가 늘었다는 출력만으로 context rot를 관찰했다고 말할 수 없는 이유는 무엇입니까?

입력의 양만 확인했기 때문입니다. 같은 과제에서 필요한 정보를 활용하는 성능이 낮아졌는지 답도 확인해야 합니다.

2. 이번 실습에서 바꾼 값 하나와 고정한 조건 세 가지를 쓰세요.

근거 앞뒤에 넣는 주변 문장의 반복 수를 바꿨습니다. 질문·정답 근거·모델을 고정했고, 지시문·출력 상한·근거를 가운데에 두는 규칙도 유지했습니다.

3. 긴 입력의 답이 ‘월요일이 아닙니다. [E01 p.2]’라면 자동 검사는 어떻게 판단하며, 사람은 무엇을 확인해야 합니까?

두 문자열이 있으므로 자동 검사는 통과합니다. 사람은 근거와 답의 의미를 비교하여 요일을 부정한 잘못된 답임을 확인해야 합니다.

4. 모든 길이에서 세 번 모두 올바르게 답했다면 어떤 결론을 쓸 수 있습니까?

이번 모델·질문·자료 구성·길이 범위에서는 저하를 관찰하지 못했다고 쓸 수 있습니다. 모든 긴 문서에서 성능이 유지된다는 결론은 내릴 수 없습니다.
