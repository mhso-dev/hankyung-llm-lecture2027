1학습 목표

  • 이 절을 마치면 Write와 Select가 컨텍스트 윈도 밖과 안을 어떻게 연결하는지 설명할 수 있습니다.
  • 이 절을 마치면 결정과 문서 조각을 외부 JSON 파일에 저장하고, 다시 읽어 메시지에 포함해야 하는 이유를 설명할 수 있습니다.
  • 이 절을 마치면 질문에서 정한 기관·주제·날짜를 조건문으로 비교하여 필요한 자료를 선택할 수 있습니다.
  • 이 절을 마치면 기관·주제·날짜로 자료를 선택하고, 답에 표시된 출처 식별자로 원문을 찾을 수 있습니다.

2이 내용을 배우는 이유

01절에서 컨텍스트에 사용할 수 있는 입력 가용분을 계산했습니다. 실제 업무 자료는 그 범위보다 길 수 있습니다. 모든 회의 기록과 규정을 매번 메시지에 복사하면 예산을 빠르게 사용하고, 현재 질문과 관련이 적은 문장이 답에 영향을 줄 수 있습니다. 긴 자료는 호출 밖에 보관하고, 이번 질문에 필요한 항목만 읽어 오는 절차가 필요합니다.

LangChain 팀은 컨텍스트를 다루는 여러 사례를 Write·Select·Compress·Isolate라는 네 이름으로 정리했습니다. 이 이름들은 업계가 공통으로 정한 공식 절차가 아니며, API가 이 순서대로 실행하도록 요구하지도 않습니다. 이 절에서는 그중 자료를 파일에 저장하는 Write와 필요한 자료를 골라 메시지에 넣는 Select를 다룹니다. 나머지 두 방법은 03절에서 살펴봅니다.

선택은 사람이 정한 조건문과 데이터로 수행합니다. 모델이 어떤 문서를 사용할지 판단하지 않으며, 임베딩이나 벡터스토어도 사용하지 않습니다. Ch 9에서는 사람이 정한 선택 기준의 일부를 검색으로 자동화합니다. 따라서 이 절의 기록 형식과 출처 식별자는 다음 챕터의 검색 결과를 이해하는 기초가 됩니다.

3앞에서 배운 내용

01절에서 외부 파일은 그 자체로 현재 컨텍스트가 아니라고 배웠습니다. 파일의 내용을 읽고 호출 메시지에 포함해야 모델이 참고할 수 있습니다. 또한 입력 가용분 안에서 지시, 질문, 근거를 배분했습니다. 이 절에서는 근거 전체를 넣지 않고 필요한 항목만 선택합니다.

Ch 6에서 작성한 모델 호출 코드에서 사용자 메시지를 만드는 위치를 찾습니다. Ch 7에서 지시와 근거를 나누어 배치한 방식을 다시 확인합니다. Select의 결과는 그 메시지의 근거 영역에 추가되며, 선택하지 않은 기록은 포함하지 않습니다.

4핵심 개념

비유 — 자료 보관함과 열람대

자료실에는 여러 기관의 규정과 회의 기록이 보관되어 있습니다. 질문을 처리할 때 모든 서류를 열람대에 펼치지 않습니다. 먼저 자료 목록에서 기관, 문서 종류, 적용 날짜를 확인합니다. 질문과 맞는 자료를 고른 뒤 그 문서만 열람대에 놓습니다. 보관함에 기록하는 일이 Write이고, 열람대에 놓을 자료를 고르는 일이 Select입니다. 모델은 열람대에 놓인 내용만 현재 답의 근거로 사용할 수 있습니다.

정의

Write (외부 기록)
나중에 사용할 결정, 문서 조각, 중간 결과를 현재 컨텍스트 윈도 밖의 변수나 파일에 저장하는 전략입니다. 이 절에서는 사람이 읽을 수 있는 JSON 파일을 사용합니다.
외부 저장소 (external store)
현재 모델 호출과 분리되어 정보를 보관하는 위치입니다. 파일, 데이터베이스, 객체 저장소 등이 될 수 있습니다. 저장되었다는 사실만으로 모델의 입력이나 학습 데이터가 되지는 않습니다.
Select (선택)
외부 기록 가운데 이번 질문에 필요한 항목을 골라 현재 호출 메시지로 가져오는 전략입니다. 이 절에서는 사람이 작성한 명시적 조건으로 선택합니다.
메타데이터 (metadata)
본문 옆에 항목별로 적어 두는 설명 정보입니다. 표의 열처럼 문서 식별자, 기관, 문서 종류, 적용 시작일, 상태를 따로 저장합니다. 프로그램은 이 항목을 비교하여 필요한 문서를 고릅니다.
출처 식별자 (source ID)
선택한 근거가 어느 기록에서 왔는지 추적하는 고유 값입니다. 답을 검토하거나 원문을 다시 열 때 사용합니다.
적용 조건 (applicability condition)
기록이 유효한 기관, 업무, 대상, 날짜, 버전의 범위입니다. 자료를 고를 때 이 조건을 확인하지 않으면 다른 기관이나 시점의 규정을 잘못 사용할 수 있습니다.

Write는 모델의 학습이나 자동 기억이 아닙니다

프로그램이 JSON 파일을 저장하면 다음 실행에서도 데이터를 다시 읽을 수 있습니다. 그러나 모델은 그 파일의 위치와 내용을 자동으로 알지 못합니다. 파일을 저장해도 모델 자체가 새 내용을 학습하는 것은 아니며, 제품 전체에서 자동으로 기억하는 기능이 생기지도 않습니다. 다음 호출에서 쓰려면 프로그램이 파일을 열고, 필요한 항목을 고른 뒤, 그 내용을 메시지에 넣어야 합니다.

이 구분은 디버깅에 필요합니다. 저장 파일에 올바른 값이 있는데 답이 틀렸다면 세 지점을 차례로 봅니다. 파일을 제대로 읽었는지, 올바른 항목을 선택했는지, 선택한 내용이 실제 메시지에 포함되었는지 확인합니다. “저장했으니 모델이 기억해야 한다”는 가정으로는 어느 단계가 빠졌는지 찾을 수 없습니다.

기록은 본문과 조건을 함께 보존합니다

Write 단계에서 문장만 저장하면 Select 단계가 판단할 정보가 부족합니다. 예를 들어 “매주 월요일에 운영하지 않는다”는 문장에는 어느 기관의 어느 시설인지, 언제부터 적용되는지, 현재 유효한지 나타나지 않습니다. 예를 들어 JSON 항목에 본문과 함께 출처 식별자, 기관, 문서 종류, 적용 날짜, 상태를 둘 수 있습니다. 이번 실습에서는 ID·기관·주제·적용일·본문을 기록합니다. 실제 필드 구성은 필요한 정보에 맞추되, 선택에 필요한 조건을 본문에서 분리하여 명시적으로 저장한다는 원칙을 지킵니다.

필드 역할선택에서 확인하는 내용이 정보를 기록하는 이유
출처 식별자어느 기록인가?원문 확인과 오류 추적
기관·대상질문의 대상과 같은가?다른 기관의 정보가 섞이는 것을 방지
문서 종류규정, 안내, 회의 기록 중 무엇인가?근거의 성격을 구분
적용 날짜·상태질문의 시점에 유효한가?폐기된 규정이나 아직 시행되지 않은 규정을 잘못 사용하는 일을 방지
본문질문에 답하는 사실이 있는가?답의 직접 근거

Select는 질문과 메타데이터를 함께 봅니다

이 절에서는 질문에 필요한 기관·주제·기준 날짜를 사람이 코드에 적습니다. 조건문은 기관과 주제가 맞고, 적용 시작일이 기준 날짜보다 늦지 않은 기록을 고릅니다. 출력된 ID와 본문을 읽어 대출·주차 기록이 선택되고 휴관 기록은 빠졌는지 확인합니다. 같은 규정의 여러 버전 중 최신 것을 고르거나 적용 종료일을 확인하는 기능은 이번 코드에 포함하지 않습니다.

이번 실습에서는 기관·주제·날짜를 자료 선택에 사용합니다. 선택을 마친 뒤에는 본문과 출처 식별자를 메시지에 넣고, 모델에게 답에도 그 식별자를 표시하도록 요청합니다. 답의 [E01-p3]를 저장된 기록의 ID와 비교하면 어떤 자료를 사용했는지 확인할 수 있습니다. 기관과 날짜를 답에 표시하는 기능은 이번 코드에 포함하지 않습니다.

점진적으로 필요한 내용만 엽니다

자료가 많을 때는 처음부터 모든 본문을 읽지 않아도 됩니다. 첫 단계에서는 식별자, 제목, 기관, 적용 날짜처럼 짧은 목록을 봅니다. 두 번째 단계에서 질문과 맞는 항목을 고릅니다. 세 번째 단계에서 선택한 항목의 본문만 읽습니다. 이를 점진적 공개(progressive disclosure)라고 합니다. 처음에는 얕은 정보를 보고, 필요한 경우에만 상세 내용을 여는 방식입니다.

점진적 공개가 언제나 더 빠르거나 더 적은 토큰을 보장하지는 않습니다. 목록의 메타데이터가 부정확하거나 선택 조건이 부족하면 필요한 문서를 놓칠 수 있습니다. 이 절에서는 사람이 후보와 원문을 확인하여 이 한계를 관찰합니다. Ch 9에서 검색이 선택을 자동화한 뒤에도 출처와 조건을 검토해야 하는 이유가 여기에 있습니다.

7주의할 점과 실무 메모

  • JSON 저장은 보안 저장을 뜻하지 않습니다. 개인 정보와 비밀 값은 평문 예제 파일에 넣지 않습니다. 실제 서비스에서는 접근 권한, 암호화, 보존 기간을 별도로 설계합니다.
  • 저장과 컨텍스트 포함을 구분합니다. 파일에 있는 데이터는 프로그램이 읽어 메시지로 전달하기 전까지 현재 모델 호출의 입력이 아닙니다.
  • 출처 식별자를 변형하지 않습니다. 요약이나 답을 만들 때도 원래 식별자를 유지해야 원문을 다시 확인할 수 있습니다.
  • 날짜 형식을 맞춘 뒤 비교합니다. 이 실습의 날짜는 모두 YYYY-MM-DD 형식이므로 문자열 순서와 날짜 순서가 같습니다. 이 합성 필드에서 effective_date <= as_of는 실습용 적용 시작일 당일부터 자료를 선택합니다. 서로 다른 날짜 형식을 받는 프로그램에서는 먼저 날짜 값으로 변환해야 합니다. 종료일이나 이전 버전의 폐기 여부를 판단하는 규칙은 추가로 작성해야 합니다.
  • Select의 누락 가능성을 기록합니다. 사람이 정한 규칙이 모든 표현을 포괄하지 못할 수 있습니다. 후보가 없으면 근거 없이 답을 만들기보다 선택 실패로 처리합니다.

8정리와 다음 절

  • Write는 정보를 컨텍스트 윈도 밖에 저장하며, 저장 자체는 모델 학습이나 자동 기억이 아닙니다.
  • Select는 질문과 메타데이터를 비교하여 필요한 기록을 고르고 현재 메시지로 가져옵니다.
  • 기관·주제·날짜는 선택 조건으로 사용하고, 본문과 출처 식별자는 모델에 전달하여 답의 근거를 확인합니다.

다음 학습과 이어지는 지점 — 03절에서는 선택한 기록이나 긴 대화가 여전히 예산보다 클 때 Compress로 줄이고, 서로 다른 업무 자료는 Isolate로 분리합니다. Ch 9에서는 이 절의 사람 선택을 검색이 수행하며, 출처 식별자와 메타데이터가 검색 결과를 검토하는 기준으로 이어집니다.

9복습 문제

문제 4개 · 해설 포함

[하] 1. JSON 파일에 기록한 사실을 모델이 다음 호출에서 사용하려면 반드시 어떤 단계가 필요합니까?

정답과 해설 — 프로그램이 파일을 읽고, 필요한 항목을 선택하여, 그 내용을 호출 메시지에 포함해야 합니다. 틀렸다면 이 절의 핵심 개념 ‘Write는 모델의 학습이나 자동 기억이 아닙니다’를 다시 봅니다.

[중] 2. 본문과 함께 출처 식별자와 적용 날짜를 저장해야 하는 이유를 각각 설명하세요.

정답과 해설 — 출처 식별자는 답의 근거가 된 원문을 다시 찾아 오류를 추적하게 합니다. 적용 날짜는 질문 시점에 유효한 기록인지 판단하게 합니다. 틀렸다면 이 절의 핵심 개념 ‘기록은 본문과 조건을 함께 보존합니다’를 다시 봅니다.

[중] 3. 문서 본문 전체를 처음부터 읽는 방식과 점진적 공개 방식의 차이를 세 단계로 설명하세요.

정답과 해설 — 점진적 공개는 먼저 식별자와 메타데이터 목록을 보고, 질문과 맞는 항목을 고른 뒤, 선택한 본문만 읽습니다. 모든 본문을 처음부터 현재 메시지에 넣지 않습니다. 틀렸다면 이 절의 핵심 개념 ‘점진적으로 필요한 내용만 엽니다’를 다시 봅니다.

[상·확장] 4. 같은 기관의 이전 규정과 현재 규정이 있을 때, 안전한 Select 규칙과 답의 출력 형식을 설계하세요.

정답과 해설 — 질문의 기준 날짜를 확인하고, 기관이 같으며 그 날짜에 유효한 기록을 선택합니다. 선택한 본문과 함께 출처 식별자·적용 기간을 메시지에 넣고, 답에는 사용한 출처 식별자를 표시합니다. 기준 날짜가 없으면 임의로 고르지 않고 추가 조건이 필요함을 표시합니다. 틀렸다면 이 절의 핵심 개념 ‘Select는 질문과 메타데이터를 함께 봅니다’를 다시 봅니다.
