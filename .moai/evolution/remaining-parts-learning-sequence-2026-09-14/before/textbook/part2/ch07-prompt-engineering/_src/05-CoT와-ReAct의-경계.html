1학습 목표

  • 사고의 연쇄와 ReAct가 제안된 배경과 두 기법의 적용 범위를 설명할 수 있습니다.
  • 모델의 비공개 내부 추론과 사용자가 확인할 수 있는 짧은 근거를 구분할 수 있습니다.
  • 같은 과제에서 최종 답 요청과 짧은 근거 요청의 출력·토큰·지연을 비교할 수 있습니다.

2이 내용을 배우는 이유

복잡한 문제를 모델에 맡길 때 “생각하는 과정을 모두 보여 달라”고 쓰면 답이 더 믿을 만해 보일 수 있습니다. 그러나 길게 생성된 설명은 모델이 실제로 계산한 내부 상태의 완전한 기록이 아니며, 설명이 자연스럽다는 이유만으로 결론이 맞다고 판정할 수도 없습니다. 고객 지원처럼 근거가 입력에 이미 있는 과제에서는 주문번호, 파손 상태, 필요한 사진처럼 사용자가 다시 확인할 수 있는 사실을 짧게 제시하는 편이 검토에 도움이 됩니다. 이번 절에서는 내부 추론 전문을 요구하지 않고도 결론과 공개 가능한 근거를 함께 받는 방법을 익힙니다.

ReAct는 이후 도구 사용 에이전트를 이해하는 데 필요한 개념입니다. 다만 이 시점에는 모델이 도구를 선택하거나 결과를 받아 반복하는 프로그램을 만들지 않습니다. Ch 20에서 ToolNode와 에이전트 실행 흐름을 배울 때 현재의 개념 경계를 다시 확인합니다.

3앞에서 배운 내용

Ch 6에서는 init_chat_model()로 모델을 준비하고 model.invoke(messages)로 한 번의 요청을 보냈습니다. AIMessage.text에서 공개된 답을 읽고 usage_metadata에서 입력·출력 토큰을 확인했습니다. 이번 챕터의 앞 절에서는 system 메시지에 공통 역할을, user 메시지에 현재 과제와 출력 조건을 두었습니다. 이번 실습도 같은 호출 함수를 사용하며, user 메시지의 요청 방식만 바꿉니다.

4핵심 개념

사고의 연쇄와 공개 근거

사고의 연쇄(Chain of Thought, CoT)는 중간 단계를 언어로 생성하도록 유도해 복합 추론 과제를 풀려는 프롬프트 전략으로 알려졌습니다. 이 기법의 효과는 모델과 과제에 따라 달라집니다. 공개된 OpenAI 모델 지침도 GPT-5 계열에는 상세한 단계 지시를 늘리는 방식보다 목표, 성공 기준, 제약, 출력 형식을 먼저 분명히 하도록 안내합니다. 따라서 “CoT를 쓰면 정확도가 높아진다”를 전제로 삼지 않고, 고정된 평가 자료에서 실제 결과를 측정해야 합니다.

공개 근거(brief evidence)는 답을 검토하는 사람이 입력에서 다시 찾을 수 있도록 사실이나 판단 기준을 짧게 적은 문장입니다. 예를 들어 “파손된 뚜껑이며 교환 접수에 사진이 필요함”은 주어진 문의와 규정에서 확인할 수 있습니다. 공개 근거는 모델의 비공개 내부 추론을 복원한 기록이 아닙니다. 근거 문장이 입력과 맞는지 사람이 대조할 수 있다는 점이 핵심입니다.

ReAct가 다루는 범위

ReAct는 추론(reasoning)과 행동(acting)을 결합한 접근입니다. 일반적인 실행 흐름에서는 모델이 현재 관찰을 바탕으로 다음 행동을 정하고, 도구가 반환한 관찰을 다시 받아 다음 단계를 정합니다. 이러한 반복에는 도구 권한, 종료 조건, 오류 처리, 상태 관리가 필요합니다. 이번 절의 노트북은 도구를 정의하지 않으며 모델 호출도 각 조건마다 한 번씩만 수행합니다. 따라서 짧은 근거가 포함된 응답을 ReAct 실행이라고 부르지 않습니다. 여기에서는 “관찰할 사실과 다음 행동을 구분한다”는 개념만 준비합니다.

5실행 예제

노트북은 깨진 텀블러 뚜껑 교환 문의를 두 조건으로 실행합니다. 첫 조건은 분류, 다음 행동, 고객 문장으로 이루어진 최종 답만 요청합니다. 둘째 조건은 내부 판단 과정을 공개하지 말라는 제약과 함께 입력에서 확인한 근거 한 줄을 추가하도록 요청합니다. 모델, 문의, 규정, 생성 상한, 포함 여부를 살펴볼 세 단어는 그대로 유지합니다. run()은 응답 원문, 사용량, 전체 호출 지연을 하나의 사전으로 반환합니다.

6실험 결과 해석

실행된 두 응답은 모두 ‘교환’, ‘A-1042’, ‘사진’을 포함했습니다. 최종 답만 요청한 조건은 입력 115토큰, 출력 87토큰, 전체 202토큰을 사용했고 응답 길이는 139자였습니다. 짧은 근거를 요청한 조건은 입력 134토큰, 출력 150토큰, 전체 284토큰을 사용했고 응답 길이는 251자였습니다. 실행 시점의 전체 호출 지연은 각각 1.187초와 1.393초였습니다. 둘째 조건은 요청 문구와 출력이 더 길었으며, 이번 한 번의 실행에서는 지연도 더 길었습니다.

둘째 응답에는 분류, 근거, 다음 행동, 고객 문장이 각각 나타났습니다. 근거 문장은 입력의 파손 사실과 사진 규정을 짧게 다시 확인했습니다. 두 응답 모두 이번에 확인한 세 단어를 포함했지만, 단어 포함만으로 어느 조건의 품질이 높다고 결론 내릴 수는 없습니다. 호출도 조건마다 한 번뿐이어서 지연 차이를 프롬프트 전략의 고정된 특성으로 일반화하지 않습니다. 이번 실험은 비공개 내부 추론을 수집하지 않았으며 ReAct의 도구 실행도 관찰하지 않았습니다.

7주의할 점과 실무 메모

  • 모델이 작성한 근거 문장이 자연스러워도 입력이나 공식 자료에서 다시 확인해야 합니다. 공개 근거는 사실 확인 절차를 대신하지 않습니다.
  • 상세한 단계별 풀이 지시는 입력·출력 토큰과 지연을 늘릴 수 있습니다. 정확도 개선 여부는 대표 평가 자료와 미리 정한 채점 기준으로 확인합니다.
  • 고객 개인정보, 내부 정책, 비공개 판단 기준을 근거 문장에 그대로 노출하지 않습니다. 사용자에게 공개해도 되는 사실의 범위를 먼저 정합니다.
  • 도구 호출이 필요한 과제는 권한과 실패 처리를 함께 설계해야 합니다. 이번 절의 한 번 호출 예제를 도구 사용 에이전트로 확장하지 않습니다.

8정리와 다음 절

  • 사고의 연쇄는 모델과 과제에 따라 측정해야 하는 프롬프트 전략입니다.
  • 짧은 공개 근거는 입력에서 다시 확인할 사실을 제시하며 내부 추론 전문과 구분됩니다.
  • 이번 실습은 조건마다 모델을 한 번 호출했으며 ReAct의 도구 반복 흐름을 구현하지 않았습니다.

다음 학습과 이어지는 지점 — 다음 절에서는 한 응답의 설명을 길게 받는 대신 같은 질문을 독립적으로 여러 번 실행하고, 공개된 최종 분류만 모아 표본 합의를 계산합니다.

9복습 문제

문제 1

짧은 공개 근거를 모델의 내부 추론 기록으로 취급하면 안 되는 이유는 무엇인가요?

해설 — 공개 근거는 사용자가 검토하도록 생성된 문장입니다. 모델 내부 상태의 완전한 기록이 아니므로 입력 사실과 별도로 대조해야 합니다.

문제 2

이번 실험이 ReAct 실행이 아닌 근거를 코드에서 어떻게 찾을 수 있나요?

해설 — 도구 정의와 도구 호출 결과를 다시 모델에 전달하는 반복이 없습니다. 각 조건은 정해진 메시지로 invoke()를 한 번 수행합니다.

문제 3

두 조건에 세 단어가 모두 포함되었다는 사실만으로 답의 품질이 같다고 할 수 있나요?

해설 — 할 수 없습니다. 단어 포함 검사는 문맥, 사실성, 불필요한 약속을 판정하지 않으므로 응답 원문을 평가 기준에 따라 읽어야 합니다.

문제 4

상세한 단계 지시를 도입하기 전에 무엇을 고정하고 측정해야 하나요?

해설 — 모델, 과제, 입력 자료, 생성 설정, 평가 기준을 고정하고 정답률이나 기준 충족 여부, 토큰, 지연을 반복 측정해야 합니다.
