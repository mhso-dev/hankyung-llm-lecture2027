1학습 목표

  • 공식 공개 자료에서 모델 판단·도구 사건·프로그램 제한을 구분할 수 있습니다.
  • 공개 추적 단서와 로컬 실행 로그의 증거 수준 차이를 설명할 수 있습니다.
  • 중간 프로젝트의 자율성 진단표 한 장을 근거와 함께 작성할 수 있습니다.

2이 내용을 배우는 이유

‘실제 에이전트 제품’이라는 이름만 비교하면 어떤 결정이 모델에 있고 어떤 제한이 코드에 있는지 보이지 않습니다. 실행 과정을 사건 단위로 나누면 도구 결과, 턴 상한, 권한 경계, 완료 증거를 구분할 수 있습니다. 다만 공식 소개 페이지가 전체 원시 로그를 공개하지 않는 경우도 많습니다. 이때 확인한 사실과 알 수 없는 내부 과정을 분리해 적는 태도가 추적 분석의 첫 기준입니다.

3앞에서 배운 내용

앞의 네 절에서 결정 주체, 워크플로우 적합 조건, 정지 조건, 궤적 지표를 배웠습니다. 중간 프로젝트에서는 검색→생성→출처 검증 순서를 직접 작성했습니다. 이 절은 그 프로젝트를 진단표에 넣고 Ch 20의 실제 비교 실험에서 무엇을 측정할지 준비합니다.

4핵심 개념

쉬운 예와 정의

경기 중계의 하이라이트와 전체 심판 기록은 증거의 깊이가 다릅니다. 하이라이트로 확인한 장면은 말할 수 있지만 보이지 않은 모든 판정을 추정해서는 안 됩니다. 트레이스(trace)는 한 요청의 처음부터 끝까지 연결된 실행 기록입니다. 스팬(span)은 모델의 생성이나 도구 호출처럼 시작과 끝이 있는 하나의 작업 단위입니다. 공개 추적 단서는 제품의 공식 문서가 공개한 로그 유형, 사건 이름, 제한 옵션, 행동 경로입니다. 원시 로그(raw log)는 특정 실행에서 실제로 저장된 사건과 입력·출력입니다. 증거 수준은 출처가 실제 실행 원문인지, 공식 동작 설명인지, 교육용 재구성인지 구분하는 표시입니다. 자율성 진단은 문제의 불확실성, 결정권, 부작용, 정지 조건, 측정 계획을 한 장에 정리하는 절차입니다.

판단 절차

먼저 원시 궤적의 저장소, 커밋, 해시, 라이선스를 확인합니다. 다음으로 사건 순서를 변경하지 않고 행동과 관찰을 짝지어 적습니다. 실패 직후의 다음 행동을 찾아 모델이 환경 피드백에 반응한 자리를 표시하고, 도구 검사·턴 상한·완료 명령처럼 코드가 강제한 경계를 따로 표시합니다. 마지막으로 성공 출력, 요구 충족, 범위 준수, 종료 증거를 서로 다른 평가 질문으로 남깁니다.

6실험 결과 해석

SWE-agent v0.7.0 공개 demonstration은 14개의 action-observation 사건을 포함했습니다. 재현 스크립트가 344를 출력한 뒤 대상 코드를 찾았고, 10번째 편집은 들여쓰기 오류로 도구가 거부했습니다. 다음 사건에서 들여쓰기를 고쳐 다시 편집하고 재현값 345를 확인한 뒤 패치를 제출했습니다. mini-SWE-agent 공개 fixture는 10개의 명령 사건을 포함했습니다. 처음 시도한 절대 경로 읽기가 실패하자 저장소와 tests 폴더를 확인했고, 문법 오류를 고친 뒤 실행값 8.2를 확인했습니다. 원래 입력 23÷0에서는 ZeroDivisionError가 발생해 0 검사를 추가했습니다. 마지막에는 시스템이 단독 완료 명령을 요구했는데 git 명령을 결합했으며 반환 코드를 기록하는 래퍼도 없어 규칙 준수와 완료 증거가 불충분합니다. 두 자료는 커밋과 SHA-256으로 고정된 실제 공개 실행 궤적이지만 이 컴퓨터에서 제품을 다시 실행한 결과는 아닙니다. Codex·Claude Code·Deep Research 자료는 보조적인 공식 추적 단서로만 구분했습니다. 작성 예시의 규정 RAG는 자율 재검색이 품질을 높인다는 측정 결과가 없어 ‘워크플로우 유지’로 판정했습니다.

7주의할 점과 실무 메모

  • 실제 공개 궤적은 저장된 당시 제품 버전의 행동입니다. 최신 제품 전체의 성능으로 일반화하지 않습니다.
  • mini-SWE-agent fixture에서 0 검사를 추가한 행동이 원래 요청 범위에 맞는지는 별도 평가가 필요합니다. 실행 성공과 요구 충족을 구분합니다.
  • 원시 파일은 MIT 라이선스이며 실습 추출본에 저장소·커밋·원문 URL·SHA-256을 남겼습니다.
  • 진단표의 결론은 현재 증거를 바탕으로 한 결정이며 Ch 20 비교 결과가 나오면 갱신합니다.

8정리와 다음 절

  • SWE-agent와 mini-SWE-agent의 실제 공개 궤적에서 실패와 회복 순서를 확인했습니다.
  • 제품 설명의 추적 단서와 특정 실행의 원시 로그를 구분합니다.
  • 현재 증거가 고정 경로를 지지하면 ‘워크플로우 유지’도 타당한 진단 결과입니다.

다음 학습과 이어지는 지점 — Ch 18에서는 고정된 네 패턴과 동적으로 작업을 나누는 오케스트레이터-워커를 직접 구현합니다. Ch 20에서는 이 과정에서 처음으로 ToolNode 그래프 루프가 모델의 도구 선택을 받아 실행되며, 고정 분기와 비용·지연·결과 편차를 실제로 비교합니다.

공개 추적 단서와 원시 로그의 차이는 무엇인가요?
