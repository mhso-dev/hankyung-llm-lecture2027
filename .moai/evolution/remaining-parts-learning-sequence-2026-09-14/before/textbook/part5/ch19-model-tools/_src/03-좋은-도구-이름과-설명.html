1학습 목표

  • 서로 겹치지 않는 도구 이름과 설명을 작성할 수 있습니다.
  • 목록·단건·집계 도구의 입력과 반환 목적을 구분할 수 있습니다.
  • 설명서의 문자 수와 실제 토큰 수가 다른 측정값임을 설명할 수 있습니다.

2이 내용을 배우는 이유

도구가 세 개가 되면 이름만 보아도 목록 조회, 한 건 조회, 집계를 구분할 수 있어야 합니다. 모델이 읽는 설명서를 출력해 사람도 그 차이를 점검합니다.

Ch 20에서 ToolNode로 실행 흐름을 조립하기 전에 도구 한 개가 어떤 정보와 결과를 주고받는지 확인합니다.

3앞에서 배운 내용

01절의 상태별 목록 조회에 정확한 주문 ID 조회와 상태별 금액 집계를 더합니다. 세 함수는 모두 같은 Ch 4 CSV를 읽지만 반환 목적이 다릅니다.

실행 파일은 labs/part5/ch19-model-tools/data/orders.csv를 사용하며 Part 1 모듈을 런타임에 import하지 않습니다.

4핵심 개념

비유로 먼저 이해하기

도구 설명서는 주문서와 비슷합니다. 모델은 함수 내부를 보지 않고 이름, 설명, 선택 항목을 보고 요청합니다.

정의

도구 이름은 동작과 대상을 함께 드러내야 합니다. 설명은 언제 이 도구를 골라야 하는지와 반환값을 짧게 밝힙니다. 세 도구가 목록 조회, ID 조회, 집계로 나뉘면 질문의 의도와 대응시키기 쉽습니다.

목록 조회는 여러 행을 반환하고, ID 조회는 한 행을 반환하며, 집계는 count와 total을 새로 계산합니다. 세 도구의 입력 이름도 status, order_id, status로 나뉩니다. 이름만 길게 만든다고 좋은 설명이 되지는 않습니다. 언제 선택하는지와 무엇을 반환하는지가 서로 겹치지 않아야 합니다. 노트북이 출력하는 문자 수는 description과 args가 공짜가 아니라는 점을 눈으로 확인하기 위한 값입니다. 실제 토큰 수는 모델의 토크나이저와 직렬화 형식에 따라 달라지므로 문자 수를 비용으로 환산하지 않습니다.

도구 호출(tool call)은 구조화된 실행 요청이며 도구 메시지(ToolMessage)는 실행 결과와 호출 ID를 돌려주는 메시지입니다.

5실행 예제

각 도구의 name, description, args를 그대로 출력하고 설명과 스키마의 문자 수도 측정합니다. 이 수치는 토큰 수가 아니며 설명서 크기를 비교하는 보조 관찰입니다.

빈 Python 3.12 커널에서 준비 셀부터 실행합니다. 모델 호출이 있는 절은 gpt-5.4-mini, temperature=0을 사용하며 키 값은 출력하지 않습니다.

6실험 결과 해석

세 도구의 name, description, args를 나란히 놓으면 목록·단건·집계의 경계를 확인할 수 있습니다. 문자 수는 설명서의 상대적 크기를 보여 주지만 모델이 청구하는 토큰 수를 뜻하지는 않습니다.

출력 읽기

세 설명서를 표처럼 읽어 봅니다. list_orders_by_status는 상태로 여러 주문을 찾는 질문에 대응합니다. get_order_by_id는 O103처럼 식별자가 들어간 질문에 대응합니다. summarize_order_amounts는 개별 행 대신 건수와 합계를 요구하는 질문에 대응합니다. 설명에 이 차이가 나타나지 않으면 모델은 인자 이름만으로 추측해야 합니다. args 출력은 status와 order_id의 차이를 보여 주지만 반환 목적은 알려 주지 않으므로 docstring이 필요합니다. 다음 절에서는 바로 이 설명 문장을 실험 변수로 삼습니다.

7주의할 점과 실무 메모

도구 이름에는 동작과 대상을 함께 씁니다. get_data처럼 범위가 넓은 이름이나 같은 설명을 반복하면 질문과 도구를 대응할 근거가 줄어듭니다.

도구 설명을 작성한 뒤에는 실제 질문을 세 부류로 적어 봅니다. ‘paid 주문을 보여 줘’는 목록, ‘O103을 찾아 줘’는 단건, ‘paid 총액은 얼마야’는 집계입니다. 어느 질문이 두 도구 설명에 동시에 맞으면 경계가 겹친 것입니다. 이때 설명에 예문을 계속 붙이기보다 함수 책임을 나누거나 이름을 고치는 편이 낫습니다. 반환 필드 설명은 모델이 다음 답을 만들 때 필요한 정도로 적고, 내부 파일명이나 구현 라이브러리는 노출하지 않습니다.

도구 수가 늘어날 때는 새 도구를 추가하기 전에 기존 도구의 인자 하나로 표현할 수 있는지 검토합니다. 그러나 목록과 집계처럼 반환 의미가 크게 다르면 억지로 합치지 않습니다. 이름 충돌 검사와 대표 질문 표를 변경 검토에 넣으면 설명이 비슷해지는 시점을 일찍 찾을 수 있습니다.

  • 도구 설명과 인자 스키마도 모델 컨텍스트를 사용합니다.
  • API 가격과 모델 동작은 달라질 수 있으므로 실행 시점의 공식 정보를 확인합니다.

8정리와 다음 절

  • 목록·단건·집계 도구가 이름과 반환 목적에서 서로 구분됩니다.
  • 인자 스키마는 입력 형식을, 설명은 선택 시점과 반환 목적을 알려 줍니다.
  • 문자 수는 설명서 크기를 비교하는 값이며 토큰 비용으로 환산할 수 없습니다.

9복습 문제

문제 1. 도구 이름에 동작과 대상을 함께 쓰는 이유는 무엇인가요?

모델과 사람이 목록 조회·단건 조회·집계를 이름부터 구분할 수 있기 때문입니다.

문제 2. 인자 스키마만으로 반환 목적까지 알 수 있나요?

알 수 없습니다. 반환 목적과 선택 시점은 설명에 밝혀야 합니다.

문제 3. 설명서의 문자 수를 토큰 수로 바꿔 쓸 수 없는 이유는 무엇인가요?

토큰 수는 모델의 토크나이저와 직렬화 형식에 따라 달라지기 때문입니다.

문제 4. get_order_by_id와 list_orders_by_status를 구분하는 핵심 입력은 무엇인가요?

하나는 정확한 order_id, 다른 하나는 status를 받습니다.
