1학습 목표

  • 검증한 함수를 도구로 감싸는 경계를 설명할 수 있습니다.
  • 직접 함수 호출과 도구의 invoke() 결과가 같은지 확인할 수 있습니다.
  • 도구의 이름·설명·인자 스키마가 기존 함수에 추가되는 과정을 설명할 수 있습니다.

2이 내용을 배우는 이유

Ch 4에서는 사람이 상태 값을 정해 함수를 호출했습니다. 이제 같은 함수가 모델이 선택할 수 있는 도구가 됩니다. 업무 로직을 다시 작성하지 않고 인터페이스만 추가해야 Ch 4 테스트의 신뢰를 이어갈 수 있습니다.

Ch 20에서 ToolNode로 실행 흐름을 조립하기 전에 도구 한 개가 어떤 정보와 결과를 주고받는지 확인합니다.

3앞에서 배운 내용

노트북에 fetch_orders() 원문을 인라인하고 공개 CSV도 함께 제공합니다. 학생은 Part 1 폴더를 import하지 않아도 되며, 원본 함수와 AST가 같은지 검증 기록에서 확인할 수 있습니다.

실행 파일은 labs/part5/ch19-model-tools/data/orders.csv를 사용하며 Part 1 모듈을 런타임에 import하지 않습니다.

4핵심 개념

비유로 먼저 이해하기

도구 설명서는 주문서와 비슷합니다. 모델은 함수 내부를 보지 않고 이름, 설명, 선택 항목을 보고 요청합니다.

정의

Ch 4의 fetch_orders()는 CSV를 읽고 조건에 맞는 사전 목록을 반환합니다. 이번 절에서는 함수 본문을 바꾸지 않고 @tool 데코레이터로 모델이 읽을 이름·설명·입력 형식을 더합니다.

도구로 감싼 뒤에도 CSV 경로는 프로그램이 넘깁니다. 모델에게 파일 경로까지 선택하게 하면 학습 목표와 관계없는 경로 오류가 늘어납니다. 이 절의 도구는 status만 공개하고 data_path는 함수 안에서 사용합니다. 직접 호출과 invoke 호출에 cancelled를 넣었을 때 모두 O104를 반환하므로 필터 조건과 행의 네 필드가 보존됐음을 읽을 수 있습니다. 반면 StructuredTool을 위치 인자로 호출한 TypeError는 주문 데이터의 실패가 아니라 인터페이스 사용 오류입니다. 실패의 층을 구분해야 수정 위치도 정확해집니다.

도구 호출(tool call)은 구조화된 실행 요청이며 도구 메시지(ToolMessage)는 실행 결과와 호출 ID를 돌려주는 메시지입니다.

출력 읽기

출력을 읽을 때 먼저 same이 True인지 확인하고, 이어서 rows 안의 order_id가 O104인지 봅니다. True만 확인하면 두 결과가 모두 빈 목록인 경우를 놓칠 수 있습니다. 실제 행의 ID·고객 ID·상태·금액까지 같아야 기존 함수의 의미가 유지됐다고 말할 수 있습니다. 다음으로 도구 객체의 name과 description, args를 확인합니다. 이 세 값은 모델에게 전달되는 설명서이고 CSV 경로는 포함되지 않습니다. 학생이 상태를 paid로 바꾸면 두 행이 반환되며, 이 변화는 도구로 감쌌기 때문이 아니라 입력 상태가 달라졌기 때문입니다.

7주의할 점과 실무 메모

데코레이터를 붙인 뒤 변수는 일반 함수가 아니라 StructuredTool입니다. 일반 위치 인자로 부르지 않고 invoke()에 필드 이름이 있는 사전을 전달합니다.

직접 함수는 Python 코드가 이름을 정해 호출합니다. 도구 객체는 같은 함수를 모델 선택 후보로 표현합니다. 이 변화 때문에 함수의 책임까지 넓히면 안 됩니다. CSV 읽기와 상태 필터는 Ch 4 함수가 맡고, 도구는 모델이 채울 status 한 칸만 공개합니다. 새로운 상태가 데이터에 추가되면 함수 테스트와 도구 설명을 함께 갱신합니다. 원본 해시는 출처 추적용이며 해시가 같다는 사실만으로 실행 결과까지 보장하지 않으므로 새 커널 비교도 수행합니다.

복사 동등성은 소스 출처를 투명하게 남기기 위한 선택입니다. 실무에서는 검증된 함수를 패키지로 배포해 import하는 편이 중복을 줄입니다. 이 기본 노트북은 프로젝트 전용 import 없이도 실행되어야 하므로 짧은 원문을 포함했습니다. 원본이 바뀌면 해시와 AST 비교가 실패하도록 검증해야 두 사본이 조용히 달라지는 일을 막을 수 있습니다.

  • 도구 설명과 인자 스키마도 모델 컨텍스트를 사용합니다.
  • API 가격과 모델 동작은 달라질 수 있으므로 실행 시점의 공식 정보를 확인합니다.

8정리와 다음 절

  • Ch 4 함수의 반환값을 보존하면서 모델용 설명서를 추가했습니다.
  • @tool은 기존 조회 로직을 바꾸지 않고 이름·설명·인자 스키마를 제공합니다.
  • 직접 호출과 invoke()가 O104를 같은 내용으로 반환하는지 확인했습니다.

모델이 읽을 이름·설명·인자 스키마가 추가됩니다.

문제 2. 직접 호출 결과와 invoke() 결과를 함께 비교하는 이유는 무엇인가요?

도구로 감싸도 기존 함수의 조회 결과가 바뀌지 않았는지 확인하기 위해서입니다.

문제 3. 이 절에서 확인한 실제 출력은 무엇인가요?

직접 호출과 도구의 invoke() 결과를 비교해 도구로 감싸기 전후의 조회 결과가 같음을 확인했습니다.

문제 4. cancelled 비교에서 O104가 양쪽에 나타난 사실은 무엇을 보여 주나요?

도구로 감싸도 기존 상태 필터와 반환 행이 바뀌지 않았음을 보여 줍니다.
