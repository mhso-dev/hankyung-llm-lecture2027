1학습 목표

  • trigger와 keep 조건을 설명할 수 있습니다.
  • Ch16 수동 요약 호출과 SummarizationMiddleware의 실행 지점을 비교할 수 있습니다.
  • 압축 결과에서 조건·예외·출처가 남았는지 확인할 수 있습니다.

2이 내용을 배우는 이유

대화가 길어지면 모든 메시지를 모델에 전달하는 비용이 커지고 모델이 현재 질문에 필요한 사실을 찾기 어려워집니다. Ch8의 Compress는 필요한 정보를 남기고 반복을 줄이는 전략이었습니다. Ch16에서는 summarize_history를 직접 호출했습니다. 미들웨어는 모델 호출 직전에 임계값을 검사하고 오래된 메시지를 요약해 이 전략을 반복 루프에 연결합니다.

이 절의 질문 — 자동 요약 압축은 언제 실행되며 최근 메시지와 중요 조건을 어떻게 보존해야 할까요?

3앞에서 배운 내용

Ch8에서는 압축할 때 결정·조건·예외·출처를 보존해야 한다고 배웠습니다. Ch16 summarize_history는 system 메시지와 최근 대화를 남기고, 오래된 대화를 summarizer 함수에 넘긴 뒤 참고용 요약 메시지로 바꿨습니다. 이번 절은 같은 메시지 수 조건을 미들웨어 설정으로 표현합니다.

4핵심 개념

비유로 시작하기

회의록을 다음 회의용 한 장 요약으로 바꾸는 상황을 생각해 봅니다. trigger는 언제 요약을 시작할지, keep은 최근 기록을 얼마나 원문으로 남길지 정합니다. SummarizationMiddleware는 before_model 훅에서 메시지 수나 토큰 수를 검사합니다. 요약 모델은 압축문을 만들고 주 모델은 압축된 문맥으로 답합니다. 압축은 원문을 완전히 보존하지 않으므로 결정, 예외, 날짜, 출처처럼 반드시 남겨야 할 필드를 프롬프트와 검증에 넣어야 합니다.

도식 읽기

파란 원본 여섯 메시지가 노란 trigger 검사로 들어갑니다. 임계값 미만이면 그대로 보라색 주 모델로 이동합니다. 임계값 이상이면 오래된 메시지가 보라색 요약 모델을 거쳐 파란 요약문과 최근 두 메시지로 바뀐 뒤 주 모델에 전달됩니다. E01 p.3은 압축 뒤에도 확인할 보존 항목입니다.

5실행 예제

여섯 메시지를 Before 에이전트에 그대로 전달한 뒤, trigger=4·keep=2 조건의 SummarizationMiddleware를 붙입니다. 결정적 요약문으로 메시지 구성 변화를 재현하고, 별도 실제 모델 호출로 권수·기간·연장 조건·출처를 보존한 요약문과 사용량을 확인합니다.

{{notebook:03-요약-압축과-Compress|example}}

확인할 점 — 모델 입력이 6개에서 요약문과 최근 2개를 합친 3개로 바뀌고, 14일과 E01 p.3이 남는지 확인합니다.

6일부러 실패해 보기

Before에서는 여섯 메시지가 그대로 주 모델에 전달됩니다. After에서는 trigger=(messages,4), keep=(messages,2)를 적용해 오래된 대화를 요약 메시지로 바꾸고 최근 두 메시지를 유지합니다. 학습용 요약 모델이 만든 문자열에서 14일, 예약 없음, E01 p.3을 검사합니다. 이 검사는 설정이 실행됐음을 보여 주지만 실제 생성 모델의 모든 요약이 정확하다는 뜻은 아닙니다.

7주의할 점과 실무 메모

  • 메시지 개수 임계값은 문자 수나 실제 토큰 수와 다릅니다. 운영에서는 모델 프로필이 확인되면 토큰 또는 fraction 조건을 검토합니다.
  • 요약 호출도 비용과 지연을 추가합니다. 너무 낮은 임계값은 매번 요약을 실행할 수 있습니다.
  • 압축본에는 원문 식별자를 남겨 중요한 판단 전에 원문을 다시 확인할 수 있게 합니다.

실습의 결정적 모델은 미들웨어 실행 경계를 재현하기 위한 검사 도구입니다. 실제 모델 품질, 공급자 장애율, 운영 비용을 대신 측정하지 않습니다. 적용 전에는 사용 중인 모델과 계정의 실제 사용량을 다시 확인합니다.

9복습 문제

문제와 해설

1. trigger와 keep의 역할은 각각 무엇인가요?

해설 — trigger는 압축 시작 조건, keep은 압축하지 않고 남길 최근 범위를 정합니다.

2. 메시지 수 임계값의 한계는 무엇인가요?

해설 — 메시지마다 길이가 달라 실제 토큰 사용량을 정확히 나타내지 못합니다.

3. 압축 결과에서 출처 식별자를 보존하는 이유는 무엇인가요?

해설 — 중요한 판단 때 압축 주장과 원문을 다시 대조하기 위해서입니다.

4. 요약 미들웨어가 비용을 항상 줄인다고 단정할 수 없는 이유는 무엇인가요?

해설 — 별도 요약 모델 호출 비용이 들고 임계값과 대화 길이에 따라 절감량이 달라집니다.
