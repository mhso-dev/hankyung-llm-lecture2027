1학습 목표

  • before 훅의 순방향 실행을 확인할 수 있습니다.
  • after 훅의 역방향 실행을 확인할 수 있습니다.
  • wrap 훅의 중첩 순서를 함수 호출 구조로 설명할 수 있습니다.

2이 내용을 배우는 이유

PII 처리, 예산, 재시도, 감사를 한 에이전트에 함께 넣으면 목록 순서가 실제 동작을 바꿉니다. 예산을 예약한 뒤 재시도하면 각 시도를 비용으로 셀지, 재시도 전체를 한 호출로 셀지에 따라 결과가 다릅니다. 출력 감사가 마스킹보다 바깥에 있으면 마스킹 전 값을 기록할 수도 있습니다. 따라서 합성 순서를 trace로 확인해야 합니다.

이 절의 질문 — 여러 미들웨어의 before·after·wrap 훅은 어떤 순서로 합성될까요?

3앞에서 배운 내용

앞 절까지 PIIMiddleware, 내장 안정화 미들웨어, 두 커스텀 미들웨어를 각각 실행했습니다. 이번에는 기능을 추가하지 않고 A, B, C 세 미들웨어가 같은 훅에서 남기는 문자열만 관찰합니다. 모델은 한 번만 답하는 결정적 모델로 고정합니다.

4핵심 개념

비유로 시작하기

겹쳐 입은 옷을 생각해 봅니다. 안으로 들어갈 때는 겉옷 A, 중간 옷 B, 안쪽 옷 C 순서로 통과합니다. 밖으로 나올 때는 C, B, A 순서입니다. LangChain의 before 훅은 목록의 앞에서 뒤로 실행됩니다. after 훅은 뒤에서 앞으로 실행됩니다. wrap 훅은 첫 항목이 가장 바깥쪽이 되어 A before, B before, C before, 모델, C after, B after, A after 순서가 됩니다.

도식 읽기

파란 middleware 목록 A·B·C가 파란 before 구간에서는 왼쪽부터 A→B→C로 실행됩니다. 보라색 모델을 감싸는 wrap 구간은 A(B(C(model))) 형태입니다. 반환과 after 구간은 C→B→A로 반대 방향입니다. 노트북의 ORDER 18개 항목이 각 화살표의 순서를 검증합니다.

확인할 점 — A·B·C의 before 순서와 C·B·A의 wrap-after·after 순서를 각각 확인합니다.

6실험 결과 해석

middleware=[A,B,C]로 한 번 실행한 trace를 세 구간으로 나눕니다. before_agent와 before_model은 A·B·C, wrap_model_call 진입은 A·B·C이고 반환은 C·B·A, after_model과 after_agent는 C·B·A입니다. 이 순서는 공식 문서의 실행 순서와 일치합니다. 도구 훅도 같은 중첩 원칙을 따르지만 이 셀은 모델 한 번의 최소 예제로 제한합니다.

7주의할 점과 실무 메모

  • 목록 순서를 문서화하고 trace 회귀 테스트로 고정합니다. 라이브러리 업그레이드 뒤에도 다시 실행합니다.
  • 마스킹 전후의 어느 값이 감사 로그에 들어가는지 실제 요청과 반환 위치로 확인합니다.
  • 재시도 미들웨어의 안쪽과 바깥쪽에 예산 미들웨어를 둘 때 시도 횟수 계산이 달라질 수 있습니다.

실습의 결정적 모델은 미들웨어 실행 경계를 재현하기 위한 검사 도구입니다. 실제 모델 품질, 공급자 장애율, 운영 비용을 대신 측정하지 않습니다. 적용 전에는 사용 중인 모델과 계정의 실제 사용량을 다시 확인합니다.

8정리와 다음 절

  • 여러 미들웨어의 before·after·wrap 훅은 어떤 순서로 합성될까요?
  • before 훅의 순방향 실행을 확인할 수 있습니다.
  • middleware=[A,B,C]로 한 번 실행한 trace를 세 구간으로 나눕니다. before_agent와 before_model은 A·B·C, wrap_model_call 진입은 A·B·C이고 반환은 C·B·A, after_model과 after_agent는 C·B·A입니다. 이 순서는 공식 문서의 실행 순서와 일치합니다. 도구 훅도 같은 중첩 원칙을 따르지만 이 셀은 모델 한 번의 최소 예제로 제한합니다.

다음 학습과 이어지는 지점 — 마지막 절에서는 wrap_model_call로 업무별 메시지만 선택해 Ch8의 Isolate를 에이전트 구현으로 연결합니다.

9복습 문제

문제와 해설

1. before 훅의 실행 순서는 무엇인가요?

해설 — middleware 목록의 첫 항목에서 마지막 항목 순서입니다.

2. after 훅이 역순인 이유를 함수 중첩으로 설명해 보세요.

해설 — 안쪽 처리가 먼저 반환되고 바깥쪽 처리가 나중에 반환되기 때문입니다.

3. 첫 미들웨어의 wrap 훅은 어느 위치인가요?

해설 — 다른 wrap 훅과 실제 호출을 감싸는 가장 바깥쪽입니다.

4. 순서 테스트가 필요한 실무 사례는 무엇인가요?

해설 — PII 마스킹 전 원문이 감사 로그에 남지 않는지 확인하는 사례입니다.
