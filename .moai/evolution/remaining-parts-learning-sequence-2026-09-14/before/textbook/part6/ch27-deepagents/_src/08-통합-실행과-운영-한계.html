1학습 목표

  • 통합 실행의 사용량을 읽고 비용·권한·정지 조건을 운영 기록으로 남깁니다.
  • 실행 출력에서 통합 실행과 운영 한계의 구성과 결과를 구분할 수 있습니다.
  • 이 실험이 확인한 범위를 설명할 수 있습니다.

2이 내용을 배우는 이유

기능이 모두 연결돼도 쓰기 범위와 종료 조건이 없으면 운영 가능한 에이전트가 아닙니다. 이 절은 앞 절의 파일을 읽지 않는 새 백엔드에서 허용 경로와 차단 경로를 동시에 요청하고 결과 메시지로 경계를 확인합니다.

3앞에서 배운 내용

Ch 24의 사람 승인과 이 장의 permissions는 도구 실행 경계를 다룹니다. 이 실습은 interrupt 대신 deny를 사용해 /blocked.txt 쓰기를 즉시 거부합니다. /run/report.md의 status: complete는 확인 가능한 종료 산출물입니다.

노트북은 앞 절 변수에 의존하지 않으며 Python 3.12, deepagents==0.7.0, langchain==1.4.0을 설치하고 상위 폴더의 .env를 찾습니다.

4핵심 개념

정의와 구체적인 상황

통합 에이전트는 기능 수보다 경계를 먼저 정합니다. 읽기·쓰기 경로, 삭제 승인, 서브에이전트의 도구, 반복 한도, 결과 파일 형식, 허용 비용을 코드와 운영 기록에 남깁니다. 이 장의 호출은 절마다 1달러 미만을 목표로 하며 실제 usage_metadata가 있는 실행은 입력·출력 토큰을 기록합니다. 가격표가 바뀔 수 있으므로 비용 계산식과 확인 날짜를 함께 남깁니다.

workspace-08을 새 root_dir로 만들고 /blocked.txt에 대한 write deny 규칙을 추가합니다. 모델에게 /run/report.md에는 완료 상태를 쓰고 /blocked.txt에도 같은 내용을 시도하게 합니다. ReadResult와 permission denied ToolMessage를 각각 검증합니다.

6실험 결과 해석

/run/report.md에는 status: complete가 저장됐고 /blocked.txt 쓰기는 permission denied로 반환됐습니다. 모델은 두 결과를 설명하고 종료했습니다. 이는 한 경로 규칙의 동작을 확인한 것이며 삭제·glob·서브에이전트 상속 규칙은 별도 테스트가 필요합니다.

7주의할 점과 실무 메모

  • deepagents의 최신 문서는 이후 버전의 기능을 포함할 수 있으므로 이 장은 설치된 0.7.0 소스와 릴리스 노트를 함께 확인합니다.
  • 파일 도구의 루트와 권한을 지정하지 않은 채 사용자 입력을 경로로 사용하지 않습니다. 특히 0.7의 delete와 기존 파일을 교체하는 write_file을 구분합니다.
  • API 호출 절의 예산은 입력 10만 토큰·출력 1만 토큰 이하를 가정하면 2026-09-11 공개 단가 기준 약 0.12달러로, 절당 1달러 미만입니다. 실제 비용은 전체 서브에이전트 사용량과 최신 가격표로 다시 계산합니다.

재현 기록에는 실행 날짜, 패키지 잠금, 모델 이름, 입력, 생성 파일 경로를 함께 적습니다. 모델이 같은 도구를 선택하지 않을 수 있으므로 저장된 출력은 한 번의 관찰입니다. 배포 전에는 정상 입력뿐 아니라 도구가 선택되지 않은 경우, 권한이 거부된 경우, 결과 파일이 빠진 경우도 반복해서 확인합니다.

9복습 문제

문제 1

허용된 종료 산출물의 경로와 내용은 무엇인가요?

해설 /run/report.md이며 내용은 status: complete입니다.

문제 2

/blocked.txt가 만들어지지 않은 근거는 무엇인가요?

해설 write_file의 ToolMessage가 permission denied를 반환했고 deny 규칙이 적용됐습니다.

문제 3

deny와 interrupt의 차이는 무엇인가요?

해설 deny는 호출을 거부하고, interrupt는 체크포인터와 승인 처리를 구성했을 때 사람의 결정을 기다립니다.
