1학습 목표

  • 생성 함수의 인자와 기본 도구 표면을 설치된 0.7.0에서 확인합니다.
  • 실행 출력에서 create_deep_agent와 도구의 구성과 결과를 구분할 수 있습니다.
  • 이 실험이 확인한 범위를 설명할 수 있습니다.

2이 내용을 배우는 이유

함수 시그니처만 읽으면 tools 인자가 있다는 사실은 알 수 있지만 모델이 도구를 선택하고 결과를 다시 읽는지는 알 수 없습니다. 이 절은 Chapter 27이라는 고정 입력을 course_lookup에 전달하고 HumanMessage → AIMessage → ToolMessage → AIMessage 순서를 실제로 확인합니다.

3앞에서 배운 내용

Ch 19에서 @tool로 함수 설명과 입력 스키마를 만들었고 Ch 21에서 create_agent에 도구를 전달했습니다. 같은 방식을 유지하되 생성 함수만 create_deep_agent로 바꿉니다. course_lookup은 네트워크를 사용하지 않는 교재용 고정 자료입니다.

노트북은 앞 절 변수에 의존하지 않으며 Python 3.12, deepagents==0.7.0, langchain==1.4.0을 설치하고 상위 폴더의 .env를 찾습니다.

4핵심 개념

정의와 구체적인 상황

create_deep_agent는 LangChain의 create_agent 위에 파일시스템과 위임, 요약 미들웨어를 조립합니다. 기본 파일 도구는 ls, read_file, write_file, edit_file, delete, glob, grep입니다. execute는 실행을 지원하는 샌드박스 백엔드가 있을 때만 실제 명령을 수행합니다. 0.7에서는 write_file이 기존 파일 전체를 교체할 수 있으므로 권한 규칙이 중요합니다.

도식 읽기

{{svg:02-흐름}}

색이 쓰인 곳에서 파란색은 학생 코드와 실행 흐름, 보라색은 모델의 판단, 초록색은 도구와 데이터, 노란색은 측정값, 빨간색은 실패 또는 권한 경계를 뜻합니다. create_deep_agent가 백엔드·미들웨어를 조립하고 파일·위임 도구를 더한 뒤 CompiledStateGraph를 반환하는 순서입니다. 실행 출력의 model과 tools 노드는 마지막 상자에 포함된 내부 실행 노드입니다.

5실행 예제

init_chat_model로 gpt-5.4-mini를 준비하고 course_lookup 하나를 추가합니다. 질문에는 도구 이름과 Chapter 27을 명시합니다. 호출 뒤 각 메시지 타입과 tool_call 이름, ToolMessage 내용을 출력하고 두 조건을 assert로 확인합니다.

확인할 점 메시지 순서에 ToolMessage가 있고 이름이 course_lookup인지 확인합니다. 모델의 최종 답만으로는 도구 호출 여부를 판별할 수 없습니다.

6실험 결과 해석

저장된 실행은 그래프 노드에 model과 tools를 표시했고, 메시지 사이에 course_lookup 이름의 ToolMessage를 남겼습니다. 도구 결과는 ‘DeepAgents 하네스’였습니다. 이는 이 입력에서 모델이 사용자 도구를 선택했다는 한 사례이며 다른 질문의 선택률은 보여 주지 않습니다.

7주의할 점과 실무 메모

  • deepagents의 최신 문서는 이후 버전의 기능을 포함할 수 있으므로 이 장은 설치된 0.7.0 소스와 릴리스 노트를 함께 확인합니다.
  • 파일 도구의 루트와 권한을 지정하지 않은 채 사용자 입력을 경로로 사용하지 않습니다. 특히 0.7의 delete와 기존 파일을 교체하는 write_file을 구분합니다.
  • API 호출 절의 예산은 입력 10만 토큰·출력 1만 토큰 이하를 가정하면 2026-09-11 공개 단가 기준 약 0.12달러로, 절당 1달러 미만입니다. 실제 비용은 전체 서브에이전트 사용량과 최신 가격표로 다시 계산합니다.

재현 기록에는 실행 날짜, 패키지 잠금, 모델 이름, 입력, 생성 파일 경로를 함께 적습니다. 모델이 같은 도구를 선택하지 않을 수 있으므로 저장된 출력은 한 번의 관찰입니다. 배포 전에는 정상 입력뿐 아니라 도구가 선택되지 않은 경우, 권한이 거부된 경우, 결과 파일이 빠진 경우도 반복해서 확인합니다.

8정리와 다음 절

  • 생성 함수의 인자와 기본 도구 표면을 설치된 0.7.0에서 확인합니다.
  • 저장된 실행은 그래프 노드에 model과 tools를 표시했고, 메시지 사이에 course_lookup 이름의 ToolMessage를 남겼습니다.
  • 버전과 측정 범위를 실행 기록에 함께 남깁니다.

다음 학습과 이어지는 지점 — 다음 절에서는 기본에서 빠진 write_todos를 TodoListMiddleware로 직접 추가하고 실제 계획 상태를 확인합니다.

9복습 문제

문제 1

도구 실행을 직접 증명하는 메시지 타입은 무엇인가요?

해설 course_lookup 이름과 반환값을 담은 ToolMessage입니다.

문제 2

create_deep_agent에 tools를 전달하면 기본 파일 도구가 제거되나요?

해설 아닙니다. 사용자 도구는 기본 하네스 도구에 추가됩니다.

문제 3

한 번 선택된 결과로 도구 선택 정확도를 말할 수 있나요?

해설 말할 수 없습니다. 여러 질문과 기대 도구를 정해 반복 평가해야 합니다.
