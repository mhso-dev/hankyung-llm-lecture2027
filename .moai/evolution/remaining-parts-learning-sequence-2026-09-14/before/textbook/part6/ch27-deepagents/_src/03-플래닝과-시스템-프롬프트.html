1학습 목표

  • 0.7에서 플래닝과 기본 프롬프트가 어떻게 달라졌는지 측정 범위와 함께 확인합니다.
  • 실행 출력에서 플래닝과 시스템 프롬프트의 구성과 결과를 구분할 수 있습니다.
  • 이 실험이 확인한 범위를 설명할 수 있습니다.

2이 내용을 배우는 이유

계획 도구가 기본이라고 가정한 0.6 예제는 0.7에서 그대로 동작하지 않습니다. 필요한 애플리케이션만 TodoListMiddleware를 추가해야 합니다. 프롬프트 감소 수치도 측정 조건을 떼어 내면 과장되므로 실제 write_todos 호출과 릴리스 PR의 조건을 함께 봅니다.

3앞에서 배운 내용

Ch 26에서 위임 완료 조건을 문장으로 적었습니다. 할 일 목록은 완료 조건을 여러 단계의 상태로 관리하는 수단입니다. 모든 짧은 질문에 계획을 만들 필요는 없으므로 0.7의 opt-in 방향과 연결됩니다.

노트북은 앞 절 변수에 의존하지 않으며 Python 3.12, deepagents==0.7.0, langchain==1.4.0을 설치하고 상위 폴더의 .env를 찾습니다.

4핵심 개념

정의와 구체적인 상황

0.7.0부터 TodoListMiddleware와 write_todos는 기본 구성에서 빠졌습니다. 계획이 필요한 애플리케이션만 middleware=[TodoListMiddleware()]로 추가합니다. 작성된 기본 시스템 프롬프트도 비어 있으며, 파일 도구와 위임 도구의 스키마와 겹치던 설명이 줄었습니다. 릴리스 PR의 65% 감소는 gpt-5.5에 ‘hello’를 보낸 첫 턴에서 5,395토큰과 1,895토큰을 비교한 값입니다. 전체 작업의 총 토큰이나 모든 모델의 절감률로 일반화할 수 없습니다.

색이 쓰인 곳에서 파란색은 학생 코드와 실행 흐름, 보라색은 모델의 판단, 초록색은 도구와 데이터, 노란색은 측정값, 빨간색은 실패 또는 권한 경계를 뜻합니다. 0.6 기본 플래닝에서 0.7 opt-in으로 이동한 뒤 빈 작성 프롬프트와 첫 턴 토큰 측정으로 이어집니다. 마지막 상자는 전체 작업 비용이 아니라 gpt-5.5 hello 첫 턴 한 조건의 측정입니다.

5실행 예제

TodoListMiddleware를 middleware 인자에 넣고 두 할 일을 write_todos로 먼저 기록하라고 요청합니다. tool_calls와 todos 상태를 출력합니다. 이어서 PR의 5,395와 1,895를 같은 식으로 계산해 64.9%, 반올림 65%인지 확인합니다.

{{notebook:03-플래닝과-시스템-프롬프트}}

확인할 점 write_todos 호출이 두 번인지와 두 할 일이 모두 completed인지 확인합니다. 65%는 현재 호출의 사용량이 아니라 릴리스 PR의 두 수치를 재계산한 값입니다.

6실험 결과 해석

모델은 write_todos를 두 번 호출했고 버전 확인과 결과 설명을 모두 completed로 기록했습니다. 이 상태는 계획 도구가 실제로 추가됐음을 보여 줍니다. 65%는 이 실행에서 측정한 값이 아니라 릴리스 PR의 gpt-5.5 첫 턴 비교를 재계산한 값입니다.

7주의할 점과 실무 메모

  • deepagents의 최신 문서는 이후 버전의 기능을 포함할 수 있으므로 이 장은 설치된 0.7.0 소스와 릴리스 노트를 함께 확인합니다.
  • 파일 도구의 루트와 권한을 지정하지 않은 채 사용자 입력을 경로로 사용하지 않습니다. 특히 0.7의 delete와 기존 파일을 교체하는 write_file을 구분합니다.
  • API 호출 절의 예산은 입력 10만 토큰·출력 1만 토큰 이하를 가정하면 2026-09-11 공개 단가 기준 약 0.12달러로, 절당 1달러 미만입니다. 실제 비용은 전체 서브에이전트 사용량과 최신 가격표로 다시 계산합니다.

재현 기록에는 실행 날짜, 패키지 잠금, 모델 이름, 입력, 생성 파일 경로를 함께 적습니다. 모델이 같은 도구를 선택하지 않을 수 있으므로 저장된 출력은 한 번의 관찰입니다. 배포 전에는 정상 입력뿐 아니라 도구가 선택되지 않은 경우, 권한이 거부된 경우, 결과 파일이 빠진 경우도 반복해서 확인합니다.

8정리와 다음 절

  • 0.7에서 플래닝과 기본 프롬프트가 어떻게 달라졌는지 측정 범위와 함께 확인합니다.
  • 모델은 write_todos를 두 번 호출했고 두 항목을 모두 completed로 기록했습니다.
  • 버전과 측정 범위를 실행 기록에 함께 남깁니다.

다음 학습과 이어지는 지점 — 다음 절에서는 대화 안의 계획 대신 파일시스템에 조사 중간 결과를 남겨 실행 사이의 인계 지점을 만듭니다.
