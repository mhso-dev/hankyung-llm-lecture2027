1학습 목표

  • 노드 재시작이 외부 쓰기를 중복할 수 있는 실행 경로를 설명할 수 있습니다.
  • operation_id를 검사한 경로와 단순 추가 경로의 로그를 비교할 수 있습니다.
  • 운영 환경에서 원자적 고유 제약이 필요한 이유를 설명할 수 있습니다.

2이 내용을 배우는 이유

체크포인트는 노드 안의 각 코드 줄 뒤에 저장되지 않습니다. 외부 쓰기 뒤 상태 반환 전에 프로세스가 끝나면 같은 노드가 다시 시작됩니다.

이 실습은 order-2306을 파일에 쓴 직후 자식 프로세스를 종료합니다. 같은 SQLite 상태로 재개했을 때 단순 추가는 두 줄을 남기고, operation_id를 확인한 경로는 한 줄만 남기는지를 확인합니다.

3앞에서 배운 내용

앞 절의 good 노드는 상태 반환까지 마쳐 pending write가 생겼습니다. 이번 절은 외부 파일에 주문 번호를 쓴 뒤 상태를 반환하기 전에 프로세스를 종료합니다. 체크포인트가 다음 노드 경계로 이동하지 못했으므로 같은 charge 노드가 처음부터 다시 시작됩니다.

4핵심 개념

구체적인 상황

결제 요청이 외부 서비스에는 반영됐지만 응답을 상태에 저장하기 전에 서버가 종료될 수 있습니다. 재개한 charge가 같은 요청을 다시 보내면 이중 결제가 됩니다. 호출마다 바뀌지 않는 주문 작업 키로 이미 처리했는지 확인해야 합니다.

정의

멱등성(idempotency)은 같은 작업을 여러 번 요청해도 외부 결과가 한 번 적용된 것과 같게 유지되는 성질입니다. operation_id를 이미 처리한 키로 기록하면 재시작한 노드가 중복 쓰기를 건너뛸 수 있습니다.

operation_id는 비즈니스 작업 한 건을 식별합니다. naive 전략은 호출할 때마다 로그에 추가합니다. idempotent 전략은 같은 operation_id가 이미 있으면 추가하지 않습니다. 이 실습의 파일 검사는 실제 운영에서 데이터베이스의 고유 키나 결제 API의 idempotency key에 대응합니다.

naive 로그에는 order-2306이 두 줄입니다. 첫 프로세스와 재개 프로세스가 charge의 파일 쓰기를 각각 실행했습니다. idempotent 로그에는 한 줄만 남습니다. 두 번째 charge도 시작됐지만 기존 키를 확인하고 외부 쓰기를 건너뛰었습니다.

같은 지점에서 자식 프로세스를 종료하고 재개했습니다. 단순 추가 방식은 주문 번호가 2줄, 멱등 키 방식은 1줄 남았습니다.

7주의할 점과 실무 메모

  • 확인과 쓰기를 별도 연산으로 구현하면 동시 요청 사이에 경쟁 조건이 생길 수 있으므로 운영에서는 원자적 고유 제약을 사용합니다.
  • operation_id의 보존 기간은 외부 서비스의 재시도 가능 기간보다 짧지 않게 정합니다.
  • 멱등 처리가 어려운 작업은 interrupt 승인과 보상 작업을 함께 설계합니다.

8정리와 다음 절

  • 상태 반환 전 종료된 charge 노드는 재개할 때 처음부터 실행됐습니다.
  • 단순 추가 로그는 order-2306을 두 번 기록했고, operation_id 검사 경로는 한 번만 기록했습니다.
  • 파일 존재 확인은 학습용 예이며 운영에서는 원자적 고유 제약 또는 제공자의 멱등 키가 필요합니다.

다음 학습과 이어지는 지점 — Ch24에서는 노드 실행 전에 사람의 승인 값을 받아 부작용 여부를 결정합니다.

9복습 문제

1. naive 로그가 두 줄이 된 실행 경로를 설명해 보세요.

해설 — 첫 charge가 기록한 뒤 종료됐고 재개한 charge가 처음부터 시작해 다시 기록했습니다.

2. idempotent 전략도 charge 노드 자체는 다시 실행되나요?

해설 — 실행됩니다. 다만 기존 operation_id를 확인하고 외부 쓰기를 생략합니다.

3. 파일 목록 검사가 운영 환경에서 충분하지 않은 이유는 무엇인가요?

해설 — 동시에 두 요청이 검사하면 둘 다 미처리로 판단할 수 있으므로 원자적 고유 제약이 필요합니다.

4. 체크포인트가 노드 내부 코드 줄마다 저장되지 않는다는 사실이 왜 중요한가요?

해설 — 상태 반환 전 장애에서는 노드가 처음부터 재시작되어 앞선 부작용도 반복될 수 있기 때문입니다.
