1학습 목표

  • sync·async·exit 모드의 저장 시점 차이를 설명할 수 있습니다.
  • 강제 종료 뒤의 checkpoint 값과 노드 호출 기록을 함께 읽을 수 있습니다.
  • 한 번의 async 관찰만으로 모든 종료 시점의 결과를 단정할 수 없는 이유를 설명할 수 있습니다.

2이 내용을 배우는 이유

체크포인트를 자주 동기 저장하면 복구 범위가 작아지지만 다음 노드가 기다리는 시간이 늘어날 수 있습니다. 저장 시점을 선택하려면 세 모드의 차이를 실제 중단에서 확인해야 합니다.

이 실습은 second 노드에 들어간 즉시 자식 프로세스를 종료합니다. 이 종료 시점에서는 exit가 first를 다시 실행했고, async와 sync는 first 결과를 읽어 second만 다시 실행했습니다.

3앞에서 배운 내용

앞 절은 정상 종료한 두 프로세스 사이의 재개를 확인했습니다. 이제 정상 종료라는 조건을 없앱니다. SQLiteSaver와 같은 thread_id는 유지하고, 두 번째 노드에 들어간 자식 프로세스를 운영체제 수준에서 종료해 durability 인자만 비교합니다.

4핵심 개념

구체적인 상황

first 노드가 분류를 마치고 second 노드가 긴 외부 처리를 시작한 순간 서버가 종료됐다고 가정합니다. 복구 뒤 first를 다시 실행해야 하는지, second부터 시작할 수 있는지는 first 결과가 종료 전에 저장됐는지에 달려 있습니다.

정의

내구성(durability) 모드는 체크포인트 저장 완료와 다음 노드 실행의 관계를 정합니다. sync는 저장 완료 뒤 다음 단계로 가고, async는 다음 단계와 저장을 겹쳐 실행하며, exit는 실행이 끝날 때 저장합니다.

sync는 first 체크포인트 저장이 완료된 뒤 second를 시작합니다. async는 저장과 second 실행을 겹치므로 지연을 줄일 수 있지만 매우 이른 종료에서는 저장 완료 여부가 달라질 수 있습니다. exit는 그래프가 끝날 때만 저장하므로 중간 종료에서 완료된 노드 결과가 남지 않습니다.

6실험 결과 해석

exit의 before는 None이고 재개 과정은 입력부터 다시 시작해 calls가 first, second, first, second입니다. 이번 실행의 async와 sync에는 completed=['first']가 남아 calls가 first, second, second였습니다. 세 모드 모두 재개 뒤 completed=['first','second']로 끝났습니다. async 결과는 저장 장치와 kill 시점이 달라지면 sync와 다를 수 있습니다.

두 번째 노드 진입 직후 자식 프로세스를 kill했습니다. sync에는 first 완료 상태가 남았고 exit에는 완료 체크포인트가 없었습니다. async 값은 실제 실행 출력에 기록했습니다.

7주의할 점과 실무 메모

  • kill 직전 ready 파일은 second 함수에 진입했다는 신호이며 second가 상태를 반환했다는 뜻이 아닙니다.
  • async 한 번의 관찰로 모든 장애 시점에 first가 보존된다고 단정하지 않습니다.
  • 복구 범위를 줄여도 노드 내부 부작용의 정확히 한 번 실행을 보장하지 않습니다.

8정리와 다음 절

  • exit는 중간 checkpoint가 없어 first와 second를 다시 실행했습니다.
  • 이번 종료 시점의 async와 sync는 first 결과를 저장해 second만 다시 실행했습니다.
  • 모드가 복구 범위를 바꾸어도 노드 내부 외부 쓰기를 정확히 한 번 실행하게 하지는 않습니다.

9복습 문제

1. exit 재개에서 first가 다시 실행된 근거는 무엇인가요?

해설 — before가 None이고 calls에 first가 두 번 기록됐습니다.

2. sync 재개가 second부터 시작한 근거는 무엇인가요?

해설 — 중단 전 completed에 first가 있고 calls에서 first는 한 번, second는 두 번입니다.

3. ready 파일은 무엇을 증명하나요?

해설 — 자식 프로세스가 second 노드 함수에 진입했음을 증명합니다.

4. async의 결과를 반복 측정해야 하는 이유는 무엇인가요?

해설 — 체크포인트 저장과 다음 노드가 겹치므로 프로세스 종료 시점과 저장 속도에 따라 결과가 달라질 수 있습니다.
