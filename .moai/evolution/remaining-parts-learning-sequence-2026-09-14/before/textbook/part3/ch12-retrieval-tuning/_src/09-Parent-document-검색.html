1학습 목표

  • 자식 청크로 검색하고 parent_id를 따라 원문 전체를 반환하는 두 단계 검색의 입력과 출력을 설명할 수 있습니다.
  • Q001에서 자식 후보 수에 따른 부모 반환 결과를 비교할 수 있습니다.
  • 관찰한 수치가 설명하는 범위와 설명하지 못하는 범위를 구분할 수 있습니다.

2이 내용을 배우는 이유

짧은 청크는 검색에는 유리하지만 생성 모델에 전달하면 문장의 앞뒤 근거가 잘릴 수 있습니다. 자식 청크로 위치를 찾고 부모 원문을 반환하면 검색 단위와 전달 단위를 따로 조절할 수 있습니다. 이때 부모 중복을 제거해야 같은 원문이 입력을 반복해서 차지하지 않습니다.

Ch11에서 만든 질문과 정답 문서 ID를 유지한 채 한 조건씩 바꿉니다. Q001에서 child_k만 바꾸어 부모 수와 순서 변화를 확인합니다.

3앞에서 배운 내용

Ch10에서 PDF를 문서와 청크로 나누고 메타데이터에 출처를 보존했습니다. Ch11의 evaluation-queries.jsonl은 질문마다 gold_doc_ids를 제공합니다. 이 절에서는 그 정답 ID에 해당하는 공개 PDF 6건을 다시 추출한 advanced-documents.json과 같은 30문항을 사용합니다. 앞 절의 변수나 실행 상태는 필요하지 않습니다.

4핵심 개념

쉬운 예

도서관에서 책을 찾을 때 먼저 검색대가 관련 서가를 좁히고, 그 안에서 제목과 목차를 자세히 읽어 우선순위를 정한다고 생각해 봅니다. 첫 단계가 서가를 빠뜨리면 다음 단계는 그 책을 검토할 수 없습니다. 반대로 후보를 지나치게 많이 가져오면 자세히 읽는 시간이 늘어납니다.

정의

자식 청크로 검색하고 parent_id를 따라 원문 전체를 반환하는 두 단계 검색입니다. 자식 청크에서 검색 점수를 계산한 뒤 parent_id가 같은 결과를 제거합니다. 남은 ID 순서대로 부모 원문을 한 번씩 반환합니다.

5실행 예제

노트북은 Python 3.12 새 커널에서 실행합니다. 먼저 부모 문서 수, 자식 청크 수, 질문 수를 출력해 입력 범위를 확인합니다. 다음 셀은 가장 작은 문항 하나에서 중간 결과를 보여 줍니다. 마지막 셀은 조건을 바꾸거나 평가 범위를 넓힙니다. 출력의 문서 ID, 점수, 실행 시간 또는 로그 수를 본문 설명과 대조합니다.

6실험 결과 해석

Q001에서 가장 가까운 자식 청크의 parent_id를 따라 2천 자가 넘는 원문을 반환했습니다. child_k를 3·8·20으로 바꾸면 발견되는 부모의 수와 순서가 달라집니다. 긴 원문을 반환했다고 답 품질이 자동으로 높아졌다고 결론 내릴 수는 없습니다.

한 번의 출력은 이 데이터와 실행 환경에서 관찰한 결과입니다. 다른 도메인, 더 긴 문서, 다른 언어 비율에서는 순서와 시간이 달라질 수 있습니다. 설정을 채택하기 전에는 실제 서비스 질문을 같은 형식으로 추가해 다시 계산해야 합니다.

7주의할 점과 실무 메모

  • 이번 절의 중간 결과를 확인한 뒤 다음 단계로 전달합니다. 검색 후보, 선택 결과, 부모 원문, 재작성 질문, 로그 행은 서로 다른 데이터입니다.
  • 실행 시간은 CPU, GPU, 배치 크기, 입력 길이, 모델 캐시에 따라 달라집니다. 장치와 패키지 버전을 로그에 함께 남깁니다.
  • 부모 원문을 많이 반환하면 생성 모델의 입력 토큰과 비용이 늘 수 있습니다. 부모 수와 글자 수도 로그에 남깁니다.
  • 공개 PDF 6건과 30문항은 학습용 기준선입니다. 실제 서비스의 문서 분포와 질문 유형을 대신하지 않습니다.

8정리와 다음 절

  • 자식 청크의 순위를 부모 ID 순서로 변환했습니다.
  • 중복 부모를 제거한 뒤 부모 원문의 길이와 반환 수를 확인했습니다.
  • 이 결과는 Q001의 자식 검색과 부모 반환에서 관찰한 실행 사례입니다.

부모 반환 비교에서 바꾸지 않은 입력을 두 가지 적어 보세요.

Q001과 같은 자식·부모 문서를 유지하고 child_k만 바꿨습니다. 오답 시 다시 볼 곳: 3절 ‘앞에서 배운 내용’

2. 이해 — 후보 수를 늘리면 항상 좋은가요?

후보 수와 품질·비용의 관계를 설명해 보세요.

후보 수를 늘리면 정답 문서가 포함될 가능성이 커질 수 있지만 리랭킹 연산과 지연도 늘어납니다. 실제 평가 지표와 시간을 함께 측정해야 합니다. 오답 시 다시 볼 곳: 7절 ‘주의할 점과 실무 메모’

3. 적용 — 한 문항의 성공을 어떻게 전체 평가로 넓히나요?

작은 성공 예제 다음에 실행할 평가 절차를 적어 보세요.

먼저 개발 문항 15개에서 같은 검색 함수를 실행해 설정을 비교합니다. 시험 문항은 설정 선택에 사용하지 않고 12절의 최종 평가까지 보류합니다. 오답 시 다시 볼 곳: 5절 ‘실행 예제’

4. 분석 — 긴 부모 원문이 답 품질을 보장하나요?

검색 지표와 생성 입력의 차이를 설명해 보세요.

보장하지 않습니다. 자식 청크가 정답 문서를 찾았는지는 검색 지표로 확인할 수 있지만, 긴 부모 원문이 답변에 도움이 되는지는 생성 단계에서 별도로 평가해야 합니다. 오답 시 다시 볼 곳: 6절 ‘실험 결과 해석’
