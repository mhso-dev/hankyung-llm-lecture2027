1학습 목표

  • 대명사와 생략된 대상을 대화 맥락으로 보충해 독립 검색 질문을 만드는 처리의 입력과 출력을 설명할 수 있습니다.
  • 대화형 후속 질문과 개발용 Q001에서 원문·재작성문 검색을 비교할 수 있습니다.
  • 관찰한 수치가 설명하는 범위와 설명하지 못하는 범위를 구분할 수 있습니다.

2이 내용을 배우는 이유

대화의 후속 질문에는 앞 문장의 기관명이나 대상이 생략될 수 있습니다. 이 질문을 그대로 검색하면 핵심 단어가 없어 관련 문서를 놓칠 수 있습니다. 원문을 보존한 채 독립 질문을 하나 더 만들고 두 순위를 따로 비교하면 재작성으로 뜻이 달라졌는지도 확인할 수 있습니다.

Ch11에서 만든 질문과 정답 문서 ID를 유지한 채 한 조건씩 바꿉니다. 대화형 후속 질문을 재작성하고 개발용 Q001에는 재작성을 적용하지 않는 조건을 확인합니다.

3앞에서 배운 내용

Ch10에서 PDF를 문서와 청크로 나누고 메타데이터에 출처를 보존했습니다. Ch11의 evaluation-queries.jsonl은 질문마다 gold_doc_ids를 제공합니다. 이 절에서는 그 정답 ID에 해당하는 공개 PDF 6건을 다시 추출한 advanced-documents.json과 같은 30문항을 사용합니다. 앞 절의 변수나 실행 상태는 필요하지 않습니다.

4핵심 개념

쉬운 예

도서관에서 책을 찾을 때 먼저 검색대가 관련 서가를 좁히고, 그 안에서 제목과 목차를 자세히 읽어 우선순위를 정한다고 생각해 봅니다. 첫 단계가 서가를 빠뜨리면 다음 단계는 그 책을 검토할 수 없습니다. 반대로 후보를 지나치게 많이 가져오면 자세히 읽는 시간이 늘어납니다.

정의

대명사와 생략된 대상을 대화 맥락으로 보충해 독립 검색 질문을 만드는 처리입니다. 입력은 대화 맥락과 후속 질문이고 출력은 독립 검색 질문입니다. 재작성문은 검색 입력으로 추가하며 원문 질문과 원문 검색 순위도 별도로 보존합니다.

도식 읽기

{{svg:11-질문-재작성}}

도식은 위에서 아래로 대화 맥락, 후속 질문, 모델 재작성, 원문·재작성·RRF 결과 순서로 읽습니다. 초록은 입력·문서·후보, 파랑은 직접 구현한 선택·설정, 보라는 모델 점수·질문 재작성, 노랑은 측정 결과·로그를 뜻합니다. 화살표는 데이터 전달 방향입니다.

이 절의 gpt-4.1-mini는 대화에서 생략된 대상을 보충하는 질문 재작성 예제에 사용합니다. Ch6·Ch9의 gpt-5.4-mini 답변 생성과는 입력·출력 과제가 다릅니다. 같은 재작성 모델을 고정하고 원문과 재작성문의 검색 결과만 비교하며, 두 모델의 답변 품질을 비교하는 실험으로 해석하지 않습니다.

5실행 예제

노트북은 Python 3.12 새 커널에서 실행합니다. 먼저 부모 문서 수, 자식 청크 수, 질문 수를 출력해 입력 범위를 확인합니다. 다음 셀은 가장 작은 문항 하나에서 중간 결과를 보여 줍니다. 마지막 셀은 조건을 바꾸거나 평가 범위를 넓힙니다. 출력의 문서 ID, 점수, 실행 시간 또는 로그 수를 본문 설명과 대조합니다.

확인할 점 — 코드가 실제 검색 또는 모델 추론을 수행하는지, 정답 문서 ID를 결과 뒤에 새로 붙이지 않는지, 비교할 때 질문과 원문이 유지되는지 확인합니다.

6실험 결과 해석

실제 채팅 모델이 ‘그곳’을 ‘미르시립도서관’으로 보충한 독립 질문을 반환했습니다. 원문 검색, 재작성문 검색, 두 순위의 RRF 결합을 따로 출력해 원문을 보존했습니다. API 출력은 모델 버전과 시점에 따라 달라질 수 있습니다. 이미 대상을 포함한 개발용 Q001에는 재작성을 적용하지 않습니다.

한 번의 출력은 이 데이터와 실행 환경에서 관찰한 결과입니다. 다른 도메인, 더 긴 문서, 다른 언어 비율에서는 순서와 시간이 달라질 수 있습니다. 설정을 채택하기 전에는 실제 서비스 질문을 같은 형식으로 추가해 다시 계산해야 합니다.

7주의할 점과 실무 메모

  • 이번 절의 중간 결과를 확인한 뒤 다음 단계로 전달합니다. 검색 후보, 선택 결과, 부모 원문, 재작성 질문, 로그 행은 서로 다른 데이터입니다.
  • 실행 시간은 CPU, GPU, 배치 크기, 입력 길이, 모델 캐시에 따라 달라집니다. 장치와 패키지 버전을 로그에 함께 남깁니다.
  • 짧은 질문 재작성 1회의 예상 API 비용은 미화 1달러 미만입니다. 실제 청구액은 모델 가격과 토큰 수를 확인합니다.
  • 공개 PDF 6건과 30문항은 학습용 기준선입니다. 실제 서비스의 문서 분포와 질문 유형을 대신하지 않습니다.

8정리와 다음 절

  • 대화 맥락과 후속 질문으로 독립 검색 질문을 만들었습니다.
  • 원문·재작성문·RRF 순위를 따로 보존해 의미 변화를 확인했습니다.
  • 이 결과는 대화형 후속 질문 1개와 개발용 Q001에서 관찰한 실행 사례입니다.

다음 학습과 이어지는 지점 — 12절에서 개발·시험 질문을 구분해 설정 비교를 기록하고 통합 검색·생성을 실행합니다.

9복습 문제

1. 이해 — 이번 절에서 고정한 조건은 무엇인가요?

질문 재작성 비교에서 바꾸지 않은 입력을 적어 보세요.

같은 문서 본문을 사용하고, 대화 맥락과 후속 질문의 원문을 보존했습니다. 이미 독립적인 개발용 Q001도 같은 문서에서 비교했습니다. 오답 시 다시 볼 곳: 3절 ‘앞에서 배운 내용’

2. 이해 — 원문 질문을 왜 보존하나요?

재작성문만 검색할 때 생길 수 있는 문제를 적어 보세요.

모델이 고유명사·날짜·부정 조건을 빠뜨리거나 뜻을 넓힐 수 있습니다. 원문과 재작성문을 따로 검색하고 RRF로 결합하면 두 순위를 비교할 수 있습니다. 오답 시 다시 볼 곳: 5절 ‘원문과 재작성문의 순위 결합’

3. 적용 — 어떤 질문을 재작성해야 하나요?

개발용 Q001과 “그곳의 정기 휴관일은?”를 비교해 판단해 보세요.

개발용 Q001은 기관명과 대상이 있어 그대로 검색할 수 있습니다. “그곳”처럼 대화 맥락 없이는 대상을 알 수 없는 후속 질문에 재작성을 적용합니다. 오답 시 다시 볼 곳: 5절 마지막 셀

4. 분석 — 이번 재작성으로 검색이 개선됐나요?

원문·재작성·RRF 출력을 근거로 판단해 보세요.
