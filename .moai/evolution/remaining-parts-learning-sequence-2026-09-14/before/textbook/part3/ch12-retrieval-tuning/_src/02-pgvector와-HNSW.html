1학습 목표

  • pgvector의 vector와 halfvec의 차이를 설명할 수 있습니다.
  • 코사인 거리 연산자에 맞는 연산자 클래스로 HNSW 인덱스를 만들 수 있습니다.
  • ef_search만 바꾸어 정확 검색과 HNSW 결과를 비교할 수 있습니다.

2이 내용을 배우는 이유

01절의 정확 검색은 문서 수에 비례해 비교 횟수가 늘어납니다. HNSW(Hierarchical Navigable Small World)는 가까운 이웃으로 연결된 그래프를 따라가며 일부 후보를 찾습니다. 검색 시간을 줄일 수 있지만 후보를 모두 확인하지 않으므로 정확 검색과 다른 결과가 나올 수 있습니다. 저장 타입·거리 연산자·인덱스 설정을 함께 기록해야 결과를 다시 만들 수 있습니다.

3앞에서 배운 내용

01절의 exact_rank()는 12개 문서를 모두 비교했습니다. Ch 10에서는 모델과 차원이 같아야 같은 공간에서 비교할 수 있음을 확인했습니다. 이번 절은 256차원 벡터를 PostgreSQL 17.10과 pgvector 0.8.2에 저장합니다.

4핵심 개념

여러 층의 길 안내판

큰 지역에서 목적지를 찾을 때 먼저 고속도로로 가까운 구역까지 이동한 뒤 작은 길로 들어갑니다. HNSW도 멀리 연결된 상위 계층에서 시작해 가까운 이웃이 촘촘한 아래 계층에서 후보를 고릅니다.

pgvector
PostgreSQL에 벡터 타입, 거리 연산자, 근사 검색 인덱스를 추가하는 확장입니다.
HNSW
벡터를 여러 계층의 이웃 그래프로 연결하는 근사 최근접 이웃 인덱스입니다.
vector
단정밀도 부동소수점 값을 저장합니다. 공식 v0.8.6의 HNSW 인덱스 제한은 2,000차원입니다.
halfvec
반정밀도 값을 저장합니다. HNSW 인덱스 제한은 4,000차원입니다.
ef_search
검색할 때 고려하는 후보 목록의 크기입니다. 기본값은 40이며 높이면 더 많이 탐색하는 대신 시간이 늘 수 있습니다.
연산자 클래스(operator class)
인덱스가 어떤 거리를 기준으로 정렬할지 정합니다. 코사인 거리에는 vector_cosine_ops를 사용합니다.

코사인 거리는 <=>, L2 거리는 <-> 연산자를 사용합니다. 질의의 ORDER BY 연산자와 인덱스의 연산자 클래스가 일치해야 합니다. 인덱스를 만들었다는 사실만으로 항상 선택되는 것은 아니므로 EXPLAIN으로 실행 계획도 확인합니다.

5실행 예제

전용 컨테이너의 확장 버전을 조회하고 ch12_core_hnsw 표에 12개 벡터를 넣습니다. 정확 검색과 HNSW의 top-3를 비교하고 ef_search를 4와 40으로 실행합니다. 마지막에는 2,001차원 vector와 halfvec의 HNSW 인덱스 생성 결과를 확인합니다.

6실험 결과 해석

vector(2001) HNSW 인덱스는 “2,000 dimensions” 제한 오류를 반환했고 halfvec(2001)은 생성에 성공했습니다. 공식 최신 v0.8.6의 2,000/4,000차원 설명과 실습 컨테이너의 0.8.2에서 관찰한 결과가 일치한 사례입니다. 문서 12개는 속도 이점이나 ef_search에 따른 Recall 차이를 관찰하기에 부족합니다. 전체 질의셋과 큰 말뭉치에서 지연 시간과 Recall을 함께 측정해야 합니다.

7주의할 점과 실무 메모

  • 공식 최신 안정판은 v0.8.6이지만 실습 컨테이너는 실행을 검증한 0.8.2-pg17입니다. 기능과 출력의 기준 버전을 섞지 않습니다.
  • halfvec는 차원 제한을 늘리지만 정밀도를 낮춥니다. 저장 크기와 Recall@50·nDCG@5를 함께 비교합니다.
  • Docker 포트는 127.0.0.1:55432에만 공개합니다. 실습 암호를 서비스에 사용하지 않습니다.

8정리와 다음 절

  • HNSW는 그래프를 따라 후보를 줄이는 근사 검색입니다.
  • 타입·차원·거리 연산자·인덱스 연산자 클래스를 함께 맞춥니다.
  • 현재 환경에서 vector 2,001차원 색인은 실패하고 halfvec는 성공했습니다.

9복습 문제

문제 4개 · 해설 포함

1. HNSW가 정확 검색보다 결과를 놓칠 수 있는 이유는 무엇입니까?

모든 벡터를 비교하지 않고 그래프 경로의 후보를 탐색하기 때문입니다. 틀렸다면 HNSW 정의를 다시 읽습니다.

2. 3,072차원 벡터를 HNSW로 색인할 때 어느 타입이 차원 제한을 통과합니까?

halfvec입니다. vector는 2,000차원, halfvec는 4,000차원까지 지원합니다. 틀렸다면 타입 정의를 확인합니다.

3. 코사인 거리와 맞는 vector 연산자 클래스는 무엇입니까?

vector_cosine_ops입니다. 틀렸다면 실행 예제의 CREATE INDEX를 확인합니다.

4. ef_search=40이 4보다 항상 더 좋은 설정입니까?

항상 그렇지 않습니다. 품질과 지연 시간을 같은 질의셋에서 측정해야 합니다. 틀렸다면 「실험 결과 해석」을 다시 읽습니다.
