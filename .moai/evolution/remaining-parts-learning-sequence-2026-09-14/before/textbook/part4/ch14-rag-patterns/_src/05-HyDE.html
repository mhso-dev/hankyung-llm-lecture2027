2이 내용을 배우는 이유

짧은 질문은 실제 문서보다 정보가 적고 문장 형태도 다릅니다. HyDE는 질문에 답할 법한 문서를 먼저 가상으로 만든 뒤 그 문서를 임베딩합니다. 검색 공간에서 질문과 문서의 표현 차이를 줄이려는 접근입니다.

Ch9의 기본 RAG는 검색 한 번과 생성 한 번으로 구성되었습니다. Ch14에서는 질문을 바꾸거나 결과를 검사하는 단계를 추가합니다. 모든 선택은 if 문, 수치 임계값, 반복 상한에 적힌 규칙으로 실행합니다. 모델이 다음 행동을 자율적으로 결정하는 에이전트는 아직 사용하지 않습니다.

3앞에서 배운 내용

Ch11에서 정답 문서 ID와 Recall을 분리해 기록했습니다. Ch12에서는 core-documents.json의 문서 12건과 core-queries.json의 질문 8건으로 검색 설정을 비교했습니다. 이 절은 두 파일의 내용을 챕터 폴더에 복제해 같은 문서와 정답을 사용합니다. 전체 제공 PDF와 30문항을 쓰지 않는 축소 표본입니다.

4핵심 개념

HyDE

HyDE
HyDE(Hypothetical Document Embeddings)는 생성 모델이 만든 가상 문서의 임베딩으로 실제 문서를 검색합니다. 가상 문서는 검색용 신호이며 사실 근거나 인용 자료가 아닙니다. 최종 답은 반드시 검색된 실제 문서를 근거로 만들어야 합니다.
흐름을 정하는 규칙
가상 문서는 두 문장으로 한 번만 생성하고 검색에만 사용합니다. 상위 세 실제 문서 가운데 정답 순위를 비교하며, 가상 문장의 내용은 답과 인용에서 제외합니다.

도식의 상자를 위에서 아래로 읽습니다. 나란한 상자는 분기하거나 따로 실행한 뒤 다시 합치는 처리입니다. 생성한 질문, 가상 문서, 평가 점수는 검색을 돕는 중간 값이며 출처로 인용하지 않습니다.

6실험 결과 해석

학생증 분실 질문의 기준선은 ACC-003을 0.420으로 1위에 두었습니다. HyDE에서는 FAC-004가 0.487로 1위, ACC-001이 0.456으로 2위, 정답 ACC-003은 0.423으로 3위가 되었습니다. 검색은 성공했지만 정답 순위는 두 단계 낮아졌고, 가상 문서 생성에 105토큰과 약 1069.6ms가 들었습니다.

가상 문서가 틀린 절차를 포함하면 검색이 잘못된 방향으로 이동할 수 있습니다. 실제 출력에도 ‘방문 신고’와 ‘비밀번호 변경’처럼 원문에 없는 내용이 들어갔습니다. 이 문장을 답의 근거로 사용하면 안 됩니다.

코사인 유사도는 질문과 문서 벡터가 같은 방향을 가리키는 정도입니다. 이 값은 정답 확률이 아니며 데이터와 임베딩 모델이 바뀌면 임계값도 다시 정해야 합니다. 실제 출력이 좋아지지 않았다면 개선으로 바꾸어 서술하지 않습니다.

7주의할 점과 실무 메모

  • 운영 전에 확인합니다. 가상 문서에 원문에 없는 절차가 포함되면 검색 방향도 달라지므로 가상 문장을 사실 근거로 저장하거나 인용하지 않습니다.
  • 기록할 항목을 정합니다. 가상 문서와 검색된 실제 문서를 서로 다른 필드에 저장해야 인용 단계에서 섞이지 않습니다.

8정리와 다음 절

  • 가상 문서가 질문과 문서의 표현 차이를 줄일 수 있지만 잘못된 내용은 정답 순위를 낮출 수 있습니다.
  • 가상 문서는 검증된 사실이 아니므로 검색 신호로만 사용해야 합니다.

9복습 문제

문제 4개 · 해설 포함

1. HyDE의 입력과 출력은 무엇입니까?

원 질문을 입력하면 답처럼 보이는 가상 문서와 그 임베딩으로 검색한 실제 문서 후보를 출력합니다.

2. 이 절의 실제 출력은 패턴 선택에 어떤 근거를 줍니까?

가상 문서의 추가 내용 때문에 정답 ACC-003이 1위에서 3위로 내려갔습니다.

3. 코드에서 호출 수나 후보 수를 제한하는 규칙은 무엇입니까?

가상 문서는 두 문장으로 한 번 만들고 실제 문서 세 건까지만 비교합니다.

4. 생성한 중간 문장을 최종 답의 출처로 쓰면 안 되는 이유를 설명하세요.

모델이 만든 문장은 원문 자료에서 확인한 사실이 아닙니다. 실제 검색된 문서의 ID와 본문만 근거로 인용합니다.
