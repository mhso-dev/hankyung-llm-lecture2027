1학습 목표

  • 모델 호출 전에 횟수와 예상 비용을 예약할 수 있습니다.
  • 상한을 넘는 요청을 실제 API 호출 전에 거부할 수 있습니다.
  • 예상 비용과 반환 사용량을 구분해 기록할 수 있습니다.

2이 내용을 배우는 이유

재작성, 검색 평가, 요약, 답변 생성을 연결하면 질문 한 건이 여러 모델 호출이 됩니다. 재시도까지 겹치면 사용자가 예상한 범위를 넘을 수 있습니다. 호출 전에 최악의 예상량을 예약해야 이미 비용이 발생한 뒤 초과를 발견하는 문제를 피할 수 있습니다.

3앞에서 배운 내용

Ch 6에서 usage_metadata의 입력·출력 토큰을 읽었고 Ch 15에서 평균 대신 대화당 비용 분포를 보았습니다. 이 절은 한 대화가 시작될 때 호출 수와 금액 상한을 정하고 각 호출 앞에서 남은 예산을 검사합니다.

4핵심 개념

쉬운 예

교통카드 잔액을 확인한 뒤 승차 금액을 먼저 확보하는 것처럼, 모델 호출도 실행 전에 최악 조건의 계획 비용이 남아 있는지 확인합니다.

정의

호출 한도(rate 또는 call limit)는 한 세션에서 허용하는 모델 호출 횟수입니다. 이 절의 비용 상한(cost cap)은 호출 전에 계산한 계획 비용의 누적 한도입니다. 예약(reservation)은 실제 결제와 별개로 최악 조건의 계획 비용을 남은 계획 비용 범위에서 먼저 확보하는 처리입니다. 호출 뒤에는 실제 사용량을 기록해 예상과 실제 차이를 분석합니다.

6일부러 실패해 보기

호출당 0.002달러라는 수업용 계산값을 예약하고 실제 모델을 한 번 호출했습니다. 두 번째 요청이 남은 금액보다 큰 조건은 API 호출 전에 거부됐고 0.001달러 조건은 통과했습니다. 계산값은 제품 가격표가 아니므로 배포 전에는 선택한 모델의 공식 가격과 사용량 필드로 다시 정합니다.

7주의할 점과 실무 메모

  • 예상 비용 단가는 코드에 근거 없이 고정하지 않고 배포 설정과 확인 날짜를 함께 관리합니다.
  • 스트리밍 중단이나 제공자 오류에도 이미 사용된 토큰이 있을 수 있으므로 실제 사용량을 별도로 기록합니다.

실제 모델 호출은 절마다 미화 1달러 미만이 되도록 짧은 입력과 출력을 사용했습니다. 정확한 청구액은 제공자 사용량 화면과 해당 실행 시점 가격표를 확인해야 합니다.

8정리와 다음 절

  • 모델 호출 전에 횟수와 예상 비용을 예약할 수 있습니다.
  • 0.005달러 계획 상한을 넘는 추가 예약은 모델 호출 전에 거부됐습니다.
  • 이 절의 통과 결과는 실행한 입력과 정책 범위에서만 해석합니다.

다음 학습과 이어지는 지점 — 다음 절에서는 한도 안에서 재시도할 오류와 폴백 경로를 정하고 그 결정을 감사 로그에 남깁니다.
