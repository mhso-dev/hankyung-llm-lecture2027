1학습 목표

  • Batch API용 JSONL 입력을 만들 수 있습니다.
  • 각 요청의 식별자와 구조를 제출 전에 검사할 수 있습니다.
  • 즉시 처리와 비동기 배치 처리의 선택 기준을 설명할 수 있습니다.

2이 내용을 배우는 이유

야간 평가, 대량 분류, 임베딩 생성처럼 완료 시각에 여유가 있는 작업은 비동기 배치로 모을 수 있습니다. OpenAI Batch API는 별도 처리 한도와 24시간 완료 창을 제공하며 표준 동기 API 대비 50% 할인된 가격을 안내합니다. 비용을 줄이는 대신 즉시 결과를 받을 수 없다는 조건을 받아들여야 합니다.

3앞에서 배운 내용

Ch 15의 runs/batch-eval-input.jsonl에서는 평가 입력 형식을 준비했습니다. 이번 절은 같은 JSON Lines(JSONL) 원리를 Responses API의 실제 배치 요청 구조에 적용합니다. JSONL은 한 줄마다 하나의 JSON 객체를 저장하는 파일 형식입니다.

4핵심 개념

접수함에 모아 처리하기

창구 직원이 손님 한 명마다 즉시 서류를 처리하는 방식과, 마감 시각까지 접수한 서류를 한꺼번에 처리하는 방식은 기다림과 운영 비용이 다릅니다. Batch API는 두 번째 방식에 해당합니다. 요청자는 custom_id로 각 결과를 원래 업무와 연결합니다.

비동기 처리(asynchronous processing)
요청 제출과 결과 수신이 같은 연결에서 즉시 끝나지 않는 처리 방식입니다.
JSONL
각 줄이 독립된 JSON 객체인 텍스트 형식입니다.
custom_id
배치 결과를 원래 요청과 연결하기 위해 사용자가 정하는 고유 값입니다.
완료 창(completion window)
배치 처리가 완료되어야 하는 시간 범위이며 현재 공식 문서는 24h를 안내합니다.

7주의할 점과 실무 메모

  • custom_id는 배치 안에서 고유해야 하며 결과 순서가 입력 순서와 같다고 가정하지 않습니다.
  • 입력 파일 업로드와 배치 생성은 외부 작업을 시작합니다. 이 교재는 구조를 완성하고 로컬 검증한 뒤 실제 제출은 수행하지 않았습니다.
  • 24시간 완료 창은 즉시 응답이 필요한 사용자 요청에 맞지 않습니다.
  • 할인율과 지원 엔드포인트는 바뀔 수 있으므로 배포 전에 공식 문서를 다시 확인합니다.

8정리와 다음 절

  • Batch API는 완료 시각에 여유가 있는 대량 작업에 사용합니다.
  • 각 요청은 JSONL 한 줄과 고유한 custom_id를 가져야 합니다.
  • 파일 구조 검증과 실제 제출을 별도 단계로 둡니다.

9복습 문제

문제와 해설

1. Batch API가 고객 채팅의 첫 응답에 맞지 않는 이유는 무엇인가요?

결과가 비동기로 처리되며 현재 완료 창이 24시간이기 때문입니다.

2. 결과를 원래 문의와 연결하는 필드는 무엇인가요?

custom_id입니다.

3. JSON 배열 파일과 JSONL의 차이는 무엇인가요?

JSON 배열은 전체가 하나의 값이고, JSONL은 각 줄이 독립된 JSON 객체입니다.
