1학습 목표

  • HTTP 요청을 Agent 상태로 변환해 실제 `ainvoke`를 호출할 수 있습니다.
  • 최종 상태에서 공개할 답만 골라 응답 모델을 만들 수 있습니다.
  • 예외와 시간 초과를 HTTP 오류로 바꿀 위치를 설명할 수 있습니다.

2이 내용을 배우는 이유

Agent를 일반 동기 함수처럼 호출하면 비동기 서버의 장점을 잃습니다. 그래프의 최종 상태를 그대로 반환하면 내부 메시지와 중간 결과도 API에 섞입니다. 서비스 계층은 HTTP 데이터와 Agent 상태 사이를 명시적으로 변환해야 합니다.

3앞에서 배운 내용

Ch21에서 Agent의 입력과 결과가 상태 사전임을 확인했습니다. Ch25에서는 단일 실행과 스트리밍이 같은 실행 객체의 다른 소비 방법임을 배웠습니다.

4핵심 개념

택배 창구는 주소와 연락처를 내부 운송 형식으로 바꾸고 결과 중 송장 번호와 상태만 고객에게 줍니다. 내부 분류 코드까지 모두 공개하지 않습니다. FastAPI 라우트도 요청과 Agent 상태 사이에서 같은 경계 변환을 맡습니다.

`ainvoke`는 비동기 단일 실행 메서드입니다. 호출자는 `await`로 최종 상태를 기다리지만 그동안 이벤트 루프는 다른 요청을 처리할 수 있습니다. 이 교재의 객체는 `StateGraph`를 컴파일한 실제 LangGraph입니다. 입력은 `{'messages': [question]}`이고 출력에는 입력 메시지와 `answer`가 있습니다.

라우트는 결과의 `answer`만 `ChatResponse`로 옮기고 요청의 `thread_id`를 함께 반환합니다. 이 변환을 명시하면 Agent 내부 키가 추가되어도 외부 계약을 유지할 수 있습니다. 반대로 외부 필드를 바꾸려면 Pydantic 모델과 변환 코드, OpenAPI 변경을 함께 검토합니다.

외부 모델 호출에는 완료 시간이 보장되지 않습니다. DNS, 공급자 대기열, 네트워크, 도구가 모두 지연 원인입니다. `asyncio.wait_for`로 전체 Agent 실행 시간을 제한하고 단일 응답에서는 504로 바꿉니다. 모델 클라이언트 timeout만 두면 여러 도구를 포함한 전체 실행 시간이 상한을 넘을 수 있습니다.

예외 원문에는 내부 경로나 공급자 정보가 포함될 수 있습니다. 로그에는 요청 식별자와 원인 예외를 남기고 공개 응답에는 안정적인 오류 코드와 사용자가 취할 행동을 담습니다. 시간 초과만 기록하지 말고 모델과 도구별 소요 시간도 측정해야 느린 단계를 찾을 수 있습니다.

서비스 설계 판단

단일 응답 API의 경계 변환에는 입력 상태, 실행 설정, 공개 응답의 세 부분이 있습니다. 질문은 messages로 바꾸고 thread_id는 체크포인터 설정이나 로그 문맥에 사용하며, 최종 상태에서는 사용자에게 공개할 AI 메시지만 선택합니다. 도구 출력에 포함된 출처와 내부 오류를 그대로 응답에 넣기 전에 공개 범위를 검토합니다. 시간 상한은 하나의 숫자로 끝나지 않습니다. 전체 요청 45초 안에서 모델 30초, 도구 10초처럼 하위 단계의 제한과 재시도 예산을 배분해야 합니다. 첫 모델 호출이 30초를 모두 사용한 뒤 같은 제한으로 재시도하면 전체 상한을 넘을 수 있습니다. 남은 시간을 전달하거나 바깥 timeout이 실행을 취소하도록 구성하고, 취소가 공급자 요청까지 전달되는지 로그와 사용량으로 확인합니다.

7주의할 점과 실무 메모

  • Agent 최종 상태의 모든 키를 응답으로 직렬화하지 않습니다.
  • 504가 발생하면 어느 내부 단계가 느렸는지 추적할 지표를 함께 남깁니다.
  • 교육용 Agent는 서비스 검증용이며 실제 모델 품질은 Ch29 평가셋으로 확인합니다.

9복습 문제

1. `ainvoke`에 `await`가 필요한 이유는 무엇인가요?

해설 — 비동기 완료를 기다리면서 다른 요청 처리를 허용하기 위해서입니다.

2. 최종 상태 전체를 반환하지 않는 이유는 무엇인가요?

해설 — 내부 정보 노출을 막고 외부 계약을 유지하기 위해서입니다.

3. 전체 시간 상한은 어디에 두나요?

해설 — Agent 호출을 감싸는 서비스 경계에 둡니다.

4. 공개 오류를 분리하는 이유는 무엇인가요?

해설 — 민감한 내부 정보를 숨기고 안정적인 처리 규칙을 주기 위해서입니다.
