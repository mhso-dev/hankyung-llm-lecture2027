| Ch7-03 Few-shot 예시 선택 | 예시 입력과 예시 답의 대응, 별도 훈련이 아님, 고정 예시 선택을 코드 전에 설명합니다. 감정 분류의 혼합 문장과 주문번호 복사 위험을 비교하고 실제 회귀를 숨기지 않습니다. |

| Ch7-05 CoT와 ReAct의 경계 | 공개 근거와 내부 추론 전문, 생성 문장과 실제 도구 행동을 구분합니다. 영수증 원문·계산 함수 사례로 경계를 옮기며 이 노트북이 ReAct 실행이 아님을 반복해 제한합니다. |
| Ch7-06 Self-Consistency와 표본 합의 | 원 기법을 다양한 추론 경로의 표집과 최종 답 집계로 먼저 정의한 뒤, 현재 노트북은 내부 추론을 수집하지 않는 최종 라벨 반복·집계 축소 실습이라고 구분합니다. 전체 시도를 과반 분모로 쓰는 코드와 형식 오류·동률을 구체적으로 계산하며 표본의 통계적 독립성을 단정하지 않습니다. 정리 문장도 원 기법 전체가 아니라 이번 축소 실습에서 관찰한 최종 분류 라벨 집계만 서술합니다. |
| Ch7-07 구조화 출력 프롬프트 진단 | `json.loads()`가 반환할 수 있는 Python 값, 키 존재 검사의 범위, 자료형·허용값·업무 사실의 별도 검증을 설명합니다. 일정 추출 사례로 적용합니다. 노트북의 첫 질문과 활성 생성기도 실제 검사 범위인 ‘필드 존재 여부’로 동기화했습니다. |

| Ch8-01 컨텍스트와 토큰 예산 | 모델 한도와 수업 예산, 출력 예약분, 여유분을 분리합니다. `input_budget()`의 입력·반환·예외와 모델의 `max_tokens`가 별도로 유지됨을 코드 전에 설명하고 분류와 장문 설명을 비교합니다. |

| Ch8-03 Compress와 Isolate | `compress()`가 원문 자동 요약이 아니라 사람이 고른 네 필드의 문자열 조립임을 명시합니다. 회의 배포 조건 사례와 출처 문자열 검사의 한계를 설명하며 태그와 보안 격리도 구분합니다. |

| Ch8-05 Context rot 측정 | 길이 증가와 정답 활용 성능 저하를 별도 축으로 둡니다. 세 길이·세 반복의 실제 9개 답을 읽게 하고 문자열 검사의 반례를 설명하며 미관찰 결론을 유지합니다. |
| Ch8-06 단계적 공개와 설계 비교 | 목록·사람이 지정한 ID·원문 읽기·모델 호출의 주체와 순서를 분리합니다. 복수 상품 규격 질문을 들어 선택 문서 수가 항상 하나가 아님을 설명하고 자동 검사의 범위를 제한합니다. 고정 반복문이 목록을 보여 주는 주체라는 문장도 자연스럽게 교정했습니다. |

## 정독 소견과 최종 검수

- 현재 인상: 기존 본문을 지우고 일반론으로 바꾼 흔적은 거의 없으며, 추가 문단은 API 첫 사용, Python 표기, 실행 경계, 다른 상황, 관찰 한계를 해당 코드 바로 앞에 배치했습니다. Ch6-03과 Ch7-04는 사용 가능한 옵션을 나열하기 전에 기본 호출 의미를 충분히 설명하여 사용자가 지적한 학습 순서 문제를 해결했습니다.
- 언어: `~합니다`체가 유지되고 비유 단락 뒤에는 정식 용어로 돌아옵니다. 기계적 수사나 비용 부연이 깊이를 대신하는 지배 패턴은 확인하지 못했습니다. 지적한 조사 오류와 검사 범위를 넓게 부른 표현은 모두 국소 교정되었습니다.
- 의미 보존 15항: 원문의 수치·날짜·고유명사·직접 인용·제목 독립성은 `before/` 비교에서 보존되었습니다. 선수 절과 Self-Consistency 첫 정의의 정확성도 안정본에서 다시 확인했습니다.
- 과윤문: 격식 상향, 상투구 주입, 문학화는 확인하지 못했습니다.
