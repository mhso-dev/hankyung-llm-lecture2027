1학습 목표
이 절을 마치면 질문과 정답 문서 ID를 한 행으로 기록할 수 있습니다.
개발용과 시험용 질문을 분리할 수 있습니다.
정답 문장이 없어도 검색 품질을 계산할 수 있는 이유를 설명할 수 있습니다.
2이 내용을 배우는 이유
검색 설정을 바꾼 뒤 결과 몇 개만 읽으면 좋아 보이는 사례를 고르기 쉽습니다. 측정은 설정을 바꾸기 전에 질문과 판정 기준을 먼저 고정하는 일에서 시작합니다. 이 장에서는 공개 PDF와 질문 30개를 사용합니다. 질문은 쉬움·보통·어려움 난이도에서 각각 10개를 고르고, 각 난이도의 질문을 개발용 5개와 시험용 5개로 나눕니다.
이 장의 대상은 검색 단계입니다. 모델 답변이 사실에 근거하는지는 Ch 15에서 평가합니다. 학습용 파일에는 질문과 정답 문서 ID를 넣고 정답 문장은 넣지 않습니다. 학생은 검색 순위만으로 지표를 계산할 수 있고, 정답 문장이 답변 생성 실험에 섞이는 문제도 줄일 수 있습니다.
3앞에서 배운 내용
Ch 9의 PDF 로더와 스플리터 실습은 E01.pdf의 2쪽을 Document 객체로 바꾸고 doc_id·page·source를 청크에 유지했습니다. Ch 10의 01~07절에서는 이 출처 항목의 형식과 문자·토큰·구조 기반 청킹의 차이를 각각 확인했습니다. Ch 10의 08절 연결 실습은 공개 디지털 PDF 18건에 세 청킹 방법과 두 임베딩 모델을 적용하고 Q001의 검색 순위를 로그로 남겼습니다. 이번 노트북은 제공 PDF를 다시 읽어 페이지 텍스트를 독립 기준선의 검색 후보로 만듭니다.
4핵심 개념
비유 — 채점표를 먼저 봉인합니다
시험 문제를 본 뒤 정답 기준을 바꾸면 점수를 믿기 어렵습니다. 검색 평가도 같습니다. 질문, 정답 문서 ID, 질문 유형, 자료 분할을 먼저 정한 뒤 검색 설정을 비교합니다.질의셋 (query set)평가에 반복해서 사용하는 질문 모음입니다.정답 문서 ID (gold document ID)질문에 답할 근거를 포함한다고 사람이 확인한 문서의 고유 식별자입니다.관련도 판정 (relevance judgment)문서가 질문에 관련되는지를 정한 라벨입니다. 이 장은 관련 1, 비관련 0의 이진 라벨을 사용합니다.개발 분할 (dev split)설정 선택과 오류 확인에 사용하는 질문입니다.시험 분할 (test split)선택을 마친 설정을 마지막에 확인하는 질문입니다.
질문에는 정답 문서 ID를 연결하고, 같은 난이도 안에서 개발용과 시험용을 나눕니다.
정답 문서 ID는 청크 ID와 다릅니다. 같은 문서에서 여러 페이지나 청크가 검색되어도 지표에서는 문서 하나로 한 번만 셉니다. 청크를 더 작게 나눈 설정이 같은 정답 문서를 여러 번 차지해 유리해지는 것을 막기 위해서입니다. 쪽 번호와 청크 ID는 오류 원인을 읽을 때 보조 정보로 남깁니다.
answerable:false이거나 정답 문서 ID가 빈 질문은 검색 지표 평균에서 제외하고 제외 건수를 기록합니다. 정답이 없는 질문에 0점을 주면 검색기가 놓친 사례와 애초에 검색할 정답이 없는 사례가 섞입니다. 그러한 질문에서 시스템이 답변을 거부해야 하는지는 Ch 15의 별도 평가 대상입니다.
답변 판정 기준은 별도 표로 합의합니다
질문 예필수 내용금지 내용출처 형식
정기 휴관일은?요일과 공휴일 예외문서에 없는 운영 시간[E01 p.2]
출장 숙박비 한도는?금액과 국내 출장 조건해외 출장 규정 혼합[E02 p.4]
이 표는 생성 답변을 평가할 때 사용합니다. Ch 11의 Recall·Precision·nDCG는 정답 문서를 찾았는지만 계산하므로 필수 내용이 답에 포함되었는지, 금지 내용을 말하지 않았는지, 출처 형식을 지켰는지 검증할 수 없습니다. 생성 답변 기준은 합의해 두되 자동 판정은 Ch 15에서 수행합니다.
평가 행을 코드에서 읽는 순서
JSONL은 한 줄에 질문 한 건을 저장하는 형식입니다. json.loads(line)가 문자열 한 줄을 사전으로 반환하고, gold_doc_ids는 답의 문장이 아니라 근거를 포함한 문서 ID 목록입니다. 이 노트북의 후보는 PDF 쪽이며 각 후보가 이미 부모 doc_id를 가집니다. search()는 같은 문서의 여러 쪽 가운데 점수가 가장 높은 쪽 하나만 남겨 고유 문서 순위를 반환합니다.
split은 코드 실행 방식을 바꾸는 옵션이 아니라 질문을 설정 선택용 dev와 마지막 확인용 test로 나누는 라벨입니다. 고객 질문처럼 실제 분포가 바뀌면 기존 30문항의 점수만으로 대표성을 보장할 수 없습니다. 정답 문서가 여러 개인 질문은 어느 문서 하나면 충분한지, 모두 필요한지 라벨 지침에서 먼저 정해야 합니다.
5실행 예제
노트북은 evaluation-queries.jsonl 30행을 읽고 필수 필드를 검사합니다. 공개 PDF에서 실제 페이지 텍스트를 추출하고 단어와 한글 두 글자 조각이 겹치는 정도로 검색합니다. 설정 선택용 dev 질문 수를 5개와 15개로 바꿔 일부 질문만 볼 때 문서 분포가 얼마나 좁아지는지도 확인합니다. 시험용 질문의 정답 분포는 설정 선택에 사용하지 않습니다.
확인할 점 — 각 행에 qid, tier, split, question, type, gold_doc_ids, answerable이 있으며 answer가 없는지 확인합니다.
6실험 결과 해석
실행 결과는 질문 30개와 실제 PDF에서 추출한 검색 후보를 보여 줍니다. 5개만 잘라 보면 일부 정답 문서에 질문이 몰릴 수 있지만, 층화한 30개에는 쉬움·보통·어려움 난이도의 질문이 포함됩니다. 이 차이는 적은 질문으로 전체 품질을 판단하면 문서 유형의 영향을 놓칠 수 있음을 보여 줍니다. 다만 30개도 운영 질문 전체를 대표한다고 단정할 수 없습니다.
7주의할 점과 실무 메모
정답 문서 ID는 원문을 읽고 부여합니다. 검색 결과를 정답으로 복사하면 기존 검색기의 편향이 라벨에 반영됩니다.
시험 분할 결과를 보고 설정을 다시 고르면 그 질문은 사실상 개발용이 됩니다.
이 실습은 로컬 PDF 추출과 일반 Python만 사용하므로 API 비용은 0달러입니다.
이 실습의 학습용 라벨은 공개 PDF의 문서 ID만 담습니다. 답변 문장·개인정보·비공개 평가 자료는 별도 권한으로 관리합니다.
8정리와 다음 절
검색 평가는 질문과 정답 문서 ID를 먼저 고정합니다.
문서 ID는 지표 단위이고 페이지·청크 ID는 원인 분석 정보입니다.
개발용과 시험용을 분리하고 정답 없는 질문은 검색 평균에서 제외합니다.
다음 학습과 이어지는 지점 — 다음 절에서는 정답 문서가 후보 50개 안에 포함되는지 Recall@50으로 계산합니다.

1학습 목표
Recall@50을 정답 문서 수와 찾은 정답 문서 수로 계산할 수 있습니다.
6위와 51위의 차이를 설명할 수 있습니다.
작은 말뭉치에서 Recall@50이 포화되는 이유를 말할 수 있습니다.
2이 내용을 배우는 이유
재정렬기는 후보 목록 안의 문서만 순서를 바꿀 수 있습니다. 정답 문서가 1차 검색 후보 50개에 없다면 재정렬기를 바꿔도 복구할 수 없습니다. Ch 12에서 상위 순위를 조정하기 전에 후보 생성 단계가 정답 문서를 포함했는지 Recall@50으로 확인합니다.
3앞에서 배운 내용
01절에서 질문마다 gold_doc_ids를 붙이고 문서 ID 중복을 제거하기로 정했습니다. 이번 절의 입력은 그 질문 파일과 검색 결과입니다. 점수가 같을 때 문서 ID와 쪽 번호로 순서를 정해 반복 실행 결과를 고정합니다.
4핵심 개념
비유 — 결승 심사 후보를 빠뜨리지 않기
결승 심사위원은 예선에서 탈락한 지원자를 다시 평가할 수 없습니다. 1차 검색은 예선, 재정렬은 결승 순서 결정에 해당합니다. Recall@50은 정답 문서가 예선을 통과했는지 측정합니다.재현율 (recall)전체 정답 문서 가운데 검색 결과에 포함된 정답 문서의 비율입니다.절단 깊이 k (cutoff)순위 목록의 앞에서 몇 개까지 평가할지 정한 값입니다.후보 집합 (candidate set)재정렬 단계에 넘기는 1차 검색 결과입니다.거시 평균 (macro mean)질문별 점수를 계산한 뒤 각 질문에 같은 가중치를 주어 평균한 값입니다.
Recall@50 = |정답 문서 ∩ 상위 50개 고유 문서| / |정답 문서|입니다. 정답 문서가 두 개이고 하나만 후보에 포함되면 0.5입니다. 검색 결과가 비어 있고 정답 문서가 있으면 0입니다.전체 말뭉치에서 후보 50개를 고른 뒤 정답 문서가 포함되었는지 확인합니다.
문서 ID 중복 제거는 상위 k개를 선택하기 전에 수행합니다. 같은 문서의 페이지 10개가 상위에 있어도 고유 문서 하나입니다. 먼저 상위 50개를 선택한 뒤 중복을 제거하면 청크 수가 많은 문서가 목록을 점유할 수 있습니다.
Recall 함수의 입력과 경계
search()는 같은 문서의 여러 쪽 가운데 최고 점수 한 쪽만 남겨 고유 문서 순위를 먼저 반환합니다. recall_at()은 이 이미 고유한 결과의 앞 k개와 정답 문서 ID 집합을 입력받아, 정답과 겹치는 문서 수를 전체 정답 수로 나눕니다. 중복 제거는 recall_at()이 아니라 search()의 책임입니다. 반환값은 질문 한 건의 0~1 점수이며 화면의 평균은 이 값을 질문별로 계산한 뒤 만든 값입니다.
정답이 6위이면 Recall@5에는 없고 Recall@50에는 있습니다. 따라서 Recall@50이 높아도 사용자가 보는 첫 화면의 순서가 좋다는 뜻은 아닙니다. 후보 생성기를 점검할 때는 큰 k, 실제 답 입력의 앞부분을 점검할 때는 더 작은 k도 함께 봅니다.
5실행 예제
설정 선택용 dev 15개 질문으로 Recall@1, @5, @10, @50을 계산합니다. 시험용 15개는 설정 선택에 사용하지 않습니다. 이어서 51개 고유 문서로 만든 통제 목록에서 정답이 50위일 때는 1, 51위일 때는 0이 되는지 검사합니다.
확인할 점 — dev 15개의 Recall@1은 0.733, Recall@5와 Recall@50은 1.000입니다. 실제 검색 가능한 고유 문서는 17개이므로, 50위·51위 경계는 별도 통제 목록으로 확인합니다.
6실험 결과 해석
기준 실행의 Recall@50은 1.000입니다. 그러나 검색 가능한 고유 문서가 17개뿐이므로 상위 50개를 요청하면 모든 문서가 후보가 됩니다. 1.000은 검색기가 어려운 질문을 모두 잘 찾았다는 증거가 아니라 현재 자료 크기에서 지표가 천장에 도달한 결과입니다.
Recall@5와 @10은 정답 문서가 앞부분에 포함되는지를 보조로 보여 줍니다. 운영 규모와 비슷한 더 큰 말뭉치가 준비되면 @50을 다시 측정해야 합니다. 51개 통제 목록은 실제 검색 품질이 아니라 절단 경계 구현을 검증합니다.
7주의할 점과 실무 메모
Recall@50과 Precision@5를 한 점수로 합치지 않습니다. 수정할 단계가 다릅니다.
정답이 50위에 있으면 Recall@50에는 포함되지만 사용자가 읽는 상위 5개에는 없을 수 있습니다.
이번 실행의 API 비용은 0달러입니다.
17개 문서 기준선은 Ch 12의 설정 우열을 판단할 Recall 실험으로는 충분하지 않습니다.
8정리와 다음 절
Recall@50은 후보에 포함된 정답 문서의 비율입니다.
중복 문서 ID를 제거한 뒤 상위 50개를 평가합니다.
지표가 1이어도 후보 수와 평가 범위를 함께 확인합니다.
다음 학습과 이어지는 지점 — 다음 절은 앞 다섯 자리의 정확성을 Precision@5로 확인합니다.

1학습 목표
Precision@5를 분모 5로 계산할 수 있습니다.
결과가 다섯 개보다 적어도 분모를 바꾸지 않는 이유를 설명할 수 있습니다.

2이 내용을 배우는 이유
후보 50개에 정답이 있어도 사용자가 처음 보는 다섯 문서가 관련 없는 내용이라면 검색 화면과 생성 입력은 불필요한 문서로 채워집니다. Precision@5는 제한된 상위 자리를 정답 문서가 얼마나 정확하게 차지하는지 확인합니다. Ch 12의 재정렬 실험은 같은 후보를 고정하고 이 지표를 비교합니다.
3앞에서 배운 내용
02절은 후보 포함 여부를 Recall@50으로 측정했습니다. 이번 절도 순서를 유지해 중복 문서 ID를 제거한 목록을 사용합니다. 정답 라벨과 질문은 그대로 두고 평가 깊이만 5로 줄입니다.
4핵심 개념
비유 — 첫 화면의 다섯 자리
검색 결과 첫 화면에 다섯 자리가 있다고 생각합니다. 관련 문서가 한 개면 Precision@5는 1/5, 즉 0.2입니다. 빈 자리가 있거나 관련 없는 문서가 있으면 정답 수는 늘지 않습니다.정밀도 (precision)평가하는 상위 k개 결과 가운데 정답 문서가 차지한 비율입니다.고정 분모 (fixed denominator)반환 문서가 부족해도 약속한 k를 분모로 사용하는 정책입니다.반환 개수 (returned count)검색기가 실제 반환한 고유 문서 수입니다.단일 정답 라벨 (single-gold label)한 질문에 정답 문서가 하나만 있는 라벨입니다.
Precision@5 = 상위 5개 안의 정답 문서 수 / 5입니다. 두 개만 반환했고 둘 다 정답이어도 2로 나누지 않습니다. 5로 나누지 않으면 결과를 덜 반환한 시스템이 부당하게 높은 점수를 받을 수 있습니다. 따라서 점수와 함께 returned_count를 남겨 결과 부족을 드러냅니다.후보 목록에서 상위 다섯 문서를 선택해 정답 문서의 비율을 계산합니다.
전체 30개 질문은 각각 정답 문서가 하나입니다. 설정을 고르는 실행은 dev 15개만 사용합니다. 그러므로 가능한 Precision@5 최댓값은 0.2입니다. 이 값에 도달했다는 사실은 정답이 모두 상위 5개에 있다는 뜻이며, 나머지 네 문서가 관련 있는지까지 보여 주지는 않습니다.
분모 정책을 코드에 고정하기
search()가 같은 문서의 여러 쪽 가운데 최고 점수 한 쪽만 남긴 고유 문서 순위를 반환합니다. precision_at()은 이 결과의 상위 k개 중 정답 ID와 일치한 개수를 세고, 실제 반환 개수가 아니라 약속한 k로 나눕니다. 중복 제거는 precision_at()의 책임이 아닙니다. 호출의 반환값은 질문 한 건의 점수이고, returned_count는 결과 부족을 설명하기 위해 따로 기록합니다. 두 값은 서로 대신할 수 없습니다.
단일 정답 라벨에서 Precision@5의 최댓값은 0.2이지만, 관련 문서를 여러 개 라벨링한 자료에서는 최댓값이 달라집니다. 그러므로 다른 평가셋의 0.4와 이 자료의 0.2를 숫자만으로 비교하지 않습니다. 첫 결과의 적중 여부가 중요하면 Precision@1을 함께 읽습니다.
5실행 예제
설정 선택용 dev 15개의 실제 검색 결과에서 Precision@1, @3, @5, @10을 계산합니다. 분모만 달라지는 것이 아니라 평가하는 자리 수도 함께 달라집니다. 질문과 검색 순위는 모든 계산에서 같습니다.

6실험 결과 해석
기준 실행의 Precision@5는 0.200입니다. 숫자만 보면 낮아 보이지만 현재 라벨 구조에서는 최댓값입니다. 이 결과를 20%만 맞았다고 해석하면 잘못입니다. 질문마다 정답으로 표시된 문서가 하나뿐이라 상위 5개 중 최대 한 자리만 정답으로 셀 수 있습니다.
Precision@1은 첫 문서가 정답인지 더 직접적으로 보여 줍니다. nDCG@5는 정답이 2위와 5위에 있을 때의 차이를 표현합니다. 다음 절에서 순위 위치를 반영하는 지표가 필요한 이유입니다.

1학습 목표
DCG@5와 IDCG@5를 수식으로 계산할 수 있습니다.
nDCG@5가 정답 순위를 반영하는 방식을 설명할 수 있습니다.
작은 순위 예제를 손으로 계산한 값과 함수 결과를 대조할 수 있습니다.
2이 내용을 배우는 이유
Precision@5는 정답이 1위여도 5위여도 같은 점수를 줍니다. 실제 검색에서는 위쪽 문서를 먼저 읽고 생성 모델에도 위쪽 문서가 먼저 전달됩니다. nDCG@5는 관련 문서가 아래로 내려갈수록 기여도를 줄여 순서의 품질을 표현합니다.
3앞에서 배운 내용
03절에서 상위 다섯 자리 안의 정답 수를 계산했습니다. 이번 절은 같은 고유 문서 순위에 위치 할인을 적용합니다. 정답 문서 ID가 같으면 관련도 1, 다르면 0을 사용합니다.
4핵심 개념
비유 — 앞자리의 가치를 더 크게 셉니다
같은 안내문도 첫 번째 자리에 있으면 곧바로 발견하고 다섯 번째 자리에 있으면 찾는 시간이 늘어납니다. 순위 할인은 아래쪽 결과의 기여도를 점차 줄입니다.누적 할인 이득 (DCG)각 순위의 관련도에 위치별 할인값을 적용해 더한 값입니다.이상적 DCG (IDCG)같은 정답 문서를 가장 좋은 순서에 놓았을 때의 DCG입니다.정규화 (normalization)DCG를 IDCG로 나누어 0에서 1 사이로 맞추는 과정입니다.이진 관련도 (binary relevance)정답은 1, 나머지는 0으로 표시하는 방식입니다.등급 관련도 (graded relevance)관련 정도를 0, 1, 2처럼 여러 단계로 표시하는 방식입니다.
DCG@5 = Σ (2^rel_i - 1) / log2(i + 1)이고 nDCG@5 = DCG@5 / IDCG@5입니다. 순위 i는 1부터 시작합니다. 이진 관련도에서는 분자의 2^rel_i - 1이 관련도와 같지만, 전체 식을 유지하면 등급 라벨로 확장할 수 있습니다.관련도에 순위 할인을 적용한 뒤 이상적인 순위와 비교해 0에서 1 사이로 정규화합니다.
IDCG는 검색 결과에서 발견된 정답 수가 아니라 전체 정답 문서 수로 계산합니다. 정답을 놓친 검색기가 작은 IDCG를 사용해 높은 점수를 받지 않도록 하기 위해서입니다. 정답 문서가 없으면 nDCG를 계산하지 않고 해당 질문을 검색 평균에서 제외합니다.
수식의 세 단계를 코드와 연결하기
코드는 먼저 검색 순위를 [0, 1, ...] 같은 관련도 배열로 바꿉니다. 다음으로 각 위치의 이득에 log2(i+1) 할인을 적용해 DCG를 만들고, 전체 정답을 가장 앞에 놓은 IDCG로 나눠 nDCG를 반환합니다. assert는 손계산과 함수가 같음을 확인할 뿐 검색 품질을 높이지 않습니다.
이진 라벨에서는 정답 여부만 반영하고, 등급 라벨에서는 매우 관련·부분 관련 같은 차이도 이득에 들어갑니다. 두 정책은 같은 nDCG 이름을 써도 값의 의미가 다릅니다. 정답이 하나인 이 실습에서는 1위와 5위의 차이를 읽는 데 집중합니다.
5실행 예제
관련도 배열 [0, 1, 0, 1, 0]을 함수와 손계산으로 각각 구하고 두 값이 같은지 assert로 확인합니다. 이어서 설정 선택용 dev 15개 질문의 nDCG@5를 계산합니다.

6실험 결과 해석

비유 — 평균 온도와 지역별 온도
전국 평균 온도만으로 어느 지역에 한파가 왔는지 알 수 없습니다. 검색 평균도 조건별 값과 개별 결과를 함께 확인해야 실패 위치를 찾을 수 있습니다.슬라이스 평가 (slice evaluation)질문을 난이도·유형·문서 형식 같은 조건으로 나누어 같은 지표를 계산하는 방법입니다.후보 누락 (candidate miss)정답 문서가 상위 50개 후보에 없는 상태입니다.순위 누락 (ranking miss)정답 문서는 후보에 있지만 상위 5개에는 없는 상태입니다.상위 5개 적중 (top-5 hit)정답 문서가 상위 5개 안에 있는 상태입니다.오류 분류표 (error taxonomy)실패를 수정할 단계와 연결한 이름 목록입니다.
먼저 후보 포함 여부를 확인하고, 포함되었다면 상위 5개 배치를 확인해 오류 이름을 정합니다.
오류 이름은 한 사례의 모든 원인을 설명하지 않습니다. 정답 문서가 상위 5개에 있어도 필요한 표 셀이 잘렸거나 검색 본문이 비어 있을 수 있습니다. 자동 분류 뒤에는 질문, 정답 문서, 검색된 쪽, 추출 본문을 읽어 실제 원인을 확인합니다.
질문 수가 적은 슬라이스는 한 문항이 평균에 큰 영향을 줍니다. 10문항 집단에서 한 문항의 점수 변화는 평균을 0.1만큼 바꿀 수 있습니다. 수치 차이가 관찰되었다고 해서 문서 난이도가 원인이라고 바로 결론짓지 않습니다.
묶기와 원인 판정을 구분하기
groupby에 해당하는 집계 코드는 같은 type이나 tier 값을 가진 질문 점수를 모아 평균과 문항 수를 반환합니다. 평균 차이는 어디에서 더 자주 문제가 보였는지를 알려 주지만, 그 라벨이 원인임을 증명하지는 않습니다. 각 집단의 문항 수와 질문 원문을 함께 읽습니다.
candidate_miss·ranking_miss·top5_hit는 검색 순위에서 관찰한 위치 이름입니다. 표 추출 실패와 질문 표현 불일치가 동시에 영향을 줄 수 있으므로 하나의 이름이 모든 원인을 설명하지 않습니다. 자동 분류 뒤에 검색된 쪽 본문을 읽는 단계가 필요합니다.
5실행 예제
설정 선택용 dev 15개의 검색 지표를 질문 유형별로 묶고, 정답 없는 질문의 제외 건수를 출력합니다. 이어서 각 질문을 candidate_miss, ranking_miss, top5_hit 중 하나로 분류합니다.
확인할 점 — dev 15개는 모두 정답 문서가 있어 제외 건수가 0이며, 모두 top5_hit로 분류됩니다. 후보 누락은 나타나지 않았지만 nDCG 차이로 순위 문제를 더 자세히 읽어야 합니다.
6실험 결과 해석
dev 15개 기준 실행에서 쉬움·보통·어려움 모두 Recall@50은 1.000이고 Precision@5는 0.200입니다. 검색 가능한 문서가 17개이고 단일 정답 라벨이므로 두 지표가 천장에 도달했습니다. nDCG@5는 쉬움과 보통이 각각 약 0.926, 어려움이 약 0.826으로 순위 차이를 보여 줍니다.
각 난이도에 dev 질문이 5개뿐이고 문서 형식도 다르므로, 이 결과만으로 난이도가 원인이라고 단정할 수 없습니다. 어휘 겹침 검색은 질문과 문서에 같은 표현이 있는 경우 유리합니다. 개별 낮은 순위 사례에서 고유명사, 표, 시점, 여러 문서 조건을 확인한 뒤 Ch 12에서 검증할 가설로 정리합니다.

작은 집단의 차이는 가설이며 원문 확인이 필요합니다.
