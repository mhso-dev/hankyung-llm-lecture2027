1학습 목표

  • FilesystemBackend로 조사 중간 결과를 실제 디스크에 저장하고 다시 읽습니다.
  • 실행 출력에서 파일시스템과 중간 결과의 구성과 결과를 구분할 수 있습니다.
  • 이 실험이 확인한 범위를 설명할 수 있습니다.

2이 내용을 배우는 이유

조사 원문을 부모 메시지에 계속 붙이면 다음 호출에도 같은 긴 내용이 들어갑니다. 파일 경로를 인계 지점으로 쓰면 원자료별 메모를 분리하고 필요한 부분만 다시 읽을 수 있습니다. 이 절은 가상 경로와 실제 저장 루트를 구분합니다.

3앞에서 배운 내용

Ch 2에서 Path와 UTF-8 파일을 다뤘고 Ch 23에서 상태 저장 범위를 구분했습니다. FilesystemBackend의 파일은 체크포인터 메시지와 다른 저장 표면입니다. root_dir 아래에 저장하되 모델에는 /research/source-a.md라는 가상 경로를 보여 줍니다.

노트북은 앞 절 변수에 의존하지 않으며 Python 3.12, deepagents==0.7.0, langchain==1.4.0을 설치하고 상위 폴더의 .env를 찾습니다.

4핵심 개념

정의와 구체적인 상황

FilesystemBackend는 에이전트가 보는 가상 경로를 지정한 root_dir 아래의 실제 파일에 연결합니다. 0.7의 기본 virtual_mode=True는 ..로 루트 밖을 가리키는 경로를 거부합니다. 조사 에이전트는 원자료 전체를 대화에 계속 두는 대신 /research/source-a.md처럼 중간 결과를 저장하고 필요한 부분만 읽을 수 있습니다.

코드 읽기와 비교 경계

FilesystemBackend(root_dir=...)는 에이전트가 사용하는 /research/source-a.md 같은 가상 경로를 실습 폴더의 실제 경로로 대응시킵니다. 가상 경로의 /는 컴퓨터의 파일 시스템 루트를 뜻하지 않습니다. write_file은 문자열을 저장하고 성공 여부를 구조화된 결과로 반환하며, read_file은 필요할 때 내용을 다시 가져옵니다. 파일을 썼다는 사실만으로 다음 모델 호출이 자동으로 그 내용을 읽는 것은 아니므로, 읽기 호출과 전달 시점을 명시해야 합니다.

중간 결과를 파일에 두는 방법은 대화 상태에 모든 문자열을 유지하는 방법과 장단점이 다릅니다. 파일은 큰 자료를 이름과 경로로 인계하고 실행 뒤에도 검사하기 좋지만, 오래된 파일을 잘못 읽거나 여러 실행이 같은 경로를 덮어쓸 수 있습니다. 실행 ID별 폴더, 출처 ID, 생성 시각, 완료 상태를 함께 기록하면 어느 작업의 자료인지 구분할 수 있습니다. 비밀이나 개인정보가 있는 자료는 저장 경로의 접근 권한과 보존 기간도 정해야 합니다.

도식 읽기

{{svg:04-흐름}}

색이 쓰인 곳에서 파란색은 학생 코드와 실행 흐름, 보라색은 모델의 판단, 초록색은 도구와 데이터, 노란색은 측정값, 빨간색은 실패 또는 권한 경계를 뜻합니다. 조사 원문→write_file→/research/*.md→read_file로 다시 읽기 순서입니다. 세 번째 상자가 중간 결과의 인계 지점입니다. 화살표는 파일 내용이 자동으로 모델 입력에 들어간다는 뜻이 아니라, 필요할 때 read_file로 선택해 읽는 순서입니다.

5실행 예제

교재 상대 위치의 workspace를 백엔드 루트로 정하고 /research/source-a.md에 두 줄을 씁니다. ReadResult의 file_data에서 UTF-8 내용을 읽고 ls의 entries에서 가상 경로를 찾습니다. 출력에는 개인 절대 경로를 표시하지 않습니다.

6실험 결과 해석

WriteResult가 반환됐고 읽은 내용은 ‘자료 A’ 제목과 하네스 설명 두 줄이었습니다. 목록에는 /research/source-a.md가 포함됐습니다. 이 결과는 같은 노트북 안의 실제 파일 쓰기와 읽기를 증명하지만 여러 스레드의 영속성은 측정하지 않습니다.

7주의할 점과 실무 메모

  • deepagents의 최신 문서는 이후 버전의 기능을 포함할 수 있으므로 이 장은 설치된 0.7.0 소스와 릴리스 노트를 함께 확인합니다.
  • 파일 도구의 루트와 권한을 지정하지 않은 채 사용자 입력을 경로로 사용하지 않습니다. 특히 0.7의 delete와 기존 파일을 교체하는 write_file을 구분합니다.
  • API 호출 절의 예산은 입력 10만 토큰·출력 1만 토큰 이하를 가정하면 2026-09-11 공개 단가 기준 약 0.12달러로, 절당 1달러 미만입니다. 실제 비용은 전체 서브에이전트 사용량과 최신 가격표로 다시 계산합니다.

재현 기록에는 실행 날짜, 패키지 잠금, 모델 이름, 입력, 생성 파일 경로를 함께 적습니다. 모델이 같은 도구를 선택하지 않을 수 있으므로 저장된 출력은 한 번의 관찰입니다. 배포 전에는 정상 입력뿐 아니라 도구가 선택되지 않은 경우, 권한이 거부된 경우, 결과 파일이 빠진 경우도 반복해서 확인합니다.

8정리와 다음 절

  • FilesystemBackend로 조사 중간 결과를 실제 디스크에 저장하고 다시 읽습니다.
  • WriteResult가 반환됐고 읽은 내용은 ‘자료 A’ 제목과 하네스 설명 두 줄이었습니다.
  • 버전과 측정 범위를 실행 기록에 함께 남깁니다.

다음 학습과 이어지는 지점 — 다음 절에서는 파일시스템이 큰 도구 결과를 자동으로 옮기는 경우를 실행해 수동 중간 저장과 자동 오프로딩을 구분합니다.

9복습 문제

문제 1

root_dir와 /research/source-a.md는 각각 무엇인가요?

해설 root_dir는 호스트의 저장 범위이고 /research/source-a.md는 에이전트가 보는 가상 경로입니다.

문제 2

ls 결과만으로 파일 본문을 확인할 수 있나요?

해설 아닙니다. entries는 경로와 메타데이터를 보여 주며 본문은 read 결과에서 확인합니다.

문제 3

경로를 저장하면 출처 정확성도 보장되나요?

해설 보장되지 않습니다. URL과 원문 식별자를 내용에 함께 기록하고 대조해야 합니다.
