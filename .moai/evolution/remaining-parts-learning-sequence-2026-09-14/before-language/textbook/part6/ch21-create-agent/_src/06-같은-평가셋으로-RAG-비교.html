1학습 목표

  • 같은 문서·질문으로 고정 RAG와 Agentic RAG를 실행할 수 있습니다.
  • 답변, 검색 문서 ID, 토큰, 지연을 질문별로 비교할 수 있습니다.
  • 세 문항의 LLM judge 판정을 일반 성능 결론으로 확대하지 않을 수 있습니다.

2이 내용을 배우는 이유

고정 RAG와 Agentic RAG를 같은 질문으로 비교하면 정확도·지연·실패 양상이 어떻게 달라지는가?

Agentic RAG의 코드가 더 복잡하다는 사실만으로 품질 향상을 말할 수 없습니다. Ch14의 같은 문서와 질문을 두 경로에 넣고 답·검색 문서·토큰·지연을 함께 비교해야 합니다.

3앞에서 배운 내용

앞 절의 검색 도구를 사용합니다. 필요한 자료와 객체는 노트북에서 다시 선언하므로 앞 노트북의 메모리 상태는 필요하지 않습니다.

4핵심 개념

정의와 구체 예

고정 RAG는 질문 임베딩으로 상위 두 문서를 검색한 뒤 모델을 한 번 호출합니다. Agentic RAG는 같은 색인을 search_documents 도구로 제공하고 모델이 검색어를 작성합니다. 평가 표본은 Ch14 documents.json 12건과 queries.json의 C01·C05·C07입니다. Grade 스키마의 judge가 사람이 지정한 gold_doc_id 원문과 답을 함께 읽어 supported를 판정합니다.

코드를 읽는 순서

공정한 비교에서는 두 경로가 같은 문서, 질문, 정답 기준, 검색 함수를 사용해야 합니다. cases는 Ch14 평가 질문 중 세 건을 고정하고, document_vectors는 두 경로가 공유하는 임베딩 색인입니다. retrieve(query, top_k=2)는 질문 벡터와 모든 문서 벡터의 코사인 유사도를 계산해 상위 두 문서와 점수를 반환합니다. 여기서 반환되는 점수는 답의 정확도가 아니라 질문과 문서 벡터의 가까움을 나타냅니다.

고정 경로는 애플리케이션이 retrieve를 호출한 뒤 원문을 모델 프롬프트에 넣습니다. 에이전트 경로는 같은 retrieve를 감싼 search_documents를 모델이 선택합니다. usage_total은 한 실행의 모든 AIMessage.usage_metadata를 합쳐 모델 호출 수와 토큰을 세며, search_events는 도구 호출 횟수와 검색어를 별도로 남깁니다. 서로 다른 측정값을 같은 비용 또는 품질 지표로 합치지 않습니다.

5실행 예제

준비 셀에서 Python 3.12와 고정 패키지를 확인한 뒤, 데이터·함수·객체 생성·invoke·관찰을 짧은 셀로 나누어 실행합니다. 각 코드 셀의 첫 주석은 그 셀에서 확인할 행동을 설명합니다.

Ch6에서 배운 model.with_structured_output(Grade, method="json_schema", strict=True)는 Grade 형식을 적용한 새 호출 객체를 준비하며, 이 줄만으로 모델을 호출하지 않습니다. 뒤의 grader.invoke(...)가 원문과 답을 실제로 보내고 Grade 객체를 반환합니다. supported: bool은 참·거짓 형식을 검증하지만 판정 자체가 옳다는 보장은 아니므로 explanation과 원문을 함께 읽습니다. Ch21 02의 create_agent(..., response_format=...)이 에이전트 최종 상태의 structured_response를 만드는 방식과 달리, 여기서는 모델 호출의 직접 반환값이 Grade입니다.

{{notebook:06-같은-평가셋으로-RAG-비교}}

확인할 점 — 이번 재실행에서 두 경로는 세 질문 모두 supported=True였습니다. Agent는 각 질문에서 모델 2회·도구 1회를 사용했고 토큰은 526·492·541, 지연은 2.007·1.538·2.094초였습니다. 고정 RAG는 모델 1회이며 토큰은 132·120·122였습니다. 고정 RAG의 C01 답은 gold 원문 밖의 전자책 7일도 포함했지만, 이번 judge는 원문과 모순되지 않는다고 True로 판정했습니다. 이 결과는 judge의 재실행 변동도 함께 보여 줍니다.

다른 상황과 적용 경계

질문이 항상 문서 검색을 요구하면 고정 RAG가 적은 분기와 일정한 호출 수를 제공합니다. 계산기·데이터베이스·검색 등 여러 도구 중 하나를 골라야 하거나 검색 결과를 보고 질의를 다시 작성해야 하면 에이전트 경로의 선택 능력이 의미가 있습니다. 같은 정답률이 나와도 실행 과정과 지연은 다를 수 있습니다.

세 질문 결과는 이 데이터와 이번 실행 조건의 관찰입니다. 전체 Agentic RAG가 항상 더 정확하거나 느리다고 일반화할 수 없습니다. 정확도, 검색 성공, 모델 호출 수, 입력 토큰, 지연을 각각 읽고, Ch29 평가에서는 저장한 원문 기록을 다시 사용합니다.

6실험 결과 해석

이번 재실행에서 두 경로는 세 질문 모두 supported=True였습니다. Agent는 각 질문에서 모델 2회·도구 1회를 사용했고 토큰은 526·492·541, 지연은 2.007·1.538·2.094초였습니다. 고정 RAG는 모델 1회이며 토큰은 132·120·122였습니다. C01의 고정 답은 전자책 7일을 포함했지만, 이번 judge는 gold 원문과 모순되지 않는다고 True로 판정했습니다.

세 문항 모두 첫 검색에 정답 문서가 포함돼 재검색 이점을 시험하지 못했습니다. 같은 답도 judge 재실행에서 다르게 판정될 수 있으므로 사람 검토와 더 큰 평가셋이 필요합니다.

7주의할 점과 실무 메모

  • 세 문항 모두 첫 검색에 정답 문서가 포함돼 재검색 이점을 시험하지 못했습니다. judge도 모델이므로 사람 검토와 더 큰 평가셋이 필요합니다.
  • 실제 모델 호출 비용은 절당 1달러 미만으로 예상하며, API 키 값은 출력하지 않습니다.
  • 재실행하면 모델 문장과 지연이 달라질 수 있으므로 저장된 원문 출력과 조건을 함께 읽습니다.

8정리와 다음 절

  • 고정 RAG는 질문 임베딩으로 상위 두 문서를 검색한 뒤 모델을 한 번 호출합니다. Agentic RAG는 같은 색인을 search_documents 도구로 제공하고 모델이 검색어를 작성합니다. 평가 표본은 Ch14 documents.json 12건과 queries.json의 C01·C05·C07입니다. Grade 스키마의 judge가 사람이 지정한 gold_doc_id 원문과 답을 함께 읽어 supported를 판정합니다.
  • 이번 재실행에서 두 경로는 세 질문 모두 supported=True였습니다. Agent는 질문마다 모델 2회·도구 1회를 사용해 고정 RAG보다 호출과 토큰이 늘었습니다. C01 판정은 재실행 때 달라질 수 있어 judge 결과만으로 우열을 말할 수 없습니다.

9복습 문제

1. 두 경로에서 같게 둔 것은 무엇인가요?

해설 — Ch14 문서·질문, 임베딩 색인, 생성 모델, 판정 기준입니다.

2. Agent 경로의 질문당 모델 호출 수는 몇 회였나요?

해설 — 도구 선택과 최종 답으로 2회였습니다.

3. 이번 결과에서 Agent가 항상 낫다고 말할 수 있나요?

해설 — 아닙니다. 이번 세 문항에서는 두 경로가 모두 3/3이었고, 재검색을 시험하지 못했으며 judge 판정도 재실행에 따라 달라질 수 있습니다.
