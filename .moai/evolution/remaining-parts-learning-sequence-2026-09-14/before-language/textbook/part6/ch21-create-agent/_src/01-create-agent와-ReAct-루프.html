1학습 목표

  • create_agent의 model·tools·system_prompt가 맡는 역할을 설명할 수 있습니다.
  • 실행 결과의 AIMessage와 ToolMessage를 순서대로 읽을 수 있습니다.
  • 그래프 구조와 실제 메시지 경로가 보여 주는 범위를 구분할 수 있습니다.

2이 내용을 배우는 이유

create_agent의 세 인자가 Ch20의 모델·도구·지시를 어떻게 묶고, 반환 그래프가 어떤 루프를 실행하는가?

Ch20에서는 model 노드, tools_condition, ToolNode, tools→model 엣지를 직접 연결했습니다. create_agent를 사용하면 호출 한 줄로 같은 반복 구조를 얻지만, 문제가 생겼을 때 어느 단계에서 멈췄는지 읽으려면 내부 그래프를 알아야 합니다.

3앞에서 배운 내용

Ch20에서 직접 연결한 StateGraph와 ToolNode를 사용합니다. 필요한 자료와 객체는 노트북에서 다시 선언하므로 앞 노트북의 메모리 상태는 필요하지 않습니다.

4핵심 개념

정의와 구체 예

ReAct는 모델이 상황을 읽고 다음 행동을 정한 뒤 도구 결과를 다시 관찰하는 반복 방식입니다. create_agent의 model은 판단과 답변을 생성하고, tools는 모델이 선택할 수 있는 동작을 제공하며, system_prompt는 근거 사용과 종료 기준을 지시합니다. 반환값은 CompiledStateGraph이므로 invoke, stream, get_graph 같은 LangGraph 인터페이스를 그대로 사용합니다.

코드를 읽는 순서

@tool은 평범한 Python 함수를 모델이 선택할 수 있는 도구 명세로 바꿉니다. 함수 이름은 도구 이름이 되고, 매개변수의 타입 힌트는 입력 형식이 되며, 독스트링은 모델이 언제 이 도구를 골라야 하는지 판단하는 설명이 됩니다. lookup_policy(topic: str) -> str에서 모델은 topic 문자열을 만들고, 실행기는 함수를 호출하며, 반환 문자열은 ToolMessage로 대화 상태에 추가됩니다.

create_agent(model, tools, system_prompt=...)는 이 명세와 모델을 엮어 CompiledStateGraph를 반환합니다. 이 객체를 만드는 순간에는 질문을 처리하지 않습니다. invoke({"messages": ...})를 호출해야 루프가 시작되고, 모델이 도구 호출을 만들지 않을 때 끝납니다. 따라서 print(type(agent).__name__)은 그래프의 종류를, result["messages"]는 한 요청이 실제로 지나간 기록을 보여 줍니다.

5실행 예제

준비 셀에서 Python 3.12와 고정 패키지를 확인한 뒤, 데이터·함수·객체 생성·invoke·관찰을 짧은 셀로 나누어 실행합니다. 각 코드 셀의 첫 주석은 그 셀에서 확인할 행동을 설명합니다.

{{notebook:01-create-agent와-ReAct-루프}}

확인할 점 — 실제 실행은 HumanMessage, 도구 호출이 든 AIMessage, 규정 원문 ToolMessage, 최종 AIMessage의 4개 메시지를 남겼습니다. lookup_policy의 topic은 대출이었고 답에는 14일이 포함됐습니다. get_graph().draw_mermaid_png()는 PNG 서명과 8,388바이트를 반환했습니다. 두 모델 호출의 합은 입력 379토큰, 출력 47토큰, 추정 0.000496달러였습니다.

다른 상황과 적용 경계

같은 구조를 주문 조회에 적용하면 lookup_policy 대신 lookup_order(order_id)를 등록할 수 있습니다. 달라지는 것은 도구의 입력과 반환 자료이고, 모델→도구→관찰→모델이라는 루프는 같습니다. 반대로 항상 한 번만 실행할 계산이라면 모델이 다음 행동을 고를 이유가 없으므로 일반 함수나 고정 그래프가 더 분명합니다.

그래프 그림은 가능한 경로의 지도이고 메시지 목록은 이번 요청의 이동 기록입니다. 그림에 ToolNode가 있다고 해서 모든 요청이 도구를 사용한 것은 아닙니다. 이번 출력에서는 AIMessage.tool_calls와 그 호출 ID에 대응하는 ToolMessage가 모두 있어 실제 도구 사용을 확인할 수 있습니다.

6실험 결과 해석

실제 실행은 HumanMessage, 도구 호출이 든 AIMessage, 규정 원문 ToolMessage, 최종 AIMessage의 4개 메시지를 남겼습니다. lookup_policy의 topic은 대출이었고 답에는 14일이 포함됐습니다. get_graph().draw_mermaid_png()는 PNG 서명과 8,388바이트를 반환했습니다. 두 모델 호출의 합은 입력 379토큰, 출력 47토큰, 추정 0.000496달러였습니다.

그래프 PNG는 구조를 보여 주지만 특정 질문에서 실제로 지난 엣지는 보여 주지 않습니다. 실제 경로는 메시지와 stream 기록으로 함께 확인해야 합니다.

7주의할 점과 실무 메모

  • 그래프 PNG는 구조를 보여 주지만 특정 질문에서 실제로 지난 엣지는 보여 주지 않습니다. 실제 경로는 메시지와 stream 기록으로 함께 확인해야 합니다.
  • 실제 모델 호출 비용은 절당 1달러 미만으로 예상하며, API 키 값은 출력하지 않습니다.
  • 재실행하면 모델 문장과 지연이 달라질 수 있으므로 저장된 원문 출력과 조건을 함께 읽습니다.
