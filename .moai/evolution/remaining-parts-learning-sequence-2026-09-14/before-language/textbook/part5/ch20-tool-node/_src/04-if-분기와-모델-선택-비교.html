1학습 목표

  • 고정 if 분기와 모델 도구 선택 분기의 책임 차이를 설명할 수 있습니다.
  • 같은 질문·자료·생성 모델로 두 경로의 전체 trace를 수집할 수 있습니다.
  • 입력·출력 토큰, 추정 비용, 지연, 출력 변동을 표로 비교하고 관찰 범위를 제한할 수 있습니다.

2이 내용을 배우는 이유

모델이 흐름을 정한다고 해서 모든 분기가 모델 판단에 적합한 것은 아닙니다. 규칙이 분명한 질문은 if 문이 더 짧고 예측 가능한 경로를 만들 수 있습니다. 반대로 표현이 다양하고 어떤 조회가 필요한지 규칙으로 모두 적기 어렵다면 모델 선택이 유용할 수 있습니다. 둘을 다른 데이터나 다른 모델로 비교하면 원인을 알 수 없으므로 같은 세 질문, 같은 로컬 규정, 같은 gpt-5.4-mini를 사용합니다.

3앞에서 배운 내용

Ch13과 Ch14의 조건부 엣지는 점수나 키워드처럼 코드가 계산한 값으로 경로를 골랐습니다. Ch18에서는 OpenAI SDK를 직접 호출하고 코드로 단계·분기·병렬 실행과 종료를 연결했습니다. Ch19에서는 모델 응답에 포함된 tool_calls를 해석했습니다. 이번 절은 Ch20에서 처음 조립한 ToolNode 루프와 고정 분기를 하나의 그래프와 측정표에 놓아, 에이전트 도입의 비용과 유연성을 함께 읽습니다.

4핵심 개념

구체적인 상황

두 상담 절차를 같은 시험 문제와 같은 그래프로 평가한다고 생각해 봅니다.

정의와 메시지 흐름

공통 choose 노드는 strategy가 fixed이면 파이썬 규칙으로 AIMessage 도구 호출을 만들고, agent이면 도구 설명을 받은 모델이 AIMessage 도구 호출을 만듭니다. 그 뒤에는 두 경로가 같은 mark_tools, ToolNode, answer 노드를 지나며, answer 노드는 같은 모델로 같은 메시지 형식의 결과를 작성합니다. trace는 실제로 실행한 fixed_choose 또는 model_choose, tools, model_answer 단계를 드러냅니다.

도식 읽기

{{svg:04-흐름}}

같은 질문으로 fixed와 agent를 각각 실행합니다. 선택 방식만 달리하고 공통 ToolNode와 답변 노드를 거친 뒤 토큰·전체 지연·반복 변동을 비교합니다.

코드를 읽기 전에

두 경로는 같은 질문·도구·최종 답 형식을 사용하고 분기 주체만 바꿉니다. fixed 경로는 코드의 조건문이 규정 조회 도구 사용 여부를 정하고, agent 경로는 도구가 바인딩된 모델의 tool_calls를 읽어 실행 여부를 정합니다. run_branch()는 한 실행의 경로, 토큰, 벽시계 시간, 답을 사전으로 반환합니다.

각 질문을 두 경로에서 두 번 실행해 문자열 변동과 평균을 계산합니다. 표의 차이는 이 질문 집합과 실행 시점에서 관찰한 값입니다. 모델 경로의 호출 수가 늘었다는 사실만으로 답의 품질이 높아졌다고 말할 수 없습니다.

다른 상황과 개념 경계

‘환불 규정’처럼 키워드와 처리 경로가 안정적인 요청은 고정 분기가 예측 가능할 수 있습니다. 같은 문장에 배송·회원 등 여러 의도가 섞이면 모델 선택이 더 유연할 수 있지만 잘못된 도구 선택도 측정해야 합니다. 비교할 때는 정답률, 불필요한 호출, 미호출, 지연, 출력 변동을 같은 평가셋에서 함께 기록합니다.

5실행 예제

하나의 StateGraph에 choose, mark_tools, ToolNode, answer를 등록합니다. strategy만 fixed 또는 agent로 바꾸고 세 질문을 각 두 번 실행합니다. 두 경로 모두 ToolMessage가 실제로 생성됐는지 검사하며, answer 노드는 같은 gpt-5.4-mini와 같은 메시지 기록을 사용합니다. 실행 전후 perf_counter로 그래프 전체 시간을 측정합니다.

{{notebook:04-if-분기와-모델-선택-비교}}

확인할 점 — 세 질문을 각 경로에서 두 번 실행합니다. 두 경로는 같은 컴파일된 그래프와 ToolNode·최종 답변 노드를 공유합니다. fixed는 fixed_choose, tools, model_answer를 실행하고, agent는 model_choose, tools, model_answer를 실행합니다. ToolMessage가 실제로 있을 때만 실행이 성공하도록 검사합니다. 표에는 실제 input_tokens, output_tokens, estimated_cost_usd, latency_sec와 답변 문자열을 기록합니다. output_variants는 같은 조건에서 두 번 실행했을 때 서로 다른 답변 문자열의 개수입니다.

6실험 결과 해석

12개 실제 실행의 총 추정 비용은 0.003314달러였습니다. fixed와 agent의 평균 입력 토큰은 각각 88과 264.3, 평균 출력 토큰은 22.5와 41.5, 그래프 전체 평균 지연은 1.077초와 1.462초였습니다. 실제 trace는 fixed_choose → tools → model_answer와 model_choose → tools → model_answer였습니다. fixed와 agent의 출력 종류는 세 질문에서 모두 2·1·2개였습니다. 두 번의 반복에서 관찰한 값이므로 일반적인 변동성 차이로 해석하지 않습니다.

세 질문을 두 번씩 실행한 소규모 비교입니다. 이번 실행에서 agent의 평균 토큰과 지연이 더 컸지만, 다른 도구 수·프롬프트·네트워크 상태에서도 같은 비율이 유지된다고 볼 수 없습니다.

7주의할 점과 실무 메모

  • 샘플 2회와 질문 3개는 학습용 소규모 비교입니다. 정확도나 안정성의 일반 결론에는 더 큰 고정 평가셋이 필요합니다.
  • fixed 경로의 키워드 규칙은 세 질문에 맞춰 작성한 기준선입니다. 새로운 표현이 들어오면 규칙을 확장하거나 실패 사례로 기록해야 합니다.
  • agent 경로는 도구 스키마가 입력 토큰에 포함되고 선택을 위한 모델 호출이 추가될 수 있습니다.
  • 예상 API 비용은 절 전체 1달러 미만이며, 노트북은 실제 사용량으로 다시 계산해 이를 검사합니다.

8정리와 다음 절

  • 두 경로는 같은 컴파일 그래프, ToolNode, answer 모델을 공유하고 choose 방식만 다릅니다.
  • 모델 선택 경로에는 도구 스키마와 선택 호출에 따른 토큰·지연이 추가됐습니다.
  • 최종 답과 함께 실제 trace와 사용량을 기록해야 경로 비용을 비교할 수 있습니다.

다음 학습과 이어지는 지점 — Ch21에서는 같은 루프를 create_agent로 만들고 직접 조립한 그래프와 노드·메시지·종료 조건을 대응합니다.

9복습 문제

1. 두 경로 비교에서 반드시 같게 유지한 조건은 무엇인가요?

해설 — 질문, 로컬 규정 자료, 최종 생성 모델, 반복 횟수와 비용 단가입니다.

2. agent 경로의 입력 토큰이 늘 수 있는 이유는 무엇인가요?

해설 — 도구 이름·설명·인자 스키마가 모델 입력에 포함되고 선택 호출이 추가되기 때문입니다.

3. 출력 문자열 종류가 한 개면 모델은 항상 같은 답을 하나요?

해설 — 아닙니다. 이번 두 번의 실행에서 변동을 관찰하지 못했다는 뜻만 가집니다.

4. 고정 분기가 알맞은 사례는 무엇인가요?

해설 — 분기 규칙이 명확하고 실행 경로를 사후에 확인해야 하며 비용과 예측 가능성이 중요한 사례입니다.

5. 최종 답만 비교하면 놓치는 것은 무엇인가요?

해설 — 도구 선택, 호출 횟수, 오류, 토큰, 지연처럼 답을 만드는 경로의 차이를 놓칩니다.
