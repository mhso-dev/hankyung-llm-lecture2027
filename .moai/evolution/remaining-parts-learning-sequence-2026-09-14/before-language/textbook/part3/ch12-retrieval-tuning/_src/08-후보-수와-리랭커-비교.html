1학습 목표

  • 후보 수가 검색할 수 있는 범위를 정하고 모델이 그 범위 안의 순서를 바꾸는 실험의 입력과 출력을 설명할 수 있습니다.
  • 개발용 15문항으로 후보 수와 두 모델의 결과를 비교할 수 있습니다.
  • 관찰한 수치가 설명하는 범위와 설명하지 못하는 범위를 구분할 수 있습니다.

2이 내용을 배우는 이유

리랭커가 검토할 후보를 늘리면 정답 문서가 포함될 여지가 커집니다. 또한 모델마다 한국어 문장의 순위를 다르게 계산합니다. 이 실습에서는 같은 상위 20개 후보를 두 모델에 입력하고, 저장한 점수로 후보 수별 검색 지표를 비교합니다. 시간은 후보 수별 값이 아니라 모델별 20개 후보 전체 점수화 시간으로 따로 기록합니다. 후보 수에 따른 추론 시간 변화를 확인하려면 각 후보 수를 따로 입력해 실행해야 합니다.

Ch11에서 만든 질문과 정답 문서 ID를 유지한 채 한 조건씩 바꿉니다. 개발용 15문항에서 같은 후보 목록을 사용해 후보 수와 모델 조건을 비교합니다.

3앞에서 배운 내용

Ch10에서 PDF를 문서와 청크로 나누고 메타데이터에 출처를 보존했습니다. Ch11의 evaluation-queries.jsonl은 질문마다 gold_doc_ids를 제공합니다. 이 절에서는 그 정답 ID에 해당하는 공개 PDF 6건을 다시 추출한 advanced-documents.json과 같은 30문항을 사용합니다. 앞 절의 변수나 실행 상태는 필요하지 않습니다.

4핵심 개념

쉬운 예

도서관에서 책을 찾을 때 먼저 검색대가 관련 서가를 좁히고, 그 안에서 제목과 목차를 자세히 읽어 우선순위를 정한다고 생각해 봅니다. 첫 단계가 서가를 빠뜨리면 다음 단계는 그 책을 검토할 수 없습니다. 반대로 후보를 지나치게 많이 가져오면 자세히 읽는 시간이 늘어납니다.

정의

후보 수가 검색할 수 있는 범위를 정하고 모델이 그 범위 안의 순서를 바꾸는 실험입니다. 문항별 상위 20개 후보를 먼저 고정합니다. 두 모델은 이 목록을 각각 한 번 점수화하며 후보 5·10·20 비교는 저장한 점수를 재사용합니다.

도식 읽기

도식은 위에서 아래로 개발 문항 15개, 후보 수 세 조건, 두 모델의 고정 후보 추론, Recall·nDCG·시간 순서로 읽습니다. 초록은 입력·문서·후보, 파랑은 직접 구현한 선택·설정, 보라는 모델 점수·질문 재작성, 노랑은 측정 결과·로그를 뜻합니다. 화살표는 데이터 전달 방향입니다.

후보 수와 모델 효과를 분리해 비교하기

후보 수 5·10·20은 리랭커가 볼 수 있는 문서 범위를 바꾸고, 두 CrossEncoder는 같은 질문·후보 쌍에 서로 다른 점수를 냅니다. 공정한 비교에서는 먼저 각 모델이 공통 상위 20개 후보를 한 번 점수화하고, 저장한 점수에서 앞 5·10·20개 범위만 잘라 지표를 계산합니다.

후보 수를 늘려 지표가 좋아지면 정답이 작은 후보 밖에 있었을 가능성이 있고, 같은 후보에서 모델별 순위가 다르면 점수화 차이를 조사합니다. 모델별 전체 추론 시간은 후보 수별 실행 시간이 아니며 장치·캐시 상태에도 영향을 받습니다. 품질과 시간을 하나의 원인으로 섞어 해석하지 않습니다.

5실행 예제

노트북은 Python 3.12 새 커널에서 실행합니다. 먼저 부모 문서 수, 자식 청크 수, 질문 수를 출력해 입력 범위를 확인합니다. 다음 셀은 가장 작은 문항 하나에서 중간 결과를 보여 줍니다. 마지막 셀은 조건을 바꾸거나 평가 범위를 넓힙니다. 출력의 문서 ID, 점수, 실행 시간 또는 로그 수를 본문 설명과 대조합니다.

확인할 점 — 코드가 실제 검색 또는 모델 추론을 수행하는지, 정답 문서 ID를 결과 뒤에 새로 붙이지 않는지, 비교할 때 질문과 원문이 유지되는지 확인합니다.

6실험 결과 해석

설정 선택 전의 개발 문항 15개에서 bge-reranker-v2-m3와 ko-reranker의 점수로 후보 수 5·10·20개의 지표를 비교했습니다. 두 모델은 동일한 상위 20개 후보를 한 번씩 점수화했고, 후보 수별 계산은 그 점수를 재사용했습니다. bge 모델은 세 후보 수에서 nDCG@5 1.000, ko-reranker는 세 후보 수에서 1.000을 기록했습니다. 전체 점수화 시간은 각각 15.82초와 19.56초였습니다.

한 번의 출력은 이 데이터와 실행 환경에서 관찰한 결과입니다. 다른 도메인, 더 긴 문서, 다른 언어 비율에서는 순서와 시간이 달라질 수 있습니다. 설정을 채택하기 전에는 실제 서비스 질문을 같은 형식으로 추가해 다시 계산해야 합니다.

7주의할 점과 실무 메모

  • 이번 절의 중간 결과를 확인한 뒤 다음 단계로 전달합니다. 검색 후보, 선택 결과, 부모 원문, 재작성 질문, 로그 행은 서로 다른 데이터입니다.
  • 실행 시간은 CPU, GPU, 배치 크기, 입력 길이, 모델 캐시에 따라 달라집니다. 장치와 패키지 버전을 로그에 함께 남깁니다.
  • 두 모델의 가중치가 크므로 후보 점수를 한 번 계산해 재사용합니다. 모델별 저장 공간과 CPU 시간을 실행 전에 확인합니다.
  • 공개 PDF 6건과 30문항은 학습용 기준선입니다. 실제 서비스의 문서 분포와 질문 유형을 대신하지 않습니다.

8정리와 다음 절

  • 두 리랭커는 동일한 고정 후보를 한 번씩 점수화했습니다.
  • 후보 수별 nDCG@5와 모델별 추론 시간을 함께 비교했습니다.
  • 이 결과는 공개 PDF 6건과 개발용 15문항에서 관찰한 기준선입니다.

9복습 문제

1. 이해 — 이번 절에서 고정한 조건은 무엇인가요?

설정 비교에서 바꾸지 않은 입력을 두 가지 적어 보세요.

개발용 15개의 질문과 각 질문의 정답 문서 ID, 공개 PDF에서 추출한 본문을 유지했습니다. 입력을 고정해야 설정 변화와 결과 변화의 관계를 설명할 수 있습니다. 오답 시 다시 볼 곳: 3절 ‘앞에서 배운 내용’

2. 이해 — 후보 수를 늘리면 항상 좋은가요?

후보 수와 품질·비용의 관계를 설명해 보세요.

후보 수를 늘리면 정답 문서가 포함될 가능성이 커질 수 있지만 리랭킹 연산과 지연도 늘어납니다. 실제 평가 지표와 시간을 함께 측정해야 합니다. 오답 시 다시 볼 곳: 7절 ‘주의할 점과 실무 메모’

3. 적용 — 한 문항의 성공을 어떻게 전체 평가로 넓히나요?

작은 성공 예제 다음에 실행할 평가 절차를 적어 보세요.

개발 문항 15개에서 같은 검색 함수를 실행해 설정을 선택합니다. 시험 문항 15개는 선택이 끝난 뒤 12절에서 한 번만 평가합니다. 오답 시 다시 볼 곳: 5절 ‘실행 예제’

4. 분석 — 어느 모델이 항상 더 좋았나요?

후보 수별 nDCG@5와 시간을 함께 해석해 보세요.

항상 우수한 모델을 정할 수 없습니다. 세 후보 수에서 두 모델의 nDCG@5가 모두 1.000이었습니다. 시간도 이 실행 환경에서만 관찰한 값입니다. 오답 시 다시 볼 곳: 6절 ‘실험 결과 해석’
