1학습 목표

  • 이 절을 마치면 모델이 이번 답을 만들 때 실제로 읽는 자료가 무엇인지 설명할 수 있습니다.
  • 이 절을 마치면 컨텍스트 윈도 최대 한도와 수업에서 정한 토큰 예산을 구분할 수 있습니다.
  • 이 절을 마치면 입력 예산에서 출력 예약분과 여유분을 먼저 제외해야 하는 이유를 계산 절차로 설명할 수 있습니다.
  • 이 절을 마치면 로컬 추정값과 API가 반환한 실제 사용량을 구분하여 기록할 수 있습니다.

2이 내용을 배우는 이유

Ch 6에서는 언어 모델에 메시지를 보내고 답을 받는 기본 호출을 배웠고, Ch 7에서는 지시와 예시를 배치하여 프롬프트를 구성했습니다. 이제 자료를 더 많이 넣으면 답이 언제나 좋아지는지 살펴볼 차례입니다. 모델이 한 번에 참고할 수 있는 범위에는 한도가 있습니다. 질문, 지시, 대화 기록, 문서, 도구 결과, 그리고 모델이 작성할 답까지 모두 같은 한도 안에서 자리를 사용합니다.

컨텍스트 엔지니어링은 모델에게 어떤 자료를 얼마나 보낼지 정하는 일입니다. 질문에 필요하다는 이유만으로 자료를 계속 추가할 수는 없습니다. 답에 필요한 자료를 정해진 토큰 수 안에 배치해야 합니다. 이 절에서는 먼저 토큰 예산표를 만듭니다. 다음 절에서는 긴 자료를 저장하고 필요한 부분을 선택하며, 03절에서는 내용을 줄이거나 업무별로 나눕니다. Ch 9에서는 이 장의 선택(Select)을 검색 코드로 확장합니다.

아직 에이전트를 만들지는 않습니다. 이 장의 흐름과 선택 기준은 모두 사람이 코드에 고정합니다. 어떤 자료를 포함할지 모델이 스스로 판단하고 도구를 호출하는 단계는 Ch 20부터 다룹니다.

3앞에서 배운 내용

Ch 6에서는 시스템 역할과 사용자 역할을 구분한 메시지 목록을 모델에 전달했습니다. 이 절에서는 특정 함수 이름을 가정하지 않고, 모델 호출에는 역할이 붙은 메시지가 입력된다는 개념만 사용합니다. Ch 7에서는 지시, 예시, 출력 형식을 프롬프트 안에 배치했습니다. 그 요소들도 모두 입력 공간을 차지합니다.

Ch 6에서 작성한 호출 코드의 메시지 목록을 열어 역할이 어떻게 나뉘었는지 확인합니다. 이어서 Ch 7에서 추가한 지시·질문·예시·출력 형식의 순서를 표시합니다. 이 요소들이 01절의 예산표에서 각각 입력 공간을 사용하는 대상입니다.

4핵심 개념

비유 — 작업 전에 책상 자리를 나눕니다

넓이가 정해진 책상에서 자료를 검토한다고 생각해 봅시다. 책상 전체가 모델의 최대 작업 공간입니다. 업무 지시서, 질문지, 참고 문서, 이전 대화 기록이 책상 위에 놓입니다. 마지막에는 답안지를 펼칠 자리도 남아 있어야 합니다. 자료로 책상을 가득 채우면 답안지를 놓을 공간이 부족해집니다. 따라서 자료를 올리기 전에 답안지 자리와 예상하지 못한 추가 자료를 위한 자리를 먼저 확보합니다.

정의

컨텍스트 (context)
모델이 현재 답을 만들 때 참고하도록 전달된 정보 전체입니다. 시스템 지시, 사용자 질문, 대화 기록, 예시, 문서와 도구 결과가 포함될 수 있습니다. 외부 파일에 존재하지만 호출 메시지에 실리지 않은 내용은 현재 컨텍스트가 아닙니다.
컨텍스트 윈도 (context window)
한 번의 모델 호출에서 처리할 수 있는 입력과 출력의 전체 범위입니다. 모델마다 최대 한도가 다를 수 있으며, 같은 모델도 사용하는 API와 설정에 따라 적용 조건을 확인해야 합니다.
토큰 (token)
모델이 텍스트를 처리하는 단위입니다. 토큰은 글자나 단어와 일치하지 않습니다. 같은 글자 수라도 언어, 숫자, 공백, 기호의 구성에 따라 토큰 수가 달라질 수 있습니다.
토큰 예산 (token budget)
이번 작업에서 사용할 수 있도록 사람이 정한 토큰 상한입니다. 모델이 허용하는 최대 한도와 별개이며, 비용·지연 시간·답의 안정성을 고려하여 더 작은 값으로 정할 수 있습니다.
출력 예약분 (output reservation)
모델이 답을 생성할 공간으로 미리 남겨 두는 토큰 수입니다. 추론 과정에 별도 토큰이 사용되는 모델이나 설정에서는 문서에 명시된 계산 방식에 따라 해당 사용분도 함께 고려합니다.
여유분 (safety margin)
토큰 추정 오차, 추가 지시, 도구 결과처럼 실행 중 늘어날 수 있는 내용을 수용하려고 비워 두는 공간입니다.
사용량 메타데이터 (usage metadata)
LangChain 응답 객체의 AIMessage.usage_metadata에 붙는 사용량 정보입니다. 입력, 출력, 전체 토큰 수가 들어갑니다. 모델 제공자가 이 정보를 보내지 않았다면 0토큰을 썼다는 뜻이 아니므로, 값이 없는 상태로 실행 기록을 완료하지 않습니다.

예산은 최대 한도보다 작게 정합니다

모델 최대 한도는 기술적으로 허용되는 범위이고, 수업 예산은 이번 실습에서 지킬 운영 기준입니다. 최대 한도가 크더라도 모든 호출에 그만큼의 입력을 사용할 이유는 없습니다. 긴 입력은 비용과 처리 시간을 늘리고, 서로 관련이 적은 자료가 함께 들어가면 모델이 필요한 근거를 찾기 어려워질 수 있습니다. 수업 예산은 실습 결과를 비교하기 위한 공통 조건이기도 합니다.

입력에 사용할 수 있는 범위는 다음 순서로 정합니다. 먼저 이번 호출의 전체 예산을 정합니다. 그다음 원하는 답의 길이를 고려하여 출력 예약분을 제외합니다. 이 장의 노트북은 init_chat_model()의 max_tokens=300으로 생성 상한을 설정합니다. 모델 제공자가 추론 토큰을 별도로 집계하는지는 반환된 메타데이터와 공식 문서에서 확인합니다. 마지막으로 추정 오차와 실행 중 추가되는 메시지를 위한 여유분을 제외합니다. 남은 범위 안에서 시스템 지시, 질문, 대화 기록, 참고 문서를 배분합니다.

문자 수와 토큰 수는 같은 값이 아닙니다

문자 수는 편집기에서 세기 쉽지만 모델의 처리 단위는 토큰입니다. 따라서 “문서가 2,000자이므로 2,000토큰이다”라고 계산할 수 없습니다. 한국어 조사와 어미, 영문 약어, 숫자, 코드 기호가 섞이면 분할 결과가 달라집니다. Ch 5에서 확인한 텍스트 분할 규칙은 모델마다 다를 수 있으므로 다른 모델의 계산기를 그대로 적용해서도 안 됩니다.

실습에서는 두 값을 따로 기록합니다. 호출 전에는 해당 모델에 맞는 로컬 계산 도구로 추정 토큰 수를 구합니다. 호출 후에는 API 응답의 실제 사용량을 저장합니다. 두 값이 다르다고 계산 오류라고 단정할 수는 없습니다. 로컬 도구는 시스템·사용자 역할 표시처럼 API가 메시지에 덧붙이는 형식과 서비스 내부 처리를 모두 똑같이 계산하지 못할 수 있습니다. 호출 전 예산 검사에는 넉넉하게 계산한 추정값을 사용하고, 비용과 실행 기록에는 API가 반환한 실제 값을 사용합니다.

도식 — 한도 안에서 자리를 먼저 확보합니다

입력 예산 계산과 실제 호출 설정

input_budget(total, output_reserve, safety_margin)는 세 정수를 받아 입력에 배정할 토큰 수 하나를 반환하는 Python 함수입니다. 여기서 total=4096은 실습에서 정한 전체 배정량입니다. 사용 모델의 실제 최대 컨텍스트를 조회한 값이 아닙니다. return은 계산값을 호출한 위치로 반환하고, 음수이면 raise ValueError가 잘못된 배정을 알립니다.

출력 예약량을 300에서 600으로 늘리는 비교는 입력에 남는 공간이 300만큼 줄어드는 산술 관계를 확인합니다. 이 함수의 인자를 바꿔도 앞에서 만든 모델 객체의 max_tokens=300은 바뀌지 않습니다. 모델 출력 상한까지 바꾸어 실험하려면 모델 설정도 별도로 변경해야 합니다.

한 줄 분류 라벨을 받는 과제와 세 문단 설명을 받는 과제는 필요한 출력 공간이 다릅니다. 같은 전체 배정량에서 설명에 공간을 더 주면 입력 자료를 더 선별해야 합니다. 반대로 출력 공간을 너무 작게 정하면 중요한 단서가 입력에 있어도 답이 완성되기 전에 잘릴 수 있습니다. 실제 요청을 설계할 때는 필요한 답의 형태를 먼저 정하고 입력과 출력 배정을 함께 확인합니다.

7주의할 점과 실무 메모

  • 최대 한도를 운영 목표로 사용하지 않습니다. 모델이 받을 수 있는 최대량과 서비스가 매 호출에 사용하도록 허용할 양은 다릅니다. 팀에서는 비용과 지연 시간 기준을 포함한 별도의 예산을 정합니다.
  • 출력 제한을 나타내는 코드 인자의 뜻을 확인합니다. 사용하는 모델과 API 버전에 따라 출력 토큰과 추론 토큰을 세는 방식이 다를 수 있습니다. 수업 코드에 고정된 SDK 버전의 공식 문서를 기준으로 해석합니다.
  • 사용량 정보가 언제 제공되는지 확인합니다. 일반 응답과 스트리밍 응답은 사용량 정보의 위치나 제공 조건이 다를 수 있습니다. 값이 없을 때 0으로 기록하면 실제 사용량이 없었다는 잘못된 뜻이 됩니다.
  • 한국어와 코드를 각각 측정합니다. 같은 문자 수라는 이유로 같은 토큰 수를 가정하지 않습니다. 실제 서비스 자료의 언어와 형식을 반영한 표본으로 예산을 검증합니다.
  • 민감한 원문은 사용량 기록에 포함하지 않습니다. 운영 로그에는 토큰 수와 문서 식별자 등 필요한 정보만 남기고, 개인 정보나 비밀 값이 포함된 메시지 원문은 별도 정책에 따릅니다.

8정리와 다음 절

  • 컨텍스트는 현재 호출에서 모델에 전달된 정보이며, 외부에 존재하기만 하는 자료는 포함되지 않습니다.
  • 토큰 예산은 모델 최대 한도와 별도로 정하고, 출력 예약분과 여유분을 먼저 확보합니다.
  • 문자 수, 로컬 추정 토큰, API 실제 사용량은 서로 다른 값으로 기록합니다.

다음 학습과 이어지는 지점 — 02절에서는 예산을 넘는 전체 자료를 외부 저장소에 Write하고, 질문에 필요한 항목만 Select하여 현재 호출의 컨텍스트에 넣습니다. Ch 9에서는 이 선택을 검색으로 자동화합니다.

9복습 문제

문제 4개 · 해설 포함

[하] 1. 외부 JSON 파일에 저장되어 있지만 호출 메시지에 포함되지 않은 문서는 현재 컨텍스트입니까?

정답과 해설 — 아닙니다. 현재 컨텍스트는 모델이 이번 답을 만들 때 받도록 전달된 정보입니다. 파일은 저장된 자료이며, 읽어서 메시지에 포함해야 컨텍스트가 됩니다. 틀렸다면 이 절의 핵심 개념 ‘정의’를 다시 봅니다.

[중] 2. 전체 예산에서 입력 가용분을 정하는 순서를 설명하세요.

정답과 해설 — 전체 수업 예산을 정한 뒤 출력 예약분을 제외하고, 추정 오차와 추가 메시지를 위한 여유분을 제외합니다. 남은 범위를 지시·질문·기록·문서에 배분합니다. 틀렸다면 이 절의 핵심 개념 ‘예산은 최대 한도보다 작게 정합니다’를 다시 봅니다.
