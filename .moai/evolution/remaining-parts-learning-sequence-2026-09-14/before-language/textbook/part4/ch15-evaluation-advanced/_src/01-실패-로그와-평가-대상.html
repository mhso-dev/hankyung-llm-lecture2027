1학습 목표

  • Ch12 검색 로그 36건과 생성 답변 로그를 구분할 수 있습니다.
  • 실제 검색 순위 문제를 분류하고 생성 평가 대상을 고를 수 있습니다.
  • 평가하지 않은 결과를 실패로 표시하지 않는 기록 원칙을 적용할 수 있습니다.

2이 내용을 배우는 이유

자동 평가자를 먼저 많이 만들면 실제 시스템에서 나타나지 않은 문제에 시간을 쓰기 쉽습니다. Ch12는 36개의 TF-IDF와 MMR 검색 설정을 비교했습니다. 각 행에는 질문, 후보 문서와 검색 지표가 있지만 생성 답변은 없습니다. 따라서 이 행을 생성 실패 36건으로 세면 사실과 다른 기록이 됩니다. 이 절에서는 검색 결과의 순위가 낮아진 실제 사례를 먼저 찾고, 그 질문에 관련 문서 본문을 전달해 실제 답변을 생성한 뒤에만 생성 평가 대상으로 등록합니다.

3앞에서 배운 내용

Ch11의 evaluation-queries.jsonl은 질문과 정답 문서 ID를 제공합니다. Ch12의 advanced-continuity-experiment-log.jsonl 36행은 개발용 검색 설정 비교이며, advanced-continuity-test-result.json은 선택 설정의 시험 평가입니다. 별도 통합 로그의 Q002 답변만 생성되었고 generation_evaluation.status는 not_evaluated였습니다.

4핵심 개념

쉬운 예

병원 접수 기록만 보고 치료가 실패했다고 말할 수는 없습니다. 접수, 검사, 처방은 서로 다른 단계입니다. RAG에서도 검색 설정 행과 생성 응답 행을 먼저 구분해야 실제로 발생한 실패를 올바른 단계에 연결할 수 있습니다.

정의

평가 대상 단위는 한 질문의 입력, 검색 문서, 생성 응답, 평가 기준을 묶은 레코드입니다. 검색 실패는 정답 문서가 검색 후보나 평가할 상위 k개 순위에 들어오지 않은 상태이고, 생성 실패는 근거가 전달되었는데도 답이 틀리거나 근거 밖 내용을 추가한 상태입니다. Q006과 Q090은 정답 문서가 2위에 있어 nDCG가 0.6309로 낮아졌지만 Recall@5는 1입니다. 이는 검색 순위 문제이며 생성 실패가 아닙니다.

호출 표기와 실행 시점

평가 사례는 입력 질문, 시스템 출력, 기대 근거 또는 기대 답, 실행 설정을 한 행에 묶습니다. 실패 로그에서 정답 문서가 낮은 순위였던 질문을 찾고, 그 질문에 실제 생성한 답을 연결해야 검색 실패와 생성 실패를 나눠 볼 수 있습니다.

다른 상황에 적용

고객지원 봇에서는 ‘환불 규정을 못 찾음’과 ‘규정은 찾았지만 답에 잘못 옮김’을 별도 사례로 저장할 수 있습니다. 같은 최종 오답이라도 수정할 단계가 다르므로 검색 후보와 최종 답을 모두 남깁니다.

비교와 경계

로그에 남았다는 이유만으로 평가 정답이 되지는 않습니다. 사용자의 불만, 낮은 검색 순위, 긴 지연은 검토할 사례를 고르는 신호입니다. 기대 답과 허용 범위는 사람이 확인한 평가 데이터에 따로 기록해야 합니다.

5실행 예제

노트북은 36행의 종류와 생성 응답 필드 부재를 확인합니다. 이어서 선택 설정 시험 결과에서 nDCG가 가장 낮은 Q006과 Q090을 찾습니다. 준비 스크립트는 두 질문과 Q002에 대해 gpt-5.4-mini로 실제 답변을 생성했고, 응답 모델·프롬프트 버전·평가 모델 원문을 evaluation-cases.json에 저장했습니다. 출력에서 검색 사례 수 36, 생성 응답 수 3, 낮은 순위 사례 2를 확인합니다.

{{notebook:01-실패-로그와-평가-대상}}

확인할 점 — Ch12 설정 행 36개, 생성 응답 필드 0개, 낮은 검색 순위 사례 2개와 별도 생성 답변 3개를 확인합니다.

6실험 결과 해석

Ch12 개발 로그는 정확히 36행이었고 생성 응답 필드는 0개였습니다. 선택 설정의 시험 결과에서 Q006과 Q090은 Recall@5가 1이지만 정답 문서가 2위여서 nDCG@5가 각각 0.6309였습니다. 준비 단계에서 이 두 질문과 Q002에 문서 본문을 전달해 실제 답변 3건을 만들었습니다. 따라서 관찰한 실패는 검색 순위 문제 2건이며 생성 실패 36건이 아닙니다.

7주의할 점과 실무 메모

  • 검색 지표가 낮아졌다는 사실만으로 최종 답이 틀렸다고 결론 내리지 않습니다.
  • 생성 응답을 만들 때 사용한 문서는 Ch12의 공개 학습용 가상 문서입니다. 실제 기관 정책을 뜻하지 않습니다.
  • 생성 모델과 실행일을 고정했지만 서비스 쪽 모델 스냅샷 변경 가능성은 실행 로그와 함께 확인합니다.

8정리와 다음 절

  • 36개 Ch12 행은 생성 답변이 없는 검색 설정 로그입니다.
  • Q006과 Q090에서 정답 문서의 낮은 순위를 실제 검색 문제로 분류했습니다.
  • 실제 답변을 생성한 세 사례만 생성 평가 대상으로 등록했습니다.

다음 학습과 이어지는 지점 — 다음 절에서는 세 생성 응답에 네 평가자를 적용하고 어떤 평가자에 정답 답변이 필요한지 구분합니다.
