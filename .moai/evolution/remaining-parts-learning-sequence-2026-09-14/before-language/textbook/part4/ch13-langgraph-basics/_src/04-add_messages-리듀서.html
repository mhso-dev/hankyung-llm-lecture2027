1학습 목표

  • add_messages가 새 메시지를 추가하고 같은 ID의 메시지를 교체하는 방식을 설명할 수 있습니다.
  • HumanMessage와 AIMessage를 그래프 상태에 저장할 수 있습니다.
  • AIMessage.text로 텍스트를 읽을 수 있습니다.

2이 내용을 배우는 이유

대화형 RAG는 현재 질문만으로 검색어를 만들기 어려울 때 이전 대화를 참고합니다. 문자열 목록만 이어 붙이면 메시지 역할과 ID를 잃기 쉽습니다. add_messages는 LangChain 메시지 객체를 상태에 유지하고, 같은 ID로 수정된 메시지는 기존 항목을 교체합니다.

이번 절의 질문은 “사람과 모델의 메시지를 객체 형식으로 누적하면서 기존 메시지를 어떻게 수정할까요?”입니다. 노트북 출력과 그래프 그림을 함께 읽어 답합니다.

3앞에서 배운 내용

앞 절에서 리듀서가 상태 키의 갱신값을 합친다는 원리를 확인했습니다. 이번 절은 메시지 목록에 맞춘 내장 리듀서 add_messages를 사용합니다. 모델 API를 호출하지 않고 AIMessage 객체를 직접 만들어 상태 처리만 관찰합니다.

각 노트북은 Python 3.12 새 커널에서 독립 실행되며 이전 절의 메모리나 개인 경로를 사용하지 않습니다.

4핵심 개념

쉬운 예

회의록에 발언을 시간순으로 추가하되 잘못 적힌 발언은 발언 번호로 찾아 고친다고 생각해 봅니다.

정의

add_messages는 새 ID의 메시지를 뒤에 추가하고 기존 메시지와 ID가 같은 메시지가 들어오면 그 위치의 메시지를 교체합니다. HumanMessage는 사용자의 발언, AIMessage는 모델의 응답을 나타냅니다. AnyMessage는 이 메시지들의 공통 형식을 표현합니다. AIMessage.text는 content가 문자열이나 콘텐츠 블록이어도 텍스트 부분을 읽기 위한 속성입니다.

코드에서 읽는 순서

ChatState의 messages 키는 add_messages를 리듀서로 사용합니다. HumanMessage가 입력되면 reply 노드는 기존 목록 전체가 아니라 새 AIMessage 하나만 반환합니다. 그래프 런타임은 리듀서를 호출해 두 메시지를 합칩니다. 다음 셀은 같은 h1 ID를 가진 HumanMessage를 add_messages에 직접 전달합니다. 첫 메시지의 위치는 유지되지만 content가 바뀌므로, 새 메시지 추가와 기존 메시지 교체라는 두 규칙을 한 출력에서 구분할 수 있습니다.

호출 표기와 실행 시점

HumanMessage(content=..., id='h1')는 역할·본문·식별자를 가진 메시지 객체를 만듭니다. add_messages는 상태의 기존 messages와 노드가 반환한 새 메시지를 받습니다. 새 ID면 끝에 추가하고 같은 ID면 해당 위치의 객체를 교체합니다. AIMessage.text는 content가 여러 블록일 때도 텍스트 부분을 읽기 위한 속성입니다.

다른 상황에 적용

상담원이 사용자의 오타를 수정하거나 도구 결과가 늦게 도착해 기존 메시지를 보완할 때 같은 ID 교체 규칙을 사용할 수 있습니다. 반대로 새 대화 턴은 새 ID를 부여해야 이전 발화를 덮어쓰지 않습니다.

비교와 경계

operator.add는 두 목록을 그대로 이어 붙이므로 같은 ID를 이해하지 못합니다. add_messages는 메시지 ID와 역할을 아는 전용 리듀서입니다. 다만 메시지를 상태에 저장한다고 장기 기억이 자동으로 생기는 것은 아니며, 체크포인터와 thread_id는 뒤 장에서 별도로 다룹니다.

6실험 결과 해석

첫 그래프 실행 결과에는 human과 ai 두 메시지가 있습니다. 이어서 add_messages 리듀서를 직접 호출해 같은 ID의 수정 메시지를 합치면 기존 human 메시지가 교체됩니다. 총 메시지 수는 둘로 유지되고 첫 내용만 달라집니다.

AIMessage.text 출력은 reply 노드가 만든 문장을 그대로 보여 줍니다. 교체 뒤에도 AIMessage의 ID와 내용은 유지되어 수정 범위가 h1 메시지 하나였음을 알 수 있습니다.

이번 실행은 로컬에서 만든 HumanMessage와 AIMessage 객체의 추가·교체 규칙만 확인했습니다. 채팅 모델은 호출하지 않았으므로 모델 응답 품질이나 비용을 평가한 결과가 아닙니다.

7주의할 점과 실무 메모

  • operator.add는 같은 ID도 단순히 뒤에 추가하지만 add_messages는 ID를 보고 교체할 수 있습니다.
  • 메시지 내용은 점 표기법인 message.content 또는 AIMessage.text로 읽습니다.
  • 이번 절의 AIMessage는 상태 처리를 보기 위한 로컬 객체이며 실제 모델 응답이 아닙니다.

8정리와 다음 절

  • 첫 실행에서 HumanMessage와 AIMessage가 순서대로 저장됐습니다.
  • 같은 h1 ID의 메시지는 기존 위치에서 내용이 교체됐습니다.
  • AIMessage.text로 모델 메시지의 텍스트를 읽었습니다.

다음 학습과 이어지는 지점 — 다음 절에서는 입력 항목 수만큼 작업을 동적으로 만들어 병렬로 보내는 Send를 사용합니다.
