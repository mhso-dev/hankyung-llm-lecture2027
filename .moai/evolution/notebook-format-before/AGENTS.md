## 1. 프로젝트 개요

**목적**: 한국경제신문 KDT 「LLM Agent 개발 & 바이브코딩」(2026년 12월 개강, 24주 960h, 8 Part 41 Chapter) 과정의 교재를 커리큘럼 v6(`커리큘럼_v6.html`)에 맞춰 집필한다. 1차 산출물은 **개념 단위 HTML 교재**이고, 그 내용을 토대로 2차로 **실습용 Jupyter 노트북**을 분할 제작한다.
**대상 독자/고객**: ① 초보자 수강생(자습용 — 설명은 많을수록 좋다) ② 강사 본인(진행용 강의 노트). 검토자는 강사 본인 1인.
**톤·형식 제약**: 커리큘럼과 같은 `~합니다`체. 분량은 강의 1h당 A4 5쪽 수준의 자습 완결형. 포맷은 HTML 학습자료(`moai-tutor:education-learning-material`). 모든 코드는 uv 환경에서 실제 실행 후 수록. 민감도 `public`.

## 2. 행동 원칙 (HARD)

1. **사전 확인 후 실행**: 맥락·목적·독자·양식을 확인한 뒤 착수한다.
2. **스킬 체인 보고 후 실행**: 멀티스텝 작업은 체인을 먼저 보고하고 구조화 질문으로 승인받는다 — Claude Cowork는 `AskUserQuestion`, ChatGPT Work는 `request_user_input`.
3. **텍스트 산출물은 반드시 AI 슬롭 검수로 종료**: `moai-coworker:ai-slop-reviewer` 스킬을 체인 마지막에 호출한다.
4. **기본 artifacts보다 moai 스킬 우선**: 아래 표의 스킬이 존재하면 Claude 기본 도구 대신 스킬을 사용한다.
5. **검증되지 않은 완료 주장 금지**: 산출물을 전달할 때, 출처 미확보 수치·미확인 사실·외부 입력 대기(자격요건·승인·미공개 데이터) 항목은 결과물 끝에 「확인 필요 항목」으로 모아 명시한다. 검증을 끝내지 못했으면 끝낸 척하지 말고 무엇이 왜 막혔는지 구체적으로 적는다. "이제 작성하겠습니다"라고 말한 뒤 실제 작업 없이 멈추지 않는다 — 말한 작업은 그 응답 안에서 수행한다.

## 3. 요청 평가 사다리 (HARD)

모든 요청은 아래 3단계를 순서대로 판단하고, 충분한 가장 가벼운 단계에서 멈춘다.

1. **대화형 답변으로 충분한가** → 프로즈로 답하고 종료한다 (체인 미기동)
2. **설치된 스킬·도구가 범주에 맞는가** → 해당 스킬 체인을 실행한다
3. **파일 산출물 신호가 있는가** ("파일로 줘", "저장해줘", 오피스 포맷 지정 등 — §4의 독립 산출물 요청은 명시 신호 없이도 파일 신호로 간주) → 파일을 생성한다

어느 단계를 왜 골랐는지는 서술하지 않는다 — 조용히 선택하고 산출한다.

## 4. 파일 생성 기준 (HARD)

판단 계층: **① 파일을 만들지 먼저 결정한다(아래 기준) → ② 만들기로 했으면 §5 표의 office 스킬을 사용한다.**

- **파일로 만든다**: 독립 산출물(교재 절·노트북·퀴즈·도식 등), 오피스 포맷(DOCX/PPTX/XLSX/HWPX) 요청, 대화 밖에서 사용할 결과물, 수정·반복이 예정된 산출물. **교재 절·노트북·도식 요청은 명시 신호 없이도 파일 신호다.**
- **대화로 답한다**: 지식 질문 답변, 짧은 목록·표, 간단한 설명, 조회·요약 응답
- **장문 산출물은 일괄 생성하지 않는다**: 개요 → 섹션별 작성 → 검토 → 마무리 순서로 반복 생성한다
- **단문 산출물은 한 번에** 생성한다

## 6. 한국어 품질 체인 (HARD)

한국어 텍스트 산출물은 **작성 기준 → 장르별 작성 → 3단 감사**를 모두 통과한 것만 전달한다. 감사만 붙이면 초안의 골격(제목·구성·표현)은 그대로 남는다 — 윤문은 문장을 다듬을 뿐 목차를 바꾸지 않는다.

- 대상: 교재 본문·강사 노트·퀴즈 해설·안내문·강의자료 원고
- 제외: 코드, JSON/CSV, 노트북 코드 셀, 차트·표, 숫자 리포트, 단순 조회 응답
- 건너뛰었다면 **그 사실과 이유를 결과에 적는다.** 조용히 생략하면 감사가 있었는지 없었는지 아무도 모른다

### 6-1. 작성 전 — 장르를 먼저 정한다

`산문`(교재 본문·강사 노트·해설) · `카피`(모집·안내) · `슬라이드`(원고·덱) 중 하나를 확정한다. 이 프로젝트의 기본값은 **산문**이다. 같은 수치가 장르에 따라 정상이 되기도 결함이 되기도 한다 — 슬라이드는 단문이 정상이고 산문은 같은 길이가 결함이다.

### 6-2. 작성 — 영어 수사 구조를 쓰지 않는다

**[HARD] 적용 범위 — 모집·랜딩·홍보·안내 장르가 대상이다.** 계약·정책·기술·학술 문서에서는 아래 표를 **보고만 하고 자동 수정하지 않는다.** 그런 문서의 `A가 아니라 B`는 A를 명시적으로 배제하는 법적·기술적 장치일 수 있다. **교재 본문은 기술 문서에 준한다** — 커리큘럼 원문의 `리랭커는 후보 안에서만 정렬합니다` 같은 대조는 내용상 대조이므로 세지 않는다.

어휘 번역투(`~에 대해`·이중 피동)보다 잡기 어려운 층이다. 문장은 어법상 완벽한 한국어인데 **글의 골격이 영어 마케팅 문서**인 경우이며, 헤딩에서 가장 잘 보인다.

| 쓰지 않는다 | 원문 | 한국 문서의 관용 |
|---|---|---|
| **수사적** `A가 아니라 B입니다`가 여러 번 | *It's not X, it's Y* | 수사만 1회까지. 부정된 쪽을 지워도 주장이 남으면 수사, 안 남으면 내용상 대조라 세지 않는다 |
| `## 이런 분에게` · `## 내 절차를 자산으로` | *For those who…* | `이런 분께 추천합니다` · `교육 대상` |
| `## 3일 뒤 손에 남는 것` | *What you'll walk away with* | `수료 후 얻는 것` · `사흘 뒤 결과물` |
| 종결 없는 `## 무엇이 다른가` | *What's different* | `어떤 점이 다른가요?` |
| `이유는 하나입니다` | *The reason is simple* | 뜸 들이지 말고 이유를 바로 쓴다 |
| `겨냥합니다` · `관통하는` · `~의 얼굴` | *target / run through* | 구체 동사로 |

- **[HARD] 지우기만 하면 글이 죽는다.** 위 표현은 강조하려던 자리다. 지운 자리에 숫자·행동·사례를 넣는다
- **[HARD] 의문형 제목·FAQ에는 물음표를 붙인다.** 독자를 부르는 목소리가 사라지는 자리다
- **[HARD] 한정어를 군더더기로 지우지 않는다.** `사실상 독점`→`독점`은 실질적 지배를 법적 독점으로 바꾼다
- 장르별 작성 스킬: 카피·랜딩 `moai-marketer:content-copywriting` / `marketing-landing-page` · 산문 `moai-marketer:content-blog` · 뉴스레터 `content-newsletter`

### 6-3. 감사 — 3단 체인 (생략 불가)

아래 §9 워크플로우 표의 `⟨감사:산문⟩`·`⟨감사:카피⟩`·`⟨감사:슬라이드⟩`는 **모두 이 3단 체인**을 뜻하며, 괄호 안은 `korean-humanize`에 넘길 장르다.

```
⟨한국어 감사 3단⟩ =
  moai-coworker:ai-slop-reviewer    1차 일반 슬롭 정리
→ moai-writer:korean-spell-check    2차 맞춤법 — 제안 수집 (민감 문서는 건너뛴다, 아래)
→ moai-writer:korean-humanize       3차 정밀 윤문 + 맞춤법 제안 반영 + Phase 6 최종 검수
```

- **[HARD] `korean-humanize`가 마지막이다.** Phase 6 최종 검수가 의미 보존을 판정한 **바로 그 산출물**이 사용자에게 간다. 검수 뒤에 다른 스킬이 문장을 다시 고치면, 전달되는 것은 검수받지 않은 텍스트다 — 맞춤법 제안이 용어·조사·법적 양태를 바꿔도 아무도 다시 보지 않는다
- **[HARD] 기본값은 「전송하지 않음」이다.** 민감도가 `public`으로 **명시 판정된 문서에서만** 맞춤법 단계를 돌린다. 미응답·모호·재진입·판정 실패는 전부 `unknown`이고, `unknown`은 **건너뛴다.** 모르면 안 보내는 쪽이 기본이다. **이 프로젝트의 교재는 `public`으로 판정되었다** — 맞춤법 단계를 돌린다
- **[HARD] 문서 단위로 다시 판정한다.** 프로젝트 전체가 `public`이어도 개별 산출물이 수강생 개인정보·평가 점수·계약을 담으면 그 문서는 건너뛴다
- **[HARD] 맞춤법 단계는 민감 문서에서 건너뛴다.** `moai-writer:korean-spell-check`는 원문을 **외부 서비스(`nara-speller.co.kr`)로 전송**한다. 아래에 해당하면 이 단계를 생략하고 그 사실을 결과에 적는다
  - 계약서·NDA·법무 검토 문서 · 재무·세무·결산 자료 · 인사·평가·급여 · 개인정보가 든 문서 · 대외비/기밀 표시가 있는 것 · 미공개 사업계획·IR
  - 생략해도 `korean-humanize`가 맞춤법을 함께 본다. 외부 전송 없이 처리된다
- **코드 블록·명령어·파일 경로는 감사 대상에서 제외한다.** 감사 전에 코드 블록을 플레이스홀더로 치환하고, 감사 후 원문을 되돌린다. 코드가 한 글자라도 바뀌면 §15 실행 검증이 무효가 된다
- 호출 시 옵션을 붙인다 — `장르: 산문|카피|슬라이드`, `최소심각도: S1`
- `korean-humanize`는 **전문 정독**으로 판정한다(`references/contextual-review.md`). 규칙 매칭은 정독이 지목한 자리를 고치는 도구이지 판정 주체가 아니다
- **최종 검수는 생략 불가**(`korean-humanize` Phase 6). 원문↔윤문본을 대조해 ① **의미 보존** — 없던 주장 주입·각주 원위치·수치와 인용 불변 ② **과윤문 역방향** — 격식 상향·상투구 주입·구어 종결 소실을 본다
- 판정이 `hold_and_report`면 **전달하지 않고** 사람에게 넘긴다
- 출력: **진단 요약 → 수정 텍스트 → 주요 변경사항** 3블록

## 7. 인용·저작권 가드 (HARD)

외부 자료(기사·서적·가사·시 등)를 인용하거나 요약할 때:

- 직접 인용은 원문 **15단어 미만**, 출처당 **최대 1회**
- 가사·시는 **한 줄도 전문 재현하지 않는다**
- 원문 소비를 대체하는 요약(원문의 구조·서사 흐름을 그대로 따라가는 요약)을 만들지 않는다
- 기본 동작은 자기 문장으로의 **완전 재표현** — 인용은 고유하게 표현된 통찰에 한정한 예외다
- 공식 문서(LangChain·LangGraph·FastAPI 등)의 코드 예제는 라이선스(MIT 등)를 확인하고 **출처 URL과 확인 날짜**를 절 끝 「참고 자료」에 적는다. 예제를 그대로 옮기지 않고 이 과정의 도메인 문서·변수명으로 다시 쓴다

## 8. 톤 규칙 (HARD)

- **프로즈 기본** — 불릿·번호 목록·볼드는 구조가 꼭 필요하거나 사용자가 요청할 때만 쓴다
- **응답 깊이는 요청 깊이에 비례한다** — 짧은 질문에 장문 설명을 붙이지 않는다 (과잉 설명 회피)
- 텍스트 대화에서 불필요한 되묻기를 피한다 — 구조화 질문이 필요하면 런타임의 질문 도구로 한다
  - Claude Cowork: `AskUserQuestion` — 1라운드 4질문 이내, 각 2~4옵션
  - ChatGPT Work: `request_user_input` — 1라운드 **1질문 권장(3 초과 금지)**, 각 **2~3옵션**, `id`(snake_case) 필수. **Plan 모드에서만 쓸 수 있다**
  - 도구가 없으면 임의로 가정하지 말고, 번호 매긴 선택지를 글로 낸다
- **교재 본문의 톤**은 §14를 따른다(`~합니다`체, 초보자 기준, 설명은 많을수록 좋다). 이 절의 "과잉 설명 회피"는 **대화 응답**에 적용되며 교재 본문에는 적용하지 않는다

## 10. 실행 플로우 (Evaluate → Interview → Plan → Confirm → Execute)

0. [Evaluate] §3 요청 평가 사다리로 응답 층을 판단 — 대화형 답변으로 충분하면 여기서 종료
1. [Interview] 소크라테스 인터뷰로 빠진 맥락 수집 (맥락 충분까지 다단계 — 1회 4질문 max, 필요 시 라운드 반복. 단순 조회·이미 상세 지시 시 스킵). 교재 절 집필에서 확인할 것: 대상 챕터·개념 단위 경계·선수 절·회수 대상 챕터
2. [Summary] 수집한 맥락을 구조화하여 확인 요약
3. [Plan+Confirm] 스킬 체인 실행 계획 + **완료 기준**(무엇이 참이면 끝인지)을 제시 → AskUserQuestion으로 승인
4. [Execute] 체인 순차 실행 → 각 단계 요약 보고 → ai-slop-reviewer 검수 → 「확인 필요 항목」 명시 → 전달

## 14. 교재 집필 규격 — 프로젝트 필수

### 14-1. 단위와 경로

- **집필 단위는 「개념」**이다. 챕터를 개념 단위로 쪼개 절 하나가 개념 하나를 완결한다. 절 하나의 분량은 해당 강의 시수 1h당 A4 5쪽(약 2,500자+코드) 기준. 커리큘럼의 챕터 시수(예: Ch 12 강의 12h)를 개념 수로 나눠 절당 분량을 정한다.
- 경로: `textbook/part{P}/ch{CC}-{slug}/{NN}-{개념}.html` (예: `textbook/part1/ch02-python/01-변수와-제어문.html`). 챕터 폴더에 `index.html`(절 목록·학습 목표·시수)을 둔다.
- 도식 소스: `textbook/part{P}/ch{CC}-{slug}/figures/{NN}-{이름}.excalidraw`(JSON) + 확정 `.svg`. 삽화: `figures/{NN}-{이름}.png`.
- 노트북: `labs/part{P}/ch{CC}-{slug}/{NN}-{개념}.ipynb` (§17).
- 진행표: `.moai/context.md` §진행표를 절 확정 시마다 갱신한다. 챕터가 끝나면 **「이 챕터가 만든 것」**(파일 경로·함수명·새 용어·다음 챕터에 넘기는 것)을 한 줄로 남긴다 — 다음 세션이 선수 절을 다시 읽지 않고 회수 연결을 잇는 근거다.
- **작업 단위는 챕터 하나**다("Ch N 교재 써줘" = 그 챕터의 개념 절 전부 + 챕터 `index.html`). 40h급 챕터(Ch 2·12·30·40·41)는 절 경계에서 두 세션으로 나누고, 8h급(Ch 20·24·25·26·34)은 인접 챕터와 묶어도 된다. 챕터 시작 시 먼저 개념 단위 분해안(절 목록·절당 시수·도식 목록)을 보이고 승인받은 뒤 집필한다.
- 집필 세션과 검토 세션을 나눈다. 집필(본문·코드·도식·삽화)은 한 세션에서 절 단위로 끝내고, 감사 3단·검토는 다른 모델의 별도 세션에서 돌린다(자기 문체 편향 회피). 집필 세션은 감사를 건너뛴 사실을 결과에 적는다.
- **검토자 지적을 반영하는 절차(2026-09-08 확정)**: ① 지적된 표현을 `_src/` 전체와 `labs/`(주석·README·데이터 문서)에서 grep한다 ② 같은 유형의 표현을 추가로 찾아 함께 고친다(지적 15건 → 실제 수정 110곳이 선례) ③ `_build.py` 재실행 ④ 새 금지 표현을 §14-4 표에 행으로 추가한다(삭제 금지) ⑤ `.moai/evolution/signals.md`에 한 줄, `.moai/context.md` 누적 노트에 한 줄 남긴다. 커리큘럼 원문 인용 안의 표현은 고치지 않고 "(커리큘럼 원문)"을 붙인다.

### 14-2. 절의 고정 구조 (순서 고정)

1. **학습 목표** — "이 절을 마치면 ~할 수 있습니다" 2~4개. 커리큘럼 챕터 설명에서 도출.
2. **왜 지금 이것인가** — 커리큘럼의 배치 이유를 학생 말로 다시 쓴다. 커리큘럼 두 규칙(에이전트는 Ch 20 `ToolNode`부터 / 측정이 튜닝보다 먼저)과 충돌하지 않는지 확인한다.
3. **선수 지식 회수** — 이전 절·챕터에서 만든 것 중 이 절이 쓰는 것을 파일 경로·함수명 수준으로 짚는다(예: "Ch 4에서 만든 `fetch_orders()`가 Ch 19에서 도구가 됩니다").
4. **핵심 개념** — 비유 → 정의 → 도식(§16) → 최소 예제 순. 초보자 기준으로 **용어는 처음 등장할 때 반드시 풀어 쓰고** 영문 원어를 괄호로 병기한다. 한 절에 새 용어 7개를 넘기지 않는다.
5. **실행 예제** — §15 규격의 코드 + 실제 출력. 예제마다 "무엇을 보라"를 한 문장으로.
6. **일부러 실패해 보기** — 커리큘럼이 강조하는 "버그 심기·실패 재현·공격해 뚫기"를 절마다 최소 1개 포함한다.
7. **주의할 점과 실무 메모** — 한국어 특수성(토크나이저·Kiwi·HWP)·버전 차이·비용을 적는다. ("함정"이라는 단어는 쓰지 않는다 — §14-4)
8. **정리와 다음 절** — 3줄 요약 + 이 절이 어디서 회수되는지(예: "Ch 22 Middleware가 이걸 한 줄로 대체합니다").
9. **복습 문제** — 3~5문항, 해설 포함(④ 체인 결과를 여기 넣는다).
10. **강사 노트**(접이식 `<details class="instructor">`) — 시간 배분(강의/실습 분), 시연 순서, 예상 질문 3개, 학생이 자주 막히는 지점, A/B 트랙 분기.
11. **참고 자료** — 공식 문서 URL + 확인 날짜 + 기준 버전.

### 14-3. 문체

- `~합니다`체. 커리큘럼 v6의 문장 호흡을 따른다 — 짧은 문장, 굵은 글씨로 핵심 한 구절, 이유를 먼저.
- 독자는 초보자다. **"당연히"·"간단히"·"쉽게"를 쓰지 않는다.** 대신 단계를 하나 더 쓴다.
- 커리큘럼이 명시한 **금지 범위를 넘지 않는다**: CNN·RNN·Transformer 구현(Ch 5), 리트리버 래퍼(Part 3), `create_agent` 조기 사용(Ch 20 이전), Middleware 조기 사용(Ch 16), LangChain·LangGraph 사용(Ch 18).
- 기준 버전을 고정한다: LangChain v1.4 · LangGraph 1.2 · DeepAgents 0.7 · MCP 2026-07 · FastAPI 0.135+ · Python 3.12 · uv. 다른 버전의 API를 섞지 않는다. `education-tutor-research`로 집필 시점에 공식 문서를 확인하고, 커리큘럼 기준 버전과 다르면 「확인 필요 항목」에 적는다.
- 미정 항목(바이브코딩 도구, 도메인 문서 세트·질의셋, 임베딩·리랭커·judge 모델)은 **플레이스홀더 `[[미정: …]]`**로 표시하고 가정을 적는다. 확정되면 일괄 치환한다.

### 14-5. 챕터 산출물 구조와 빌드 (HARD, Ch 9에서 확정)

Ch 9에서 만든 구조를 이후 모든 챕터가 그대로 따른다. 새 챕터는 `textbook/part3/ch09-rag-first-run/`의 `_build.py`·`figures/_gen_figures.py`를 복사해 시작한다.

- **원본은 `_src/{NN}-{개념}.html`(본문 조각)이다.** 완성 HTML(`{NN}-{개념}.html`)은 `python _build.py`가 생성하는 산출물이며 직접 편집하지 않는다. 검토·윤문·용어 치환은 전부 `_src/`에 하고 다시 빌드한다.
- `_build.py`가 하는 일: 공통 골격(헤더·CSS·목차·hljs) → `{{svg:이름}}`을 `figures/이름.svg` 인라인 → `{{img:이름|alt}}`를 `figures/이름.png`의 base64 JPEG(1100px, q82)로 → `<table>`을 `.tw`(가로 스크롤)로 감싸기 → `index.html` 생성. 외부 의존은 Google Fonts와 highlight.js CDN뿐이다.
- 절 첫 줄의 `<!--meta: 강의 Nh | 실습 Nh | 코드 … | 새 용어 N -->`가 헤더 배지가 된다.
- 고정 소제목(§14-2 11블록)의 한국어 표기는 `_build.py`의 `TOC_BLOCKS`가 정본이다: 학습 목표 · 왜 지금 이것인가 · 선수 지식 되짚기 · 핵심 개념 · 실행 예제 · 일부러 실패해 보기 · 주의할 점과 실무 메모 · 정리와 다음 절 · 복습 문제 · 강사 노트 · 참고 자료. 실행 출력 뒤의 해설 단락은 `<p class="look"><b>확인할 점</b> — …</p>`, 8번 블록의 연결 단락은 `<strong>다음 학습과 이어지는 지점</strong>`으로 시작한다.
- **도식은 `figures/_gen_figures.py` 한 파일이 정본이다.** 요소 목록(box·arrow·zone·text·dot) 하나에서 `.svg`와 `.excalidraw`를 함께 생성하므로 두 파일이 어긋나지 않는다. 도식을 고칠 때는 SVG를 손으로 만지지 않고 생성기를 고친 뒤 `python _gen_figures.py` → `python _build.py`.
- 삽화는 `figures/{NN}-{이름}.png`(원본) + `{NN}-{이름}.caption.md`(설명 대상 문장·캡션·시선 순서·alt·세 질문 답). 캡션 파일이 없는 삽화는 채택하지 않는다.
- 실습 코드는 `labs/part{P}/ch{CC}-{slug}/` — `rag.py` 같은 본체 모듈, `examples/exNN_*.py`(절 번호와 일치, 교재 실행 출력의 출처), `tests/`, `README.md`(실행 명령 목록). 교재의 코드 블록은 이 파일에서 함수 단위로 그대로 복사한 것이어야 하며, 전달 전 두 쪽을 diff한다.
- 실행 출력이 새 실행으로 바뀌면 교재의 출력 블록과 해설 숫자(토큰·비용·순위)를 함께 갱신한다. 한쪽만 고친 상태로 전달하지 않는다.

## 15. 코드 실행 검증 — 프로젝트 필수

- **교재에 실리는 모든 코드는 실제로 실행한 것만 싣는다.** 실행 환경은 `uv`(`pyproject.toml` + `uv.lock`, Python 3.12). 챕터별 의존성은 `labs/part{P}/ch{CC}-{slug}/pyproject.toml`에 고정한다.
- 출력은 실행 결과를 그대로 붙이되, API 키·토큰·개인 경로는 마스킹한다. LLM 출력처럼 비결정적인 결과에는 "출력은 실행마다 달라집니다"를 명시하고 실행일과 모델명을 적는다.
- 실행하지 못한 코드(키 없음·외부 서비스 미가동·Docker 불가)는 싣지 않거나 `# 미실행 — 사유` 표시와 함께 「확인 필요 항목」에 적는다. 미실행 코드를 실행된 것처럼 쓰지 않는다.
- 코드 스타일: 타입힌트, `ruff` 통과, 한국어 주석은 "왜"만, 파일 하나로 실행되는 형태. 커리큘럼 원칙대로 **평범한 파이썬 함수**로 조립하고 래퍼로 감추지 않는다.
- 각 예제는 `pytest` 테스트 1개 이상을 동반한다(노트북 분할 시 "테스트로 검증" 단계가 된다).
- 비용이 드는 호출(LLM API)은 실행 전 예상 비용을 적고, 절당 누적 $1를 넘기면 사용자에게 확인한다.
- **샌드박스(Cowork Linux)에서 `uv sync`는 마운트 폴더에 `.venv`를 만들지 못한다**(FUSE에서 wheel 설치 실패, 삭제도 불가). 항상 `export UV_LINK_MODE=copy UV_PROJECT_ENVIRONMENT=/tmp/venv-{chapter}`로 가상환경을 마운트 밖에 둔다. `.venv`가 마운트 안에 생겼으면 `mcp__cowork__allow_cowork_file_delete`로 삭제 권한을 받은 뒤 지운다. `.gitignore`에 `labs/**/.venv/`·`.cache/`가 있다.
- **비결정적 출력은 반복으로 다룬다.** 2026년 모델(gpt-5.4-mini 등)은 근거가 없어도 대개 "찾을 수 없다"고 답하므로 환각 한 번을 보려면 조건(빗나간 검색 + 친절 프롬프트 + 5회 이상 반복)을 만들어야 한다. 교재에 "N회 중 M회"를 쓸 때는 사람이 다시 센 값을 쓰고, 스크립트 판정과 다르면 그 차이를 본문에 그대로 적는다(Ch 9 05절이 선례).
- **기록 단위는 처리 단위와 같아야 한다.** 검색 결과를 쪽 단위로만 기록하면 청크 단위 실패가 숨는다(Ch 9 Q008). 로그·상세 파일에는 `chunk_id`처럼 파이프라인이 실제로 다루는 단위의 식별자를 남긴다.
- 교재에 실린 사례를 설명하는 숫자(순위·점수·토큰)는 본문을 쓰기 전에 스크립트로 다시 확인한다. 기억으로 쓴 "6위까지 넓혀도 없다" 같은 문장이 실측과 달랐던 사례가 Ch 9 03절에 있었다.
- 라이브러리 선택이 커리큘럼 문구와 어긋나면(예: `langchain-community` sunset → `PyPDFLoader` 대신 `pypdf` 직접 호출) 교재 「주의할 점」에 이유를 적고 「확인 필요 항목」에 올린다. 조용히 바꾸지 않는다.

## 16. 도식·삽화 규격

- **워크플로우·아키텍처·데이터 흐름**은 Excalidraw MCP `create_view`로 초안을 그려 채팅에서 확인받는다(`read_me`는 세션당 1회). 확정되면 같은 요소를 **인라인 SVG**로 교재 HTML에 넣고, Excalidraw JSON을 `figures/*.excalidraw`로 저장해 나중에 수정할 수 있게 한다. HTML은 외부 이미지 링크 없이 단일 파일로 완결한다.
- 도식 하나에 상자 7개 이하, 한국어 라벨, 색은 의미별로 고정: 학생이 적은 흐름(`if`·조건부 엣지)=파랑, 모델 판단=보라, 도구·데이터=초록, 측정·평가=노랑, 실패·공격=빨강. 이 색 규칙은 커리큘럼의 핵심 대비(흐름을 누가 정하는가)를 41장 내내 같은 색으로 보이게 하는 장치다.
- **삽화는 장식이 아니라 교육 자료다.** 분위기용 추상 이미지(빛나는 뇌·회로 배경·로봇 손 등)는 만들지 않는다. 삽화 하나는 **본문의 특정 문장 하나를 그림으로 설명**해야 하며, 그 문장을 캡션에 적는다. 생성 전에 다음 세 가지에 답이 없으면 그리지 않는다: ① 이 그림이 없으면 학생이 무엇을 오해하는가 ② 그림에서 학생이 **어디를 보고 무엇을 읽어야** 하는가(시선 순서 1→2→3) ③ 같은 내용을 도식(§16 상단)으로 그리는 편이 더 정확하지 않은가 — 정확하다면 도식으로 간다.
- 삽화 허용 유형: **비유의 구체화**(컨텍스트 윈도 = 책상 위 공간, 토큰 = 낱말을 자르는 가위), **눈에 안 보이는 과정의 가시화**(임베딩 공간에서 가까운 문장, 어텐션이 어느 단어를 보는지), **실패 장면의 재현**(검색 결과에 숨은 지시문이 모델을 속이는 순간), **비교 대비**(같은 질문에 순수 RAG와 에이전트가 움직이는 경로). 각 유형은 그림 안에 **비교 대상이나 인과 관계가 드러나는 구성**(before/after, 좌우 대비, 번호 순서)을 갖는다.
- `moai-media:media-higgsfield-image` 프롬프트는 "교육용 설명 일러스트, 흰 배경, 평면, 텍스트 없음(라벨·번호·화살표 설명은 HTML에서 오버레이), 구성 요소 N개를 좌→우 순서로, 요소 간 관계를 화살표·크기·거리로 표현"을 기본으로 하고, 반드시 **구성 요소 목록과 배치**를 프롬프트에 적는다. 분위기 형용사(futuristic·glowing·abstract)는 쓰지 않는다.
- 생성 결과는 채택 전 검수한다: 본문 문장을 모르는 사람에게 그림만 보여 줘도 "무엇이 무엇에게 어떻게 한다"가 읽히는가. 읽히지 않으면 구성 요소를 줄여 다시 만들거나 도식으로 바꾼다. 크레딧 절약보다 이 기준이 우선이다.
- Mermaid(시퀀스·상태도)는 `education-learning-material`이 지원하므로 그래프 구조(Ch 13·20·21)는 Mermaid로 그려도 된다. `draw_mermaid_png()` 출력과 대조하는 절에서는 반드시 Mermaid를 쓴다.
- 모든 그림에 캡션과 한 문장 설명, `alt` 텍스트를 붙인다.
- **삽화 생성 실무(Ch 9 확정)**: 모델 `nano_banana_pro`(16:9, 1k, 장당 2크레딧)로 충분하다. 프롬프트는 영어로, "no text, no letters, no numbers"를 반복해 적고, 좌→우 구성 요소를 번호 순서로 나열한다. 결과는 900px 축소본을 Read로 직접 보고 "그림만 보고 관계가 읽히는가"를 판정한 뒤 채택한다. 세 질문(§16 상단)에 답이 없는 절은 삽화 없이 도식만 둔다 — Ch 9는 6절 중 3절(01·05·06)만 삽화를 넣었다.
- **도식 초안은 `create_view`로 한 번 보여 주고, 확정본은 생성기(§14-5)로 만든다.** 라벨이 상자에 겹치면 라벨을 줄이거나(예: "검색 실패·정답 누락") 별도 `text` 요소로 뺀다. 도식 라벨에도 §14-4가 적용된다("k=4 안쪽" → "k=4 범위").
- **시각 품질 게이트는 DOM 실측으로 통과시킨다.** Chrome 확장이 없으면 샌드박스에 `playwright` + `chromium`(`channel="chromium"`, `libXdamage.so.1`은 `apt-get download`로 내려받아 `LD_LIBRARY_PATH`로 로드)을 두고, 1280px·390px 두 폭에서 ① 본문 ≥16px·캡션/코드 ≥14px ② WCAG 대비 ≥4.5:1(큰 글자 3:1) ③ `overflow:hidden` 잘림 0 ④ 문서 가로 스크롤 0 ⑤ `.page` 밖 텍스트 0을 잰다. Ch 9에서 걸린 것: 인라인 `code` 0.88em(13.2px), 토큰 `--g500 #87867F`(3.47:1), 링크 `--clay-d`(4.3:1), 긴 URL·코드의 줄바꿈 없음, 표의 가로 넘침. `_build.py`의 CSS에 수정본이 들어 있으니 그대로 쓴다.

## 17. 실습 노트북 분할 규격

- 입력은 **확정된 HTML 절**이다. 노트북이 교재보다 앞서지 않는다.
- 노트북 하나 = 절 하나. 셀 구조는 커리큘럼 Ch 2의 실습 4단을 따른다: `개념 요약(md)` → `예제 실행(code)` → `예제 수정 과제(code, TODO)` → `일부러 버그 심고 찾기(code)` → `pytest로 검증(code)` → `정리(md)`.
- 정답 셀은 별도 `{NN}-{개념}-solution.ipynb`로 분리한다. 학생 배포본에는 `# TODO`와 `assert`만 남긴다.
- 노트북은 커널을 새로 띄워 **위에서 아래로 한 번에 실행**되어야 한다(`jupyter nbconvert --execute`로 검증). 실행 실패 셀이 있으면 전달하지 않는다.
- 데이터·문서 세트가 필요한 절(Ch 9~12)은 `labs/data/` 경로와 `[[미정: 도메인 문서 세트]]` 플레이스홀더를 쓴다.
- 마크다운 셀만 `ai-slop-reviewer`를 돌리고, 코드 셀은 감사에서 제외한다.
