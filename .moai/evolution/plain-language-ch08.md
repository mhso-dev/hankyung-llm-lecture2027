# Ch 8 초보자용 표현 정독 기록

## 검토 범위와 기준

`textbook/part2/ch08-context-engineering/_src/`의 여섯 절과 `index-body.html`을 처음부터 끝까지 읽었습니다. 대응하는 노트북 여섯 개의 모든 마크다운 셀도 읽고, 학생이 노트북만 열어도 용어의 뜻과 관찰 대상을 이해할 수 있는지 확인했습니다. 문장은 단순 치환하지 않고 앞뒤 설명, 코드에서 쓰는 필드명, 실험의 한정 조건을 함께 보아 고쳤습니다.

기술 용어를 없애기보다 첫 등장에 구체적인 행동과 예를 먼저 적었습니다. 경고 문장은 금지 표현만 남기지 않고, 무엇이 잘못될 수 있는지와 무엇을 확인해야 하는지를 이어서 설명했습니다. `korean-humanize`의 전문 정독 기준과 `ai-slop-reviewer`의 반복·추상 표현 기준을 적용했습니다. 외부 맞춤법 서비스는 이번 작업 지시에 따라 사용하지 않았습니다.

## 파일별 검토 내역

- `index-body.html`: 네 전략을 “저장하고, 고르고, 줄이고, 업무별로 나누는 방법”으로 풀었습니다. 네 실패 이름은 공식 오류 코드가 아니며 한 사례에 여러 문제가 함께 나타날 수 있다는 두 한정 조건을 각각 구체적인 문장으로 유지했습니다.
- `01-컨텍스트와-토큰-예산.html`: 컨텍스트 엔지니어링을 “모델에게 어떤 자료를 얼마나 보낼지 정하는 일”로 설명했습니다. `usage_metadata`가 응답에 붙는 토큰 수 정보라는 점과 값이 없다고 0토큰은 아니라는 점을 풀어 썼습니다. 로컬 추정과 API 실제 값이 달라질 수 있는 이유도 시스템·사용자 역할 표시를 예로 들어 설명했습니다.
- `02-Write와-Select.html`: Write와 Select가 공식 절차가 아니라 설명을 위한 이름임을 밝혔습니다. 메타데이터를 “본문 옆에 따로 적는 표의 열”로 설명하고, JSON 저장이 모델을 다시 학습시키는 일은 아니라는 점을 구체화했습니다. 날짜 형식과 시간대를 맞춘다는 말도 실제 날짜 형식 예와 함께 적었습니다.
- `03-Compress와-Isolate.html`: “정보 밀도와 작업 경계”를 한 기록의 반복 표현을 줄이는 일과 업무별 메시지가 섞이지 않게 하는 일로 바꿨습니다. 텍스트 태그는 제목표시에 가깝고 접근을 막지 못한다는 이유를 설명한 뒤, 권한 검사·별도 저장소·별도 호출을 보안 격리의 예로 제시했습니다.
- `04-네-가지-실패-모드.html`: Poisoning·Distraction·Confusion·Clash를 각각 틀린 메모의 재사용, 무관한 자료로 인한 근거 누락, 비슷한 기관의 혼동, 시행일 없는 상충 규정으로 설명했습니다. 이 이름들이 공식 오류 이름이 아니고 서로 겹칠 수 있다는 뜻을 보존했습니다. 실패를 일으키려 넣은 문장과 실제 답에서 확인한 오류도 구분했습니다. 시행일 수정 예제는 질문 날짜보다 이르거나 같은 시행일 중 가장 최근 기록을 고르는 절차로 풀었습니다.
- `05-Context-rot-측정.html`: 현상을 먼저 “긴 입력에서 필요한 문장을 찾아 답에 적용하는 능력이 낮아질 수 있음”으로 설명한 뒤 context rot라는 이름을 붙였습니다. 통제 조건과 문자열 자동 검사의 한계를 예로 설명했습니다. 2026-09-09 실행값 64·2,224·21,664토큰, 각 3 / 3, 총 아홉 답에서 저하를 관찰하지 못했다는 결론은 그대로 유지했습니다.
- `06-단계적-공개와-설계-비교.html`: 단계적 공개를 문서 ID와 제목을 먼저 보고 선택한 문서 본문을 나중에 읽는 순서로 설명했습니다. “얕고 넓은 정보/깊고 좁은 정보” 대신 여러 문서의 짧은 목록과 한 문서의 자세한 본문이라고 적었습니다. 학생 코드가 ID를 고르므로 모델이 문서를 고르는 에이전트가 아니라는 차이도 구체화했습니다. 앞 절 실험은 길이만 변경하고 질문·모델·근거 위치를 고정했으며 각 길이를 세 번 실행했다는 조건으로 바로잡았습니다.
- `notebooks/*.ipynb`: 코드 옆에서 바로 이해해야 하는 11개 마크다운 셀을 수정했습니다. 토크나이저와 `usage_metadata`, 임시 폴더, Compress와 Isolate, 네 실패 이름, 문제 문장과 관찰 결과, `record` 딕셔너리와 `records` 목록, 단계적 공개를 각 셀의 실제 코드에 맞게 설명했습니다.
- `_make_notebooks.py`: 위 노트북 마크다운 문구를 생성기에도 같은 내용으로 반영했습니다. 05절은 기존 생성 구조상 전용 실행 환경 안내를 별도로 갖고 있지만, 이번에 수정한 마크다운 문구는 현재 노트북과 일치합니다.
- `figures/_gen_figures.py`, `01-책상-예산.caption.md`: 모든 학생용 라벨과 캡션을 읽었습니다. 현재 문구는 책상, 보관함, 질문, 근거처럼 화면에서 바로 찾을 수 있는 대상을 사용하고 있어 수정하지 않았습니다.

## 대표 변경 예

1. “네 가지 실무 범주”를 “자료를 저장하고, 고르고, 줄이고, 업무별로 나누는 방법”으로 바꿨습니다.
2. “국제 표준이나 상호 배타적인 오류 코드가 아니다”를 “업계가 공통으로 정한 공식 오류 이름이 아니며, 한 사례에 여러 문제가 함께 나타날 수 있다”로 나누어 설명했습니다.
3. “정보 밀도를 조정하고 경계를 정한다”를 “한 기록의 반복 표현을 줄이고, 대출 자료가 휴관 메시지에 섞이지 않게 한다”로 바꿨습니다.
4. “사용량 메타데이터”를 `AIMessage` 응답에 붙는 입력·출력·전체 토큰 수로 설명하고, 값 없음과 0을 구분했습니다.
5. “시행일·요일·출처를 구조화한다”를 각 값을 따로 적은 뒤 질문 날짜 이하에서 가장 최근 시행일을 고르는 절차로 풀었습니다.

## 남긴 전문 용어

- `context`, `context window`, `token`: 모델의 입력 한도와 API 사용량을 읽을 때 필요한 기본 용어라서 한국어 설명과 함께 유지했습니다.
- `Write`, `Select`, `Compress`, `Isolate`: 이 챕터와 다음 챕터에서 같은 전략을 가리키는 이름이며 코드·도식과 연결되므로 유지했습니다.
- `Poisoning`, `Distraction`, `Confusion`, `Clash`: 원문 자료의 문제 이름을 찾아볼 수 있어야 하므로 유지했습니다. 공식 오류 코드가 아니며 서로 겹칠 수 있다는 제한을 바로 옆에 적었습니다.
- `metadata`, `document ID`, `source`: JSON 필드와 답의 출처를 연결하는 실제 코드 이름이므로 쉬운 정의를 붙여 유지했습니다.
- `AIMessage`, `invoke`, `usage_metadata`: LangChain 코드에서 학생이 직접 읽고 사용하는 API 이름이라서 반환값과 역할을 설명했습니다.
- `context rot`: 05절에서 측정하는 현상의 이름이라서 쉬운 현상 설명 뒤에 표기했습니다.
- `full`, `selected`, `compressed`: 노트북 딕셔너리의 실제 키와 출력 이름이므로 한국어인 전체·선택·압축 입력과 나란히 유지했습니다.
- `progressive disclosure`: 06절의 핵심 개념이며 후속 자료 검색의 설계 근거라서 “목록을 먼저 보고 필요한 본문을 나중에 읽는 방식”이라는 설명과 함께 유지했습니다.
