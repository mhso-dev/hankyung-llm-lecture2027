1학습 목표

  • HTML 요소와 CSS 선택자로 기사 필드를 추출할 수 있습니다.
  • 선택 결과가 없을 때 반환 형식을 유지할 수 있습니다.
  • robots.txt와 별도로 이용 조건·저작권·개인정보·호출 간격을 확인해야 하는 이유를 설명할 수 있습니다.

2이 내용을 배우는 이유

모든 웹사이트가 구조화된 API를 제공하지는 않습니다. 공개 HTML에서 제목과 날짜를 읽어야 할 때는 문서의 태그와 속성을 분석해 필요한 값만 추출합니다. 화면에 보이는 문자열을 임의 위치로 자르면 광고나 메뉴가 섞이고 페이지 구조가 조금만 바뀌어도 결과가 달라집니다.

스크래핑은 기술적으로 읽을 수 있다는 사실만으로 사용이 허용되는 작업이 되지 않습니다. 대상 주소의 이용 약관, 저작권과 데이터베이스 권리, 개인정보, 접근 빈도 제한을 확인해야 합니다. robots.txt는 크롤러의 접근 경로를 알리는 규칙이며 접근 허가서나 비공개 보호 장치가 아닙니다.

3앞에서 배운 내용

앞 절에서 HTTP로 JSON을 받아 사전의 키로 값을 읽었습니다. HTML은 같은 값을 태그의 계층과 속성으로 표현합니다. Ch 2에서 배운 None 검사와 예외 처리를 사용하면 선택한 요소가 없을 때 함수가 갑자기 중단되는 문제를 줄일 수 있습니다.

4핵심 개념

쉬운 예

신문 한 면에서 기사 제목, 요약, 발행일이 놓인 자리를 규칙으로 적는다고 생각해 봅니다. HTML의 article, h1, time 요소가 문서 구조를 나타냅니다. .summary는 class가 summary인 요소를 고르는 CSS 선택자입니다.

정의

파싱(parsing)은 문자열을 태그와 계층을 가진 구조로 해석하는 과정입니다. Beautiful Soup에 lxml 파서를 명시하면 어떤 파서로 트리를 만들었는지 실행 조건이 분명해집니다. 잘못 구성된 HTML은 파서에 따라 트리가 다를 수 있으므로 프로젝트와 실습의 파서 버전을 고정합니다.

스크래핑(scraping)은 웹 문서에서 필요한 데이터를 자동으로 추출하는 작업입니다. CSS 선택자는 요소 이름, class, 속성 등의 조건으로 노드를 고릅니다. robots.txt는 사용자 에이전트별 접근 경로 규칙을 전달하지만 이용 약관이나 법률 검토를 대신하지 않습니다.

5실행 예제

배포된 data/article.html을 읽어 BeautifulSoup(html, "lxml")로 파싱합니다. select_one("article")로 기사 컨테이너를 고르고 속성과 자식 요소에서 기사 ID, 제목, 요약, 발행일을 읽고 제목과 요약을 합친 모델 입력용 text를 만듭니다. 결과는 A10, 골목상권 매출 회복, 요약 문장, 2026-09-01과 합친 텍스트를 담은 사전입니다. 이 사전에 스키마 버전과 원본 경로를 더해 data/article-text.json에 기록하고, 파일을 다시 읽어 기록 전 값과 같은지 확인합니다. 이어서 RobotFileParser에 교육용 규칙을 넣어 /articles/는 허용되고 /private/는 차단되는지 확인합니다.

파싱 함수의 반환 필드는 API 응답처럼 명시적인 이름을 사용합니다. 제목과 요약은 화면 표시 문자열을 정리해 반환하고 발행일은 time 요소의 datetime 속성에서 읽습니다. 선택자가 문서 전체에서 여러 번 나타날 수 있다면 먼저 기사 컨테이너를 고른 뒤 그 안에서 다시 선택해야 다른 영역의 제목이 섞이지 않습니다. 필수 필드인 기사 컨테이너와 제목이 없을 때는 해당 페이지의 구조가 달라졌음을 별도 오류로 기록하는 편이 좋습니다.

6일부러 실패해 보기

Before는 문서에 없는 .subtitle을 선택하고 바로 get_text()를 호출합니다. 선택 결과가 None이므로 AttributeError가 발생합니다. After는 요소가 있는지 확인하고 없는 선택 필드를 None으로 반환합니다. 이렇게 하면 함수 사용자는 키 자체가 빠진 상태와 값이 없는 상태를 구분하지 않고 일정한 사전 구조를 받을 수 있습니다.

7주의할 점과 실무 메모

  • robots.txt 허용은 법적 이용 허가가 아닙니다. 대상 사이트의 이용 약관, 저작권·데이터베이스 권리, 개인정보 처리 조건을 주소별로 확인합니다.
  • 로그인, 접근 통제, CAPTCHA를 우회하지 않습니다. 접근 제한이 있으면 공식 API나 데이터 제공 경로를 찾습니다.
  • 요청 간격과 동시 요청 수를 제한하고 서비스의 rate limit을 따릅니다. 이 노트북은 외부 사이트에 요청하지 않습니다.
  • 선택자가 바뀌었을 때 빈 값을 계속 저장하지 않도록 필수 필드 누락을 검사하고 원문 URL과 수집 시각을 기록합니다.
  • 기사 전문을 저장하거나 재배포하기 전에 필요한 범위와 권리를 검토합니다.

8정리와 다음 절

  • 파서는 HTML 문자열을 요소 트리로 바꿉니다.
  • 선택 결과의 존재를 확인해 반환 구조를 일정하게 유지합니다.
  • robots.txt와 이용 조건·권리·개인정보·호출 제한은 서로 다른 확인 항목입니다.

다음 학습과 이어지는 지점 — 추출한 제목과 요약은 data/article-text.json에 원본 경로와 함께 보존되며, Ch 5 01절이 이 파일을 직접 읽어 토큰 수를 측정합니다. Ch 19에서는 세 가지 조회 함수를 도구로 등록하되 스크래핑 정책 검사는 함수 바깥의 운영 규칙으로도 유지합니다.

9복습 문제

문제와 해설

1. .summary 선택자는 무엇을 고르나요?

정답 class 속성에 summary가 있는 요소를 고릅니다.

2. 없는 subtitle에 바로 get_text()를 호출하면 왜 실패하나요?

정답 select_one이 요소 대신 None을 반환하고 None에는 해당 메서드가 없기 때문입니다.

3. robots.txt에서 허용된 경로의 콘텐츠는 자유롭게 재배포해도 되나요?

정답 아닙니다. robots.txt는 크롤러 접근 경로 규칙이며 이용 약관과 저작권을 별도로 확인해야 합니다.

4. 날짜를 화면 문자열 대신 datetime 속성에서 읽는 이유는 무엇인가요?

정답 표시 문구와 분리된 일정한 기계 판독 형식을 얻기 위해서입니다.
