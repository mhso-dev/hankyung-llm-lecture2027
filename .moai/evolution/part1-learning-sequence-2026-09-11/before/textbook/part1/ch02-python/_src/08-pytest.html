1학습 목표

  • pytest 테스트 함수를 작성하고 현재 Python 환경에서 실행할 수 있습니다.
  • 매개변수화로 같은 검사 규칙을 여러 입력에 적용할 수 있습니다.
  • 실제 결함이 있을 때 실패하는 테스트를 확인하고, 구현 수정 뒤 같은 테스트가 통과하는지 검증할 수 있습니다.

2이 내용을 배우는 이유

함수를 수정한 직후 한 번 출력해 보는 것만으로는 다음 수정에서도 같은 동작이 유지되는지 알기 어렵습니다. 테스트는 입력과 기대 결과를 코드로 기록하고 필요할 때 다시 실행합니다. 가격 계산처럼 숫자 하나가 달라져도 중요한 기능에서는 사람이 매번 출력 전체를 비교하는 작업을 줄여 줍니다.

좋은 테스트는 결함이 있을 때 실제로 실패하고, 원인을 고친 뒤 통과합니다. 처음부터 통과만 한 테스트로는 잘못된 구현을 구별할 수 있는지 알 수 없습니다. 이번 절에서는 10% 할인 결과에 100원을 잘못 더하는 결함을 준비합니다. 기대값 9,000원은 유지하고 구현만 수정하여 빨간 실패와 초록 통과를 모두 관찰합니다.

3앞에서 배운 내용

04절에서 반환값을 단언문으로 확인했고, 07절에서 타입힌트가 런타임 검증을 대신하지 않는다는 점을 확인했습니다. pytest도 assert를 사용하지만 여러 테스트를 찾아 실행하고 실패한 식을 자세히 보여 줍니다. 노트북은 별도 모듈이나 개인 폴더에 의존하지 않습니다. 임시 폴더 안에 각 테스트 파일을 작성하고 현재 커널의 Python으로 pytest를 실행합니다.

4핵심 개념

쉬운 예

계산기를 고친 뒤 1+1만 눌러 보는 것으로 모든 계산이 맞다고 말할 수 없습니다. 덧셈, 0, 여러 수량처럼 중요한 사례를 미리 적고 같은 방식으로 반복 확인해야 합니다. 테스트 케이스(test case)는 하나의 입력, 실행, 기대 결과를 묶은 검사 사례입니다. pytest는 이름이 test_로 시작하는 함수와 파일을 찾아 실행합니다.

정의

단언(assertion)은 조건이 참이어야 한다고 명시하는 문장입니다. 조건이 거짓이면 테스트가 실패합니다. 종료 코드(exit code)는 프로세스가 운영체제에 알리는 결과 숫자입니다. pytest의 이번 실행에서 0은 통과, 1은 테스트 실패를 뜻합니다. 다른 실행 오류에는 다른 코드가 사용될 수 있으므로 출력과 함께 읽습니다.

매개변수화(parametrization)는 하나의 테스트 함수에 여러 입력과 기대값 묶음을 제공하는 기능입니다. 같은 곱셈 규칙을 세 사례에 적용하면 검사 코드 중복을 줄이면서 어느 입력이 실패했는지 구분할 수 있습니다. 회귀 테스트(regression test)는 고친 결함이 이후 변경에서 다시 생기지 않는지 확인하도록 남긴 테스트입니다. 픽스처(fixture)는 테스트가 요청하는 준비 값을 제공하는 pytest 기능이며, 이 절에서는 개념만 연결하고 11절에서 테스트 격리와 함께 다룹니다.

5실행 예제

첫 셀은 현재 노트북 커널에 pytest 9.1.1을 설치합니다. 실행 함수는 sys.executable -m pytest 형식을 사용하여 노트북과 같은 Python 환경에서 pytest를 시작합니다. 플러그인 자동 로드를 끄는 환경 변수를 하위 프로세스에만 전달하므로 개인 환경에 설치된 pytest 플러그인이 실습 결과에 영향을 줄 가능성을 낮춥니다.

기본 테스트 파일의 test_total()은 1,200과 800의 합이 2,000인지 검사합니다. 이어서 매개변수화된 test_line_total()은 가격, 수량, 기대값 세 묶음을 받습니다. 출력의 점 세 개와 3 passed가 세 사례의 통과를 나타냅니다. 값 하나 비교에서는 같은 테스트 함수에 (900, 3, 2700) 한 사례만 추가합니다. 출력이 4 passed로 바뀌는지 확인합니다.

6일부러 실패해 보기

Before의 discounted()는 가격의 90%를 계산한 뒤 100원을 추가합니다. 테스트 입력은 10,000원이고 기대값은 9,000원입니다. 실제값 9,100원이 기대값과 다르므로 pytest는 비교식을 보여 주고 1 failed, 종료 코드 1을 반환합니다. 의도한 실패가 발생했는지 노트북의 단언문으로 다시 확인합니다.

After는 함수에서 + 100만 제거합니다. 테스트 함수, 입력, 기대값은 바꾸지 않습니다. 같은 테스트 파일을 다시 실행하면 1 passed와 종료 코드 0이 나타납니다. 이 테스트를 프로젝트에 남기면 이후 할인 계산을 수정했을 때 같은 결함이 다시 나타나는지 확인할 수 있습니다. 한 입력의 통과는 모든 가격과 할인 정책을 보장하지 않으므로 경계값과 반올림 규칙은 요구사항에 맞춰 추가해야 합니다.

7주의할 점과 실무 메모

  • 테스트를 통과시키려고 기대값을 현재의 잘못된 출력으로 바꾸면 결함을 고친 것이 아닙니다. 요구사항의 기대값을 유지하고 구현을 수정합니다.
  • 한 테스트에 여러 원인을 넣으면 실패 위치를 해석하기 어렵습니다. 테스트 이름과 입력이 확인하려는 행동 하나를 분명히 나타내게 작성합니다.
  • 실수 계산과 금액 반올림은 정책에 따라 결과가 달라질 수 있습니다. 이번 int(price * 0.9) 예제만으로 실제 결제 정책을 결정할 수 없습니다.
  • pytest 9.1.1과 Python 3.12에서 실행한 결과입니다. 프로젝트의 고정 버전을 잠금 파일과 함께 관리해야 팀원도 같은 조건을 재현할 수 있습니다.

8정리와 다음 절

  • pytest는 test_ 이름의 테스트를 실행하고 단언 실패를 구체적으로 보여 줍니다.
  • 매개변수화는 같은 검사 규칙을 여러 입력에 적용합니다.
  • 결함이 있을 때 실패하고 수정 뒤 통과한 테스트는 이후 변경을 확인하는 근거가 됩니다.

9복습 문제

문제와 해설

1. pytest가 기본적으로 테스트 함수로 찾기 쉬운 이름은 어떤 형태인가요?

정답 test_로 시작하는 함수 이름입니다. 이 절에서는 test_total()과 test_discounted()를 사용합니다.

2. 매개변수화 전후 출력이 3 passed와 4 passed로 바뀐 이유는 무엇인가요?

정답 같은 테스트 함수에 입력과 기대값 묶음 한 개를 추가했기 때문입니다. 실행 함수는 해당 파일만 대상으로 지정합니다.

3. Before에서 종료 코드 1을 성공적으로 관찰했다고 말할 수 있는 이유는 무엇인가요?

정답 기대값 9,000원과 실제값 9,100원이 달라 실제 테스트가 실패했고, 노트북은 반환 코드가 1인지 확인했기 때문입니다.

4. After에서 테스트의 기대값을 9,100원으로 바꾸지 않은 이유는 무엇인가요?

정답 요구사항은 10% 할인 결과 9,000원이며 결함은 구현의 추가 100원입니다. 기대값을 바꾸면 잘못된 동작을 승인하게 됩니다.
