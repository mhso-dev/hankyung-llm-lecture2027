# Ch 1 작성자 개정 기록

검토 범위는 `textbook/part1/ch01-development-environment/_src/`의 다섯 절과 대응하는 노트북 다섯 개입니다. 기존 코드 셀과 출력은 변경하지 않았습니다. 이번 개정은 처음 개발하는 학습자가 준비 코드의 역할을 모른 채 다음 셀로 넘어가는 문제를 보완합니다. 교육적 완료 여부는 별도 검토자가 다시 판정해야 합니다.

## 01 과정 지도와 학습 규칙

- 발견 문제: 본문은 프로그램·입력·출력·셀을 정의했지만, 첫 노트북 셀의 `import sys`, 버전 정보 선택, 튜플 비교, 불리언 결과를 실행 전에 풀어 설명하지 않았습니다. 대입, f 문자열, `assert`도 한 문장으로 지나가 Ch 2 문법을 이미 아는 독자에게 유리했습니다.
- 선수 개념: 프로그램과 코드의 관계, 노트북 셀과 커널, 이름에 값 저장, 함수 호출의 괄호, 참과 거짓을 뜻하는 `True`·`False`입니다. 이 문법을 배웠다고 가정하지 않고 Ch 2에서 자세히 배울 준비 코드로 설명했습니다.
- 수정 위치: HTML 5번 실행 예제 앞에 `sys.version_info[:2]`, `== (3, 12)`, 대입, f 문자열, `print`, `assert`의 입력·결과를 추가했습니다. 노트북의 도입, 환경 확인, 예상, 실행 마크다운을 같은 순서로 보강했습니다.
- 관찰 결과: 기존 출력은 `Python 3.12: True`, 예상·실행 합계 6000원, 수량 변경 뒤 9000원입니다. 코드와 출력은 보존했습니다.

## 02 도구 설치와 터미널

- 발견 문제: 터미널·셸·현재 작업 폴더·절대/상대 경로 정의는 있었지만, 노트북의 `Path` 객체, 함수 인자와 반환값, 경로 결합의 `/`, 메서드 호출, 문자 인코딩, `try/except/else`가 주석 수준에 머물렀습니다.
- 선수 개념: 파일과 폴더의 포함 관계, 경로는 위치를 나타내는 값이라는 점, 함수 호출의 괄호와 인자, 호출 결과를 이름에 저장하는 순서입니다.
- 수정 위치: HTML 5번에 가져오기, 호출, 인자, 반환값, 경로 표현과 실제 폴더 생성의 차이, `write_text`·`read_text`·`is_file`을 설명했습니다. 6번에는 경로 읽기 실패를 포착하는 구조를 설명했습니다. 노트북의 각 마크다운 셀도 코드 바로 앞에서 같은 내용을 한 줄씩 따라가도록 보강했습니다.
- 관찰 결과: 올바른 기준에서는 `안녕, 터미널!`을 읽고, 잘못된 기준에서는 실제 `FileNotFoundError`가 발생하며, 기준을 `project`로 고치면 같은 내용을 다시 읽습니다. 코드와 출력은 보존했습니다.

## 03 Python과 가상환경

- 발견 문제: 인터프리터·패키지·가상환경·커널 정의는 있었지만, 설치와 `import`의 차이, 표준 라이브러리, `shutil.which`의 반환값, `subprocess.run`의 명령 목록과 옵션, 운영체제 분기, `sys.prefix` 비교를 충분히 연결하지 않았습니다.
- 선수 개념: Python 인터프리터가 코드를 실행한다는 점, 노트북 커널이 상태를 기억한다는 점, 프로젝트별로 실행 위치와 패키지 설치 위치를 구분하는 이유입니다.
- 수정 위치: HTML 5번에 표준 라이브러리와 제삼자 패키지, 명령 탐색, `None`, 외부 명령의 인자·반환·출력, 운영체제별 실행 파일, `prefix` 비교를 추가했습니다. 노트북의 모든 설명 셀을 실행 순서에 맞춰 보강했습니다.
- 관찰 결과: 두 환경 모두 가상환경 내부이며 환경 A와 B의 위치가 다르다는 `True` 출력을 확인합니다. 제삼자 패키지 충돌은 실행하지 않았다는 해석 범위를 유지했습니다. 코드와 출력은 보존했습니다.

## 04 첫 스크립트와 디버거

- 발견 문제: 화면 디버깅 절차는 자세했지만, 노트북이 임시 파일을 만드는 시점, 여러 줄 문자열, `subprocess.run` 반환 객체, `stdout.strip()`, `int`, pdb 명령, 출력 정리 목록을 이미 아는 문법처럼 사용했습니다.
- 선수 개념: 스크립트는 `.py` 파일에 저장한 코드라는 점, 경로를 정하는 일과 파일을 만드는 일의 차이, 다른 Python 파일을 별도 실행하면 출력이 문자열로 반환된다는 점입니다.
- 수정 위치: HTML 5번에 임시 경로, 파일 생성, 여러 줄 문자열, 별도 실행과 문자열→정수 변환을 추가했습니다. 6번에는 pdb 명령과 출력 정리 코드의 목적을 추가했습니다. 노트북 도입·환경·기본 실행·Before·디버거·결과 해석 마크다운을 보강했습니다.
- 관찰 결과: 같은 입력에서 덧셈은 3002원, 디버거 관찰값은 3000·2·3002, 곱셈 수정 뒤 결과는 6000원입니다. 코드와 출력은 보존했습니다.

## 05 Git과 Docker 준비

- 발견 문제: Git·GitHub, Docker 클라이언트·데몬 정의는 있었지만, 첫 셀부터 사용하는 `which`, `None`, 조건문, `returncode`, `cwd`, Git의 추적 상태, 시간 제한과 예외 처리를 실행 전에 충분히 설명하지 않았습니다.
- 선수 개념: 터미널 명령은 실행 파일과 인자의 순서로 구성된다는 점, 명령을 찾은 상태와 성공한 상태의 차이, 저장소·추적·커밋·원격 전송은 서로 다른 단계라는 점입니다.
- 수정 위치: HTML 5번에 명령 탐색, 인자 목록, 반환 코드, 조건 분기, 현재 작업 폴더 지정의 역할을 추가했습니다. 노트북의 도입과 Git 버전·저장소·새 파일·Docker 클라이언트·데몬·종합 결과 설명을 각 코드 셀 앞에서 보강했습니다.
- 관찰 결과: 검증 환경에서는 Git 파일 생성 전 상태가 비어 있고 생성 뒤 `?? hello.py`가 나타났습니다. Docker 클라이언트와 서버는 각각 별도 `True` 결과로 확인됩니다. 이미지 내려받기나 컨테이너 실행까지 확인한 것으로 확대하지 않았습니다. 코드와 출력은 보존했습니다.
