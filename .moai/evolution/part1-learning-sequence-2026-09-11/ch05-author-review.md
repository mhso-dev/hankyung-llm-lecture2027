## 독립 리뷰 S1 반영과 최종 재검증

- 01절: 준비 파일을 찾는 generator expression을 `for` 반복문, `break`, 미발견 오류로 풀었습니다. `from_pretrained()`의 모델 ID·revision 입력, tokenizer 반환, `vocab_size` 의미와 어휘 크기만으로 한국어 효율을 판단할 수 없다는 범위를 코드 전에 설명했습니다. 두 토큰화기가 문장을 각각 39개와 9개의 토큰으로 나눈다는 문장으로 주술 관계도 바로잡았습니다.
- 02절: `axis=1`, `keepdims=True`, `ravel()`, `vectors.T`, `@`, `np.argsort(-scores[0])`, `[1:]`의 입력·처리·반환을 코드 전에 연결했습니다. 자기 비교 제외는 현재 0번 기준 표본에서 인덱스 0을 명시적으로 제외하는 동작으로 한정했습니다.
- 03절: 여섯 조각이 실제 tokenizer 출력이 아닌 설명용 토큰이라는 점을 명시했습니다. 수동 가중치는 질문 B에서 `B는=0.30`, `빨간색입니다=0.45`, 질문 A에서 `A는=0.30`, `파란색이고=0.45`가 되도록 대상과 색상 관계에 맞췄습니다. `{token:12}`, `{weight:.2f}`, `int(weight * 20)`의 출력 표기를 코드 전에 설명했습니다.
- 04절: 사전 컴프리헨션을 명시적 `for`와 대입으로 바꿨습니다. `IProgress` 관련 비핵심 경고는 모델 import 전에 제한적으로 억제했습니다.
- 05절: 출력 목록과 적중 수 계산, 구조 검증의 generator expression을 명시적 `for`, `append`, 누적 변수로 바꿨습니다. `model.config.max_position_embeddings`의 실제 출력 32,768과 가장 긴 조건 `1,201 + 20 <= 32,768: True`를 노트북 출력과 검증 assertion으로 남겼습니다.
- 06절: 로짓·softmax·확률 최소 예제를 모델 준비 직후, 전체 생성 도우미 정의 전에 배치했습니다. 도우미의 프롬프트·temperature·seed·최대 생성 수 입력, `return_tensors`, `pad_token_id`, 입력 부분 제외, `decode()`의 역할과 문자열 반환을 호출 전에 설명했습니다. 후보 표현은 후보 토큰으로 통일했고 목록·집합 컴프리헨션을 명시적 반복문으로 바꿨습니다. 첫 배치 시도에서는 로짓 셀이 모델 준비 코드보다 먼저 놓여 `torch` 미정의로 실패했으며, 삽입 위치를 수정한 뒤 새 커널 실행을 통과했습니다.
- 07절: 웹·사내 데이터베이스를 자동 조회하지 않는다는 설명을 이 절의 로컬 모델로 한정했습니다. 출력에서 기관·제도 이름과 지원 절차에서 볼 법한 표현이 나타났다는 관찰만 적고, 어떤 내부 계산이나 학습 자료가 영향을 줬는지는 이 실험으로 알 수 없다고 수정했습니다.
- 08절: 후보 필터를 `for`, 두 불리언 비교, `and`, `append()`로 풀고 자체 질의셋을 서비스 대표 질문과 질문별 정답 기준을 모은 평가 자료로 정의했습니다. 양자화·워밍업·순전파·스트리밍·상위 백분위수 같은 처음 나온 고급 용어는 수치 저장 정밀도, 첫 실행과 준비 후 실행, 입력 계산과 새 토큰 생성, 생성 중인 답 전송, 정렬한 측정값의 느린 사례로 풀었습니다. `IProgress` 관련 비핵심 경고도 제한적으로 억제했습니다.
- 생성기 동기화: `CH05_NOTEBOOK_OUT` 임시 출력과 실제 8개 노트북의 셀 종류·셀 소스를 비교해 모두 일치함을 확인했습니다. 실제 노트북에는 셀만 병합했고 기존 `metadata.verification`을 병합 전후 assertion으로 보존했습니다. 그 뒤 공통 `textbook/_notebook/execute.py`가 새 검증 기록과 출력을 생성했습니다.
- 최종 실행 검증: Python 3.12 새 커널에서 01–08절이 각각 5, 5, 3, 4, 4, 6, 5, 4개 코드 셀로 PASS했습니다. 이어서 `textbook/_notebook/render.py`의 `validate()`를 8개 모두 직접 호출해 `status=passed`, `fresh_kernel=true`, 코드·출력 해시, 순차 실행 번호를 확인했습니다. 08절 최종 환경 의존 출력은 캐시 로딩 0.39초와 1,202토큰 토큰화 1.791밀리초이며 본문 수치를 일치시켰습니다.

## 최종 통합 재검토 4건

- 01절의 파일 탐색에서 별표 풀기를 제거했습니다. 현재 폴더를 `search_paths`에 넣고 부모 폴더를 `for`로 순회해 `append()`한 뒤, 두 번째 `for`가 파일을 찾는 순서를 독립 노트북의 코드 직전 마크다운에 설명했습니다.
- 02절 독립 노트북에서 벡터를 순서가 있는 숫자 목록으로 정의하고, `nearest.tolist()`가 NumPy 배열을 Python 목록으로 바꾸는 역할을 코드 직전에 추가했습니다.
- 03절 독립 노트북에서 '가중치의 읽는 법'을 '가중치를 읽는 법'으로 고쳤습니다. `{token:12}`, `{weight:.2f}`, `"■" * int(weight * 20)`의 표시 규칙을 첫 코드 셀 전에 설명하고 제목의 '바뀍니다'를 '바뀝니다'로 고쳤습니다.
- 04절 독립 노트북에서 `parts` 사전, `messages` 사전 목록, `role`·`content`, `system` 지시, `user` 문서·질문, `add_generation_prompt=True`의 답 시작 표시 추가를 첫 코드 셀 전에 설명했습니다.
- 05절은 06절보다 먼저 temperature·seed·top-p를 사용하지 않도록 결정적 생성 전용 준비 함수로 분리했습니다. 함수 입력은 프롬프트와 최대 생성 토큰 수이며 `do_sample=False`와 `pad_token_id`만 생성 옵션으로 사용합니다. 조건 준비와 아홉 조건 실행을 각각 15줄과 17줄 코드 셀로 나눴고, 두 번의 호출은 `for _ in [1, 2]`로 표현해 횟수 값 자체를 사용하지 않는다는 점을 설명했습니다. 재실행 출력은 이전과 같았습니다.
- 06절 독립 노트북의 로짓 최소 예제 직전에 `torch.tensor()`가 1차원 PyTorch 숫자 배열을 만들고 `dim=0`이 현재 후보 축 전체에 softmax를 적용한다는 뜻을 추가했습니다.
- 새 커널 전체 재실행 결과 01–08절이 PASS했으며 05절 코드 셀은 15·14·15·17·11줄로 모두 25줄 이하입니다. 08절 환경 의존 출력은 캐시 로딩 0.384초와 1,202토큰 토큰화 3.631밀리초로 바뀌어 본문 수치를 맞췄습니다.
- 07절 최종 재검토에서는 두 질문의 응답 유형이 다르게 나타났다는 관찰만 남기고, 그 차이가 어떤 학습 자료나 내부 계산에서 비롯됐는지는 알 수 없다고 한정했습니다. 독립 노트북에는 해당 내부 원인 주장이 없음을 함께 검색했습니다.
