1학습 목표

  • 클래스와 인스턴스의 관계를 주문 예제로 설명할 수 있습니다.
  • __init__과 self를 사용하여 객체마다 다른 상태를 저장할 수 있습니다.
  • 가변 클래스 속성이 여러 인스턴스에 공유되는 문제를 재현하고 수정할 수 있습니다.

2이 내용을 배우는 이유

주문 한 건에는 고객명, 품목 목록, 품목을 추가하는 행동이 함께 필요합니다. 사전과 함수만으로도 표현할 수 있지만 주문 수가 늘면 어느 데이터와 함수가 한 묶음인지 계속 확인해야 합니다. 클래스는 관련 데이터와 동작을 하나의 새 유형으로 정의합니다. 같은 설계로 민지 주문과 준호 주문을 만들되, 각 주문의 내용은 따로 보관할 수 있습니다.

클래스를 처음 사용할 때 자주 생기는 문제는 가변 목록을 클래스 자체에 두는 것입니다. 그러면 한 주문에 품목을 추가했는데 다른 주문에도 같은 품목이 나타납니다. 이번 절은 이 잘못된 결과를 실제로 확인하고, 목록 생성 위치를 __init__으로 옮겨 상태를 분리합니다. 객체별 상태 분리는 이후 설정 객체, 문서 객체, 테스트 준비 데이터를 이해하는 기반이 됩니다.

3앞에서 배운 내용

03절에서 목록은 내용을 변경할 수 있는 자료구조라고 배웠습니다. 04절에서는 함수의 매개변수와 반환값을 작성했습니다. 이번 절의 Order.add()도 문자열 하나를 받아 현재 객체의 목록을 변경하는 함수입니다. 별도 값을 반환하지 않고 객체의 상태를 바꿉니다. 타입 힌트는 07절에서 배우므로 이번 코드에는 사용하지 않습니다. 05절에서 파일의 주문 한 줄을 튜플로 바꾸었다면, 이제 주문과 관련된 값과 행동을 한 클래스 안에 배치합니다.

4핵심 개념

쉬운 예

같은 주문서 양식을 여러 장 인쇄한다고 생각해 봅니다. 양식의 항목과 작성 규칙은 같지만 각 장에 적힌 고객과 품목은 서로 다릅니다. 클래스(class)는 주문서 양식에 해당하고, 인스턴스(instance)는 그 양식으로 만든 개별 주문서입니다. 인스턴스를 새로 만들 때마다 빈 품목 목록을 준비하면 각 주문서의 기록이 섞이지 않습니다.

정의

class Order:는 Order라는 새 객체 유형의 정의를 시작합니다. 콜론 다음에 들여쓴 함수들이 클래스에 속합니다. Order("민지")처럼 클래스 이름을 호출하면 새 인스턴스가 만들어지고 초기화 메서드(initializer) __init__이 자동으로 실행됩니다. 호출의 문자열은 customer 매개변수로 들어가고, self에는 Python이 새 인스턴스를 전달합니다.

속성(attribute)은 객체에 저장된 이름과 값입니다. self.customer = customer는 입력받은 고객명을 현재 인스턴스의 속성에 저장합니다. 점 왼쪽은 객체이고 점 오른쪽은 그 객체에서 찾을 속성이나 메서드입니다. 메서드(method)는 클래스 안에 정의되어 객체의 상태를 읽거나 바꾸는 함수입니다. first.add("노트")를 호출하면 first가 self로, "노트"가 item으로 전달됩니다.

인스턴스 속성은 self.items처럼 각 인스턴스에 저장됩니다. 클래스 속성은 클래스 본문에 정의되어 기본적으로 모든 인스턴스가 함께 참조합니다. 숫자나 고정 문자열 같은 공통 설정에는 클래스 속성을 사용할 수 있지만, 내용이 바뀌는 목록을 그곳에 두면 여러 객체가 같은 목록을 수정합니다. is는 두 목록의 내용이 같은지가 아니라 두 속성이 같은 객체를 가리키는지 검사합니다.

5실행 예제

Order("민지")의 입력은 고객명 문자열입니다. 호출하면 새 인스턴스가 만들어지고 __init__이 고객명과 새 빈 목록을 속성으로 저장합니다. 생성된 객체가 first에 반환됩니다. 이어서 first.add("노트")를 호출하면 입력 문자열을 현재 객체의 목록 끝에 추가합니다. 이 메서드는 별도 계산값을 반환하지 않고 객체의 상태를 변경합니다.

두 번째 호출 Order("준호")는 다른 인스턴스와 새 목록을 만듭니다. first.items is second.items가 False이면 두 속성이 서로 다른 목록 객체를 가리킵니다. 이후 민지 주문에만 지우개를 입력합니다. 준호 주문이 ['연필']로 유지되는지 단언문으로 확인합니다. 고객명 값의 차이와 목록 객체의 분리를 구분해서 읽습니다.

6일부러 실패해 보기

Before의 SharedOrder는 items를 클래스 본문에 둡니다. bad_first와 bad_second를 만들었지만 둘 다 같은 클래스 속성 목록을 참조합니다. 첫 주문에 노트를 추가한 뒤 두 번째 주문을 출력하면 ['노트']가 나타납니다. 프로그램은 예외 없이 실행되지만 주문 데이터가 섞인 잘못된 결과입니다.

After의 IsolatedOrder는 목록을 __init__ 안에서 self.items = []로 만듭니다. 인스턴스가 만들어질 때마다 새 목록 표현식이 평가됩니다. 같은 두 인스턴스를 만들고 첫 주문에 같은 품목을 추가해도 두 번째 주문은 빈 목록입니다. 비교에서는 품목, 인스턴스 수, 변경 순서를 유지하고 목록이 만들어지는 위치만 바꾸었습니다.

7주의할 점과 실무 메모

  • self라는 이름은 관례이며 메서드 정의에서 직접 적어야 합니다. 호출할 때는 Python이 현재 인스턴스를 첫 인자로 전달합니다.
  • 클래스 속성이 항상 잘못된 것은 아닙니다. 모든 주문이 공유하는 고정 통화 코드처럼 공통값을 표현할 수 있습니다. 변경 가능한 데이터의 공유 여부를 의도적으로 결정해야 합니다.
  • add()가 내부 목록을 변경하므로 호출 전후에 같은 객체의 상태가 달라집니다. 상태 변경이 필요한지, 새 값을 반환하는 편이 나은지는 프로그램 요구사항에 따라 판단합니다.
  • 이번 절은 생성자, 속성, 메서드에 집중합니다. 상속은 여러 유형 사이에 실제 공통 관계가 필요할 때 별도로 학습합니다.

8정리와 다음 절

  • 클래스는 관련 데이터와 동작을 묶은 새 객체 유형을 정의합니다.
  • __init__에서 만든 인스턴스 속성은 객체마다 다른 상태를 저장합니다.
  • 변경 가능한 클래스 속성은 모든 인스턴스가 공유할 수 있으므로 사용 의도를 확인해야 합니다.

9복습 문제

문제와 해설

1. 클래스와 인스턴스의 차이를 주문 예제로 설명해 보세요.

정답 클래스는 고객명과 품목 처리 방식을 정의한 설계이고, 인스턴스는 그 설계로 만든 민지 주문이나 준호 주문 같은 개별 객체입니다.

2. __init__에서 self.items = []를 실행하는 이유는 무엇인가요?

정답 새 인스턴스마다 별도의 빈 목록을 만들어 주문 상태가 다른 인스턴스와 섞이지 않게 하기 위해서입니다.

3. first.items is second.items가 False라는 결과는 무엇을 보여 주나요?

정답 두 속성의 내용 비교가 아니라 두 인스턴스가 서로 다른 목록 객체를 참조한다는 것을 보여 줍니다.

4. 모든 인스턴스가 공유해도 되는 클래스 속성의 예를 하나 들어 보세요.

정답 모든 주문에 공통인 통화 코드 currency = "KRW"를 예로 들 수 있습니다. 실행 중 변경할 필요가 없는 공통값이라는 조건도 함께 확인해야 합니다.
