1학습 목표

  • HTTP 요청과 JSON 응답에서 상태 코드와 본문을 확인할 수 있습니다.
  • 다음 페이지 값이 없어질 때까지 REST 결과를 수집할 수 있습니다.
  • 시간 제한과 상태 코드 검사를 포함한 조회 함수를 작성할 수 있습니다.

2이 내용을 배우는 이유

기사, 상품, 업무 시스템의 데이터는 파일이나 데이터베이스 대신 HTTP API로 제공되기도 합니다. 한 번의 요청으로 모든 결과를 반환하면 응답이 너무 커질 수 있어 서버는 여러 페이지로 나눕니다. 첫 페이지만 읽는 함수는 정상 응답을 받더라도 뒤쪽 데이터를 빠뜨립니다. 에이전트 도구가 이 함수를 사용하면 모델은 누락 사실을 알기 어렵습니다.

이번 실습은 외부 사업자의 실제 API 동작을 그대로 재현하지 않습니다. Python의 HTTP 서버를 localhost 임의 포트에서 실행하고 httpx가 실제 TCP·HTTP 요청을 보냅니다. 네트워크 요청, 쿼리 매개변수, 상태 코드, JSON 변환, 페이지 종료를 재현하면서 외부 서비스의 변경과 비용 없이 결과를 고정합니다.

3앞에서 배운 내용

앞 절에서 함수 입력과 데이터 조회를 분리하고 조회 결과를 사전 목록으로 반환했습니다. Ch 2의 05절에서는 예외 처리를 확인했습니다. async/await은 아직 선수 개념으로 사용하지 않습니다. 이번 절은 코드가 한 요청의 응답을 받은 뒤 다음 요청을 보내는 동기 httpx.Client 흐름에 집중합니다. 비동기 클라이언트는 Ch 30의 실행 환경에서 다룹니다.

4핵심 개념

요청과 응답을 한 쌍으로 읽습니다

HTTP 요청(request)은 클라이언트가 서버에 보내는 메시지입니다. 요청에는 주소(URL), 작업을 나타내는 메서드, 추가 조건, 필요하면 본문이 들어갑니다. HTTP 응답(response)은 서버가 반환하는 메시지이며 상태 코드, 헤더, 본문으로 구성됩니다. 이 절의 클라이언트는 GET /articles?page=1을 요청하고 서버는 상태 코드 200, JSON이라는 본문 형식을 알리는 헤더, 기사 목록이 든 본문을 반환합니다.

JSON(JavaScript Object Notation)은 문자열·숫자·참과 거짓·null·배열·객체를 텍스트로 표현하는 형식입니다. HTTPX의 response.json()은 JSON 본문을 Python의 사전과 목록으로 변환합니다. JSON의 null은 Python에서 None이 됩니다.

페이지를 하나씩 이어서 요청합니다

페이지네이션(pagination)은 큰 결과를 여러 응답으로 나누는 방식입니다. 첫 응답에는 기사 두 건과 다음 페이지 2가 들어 있습니다. 함수는 현재 페이지를 요청 입력으로 보내고, 응답의 기사 목록을 누적한 뒤, next_page를 다음 요청 입력으로 바꿉니다. 두 번째 응답의 next_page가 None이면 반복을 마치고 누적한 목록을 반환합니다. 구현마다 페이지 번호, 커서, 다음 링크를 사용할 수 있으므로 API 문서를 확인해야 합니다.

REST와 실패 처리를 구분합니다

REST API는 HTTP의 주소, 메서드, 상태 코드와 표현 형식을 사용해 자원을 다루는 인터페이스입니다. 이 절은 GET 요청으로 기사 목록을 읽습니다. 시간 제한(timeout)은 응답을 무한히 기다리지 않도록 대기 한도를 정합니다. raise_for_status()는 4xx·5xx 응답을 성공 데이터처럼 처리하지 않고 예외로 바꿉니다.

5실행 예제

노트북은 ThreadingHTTPServer를 127.0.0.1의 사용 가능한 포트에서 실행합니다. 이것은 인터넷의 외부 API 대신 같은 HTTP 규칙으로 응답하는 로컬 fixture입니다. 첫 요청의 params={"page": 1}은 주소 뒤에 ?page=1이라는 쿼리 매개변수를 만듭니다. timeout=2.0은 최대 대기 시간을 초 단위로 지정합니다. 반환된 response에서 raise_for_status()로 상태를 검사한 다음 json()으로 본문을 변환합니다.

fetch_articles의 입력은 기본 주소, 선택 범주, 시간 제한, 선택적인 HTTP 클라이언트입니다. 반복문은 페이지 번호를 요청하고, 응답을 검사하고, items를 누적하고, next_page로 상태를 갱신합니다. 반환값은 모든 페이지에서 모은 기사 사전의 목록입니다. 범주를 전달하면 모든 페이지를 수집한 뒤 해당 범주의 기사만 남깁니다. 방문한 페이지를 seen 집합에 저장하므로 서버가 같은 페이지를 계속 안내하는 잘못된 응답도 감지합니다.

6일부러 실패해 보기

Before 함수는 page=1을 한 번만 요청해 A01과 A02를 반환합니다. HTTP 요청과 JSON 변환은 성공하지만 A03이 누락됩니다. After 함수는 현재 페이지를 변수로 두고 next_page가 None이 될 때까지 반복합니다. 각 응답에서 상태를 검사하고 기사 목록을 누적하여 A01, A02, A03을 모두 반환합니다. 방문한 페이지 번호를 집합에 기록하므로 서버가 같은 next_page를 반복하면 ValueError로 종료합니다. 마지막에는 서버를 종료해 포트와 스레드를 정리합니다.

7주의할 점과 실무 메모

  • 페이지 종료 규칙은 서비스마다 다릅니다. 빈 목록, 다음 링크 부재, 커서 부재 중 무엇을 사용하는지 공식 문서를 확인합니다.
  • 시간 제한은 연결·읽기 등 단계별로 설정할 수 있습니다. 작업의 응답 시간 요구와 서버 특성에 맞춰 정합니다.
  • 모든 오류를 즉시 재시도하면 서버 장애를 키울 수 있습니다. 재시도할 상태, 횟수, 대기 증가 규칙을 정하고 중복 요청의 영향을 확인합니다.
  • 실제 API의 인증 토큰은 코드나 노트북 출력에 넣지 않고 환경 변수에서 읽습니다.

8정리와 다음 절

  • HTTP 응답은 상태를 확인한 뒤 본문을 해석합니다.
  • 페이지네이션 함수는 다음 값, 정상 종료 조건, 반복 페이지 오류를 모두 처리합니다.
  • 시간 제한과 자원 정리는 조회 함수의 정상 동작에 포함됩니다.

다음 학습과 이어지는 지점 — 다음 절에서는 JSON API가 없는 HTML 문서에서 구조를 읽고 필요한 필드를 추출합니다. 이 절의 fetch_articles는 Ch 19 도구 함수의 세 번째 재사용 예제입니다.

9복습 문제

문제와 해설

1. 첫 페이지만 읽은 함수가 반환한 기사 ID는 무엇인가요?

정답 A01과 A02입니다. A03은 두 번째 페이지에 있어 누락됩니다.

2. raise_for_status()의 역할은 무엇인가요?

정답 4xx·5xx 응답을 정상 데이터로 계속 처리하지 않고 HTTP 상태 오류로 알립니다.

3. 반복문이 끝나는 조건은 무엇인가요?

정답 응답의 next_page가 None이 되는 경우입니다.

4. 로컬 서버 실습으로 확인할 수 없는 실제 운영 조건 하나를 쓰세요.

정답 예 인증, 사업자별 호출량 제한, 외부 네트워크 장애, 실제 응답 스키마 변경 중 하나입니다.
