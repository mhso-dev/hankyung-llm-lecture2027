  • SELECT·JOIN·WHERE·ORDER BY의 역할을 구분할 수 있습니다.
  • SQLite 조회 행을 사전 목록으로 변환하는 함수를 작성할 수 있습니다.
  • 사용자 입력을 SQL 문자열과 분리해 매개변수로 전달할 수 있습니다.

2이 내용을 배우는 이유

표 파일은 학습과 작은 업무에 편리하지만 여러 사용자가 같은 구조를 반복 조회할 때는 데이터베이스가 더 적합합니다. SQL은 어떤 열을 반환하고 어떤 테이블을 연결하며 어떤 조건과 순서로 결과를 만들지 선언합니다. 에이전트 도구의 함수는 자연어 질문 전체를 SQL로 바꾸기 전에 검증된 조건 조회부터 제공하는 편이 안전합니다.

이번 절의 find_customer_orders(database, customer_id)는 데이터베이스 경로와 고객 번호를 입력으로 받고 사전 목록을 반환합니다. Ch 19에서 이 함수를 도구로 등록할 때는 실행 환경에서 데이터베이스 경로를 정하고 모델이 고객 번호를 전달하도록 입력 범위를 설계합니다. 데이터 접근과 답변 생성을 나누면 어느 단계에서 잘못된 값이 생겼는지 찾기 쉬워집니다.

4핵심 개념

요청 문장을 SQL 절로 나눕니다

“고객 C001의 주문 번호, 이름, 금액을 금액이 큰 순서로 주세요”라는 요청에는 네 가지 결정이 들어 있습니다. SELECT는 반환할 열, FROM과 JOIN은 읽고 연결할 테이블, WHERE는 남길 행의 조건, ORDER BY는 반환 순서를 정합니다. SQL은 보통 SELECT → FROM/JOIN → WHERE → ORDER BY → LIMIT 순서로 작성합니다. LIMIT는 최대 몇 행을 반환할지 정하며 이번 함수에는 사용하지 않습니다.

데이터베이스가 개념적으로 처리하는 순서는 작성 순서와 다릅니다. 먼저 FROM/JOIN으로 행의 원천을 만들고, WHERE로 행을 줄인 뒤, SELECT로 반환 열을 정하고, ORDER BY로 정렬하며, 마지막에 LIMIT로 행 수를 제한합니다.

쿼리와 입력값을 분리합니다

SQL(Structured Query Language)은 관계형 데이터베이스의 구조와 데이터를 다루는 언어입니다. 쿼리(query)는 데이터베이스에 보내는 조회 또는 변경 명령입니다. 매개변수 쿼리(parameterized query)는 SQL 문장과 입력값을 분리해 전달합니다. Python sqlite3에서는 물음표 자리표시자와 값 튜플을 사용하므로 입력 전체가 SQL 문법이 아닌 하나의 값으로 처리됩니다.

db.execute(sql, (customer_id,))에서 첫 번째 인자는 SQL 문자열이고 두 번째 인자는 물음표에 대응하는 값의 튜플입니다. 값이 하나뿐이어도 (customer_id,)처럼 쉼표를 써야 한 원소 튜플이 됩니다. 반환되는 커서는 조회 결과를 순회할 수 있는 객체입니다. 행 팩토리(row factory)는 커서가 각 행을 어떤 Python 객체로 만들지 정합니다. sqlite3.Row를 사용하면 열 이름으로 값에 접근할 수 있고 dict(row)로 사전으로 변환할 수 있습니다.

5실행 예제

TemporaryDirectory 안에 orders.db SQLite 파일을 만들고 고객 두 명과 주문 세 건을 준비합니다. find_customer_orders의 입력은 데이터베이스 경로와 고객 번호입니다. 함수는 데이터베이스에 연결하고, JOIN으로 주문의 고객 번호와 고객의 기본 키가 같은 행을 결합하고, WHERE로 입력 고객만 남기고, ORDER BY amount DESC, order_id로 금액 내림차순과 주문 번호 오름차순을 차례로 적용합니다.

c.name AS customer_name의 AS는 결과 열에 새 이름을 붙입니다. 처리 결과의 각 sqlite3.Row를 dict로 바꾸므로 함수는 사전 목록을 반환합니다. C001의 결과는 O101, O103 순서이며 두 행의 customer_name은 김하나입니다. 고객 번호만 C002로 바꾸면 같은 처리에서 O102 한 행을 반환합니다. 입력값과 SQL 구조는 분리되어 있으므로 SQL 문법처럼 보이는 고객 번호도 하나의 문자열 값으로 비교됩니다.

6일부러 실패해 보기

Before는 C001' OR 1=1 --을 문자열 보간으로 SQL에 붙입니다. 입력의 OR 1=1이 조건식으로 해석되어 세 주문이 모두 조회됩니다. 이 결과는 SQL 주입(SQL injection)을 작은 예제로 재현합니다. After는 SQL을 고정하고 입력을 값 튜플로 전달합니다. 같은 문자열 전체가 고객 번호로 비교되므로 일치하는 행이 없습니다. 이어서 부모 고객이 없는 주문도 외래 키 제약으로 거부합니다.

7주의할 점과 실무 메모

  • 값은 매개변수로 전달하지만 테이블명이나 열 이름은 허용 목록에서 고릅니다. 자리표시자는 일반적으로 SQL 식별자를 대신하지 않습니다.
  • 조회 결과가 없다는 사실과 데이터베이스 오류를 같은 빈 목록으로 처리하지 않습니다. 오류는 기록하거나 호출자에게 전달해야 원인을 구분할 수 있습니다.
  • 연결은 작업 뒤 닫아야 합니다. 모듈 함수는 with sqlite3.connect(...)로 연결 범위를 제한합니다.
  • 실제 서비스에서는 읽기 전용 계정, 쿼리 시간 제한, 반환 행 수 제한도 함께 적용합니다.

8정리와 다음 절

  • SQL 절은 반환 열, 연결, 조건, 순서를 각각 명시합니다.
  • 조회 행을 사전 목록으로 변환하면 후속 코드가 열 이름으로 값을 읽을 수 있습니다.
  • 사용자 입력은 SQL 문자열에 붙이지 않고 매개변수로 전달합니다.

9복습 문제

문제와 해설

1. 결과 행을 금액 내림차순으로 정하는 SQL 절은 무엇인가요?

정답 ORDER BY amount DESC입니다.

2. JOIN이 필요한 이유는 무엇인가요?

정답 주문의 고객 번호를 고객 표의 이름과 결합하기 위해서입니다.

3. 입력을 문자열 보간으로 붙였을 때 세 행이 반환된 이유는 무엇인가요?

정답 입력 일부가 SQL 조건식으로 해석되어 OR 1=1이 모든 행에서 참이 되었기 때문입니다.

4. 빈 결과와 실행 오류를 구분해야 하는 이유는 무엇인가요?

정답 조건에 맞는 데이터가 없는 상태와 조회 자체가 실패한 상태는 대응 방법이 다르기 때문입니다.
