1학습 목표

  • 컨텍스트 윈도를 한 번의 처리에서 사용할 수 있는 토큰 범위로 설명합니다.
  • 전체 한도에서 출력 예산을 빼 입력 예산을 계산합니다.
  • 시스템 지시, 문서, 질문이 하나의 입력 예산을 공유함을 설명합니다.

2이 내용을 배우는 이유

모델에 긴 문서를 넣을 때는 '몇 자까지'보다 '몇 토큰까지'를 확인해야 합니다. 입력에는 문서 외에도 시스템 지시, 대화 기록, 사용자 질문, 도구 결과가 들어갑니다. 출력을 생성할 공간도 미리 남겨야 하므로 총 한도와 입력 한도를 구분합니다.

3앞에서 배운 내용

01절에서 토큰화기로 문장의 토큰 수를 세었고, 03절에서는 입력 토큰 사이의 관계를 반영하는 어텐션 직관을 살펴봤습니다. 이 절에서는 Qwen2.5 토큰화기로 시스템, 문서, 질문을 각각 인코딩하고 합계를 구합니다. 현실 모델의 공식 한도를 재현하는 대신 계산 구조를 보이기 위해 512토큰의 실습용 한도를 설정합니다.

4핵심 개념

정의와 관찰

컨텍스트(context)는 모델이 현재 응답을 만들 때 함께 참조하도록 한 입력 전체입니다. 사용자 질문만 뜻하지 않으며 시스템 지시, 앞선 대화, 문서, 도구 결과도 포함합니다. 토큰화기는 이 입력을 토큰 ID 목록으로 바꾸고, 채팅 템플릿(chat template)은 역할 표시와 생성 시작 표시를 덧붙인 모델용 입력을 만듭니다.

컨텍스트 윈도(context window)는 모델이 한 번의 처리에서 참조할 수 있는 토큰 범위입니다. 모델별 공식 한도는 서로 다를 수 있고, 같은 모델이어도 제공 환경의 설정에 따라 달라질 수 있습니다. 한도 안에 들어간다는 말은 모델이 모든 정보를 같은 정확도로 사용한다는 뜻이 아닙니다.

노트북의 첫 계산은 각 문자열을 tokenizer.encode(text)에 넣고 토큰 ID 목록의 길이를 반환받습니다. 다음으로 apply_chat_template(..., tokenize=True)가 세 구성 요소를 실제 대화 형식으로 합친 토큰 ID 목록을 반환합니다. 원시 문자열의 토큰 수 합과 템플릿 적용 뒤의 입력 수가 다른 이유를 이 두 반환값으로 확인합니다.

토큰 예산(token budget)은 제한된 한도를 입력과 출력에 나눠 배정하는 계획입니다. 실습용 한도가 512이고 출력 64개를 예약하면 입력에는 448개가 남습니다. 채팅 템플릿을 적용한 실제 입력이 400개이므로 48개의 여유가 있습니다. 출력을 128개로 늘리면 입력 한도는 384개가 되어 현재 입력이 16개 초과합니다.

시스템 지시와 질문도 토큰을 사용합니다. 실습에서 시스템 지시 12개, 문서 360개, 질문 15개의 raw 텍스트 합계는 387개였습니다. 채팅 템플릿이 역할과 생성 시작 표시를 추가한 실제 입력은 400개였습니다. 예산 판정은 400을 기준으로 하고, 387은 구성 요소별 크기를 읽는 참고값으로 사용합니다.

한도를 넘는 입력은 무조건 뒷부분을 잘라 해결하지 않습니다. 뒷부분에 현재 질문이 있을 수 있고, 앞부분에 전체 작업 규칙이 있을 수 있습니다. 대화 요약, 관련 문서 선택, 중복 제거 등을 사용하되 남겨야 할 정보를 평가 자료로 확인합니다. 이 설계는 Ch 8 컨텍스트 엔지니어링에서 더 구체적으로 배웁니다.

토큰 예산은 정적인 문서 하나만 계산하고 끝나지 않습니다. 대화가 이어지거나 도구 결과가 추가되면 매 요청의 입력 크기가 달라집니다. 요청 전에 토큰 수를 기록하고, 한도에 가까운 요청은 문서 선택과 요약 정책을 적용합니다.

5실행 예제

시스템 지시, 문서, 질문을 각각 토큰화한 합과 채팅 템플릿을 적용한 전체 입력을 비교합니다. 이어서 출력 예약량을 32·64·128로 바꾸고 입력 한도를 계산한 뒤, 문서 반복 횟수별 실제 입력이 448 이하인지 판정합니다.

6실험 결과 해석

채팅 템플릿을 적용하고 문서 문장을 10, 20, 40, 80회 반복했을 때 전체 입력은 220, 400, 760, 1480토큰이었습니다. 실습용 입력 한도 448을 적용하면 10회와 20회는 한도 이하였고 40회와 80회는 한도를 넘었습니다. 이 결과는 토큰화와 예산 계산만 보여 줍니다. 모델이 정답을 생성할 수 있는지나 어떤 절단 정책을 사용하는지는 측정하지 않았습니다.

7주의할 점과 실무 메모

  • 모델 카드의 총 한도와 API의 실제 요청 한도를 함께 확인합니다.
  • 출력 토큰을 예약하지 않으면 응답이 중간에 끊길 수 있습니다.
  • 한도 이내에 있다고 해서 모든 정보가 균등하게 사용되는 것은 아닙니다.

8정리와 다음 절

  • 컨텍스트 윈도는 한 번의 처리에서 참조할 수 있는 토큰 범위입니다.
  • 총 한도에서 출력 예산을 빼면 입력 예산을 구할 수 있습니다.
  • 지시, 문서, 질문, 대화 기록은 같은 입력 예산을 사용합니다.

다음 학습과 이어지는 지점 — 다음 절에서는 한도 안에 있는 정보도 길이와 위치에 따라 활용 결과가 달라질 수 있는지 실제 생성으로 관찰합니다.

9복습 문제

문제와 해설

1. 총 한도가 512이고 출력에 64개를 남겨 두면 입력 한도는 몇 개인가요?

해설 — 448개입니다.

2. 문서만 컨텍스트 예산을 사용하나요?

해설 — 아닙니다. 시스템 지시, 대화, 질문, 도구 결과도 포함됩니다.

3. 한도 이내의 모든 정보는 같은 정확도로 사용되나요?

해설 — 그렇지 않습니다. 한도는 처리 가능 범위이며 정보 활용 품질을 보장하지 않습니다.
