공통 정의가 일부 반복되지만 각 노트북을 따로 내려받아 새 커널에서 실행하는 구조에 필요한 되짚기입니다. 사용하지 않는 `HEAD~1`, `origin/main`, `git diff --cached -- app.py`를 모든 노트북에 미리 열거하던 문제는 없어졌습니다. 첫 코드 셀의 `git()` 보조 함수도 “터미널에서 같은 명령을 실행하도록 인자를 나눈 Python 표현”으로 범위를 제한해, 준비 도구의 내부 구현을 현재 학습 목표로 오해하지 않게 합니다.

## 한국어 감사 3독

1. **독자 관점 정독:** Ch 1은 수정 뒤 처음 보는 기호와 검사 조건을 코드 전에 읽을 수 있습니다. Ch 3은 Git 상태를 실제 출력으로 확인하는 흐름이 선명합니다. Ch 3-04의 문자열 분리와 Ch 3-05의 이력 검사도 처리 순서와 반환값을 먼저 설명하므로 초보자가 핵심 코드까지 따라갈 수 있습니다.
2. **편집자 관점 정독:** 설명은 커밋 → 협업 → 충돌 → 복구 → 시크릿 대응 순서로 이어집니다. Ch 3-03에서 `reset --hard`를 삭제해 앞 절의 범위를 넘지 않으며, 임시 절대 경로는 고정 문자열이 아니라 브랜치·원격 관계를 확인하도록 바뀌었습니다. 독립 실행을 위한 공통 Git 정의와 절별 새 개념도 구분됩니다.
3. **소리 내어 읽는 관점:** `~합니다`체와 짧은 문장 호흡은 일정합니다. S1 수준의 상투적 결론, 독자 칭찬, 불필요한 수사적 대조는 발견하지 못했습니다. `staged diff`와 내부 작업 용어인 “회수”를 한국어 문장으로 다듬었으며, `bare`, `fast-forward`, `reflog` 같은 학습 대상 용어는 처음 나올 때 뜻을 함께 둡니다.

외부 맞춤법 검사는 상업적 대량 문서에 사용하지 말라는 스킬 제한과 이번 검토 지시에 따라 실행하지 않았습니다. 대신 코드 블록·명령·경로를 제외한 한국어를 로컬에서 직접 정독했습니다. `ai-slop-reviewer`의 S1 이상 기준과 `korean-humanize`의 의미 보존 기준을 적용했습니다.
