## 01 커밋과 `.gitignore`

- 발견한 누락: 작업 폴더·색인·커밋의 관계와 `HEAD`가 정의되기 전에 커밋 단위, `git diff --cached`, `git show --stat`이 먼저 등장했습니다. 작업 폴더에서 수정한 파일과 add한 파일이 달라질 수 있다는 구체 상태도 부족했습니다.
- 추가·이동 위치: 핵심 개념을 사진 비유 → 작업 폴더·색인·커밋 정의 → `app.py`의 2건/3건 상태 비교 → HEAD → 명령·옵션 읽기 → `.gitignore` 순서로 통합했습니다. 학습 목표 직후의 고급 설명은 제거하고 실행 예제와 기존 실무 메모가 정의 뒤에 이어지게 했습니다.
- 선수 개념: Ch 1의 현재 폴더와 Git 설치 확인, Ch 2의 `Path.write_text()`와 `subprocess.run()`만 전제로 남겼습니다.
- 코드 연결: 기본 셀의 `.gitignore`와 `app.py` 분리 커밋, 비교 셀의 `git diff -- app.py`, 실패/수정 셀의 `git rm --cached`와 `git check-ignore -v` 출력에 연결했습니다.
- 결과 읽기: `!! .env`, diff의 `-`/`+`, 추적 결과 `없음`, 파일 존재 `True`가 각각 무시·작업 폴더 차이·색인 제거를 뜻하도록 설명했습니다.

## 02 GitHub Flow와 PR 리뷰

- 발견한 누락: 브랜치를 폴더 복사본으로 오해할 가능성, `origin/main`을 실시간 원격으로 오해할 가능성, push가 미커밋 파일까지 보낸다는 오해를 교정하는 설명이 부족했습니다. merge와 rebase도 이름만 나열되어 이력 차이가 드러나지 않았습니다.
- 추가·이동 위치: 핵심 개념을 사본 비유와 GitHub Flow → 브랜치 참조 → 원격과 원격 추적 브랜치 → push 인자 → merge/rebase 비교 → 점 세 개 diff → PR·리뷰 순서로 통합했습니다. 학습 목표 직후의 PR 운영 설명은 제거했습니다.
- 선수 개념: 01절의 커밋·HEAD·브랜치 기본 관계를 사용합니다. PR 화면 사용 경험은 요구하지 않습니다.
- 코드 연결: `git switch -c`, `git push -u origin ...`, `git branch -vv`, `git diff --stat origin/main...HEAD`, `git fetch`, `git merge --no-ff`와 직접 연결했습니다.
- 결과 읽기: `branch -vv`의 현재·추적 브랜치, stat의 파일 범위, 병합 그래프의 두 부모, 빈 문자열 실행의 `TypeError`를 구분했습니다.

## 03 병합 충돌 해결

- 발견한 누락: push 거절과 병합 충돌이 같은 실패처럼 보였고, `pull --no-rebase`가 수행하는 fetch와 merge, fast-forward, 충돌 표시의 양쪽 범위가 코드 전에 충분히 설명되지 않았습니다.
- 추가·이동 위치: 핵심 개념을 공동 문서 비유 → 공통 조상과 3방향 비교 → fast-forward와 push 거절 → pull 인자 → 충돌 표시 → 정책 파일을 근거로 한 해결 → 두 부모 커밋 순서로 통합했습니다. 학습 목표 직후의 해결 절차와 push 설명은 정의 뒤 실행·주의 문단으로 흡수되도록 제거했습니다.
- 선수 개념: 02절의 로컬 브랜치, 원격 추적 브랜치, fetch, merge를 전제로 사용하며 rebase는 비교 정의만 회수합니다.
- 코드 연결: Alice와 Bob의 같은 `message.txt` 한 줄 변화, non-fast-forward 출력, 충돌 표시, `policy.txt`, 해결 커밋의 부모 두 개 검증과 연결했습니다.
- 결과 읽기: push 종료 코드와 병합 종료 코드를 별도로 읽고, `<<<<<<<`, `=======`, `>>>>>>>`의 범위와 최종 파일에서 표시가 사라진 사실을 확인합니다.

## 04 revert, reflog, worktree

- 발견한 누락: 세 기능이 모두 취소 명령처럼 보일 수 있었고, revert와 reset이 같은 파일 결과를 만들더라도 이력이 다르다는 설명, `HEAD~1`, `--hard`, `worktree add -b` 인자 설명이 부족했습니다.
- 추가·이동 위치: 핵심 개념을 공용 장부 비유 → revert의 새 커밋 → reset의 참조·색인·작업 폴더 이동 → reflog 복구 → worktree의 공유 객체와 분리 작업 폴더 → 상황별 선택 순서로 통합했습니다. 학습 목표 뒤에 있던 선택 지침은 정의보다 앞서지 않도록 제거했습니다.
- 선수 개념: 01절의 HEAD·색인·커밋과 02~03절의 브랜치·공유 이력을 사용합니다.
- 코드 연결: `discount=90` 커밋과 revert 후 10, `HEAD~1` hard reset 뒤 사라진 `idea.txt`, reflog 후보 해시에 만든 `recovered-idea`, 두 worktree의 서로 다른 브랜치 출력과 연결했습니다.
- 결과 읽기: 파일 값 10과 이력에 남은 잘못된 커밋을 함께 읽고, 일반 log 미표시와 reflog 표시를 구분합니다.

## 05 시크릿 이력 정리와 예방

- 발견한 누락: 현재 파일 삭제, 이전 커밋의 객체, 외부 복제본의 세 범위가 명령 인자와 함께 연결되지 않았습니다. `--path`와 `--invert-paths`, mirror와 force push 결과의 검증 범위도 초보자가 독립적으로 읽기 어려웠습니다.
- 추가·이동 위치: 핵심 개념을 열쇠 비유 → 시크릿 정의와 폐기·교체 → 현재 파일과 과거 커밋 → `.gitignore` 범위 → 이력 재작성 정의 → filter-repo 인자 → mirror·force 범위 순서로 통합했습니다. 기존의 반복 정의는 삭제했습니다.
- 선수 개념: 01절의 `.gitignore`와 색인, 02절의 원격, 04절의 revert·reflog 차이를 사용합니다.
- 코드 연결: `git check-ignore -v`, `git ls-files`, `git diff --cached`, 강제 add한 더미 `.env`, `git show <커밋>:.env`, `filter-repo --path .env --invert-paths`, 새 mirror의 경로·값 검사와 연결했습니다.
- 결과 읽기: 현재 파일 `False`와 이전 커밋의 더미 값이 동시에 나오는 이유, 정리 후 경로 `False`와 값 커밋 `0`이 임시 참조 범위만 증명한다는 한계를 적었습니다.

## 2026-09-11 독립 검토 잔여 항목 반영

- 03절은 공통 첫 커밋 직후 Bob의 작업 폴더를 복제하고 그 뒤 Alice가 두 번째 커밋을 게시하도록 순서를 바꿨습니다. Bob은 공통 부모에서 바로 자신의 커밋을 만들므로 브랜치 위치를 인위적으로 옮기는 명령 없이 non-fast-forward와 병합 충돌을 재현합니다.
- 04절은 reflog의 `%H%x09%gs` 출력이 `해시 → 탭 → 이동 이유`라는 점과 `splitlines()` → `next(...)` → `split("\t", 1)[0]`의 입력·선택 조건·반환값을 본문과 노트북에 설명했습니다.
- 05절은 `filter-repo --force`가 새 복제본 검사 안전장치를 완화한다는 의미를 적었습니다. `rev-list --objects --all`의 행을 `splitlines()`로 나누고 `endswith(" .env")`와 `any(...)`로 검사하는 조건과 불리언 결과도 설명했습니다.
- 01절은 `feat`·`fix`·`chore`가 Git 필수 문법이 아닌 팀 메시지 관례임을 밝혔고, `.gitignore`의 `*.log`에서 별표가 파일 이름의 임의 문자열과 일치한다고 설명했습니다.
- 02절은 풀 리퀘스트(Pull Request, PR)를 처음 등장할 때 풀어 썼습니다. bare 저장소를 객체·참조만 보관하고 편집 작업 폴더가 없는 저장소로 정의하고, fast-forward를 정의한 뒤 `--no-ff`의 결과를 연결했습니다.
- 5개 노트북의 첫 마크다운은 절별로 필요한 참조만 남겼습니다. 01절은 HEAD까지만, 02~03절은 `origin/main`, 04절은 `HEAD~1`, 05절은 참조의 범위를 소개합니다.
- 02절의 원격 경로와 04절의 worktree 경로는 임시 폴더이므로 실행마다 달라집니다. 출력에서 비교할 고정 요소를 각각 `origin`·`team.git`, `main`·`fix/urgent`로 명시했습니다.
- 생성기를 임시 경로에서 실행해 실제 노트북의 전체 셀 source와 비교했습니다. source를 동기화할 때 기존 최상위 `metadata.verification`을 그대로 보존했으며, 코드 변경 뒤 새 커널 실행기가 새 검증 해시와 실행 시각을 기록했습니다.
