챕터 개요

문서에서 글자를 추출했다고 해서 검색에 필요한 정보가 모두 보존되는 것은 아닙니다. 표의 열 제목이 사라지면 숫자의 뜻을 알기 어렵고, 예외 조항이 다음 청크로 분리되면 본문 규정만 검색될 수 있습니다. 이 챕터에서는 원문의 내용과 출처를 함께 보존하는 문서 처리 과정을 만듭니다. Ch 9에서 연결한 로더·스플리터·임베딩의 입력과 출력을 하나씩 확인하고, 처리 방법을 바꾸었을 때 무엇이 달라지는지 기록합니다.

학습 범위는 강의 8시간과 실습 16시간입니다. 각 절은 강의 1시간과 실습 2시간으로 구성하며, 설명·실행 예제·실패 사례·복습 문제를 함께 제공합니다. 노트북 셀을 순서대로 실행하며 각 단계의 입력과 출력을 확인합니다. 검색 품질 지표는 Ch 11에서 계산하고, 최적 설정은 Ch 12에서 선택합니다.

학습 목표

  • 문서 형식에 맞는 로더를 선택하고, 텍스트·표·쪽 번호가 보존되었는지 원문과 대조할 수 있습니다.
  • 문자·재귀·토큰·구조·시맨틱 청킹의 경계 기준과 한계를 설명할 수 있습니다.
  • 임베딩의 한국어 적합성을 확인할 항목을 정하고, 모델·입력·설정이 다른 캐시를 분리할 수 있습니다.
  • 짧은 원문과 질문을 고정하고 청크 크기만 바꾼 비교와 임베딩 모델만 바꾼 비교를 구분해 기록할 수 있습니다.

준비 자료와 학습 순서

선수 교재는 Ch 9 RAG 첫 완주와 실험 기록입니다. 실습 코드는 labs/part3/ch10-document-processing/notebooks/에 있습니다. 01·02절은 제공 PDF, 03·04절은 fixtures/의 DOCX·HTML·CSV·HWP·HWPX 표식 파일을 사용합니다. 05~08절은 청크 경계와 검색 결과를 바로 비교할 수 있도록 노트북 안의 짧은 교육용 원문을 사용합니다.

전체 합성 문서 모음과 수강생이 실제 업무에서 다룰 문서 100건 실험은 기본 노트북의 범위가 아닙니다. 스캔 PDF는 텍스트 층이 빈 OCR 후보로 분류하며, OCR 인식 성공을 주장하지 않습니다. 임베딩 최종 선정은 [[미정: 임베딩 모델]]로 남겨 두며, 예제에서 사용하는 모델과 선정 기준을 구분합니다.

다음 학습과 이어지는 지점

08절에서는 청크 ID와 검색된 본문을 함께 기록합니다. 문서 단위 평가로 확장할 때는 출처의 문서 ID도 함께 보존해야 합니다. Ch 11에서는 이 ID를 정답표에 적힌 문서 ID와 비교하여 검색 지표를 계산합니다. Ch 12에서는 그 지표를 근거로 청킹·검색·리랭킹 설정을 변경합니다. 처리 시간과 청크 수만으로 검색 품질이 좋아졌다고 결론 내리지 않습니다.

확인 필요 항목

실제 업무에서 다룰 문서 100건 확보와 최종 임베딩 모델 선정은 남아 있습니다. HWP 변환, 실제 업무 HWPX 문서 검증, OCR 및 상용 파서 실행 범위는 각 절의 실행 결과와 주의할 점에 표시합니다. 실습용 파일에서 확인한 성공 사례를 모든 업무 문서에 일반화하지 않습니다.

OPENAI_API_KEY를 사용하는 06~08절은 노트북 안의 작은 입력으로 실제 임베딩을 실행합니다. 08절은 45자 청크·small 모델을 기준으로 실행하고, 청크 크기만 30자로 바꾼 실행, 30자 청크에서 모델만 large로 바꾼 실행을 비교합니다. 짧은 원문 하나와 질문 하나의 결과이므로 정답 질의셋을 사용한 성능 비교나 최종 모델 선정 근거로 사용하지 않습니다.
