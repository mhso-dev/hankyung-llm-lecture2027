생성 모델은 Ch 6에서 배운 init_chat_model로 준비하고 invoke()로 호출합니다. 텍스트는 응답의 text 속성에서 읽으며, 임베딩은 OpenAIEmbeddings를 사용합니다.

Ch 9챕터 개요

이 챕터에서는 수업을 위해 내용을 지어 만든 PDF로 작은 RAG를 처음부터 끝까지 실행합니다. 노트북 안에서 PDF 읽기 → 청크 나누기 → 임베딩 → 벡터스토어 → top-k 검색 → 출처가 있는 답 생성을 순서대로 확인합니다. 마지막 절에서는 설정 딕셔너리의 값 하나를 바꾸고, 색인 설정을 구분하는 해시를 비교해 이전 색인을 다시 쓸 수 있는지 판단하며, 검색 결과를 임시 JSONL 파일 한 줄로 기록합니다. JSONL은 한 줄에 JSON 객체 하나를 저장하는 파일 형식입니다. 검색 결과에 점수를 매기는 방법과 설정을 개선하는 작업은 후속 챕터에서 다룹니다.

커리큘럼 두 규칙① 이 챕터에 에이전트는 없습니다 — 검색 횟수·k·프롬프트는 학생이 코드에 적고, 모델은 답 문장을 만듭니다. ② 측정이 튜닝보다 먼저입니다 — 이 챕터의 JSONL 한 줄은 설정과 검색 ID만 기록하며, 품질 지표는 Ch 11에서 추가합니다.

목표챕터를 마치면

  • 제공된 합성 PDF에서 질문과 관련된 쪽을 읽고 청크로 나눈 뒤, 질문 하나에 출처가 붙은 답을 받을 수 있습니다.
  • 검색 결과 (청크, 점수)를 읽고 "검색이 틀렸나, 생성이 틀렸나"를 가릴 수 있습니다.
  • 같은 출력 "문서에서 찾을 수 없습니다"가 두 가지 원인에서 나온다는 것을 설명하고, 정답 문서 ID가 왜 필요한지 말할 수 있습니다.
  • 설정 딕셔너리의 검색 개수 k만 바꿀 수 있습니다. 색인 설정을 구분하는 해시, 이전 색인을 다시 썼는지 여부, 검색된 문서 ID를 JSONL 파일 한 줄에 기록할 수 있습니다.
