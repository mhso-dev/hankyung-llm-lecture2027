1학습 목표

  • 이 절을 마치면 중첩 딕셔너리의 기본 설정을 읽고 retrieval.k만 복사본에서 바꿀 수 있습니다.
  • 이 절을 마치면 색인 설정을 JSON 문자열로 바꾸고, 같은 설정인지 비교할 수 있는 SHA-256 해시를 만들 수 있습니다.
  • 이 절을 마치면 설정 해시를 비교해 이미 만든 벡터스토어를 다시 쓸 수 있는지 판단하고 실제 검색을 실행할 수 있습니다.
  • 이 절을 마치면 설정, 이전 색인 재사용 여부, 검색된 문서 ID를 JSONL 파일 한 줄에 저장하고 다시 읽을 수 있습니다.

2이 내용을 배우는 이유

앞 절에서는 설정을 바꾸고 결과를 화면으로 확인했습니다. 실험이 늘어나면 어떤 설정에서 얻은 결과인지 함께 남겨야 다시 비교할 수 있습니다. 이번 절은 설정을 모으고 검색을 실행한 뒤 기록 한 행을 저장하는 과정을 배웁니다.

설정 변경, 실행, 기록을 같은 순서로 반복하도록 연결한 흐름을 실험 하네스라고 부릅니다. 처음에는 별도 프로그램이나 명령을 만들지 않고 노트북 셀에서 한 단계씩 확인합니다. Ch 11에서 검색 지표를 배운 뒤 기록 항목을 확장합니다.

3앞에서 배운 내용

  • 딕셔너리 — 관련 설정을 키와 값으로 묶습니다. 이번에는 split·embedding·retrieval 안에 세부 설정을 둡니다.
  • 문서 분할과 벡터스토어 — 설정에 따라 Document를 나누고 InMemoryVectorStore에 저장합니다.
  • 파일 읽기와 쓰기 — 검색 결과를 JSON 한 행으로 저장한 뒤 다시 읽어 같은 기록인지 확인합니다.
  • assert 단언문 — 조건이 거짓이면 실행을 멈추고 AssertionError를 냅니다. 이번에는 청크 설정이 바뀌었는데 이전 색인을 다시 썼다는 잘못을 조건으로 찾아냅니다.

4핵심 개념

비유 — 실험 노트

화학 실험에서 시약의 양을 바꾸면 조건과 관찰 결과를 함께 적습니다. 검색 실험에서도 설정과 결과를 같은 기록에 남겨야 이전 실행과 비교할 수 있습니다. 이번에는 딕셔너리의 값을 바꾸고 셀을 실행한 뒤 JSONL 파일에 기록 한 행을 저장합니다.

정의

실험 하네스 (experiment harness)
설정을 바꾸고 실행한 뒤 결과를 같은 형식으로 기록하게 만든 반복 실험 틀입니다. 기본 노트북은 설정 만들기, 설정 식별 문자열 만들기, 이전 색인 찾기, 검색하기, JSONL 한 줄 기록하기를 한 행동씩 나눈 셀로 보여 줍니다.
설정 딕셔너리 (configuration dictionary)
실험에서 사용하는 값을 모은 딕셔너리입니다. split은 청크 설정, embedding은 모델 설정, retrieval은 검색 설정을 담습니다.
실행 기록 (run record)
한 설정에서 실행한 결과를 담은 기록입니다. 이 절은 name이 k2인 딕셔너리 한 개를 파일에 저장합니다.
설정 해시 (config hash) · 캐시 (cache)
설정 해시는 색인 설정마다 붙이는 짧은 식별 문자열입니다. 캐시는 이미 만든 결과를 잠시 보관하는 공간입니다. 캐시는 설정 해시를 이름표처럼 사용해 기존 벡터스토어 객체를 찾습니다. 이번 예제는 같은 문서를 사용하며 split과 embedding 설정을 해시 입력으로 삼습니다.
JSON Lines (JSONL)
한 줄에 JSON 객체 하나를 두는 파일 형식입니다. 줄을 덧붙이기만 하면 되고, 각 줄을 독립적으로 읽을 수 있습니다. 잘못된 줄의 처리는 별도 오류 대응이 필요합니다. 기본 노트북은 임시 runs.jsonl 파일에 실행 기록을 저장합니다.

도식 — 루프

기본 실습의 실행 범위

원문 두 개를 준비하고 실제 분할 설정을 적용한 뒤 임베딩합니다. 설정을 구분하는 해시와 벡터스토어 객체를 파이썬 딕셔너리인 cache에 보관합니다. 여기서 cache는 이미 만든 벡터스토어를 잠시 저장해 다시 쓰는 공간입니다. 검색 개수 k만 바꾼 복사본의 해시가 같으면 같은 객체를 재사용합니다. 커널을 다시 시작하면 이 메모리 캐시는 사라집니다.

설정 하나를 바꾸고 식별 문자열 만들기

기본 노트북은 deepcopy()로 설정을 복사한 뒤 retrieval.k만 1에서 2로 바꿉니다. 이어서 색인에 영향을 주는 split과 embedding만 별도 딕셔너리에 담습니다.

json.dumps(..., sort_keys=True)는 키 순서를 고정한 JSON 문자열을 만들고, SHA-256은 이 문자열을 고정 길이의 해시로 바꿉니다. 해시는 설정에 붙이는 지문과 같습니다. 내용이 같으면 같은 해시가 나오고, 내용 하나가 바뀌면 다른 해시가 나옵니다. 노트북은 전체 해시를 출력하고 앞의 10자만 학습용 키로 사용합니다. 색인 설정을 구분하는 해시를 만들 때 retrieval.k는 뺍니다. k는 이미 만든 색인에서 문서를 몇 건 가져올지만 바꾸기 때문입니다. 따라서 k만 바꾼 설정은 같은 해시를 사용하고 기존 색인을 다시 씁니다.

기록 한 행

한 행에는 name(실험 이름), config_sha(설정 해시), cache_hit(이전 색인을 찾아 다시 썼는지 여부), retrieved(검색된 문서 ID)가 들어갑니다. 임시 JSONL 파일에 이 행을 추가하고 다시 읽습니다. 이번 기록은 검색 결과를 어떤 모양으로 저장하는지만 확인합니다. 모델 답, 비용, 걸린 시간, 품질 점수는 기록하지 않습니다.

7주의할 점과 실무 메모

  • 원문은 고정한 실험입니다. 기본 키에는 split과 embedding만 들어갑니다. 문서가 바뀌는 확장에서는 원문 내용과 전처리 설정도 구분해야 이전 색인을 잘못 재사용하지 않습니다.
  • 키는 학습용으로 줄였습니다. 앞의 10자는 짧게 비교하기 위한 선택입니다. 큰 저장소를 설계할 때는 충분한 길이의 식별자와 실제 설정 대조가 필요합니다.
  • 같은 객체인지 확인합니다. is 비교는 기존 벡터스토어 객체를 다시 가져왔는지 보여 줍니다. 문서 색인은 재사용해도 질문 검색에는 임베딩 API 호출이 발생할 수 있습니다.
  • 임시 저장 범위를 구분합니다. cache는 현재 커널의 메모리에 있고 JSONL 파일은 임시 폴더에 있습니다. 노트북을 닫은 뒤에도 기록을 남겨야 하는 후속 실습에서는 삭제되지 않는 저장 폴더를 정해야 합니다.
  • 동시에 쓰는 상황은 다루지 않습니다. 이번 실습은 한 커널에서 한 파일에 기록합니다. 여러 실행이 같은 파일에 동시에 쓰는 설계는 별도 처리가 필요합니다.

8정리와 다음 절

  • 기본 config를 깊은 복사하고 k 하나만 2로 바꾸었습니다.
  • split·embedding 설정을 JSON 문자열과 SHA-256 해시로 바꿔 색인 캐시 키로 사용했습니다.
  • k 변경은 기존 store를 재사용했고, 설정, 이전 색인 재사용 여부, 검색된 문서 ID를 JSONL 파일 한 줄에 저장했습니다.

9복습 문제

문제 4개 · 해설 포함

1. deepcopy()를 사용해 k를 바꾼 이유는 무엇입니까?

중첩 딕셔너리의 안쪽 값까지 복사해 원본 config를 보존한 채 변경 설정을 만들기 위해서입니다.

2. 색인 해시 입력에 retrieval.k를 넣지 않은 이유는 무엇입니까?

k는 기존 벡터스토어에서 몇 건을 반환할지만 바꾸며 문서 벡터 자체를 바꾸지 않기 때문입니다.

3. is로 reused_store와 store를 비교하면 무엇을 확인합니까?

두 변수가 값만 같은지가 아니라 메모리의 같은 벡터스토어 객체를 가리키는지 확인합니다.

4. JSONL을 다시 읽었을 때 확인한 네 가지 필드는 무엇입니까?

실험 이름, 설정 해시, 이전 색인을 다시 썼는지 여부, 검색된 Document ID 리스트입니다.
