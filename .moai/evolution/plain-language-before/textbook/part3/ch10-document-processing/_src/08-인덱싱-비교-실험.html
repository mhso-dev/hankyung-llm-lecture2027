1학습 목표

  • 이 절을 마치면 한 가지 청킹·임베딩 설정으로 문서 분할부터 검색 결과 확인까지 실행할 수 있습니다.
  • 이 절을 마치면 청크 크기만 바꾼 비교와 임베딩 모델만 바꾼 비교를 구분할 수 있습니다.
  • 이 절을 마치면 설정·청크 수·첫 번째 청크 ID와 본문를 같은 형식으로 기록할 수 있습니다.
  • 이 절을 마치면 질문 하나의 검색 결과와 전체 검색 품질 평가를 구분할 수 있습니다.

2왜 지금 이것인가

앞 절에서는 문서를 읽고 나누는 방법과 임베딩을 배웠습니다. 이번 절에서는 그 과정을 연결합니다. 먼저 짧은 배송·환불 원문으로 검색을 한 번 마칩니다. 어떤 객체에 무엇이 들어 있는지 확인한 다음 설정을 바꿔야 결과가 달라진 이유를 설명할 수 있습니다.

처음부터 모든 조합을 반복문에 넣으면 어느 단계에서 청크가 만들어지고 모델이 호출되는지 구분하기 어렵습니다. 이 실습은 기준 실행, 청크 크기 변경, 모델 변경의 세 단계를 각각 실행합니다. 앞 단계의 결과를 남겨 두고 다음 단계와 비교합니다.

3선수 지식 되짚기

  • Ch 9 검색 결과 확인 — 생성 전에 검색된 본문과 출처를 확인했습니다. 이번 절에서는 답변을 생성하지 않고 검색 결과까지 관찰합니다.
  • 05절 재귀 청킹 — chunk_size와 chunk_overlap이 경계에 미치는 영향을 확인했습니다.
  • 07절 임베딩 — 텍스트를 벡터로 변환하고 차원을 확인했습니다. 이번 절은 두 모델을 같은 256차원으로 사용합니다.

4핵심 개념

비유 — 같은 재료로 조리 조건 바꾸기

같은 재료를 사용하면서 온도만 바꾸면 온도에 따른 차이를 관찰할 수 있습니다. 재료와 시간까지 한꺼번에 바꾸면 무엇이 결과에 영향을 주었는지 구분하기 어렵습니다. 검색 실험도 원문과 질문을 고정하고 한 조건씩 바꿉니다.

정의

기준 실행 (baseline run)
변경 결과와 비교하기 위해 먼저 실행하는 설정입니다. 이 절에서는 45자 재귀 청킹과 small 모델을 사용합니다.
통제 조건 (controlled condition)
두 실행을 비교할 때 유지하는 입력이나 설정입니다. 원문과 질문, 오버랩, 검색 결과 수 등을 고정합니다.
실험 기록 (experiment record)
어떤 설정에서 어떤 결과를 관찰했는지 함께 남긴 자료입니다. 이번 실습은 딕셔너리 목록으로 기록합니다.
평가 범위 (evaluation scope)
결과를 판단할 때 실제로 사용한 문서와 질문의 범위입니다. 이 절은 짧은 원문 하나와 질문 하나를 사용합니다.

어느 두 실행을 비교하는지 먼저 정합니다

실행청크 크기임베딩 모델비교 대상과 변경값
기준45자text-embedding-3-small첫 검색 결과를 확인합니다.
청킹 변경30자text-embedding-3-small기준 실행과 비교하며 크기만 바꿉니다.
모델 변경30자text-embedding-3-large청킹 변경 실행과 비교하며 모델만 바꿉니다.

모델 변경 실행을 45자 기준 실행과 바로 비교하면 청크 크기와 모델이 함께 달라집니다. 모델 차이를 관찰할 때는 같은 30자 청크를 사용하는 두 실행을 비교합니다. 모든 실행에서 원문, 질문, 오버랩 8자, 검색 결과 수 k=2, 벡터 길이 256을 유지합니다.

숫자와 본문을 함께 읽습니다

InMemoryVectorStore에 문서를 추가하면 임베딩 모델이 문서를 벡터로 바꿉니다. similarity_search_with_score()는 질문으로 검색한 문서와 점수를 함께 반환합니다. 점수만 비교하지 말고, 본문에 제주 배송과 추가 기간을 설명하는 내용이 있는지 확인합니다.

출력의 청크 ID는 이번 실행에서 청크를 구분하는 이름입니다. baseline:00과 smaller:00이 같은 원문 범위를 뜻한다고 가정하지 않습니다. 청크 크기가 바뀌면 경계도 바뀌므로 본문을 함께 읽어야 합니다. 서로 다른 임베딩 모델의 점수 크기만으로 우열을 판단하지 않습니다.

원리 더 알아보기 — 전체 문서와 여섯 조합으로 확장하기

커리큘럼의 확장 목표는 자기 도메인 문서 100건을 세 청킹 방식과 두 임베딩으로 인덱싱하는 것입니다. 현재 제공 자료의 디지털 PDF 18건과 스캔 변형 3건은 그 목표와 구분합니다. 스캔 변형을 같은 원문의 새로운 문서로 세지 않으며, 같은 PDF를 복사해 수량을 채우지 않습니다.

전체 실험 전에는 파일의 고유성, 읽기 가능 여부, 스캔 여부를 점검하고 원문 해시와 파서·청킹·모델 설정을 기록합니다. 청킹 세 가지와 모델 두 가지를 조합하면 여섯 번 실행합니다. 이 반복은 기본 실습의 각 단계가 이해된 뒤 적용합니다.

여러 질문을 평가할 때는 JSONL 파일에 질문, 정답 문서 ID, 검색 결과 전체, 실행 설정을 기록합니다. 캐시 적중 수와 처리 시간, 비용도 별도 항목으로 추가할 수 있습니다. 기본 노트북은 이러한 전체 평가나 비용 계측을 수행하지 않습니다.

6일부러 실패해 보기

Before는 정답을 판단할 기준이 없는 상태를 확인합니다. After는 제주 배송과 추가 기간에 관한 핵심어를 정하고 첫 검색 결과를 검사합니다. 이 검사는 후보 본문에 필요한 단서가 있는지 보는 간이 검사입니다. False가 나오면 해당 첫 결과에 필요한 단서가 빠졌다는 뜻입니다. After가 고치는 것은 판정 기준이 없는 문제이며 검색 결과가 모두 정답이라고 보장하지 않습니다. 키워드가 있어도 문맥이 틀릴 수 있으므로 검색 정확도나 최종 답변의 정답률로 해석하지 않습니다.

7주의할 점과 실무 메모

  • 비교 대상을 구분합니다. 기준과 청킹 변경은 크기 차이, 청킹 변경과 모델 변경은 모델 차이를 확인합니다.
  • API는 실제로 호출됩니다. 문서를 저장하거나 질문으로 검색할 때 임베딩 비용이 발생합니다. 이 노트북은 공급자의 토큰 사용량이나 청구 비용을 출력하지 않습니다.
  • 한 질문은 전체 평가를 대신하지 않습니다. 같은 첫 결과가 나왔다고 모델이 동등하다고 결론짓거나, 다른 결과가 나왔다고 한 모델이 우수하다고 결론짓지 않습니다.
  • 100건 실험은 후속 확장입니다. 기본 실습의 작은 입력과 전체 업무 문서 평가는 범위를 나눠 기록합니다.

8정리와 다음 절

  • 한 설정으로 분할·저장·검색을 끝까지 실행한 뒤 조건을 바꿉니다.
  • 한 조건의 효과를 관찰하려면 비교하는 두 실행의 나머지 조건을 유지합니다.
  • 검색 결과의 본문과 청크 ID를 기록하되, 작은 표본의 키워드 검사를 전체 품질 평가로 표현하지 않습니다.

9복습 문제

문제 4개 · 해설 포함

1. 임베딩 모델만 바꾼 효과를 보려면 어느 두 실행을 비교해야 합니까?

30자 청크와 small 모델을 사용한 실행, 같은 30자 청크와 large 모델을 사용한 실행을 비교합니다.

2. 크기를 바꾼 두 실행의 청크 ID 끝자리가 같으면 같은 내용입니까?

그렇지 않을 수 있습니다. 청크 경계가 달라지므로 실제 본문을 확인해야 합니다.

3. 첫 검색 결과에 제주라는 단어가 있으면 배송 기간 질문에 답할 수 있다고 확정할 수 있습니까?

확정할 수 없습니다. 추가 기간을 설명하는 내용과 그 문맥까지 읽어야 합니다. 키워드 검사는 필요한 단서가 있는지 확인하는 보조 수단입니다.

4. 이 실습에서 두 모델이 같은 문서를 첫 번째로 반환했습니다. 두 모델의 전체 품질이 같다는 뜻입니까?

아닙니다. 원문 하나와 질문 하나에서 얻은 결과입니다. 다양한 질문과 정답 문서로 품질을 측정해야 합니다.
