# Ch10 주제·코드·출력 정합 검토

| 절 | 학습 질문 | 기존 문제 | 수정 | 실제 근거 |
|---|---|---|---|---|
| 01 | 선택한 PDF 쪽을 출처에 어떻게 기록하는가? | `page=0` 자체만 거부해 실제 쪽 표시 오류가 보이지 않았습니다. | 0부터 센 위치 1을 잘못 기록한 결과와 `+1` 변환을 Before/After로 비교했습니다. | 실제 선택 2쪽·잘못 기록 1쪽 → 수정한 출처 2쪽 |
| 02 | 디지털 PDF와 스캔 PDF에서 무엇을 관찰하는가? | 과장 없음 | 표는 실제 추출하고, 스캔본은 OCR 후보만 분류한다는 한계를 유지했습니다. | 표 1개, OCR 후보 1~5쪽; OCR 실행·성공 주장 없음 |
| 03 | CSV의 열 이름과 값 관계를 왜 보존하는가? | 임의의 없는 열 오류만 보여 형식 구조와 연결이 약했습니다. | 값만 남겨 열 이름이 사라진 결과와 딕셔너리 행을 비교했습니다. | `['쿠키','실온']` → `쿠키의 보관 방법: 실온` |
| 04 | HWP와 HWPX를 어떤 경로로 나누는가? | 과장 없음 | 레거시 HWP는 미지원, HWPX만 ZIP/XML로 읽는 범위를 유지했습니다. | HWP 미지원 상태·HWPX 실제 본문을 함께 출력 |
| 05 | 청크 경계가 질문의 두 근거를 갈라놓는가? | 오버랩 숫자 오류는 주제와 직접 연결되지 않았습니다. | 결제 시점·제주 기간이 35자에서는 분리되고 50자에서는 함께 놓이는지 비교했습니다. | 35자 일치 청크 0개 → 50자 일치 청크 1개 |
| 06 | 백분위 기준값이 청크 결과를 어떻게 바꾸는가? | 청크 감소를 개선처럼 표현했습니다. | `lesson_format=experiment`로 바꾸고 95·50·0의 수와 본문을 관찰하되 우열을 단정하지 않았습니다. | 청크 수 2·4·7, “수만으로 더 좋다고 결론내리지 않음” 출력 |
| 07 | 캐시는 언제 재사용되고 설정은 어떻게 구분하는가? | 파일 수·벡터 동일이 API 회피의 직접 증거처럼 읽혔습니다. | 기본 흐름은 실제 LangChain 캐시 관찰로 유지하고, BA는 같은 namespace의 256차원 오염을 128차원 namespace로 분리했습니다. | 잘못 재사용 256차원 → 새 namespace 128차원 |
| 08 | 청크 크기와 모델 효과를 어느 실행끼리 비교하는가? | 인위적인 “정답 기준 없음” 실패가 설정 비교와 어긋났고 도식은 옛 3×2 흐름이었습니다. | `lesson_format=experiment`로 바꾸고 45/small↔30/small, 30/small↔30/large 비교와 1위 청크 근거 포함 여부를 기록했습니다. | 기준만 제주·이틀 동시 포함; 질문 하나로 일반화하지 않음 |

- 백업: `.moai/evolution/topic-alignment-before/`
- 변경 노트북: 01, 03, 05, 06, 07, 08; 02와 04는 출력과 한계 설명이 일치해 유지했습니다.
- 새 실행: 변경 노트북 6개를 Python 3.12.13의 새 커널에서 순차 실행했고 모두 `status=passed`입니다. 07은 최종 단순화 뒤 다시 실행했습니다.
- 셀 길이: 전체 8개 노트북의 가장 긴 코드 셀은 23줄이며 모두 25줄 이하입니다.
- 도식: 01은 01~04절이 `Document`를 직접 만든다는 약속을 제거했고, 05는 실제 35/5·50/5·20/4 수치로, 08은 실제 세 실행 순서로 다시 생성했습니다.
- 정적 검사: 8개 검증 메타데이터, paired/experiment 단계 규칙, 9개 HTML 조각 파싱, 도식 생성기 컴파일을 확인했습니다.
- HTML 최종 빌드는 공통 빌더 소유자인 root가 수행합니다.
