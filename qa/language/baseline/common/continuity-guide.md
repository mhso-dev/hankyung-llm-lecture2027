# Part 7 학습 연결 안내

각 노트북은 새 커널에서 실행합니다. 앞 챕터의 개념을 다시 사용하더라도 이전 커널의 변수를 그대로 요구하지 않습니다. 제공 파일을 읽는 경우에는 준비 셀에서 상대 경로와 파일 존재를 확인합니다.

| 앞에서 배운 내용 | 이번 학습 | 다음에 적용할 곳 |
| --- | --- | --- |
| Ch2의 비동기 함수와 Ch25의 스트리밍 | Ch30 HTTP 요청과 SSE 이벤트 | 클라이언트의 진행 표시와 오류 처리 |
| Ch21의 에이전트, Ch23의 저장 상태 | Ch30의 호출 경계와 Ch31의 데이터 저장 | 서비스 재시작과 사용자별 상태 관리 |
| Ch4의 SQL, Ch12의 pgvector | Ch31의 트랜잭션·연결 풀·인덱스 | Ch32의 데이터베이스 컨테이너 |
| Ch30·31의 서비스와 데이터베이스 | Ch32 실행 이미지와 Compose | Ch33에서 검사한 이미지의 배포 |
| Ch15·29의 평가 질문과 기록 | Ch33의 평가 회귀 검사 | Ch38에서 변경 직후 실행하는 검사 |
| Ch6·29의 사용량·지연 측정 | Ch34 캐시·모델 선택·대기열·예산 | 최종 프로젝트의 품질과 비용 목표 |

서비스 코드·마이그레이션·워크플로우 파일은 각 챕터 README가 안내하는 실행 자료입니다. 작은 원리 예제와 전체 서비스 실습이 나뉘는 경우 두 예제의 입력과 측정 범위를 확인합니다. 여러 챕터의 측정값을 하나의 서비스에서 동시에 얻은 결과처럼 합치지 않습니다.

Part 8에서는 이번에 직접 확인한 오류와 운영 기준을 개발 도구에 전달할 지침으로 바꿉니다. API 입력 항목, 시간 제한, 데이터 저장 범위, 평가 회귀 기준, 복구에 사용할 이미지, 비용 상한처럼 실행 결과로 확인할 수 있는 조건을 남깁니다.
