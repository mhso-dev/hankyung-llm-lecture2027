## 진단 요약

Ch30 학생용 본문 9절 전체, 실습 README 1개, 노트북 마크다운 9개를 전문 정독했습니다. 코드 셀·실행 출력·수치·날짜·파일 경로는 문체 교정 대상에서 제외했습니다. 각 절은 요청 검증, 의존성 주입, 단일 실행, 스트림, SSE, 재연결, 인증, OpenAPI, 실제 Agent 통합이라는 순서로 이어지며, 같은 설명을 불필요하게 반복하거나 근거 없는 과장으로 결론을 확대하지 않습니다.

공통 `확인할 점` 문장이 실제 노트북 출력과 무관하게 상태·키·이벤트를 한꺼번에 열거했습니다. 학생이 무엇을 읽어야 하는지 알기 어려웠으므로, 각 절의 고정 출력으로 확인할 수 있는 값으로 바꿨습니다. 예를 들어 01절은 200·`length`와 422·`string_too_short`, 06절은 `resume-1:1`과 HTTP 200 뒤의 `event: error`, 08절은 OpenAPI 참조와 직렬화 결과를 직접 가리킵니다.

## 수치·의미 보존

수정 전후 diff는 9개 본문 파일의 `확인할 점` 한 문장과 01~08절 도식 안내의 방향 표현만 바뀐 것을 보였습니다. 방향 표현은 세로 SVG 8개의 위에서 아래로 향하는 화살표와 대조해 확인했습니다. 노트북 코드·출력 결합 SHA-256은 전후 모두 `6a1068355cc4aacc3d4240cf936b7ee6173edb4a71358b44e68769c75b444fa2`로 일치했고, 노트북 전체 파일과 README 해시도 전후 일치했습니다.

각 절의 `verify_gates.py` P3 불변식은 수치·직접 인용·이모지·격식 이상 없음으로 통과했습니다. 변경률은 0.1~1.0%여서 P0은 저윤문 WARN을 냈습니다. 이는 적은 국소 교정의 결과이며, S1 잔존을 전문 정독과 검색으로 재확인했습니다. 대구 전멸은 없었습니다.

Phase 6에서 수정본만 통독한 뒤 원문과 문단 단위로 대조했습니다. 새 확인 문장은 기존 노트북 출력에 있던 관찰값만 더 구체적으로 적고, 도식 안내는 기존 흐름의 방향만 SVG와 일치시켰습니다. 수치·날짜·고유명사·조건·가능성을 추가하거나 삭제하지 않았으며, 격식 상향·상투구 주입·문학화도 없으므로 `accept`로 판정했습니다.

## 검증과 생략 단계

`uv run --project labs/part7/ch30-fastapi-serving --with pillow python textbook/part7/ch30-fastapi-serving/_build.py`로 챕터 HTML 10개를 다시 생성했습니다. 이어서 `labs/part7/ch30-fastapi-serving`에서 `uv run pytest`를 실행해 6개 테스트가 통과했습니다.

`korean-spell-check`의 외부 맞춤법 서비스는 실행하지 않았습니다. 상업 교재 전체의 외부 전송은 스킬의 상업적 대량 처리 제한에 해당합니다. 대신 외부 전송 없는 로컬 맞춤법 확인, 일반 AI 슬롭 검토, 전문 정독, Phase 6 의미 보존 대조를 수행했습니다. Codex 적대적 감사 도구는 이 환경에 없어 실행하지 않았습니다.
