**[중] A-8 「입력 검사 오류는 `ValueError`가 아님」 — 원래 오류는 `ValueError`의 한 종류**

- 문제: 입력 검사에서 걸린 원래 오류는 Pydantic `ValidationError`(Ch 19 02 「값 검사 오류」)이고, 이 클래스는 `ValueError`를 물려받습니다. `ValueError`가 아닌 것은 도구 실행 노드가 그 오류를 **감싼** `ToolInvocationError`입니다. 02-4 회색 「공통 사실」 상자와 복습 4 해설은 이를 일반 사실처럼 적어, Ch 19 흐름(`도구.invoke` 직접 호출 — 감싸기 없음)에서는 `except ValueError`가 이 오류를 받는다는 사실과 부딪힙니다. 같은 상자의 「두 설정이 받는 오류가 서로 반대」도 두 요청 범위를 넘습니다(도구 몸통의 `KeyError` 같은 다른 오류는 두 설정 모두 올림 — 설치판 383~391행·984~1003행).
- 근거: `figures/02-4-…mmd` `same["입력 검사 오류는<br>ValueError가 아님<br>두 설정이 받는 오류가<br>서로 반대"]` · `_src/02` 30행 도식 읽기 「맨 아래 회색 상자는 두 칸의 출력을 견줘 얻은 사실」 · 35행 복습 4 해설 「입력 검사에서 걸린 오류는 `ToolInvocationError`이고 `ValueError`가 아닙니다」 · 검토자 확인: `pydantic.ValidationError.__mro__` = `ValidationError → ValueError → Exception`, `lookup_policy.invoke({"주제": "대출"})`를 `except ValueError`가 받음(`pydantic_core` `ValidationError`), `ToolInvocationError.__mro__` = `ToolInvocationError → ToolException → Exception`. 본문 29행 b6 문장(「입력 검사에서 걸렸고, 도구 실행 노드는 이 오류를 `ToolInvocationError`로 감쌌습니다. … 받을 오류 표시가 `ValueError`라 이 오류를 받지 않았고」)과 노트북 [52]는 정확합니다.
- 권하는 고침: 02-4 공통 상자 → 「노드가 감싼<br>ToolInvocationError는<br>ValueError가 아님<br>두 요청에서 받은 오류가<br>서로 엇갈림」 · 복습 4 해설 → 「도구 실행 노드는 입력 검사 오류를 `ToolInvocationError`로 감싸 넘기고, 이 이름은 `ValueError`의 한 종류가 아닙니다」 · b6 29행 「두 설정이 받는 오류 종류는 서로 반대였습니다」 → 「이 두 요청에서는 두 설정이 받은 오류가 서로 엇갈렸습니다」(정리·캡션 `02-4-…caption.md`도 같은 범위로).
