## 0. 실행 전에 적은 입력과 판단 규칙 (2026-09-24, 첫 요청 전)

공통(노트북과 같은 코드):

- 모델 `init_chat_model("openai:gpt-5.4-mini", temperature=0, reasoning_effort="none")`(과정 표준) · 시스템 메시지 없음 · 첫 메시지 `HumanMessage(content=질문)` 하나 · 실행 흔적 칸은 빈 목록.
- 자료 `POLICIES` 셋과 도구 `lookup_policy(topic: str)`는 01절 셀과 같은 코드(독스트링 「교육센터 자료실 규정 하나를 주제어로 찾습니다. topic에는 대출, 운영, 연체 가운데 하나를 넣습니다.」). 상태 형식 `AgentState`(메시지 칸 `add_messages` · 흔적 칸 `operator.add`)도 01절과 같음. 도구 실행 노드 `ToolNode(tools)` 하나를 두 그래프가 함께 씀.
- **(가) 규칙 갈래 그래프**(이 절이 새로 만듦): 규칙 함수 `keyword_topic(question)` — 여러 줄 `if`로 질문에 규정 주제어가 글자 그대로 있는지 딕셔너리 키 차례(대출 → 운영 → 연체)로 보고, 먼저 맞은 주제어 하나를 내놓음(없으면 빈 글). 조건 함수 `pick_by_rule(state)` — 첫 메시지(질문)에 규칙을 대어 빈 글이면 이름표 `"answer"`, 아니면 `"request"`. 이름표 표 `{"request": "request", "answer": "answer"}`로 **시작점 뒤 조건부 엣지**. 요청 노드 `make_rule_request` — 규칙이 고른 주제어로 도구 호출 요청을 손으로 만듦(`id` `"rule_call_1"`, 01절 5절 모양). `request → tools → answer → END`. 답 노드 `call_answer` — **도구를 알려 주지 않은 모델**(`model`)에 메시지 칸 전체를 보냄. 모델 요청은 답 노드에서만(실행마다 1번).
- **(나) 모델 선택 그래프**: 01절 그래프 그대로 — 모델 노드 `call_model`(`bind_tools(tools, parallel_tool_calls=False)`한 `bound_model`) · 도구 조건 함수 `tools_condition` + `path_map = {"tools": "tools", END: END}` · 되돌아가는 엣지 `tools → model`. 실행 한도 인자 없음(설치판 기본값).

입력 넷(모두 이 표를 적은 뒤 바꾸지 않음):

- **L 대출(주 입력)** 「자료실에서 일반 도서를 며칠 대출할 수 있나요?」 — 01절 대출 질문의 「빌릴」만 규정 주제어 「대출할」로 바꾼 글(이 절이 정함).
- **G 인사(주 입력)** 「안녕하세요. 한 문장으로 인사해 주세요.」 — 01절 인사 질문 그대로.
- **T 운영·연체(주 입력)** 「자료실 운영 시간과 연체 규정을 함께 알려 주세요.」 — 01절 값 바꿔 보기 질문 그대로.
- **B 빌림(값 바꿔 보기)** 「자료실에서 일반 도서를 며칠 빌릴 수 있나요?」 — 01절 대출 질문 그대로. L과 뜻은 같고 규칙에 없는 낱말(「빌릴」)로 물음.

규칙 함수가 내놓을 값(코드로 정해짐, 모델 없음): L `대출` · G 빈 글 · T `운영`(먼저 맞은 하나) · B 빈 글.

회차마다 기록하는 표지: 그래프·입력 · 실행 흔적 칸 · 메시지 종류 차례 · 도구 호출 요청의 주제어 인자 차례 · 도구 메시지 수와 결과 상태 · 모델 응답마다 입력·출력 토큰(캐시 입력 포함) · 모델 요청 수(모델 응답 수) · 마지막 응답의 도구 호출 요청 수 · 답 글(기록만) · 응답 모델 이름 · 오류.

판단 규칙:

- (가)의 흔적·주제어 인자·모델 요청 수는 코드가 정합니다. 예상 L `['request', 'answer']`·`['대출']`·1 · G `['answer']`·`[]`·1 · T `['request', 'answer']`·`['운영']`·1 · B `['answer']`·`[]`·1. 다섯 번 모두 이대로면 결론에 씁니다. 다르면 코드를 다시 봅니다(모델 탓이 아님).
- (나)의 예상(01절 흔들림 확인 L·G·T 판을 바탕으로): L `['model', 'model']`·`['대출']`·2 · G `['model']`·`[]`·1 · T `['model', 'model', 'model']`·`['운영', '연체']`·3 · B `['model', 'model']`·`['대출']`·2. **입력마다 다섯 번 모두 같으면** 노트북 주 입력·값 바꿔 보기로 그대로 쓰고, 새 커널 두 번에서도 같을 때만 결론·그림에 씁니다.
- 입력 토큰(요청마다)이 다섯 번 모두 같으면 결론에 씁니다(입력 토큰 몫의 예상 비용도). 출력 토큰·답 글·예상 비용 합(출력 몫 포함)은 결론에 쓰지 않고, 흔들림을 **센 값**(답 글 종류 수, 달라진 회차 수)만 「결과 편차」로 b6·b7에 적습니다.
- (나)에서 한 입력이라도 다섯 번 가운데 다른 회차가 있으면: **입력을 바꾸지 않고** 노트북에서 그대로 쓰며, 그 입력의 모델 쪽 값은 결과 읽기 둘째 단락·「확인할 점」에만 「이번 실행에서는」으로 두고, b7에 다른 회차 수를 적습니다. 결론에는 다섯 번과 두 번 모두 같았던 값만 씁니다.
- 입력 후보는 위 넷뿐입니다. 결과를 보고 다른 질문·다른 키워드·다른 차례로 바꾸지 않습니다. 옛 판 질문 글 끝의 강제 문구(「반드시 제공된 규정 조회 도구로 확인한 뒤 한 문장으로 답하세요.」)는 넣지 않습니다 — 모델이 스스로 고르는지를 보는 절이라, 도구를 쓰라고 시키면 (나)가 도구를 부르지 않는 선택을 볼 수 없기 때문입니다.
