# 02절 그림 설계표 (규격 §5-2)

색 규칙(챕터 리드 결정·01절 선례): 질문·첫 상태·손으로 만든 요청 초록(tool) · 우리가 적은 모델 노드 파랑(flow) · 실제로 부른 모델 보라(model — 02-3의 모델 노드 요청 상자 하나) · 출력으로 확인한 값·After와 값 바꿔 보기에서 받은 오류와 `status: error` 도구 메시지 노랑(measure) · LangGraph가 준 것(`ToolNode`·가상 시작점/끝점·노드 안 오류 처리 차례)과 두 칸 공통 사실 회색 · **빨강은 Before 결함 결과만**(기본값 노드 + 주차 요청 → `ValueError`로 멈춤, 02-1·02-3·02-4에서 같은 요소는 같은 빨강). 도구 조건 함수는 상자로 그리지 않고 모델 노드에서 나가는 점선 갈래 라벨로만(01-1과 같음). 갈래는 점선, 나란한 상자는 `~~~`, 라벨에 대괄호·따옴표 없음, 개수는 한글(0건은 출력 글자 그대로), 노드 id `call`·`end` 안 씀. 모든 값은 새 커널 두 번(A·B, 25셀 중 24셀 출력 글자 해시 같음 — 다른 한 셀은 7절 주차 답 글)에서 같았던 값만.

## 마감 반영 (2026-09-24, 검토 1차 A-8·A-10·A-11·A-17)

- 02-3: 보라 상자 라벨 「모델 노드 요청 한 번」 → **「모델 요청 한 번」**(02-2의 파란 모델 노드와 같은 요소로 읽히지 않게, A-11). alt 같이, `--force` 다시 렌더(폭 654 그대로). 노트북 첨부 그림 아님.
- 02-4: 회색 공통 상자 「입력 검사 오류는 ValueError가 아님 · 두 설정이 받는 오류가 서로 반대」 → **「노드가 감싼 ToolInvocationError는 ValueError가 아님 · 두 요청에서 받은 오류가 서로 엇갈림」**(A-8 — 원래 오류 `ValidationError`는 `ValueError`의 한 종류, 「반대」는 이 두 요청 범위). 「도식 읽기」에 앞 세 줄은 설치판 소스로 확인한 사실, 뒤 두 줄은 두 요청의 출력을 견준 것이라고 근거 갈래를 적음. 캡션·alt·본문 b6 같이, `--force` 다시 렌더(폭 640 그대로). 설명 대상 문장은 이제 「이 두 요청에서는 두 설정이 받은 오류가 서로 엇갈렸습니다」.
- 02-1: 그림은 그대로 두고 「도식 읽기」(본문·노트북 「오늘 볼 그림」)에 「맨 위 초록 상자는 5절 요청이고, 오류 없음 갈래는 8절 둘째 도구 메시지에서 본 흐름」 한 문장(A-10). 첨부 PNG 그대로.
- 02-5: 다시 만들지 않음. PNG를 직접 보고 「그림 읽기」에 책장 빈칸의 뜻과 「그림에는 글자를 넣지 않았지만 본문 비유에서는 카드에 찾지 못한 까닭이 적혀 있다」를 더함(A-17). 위 표 02-5 줄을 채택본(집게 없음, 빈 회색 카드 하나)대로 고침.
- 02-3·02-4 PNG를 다른 이름으로 복사해 직접 봄: 02-3 왼쪽 빨강 둘·오른쪽 노랑·보라(「모델 요청 한 번 gpt-5.4-mini」)·노랑, 02-4 칸 둘과 아래 회색 상자 다섯 줄.
