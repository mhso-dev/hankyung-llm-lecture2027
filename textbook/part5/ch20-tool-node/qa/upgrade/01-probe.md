# 01절 흔들림 확인 (노트북 밖, 2026-09-24)

규격 §2-7 10번 끝 · 챕터 리드 결정 6 · 준비 노트 §2 01·§9-1. 노트북을 쓰기 **전에** 핵심 관찰(질문에 따라 도구 호출 요청이 있는지·도구 이름·실행 흔적)을 노트북 밖에서 **5번** 봅니다. 키는 루트 `.env`에서만 읽고 출력하지 않습니다.

## 0. 실행 전에 적은 입력과 판단 규칙 (2026-09-24, 첫 요청 전)

공통(노트북과 같은 코드):

- 모델 `init_chat_model("openai:gpt-5.4-mini", temperature=0, reasoning_effort="none")`(과정 표준 — `nbkit.key_and_model_cells`) · 시스템 메시지 없음 · 첫 메시지 `HumanMessage(content=질문)`.
- 자료 `POLICIES` 딕셔너리 셋(대출 「일반 도서는 1인 5권까지 14일 동안 대출할 수 있습니다.」 · 운영 「평일은 09:00~20:00, 토요일은 10:00~17:00에 운영합니다.」 · 연체 「연체한 일수만큼 새 대출이 제한됩니다.」 — 옛 판 글 그대로).
- 도구 하나 `@tool lookup_policy(topic: str)`, 독스트링 「교육센터 자료실 규정 하나를 주제어로 찾습니다. topic에는 대출, 운영, 연체 가운데 하나를 넣습니다.」, 없는 주제면 `raise ValueError("지원하지 않는 주제: " + topic)`.
- `bound_model = model.bind_tools(tools, parallel_tool_calls=False)`(Ch 19 04·06과 같게 한 응답에 도구 호출 요청 하나까지).
- 상태 형식 `AgentState(TypedDict)` — `messages: Annotated[list[AnyMessage], add_messages]` · `trace: Annotated[list[str], operator.add]`(Ch 13 04 모양). 모델 노드 `call_model`은 `{"messages": [응답], "trace": ["model"]}`만 냄(도구 실행 노드는 흔적 칸을 쓰지 않음).
- 그래프 `START → model`, `add_conditional_edges("model", tools_condition, {"tools": "tools", END: END})`, `tools → model`, `ToolNode(tools)`를 `"tools"`로 등록, 실행 한도 인자 없음(설치판 기본값).

입력 셋:

- **L(도구가 필요한 질문, 주 입력)** 「자료실에서 일반 도서를 며칠 빌릴 수 있나요?」(옛 판 글 그대로).
- **G(도구가 필요 없는 질문, 주 입력)** 「안녕하세요. 한 문장으로 인사해 주세요.」(옛 판 글 그대로).
- **T(값 바꿔 보기 후보)** 「자료실 운영 시간과 연체 규정을 함께 알려 주세요.」(주제 둘이 필요한 질문 — 여럿 담기를 껐으니 바퀴가 둘 돌 것이라고 예상).

셀 표지(한 회차마다 기록): 실행 흔적 칸 · 메시지 종류 차례 · 응답마다 도구 호출 요청 이름과 인자 · 도구 메시지의 결과 상태와 내용 · 요청 `id` 목록 == 도구 메시지 호출 ID 목록 · 마지막 응답의 도구 호출 요청 수 · 응답마다 사용량(입력·출력·캐시 입력) · 답 글(기록만, 결론에 안 씀).

판단 규칙(결론에 쓸 수 있는 관찰):

- L: 흔적 `['model', 'model']` · 종류 `HumanMessage, AIMessage, ToolMessage, AIMessage` · 첫 응답 요청 1건 `lookup_policy` `{'topic': '대출'}` · 결과 상태 `success` · 호출 ID 짝 `True` — **5번 모두 같으면** 노트북 주 입력으로 쓰고 결론·그림에 씀.
- G: 흔적 `['model']` · 종류 `HumanMessage, AIMessage` · 도구 호출 요청 0건 — 5번 모두 같으면 주 입력.
- T: 흔적 `['model', 'model', 'model']` · 도구 메시지 둘(주제 `운영`·`연체`, 차례는 기록) · 마지막 응답 요청 0건 — 5번 모두 같으면 값 바꿔 보기로 씀.
- 5번 가운데 하나라도 다르면: L·G는 **입력을 그대로 두고** 학생 본문 b7에 「같은 요청도 실행한 때에 따라 달라질 수 있다」와 다른 회차 수를 적고, 노트북 결과가 다르면 사실대로 둔 채 원래 관찰일 때의 값을 셈 한 문장으로 덧붙임. T가 흔들리면 값 바꿔 보기 결과는 둘째 단락·「확인할 점」에만 「이번 실행에서는」으로 두고 결론·그림·정리에서 뺌(후보를 바꿔 가며 고르지 않음).
- 입력 후보는 위 셋뿐입니다. 결과를 보고 다른 질문으로 바꾸지 않습니다.

## 2. 입력 결정

- 판단 규칙(§0)대로 **L·G를 노트북 주 입력으로, T를 값 바꿔 보기로 그대로** 씁니다(세 입력 모두 5번 같음 — 후보를 바꾸거나 더 보내지 않음).
- 결론·그림에 쓸 값(새 커널 두 번에서도 같아야 씀): 흔적 `['model', 'model']`·`['model']`·`['model', 'model', 'model']` · 모델 요청 수 2·1·3 · 도구 메시지 1·0·2 · 도구 이름과 인자 · 결과 상태 `success` · 호출 ID 짝 `True`.
- 둘째 단락·「확인할 점」에만 둘 값: 답 글, 출력 토큰. 노트북은 토큰을 세지 않습니다(주제가 아님 — 챕터 리드 결정 5, 04가 셈).
- 질문 셋은 옛 판 글 둘 + 이 절이 정한 값 바꿔 보기 하나이고, 흐름을 보여 주려고 정한 예라고 b7에 밝힙니다.
