# 02절 흔들림 확인 (노트북 밖, 2026-09-24)

규격 §2-7 10번 끝 · 챕터 리드 결정 6 · 인계 §01 → §02 6항. 이 절의 핵심 장면(Before `ValueError`·After 도구 메시지·받을 오류 표시)은 **손으로 만든 도구 호출 요청**으로 모델 없이 정해집니다. 모델은 도구 실행 노드가 도구 메시지를 더한 **뒤에만** 불립니다(시작 엣지를 도구 실행 노드로 옮긴 그래프). 그 뒤 흐름(모델이 도구 메시지를 읽고 다시 요청하는지, 몇 번 요청하는지)은 모델 답에 기대므로, 노트북을 쓰기 전에 노트북 밖에서 **5번씩** 봅니다. 키는 루트 `.env`에서만 읽고 출력하지 않습니다.

## 0. 실행 전에 적은 입력과 판단 규칙 (2026-09-24, 첫 요청 전)

공통(노트북과 같은 코드):

- 모델 `init_chat_model("openai:gpt-5.4-mini", temperature=0, reasoning_effort="none")`(과정 표준) · 시스템 메시지 없음 · `bound_model = model.bind_tools([lookup_policy], parallel_tool_calls=False)`(01절과 같은 값).
- 자료 `POLICIES` 셋과 도구 `@tool lookup_policy(topic: str)`은 01절 셀과 글자까지 같은 코드(독스트링 「교육센터 자료실 규정 하나를 주제어로 찾습니다. topic에는 대출, 운영, 연체 가운데 하나를 넣습니다.」, 없는 주제면 `raise ValueError("지원하지 않는 주제: " + topic)`).
- 상태 형식 `AgentState`(메시지 칸 `add_messages` · 흔적 칸 `operator.add`)·모델 노드 `call_model`·이름표 표 `{"tools": "tools", END: END}`는 01절과 같음. 그래프만 **시작 엣지를 `START → "tools"`**로 옮김(`tools → model`, `model` 뒤 `tools_condition` 조건부 엣지는 01절 그대로).
- 오류 처리 함수(노트북과 같은 글):
  `def handle_policy_error(error: ValueError):` → `"규정을 찾지 못했습니다(" + str(error) + "). 이 도구로 찾을 수 있는 주제어는 대출, 운영, 연체입니다."`

입력 둘(첫 상태 = 질문 하나 + 손으로 만든 응답 하나, 흔적 칸 빈 목록):

- **P(주 입력, After 흐름)** 질문 「자료실 주차 규정을 알려 주세요.」(옛 판 글 그대로) + 요청 `{"name": "lookup_policy", "args": {"topic": "주차"}, "id": "hand_call_park", "type": "tool_call"}` · 도구 실행 노드 `ToolNode(tools, handle_tool_errors=handle_policy_error)`.
- **K(값 바꿔 보기, 기본값 노드 흐름)** 질문 「자료실에서 일반 도서를 며칠 빌릴 수 있나요?」(01절 7절 질문 그대로) + 인자 이름이 틀린 요청 `{"name": "lookup_policy", "args": {"주제": "대출"}, "id": "hand_call_key", "type": "tool_call"}` · 도구 실행 노드 `ToolNode(tools)`(기본값, Before와 같은 노드).
- (모델 없이 정해지는 둘 — 5번 보내지 않고 한 번씩만 기록) Before = P 입력 + 기본값 노드 → `ValueError`로 멈춤 · K 입력 + 오류 처리 함수 노드 → 입력 검사 오류(`ToolInvocationError`)로 멈춤. 두 경우 모두 모델 노드에 닿지 않으므로 요청 0번.

셀 표지(한 회차마다 기록): 실행 흔적 칸 · 메시지 종류 차례 · 응답마다 도구 호출 요청의 이름과 인자 · 도구 메시지마다 결과 상태와 내용 · 요청 `id` 목록 == 도구 메시지 호출 ID 목록 · 마지막 응답의 도구 호출 요청 수 · 응답마다 사용량(입력·출력·캐시 입력) · 답 글(기록만, 결론에 안 씀).

판단 규칙(결론에 쓸 수 있는 관찰):

- **모델 없이 정해지는 값**(셋째 메시지가 도구 메시지인지·그 결과 상태 `error`·호출 ID가 손으로 만든 요청의 `id`와 같은지·Before와 K+오류 처리 함수의 오류 이름)은 흔들림 확인과 상관없이 결론에 씁니다(새 커널 두 번에서도 같아야 함).
- P: 흔적 `['model']` · 종류 Human·AI·Tool·AI · 마지막 응답 요청 0건 — **5번 모두 같으면** 「모델이 도구 메시지를 읽고 도구 없이 답했다」를 결론·그림에 씀.
- K: 흔적 `['model', 'model']` · 종류 Human·AI·Tool(error)·AI·Tool(success)·AI · 둘째 응답의 요청 `lookup_policy {'topic': '대출'}` · 마지막 응답 요청 0건 — **5번 모두 같으면** 「모델이 오류 글을 읽고 인자를 고쳐 다시 요청했다」를 결론·그림에 씀.
- 5번 가운데 하나라도 다르면: **입력은 그대로 두고**, 그 흐름의 모델 쪽 값은 결과 읽기 둘째 단락·b6 「확인할 점」·b7에만 「이번 실행에서는」과 다른 회차 수로 적고, 결론·그림·정리는 모델 없이 정해지는 값만 씀. 노트북 결과가 원래 관찰과 다르면 사실대로 두고 원래 관찰일 때의 값을 셈 한 문장으로 덧붙임.
- 입력 후보는 위 둘뿐입니다. 결과를 보고 질문·요청·안내 글을 바꾸지 않습니다.
