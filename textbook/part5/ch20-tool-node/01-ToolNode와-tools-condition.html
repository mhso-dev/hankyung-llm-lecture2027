1학습 목표

  • 모델 노드와 도구 실행 노드(ToolNode)를 한 상태 그래프에 등록하고, 도구 조건 함수(tools_condition)로 이을 수 있습니다.
  • 도구 조건 함수가 마지막 응답의 무엇을 보고 다음 갈 곳을 고르는지 설명할 수 있습니다.
  • 실행 흔적 칸과 메시지 칸으로, 그래프가 도구 쪽을 몇 번 다녀왔는지 셀 수 있습니다.

2이 내용을 배우는 이유

Ch 19 05절에서는 도구 호출 요청을 실행하고 모델에게 다시 묻는 일을 우리가 쓴 함수로 했습니다. 함수 ask_until_answer 안의 for 루프가 응답마다 요청이 있는지 보고, 있으면 도구를 실행했습니다. 요청이 없는 응답이 오면 break로 멈췄습니다.

Ch 13에서는 노드와 엣지로 흐름을 그래프에 적었습니다. 그런데 Ch 13의 그래프는 앞에서 뒤로만 흘렀고, 같은 노드를 다시 지나지 않았습니다. Ch 18의 다섯 패턴에서도 다음 단계를 고른 쪽은 늘 코드였습니다.

이 절은 Ch 19 05절의 되풀이를 상태 그래프로 옮깁니다. 모델이 도구 호출 요청을 보내면 그래프가 도구를 실행하러 가고, 보내지 않으면 끝납니다. 어느 쪽으로 갈지는 모델의 응답이 정합니다. Ch 21에서는 create_agent 호출 한 줄로 같은 되풀이 구조를 만듭니다. 그 안에서 무엇이 도는지 읽으려면 이 절의 그래프를 알아야 합니다.

4핵심 개념

비유로 시작하기

두 층으로 된 자료실을 떠올려 봅니다. 위층 창구에서는 사서가 질문을 받고, 아래층 서고에는 규정 책이 있습니다. 두 층은 벽 속의 작은 승강 상자로 이어져 있습니다. 음식이나 물건을 층 사이로 올리고 내리는 작은 승강기입니다.

사서는 규정을 찾아야 하면 요청 쪽지를 적어 상자에 넣습니다. 쪽지가 든 상자는 서고로 내려가고, 서고에서는 쪽지대로 규정 책을 찾아 상자에 실어 올려 보냅니다. 찾을 것이 없으면 사서는 쪽지를 넣지 않고 바로 답하고, 상자는 창구에 그대로 있습니다.

사서는 모델이고, 창구는 모델 노드입니다. 요청 쪽지는 도구 호출 요청, 서고는 도구 실행 노드, 올라온 책은 도구 메시지입니다. 쪽지가 있는지 보고 상자를 내려보낼지 정하는 일이 도구 조건 함수입니다. 상자가 다시 창구로 올라오는 길이 되돌아가는 엣지입니다. Ch 19의 식당에서는 우리가 전표를 들고 주방을 오갔지만, 이 자료실에서는 승강 상자가 그 오가기를 맡습니다.

그림 읽기 — 위층에는 긴 나무 창구, 아래층 왼쪽에는 파란 책이 꽂힌 책장이 있습니다. 벽 속 승강 통로 둘 가운데 왼쪽 통로의 상자는 아래층까지 내려가 있습니다. 그 상자에는 흰 쪽지가 반쯤 삐져나와 있고, 파란 책 한 권이 들어 있습니다. 오른쪽 통로의 같은 상자는 위층 창구 앞에 빈 채로 있습니다. 쪽지는 도구 호출 요청, 책은 도구 메시지, 빈 상자는 요청이 없어 끝나는 흐름입니다.

말뜻
모델 노드도구를 알려 준 모델에 메시지 칸 전체를 보내고, 받은 응답을 메시지 칸에 더하는 노드입니다. 자료실의 창구와 같습니다.
도구 실행 노드(ToolNode)마지막 응답의 도구 호출 요청을 실행하고, 결과를 도구 메시지로 메시지 칸에 더하는 노드입니다. LangGraph가 미리 만들어 둔 노드입니다. 아래층 서고와 같습니다.
도구 조건 함수(tools_condition)마지막 응답에 도구 호출 요청이 있으면 이름표 "tools"를, 없으면 END를 내놓는 조건 함수입니다. LangGraph가 미리 만들어 둔 함수입니다. 쪽지가 있는지 보고 상자를 내려보낼지 정하는 일과 같습니다.
되돌아가는 엣지뒤에 있는 노드에서 앞의 노드로 다시 가는 엣지입니다. 그래프가 같은 노드를 다시 지나게 합니다. 상자가 창구로 다시 올라오는 길과 같습니다.

새 말을 이 절 코드에서 보면 이렇습니다. 모델 노드는 함수 call_model이고, 이름 "model"로 등록합니다. 도구 실행 노드는 ToolNode(tools)로 만들어 이름 "tools"로 등록합니다. 도구 조건 함수는 builder.add_conditional_edges("model", tools_condition, path_map)에 들어갑니다. 되돌아가는 엣지는 builder.add_edge("tools", "model") 한 줄입니다.

도식 읽기 — 위에서 아래로 읽고, 상자 넷은 노트북 6절 구조 문자열의 상자 넷과 같습니다. 파란 상자는 우리가 적은 모델 노드, 회색 상자는 LangGraph가 준 도구 실행 노드와 가상 시작점·끝점입니다. 모델 노드에서 나가는 점선 두 갈래는 도구 조건 함수가 고르고, 이 함수는 노드가 아니라 상자로 그리지 않았습니다. 도구 실행 노드에서 모델 노드로 올라가는 실선이 되돌아가는 엣지입니다.

Ch 19 05절의 되풀이와 견주기

이 그래프는 Ch 19 05절 함수 ask_until_answer가 하던 일을 나눠 맡습니다. 아래 표의 왼쪽이 그 함수의 줄이고, 오른쪽이 이 절 그래프에서 같은 일을 맡은 부분입니다.

Ch 19 05절 함수 ask_until_answer이 절 그래프
bound_model.invoke(messages)로 모델 요청모델 노드 call_model
run_tool_calls(response, tools_by_name)로 도구 실행도구 실행 노드 ToolNode(tools)
도구 호출 요청이 없으면 break도구 조건 함수 tools_condition이 END를 내놓음
messages.append(…)로 목록에 붙이기메시지 칸의 메시지 리듀서 add_messages
for turn in range(turn_limit)로 되풀이되돌아가는 엣지 tools → model(한도는 03절)

도식 읽기 — 위 칸이 Ch 19 05절 함수 안의 for 루프이고, 아래 칸이 이 절 그래프입니다. 두 칸에서 같은 자리에 놓인 상자가 같은 일을 맡습니다. 파란 상자는 우리가 적은 코드이고, 회색은 LangGraph가 준 것입니다. 그래프가 되풀이하는 횟수의 한도는 바퀴 한도 turn_limit과 세는 것이 달라, 아래 칸에 그리지 않고 03절에서 봅니다.

다른 상황에 적용

Ch 19의 주문 도구를 넣는다면, 도구 목록을 바꿔 모델에게 다시 알리고 도구 실행 노드를 새로 만들면 됩니다. 그래프 모양은 그대로입니다. 모델이 주문 번호가 든 질문에 요청을 보내면 도구 실행 노드가 주문을 찾고, 모델이 도구 메시지를 읽고 답합니다. 이 조합은 이번에 실행하지 않았습니다.

비교와 경계

도구 조건 함수는 답이 맞는지 보지 않습니다. 마지막 응답에 도구 호출 요청이 있는지만 봅니다. 그래서 모델이 요청을 끝없이 보내면 그래프도 계속 되풀이됩니다. 그래프가 되풀이하는 횟수의 한도는 03절에서, 도구가 오류를 낼 때는 02절에서 봅니다.

세 흐름은 같은 그래프였고, 도구 쪽으로 몇 번 갈지는 모델의 응답이 정했습니다. 노트북 밖에서 세 질문을 다섯 번씩 보냈을 때도 세 줄의 값이 모두 같았습니다.

Ch 19 05절 함수 ask_until_answer의 줄마다 이 그래프에서 맡는 곳은 아래와 같습니다.

- 모델에게 묻는 줄 bound_model.invoke(messages)는 모델 노드 call_model이 맡습니다. - 도구를 실행하는 함수 run_tool_calls는 도구 실행 노드 ToolNode(tools)가 맡습니다. - 요청이 없으면 멈추는 break는 도구 조건 함수가 END를 내놓는 일이 맡습니다. - 목록에 붙이는 messages.append는 메시지 칸의 메시지 리듀서 add_messages가 맡습니다. - 되풀이하는 for 루프는 되돌아가는 엣지 tools → model이 맡고, 한도는 03절에서 봅니다.

정리

1. 도구 조건 함수는 마지막 응답에 도구 호출 요청이 있으면 도구 실행 노드로, 없으면 END로 보냈습니다. 2. 도구 실행 노드가 도구 메시지를 더하면, 되돌아가는 엣지로 모델 노드에 다시 갔습니다. 3. 대출·인사·운영과 연체 질문의 모델 요청은 2·1·3번, 도구 메시지는 1·0·2개였습니다.

02절에서는 도구 실행 노드가 실행한 도구가 오류를 낼 때를 봅니다. Ch 19 06절에서 도구 속성으로 하던 일을 도구 실행 노드 쪽에서 다룹니다.

확인할 점 — 노트북 7절 출력 실행 흔적 칸: ['model', 'model']과 메시지 네 줄로, 도구 쪽을 한 번 다녀왔는지 봅니다. 노트북 8절 출력 실행 흔적 칸: ['model']로, 도구 없이 끝났는지 봅니다. 노트북 10절 표에서 세 질문의 모델 요청 수와 도구 메시지 수를 견줍니다. 답 글은 실행마다 달라질 수 있어 결론에 쓰지 않았습니다. 교재 출력에서는 대출 답 글에 규정 글의 5권과 14일이 들어 있었습니다.

도식 읽기 — 위에서 아래로 읽고, 세로선은 왼쪽부터 노트북 코드, 모델 노드, 도구 실행 노드입니다. 연보라 띠는 실제로 부른 모델 gpt-5.4-mini가 있는 자리입니다. 요청 1의 응답에 도구 호출 요청이 있어, 도구 조건 함수가 도구 실행 노드로 보냅니다. 되돌아가는 엣지로 모델 노드에 온 뒤, 요청 2의 응답에는 요청이 없어 끝납니다. 노란 메모는 모두 노트북 7절 출력입니다.

세 흐름은 모두 같은 그래프였습니다. 도구 쪽으로 몇 번 갈지는 모델의 응답이 정했고, 도구 조건 함수는 그 응답에 요청이 있는지만 보았습니다.

세 질문 모두 모델 요청 수가 도구 메시지 수보다 하나 많았습니다. 여럿 담기를 꺼서, 요청이 있는 응답마다 도구 메시지가 하나였습니다. 그리고 마지막 응답은 늘 요청이 없는 응답이었습니다.

새 커널로 두 번 실행했을 때 표의 값은 두 번 모두 같았습니다. 노트북 밖에서 세 질문을 다섯 번씩 보냈을 때도 같았습니다. 답 글의 문장은 실행마다 달랐고, 이 표에 넣지 않았습니다.

7주의할 점과 실무 메모

  • 노트북을 실행하기 전에 노트북 밖에서 세 질문을 다섯 번씩 보냈습니다. 실행 흔적, 도구 이름과 인자, 도구 메시지 수가 다섯 번 모두 같았습니다. 같은 요청도 실행한 때에 따라 모델이 도구를 부를지가 달라질 수 있습니다.
  • 질문 셋은 흐름을 보여 주려고 이 절에서 정한 예입니다. 운영·연체 질문은 규정 두 가지가 필요하도록 값 바꿔 보기로 정했습니다.
  • 도구를 부를지와 그 인자에는 assert를 걸지 않았습니다. 모델이 정하는 값이기 때문입니다. 셀의 assert는 도구 실행 노드가 옮겨 적는 호출 ID 짝에만 걸었습니다.
  • 도구 조건 함수의 동작은 손으로 만든 응답 두 개로 모델 없이 확인했습니다. 설치한 langgraph-prebuilt 1.1.0 소스도 도구 호출 요청의 개수가 0보다 큰지만 봅니다.
  • 여럿 담기를 끈 채 도구를 알려 주었습니다. 한 응답에 담긴 요청 여럿을 도구 실행 노드가 실행하는 장면은 이 절에서 보지 않았습니다. 설치판 소스에서는 요청 여럿을 스레드로 한꺼번에 실행하고, 도구 메시지는 요청 차례대로 둡니다. 요청 여럿이 한 응답에 오면, 모델 요청 수와 도구 메시지 수의 셈은 달라질 수 있습니다.
  • 도구 실행 노드는 이 절의 실행 흔적 칸을 쓰지 않습니다. 도구 실행은 메시지 칸의 도구 메시지로 읽었습니다.
  • 그래프가 되풀이하는 횟수의 한도는 따로 정하지 않고 실행했습니다. 그 한도는 03절에서 다룹니다.
  • 걸린 시간과 토큰은 재지 않았습니다. 모델 요청 수는 실행 흔적 칸의 길이로 셌습니다.
  • 도구는 딕셔너리를 읽기만 합니다. 무언가를 바꾸는 쓰기 도구라면, Ch 19 06절처럼 사람 확인 값으로 알려 줄 도구를 먼저 고릅니다.
  • 이 절이 도구 파일 graph_tools.py에서 가져오는 두 함수는 Ch 19 order_tools.py의 본문을 글자 그대로 옮긴 것입니다.
  • 예상 비용은 2026-09-17 요금표로 어림하면 노트북 한 번에 0.01달러 아래이고, 청구 금액이 아닙니다.
  • 교재 출력은 Linux의 Python 3.12.13으로 만들었습니다. 다른 판과 Windows·macOS에서는 이번에 실행하지 않았습니다.

9복습 문제

문제 4개 · 해설 포함

1. 도구 조건 함수는 무엇을 보고 이름표를 고르나요?

메시지 칸의 마지막 응답에 도구 호출 요청이 있는지만 봅니다. 있으면 "tools", 없으면 END를 내놓습니다. 틀렸다면 노트북 5절을 다시 읽습니다.

2. 대출 질문의 실행 흔적 칸에는 model만 두 번 있습니다. 도구가 실행된 것은 어디서 확인하나요?

메시지 칸의 도구 메시지로 확인합니다. 도구 실행 노드는 실행 흔적 칸을 쓰지 않고, 결과 상태 success인 도구 메시지를 메시지 칸에 더했습니다. 틀렸다면 노트북 7절을 다시 읽습니다.

3. 되돌아가는 엣지는 무엇을 하나요?

도구 실행 노드가 끝난 뒤 모델 노드로 다시 가게 합니다. 그래서 모델이 도구 메시지를 읽고 답하거나 다음 요청을 보낼 수 있습니다. 운영·연체 질문에서는 이 엣지를 두 번 지났습니다. 틀렸다면 노트북 6절과 9절을 다시 읽습니다.

4. Ch 19 05절 함수 ask_until_answer의 run_tool_calls와 break는 이 그래프에서 무엇이 맡나요?

함수 run_tool_calls는 도구 실행 노드가 맡고, break는 도구 조건 함수가 END를 내놓는 것이 맡습니다. 틀렸다면 본문 4 「핵심 개념」의 표를 다시 읽습니다.
