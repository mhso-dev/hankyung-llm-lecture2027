1학습 목표

  • `bind_tools` 응답과 실제 도구 실행을 구분할 수 있습니다.
  • 노트북의 실제 출력에서 도구 이름, 인자, 결과를 확인할 수 있습니다.
  • 관찰한 범위를 넘지 않고 결과를 해석할 수 있습니다.

2이 내용을 배우는 이유

모델이 올바른 도구 이름과 인자를 만들었더라도 조회 결과는 아직 없습니다. 요청을 실행한 뒤 결과 메시지를 원래 호출과 연결하는 과정을 직접 확인해야 합니다.

Ch20에서 ToolNode로 실행 흐름을 조립하기 전에 도구 한 개가 어떤 정보와 결과를 주고받는지 확인합니다.

4핵심 개념

비유로 먼저 이해하기

도구 설명서는 주문서와 비슷합니다. 모델은 함수 내부를 보지 않고 이름, 설명, 선택 항목을 보고 요청합니다.

정의

bind_tools()는 모델에게 도구 설명서를 제공합니다. 모델의 tool_calls에는 이름·인자·고유 ID가 들어 있지만 조회 결과는 아직 없습니다. 프로그램이 호출을 실행하고 같은 ID를 가진 ToolMessage를 대화에 추가해야 결과를 바탕으로 답할 수 있습니다.

AIMessage의 content가 비어 있어도 tool_calls가 있으면 모델은 답 대신 실행 요청을 보낸 것입니다. 각 항목의 name은 실행할 도구를, args는 전달할 주문 ID를, id는 결과 연결표를 나타냅니다. StructuredTool.invoke에 호출 사전 전체를 넘기면 LangChain은 실행 결과를 ToolMessage로 만들고 원래 id를 넣습니다. 마지막 호출에서는 사용자 질문, AIMessage, 두 ToolMessage를 순서대로 전달합니다. 이 메시지 순서가 어긋나거나 ID가 빠지면 제공자 API가 잘못된 대화 형식으로 판단할 수 있습니다.

도구 호출(tool call)은 구조화된 실행 요청이며 도구 메시지(ToolMessage)는 실행 결과와 호출 ID를 돌려주는 메시지입니다.

도식 읽기

모델 요청과 함수 실행 사이의 경계를 따라 읽습니다. 자율 반복은 Ch20 이후에 다룹니다.

6실험 결과 해석

한 질문이 독립된 두 주문을 요구하면 모델은 한 응답에 여러 호출을 낼 수 있습니다. 실제 출력의 호출 개수와 ID 대응을 확인합니다. 같은 질문과 입력을 유지한 채 비교 대상 한 가지를 바꿉니다. 출력에 나타난 값만 근거로 삼으며, 작은 표본으로 모든 모델과 질문에 같은 결과가 난다고 단정하지 않습니다.

출력 읽기

첫 출력에서 content가 빈 문자열이고 tool_calls가 두 개인지 확인합니다. 이것은 모델이 최종 문장보다 두 조회를 먼저 요청했다는 뜻입니다. 두 번째 출력의 content에는 O101의 paid·32000과 O103의 paid·27000이 직렬화되어 있습니다. 세 번째 출력에서 requested와 returned 배열이 같은 순서와 값인지 확인합니다. 마지막 자연어 답은 두 도구 결과를 읽은 모델의 새 응답입니다. 중간 ToolMessage를 생략하고 마지막 호출을 보내면 모델은 주문 상태와 금액을 알 수 없습니다.

7주의할 점과 실무 메모

parallel_tool_calls는 한 응답에 여러 호출을 허용하는 설정입니다. 이 노트북은 실제 함수 실행 시간을 측정하지 않으므로 동시에 실행됐다고 주장하지 않습니다.

두 주문 조회는 서로 의존하지 않으므로 모델이 호출 두 개를 한 응답에 담을 수 있는 사례입니다. 두 번째 주문이 첫 번째 결과를 필요로 한다면 같은 방식으로 병렬 요청하면 안 됩니다. 또한 호출 두 개가 생성됐다는 사실과 Python 함수가 동시에 실행됐다는 사실은 다릅니다. 이 노트북의 리스트 컴프리헨션은 순서대로 invoke를 호출합니다. 실제 동시 실행을 가르치려면 비동기 실행 시간과 시작·종료 기록을 별도 측정해야 하며, 그 내용은 이 절의 범위를 넘습니다.

도구 결과를 모델에게 다시 보낼 때 원본 AIMessage도 함께 넣습니다. ToolMessage만 보내면 어떤 요청에 대한 결과인지 대화 기록이 완전하지 않습니다. 운영 로그에서는 호출 ID로 모델 요청, 함수 시작, 함수 종료, 최종 답을 연결하면 지연과 오류가 생긴 위치를 찾기 쉽습니다.

  • 도구 설명과 인자 스키마도 모델 컨텍스트를 사용합니다.
  • API 가격과 모델 동작은 달라질 수 있으므로 실행 시점의 공식 정보를 확인합니다.

8정리와 다음 절

  • 관찰한 요청과 실행 결과를 구분해 기록했습니다.
  • 작은 표본의 결과를 다른 모델과 질문에 일반화하지 않습니다.
