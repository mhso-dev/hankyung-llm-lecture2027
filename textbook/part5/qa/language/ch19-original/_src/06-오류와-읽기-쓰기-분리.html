1학습 목표

  • 오류 결과를 모델이 읽을 수 있게 만들고 읽기와 쓰기 도구를 분리할 수 있습니다.
  • 노트북의 실제 출력에서 도구 이름, 인자, 결과를 확인할 수 있습니다.
  • 관찰한 범위를 넘지 않고 결과를 해석할 수 있습니다.

2이 내용을 배우는 이유

주문 조회 실패와 주문 취소 요청은 위험이 다릅니다. 예상 가능한 조회 실패는 모델이 다음 판단에 사용할 오류 코드로 반환하고, 상태를 바꾸는 동작은 확인 경로를 별도로 둡니다.

Ch20에서 ToolNode로 실행 흐름을 조립하기 전에 도구 한 개가 어떤 정보와 결과를 주고받는지 확인합니다.

3앞에서 배운 내용

공개 주문 목록을 메모리에서 읽고 존재하지 않는 O999를 조회합니다. 쓰기 예제는 실제 주문을 변경하지 않고 취소 요청 상태만 구조화해 반환합니다.

실행 파일은 labs/part5/ch19-model-tools/data/orders.csv를 사용하며 Part1 모듈을 런타임에 import하지 않습니다.

4핵심 개념

비유로 먼저 이해하기

도구 설명서는 주문서와 비슷합니다. 모델은 함수 내부를 보지 않고 이름, 설명, 선택 항목을 보고 요청합니다.

정의

예상 가능한 업무 오류는 NOT_FOUND처럼 짧고 일정한 코드와 관련 인자를 반환합니다. 쓰기 권한은 모델 인자가 아니라 애플리케이션이 기록한 사용자 확인 상태로 제어합니다.

O999가 없다는 사실은 예상 가능한 업무 결과입니다. read_order는 예외 대신 ok=False, error=NOT_FOUND, order_id=O999를 반환합니다. 취소 도구에는 confirmed 필드가 없습니다. 확인 전 available_tools에는 읽기 도구만 있고, 신뢰하는 애플리케이션 상태가 사용자 확인을 기록한 뒤에만 취소 도구를 추가합니다. 이 예제의 True는 흐름을 보여 주는 로컬 실습값이며 실제 외부 동의가 아닙니다. 실제 서비스라면 인증, 권한, 중복 요청 방지 키, 감사 로그가 추가로 필요합니다.

도구 호출(tool call)은 구조화된 실행 요청이며 도구 메시지(ToolMessage)는 실행 결과와 호출 ID를 돌려주는 메시지입니다.

도식 읽기

모델 요청과 함수 실행 사이의 경계를 따라 읽습니다. 자율 반복은 Ch20 이후에 다룹니다.

6일부러 실패해 보기

조회는 상태를 바꾸지 않지만 취소 요청은 부작용이 있습니다. 확인 전에는 읽기 도구만 제공하고 확인 뒤에만 쓰기 도구를 추가합니다. 같은 질문과 입력을 유지한 채 비교 대상 한 가지를 바꿉니다. 출력에 나타난 값만 근거로 삼으며, 작은 표본으로 모든 모델과 질문에 같은 결과가 난다고 단정하지 않습니다.

출력 읽기

NOT_FOUND는 재시도하면 항상 해결되는 시스템 장애가 아닙니다. 먼저 주문 ID를 확인하거나 사용자에게 올바른 대상을 요청해야 합니다. 쓰기 도구 제공 여부는 모델 출력과 분리된 애플리케이션 상태가 결정합니다. 확인 전 목록에 취소 도구가 없다는 assert는 구성 실수를 찾는 작은 검사입니다. 실제 취소 API를 연결할 때는 인증된 사용자와 대상 주문의 소유 관계도 검사해야 합니다.

7주의할 점과 실무 메모

예상 가능한 업무 실패와 시스템 예외를 구분합니다. 내부 스택 추적은 운영 로그에 남기고 모델에는 다음 행동에 필요한 코드와 대상만 제공합니다.

확인 상태는 대화 문장만 보고 추측하지 않습니다. 애플리케이션의 확인 화면이나 승인 API가 남긴 신뢰 가능한 상태를 서버가 읽어야 합니다. 실습의 app_user_confirmed=True는 이 경계를 보여 주는 고정 예시이며 실제 사용자의 승인을 대신하지 않습니다. 확인이 취소되거나 시간이 지나면 쓰기 도구를 다시 목록에서 제거해야 합니다. 도구 실행 뒤에는 order_id와 요청 상태를 반환하고, 실제 운영에서는 요청 식별자와 실행 시각도 감사 로그에 남깁니다.

읽기와 쓰기를 분리해도 쓰기 함수 자체의 검증은 필요합니다. 도구 목록은 선택 가능성을 제한하고, 함수 내부 권한 검사는 최종 방어선을 제공합니다. 모델이 도구를 호출하지 않는 별도 경로에서도 같은 쓰기 API가 사용될 수 있으므로 권한 검사를 도구 설명에만 의존하면 안 됩니다.

  • 도구 설명과 인자 스키마도 모델 컨텍스트를 사용합니다.
  • API 가격과 모델 동작은 달라질 수 있으므로 실행 시점의 공식 정보를 확인합니다.

8정리와 다음 절

  • 읽기 질문의 도구 집합과 확인 뒤의 쓰기 도구 집합을 분리했습니다.
  • 관찰한 요청과 실행 결과를 구분해 기록했습니다.
  • 작은 표본의 결과를 다른 모델과 질문에 일반화하지 않습니다.
