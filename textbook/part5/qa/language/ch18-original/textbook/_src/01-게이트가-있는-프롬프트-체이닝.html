1학습 목표

  • 한 모델 출력이 다음 모델 입력이 되는 체인을 직접 구현할 수 있습니다.
  • 중간 결과의 필수 항목과 개수를 코드로 검사할 수 있습니다.
  • 검사에 실패한 체인을 다음 호출 전에 중단할 수 있습니다.

2이 내용을 배우는 이유

한 번의 긴 프롬프트에 기획과 집필을 모두 맡기면 어느 단계에서 조건이 빠졌는지 찾기 어렵습니다. 프롬프트 체이닝(prompt chaining)은 일을 작은 단계로 나누고 앞 단계의 출력을 다음 단계의 입력으로 사용합니다. 단계가 늘면 호출 비용과 지연도 늘기 때문에 중간 결과가 쓸 수 없는 상태라면 다음 호출을 막아야 합니다. 이 절의 질문은 ‘기획 결과에 독자와 단계가 빠졌을 때 비용을 쓰기 전에 어떻게 멈추는가?’입니다.

3앞에서 배운 내용

Ch 4에서 함수의 반환값을 다음 함수의 인자로 전달했고, Ch 16에서 호출 전에 입력과 비용을 검사했습니다. 여기서는 같은 파이썬 흐름 안에 실제 Responses API 호출을 두 번 연결합니다. LangChain이나 LangGraph는 사용하지 않습니다. OpenAI 클라이언트, responses.create(), response.output_text를 직접 확인합니다.

4핵심 개념

쉬운 예

기사 초고를 쓰기 전에 취재 메모를 확인하는 상황을 떠올려 봅니다. 메모에 제목만 있고 독자와 설명 순서가 없다면 초고를 쓰기 시작하지 않습니다. 빠진 항목을 채운 뒤에야 다음 작업으로 넘깁니다. 게이트는 이 확인표를 코드로 옮긴 것입니다.

정의

프롬프트 체이닝은 고정된 순서의 여러 모델 호출을 연결하는 패턴입니다. 중간 출력(intermediate output)은 다음 호출에 전달할 데이터이고, 게이트(gate)는 그 데이터가 정해 둔 조건을 만족하는지 검사하는 코드입니다. 이 실습의 outline_gate()는 title, audience, steps가 있으며 단계가 3개 이상인지 확인합니다. 모델이 판단한 품질 점수 대신 파이썬이 확인할 수 있는 형식을 기준으로 삼습니다.

기본 실행은 완전한 예시 사전이 (True, [])를 반환하는지 먼저 확인합니다. Before에서는 실제 모델에 제목만 요청했습니다. 출력은 {'title': '비밀번호 재설정 안내'}였고, 게이트는 audience와 3개 이상의 steps가 부족하다고 판정했습니다. 다음 호출 수는 0이었습니다. After에서는 세 필드를 요청해 게이트를 통과했고, 검사된 기획으로 4문장 안내문을 생성했습니다. 성공한 SDK 응답은 3개였으며 반환 사용량과 2026-09-10 가격으로 계산한 추정 비용은 0.001007달러였습니다.

6일부러 실패해 보기

Before의 실패는 테스트 함수가 임의로 예외를 만든 결과가 아닙니다. 실제 첫 호출의 출력이 후속 단계에 필요한 정보를 담지 못한 상태입니다. 잘못된 방식은 사전에 빠진 키가 있어도 문자열로 바꾸어 다음 프롬프트에 넣는 것입니다. 수정한 방식은 누락 목록을 출력하고 두 번째 호출을 실행하지 않습니다. After에서는 같은 게이트를 유지하고 첫 프롬프트의 산출 형식만 명확히 했습니다.

7주의할 점과 실무 메모

  • 게이트가 확인하는 것은 필드와 개수입니다. 단계 내용의 사실성이나 문장 품질까지 보장하지 않습니다.
  • max_retries=0으로 두어 표의 호출 수가 성공 응답 수와 일치하게 했습니다. 운영 환경에서 재시도를 켜면 HTTP 시도 횟수를 별도로 기록합니다.
  • 추정 비용은 SDK가 반환한 사용량과 확인한 단가의 곱입니다. 제공자 청구서의 실제 결제 금액으로 표시하지 않습니다.

8정리와 다음 절

  • 체이닝은 앞 호출의 출력을 다음 호출의 입력으로 연결합니다.
  • 게이트는 불완전한 중간 결과를 후속 호출 전에 막았습니다.
  • 형식 검사는 내용 평가와 범위가 다릅니다.

다음 학습과 이어지는 지점 — 다음 절에서는 입력을 여러 전문 경로 가운데 하나로 보내고, 분류값이 허용 목록 밖일 때 안전하게 처리합니다.
