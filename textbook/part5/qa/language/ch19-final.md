## 문맥 정독과 의미 보존

- 04절은 공개 도구 이름, 인자 스키마, 함수 동작, 질문, 모델, 온도, 도구 순서를 같게 유지하고 `description`만 바꾼 실험입니다. 두 조건은 모두 9/9이며 차이를 관찰하지 못했다고 기록했습니다. 합산 사용량은 입력 3,483토큰, 출력 366토큰, 추정 비용 미화 0.00425925달러입니다.
- 05절은 O101과 O103 호출을 각각 실행해 성공한 `ToolMessage` 두 개를 만들고 호출 ID가 같은지 확인합니다. 마지막 모델 호출의 사용량은 입력 290토큰, 출력 36토큰입니다. 추정 비용 미화 0.00074925달러는 첫 호출과 마지막 호출을 합한 값입니다. 한 응답에 호출 두 개가 있다는 사실을 실제 동시 실행의 증거로 확대하지 않았습니다.
- 06절은 모델 인자에 `confirmed`를 두지 않습니다. 애플리케이션이 확인한 주문 ID를 기록하며, 확인 전 O101과 O101 확인 뒤 O103을 직접 호출했을 때 모두 `PermissionError`가 발생합니다. O101의 성공 결과는 실제 데이터베이스를 변경하지 않는 모의 취소 요청입니다.
- 02절은 `OrderRecord`와 `TypeAdapter`로 반환 목록을 실제 검증합니다. 출력에서 O101/C001/paid/32000.0을 확인했습니다.
- 수치, 주문 ID, 모델명, 오류 코드, 함수 역할, 비교 조건을 원본과 실행 출력에 대조했습니다. 없던 성능·인과 주장을 추가하지 않았습니다.
