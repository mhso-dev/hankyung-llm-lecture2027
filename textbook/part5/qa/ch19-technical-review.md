# Ch19 독립 기술 검토

검토자: 집필자와 구분된 code-reviewer 에이전트. 판정: **코드·노트북 범위 APPROVE**. 도식 의미·편집 가능성 검증은 통합 담당자의 별도 범위입니다.

여섯 노트북의 43개 코드 셀은 최대 16줄이며 새 커널 실행과 HTML·저장 출력·내장 다운로드 대조를 통과했습니다. Ch 4의 fetch_orders 함수는 AST가 같고 주문 CSV도 원본과 같습니다. CSV SHA-256은 f2d1e3ee1e4f6d22fd1cf84b0c77242a66a344ae7925be74c5d471569366ef64입니다. 공개 묶음의 Ch19 data/orders.csv로 독립 실행합니다.

입력 스키마는 status의 paid·pending·cancelled 값과 limit 1..10 범위를 제한합니다. 실제 잘못된 인자의 ValidationError, 잘못된 호출 인터페이스의 TypeError와 수정 후 결과를 확인했습니다. 반환값은 OrderRecord와 TypeAdapter(list[OrderRecord])로 실제 검사합니다. 입력 검증과 반환 형식 검증을 구분합니다.

설명 비교는 함수 이름·스키마·동작·질문·모델·temperature·순서를 유지하고 설명만 변경합니다. 실제 두 조건은 모두 9/9이며 설명의 개선 효과가 관찰되었다고 일반화하지 않습니다. 병렬 호출 절은 한 AIMessage에 O101·O103 조회 요청 두 개를 받고 각각의 ID에 대응하는 ToolMessage를 구성했습니다. 실제 Python 함수 실행은 순차적이며 병렬 실행 속도 개선을 주장하지 않습니다.

쓰기 도구의 제공 여부는 신뢰하는 앱 상태에서 결정하고 실행 직전에도 확인합니다. 확인 상태는 주문 ID와 결합하며, O101을 확인한 뒤 O103을 요청하면 PermissionError로 거부합니다. 모델에 confirmed 인자를 주어 승인을 받는 구조를 사용하지 않습니다. 로컬 True 값은 교육용 상태 모의이며 실제 사람의 동의를 증명하지 않습니다.

검토 중 도식 편집본이 비어 있는 문제를 통합 담당자가 추가 발견했습니다. 코드 검토 승인에는 이 문제가 포함되지 않으며, 도식 교체·요소 대조·화면 검증 결과를 Part5 최종 검증 기록에 따로 남깁니다.

## 최종 실제 코드 재검토

기존 검토의 출력·메타데이터 중심 결론을 철회하고, 통합 보완 뒤 여섯 노트북의 실제 코드 셀을 다시 읽었습니다. 현재 코드 범위 CRITICAL/HIGH/MEDIUM 지적은 0건입니다. 모든 셀의 목적 주석과 함수 타입 주석, 실제 결과 assert를 확인했습니다. Ch 19의 01~05 fetch_orders AST는 Ch 4와 동일합니다.

04는 두 조건 모두 9/9, 입력 3,483·출력 366토큰, 추정 비용 0.00425925달러입니다. 05는 O101·O103 두 요청 및 호출 ID 대응을 검사했고 추정 비용은 0.00074925달러입니다. 06은 확인 전 직접 호출 거부, 확인한 O101의 모의 결과 생성, 확인하지 않은 O103 거부를 실제 실행했습니다. 취소 요청 결과는 교육용 사전이며 주문 DB를 변경하지 않습니다.

Ruff 노트북 검사 통과. 실습 환경은 실제 챕터 .venv이며 notebooks 폴더에서 여섯 파일을 새 커널로 실행했습니다. 실행 가능성은 외부 서비스의 향후 응답 동일성을 보장하지 않습니다. 최종 본문·도식·배포 대조는 통합 기록으로 연결합니다.
