## 2. 주제와 붙인 앞 절 기능 (b3 두 단락)

**주제(새 작은 일)**: 사내 공지 창구. 직원이 보낸 공지 요청 글 하나(「전 직원 계정에 2단계 인증을 적용한다는 공지를 올려 주세요.」 — 종류 이름이 글에 없음)를 분류하고, 게이트 자리의 검사를 지난 요청만 그 종류 갈래의 부분 요청으로 함께 써서 안내문을 만든다. 실행 1은 허용 목록 셋(보안·인사·회계), 실행 2는 허용 목록 하나만 바꿔 보안을 뺀다. 조립 함수 `serve_notice`가 흐름 결과 딕셔너리를, 기록 장치 `summarize_run`·`print_summaries`가 실행마다 한 줄 요약(허용 목록·종류·상태·요청 수·부분 요청 수)을 낸다.

- **붙인 기능 셋**(인계 권고 「요청 수가 코드로 정해지는 흐름(01·02·03)」):
  1. **01절 단계 잇기와 게이트** — 앞 단계(분류)와 뒤 단계(나눠 쓰기) 사이에 검사를 두고 통과한 것만 넘김. `ask_json`(요청 한 번 = 기록 한 줄)·`print_records`·요청 수 = 기록 줄 수.
  2. **02절 라우팅** — 분류 지시 글(06절 글에서 첫 문장만 바꿈)·요청 머리글·`check_route`(허용 목록·기준값 0.75)·갈래 표·되묻기 갈래. 창구 설정은 02절 라우팅 설정과 같은 여섯 칸.
  3. **03절 함께 보내기(나눠 쓰기)** — `write_sections`로 부분 요청을 함께 보내고 이음, `build_part_request`로 요청 글 미리 보기. **갈래 표의 값을 03절 나눠 쓰기 설정(지시 글·요청 머리글·부분)으로 둔 것**이 이 실습의 조립 자리.
  읽기에 이어 쓴 것(기능으로 세지 않음): 05절 설정 `copy()` · 06절 관찰 「앞의 셋은 요청 수를 코드가 정한다」 · 04절 `async def` 흐름 함수 안에서 동기 `ask_json`과 `await`를 섞는 모양.
- **고른 까닭**(b3 셋째 단락): 06절에서 두 번 모두 요청 수를 코드가 정한 세 흐름이라 두 실행의 요청 수를 실행 전에 셀 수 있고, 요청 수가 3~5번 안에 듦.
- **뺀 것과 까닭**(b3 셋째·넷째 단락):
  - 01절 흐름 함수 `run_gated_chain` 통째 — 기획·작성 요청이 둘 더 들어 5번을 넘음. 두 단계 사이에 검사를 두는 모양만 가져옴.
  - 04절 작업 나눠 맡기기·05절 쓰고 평가하기 반복 — 요청 수를 모델 답이 정함(4~6번·2~6번). 한 번만 넣어도 많게는 여섯 번(인계 5번).
  - 03절 투표 — 평가자 셋만큼 요청이 셋 더 듦.
  - 06절 비교 표·걸린 초·품질 칸 — 06절 실험 되풀이(규격 §7-2 5항). 이 절은 걸린 시간을 재지 않음(챕터 리드 결정 7), `make_row`·`time`을 쓰지 않음.
- **06 결론과 부딪히지 않게**: 「어느 패턴이 낫다」를 말하지 않고, 06절 관찰(앞의 세 흐름은 코드가 요청 수를 정함)을 두 패턴을 이은 흐름에서 다시 확인하는 데만 씀(b6 넷째 단락). 검사가 무엇을 받을지만 정하고 안내문 내용은 보지 않는다는 한계를 b4·b7에 적음.
