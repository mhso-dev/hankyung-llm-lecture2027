## 0. 첫 시도가 서비스에서 막힘 (요청 1번, 노트북 밖)

- 요청 글에 머리글 없이 문의만 넣고(JSON이라는 말은 지시 글에만) 보냄 → **`openai.BadRequestError` 400** 「Response input messages must contain the word 'json' in some form to use 'text.format' of type 'json_object'.」
- → 서비스는 **지시 글(instructions)이 아니라 요청 글(input)**에서 `json`이라는 말을 찾습니다. 01절 본문·인계는 「지시 글이나 요청 글에 JSON이라는 말」이라고 적었으나, 이번 확인으로는 **요청 글에 있어야** 합니다(01절 요청 글에는 모두 있었음). 02는 모든 요청 글 앞에 JSON이라는 말이 든 요청 머리글을 붙였습니다(노트북 3절 설명·b7에 한 문장). 03~06 인계에 적음.

## 3. 신뢰도가 낮게 나오는 문의 찾기 (탐색 — b7에 밝힘)

기준값 검사가 실제 모델 답에서 걸리는 장면을 찾으려고 후보 둘을 보냈습니다(규격 §3 「탐색 실행은 b7에」, 인계 「후보 입력 최대 둘」).

| 후보 | 확인 | 횟수 | 결과 |
|---|---|---|---|
| 「앱에서 결제 버튼을 누르면 화면이 멈춰요.」 | `probe02.py vague 5` | 5 | 다섯 번 모두 `기술` `0.98` → 기준값 검사에 안 걸림 → **쓰지 않음** |

→ 배송 문의는 **열 번 모두 「허용 목록 안의 종류 + 신뢰도 0.18~0.34 < 기준값 0.75」** — 흔들리지 않은 관찰. **종류 이름은 흔들림**(결제 8 · 기술 2) → 본문·그림에는 「허용 목록 안의 종류」로만, 이름은 결과 읽기 둘째 단락에만. 채택: Before 둘째 결함(신뢰도 낮은 분류로 갈래를 골라 `완료`)·After 되묻기 둘째 사례.
