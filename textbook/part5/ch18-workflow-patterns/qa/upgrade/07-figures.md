색 약속(01~06절 설계표를 이음): **손으로 적은 공지 요청 글 초록(tool)** · **우리가 코드로 적은 함수(`check_route`·`write_sections`) 파랑(flow)** · **실제로 부른 모델 요청만 보라(model)** — 분류 요청·부분 요청 · **출력으로 확인한 값(상태·분류·요청 수·입력 토큰) 노랑(measure)** · **두 실행 공통 사실 회색(클래스 없음)** · **빨강 0**(experiment 절, 멈추는 실패 없음 — 되묻기는 코드가 고른 갈래). `sequenceDiagram` 메모는 노랑, 세로줄 머리 상자는 기본 회색.
- **새 커널 두 번(A·B)에서 달랐던 값은 어느 그림에도 넣지 않았습니다**: 부분 기록 줄의 도착 차례(A 등록 → 적용 / B 적용 → 등록). 출력 토큰·안내문 글도 넣지 않았습니다(두 번은 같았지만 노트북 밖 다섯 번에서 적용 부분 출력 토큰 48·59·60, 안내문 130·149·151자로 흔들림).
- 그림 라벨의 수는 두 번(과 밖 다섯 번) 모두 같았던 값(분류 보안·신뢰도 0.99, 분류 입력 토큰 138, 요청 3·1, 부분 요청 2·0)과 코드에 적은 값(기준값 0.75)뿐입니다.
