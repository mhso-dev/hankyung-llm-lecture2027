## 3. 설계 — experiment

**학습 질문**: 같은 과제를 01~05절의 흐름 다섯에 넣으면 요청 수·토큰 수·걸린 초·코드 검사 결과는 어떻게 다를까요? 그 가운데 흐름의 모양이 정한 값과 실행마다 달라진 값은 무엇일까요? (옛 학습 목표 「같은 과제와 모델로 다섯 워크플로우 실행」·「호출 수·토큰·지연·품질 집계」·「비교 결과의 한계」를 이음)

- **조립만(규격 §2-7 3항)**: 도구 파일에서 `check_draft, route_question, run_gated_chain, run_orchestrator, run_write_judge_loop, write_sections`(알파벳 순) + `time` + `OpenAI`. 흐름 함수 본문은 다시 적지 않고 흐름마다 **설정 딕셔너리만** 이 과제에 맞게 적음. `write_sections`·`run_orchestrator`는 셀 맨 위 `await`, `run_write_judge_loop`는 동기.
- **같은 조건**: 공통 사실(01~05와 같은 131자) · 과제 글 「전 직원에게 보낼 2단계 인증 안내문을 120~180자로 쓰세요. 적용 날짜, 대상, 등록 방법, 문의처 주소를 담습니다.」 · 코드 검사 값 `grade_setup`(120·180·필수 말 넷, 05와 같은 말) · 규칙 문장 `rule_text`(05 쓰기 지시 글의 둘째 문장). 04 지시 글 셋·머리글 둘, 05 지시 글 둘·머리글 둘은 **04·05 생성기의 셀을 exec한 문자열과 `==` 대조해 같음**(`06-probe.md` §1). 03 지시 글은 「두 문장」→「한 문장」만 다름(대조함), 요청 머리글은 03과 같음. 02 분류 지시 글은 첫 문장·종류 이름만 다름.
- **흐름별로 과제를 넣은 자리**: 01 기획 요청 글·작성 머리글에 과제 글 + 공통 사실 · 02 요청 머리글 + `base_text`(분류와 갈래 답이 같은 요청 글) · **03 함수가 과제 글을 받지 않는 모양** → 과제의 담을 내용을 부분 셋(적용·등록·문의)으로, 글자 수를 「부분마다 한 문장」으로 옮김(b7에 밝힘) · 04 계획 머리글(04 그대로) + **종합 머리글에만 과제 글**(종합 요청이 글자 수를 보게, 작업 요청은 04 그대로) · 05 과제 글·공통 사실(05 그대로, 글자 수만 120·180).
- **품질 칸 = 코드 검사**(05 관찰 「평가 점수는 글자 수 어긋남을 가르지 못함」과 맞춤): `grade_notice` = 항목 수(1 + 필수 말 수) − `check_draft` 문제 수 → 0~5 정수. 평가 모델 점수가 아님(b4·b7). **05 흐름은 같은 검사를 정지 조건에 넣었으므로 「완료」면 품질 5가 구조로 정해짐** — 성능 차이가 아니라 검사를 둔 자리 차이라고 b4·b6·복습 3.
- **표 한 줄 `make_row(pattern, records, elapsed, state, notice, grade_setup)`**: `{"패턴", "요청 수": len(records), "토큰 수": total_tokens(records), "걸린 초": round(elapsed, 3), "품질", "상태"}`, 상태 「완료」만 `ok`, 그 밖은 한국어 상태 그대로(손 확인 `assert`로 「멈춤」 줄 확인 — 모델 답으로는 나오지 않음). 기록 칸은 01 그대로, 흐름마다 기록 목록 따로.
- **Ch 29 04 계약**(§6): 9절 표를 노트북의 **마지막 `" | "` 출력**으로(그 뒤 셀 출력에 `|` 없음, `print_records`는 가져오지 않아 노트북 전체에서 `" | "` 줄은 표 머리줄 + 다섯 줄뿐), 머리줄 옛 판 그대로 `pattern | calls | tokens | latency_s | quality/5 | status`, 패턴 이름 영어(`chaining`·`routing`·`parallel`·`orchestrator_worker`·`generator_evaluator`), `print(…, "|", …)`로 `" | "` 구분. 표 셀에서 `상태가 ok인 줄 수:`를 셈.
- **값 바꿔 보기(10절)**: 코드 검사의 최소 글자 수 120 → 100, 받은 안내문 다섯을 다시 검사(모델 요청 없음, 01~03절 값 바꿔 보기와 같은 모양). 결론은 「같은 안내문이라도 검사 값에 따라 품질 칸이 달라진다 → 검사 값은 결과를 보기 전에 정한다」. 출력에 `|` 없음.
- **처음 쓴 모양**(한 문장씩 풂): 흐름 함수 다섯을 한 노트북에서 조립 · 흐름 앞뒤 `time.perf_counter()`(03 모양을 흐름 전체에) · 표 한 줄 딕셔너리 · 목록에서 가장 큰 줄 찾기(`>` + `for`, `max` 대신) · `range(len(rows))`로 두 목록을 같은 자리끼리. `hand_records[:1]`(Ch 2 슬라이스, 04 `[:max_tasks]`와 같음).
