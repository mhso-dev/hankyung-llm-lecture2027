## 3. 설계 — experiment

**학습 질문**: 작업 목록을 코드에 미리 적지 않고 모델이 입력을 보고 정하면, 코드는 무엇을 검사하고 차례는 누가 정할까요? 종합 답에 공통 사실에 없는 연락처가 들어가면 코드로 어떻게 찾을까요? (옛 학습 목표 「오케스트레이터가 만든 하위 작업 목록 검사」·「작업 수만큼 워커 실행」·「고정 병렬화와 동적 분해의 차이」를 이음)

- **누가 무엇을 정하는가(Ch 17 01과 맞춤)**: 차례(계획 요청 → 작업 요청들 → 종합 요청)는 흐름 함수 `run_orchestrator` 코드가 정하고, 작업 수와 작업마다 맡을 일은 계획 모델이 쓴 작업 목록이 정함 → 요청 수 = 1 + 작업 수 + 1. **Ch 17 01 규칙으로 가르면 칸 「고른 쪽」이 모두 코드라 워크플로우**(b4 「누가 무엇을 정하는가」·노트북 9절 결과 읽기·복습 3), 모델이 쓴 작업 목록은 02 라우팅에서 모델이 쓴 종류처럼 「코드가 받아 쓰는 값」. Anthropic 글도 orchestrator-workers를 워크플로우로 둠(WebFetch 확인). 「얼마나」·「자율성」·「정도」 0건.
- **옛 손 값 대신 계산값**: 5절 `COMPARE_FIXED` — 03절 부분 목록 `['목적', '절차', '문의']`(03절이 코드에 적은 값)과 계획 모델의 작업 이름을 나란히 출력하고 `두 목록이 같은가: False`를 `==`로 셈.
- **작업 목록 거르기(01 게이트 모양)**: `pick_tasks(plan, max_tasks)` — 칸 「이름」·「맡을 일」이 모두 있는 작업만, `[:max_tasks]`(Ch 2 목록 자르기)까지. 최대 작업 수 4 · 최소 작업 수 2(옛 판의 2~4 범위 유지). 흐름 함수는 최소보다 적으면 작업 요청 없이 `{"상태": "멈춤", "작업", "답": [], "안내문": ""}`(옛 `raise ValueError` 대신 01의 「멈춤」). 거르기 규칙은 손으로 적은 계획 둘(작업 여섯 중 칸 빠진 하나 → 4 · 작업 둘 중 칸 빠진 하나 → 1)로 `assert`.
- **작업 요청**: `build_task_requests(instructions_text, task_head, fact, tasks)` → 요청 딕셔너리 목록 → 도구 파일 `ask_all_together`(03, 스레드 확인은 03이 함 — b7 한 문장). 기록 목록 하나를 계획·작업·종합 요청이 함께 씀(첫 줄 계획 · 가운데 도착 차례 · 끝 줄 종합, 기록 칸은 01 그대로). 받은 답의 칸 「작업」 차례를 작업 이름 차례와 `==`로 견줌(`True`, 넣은 차례).
- **종합**: 새 말 「종합(synthesis)」 — 03은 받은 글을 코드가 이었고(`join_parts`), 04는 작업 답을 `build_summary_request`(`join_parts`로 이어 붙임)로 모델에 한 번 더 보냄. 종합 요청도 계획 모델의 일로 봄(Anthropic 글의 orchestrator가 synthesize).
- **지어낸 연락처(절 작업 지시·인계 제안)**: ① 공통 사실에 문의처(03과 같은 공통 사실, `help@company.test`) ② 작업 지시 글 「공통 사실에 없는 날짜·연락처·절차는 지어내지 않습니다」(03 판) · 종합 지시 글 「공통 사실에 없는 날짜·연락처·번호는 쓰지 않습니다」 ③ **결정적 검사 `find_new_contacts(text, fact, patterns)`** — Ch 16 02 `re.findall`로 주소 모양 `[a-z]+@[a-z]+\.[a-z]+`와 숫자 모양 `\d+`를 찾고, 공통 사실에서 같은 정규식으로 찾은 값에 없는 것만 목록으로. - **값 바꿔 보기(10절)**: 과제 글 하나만 바꿔(「등록 방법만 짧게」) 9절 흐름 함수 실행 → 작업 넷 → 셋, 요청 6 → 5(예상 먼저). 흐름 함수가 처음 실행되는 자리이기도 함.

- **처음 쓴 모양**(한 문장씩 풂): 목록 자르기 `[:max_tasks]`(Ch 2 되짚기) · 정규식 `[a-z]`·`\.` · 한 기록 목록을 계획·작업·종합이 함께 씀 · 흐름 결과의 「멈춤」(01)을 `async def` 안에서. `raise`는 쓰지 않음.
