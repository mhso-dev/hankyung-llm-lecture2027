## 0. 실행 전에 적은 입력 (2026-09-24, 첫 요청 전)

공통: 모델 `init_chat_model("openai:gpt-5.4-mini", temperature=0, reasoning_effort="none")`(과정 표준 — `nbkit.key_and_model_cells`) · 시스템 메시지 없음 · 도구는 **하나** — 03절 이름 `get_order_by_id(order_id: str)` + 03절 자세한 판 독스트링(`author_03.GOOD_GET_DOC`, 문자열 그대로), 몸통 `return find_order(csv_path, order_id)`(도구 파일) · 도구 실행은 프로그램이 `도구.invoke(도구 호출 요청)`으로 **받은 차례대로** 한 건씩 · 첫 메시지는 `HumanMessage(질문)`.

- **P(주 입력)** — `bind_tools([get_order_by_id], parallel_tool_calls=True)`, 질문 「O101 주문과 O103 주문의 금액을 알려 줘.」(도구를 몇 번 부르라는 말은 넣지 않음).
  - 흐름: 첫 요청 → 도구 호출 요청을 차례로 실행해 도구 메시지 → `[HumanMessage, 첫 응답, 도구 메시지…]`로 둘째 요청.
  - 셀 표지: 첫 응답의 도구 호출 요청 수 · 도구 이름 · 인자 · 응답 글 길이 / 도구 메시지 수와 `tool_call_id` 목록 == 요청 `id` 목록 / 둘째 응답의 도구 호출 요청 수 · 쉼표를 뺀 답 글에 `32000`·`27000`이 있는가 / 사용량(입력·출력·캐시 입력).
- **M(값 바꿔 보기 후보)** — 같은 도구·질문에 `parallel_tool_calls=False`. 도구 호출 요청이 없는 응답이 올 때까지 실행하고 다시 보냄(바퀴 한도 5). 셀 표지: 응답마다 도구 호출 요청 수·이름·인자 · 모델 요청 수 · 마지막 답 글의 두 금액 · 입력 토큰 합.
- **P의 핵심 관찰(첫 응답에 도구 호출 요청 둘 · 둘째 응답이 도구 호출 없이 두 금액을 담음)이 5번 모두 같지 않을 때만** 아래 후보를 차례로 씁니다(이 절 지시 「후보 입력 최대 둘」).
  - C1: 질문만 옛 판 글 「O101과 O103 주문을 각각 조회해 줘. 각 주문마다 도구를 한 번씩 호출해.」로 바꿈(호출 수를 질문이 정하는 모양 — 쓰면 b7에 밝힘).
  - C2: 질문만 「O101 주문의 금액은 얼마고, O103 주문의 금액은 얼마야?」로 바꿈.
  - 둘 다 서지 않으면 노트북은 P로 쓰고 본문에 이번 실행에서 본 값을 사실대로 적음.

## 3. 입력 결정

- 노트북 주 흐름 = **P 그대로**, 값 바꿔 보기 = **M**(`parallel_tool_calls=False`, 바퀴 한도 5). 탐색으로 입력을 고른 것은 아니지만(첫 후보에서 관찰이 섬), 질문·도구 하나는 이 절이 흐름을 보여 주려고 정한 예라고 본문 b7에 밝힙니다.
- 결론에 쓸 관찰(새 커널 두 번에서도 같아야 씀): `True` 첫 응답 도구 호출 요청 2건(같은 도구 · 인자 O101·O103) · 도구 메시지 2개와 호출 ID 짝 · 둘째 응답 도구 호출 요청 0건 · 답 글에 두 금액 / `False` 응답마다 1건 · 모델 요청 3번 · 두 흐름의 입력·출력 토큰 합.
- 쓰는 도구는 한 건 도구 하나뿐입니다(옛 판의 쓰지 않는 도구 둘을 뺌). 같은 도구를 두 번 부르므로 도구 이름으로는 두 결과를 가를 수 없고, 호출 ID가 짝을 맞춘다는 점이 이 절의 핵심과 이어집니다.
