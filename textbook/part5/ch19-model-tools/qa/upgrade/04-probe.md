# 04절 흔들림 확인 (노트북 밖, 2026-09-24)

규격 §2-7 10번 끝 · 인계 `§03 → §04` 6항 · 절 작업 지시 「흔들림 먼저 확인(필수)」. 노트북을 쓰기 **전에** 두 조건의 요청을 노트북 밖에서 조건마다 **5번씩** 보냅니다.

## 0. 실행 전에 적은 입력 (2026-09-24, 첫 요청 전)

공통: 모델 `init_chat_model("openai:gpt-5.4-mini", temperature=0, reasoning_effort="none")`(과정 표준 — `nbkit.key_and_model_cells`) · `model.bind_tools(도구 셋, parallel_tool_calls=False)` · 메시지는 사용자 질문 한 줄뿐(시스템 메시지 없음) · 도구 이름은 두 조건 모두 **`tool_a`(목록, 인자 `status`) · `tool_b`(한 건, 인자 `order_id`) · `tool_c`(합계, 인자 `status`)** · 몸통은 도구 파일 `fetch_orders`·`find_order`·`sum_orders`(도구는 실행하지 않음) · 채점은 **도구 호출 목록의 이름만**(인자는 보지 않음, 기대 도구는 실행 전에 손으로 정함).

- **P(주 입력)** — 짧은 판 = 03절 짧은 판 독스트링 셋(「주문을 찾습니다.」·「주문 정보를 봅니다.」·「주문 금액을 봅니다.」) / 자세한 판 = 03절 자세한 판 독스트링 셋(`author_03.GOOD_LIST_DOC`·`GOOD_GET_DOC`·`GOOD_SUM_DOC`, 문자열 그대로).
  - 질문 셋과 기대 도구: Q1 「결제된(paid) 주문 목록을 보여 줘.」 → `tool_a` · Q2 「O103 주문의 금액은 얼마야?」 → `tool_b` · Q3 「결제된(paid) 주문은 모두 몇 건이야?」 → `tool_c`.
  - 값 바꿔 보기 후보 M: 짧은 판 셋에서 **합계 도구 `tool_c`의 설명 하나만** 자세한 판으로 바꾼 판(`tool_a` 짧은 · `tool_b` 짧은 · `tool_c` 자세한), 같은 질문 셋.
- **P에서 두 조건의 대비가 5번 모두 같게 서지 않을 때만** 아래 후보를 차례로 씁니다(이 절 지시 「후보 입력 최대 둘」).
  - C1: 설명·이름은 P 그대로, Q3만 「결제된(paid) 주문이 몇 건인지만 알려 줘.」로 바꿈.
  - C2: 이름·질문은 P 그대로, 짧은 판 설명을 셋 모두 같은 한 문장 「주문 정보를 봅니다.」로 바꿈(자세한 판은 그대로).
  - 둘 다 서지 않으면 노트북은 P로 쓰고 본문에 「이번 실험에서는 두 조건의 차이가 없었다」를 사실대로 적음(Ch 16 06 선례).

## 3. 입력 결정

- 노트북 질문 셋·기대 도구·두 판 설명 = **P 그대로**, 값 바꿔 보기 = **M**. 탐색으로 입력을 고른 것은 아니지만(첫 후보에서 대비가 섬), 질문 셋·기대 도구·이름 가림은 이 절이 흐름을 보여 주려고 정한 예라고 본문 b7에 밝힙니다.
- 결론에 쓸 관찰(새 커널 두 번에서도 같아야 씀): 건수 질문에서 짧은 판은 목록 도구 `tool_a`, 자세한 판·M은 합계 도구 `tool_c` · 목록·한 건 질문은 모든 판에서 같은 도구 · 입력 토큰 차이.
- 기대 도구는 03절 자세한 판 설명의 사용 조건(「주문 목록 대신 개수나 합계를 물을 때 씁니다」)을 보고 실행 전에 정한 값입니다. 목록 도구를 골라도 프로그램이 줄 수를 세면 건수는 답할 수 있으므로, 「틀린 도구」가 아니라 「이 절이 정한 역할 나눔과 다른 도구」로 적습니다.
