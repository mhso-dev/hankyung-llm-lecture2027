## 2. 수정 전 주요 문제

## 3. 설계 — experiment (결정과 까닭)

- **도구 하나, 질문 하나**: 03절 이름 `get_order_by_id` + 03절 자세한 판 독스트링(`author_03.GOOD_GET_DOC`). 정의 셀은 `author_03.DETAIL_GET`과 **첫 줄 주석만 다름**(생성기 `assert DEF_TOOL.split("\n", 1)[1] == author_03.DETAIL_GET.split("\n", 1)[1]`) → 본문은 「03절 자세한 판 한 건 도구와 같은 정의」. 04의 이름 가림은 실험 장치라 쓰지 않음(인계 2항). 쓰지 않는 도구는 빼서 **목록 `tools = [get_order_by_id]`** — 같은 도구를 두 번 부르니 도구 이름으로는 두 결과를 가를 수 없고, 호출 ID가 짝을 맞춘다는 핵심과 이어짐.
- **질문** 「O101 주문과 O103 주문의 금액을 알려 줘.」 — 도구를 몇 번 부르라는 말 없음(옛 질문의 「각 주문마다 도구를 한 번씩 호출해」는 뺌, b7에 밝힘). 첫 메시지는 Ch 13 04 모양 `HumanMessage(content=question)`, 목록에 `append`(별표 풀기·딕셔너리 메시지 없음), 답 글은 `.content`.
- **「병렬」은 제목에만**: 노트북 1절·b2에 「제목의 「병렬 호출」은 한 응답 안에 도구 호출 요청이 여럿 오는 것을 뜻합니다」 한 번씩. **Ch 18 03 「함께 보내기」와 다르다는 문장**을 노트북 3절 결과 읽기·b3에(「함께 보내기는 모델 요청 여럿을 동시에 보내는 일 → 이 절에서 여럿인 것은 응답 하나에 담긴 도구 호출 요청이고 모델 요청은 한 번」), 복습 4번이 같은 구분을 물음. 프로그램은 `for`로 차례로 실행하고 걸린 시간은 재지 않음(b4 「차례로 실행하고 함께 보내기」·b7).
- **새 말 다섯**(meta 「새 용어 5」): 도구 실행 · 도구 메시지(`ToolMessage`) · 호출 ID(`tool_call_id`) · 여럿 담기(`parallel_tool_calls`) · 도구 찾기 표(`tools_by_name`). 처음 쓰는 자리에서 한 문장씩(여럿 담기 3절, 도구 실행·도구 찾기 표 4절 머리, 도구 메시지·호출 ID 4절 `BY_HAND` 결과 읽기).
- **`.invoke(도구 호출 요청)` 대 `.invoke(칸 args)`**: 요청을 통째로 넣으면 `ToolMessage`, 칸 `args`만 넣으면 01절처럼 `dict`(두 셀로 보임). 근거는 설치한 langchain-core 1.6.2 `tools/base.py` — `_is_tool_call`(1269행, `type == "tool_call"`)·`_prep_run_args`(1352행, 칸 `id`를 꺼냄)·`_format_output`(1390행, `tool_call_id`가 있을 때만 `ToolMessage`)·`_stringify`(1471행, `json.dumps(ensure_ascii=False)`). 노트북에서 실행한 것은 두 모양의 결과뿐이고 소스 행은 b7·b10에만.
- **`parallel_tool_calls`**: `True`면 요청 본문에 `parallel_tool_calls: true`, 인자를 빼면 칸 자체가 실리지 않음(langchain-openai 1.6.0 `chat_models/base.py` 2427~2428행 + 보내지 않은 본문 확인). 「인자를 빼면 OpenAI 기본값에 맡긴다」는 소스·본문으로만 확인했다고 3절 결과 읽기·b7에 밝힘.
- **값 바꿔 보기(6절) = `parallel_tool_calls=False`** — 바꾼 값 하나, 질문·도구 그대로. 여러 번 오가는 일은 함수 `ask_until_answer`(Ch 17 03 「바퀴 한도」, `turn_limit = 5`, 도구 호출 요청이 없는 응답에서 멈춤)로. 7절에서 두 흐름의 요청 수·토큰 합(`sum_usage`)과 예상 비용(`estimate_cost`)을 견줌.
- **`assert`는 코드가 옮겨 적는 값에만**: `PAIR` 셀 `assert request_ids == message_ids`(요청 `id` 목록과 도구 메시지 `tool_call_id` 목록 — 길이 포함). 도구 호출 요청 수·인자·답 글에는 걸지 않고 출력만, 답 글은 **코드로 센 표지**(`check_amounts` — 쉼표를 뺀 답 글에 도구 메시지의 금액 숫자가 있는가)만 결론에. 그 밖의 `assert`는 준비 셀 둘(자리 찾기·키)뿐.
- **비용**: Ch 6 06 `estimate_cost`를 도구 파일에서 가져오고 요금은 이름 있는 변수(`input_rate = 0.75` 등, 식 안 숫자 없음), 말은 「예상 비용」(「추정」 0건). 합친 사용량에 캐시 입력 칸이 없어 함수가 입력을 모두 일반 입력 요금으로 센다는 것과, 노트북 밖 확인의 캐시 입력이 26/26 0이었다는 것을 결과 읽기·b7에 밝힘.
- **준비 셀**: 설치(04와 같은 다섯, 잠금 판) → 가져오기(`import json`·`os` + `from order_tools import estimate_cost, find_order, tool_call_names`, 알파벳 순, 고정 세 문장 + 커널 폴더 한 문장) → 자리 찾기(01~04와 글자 같음 — 생성기 `assert PATH == author_03.PATH`) → 키(`nbkit.KEY`) → 모델 셀(`nbkit.key_and_model_cells("openai:gpt-5.4-mini")`, 실행일 한 줄).
- **비유**: 「식당 주문 전표와 내주는 창」 — 전표 한 장(응답 하나)에 같은 국수 두 그릇(같은 도구 요청 둘), 주방(프로그램)이 차례로 만들어 그릇마다 전표와 같은 색 집게(호출 ID)를 꽂고 창으로 함께 내보냄(도구 메시지 둘을 한 요청에). Ch 20 02 「택배 송장 번호」와 겹치지 않게 번호 없이 색으로만.
