### 01이 푼 문장 (뒤 절은 되풀이하지 말고 「01절에서 본 것처럼」으로)

- **도구(tool)** = 「모델이 필요할 때 고를 수 있게 이름·설명·입력 형식을 붙여 감싼 함수」(식당: 주방 요리를 메뉴판에 한 줄로 올리는 일).
- **데코레이터 줄** = 「함수 위에 붙여 그 함수를 다른 것으로 감싸는 표시」 · 「`@tool` 줄이 아래 함수를 도구로 등록합니다」 · 「파이썬은 함수를 만든 뒤 곧바로 `tool`에 넣고, `tool`이 만든 도구를 같은 이름에 담습니다(Ch 2 09 `@` 줄 규칙)」 → 그래서 이름에 함수가 아니라 도구(`StructuredTool`)가 남고, **괄호로 부르면 `TypeError: 'StructuredTool' object is not callable`**(01 Before). 링크 `../../part1/ch02-python/09-데코레이터와-컨텍스트-매니저.html`.
- **독스트링(docstring)** = 「함수 첫 줄에 큰따옴표 세 개로 감싸 적는 설명 글」 → 도구 설명(`.description`)이 됨(`.__doc__`와 같음 `True`). 독스트링도 `description=`도 없으면 오류(설치판 langchain-core 1.6.2 `structured.py` 289행 — **노트북에서 실행하지 않음**).
- **타입힌트** = Ch 2 07(「값을 검사하지 않는다」) → 도구에서는 입력 형식의 자료형(`str` → `'type': 'string'`). **빼도 도구는 만들어지고 자료형만 빠짐**(01 값 바꿔 보기: `{'status': {'title': 'Status'}}`·명세 `{'status': {}}`, 결과 같음). LangChain 문서는 「Type hints are required」.
- **`.invoke(인자 딕셔너리)`** = 키는 입력 형식의 인자 이름, 값은 넣을 값(식당: 주문 전표를 창에 넣기). 「04절부터는 모델이 도구 이름과 이런 인자 딕셔너리를 적어 보내고, 도구를 부르는 일은 프로그램이 합니다」(**04·05가 참이 되게** — `tool_calls`의 `args`).
- **도구 명세** = `convert_to_openai_tool(도구)`가 내놓는 `{'type': 'function', 'function': {'name', 'description', 'parameters': {'properties', 'required', 'type': 'object'}}}`. 「설치한 langchain-openai 1.6.0 소스를 보면 `bind_tools`도 도구마다 이 함수로 명세를 만든다」(`chat_models/base.py` 2435~2436행) — **04가 실제 요청으로 확인할 몫**.
