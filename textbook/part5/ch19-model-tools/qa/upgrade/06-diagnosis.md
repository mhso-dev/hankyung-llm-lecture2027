## 3. 설계 — paired (결정과 까닭)

- **한 흐름에 결함 둘 — 제목의 「오류」와 「읽기 쓰기 분리」**. Before = **05절 방식 그대로**: 읽기 도구와 쓰기 도구를 **한 목록**으로 `bind_tools`, 읽기 도구의 `handle_tool_error`는 기본값. After = **같은 도구 객체**에 `handle_tool_error = True` 한 줄 + **`pick_tools(읽기 목록, 쓰기 목록, person_confirmed)`**로 나눈 목록. 값 바꿔 보기 = `person_confirmed` 하나만 `True`. 인계대로 **전역 확인 상태를 도구가 읽지 않고, 확인 값이 도구 목록 구성을 정합니다**(§2-7 4항과 부딪히지 않음).
- **읽기 도구** `get_order_by_id(order_id: str)` — 03 자세한 판 설명(`author_03.GOOD_GET_DOC`)에서 **넷째 문장 끝만** 「없으면 None을 내놓습니다」 → 「없으면 오류를 냅니다」(생성기 `assert READ_DOC.rsplit(", ", 1)[0] == GOOD_GET_DOC.rsplit(", ", 1)[0]`). 몸통: 도구 파일 `find_order` → 없으면 `raise ToolException("주문 번호 " + order_id + "에 맞는 주문이 없습니다. 주문 번호를 다시 확인해 주세요.")`(Ch 16 01 `raise`와 같은 모양, 오류 글에 다음 할 일). `ToolException`은 `from langchain.tools import ToolException, tool`로 가져옴(설치판에서 `langchain.tools`가 내보냄 — 확인).
- **쓰기 도구** `cancel_order(order_id: str)` — 03 자세한 판 네 기준(하는 일·사용 조건·인자·내놓는 값) 설명. **몸통은 이 절의 흉내**: `{"order_id": order_id, "cancel_requested": True}`만 내놓음. 노트북 준비물·4절·b7에 「파일을 바꾸지 않음 · 실제 서비스라면 이 자리에서 주문 상태가 바뀜」, 8절 끝 셀이 CSV의 O101 상태 `paid`를 다시 읽어 `assert`(CSV에서 정해지는 값). Before에서는 **실행하지 않음**(첫 응답만 봄) — 흉내를 실제 쓰기처럼 쓰지 않도록.
- **Before 두 셀**: ① 취소 질문 「O101 주문을 취소해 줘.」 한 번(첫 응답의 도구 호출 요청만) ② 「O999 주문의 금액을 알려 줘.」를 05 `ask_until_answer`로 → 도구 안 `ToolException`이 `run_tool_calls`를 뚫고 올라와 멈춤, 메시지 목록 2(질문·첫 응답). Ch 2 05 모양 `try/except ToolException as error` + 「오류를 받지 않는 실제 프로그램이라면 여기서 멈춥니다」(챕터 리드 결정 7).

## 12. 강사 확인 대상

1. **Before 쓰기 결함을 코드 쪽 사실로 세움** — 노트북 두 커널 모두 첫 응답이 `cancel_order`였지만 노트북 밖 같은 요청 11번 중 1번이 읽기 도구 먼저라, 결론·그림은 「명세에 쓰기 도구가 실려 사람 확인 없이 고를 수 있다」로 한정. 학생에게 「요청이 왔다」가 약하게 읽히지 않는지.
