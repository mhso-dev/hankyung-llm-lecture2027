## 칸 순서 확인 (PNG를 직접 열어 본 결과)

- `03-1`: 맨 위 초록 기록 상자에서 실선이 **오른쪽** 파란 `ask_next`로 내려가고, 보라 모델 → 파란 `stop_reason`으로 이어집니다. `stop_reason`에서 점선 둘이 **왼쪽 아래** 파란 `run_tool`(「까닭 없음」)과 **오른쪽 아래** 노란 멈춤(「까닭 있음」)으로 갑니다. `run_tool`에서 실선이 왼쪽 가장자리를 따라 맨 위 초록 상자로 되돌아가고(라벨 「결과를 기록에 더함」), 초록 상자 **바로 아래**로 점선 「바퀴를 다 쓰면」이 회색 「멈춤 바퀴 한도」로 갑니다. 되돌아가는 실선이 라벨 글자 사이를 지나지만 읽는 데 지장은 없습니다.
- `03-2`: 왼쪽 칸 도착 문의(노랑 셋, 위에서 아래), 오른쪽 칸 환불 문의(노랑 넷), 맨 아래 가운데 회색 상자.
- `03-3`: 첫 렌더에서 오른쪽 회색 상자의 「고르면」이 저절로 한 줄로 떨어져, 라벨을 네 줄로 미리 나눠 다시 렌더했습니다(폭 536 → 497). 위에서 아래로 초록 → 파랑 → 보라 → 점선 둘(왼쪽 「등록」, 오른쪽 「조회」) → 회색 둘 → 맨 아래 노랑.
- `03-4`: 첫 렌더에서 회색 상자 셋째 줄에 「확인」만 떨어져, 「주문 조회」·「그다음 환불 규정 확인」으로 미리 나눠 다시 렌더했습니다. 왼쪽 칸 사람 확인 있음(초록 → 노랑), 오른쪽 칸 사람 확인 없음(초록 → 노랑), 맨 아래 가운데 회색.

## 라벨에 넣지 않은 값 · 숫자 표기

- **새 커널 두 번(실행 A 15:23:51 · B 15:24:26 UTC)에서 달랐던 값은 라벨에 넣지 않았습니다**: 9절 바퀴 한도 2 기록(A는 두 바퀴 뒤 `바퀴 한도`, 모델 요청 2 · B는 첫 바퀴에 `환불 요청 등록`을 골라 `사람 확인`, 모델 요청 1 · 표의 구조 A `에이전트 후보` · B `워크플로우`). `03-3`은 두 갈래를 **코드의 셈**(「…을 고르면 …로 멈춤」)으로만 회색에 적고, 두 실행 모두 같은 성질(모델 요청 두 번 이하 · 멈춘 쪽 코드)만 노랑에 넣었습니다. 모델이 쓴 까닭 문장도 넣지 않았습니다.
- **개수는 한글로**: 「바퀴를 두 번까지만」·「두 번 이하」·「앞 두 바퀴」·「셋째·넷째 바퀴」. **값은 숫자로**: 바퀴 번호 `1`·`2`·`3`, 모델 요청 `2`·`3`·`4`, 바퀴 한도 `4`·`2`(모두 한 자리, 노트북 출력의 번호 칸·표 칸에 있음). 두 자리 숫자는 `03-4`의 「02절」 하나이고 출력 줄 `02절 코드 차례와 같은가: True`에 있습니다.
- 파란 상자의 함수 이름은 노트북 정의 셀의 이름 그대로입니다. 보라 상자의 모델 이름 `gpt-5.4-mini`는 2절 출력 `모델 이름: gpt-5.4-mini`와 같습니다.
