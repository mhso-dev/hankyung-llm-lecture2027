## 4. 설계 — experiment

**학습 질문**: 남이 공개한 단계 차례 자료만 읽고 무엇을 알 수 있을까요? 다음 단계를 누가 골랐는지는 알 수 있을까요? 그렇다면 자기 흐름의 자율성은 무엇으로 진단할까요?

- **옛 학습 질문 유지·바꿈**: 「공개 자료에서 모델 판단·도구 사건·프로그램 제한 구분」 → 「단계 차례에서 보이는 것(차례·결과·실패 뒤 다음 한 일)과 보이지 않는 것(고른 쪽·까닭·걸린 초·토큰)」 + 코드가 막는 경계(SWE-agent 문법 검사기)와 글로 준 지시(mini 시스템 메시지)의 차이. 「공개 추적 단서와 원시 로그의 증거 수준」 → 새 말 「추출본」·「증거 수준」·「공개 추적 단서」. 「중간 프로젝트 진단표 작성」 → **이 챕터 03·04절 환불 문의 흐름**을 진단(중간 프로젝트는 과정 요약·계약에 없어 자료의 예시 이름으로만 둠).
- **자료 읽기**: `read_json`(UTF-8) → 추출본 둘의 출처(저장소·커밋 앞 일곱 자리·라이선스·지문 앞 열두 자리) → `print_events`(번호·한 일·결과·근거) → `count_steps`(영어 칸) → `print_after_failures`(실패 단계와 바로 다음 한 일) → 자료에 적힌 짝·경계·한계.
- **알 수 없는 칸**: `key_names`로 두 자료 칸이 넷뿐임을 보이고, `to_steps(events, chooser)`로 01 기록 모양에 옮겨 모르는 칸 「고른 쪽」을 「모름」으로 채우면 01 `classify`가 **워크플로우**를 냄 → 9절 값 바꿔 보기에서 「모델」로 채우면 **에이전트 후보**. 판정이 자료가 아니라 채운 값에서 나옴을 실행으로 보임. 칸 「한 쪽」은 「자료의 한 일은 모두 명령을 실행한 일」이라 `도구`로 적음(노트북 6절에 밝힘).
- **제품 문서 단서**: `count_control(clues, word)`로 칸 `control`에 「모델」·「코드」·「미확인」이 든 단서 수 → Deep Research 5·0·0 / Claude Code 0·4·0 / Codex 0·1·2. 「제품의 자율성 차이가 아니라 문서가 설명하려는 쪽의 차이」로 읽음. Claude Code `max-turns stop`을 03 바퀴 한도와 이음.
- **진단표**: 작성 예시(자료) 칸 열하나를 읽고 옛 말을 풂 → 빈 진단표 CSV(9행, 답 빈 칸 9 — `count_steps`로 셈) → 이 절에서 정한 답 아홉·근거 아홉 → 표 출력 → 「워크플로우 유지」. 근거는 02 코드 차례 · 03 노트북 10절(모델도 같은 차례) · 03 바퀴 한도·사람 확인·끝 고르기(예산 없음) · 04 요청 수와 입력 토큰(품질 평가 안 함) · 워크플로우 실패 기록 없음.
- **값 바꿔 보기 둘**: ① 모르는 칸을 채우는 값 「모름」 → 「모델」(판정 워크플로우 → 에이전트 후보) ② 보이는 단계 수 14 → 9(`[:shown_count]` — 실패 0, 실패 뒤 짝이 사라짐, 「공개 범위 밖은 모른다」). 둘 다 실행 전 예상 → 실행 → 「예상과 맞았습니다」.
- **`assert`**: 자리 찾기 셀 하나(자료 폴더를 못 찾을 때 안내). 자료 값에는 걸지 않음(옛 판 여섯은 출력·결과 읽기로 대신 확인).
- **새 말 다섯**(meta 「새 용어 5」): 추출본(extract) · 증거 수준 · 공개 추적 단서 · 코드가 정한 경계 · 자율성 진단표. 이어 쓴 말: 단계 차례(04) · 결정 주체·고른 쪽·에이전트 후보(01) · 바퀴 한도·사람 확인(03) · 실행 추적(Ch 15 05) · 지문(Ch 7 08) · 커밋(Ch 3). 설명으로만 푼 말: 시범 기록(demonstration) · 테스트에 쓰려고 저장해 둔 파일(fixture) · 종료 코드(`returncode`) · 역할 이름 `assistant` · MIT 라이선스.
- **처음 쓴 모양(한 문장씩 풂)**: 딕셔너리를 `for`로 돌아 칸 이름 받기 · 글에 `in`(낱말이 들어 있는지) · `not in` · `[:n]`·`[-1]` · `with open(…, encoding="utf-8")`+`read()` · `is not None` · `os.path.exists`(Ch 10부터의 경로 셀 모양).
- **노트북 차례**: 제목 → 오늘 볼 그림(`05-1`) → 1 준비(가져오기 · 자리 찾기) → 2 공개 단계 차례 자료(`read_json`·자료 이름·출처) → 3 SWE-agent 시범 기록(`print_events`·단계 열넷·결과별 수) → 4 실패 뒤 다음 한 일(`print_after_failures`·자료에 적힌 짝·경계·한계) → 5 mini-SWE-agent 테스트 파일(단계 열·결과별 수·실패 뒤 둘·마지막 단계·경계) → 6 단계 차례만으로 알 수 없는 것(`key_names`·`to_steps`·「모름」 → 워크플로우) → 7 제품 문서의 공개 추적 단서(`count_control`·표·Claude Code 단서) → 8 자율성 진단표(작성 예시·빈 진단표·답·근거·표) → 9·10 값 바꿔 보기 → 정리.
