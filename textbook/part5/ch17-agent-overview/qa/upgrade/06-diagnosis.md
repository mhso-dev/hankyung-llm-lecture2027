## 2. 주제와 붙인 앞 절 기능 (b3 두 단락)

**주제(새 작은 일)**: 손님이 주문 A-1024를 **지금 환불할 수 있는지만** 묻는 새 문의를 03절 루프로 처리하며 04절처럼 요청마다 재고, 01절 규칙으로 기록을 가른다. 실행 1은 바퀴 한도 4(03·04절 값), 실행 2는 바퀴 한도 하나만 2로 바꾼다. 조립 함수 `serve_inquiry`가 실행마다 실행 요약(바퀴 한도·모델 요청·입력 토큰·도구 차례·멈춘 까닭·구조) 한 딕셔너리를 내놓고, 기록 장치 `print_reports`가 한 줄로 보인다.

- **붙인 기능 셋**(지시서 예 「01 분류 + 03 루프·정지 조건 + 04 요청 수 세기」 그대로):
  1. **01절 가르기** — `count_steps`(모델 요청 수 = 칸 「한 쪽」이 모델인 줄 수, 02절 약속 · 모델이 고른 단계 수), `classify`(구조).
  2. **03절 루프와 정지 조건** — 사람 확인(`confirm_tools`)·바퀴 한도(`turn_limit`)·`stop_reason`·멈춤 줄(`run_measured_loop` 안).
  3. **04절 요청마다 재기** — `run_measured_loop`(03 `run_loop`와 같은 차례 + 고른 줄에 토큰·걸린 초), `total_of`(입력 토큰 합), `print_measures`.
  재료·읽기에 이어 쓴 이름(기능으로 세지 않음): 02절 `tool_names` · 03절 `run_tool`·`build_request`·`turn_lines`·`print_results` · 03·04절 도구 이름 셋·머리글 네 줄.
- **고른 까닭**(b3): 모델에게 다음 단계를 맡긴 흐름에서 꼭 볼 것은 누가 골랐는지(01)·무엇이 멈췄는지(03)·얼마나 들었는지(04).
- **뺀 것과 까닭**(b3 두 단락):
  - 02절 진단 질문·워크플로우 점수 — 실행 전에 사람이 답을 적는 진단이라 실행 흐름에 넣지 않음.
  - 04절 (가) 코드 차례 흐름과 견주기 — 04절 실험 그대로(규격 §7-2 5항). b6에서 「코드 차례로 두 도구를 부르면 다음 행동을 고르는 모델 요청은 0번 · 이번에 실행하지 않았다」로 셈만.
  - 04절 걸린 초·출력 토큰·예상 비용 — 출력은 되지만 실행마다 달라 결론에 쓰지 않음(규격 §7-2 6항). 예상 비용은 계산하지 않음.
  - 03절 사람 확인 빼기 — 03절 10절 되풀이이고 요청이 네 번 더 들어 3~5번을 넘음.
  - 05절 공개 자료·진단표 — 남이 남긴 기록(고른 쪽을 모름). 05 교훈대로 고른 쪽을 아는 자기 기록만 가른다. 05 결론(「환불 문의 흐름에는 워크플로우 유지」)과는 b3 마지막 단락·b6 다섯째 단락으로 이음(권고를 바꾸려는 것이 아니다 · 단계를 미리 알면 워크플로우로 충분 · 같은 방향).
- **손으로 적은 새 값**(실행 전에 정함, 출처를 출력과 b7에): 새 문의 `"주문 A-1024를 지금 환불할 수 있는지 알려 주세요."`와 예상한 도구 차례 `["주문 조회", "환불 규정 확인"]`(03절 도구 흉내 결과 글을 보고 정함) — 출력 줄 `출처: 이 절에서 실행 전에 적은 글과 예상`·b7 첫 항목. 모델 없이 만든 한 바퀴 기록(`turn_lines("주문 조회", "")`)도 「고른 이름은 이 절에서 정한 것」으로 밝힘(노트북 3절).
