## 5. 본문에 반영한 것

- **결론(b6 첫 단락·b8 정리·노트북 정리)과 그림 라벨**: 두 실행이 같았던 7·8·10절 값만(도착 문의 요청 2 · 모델이 끝을 고름, 환불 문의 요청 3 · 사람 확인, 사람 확인을 빼면 요청 4 · 등록이 불림 · `02절 코드 차례와 같은가: True`).
- **9절**: 결과 읽기 첫 단락은 두 실행 공통 성질만(마지막 줄이 칸 「고른 쪽」 `코드`인 멈춤 줄 · 모델 요청이 한도 2를 넘지 않음). 둘째 단락 「이번 실행에서는」에 교재 출력(첫 바퀴 등록 → 사람 확인 · 요청 1 · 구조 워크플로우와 그 까닭)과 셈 「첫 두 바퀴에 8절처럼 … 골랐다면, 바퀴 한도로 멈추고 모델 요청은 2번이 됩니다」 · 「이 줄은 모델 요청 2, 멈춘 까닭 바퀴 한도, 에이전트 후보가 됩니다」. 그림 `03-3`은 두 갈래를 코드의 셈으로만(회색) 그리고 두 실행 공통 값(요청 두 번 이하 · 멈춘 쪽 코드)만 노랑. b6은 「바퀴 한도를 2로 낮추면 모델이 무엇을 고르든 요청이 두 번을 넘지 않는다」(코드가 정하는 성질)와 「9절 첫 바퀴 선택은 두 실행에서 달라 결론에 쓰지 않음」, 복습 3을 이 성질로 바꿈.
- **b7**: 확인 1 결과 + 「교재 출력의 9절 첫 바퀴에서는 8절과 같은 요청 글에 모델이 환불 요청 등록을 골랐습니다. 같은 요청도 실행한 때에 따라 모델이 고르는 행동이 달라질 수 있습니다」 + 확인 2 결과. 준비물·b5·b7의 요청 수는 실행마다 달라져 「예상대로 고르면 12번 · 바퀴 한도 때문에 15번을 넘지 않음」으로(교재 출력 B는 11번 · A는 12번).
- 모델이 쓴 글(칸 「다음」·「까닭」)에는 `assert`를 걸지 않았습니다. `assert`는 손으로 적은 기록 한 줄로 `stop_reason`을 확인하는 셀 하나뿐입니다.
