## 4. 설계 — experiment

**학습 질문**: 같은 문의를 코드가 도구 차례를 정한 워크플로우와 모델이 다음 행동을 고르는 루프로 처리하면 모델 요청 수·토큰 수·걸린 시간은 어떻게 다를까요? 그 가운데 매번 같은 값과 실행마다 달라지는 값은 무엇일까요?

- **옛 학습 질문 유지·바꿈**: 「자율성 증가를 비용·지연·단계 차례로 설명」은 유지하고 손 값 대신 실제로 잼. 옛 「최종 답 평가와 중간 단계 평가 구분」은 b4 「비교와 경계」(두 흐름이 문의를 제대로 처리했는지는 평가하지 않음 · Ch 29 02)로 줄임. 옛 「합성 지표의 범위와 실제 측정이 필요한 부분」 → 「실행마다 같은 값과 달라지는 값을 가르고 같은 값으로만 결론」(학습 목표 셋째).
- **두 흐름**: (가) `run_workflow(order, confirm_tools)` — 코드에 적은 차례대로 도구 흉내를 부르고(도구 줄 고른 쪽 `코드`), 사람 확인 도구 앞에서 `stop_line("사람 확인")`, 차례 끝이면 `stop_line("코드 차례 끝")`. **모델을 부르지 않는 워크플로우로 정함** — 두 흐름에 똑같이 들 일(02 「안내 문장 쓰기」)은 빼고 다음 단계를 고르는 몫만 견줌(b7). (나) `run_measured_loop` — 03 루프 + 잰 값.
- **문의**: 결론 기준 **도착 문의**(3~8절) — (가) 코드 차례 `["주문 조회"]` · 값 바꿔 보기 **환불 문의**(9절) — (가) 02절 코드 차례 `["주문 조회", "환불 규정 확인", "환불 요청 등록"]`을 새로 적음. (가)는 문의 글을 읽지 않아 문의가 바뀌면 사람이 차례를 새로 적어야 한다는 것 = 자율성으로 얻는 것(b6).
- **재는 자리**: 5절 요청 한 번(D0)을 셀 안에 풀어 `time.perf_counter()` 앞뒤·`usage_metadata` → 함수 `send_and_measure`로 묶음. 흐름 전체의 걸린 초는 실행 앞뒤 시각(`flow_seconds`·`loop_seconds`). 6절 끝에서 **5절 요청과 루프 첫 바퀴 요청(글자까지 같은 요청 글)**을 나란히 놓아 입력 토큰은 같고(`입력 토큰이 같은가: True`) 출력 토큰·걸린 초는 다를 수 있음을 노트북 안에서 보임.
- **표**: `total_of(steps, key)`(고른 줄 칸 값 합) · `print_costs(runs)`(기록 | 모델 요청 | 입력 토큰 | 출력 토큰 | 걸린 초 | 구조 — 01 `count_steps`·`classify`). `print_measures(steps)`(바퀴 | 고른 이름 | 입력 토큰 | 출력 토큰 | 걸린 초). 도구 차례 같은지 02 `tool_names`로 `==`.
- **예상 비용**: Ch 6 06 요금표 `mini_prices`(2026-09-17, 0.75·0.075·4.50) + `estimate_cost`(도구 파일). 사용량 딕셔너리를 토큰 합으로 만들어 넘김(캐시 입력 칸 없음 → 함수가 0으로 셈 — 노트북 밖 23번 모두 캐시 입력 0, b7에 밝힘). `round(…, 6)`으로 출력.
