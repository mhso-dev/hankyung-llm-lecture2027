## 4. 설계에 반영한 것

- **새 문의 = 실행 1**: 문의·예상한 도구 차례(`["주문 조회", "환불 규정 확인"]`)는 이 확인 **전에** 정했습니다(도구 흉내 결과 글을 보고). 설계 때는 셋째 바퀴에 모델이 끝을 고를 것으로 봤지만, 다섯 번 모두 환불 요청 등록이었습니다. 이 관찰(묻지 않은 부작용 도구를 모델이 고르고 사람 확인이 멈춤)을 실습의 첫 결론으로 삼았습니다. 노트북 5절의 「실행 전 예상」은 「문의만 보면 셋째 바퀴에는 끝을 고르면 된다 · 무엇을 고르든 요청은 세 번」으로 적고, 결과 읽기에 이 확인 결과를 밝혔습니다.
- **실행 2의 값 = 바퀴 한도 2**: 설계 때는 1과 2를 견주고 있었고, 이 확인에서 모델이 셋째 바퀴에 등록을 고르는 것을 **본 뒤** 2로 정했습니다(등록을 고르는 바퀴 앞에서 멈추는 값). 규격 §3대로 학생 본문 b7 셋째 항목에 「그 확인을 본 뒤 정했습니다 · 흐름을 보여 주려고 정한 예」로 밝혔습니다. 원하는 값이 나올 때까지 다시 돌린 일은 없습니다(노트북 실행은 계획대로 A·B 두 번).
- **흔들리는 값**(출력 토큰·걸린 초·까닭 문장)은 결과 읽기 둘째 단락에 「결론에 쓰지 않는다」로만 적고, 숫자로 인용하지 않았습니다. 캐시 입력은 다섯 번 모두 0이라 노트북에서 출력하지 않았습니다.
