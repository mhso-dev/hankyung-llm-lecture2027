## 검토 중 수정한 결함

- 02절에 기본 정상 읽기가 없었고 본문이 `exists`를 실행했다고 쓴 불일치를 수정했습니다. 현재는 `is_file`·`read_text`와 기본·Before·After 순서가 맞습니다.
- 03절의 표준 `venv.EnvBuilder`가 uv 관리 Python에서 `libpython3.12.dylib` 로드 실패로 중단되는 것을 재현했습니다. 교재의 기본 도구인 `uv venv`로 교체한 뒤 새 커널에서 통과했습니다.
- 04절의 기본 실행 부분에 정상 6,000원 계산이 없었습니다. 기본 셀을 추가해 정상 결과 후 같은 입력의 실패·수정을 비교하도록 수정했습니다.
- 05절의 초기 노트북은 Git이 없으면 나머지 진단을 실행하지 못했습니다. 누락 도구를 실패 대신 보완 항목으로 기록하고 계속 실행하도록 수정했습니다.
- 05절의 환경 준비 표를 능력 배치로 해석할 수 있었습니다. 환경 준비 안내와 A/B 트랙 자가진단을 분리하고, 중간 상태가 누락되지 않도록 A/B 분기를 완결했습니다.

## 확인하지 못한 항목

- Windows·Linux·macOS에서 VS Code, uv, Git, Docker Desktop을 각각 새로 설치하는 화면 절차는 실행하지 않았습니다. 본문은 이 절차를 교재 제작 환경의 실행 검증으로 표시하지 않고 공식 안내와 사용자 확인 절차로 제한합니다.
- Docker 명령줄 클라이언트와 서버 응답은 확인했지만 Docker Desktop GUI에서 표시되는 상태와 메뉴는 확인하지 않았습니다.
- 교육기관의 공식 A/B 트랙 배치 기준은 확정되지 않아 `[[미정: Ch 1 A/B 트랙 공식 배치 기준]]`으로 남았습니다. 현재 자가진단은 학습 경로 선택용 비공식 기준이며, 공식 성적·고정 배치로 쓰지 않도록 명시했습니다.

## 잔여 위험

- Docker Desktop·VS Code의 UI와 지원 조건은 제품 버전·운영체제 업데이트에 따라 바뀐 수 있습니다. 배포 직전에 공식 설치 문서와 화면 이름을 다시 대조해야 합니다.
- 05절의 Docker 29.4.1 출력은 교재 제작 환경의 관찰값입니다. 학습자의 버전이 같아야 하는 기대값으로 쓰지 않고, Client·Server 구역과 응답 여부만 확인해야 합니다.
