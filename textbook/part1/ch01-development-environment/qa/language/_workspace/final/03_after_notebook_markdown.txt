# Git과 Docker 준비

이번 실습은 도구 설치와 실행 준비 상태를 각각 확인합니다. 3절의 Python 3.12 프로젝트 환경을 준비합니다. Git과 Docker가 아직 없으면 해당 실습을 생략하고 미준비 상태를 기록합니다. Docker가 아직 준비되지 않았으면 해당 상태를 출력하고 다른 확인을 계속합니다. 외부 명령을 호출하는 보조 문법은 주석을 읽으며 따라 합니다.
## 1. Git 명령의 실제 응답

명령 위치를 찾는 것과 실제 실행은 구분합니다. 은 목록에 적은 프로그램을 실행합니다. 는 결과를 변수에 저장하고, 는 글자로 읽게 합니다. Git 명령이 없거나 응답하지 않으면 상태를 기록하고 다음 도구를 확인합니다.
## 2. 비어 있는 임시 저장소

실제 프로젝트 대신 새 임시 폴더에서 을 실행합니다. 는 해당 명령이 사용할 작업 폴더입니다. 의 출력이 비어 있으면 이번 폴더에서 표시할 변경 파일이 없다는 뜻입니다. 커밋을 생성했다는 뜻은 아닙니다.
## 3. 파일 하나를 만든 뒤 비교

같은 저장소에  파일 하나를 추가합니다. 는 Git이 아직 추적하지 않는 파일 표시입니다. 이 셀은 파일의 내용을 실행하는 것이 아니라 파일 생성 전후의 Git 상태를 비교합니다.
## 4. Docker 클라이언트 확인

은 클라이언트 프로그램이 응답하는지 확인합니다. 아직 설치되지 않았다면 준비하지 않은 상태로 기록합니다. 명령이 있더라도 실행 결과를 별도로 확인합니다. 버전 문자열은 컴퓨터마다 달라질 수 있습니다.
## 5. Docker 데몬 응답 확인

Docker 서버는 요청을 처리하는 데몬(daemon)을 뜻하며, 출력의 Server 항목에 해당합니다. 클라이언트가 응답한 경우에만 데몬의 버전을 요청합니다. 은 필요한 버전 항목만 선택합니다. 서버가 응답하지 않으면 원인을 숨겨 성공으로 표시하지 않고 미준비 상태를 기록합니다. 10초 안에 응답하지 않는 경우도 별도로 표시합니다.
## 6. 여섯 가지 준비 상태

Python 버전, uv 응답, 현재 커널의 가상환경 여부, Git, Docker 클라이언트, Docker 서버를 각각 읽습니다. 가상환경 여부는 현재 커널이 어떤 가상환경 안에 있다는 사실만 확인합니다. 원하는 프로젝트의 인지 여부는 3절의 인터프리터·커널 선택 화면과 함께 확인합니다. 아래 결과는 도구 준비 상태이며 A/B 학습 수준을 채점하는 표가 아닙니다.
## 결과를 해석합니다

Git의 변경 상태는 파일 하나의 생성 전후를 비교한 실제 결과입니다. Docker 서버가 미준비이면 Docker Desktop을 시작한 뒤 다시 확인합니다. 서버가 응답해도 이미지 내려받기와 컨테이너 실행을 검증한 것은 아닙니다. Python·Git 실습과 Docker 준비를 나눠 기록합니다.
