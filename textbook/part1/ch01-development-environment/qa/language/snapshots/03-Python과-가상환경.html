1학습 목표

  • 이 절을 마치면 프로젝트에서 사용하는 Python이 3.12인지 확인할 수 있습니다.
  • 프로젝트의 가상환경을 준비하고 VS Code의 실행 환경과 노트북 커널을 선택할 수 있습니다.
  • 두 가상환경의 실행 위치가 서로 다르다는 실제 결과를 읽고, 설치한 패키지의 범위를 설명할 수 있습니다.

2이 내용을 배우는 이유

같은 코드를 실행했는데 한 컴퓨터에서는 되고 다른 컴퓨터에서는 필요한 기능을 찾지 못할 수 있습니다. 코드 파일만 같아도 실행하는 Python 버전과 설치한 패키지가 다르면 결과가 달라질 수 있기 때문입니다. 먼저 어떤 Python으로 실행하는지와 어디에 패키지를 설치하는지를 정합니다. 이후 문제가 생겼을 때 코드와 환경 중 무엇이 다른지 나눠 확인할 수 있습니다.

이 과정은 Python 3.12를 사용합니다. 버전 번호를 단순히 외우는 대신, 터미널과 노트북에서 실제 실행한 버전을 확인합니다. 컴퓨터에 Python이 여러 개 있어도 실습마다 필요한 환경을 선택할 수 있습니다. 프로그램 전체를 삭제하고 재설치하기 전에 현재 프로젝트가 어느 환경을 사용하고 있는지 살펴보는 것이 첫 확인 순서입니다.

3앞에서 배운 내용

2절에서 VS Code와 uv를 설치하고, 실습 폴더를 열어 터미널의 현재 위치를 확인했습니다. uv --version이 인식되지 않으면 2절의 설치 안내를 먼저 확인합니다. 이번 절에서는 노트북과 실습 파일 묶음의 labs/part1/ch01-development-environment 폴더를 사용합니다. 폴더 이름만 비슷한 빈 연습 폴더와 구분하고, 안에 pyproject.toml과 uv.lock, notebooks가 있는지 확인합니다.

처음 실습 묶음을 받았다면 압축을 푼 뒤 위 폴더를 VS Code의 Open Folder로 엽니다. Python 확장과 Jupyter 확장은 설치되어 있어야 합니다. 이 장에는 외부 모델 서비스 계정이나 API 키가 필요하지 않습니다. 준비 단계에서는 Python과 실습 도구를 내려받으므로 인터넷 연결이 필요할 수 있습니다.

4핵심 개념

작업별 준비물을 따로 둡니다

서로 다른 실습의 준비물을 각각의 보관함에 넣으면 어느 실습에서 쓰는지 구분할 수 있습니다. 프로그램의 실행 환경도 프로젝트마다 분리합니다. 다만 실제 보관함처럼 컴퓨터 전체를 나누는 것은 아닙니다. 가상환경은 주로 Python 실행 위치와 패키지 설치 위치를 구분하며, 같은 컴퓨터의 파일과 운영체제를 사용합니다. 어떤 코드든 안전하게 실행해 주는 격리 장치라고 생각하지 않습니다.

인터프리터(interpreter)는 Python 코드를 읽고 실행하는 프로그램입니다. 프로젝트(project)는 하나의 작업에 필요한 코드와 설정을 모은 단위입니다. 패키지(package)는 설치해서 사용하는 Python 기능의 묶음입니다. 가상환경(virtual environment)은 프로젝트별로 Python 패키지 설치 위치를 구분하는 실행 환경입니다. 이 과정은 프로젝트 폴더 안의 .venv를 사용합니다.

의존성(dependency)은 프로그램을 실행하는 데 필요한 다른 패키지입니다. 잠금 파일(lockfile)은 설치할 패키지와 선택된 버전을 기록해 다시 준비할 때 참고하는 파일입니다. uv에서는 uv.lock을 사용합니다. 커널(kernel)은 노트북 코드를 실행하고 변수를 기억하는 프로그램입니다. VS Code에서 파일 실행에 사용할 Python을 골랐더라도 노트북의 커널은 별도로 확인합니다.

프로젝트 안의 세 파일을 읽습니다

파일 또는 폴더담고 있는 내용학생이 확인할 점
pyproject.toml프로젝트 정보와 필요한 Python·패키지 조건입니다.Python 3.12와 노트북 실행 도구 조건을 확인합니다. 처음 실습에서는 수정하지 않습니다.
uv.lock의존성을 계산한 뒤 선택한 패키지 버전입니다.직접 편집하지 않고 제공된 파일로 환경을 준비합니다.
.venv현재 컴퓨터에서 실제 사용할 실행 환경입니다.준비 명령을 실행한 뒤 생성되는지 확인합니다. 다른 컴퓨터에 그대로 복사하지 않습니다.

프로젝트 설정과 잠금 파일이 같으면 설치할 버전을 맞추는 데 도움이 됩니다. 그래도 운영체제와 CPU, 외부 파일까지 모두 같아지는 것은 아닙니다. 설치 오류가 있다면 운영체제와 Python 버전, 실패한 패키지 이름을 함께 확인합니다. 설치된 가상환경 전체 대신 설정과 잠금 파일을 공유하고, 각 컴퓨터에서 환경을 다시 만드는 이유입니다.

확인할 점 — 초록색 환경 A와 B는 각각의 실행 위치를 갖습니다. 노란 확인 단계는 두 위치가 서로 다른지와 기반 Python에서 분리되어 있는지를 비교합니다. 그림은 패키지 설치 위치를 나누는 원리를 설명하며 운영체제 전체가 두 개 생겼다는 뜻이 아닙니다.

5실행 예제

노트북을 열기 전에 한 번 준비합니다

  1. VS Code에서 제공된 labs/part1/ch01-development-environment 폴더를 엽니다. Terminal → New Terminal로 새 창을 열고 현재 폴더와 파일 목록을 확인합니다.
  2. 터미널에서 uv sync --locked를 실행합니다. 잠금 파일의 버전을 사용해 프로젝트에 필요한 도구를 준비합니다. 설치 중에는 기다리고, 오류 없이 명령 입력 상태로 돌아왔는지 확인합니다.
  3. uv run python --version을 실행해 Python 3.12로 시작하는 출력인지 확인합니다. 마지막 패치 번호는 설치된 환경에 따라 다를 수 있습니다.
  4. VS Code 명령 팔레트를 열고 Python: Select Interpreter를 선택합니다. Windows·Linux는 Ctrl+Shift+P, macOS는 Cmd+Shift+P로 명령 팔레트를 엽니다. 현재 프로젝트의 .venv를 고릅니다.
  5. notebooks에서 원하는 절의 .ipynb를 열고, 오른쪽 위 Select Kernel → Python Environments에서 같은 프로젝트의 .venv를 선택합니다. 표시되지 않으면 VS Code의 환경 목록을 새로 고친 뒤 다시 선택합니다.
  6. 첫 코드 셀을 선택하고 Shift+Enter를 누릅니다. 실행 중 표시가 사라진 뒤 출력을 읽고 다음 셀로 이동합니다. 1절과 2절의 노트북도 같은 준비 환경에서 실행할 수 있습니다.

uv sync는 프로젝트의 실행 환경을 준비하는 명령이고, --locked는 제공된 잠금 파일을 변경하지 않고 사용할 수 있는지 확인하는 옵션입니다. 설정과 잠금 파일이 서로 맞지 않아 실패하면 옵션을 지우기 전에 제공 파일이 함께 있는지 확인합니다. uv run은 프로젝트 환경에서 뒤에 적은 명령을 실행합니다. 이 방식에서는 매번 별도의 활성화 명령을 입력할 필요가 없습니다.

터미널의 python 명령과 uv run python이 같은 실행 파일을 사용한다고 가정하지 않습니다. 현재 셸 설정에 따라 앞의 명령은 다른 Python을 실행할 수 있습니다. 이 교재의 터미널 예제는 uv run으로 실행 환경을 명확히 지정합니다. 노트북에서는 선택한 커널이 실제로 Python 3.12인지 첫 셀의 결과로 확인합니다.

서로 다른 두 환경을 실제로 확인합니다

다음 노트북은 Python에 포함된 venv 기능으로 연습용 환경 두 개를 만듭니다. 프로젝트를 준비하는 도구는 uv이며, 이 셀에서는 가상환경의 원리를 보기 위해 Python 기본 기능을 사용합니다. sys는 실행 중인 Python 정보를 읽고, subprocess는 별도의 프로그램을 실행하는 기능입니다. 보조 문법은 주석을 따라 읽고, 어떤 위치를 비교하는지와 결과의 뜻에 집중합니다.

6실험 결과 해석

두 환경은 같은 기반 Python을 사용할 수 있지만 환경의 위치는 서로 다릅니다. 이 실험은 환경을 새로 만들고 각각의 Python을 실행해 그 정보를 확인합니다. 폴더 이름만 두 개 만들어 놓고 가상환경이 분리되었다고 설명하는 것과는 확인 범위가 다릅니다. 출력에서 분리 여부가 참인지 확인하고, 같은 환경을 다시 실행했을 때도 동일한 조건인지 비교합니다.

이번 예제는 제삼자 패키지의 서로 다른 버전을 설치하지 않았습니다. 그러므로 실제 패키지 충돌을 재현하거나 해결했다고 기록하지 않습니다. 패키지 설치 위치가 분리되는 원리를 확인했으며, 특정 패키지의 호환성은 그 패키지를 설치하고 사용하는 별도 실행이 필요합니다. 연습용 임시 환경과 현재 노트북을 실행하는 프로젝트의 .venv도 구분합니다.

7주의할 점과 실무 메모

환경을 선택한 뒤에도 이미 실행 중인 커널이 이전 상태를 기억할 수 있습니다. VS Code에서 Restart Kernel을 선택하면 노트북의 기존 변수가 사라집니다. 다시 첫 셀부터 실행합니다. 저장된 코드와 출력 파일은 커널 재시작만으로 삭제되지 않습니다. 실행 중인 변수, 저장한 코드, 저장된 출력이 각각 무엇인지 구분하면 이전 실행의 숫자를 새 결과로 오해하는 일을 줄일 수 있습니다.

패키지를 설치했는데 찾지 못한다면 설치한 환경과 실행 중인 커널을 확인합니다. 다른 Python에 다시 설치하는 일을 반복하기 전에 인터프리터와 커널이 같은 프로젝트를 가리키는지 살펴봅니다. .venv를 이동하거나 이름을 바꾼 경우에는 기존 경로를 기억한 설정이 맞지 않을 수 있으므로 제공된 설정으로 새 위치에서 환경을 준비하고 다시 선택합니다.

9복습 문제

1. 가상환경은 무엇을 구분하나요? · 기초

프로젝트가 사용하는 Python 실행 위치와 패키지 설치 위치를 구분합니다. 운영체제 전체를 복제하거나 임의 코드 실행을 안전하게 만드는 장치로 해석하지 않습니다.

2. 설치 후 노트북에서 패키지를 찾지 못하면 무엇을 확인하나요? · 적용

패키지를 설치한 환경과 선택한 노트북 커널이 같은지 확인합니다. 편집기의 인터프리터를 고른 것만으로 커널도 같아졌다고 판단하지 않습니다.

3. 새 컴퓨터에 .venv만 복사하면 충분한가요? · 적용

충분하지 않습니다. 경로와 운영체제 조건이 다를 수 있으므로 프로젝트 설정과 잠금 파일을 사용해 새 컴퓨터에서 환경을 준비합니다.

4. 이번 결과로 패키지 버전 충돌을 해결했다고 말할 수 있나요? · 분석

말할 수 없습니다. 두 환경의 Python을 실행해 위치 관계를 확인했지만, 제삼자 패키지의 충돌은 실행하지 않았습니다. 실험 결과 해석의 범위를 다시 확인합니다.
