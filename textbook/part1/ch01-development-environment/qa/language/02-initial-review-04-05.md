## 정독 소견

- 04절은 저장 파일, 선택 인터프리터, VS Code 화면 디버깅, 노트북 `pdb` 시연의 범위를 잘 분리합니다. Before/After의 원인과 결과도 한 입력·한 연산자 차이로 설명합니다.
- 05절은 Git과 GitHub, Docker 클라이언트와 데몬, 준비 상태와 능력 수준을 구분합니다. Docker 설치 조건과 이용 조건을 단정하지 않고 공식 문서 확인으로 연결한 점이 적절합니다.
- 두 절 모두 목록은 학습 목표·실무 메모·자가 점검표처럼 병렬 정보가 필요한 곳에만 사용하므로 산문화하지 않습니다.

## 손대지 않을 자리

- 04절의 `pdb`, F5, F10, `Step Over`, `launch.json`은 실제 도구 이름과 코드 요소이므로 문체 감사에서 바꾸지 않습니다.
- 05절의 Docker 이용 조건 문장은 법률·조직별 적용을 판단하지 않고 최신 공식 안내 확인을 요구하므로, 한정어를 삭제하거나 더 단정적으로 고치지 않습니다.
- “배치 안내” 단락은 준비 상태가 능력 수준이나 영구적 반 편성과 다르다는 핵심 설명을 포함하므로, 짧게 줄이지 않습니다.
