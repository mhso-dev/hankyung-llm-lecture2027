# 05 Git과 Docker 준비 — 그림 설계표

| 번호 | 위치 | 종류 | 설명 대상 문장 | 보여 줄 실제 값 | 색 |
|---|---|---|---|---|---|
| 05-5 | 4 핵심 개념 · 비유로 시작하기 | Higgsfield 삽화 | 리모컨이 있는지와 TV가 켜질 수 있는지는 따로 확인해야 합니다. | 값 없음(비유). 리모컨 = docker 명령(클라이언트), TV 본체 = 서버(데몬), 빠진 플러그 = 시작하지 않은 Docker Desktop | — |
| 05-1 | 4 핵심 개념 · 확인을 세 단계로 나눕니다 (노트북 「오늘 볼 그림」) | Mermaid flowchart TB(두 칸) | 도구 하나가 준비됐는지는 세 단계로 확인합니다. | [명령 찾기] 셀 `git을 찾았는가: True`·`docker를 찾았는가: False`, [버전] 셀 `git 종료 코드: 0`, [커밋] 셀 `커밋 종료 코드: 0`, [Docker 클라이언트] 셀 `Docker 클라이언트: 명령을 찾지 못함`, [Docker 서버] 셀 `확인하지 않음` | 통과한 확인 결과 measure(노랑), 준비되지 않은 결과 fail(빨강), 확인하지 않은 단계 회색 |
| 05-2 | 5 실행 예제 · 임시 저장소에서 기록하기 | Mermaid flowchart TD | 작업마다 같은 상태 명령 git status --short를 다시 실행해 표시를 비교합니다. | [init] 셀 `상태 출력 줄 수: 0`, [저장] 셀 `상태 출력: ?? hello.py`, [add] 셀 `상태 출력: A  hello.py`, [커밋] 셀 `상태 출력 줄 수: 0` | 상태 출력 measure(노랑). 명령은 화살표 라벨 |
| 05-3 | 6 실험 결과 해석 | Mermaid flowchart TB(기록 + 두 칸 비교) | 이번 실행에서 Git은 저장했는지가 아니라, 내용이 기록과 같은지로 판단했습니다. | [실험] 셀 `상태 출력: M hello.py`, [diff] 셀 `-count = 2`·`+count = 3`, [값 바꿔 보기] 셀 `상태 출력 줄 수: 0` | 기록과 파일 tool(초록), 비교 결과 measure(노랑) |
| 05-4 | 6 실험 결과 해석 · 여섯 가지 준비 상태 읽기 | Mermaid flowchart TD | 위 네 줄이 모두 True이면 Ch 2의 Python 학습을 시작할 수 있습니다. | [여섯 가지] 셀 `Python 3.12: True`·`uv 응답: True`·`커널이 가상환경 안: True`·`Git 응답: True`·`Docker 클라이언트: False`·`Docker 서버: False` | 출력 모음·다음 행동 flow(파랑), 준비된 네 줄 measure(노랑), 준비되지 않은 두 줄 fail(빨강) |

색 규칙: 확인 결과(True, 종료 코드 0, 상태 출력)는 네 그림 모두 노랑입니다. 빨강은 이 교재 환경에서 실제로 준비되지 않은 Docker 결과(05-1의 명령 찾기 False·명령을 찾지 못함, 05-4의 Docker 두 줄) 두 그림에만 쓰고 같은 대상입니다. 05-1의 서버 확인은 실패가 아니라 실행하지 않은 단계라 회색입니다. 커밋한 기록과 저장한 파일은 04절처럼 초록입니다. 우리가 할 행동(다음 행동, 출력 모음)은 파랑입니다. 05-2의 git 명령은 상자가 아니라 화살표 라벨로 둡니다.
