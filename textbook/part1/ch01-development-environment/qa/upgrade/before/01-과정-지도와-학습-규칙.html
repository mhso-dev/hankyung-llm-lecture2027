2이 내용을 배우는 이유

처음 프로그램을 실행하면 화면에 숫자나 문장이 나타납니다. 그 결과가 의도한 것인지 판단하려면 실행 전에 무엇을 만들려 했는지 알아야 합니다. 예를 들어 3,000원짜리 상품 두 개의 합계는 6,000원입니다. 프로그램이 오류 없이 3,002원을 출력했더라도 가격을 올바르게 계산한 것은 아닙니다. 실행되었다는 사실과 원하는 일을 했다는 사실을 각각 확인하는 습관을 첫 장부터 연습합니다.

프로그램에 적힌 명령을 코드(code)라고 합니다. 초반에는 코드를 직접 읽고 입력하며, 바꾼 줄이 결과에 미치는 영향을 설명합니다. 다른 사람이 작성한 코드를 사용하는 경우에도 입력·처리·결과를 스스로 확인할 수 있어야 합니다. 답을 빠르게 얻는 데만 집중하면 예상하지 못한 결과를 어디서부터 살펴볼지 알기 어렵습니다. 지금 쌓는 실행 기록은 이후 더 긴 프로그램을 읽고 수정할 때 원인을 찾는 근거가 됩니다.

3앞에서 배운 내용

이 절은 첫 학습이므로 프로그래밍 경험을 요구하지 않습니다. 파일을 내려받고 폴더에서 찾는 방법을 알고 있으면 시작할 수 있습니다. 아직 실행 도구가 없다면 지금은 설명과 저장된 출력을 읽습니다. 다음 절의 설치 안내와 3절의 실행 환경 준비를 마친 뒤 이 절의 노트북으로 돌아와 직접 실행합니다. HTML은 내용을 읽고 코드를 복사하는 데 사용하는 교재이며, 화면의 복사 버튼이 코드를 실행하지는 않습니다.

준비된 환경이 있다면 이 절 상단의 노트북 내려받기로 파일을 저장합니다. 파일 이름 끝의 .ipynb는 설명과 실행 코드를 함께 담은 노트북 파일임을 나타냅니다. 파일을 열었을 때 글과 코드가 여러 칸으로 나뉘어 보이면 맞는 화면입니다. 파일 내용이 중괄호와 따옴표로만 보이면 텍스트 편집기로 열린 상태이므로 2절의 Jupyter 확장 준비를 확인합니다.

4핵심 개념

예상한 금액과 영수증을 비교합니다

가게에서 상품 두 개를 살 때 머릿속으로 계산한 금액과 영수증을 비교할 수 있습니다. 프로그램에서도 실행 전에 예상값을 적고 실행 후 표시된 값과 비교합니다. 영수증의 합계만 보는 대신 상품 수량과 단가도 확인하는 것처럼, 프로그램이 받은 값과 계산한 값을 함께 살펴봅니다. 이 비유에서는 예상 금액이 확인 기준이며 실제 영수증이 실행 결과에 해당합니다.

이번 절에서 사용하는 다섯 가지 말

프로그램(program)은 컴퓨터가 수행할 작업을 적은 것입니다. 입력(input)은 작업에 사용하는 값이며, 여기서는 단가 3,000과 수량 2입니다. 출력(output)은 실행 결과로 밖에 보여 주는 값입니다. 계산한 합계 6,000을 화면에 표시하면 출력이 됩니다. 셀(cell)은 노트북에서 설명이나 코드를 담는 한 칸입니다. 검증(verification)은 결과가 미리 정한 조건에 맞는지 확인하는 일입니다. 이번 조건은 ‘단가에 수량을 곱한 값이 합계와 같다’입니다.

계산한 값을 기억하는 것과 화면에 표시하는 것은 별개의 동작입니다. 코드에서 이름에 값을 저장해도 화면에 아무것도 나타나지 않을 수 있습니다. 이 교재는 확인할 값을 print로 표시합니다. 처음에는 괄호 안의 값을 화면에 보여 주는 명령으로 읽으면 충분합니다. 코드에서 *는 곱셈을 뜻하고, =는 오른쪽 값을 왼쪽 이름에 저장할 때 사용합니다. 이름과 값의 관계는 Ch 2에서 자세히 배웁니다.

5실행 예제

첫 실행에서는 코드를 바꾸지 않습니다. 6,000이라는 예상값을 먼저 적고 셀을 위에서 아래로 실행합니다. 앞 셀이 만든 값을 다음 셀이 사용하므로 중간 셀만 실행하면 필요한 값이 없을 수 있습니다. 셀 왼쪽의 입력 번호는 실행된 순서를 나타내며, 교재의 번호를 외우거나 코드에 복사할 필요는 없습니다.

첫 셀의 import sys는 Python에 포함된 sys 기능을 현재 노트북에서 사용하겠다는 뜻입니다. sys.version_info는 실행 중인 Python의 버전 정보를 반환합니다. 뒤의 [:2]는 그 정보에서 앞의 두 값인 주 버전과 부 버전만 고릅니다. == (3, 12)는 고른 두 값이 3과 12인지 비교하며, 비교 결과는 참을 뜻하는 True 또는 거짓을 뜻하는 False가 됩니다. 이 문법은 Ch 2에서 차례로 배우므로, 지금은 “현재 실행기가 Python 3.12인가?”라는 질문을 코드로 적은 것으로 읽습니다.

price = 3000에서 price는 값을 다시 사용할 수 있도록 붙인 이름이고, =는 오른쪽 값 3000을 왼쪽 이름에 저장합니다. print(...)는 괄호 안에서 만든 문장을 화면에 출력합니다. 문자열 앞의 f와 중괄호는 저장한 값을 문장 안에 넣는 표기입니다. 예를 들어 f"{price}원"은 3000원이라는 문장을 만듭니다. 함수, 문자열, 이름에 관한 규칙은 Ch 2에서 배우지만, 이 절에서는 각 줄의 역할을 구분할 수 있어야 합니다.

assert total == prediction은 total과 prediction이 같은지 검사합니다. 두 값이 같으면 별도 문장을 출력하지 않고 다음 줄로 넘어가며, 다르면 실행을 멈추고 AssertionError를 표시합니다. 따라서 출력이 없다는 사실만 보지 말고, 그 앞의 print 결과와 셀이 오류 없이 끝났는지를 함께 확인합니다.

Python 3.12 · 실행 확인 2026-09-09노트북만 내려받기

준비된 Python 3.12 노트북에서 첫 셀부터 Shift+Enter로 하나씩 실행합니다. 안내한 결과를 먼저 확인하고 지정한 값 하나를 바꿔 비교합니다. 문서를 사용하는 실습은 파일 묶음이 필요합니다. 노트북과 실습 파일 함께 받기 · 처음 실습하는 방법. 전체 코드 복사에는 실험 셀 전체가 포함됩니다. 이 HTML에서는 코드를 실행하지 않습니다.

과정 지도와 학습 규칙

예상하고, 실행하고, 값을 바꾼 뒤 다시 확인하는 학습 순서를 연습합니다. 프로그램은 컴퓨터가 수행할 작업을 적은 것이고, 코드는 그 작업을 Python 문법으로 표현한 글입니다. 코드 셀을 실행하면 커널이 코드를 읽고 앞 셀에서 만든 값을 기억합니다.

실행 환경 확인

이 노트북은 Python 3.12 커널에서 첫 셀부터 순서대로 실행합니다. 커널은 노트북의 Python 코드를 실행하고 앞 셀에서 만든 값을 기억하는 프로그램입니다. import sys는 Python에 포함된 sys 기능을 가져오며, sys.version_info[:2]는 실행 중인 Python 버전에서 앞의 두 숫자를 고릅니다. == (3, 12)의 결과가 True이면 주 버전 3과 부 버전 12가 맞습니다. assert는 이 조건이 거짓일 때 실행을 멈춥니다.

In [1]:
import sys

# version_info는 현재 Python의 주 버전과 부 버전을 숫자로 제공합니다.
python_312 = sys.version_info[:2] == (3, 12)
print(f"Python 3.12: {python_312}")
assert python_312
출력:
Python 3.12: True

1단계: 결과 예상

가격이 3,000원인 상품 2개의 총액을 먼저 예상합니다. price, count, prediction은 각각 단가, 수량, 예상 합계에 붙인 이름입니다. =는 오른쪽 값을 왼쪽 이름에 저장합니다. 문자열 앞의 f와 문장 안의 중괄호는 저장한 값을 출력 문장에 넣습니다. 이 문법은 Ch 2에서 배우며, 여기서는 세 이름에 어떤 값이 저장되는지 한 줄씩 확인합니다.

In [2]:
# price는 한 개의 가격, count는 상품 개수입니다.
price = 3000
count = 2
prediction = 6000
print(f"예상 총액: {prediction}원")
출력:
예상 총액: 6000원

2단계: 코드 실행

곱셈 기호 *로 실제 총액을 계산하고 예상과 맞는지 확인합니다. total = price * count는 저장된 3,000과 2를 곱해 6,000을 만든 뒤 total에 저장합니다. print는 값을 화면에 보여 주고, assert total == prediction은 실제 합계와 예상 합계가 같은지 검사합니다. 조건이 참이면 assert는 아무 문장도 출력하지 않습니다.

In [3]:
# price * count의 결과를 total이라는 이름으로 저장합니다.
total = price * count
print(f"실행 총액: {total}원")
assert total == prediction
출력:
실행 총액: 6000원

3단계: 값 하나 변경

가격은 그대로 두고 개수만 3개로 바꿥니다. 결과가 9,000원으로 변하는지 비교합니다.

In [4]:
# count만 2에서 3으로 바꾼 뒤 다시 계산합니다.
count = 3
changed_total = price * count
print(f"2개: {total}원")
print(f"3개: {changed_total}원")
assert changed_total == 9000
출력:
2개: 6000원
3개: 9000원

실험 결과 해석

예상과 실행 결과가 6,000원으로 같았습니다. 개수 하나만 바꾸었을 때 총액은 9,000원으로 변했습니다. assert는 관찰한 값이 기대한 값과 같은지 확인합니다.

확인할 점 — 기본 수량 2의 합계와 변경한 수량 3의 합계를 비교합니다. 단가는 그대로 두었습니다. assert 뒤 조건이 참이면 오류가 발생하지 않습니다. 출력 문장과 확인 조건을 함께 읽고 어느 계산을 확인했는지 설명합니다.

6실험 결과 해석

이번 실행에서는 같은 단가에 수량만 바꿨습니다. 3,000에 2를 곱하면 6,000이고, 3을 곱하면 9,000입니다. 두 조건의 차이는 수량 하나이므로 합계가 3,000만큼 증가한 이유를 설명할 수 있습니다. 입력을 여러 개 동시에 바꾸면 어떤 값이 결과 차이를 만들었는지 따로 확인해야 합니다. 처음에는 비교 조건을 하나씩 정하는 편이 원인을 추적하기 좋습니다.

이 결과로 모든 계산 프로그램이 올바르다고 판단할 수는 없습니다. 할인·환불·배송비가 포함된 계산은 실행하지 않았습니다. 이번 실습에서 확인한 것은 정수 단가와 두 수량의 곱셈입니다. 오류를 재현하지 않은 절이므로 실패를 고쳤다고 기록하지 않습니다. 4절에서는 잘못된 연산으로 계산한 실제 결과를 관찰하고 같은 입력에서 수정합니다.

7주의할 점과 실무 메모

실습 기록에는 예상한 값, 실제 출력, 바꾼 입력, 다음에 확인할 것을 남깁니다. ‘잘 됨’만 적으면 무엇이 맞았는지 나중에 확인하기 어렵습니다. ‘단가 3,000과 수량 2에서 출력 6,000을 확인했다’처럼 입력과 결과를 함께 적습니다. 오류가 발생하면 마지막 메시지와 실행한 셀을 기록하고, 이미 확인한 정상 셀을 무작정 여러 군데 바꾸지 않습니다.

저장된 출력은 교재를 만들 때 실행한 기록입니다. 파일을 열어 출력이 보인다는 사실만으로 자신의 컴퓨터에서도 실행된 것은 아닙니다. 직접 셀을 실행하고 새 입력 번호와 출력을 확인해야 합니다. 실습 중 값이 예상과 다르게 남았다면 실행 프로그램을 다시 시작한 후 처음부터 순서대로 실행합니다. 이 초기화 방법은 3절에서 배웁니다.

8정리와 다음 절

실행 전에 입력과 예상 결과를 정합니다.
실행 후 실제 출력이 조건에 맞는지 확인합니다.
값 하나를 바꾸고 같은 확인 과정을 반복합니다.

다음 학습과 이어지는 지점 — 다음 절은 이 과정을 자신의 컴퓨터에서 수행하도록 편집기와 터미널을 준비합니다. 이번 절에서 남긴 예상값과 실제값 기록은 4절의 계산 오류를 설명하는 데 다시 사용합니다.

9복습 문제

1. 입력과 출력은 각각 무엇인가요? · 기초

단가 3,000과 수량 2는 입력이며, 화면에 표시한 합계 6,000은 출력입니다. 어떤 값을 사용했는지와 무엇을 보여 주었는지를 구분합니다.

2. 수량을 3으로 바꾸면 어떤 값을 예상하나요? · 적용

단가를 3,000으로 유지하면 9,000을 예상합니다. 실행 전에 예상값을 적고, 실행 후 출력과 비교합니다.

3. 오류 없이 3,002가 출력되면 올바른 합계인가요? · 적용

아닙니다. 두 상품의 총금액은 6,000이어야 합니다. 실행 가능 여부와 계산 결과의 정확성은 별도로 확인해야 합니다.

4. 두 번 확인한 결과로 할인 계산도 맞다고 말할 수 있나요? · 분석

말할 수 없습니다. 할인 조건은 입력하거나 실행하지 않았습니다. 할인 규칙과 예상값을 정한 별도 사례가 필요합니다. 해석 범위를 다시 읽고 실행한 조건만 기록합니다.
