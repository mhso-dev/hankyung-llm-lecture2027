1학습 목표

  • 컨텍스트 로트를 입력 길이와 정보 위치에 따라 활용 성능이 달라질 수 있는 현상으로 설명합니다.
  • 질문·근거·모델을 고정하고 길이와 위치를 바꾸어 응답을 측정합니다.
  • 저하를 관찰하지 못한 조건과 관찰한 조건을 구분해 설명합니다.

2이 내용을 배우는 이유

컨텍스트 윈도에 정보가 들어간다고 해서 모델이 모든 정보를 균등하게 사용하는 것은 아닙니다. 관련 없는 문장이 늘어나거나 핵심 근거의 위치가 바뀌면 응답이 달라질 수 있습니다. 이 현상을 컨텍스트 로트(context rot)라고 부릅니다. 실습은 하나의 작은 로컬 모델을 사용하므로 모델 전체에 대한 결론을 내리지 않습니다.

3앞에서 배운 내용

앞 절에서 연습용 컨텍스트 예산 512토큰을 계산했습니다. 이 값은 이번 모델의 입력 한도가 아닙니다. 노트북이 불러오는 Qwen 설정의 max_position_embeddings는 32,768이며, 가장 긴 조건의 입력 1,201토큰과 최대 생성 20토큰의 합은 1,221로 이 값보다 작습니다. 코드도 입력을 잘라내지 않습니다. 따라서 이 절에서는 한도 초과가 아닌 상태에서 길이와 위치가 활용 결과에 미치는 영향을 관찰합니다. '해바라기 작전의 확인 코드는 314159'라는 근거와 같은 질문을 사용합니다.

4핵심 개념

정의와 관찰

컨텍스트 로트(context rot)는 입력이 모델의 허용 범위 안에 있더라도 길이, 정보 위치, 주변 내용에 따라 필요한 정보를 활용한 결과가 달라질 수 있는 현상을 가리킵니다. 입력 한도를 넘겨 잘린 현상과 구분해야 합니다. 이 노트북은 가장 긴 입력도 모델 설정의 한도 안에 두고 위치와 주변 문장 수만 바꿉니다.

생성 함수의 입력은 프롬프트 문자열이며, 채팅 템플릿 적용과 토큰화를 거쳐 모델에 전달됩니다. 모델은 새 토큰 ID를 반환하고 tokenizer가 이를 다시 문자열로 복원합니다. 실험 코드는 그 문자열에 정답 코드 314159가 들어 있는지만 판정해 조건별 결과를 반환합니다.

실험은 무관한 문장을 2, 20, 60개로 늘리고 핵심 근거를 시작, 중간, 끝에 배치합니다. 질문과 정답 판정 기준은 고정합니다. 정답 문자열 314159가 응답에 포함되면 성공으로 세었습니다. 이 판정은 코드 회상 여부만 확인하며, 응답의 문장 품질은 측정하지 않습니다.

이 절의 생성 함수는 do_sample=False로 샘플링을 끄고 같은 프롬프트를 두 번 호출합니다. 두 응답은 독립 확률 표본이 아니라 같은 설정에서 출력이 반복되는지 확인하는 중복 실행입니다. 성공률을 추정하려면 다른 평가 설계와 더 많은 반복이 필요합니다.

관찰 결과에서 근거가 시작에 있을 때는 세 길이 모두 2/2였습니다. 중간 위치는 세 길이 모두 0/2였습니다. 끝 위치는 무관한 문장 2개 조건에서 0/2, 20개와 60개 조건에서 2/2였습니다. 위치별 차이는 관찰했지만 길이가 늘어날수록 계속 나빠지는 패턴은 관찰하지 못했습니다.

중간 위치의 실패가 어느 모델에서나 반복된다고 단정하지 않습니다. 모델 크기, 프롬프트, 무관 문장의 내용, 생성 전략을 바꾸면 결과가 달라질 수 있습니다. 핵심은 '길면 나쁘다'라고 단정하는 것이 아니라 현재 작업의 길이와 위치를 분리해 측정하는 실험 설계입니다.

5실행 예제

먼저 model.config.max_position_embeddings가 반환한 모델 위치 한도를 출력합니다. 근거 문장과 질문은 유지하고 무관한 문장 수와 근거 위치만 바꿉니다. 각 조건에서 입력 토큰 수와 최대 생성 20토큰의 합이 한도 이하인지 검사한 뒤, generate()가 반환한 문자열에 314159가 있는지 셉니다.

노트북을 새 Python 3.12 커널에서 첫 셀부터 순서대로 실행합니다.

컨텍스트 로트

근거 문장의 위치와 주변 문장 수가 답에 어떤 차이를 만들까요?

Python 3.12와 잠긴 패키지를 사용합니다. 첫 실행에서는 로컬 모델을 다운로드합니다.

로컬 생성 모델 준비

고정 revision의 사전학습 모델과 tokenizer를 로컬에서 불러옵니다. generate()는 프롬프트 문자열과 최대 생성 토큰 수를 입력받습니다. 모델은 샘플링을 끈 같은 생성 방식으로 새 토큰 ID를 만들고, 함수는 새 부분만 문자열로 복원해 반환합니다. 모델 구조를 구현하거나 학습하는 셀이 아닙니다.

In [1]:
# 위 설명의 조건을 실행하고 실제 출력을 확인합니다.
import warnings
warnings.filterwarnings("ignore", message="IProgress not found")
import torch
from transformers import AutoModelForCausalLM, AutoTokenizer, logging

logging.set_verbosity_error()

MODEL_ID = "Qwen/Qwen2.5-0.5B-Instruct"
REVISION = "7ae557604adf67be50417f59c2c2f167def9a775"
tokenizer = AutoTokenizer.from_pretrained(MODEL_ID, revision=REVISION)
model = AutoModelForCausalLM.from_pretrained(MODEL_ID, revision=REVISION)
model.eval()
print("model:", MODEL_ID)
print("parameters:", f"{model.num_parameters():,}")
출력:
model: Qwen/Qwen2.5-0.5B-Instruct
parameters: 494,032,768
In [2]:
def generate(prompt: str, *, max_new_tokens: int = 48) -> str:
    # 샘플링을 끈 결정적 생성으로 새 토큰만 복원합니다.
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt")
    with torch.inference_mode():
        output = model.generate(
            **inputs,
            max_new_tokens=max_new_tokens,
            do_sample=False,
            pad_token_id=tokenizer.eos_token_id,
        )
    new_tokens = output[0, inputs["input_ids"].shape[1]:]
    return tokenizer.decode(new_tokens, skip_special_tokens=True).strip()

비교 조건 준비

model.config.max_position_embeddings가 반환한 모델의 위치 한도를 출력합니다. 정답 근거와 질문은 고정하고 무관한 문장 수를 2·20·60개로, 근거 위치를 시작·중간·끝으로 바꿉니다. 이 조합으로 아홉 개의 프롬프트를 만들어 conditions 목록에 추가합니다.

In [3]:
# 위 설명의 조건을 실행하고 실제 출력을 확인합니다.
fact = "해바라기 작전의 확인 코드는 314159입니다."
filler = "주문 조회 화면에는 결제 상태와 배송 상태가 표시됩니다."
question = "해바라기 작전의 확인 코드만 답하세요."
model_limit = model.config.max_position_embeddings
max_new_tokens = 20
print("model max_position_embeddings:", model_limit)
conditions = []
for repeats in [2, 20, 60]:
    for position in ["start", "middle", "end"]:
        items = [filler] * repeats
        index = {"start": 0, "middle": repeats // 2, "end": repeats}[position]
        items.insert(index, fact)
        prompt = "\n".join(items) + "\n\n" + question
        conditions.append((repeats, position, prompt))
출력:
model max_position_embeddings: 32768

아홉 조건 실행

준비한 프롬프트를 같은 결정적 생성 방식으로 두 번씩 호출합니다. for _ in [1, 2]의 밑줄은 실행 횟수 값 자체를 이후 계산에 사용하지 않는다는 뜻입니다. 각 조건에서 입력 토큰 수 + 최대 생성 20토큰이 한도 이하인지 검사하고, 반환 문자열에 314159가 있으면 적중으로 셉니다. hits=0/2는 두 실행 모두 코드 문자열을 출력하지 않았다는 뜻이며 모델 전체의 실패율을 뜻하지 않습니다.

6실험 결과 해석

근거가 중간에 있는 조건은 세 길이에서 모두 정답 코드를 반환하지 못했습니다. 그러나 시작 위치의 성공은 유지되었고, 끝 위치는 짧은 조건에서 실패했다가 더 긴 조건에서 성공했습니다. 따라서 이 실험은 위치와 응답 차이를 보여 주지만, 입력이 길어질수록 성능이 단조롭게 낮아진다는 결론은 받침하지 않습니다.

7주의할 점과 실무 메모

  • 토큰 수는 채팅 템플릿을 적용한 실제 모델 입력을 기준으로 세어야 합니다.
  • 샘플링을 끈 결정적 생성의 중복 결과를 독립 확률 표본으로 해석하지 않습니다.
  • 단일 작은 모델의 위치 패턴을 다른 모델로 일반화하지 않습니다.

8정리와 다음 절

  • 컨텍스트 로트는 길이와 정보 위치에 따라 활용 결과가 달라질 수 있는 현상입니다.
  • 실험은 질문·근거·모델을 고정하고 길이와 위치를 분리해야 합니다.
  • 이 실험에서는 위치별 차이를 관찰했지만 길이에 따른 단조 저하는 관찰하지 못했습니다.

9복습 문제

문제와 해설

1. 중간 위치가 실패했으므로 모든 모델이 중간 정보를 사용하지 못하나요?

해설 — 아닙니다. 하나의 로컬 모델과 특정 프롬프트의 결과입니다.

2. 이 실험에서 길이가 늘어날수록 성능이 계속 낮아졌나요?

해설 — 아닙니다. 시작 위치의 성공은 유지되었고 끝 위치는 긴 조건에서 성공했습니다.

3. 샘플링을 끈 같은 설정으로 두 번 호출한 결과는 독립 표본인가요?

해설 — 아닙니다. 같은 설정의 출력이 반복되는지 확인하는 중복 실행입니다.
