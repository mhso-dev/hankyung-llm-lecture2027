1학습 목표

  • 다음 토큰의 확률 분포와 샘플링의 관계를 말로 설명할 수 있습니다.
  • 같은 프롬프트와 난수 시드에서 temperature만 바꾸어 생성 결과를 비교할 수 있습니다.
  • 서로 다른 출력 수와 생성 품질을 구분하고 관찰하지 못한 효과를 과장하지 않을 수 있습니다.
  • 최대 생성 토큰 수 때문에 문장이 잘린 흔적을 출력에서 찾을 수 있습니다.

2이 내용을 배우는 이유

언어 모델은 입력 뒤에 올 토큰을 하나씩 선택해 문장을 만듭니다. 같은 질문이라도 샘플링을 사용하면 실행할 때마다 다른 표현이 나올 수 있습니다. 아이디어 이름을 여러 개 만들 때는 이러한 변화가 유용할 수 있지만, 데이터 형식이나 정책 답변처럼 일정한 결과가 필요한 작업에서는 변화가 검증을 어렵게 합니다. 개발자는 temperature 값을 높이거나 낮추는 방법만 외우기보다, 무엇을 고정했고 무엇을 측정했는지 구분해야 합니다. 한 번의 출력이 마음에 들었다는 인상만으로 설정을 정하면 다른 입력에서 결과가 달라졌을 때 원인을 찾기 어렵습니다.

이 절에서는 로컬 생성 모델을 사용해 같은 행사 이름 제안 프롬프트를 반복 실행합니다. temperature 0.3과 1.0에서 난수 시드 11, 22, 33을 동일하게 사용하고, top-p와 최대 생성 길이도 고정합니다. 이렇게 하면 두 조건의 차이는 temperature에 집중됩니다. 그러나 반복 횟수는 조건마다 세 번뿐이고 모델도 하나입니다. 결과는 temperature의 보편적인 효과를 증명하는 자료가 아니라, 이 실행 조건에서 실제로 나온 문자열을 읽는 연습 자료입니다.

3앞에서 배운 내용

01절에서 문장이 토큰으로 나뉘고 모델이 토큰 단위로 입력을 처리한다는 점을 확인했습니다. 03절에서는 어텐션이 현재 표현을 만들 때 입력 토큰의 관계에 가중치를 두는 방식을 살펴봤습니다. 04절과 05절에서는 모델이 받을 수 있는 입력 길이와 긴 문맥에서의 관찰 범위를 구분했습니다. 이번 절은 입력을 처리한 뒤 출력 토큰을 선택하는 단계에 초점을 둡니다. 노트북은 Qwen/Qwen2.5-0.5B-Instruct의 고정 revision을 로컬에서 불러오며 외부 생성 API를 호출하지 않습니다.

실행 함수 generate()는 사용자 문장을 채팅 템플릿에 넣고 tokenizer로 숫자 ID로 변환합니다. model.generate()가 새 토큰을 만들고, 입력 길이 이후의 토큰만 잘라 다시 문자열로 해석합니다. torch.inference_mode()는 학습에 필요한 기울기 기록을 하지 않아 생성에 필요한 계산만 수행하게 합니다. 이 코드는 Transformer 내부 구조를 구현하는 실습이 아닙니다. 이미 학습된 모델의 생성 설정을 바꾸고 출력 차이를 관찰하는 실습입니다.

4핵심 개념

후보 토큰이 적힌 제비를 뽑습니다

모델은 다음 위치의 각 토큰 후보에 로짓(logit)이라는 변환 전 점수를 계산합니다. 로짓은 확률이 아니므로 합이 1일 필요가 없고 음수일 수도 있습니다. 소프트맥스(softmax)는 로짓을 0과 1 사이의 값으로 바꾸고 합이 1인 확률 분포를 반환합니다. temperature는 소프트맥스를 적용하기 전에 로짓의 상대적인 차이를 조정합니다. 노트북은 실제 Qwen 로짓을 추출하지 않고 [2.0, 1.0, 0.0]이라는 교재용 입력으로 이 변환만 먼저 확인합니다.

문장을 이어 쓸 수 있는 후보 토큰이 세 개이고 각 후보 토큰이 적힌 제비의 수가 다르다고 생각해 봅니다. 가능성이 높은 후보의 제비가 많으면 자주 선택되지만, 제비가 하나라도 있는 다른 후보도 뽑힐 수 있습니다. 모델의 확률 분포(probability distribution)는 다음 위치에 올 각 토큰의 상대적인 가능성을 나타냅니다. 샘플링(sampling)은 이 분포를 사용해 후보 중 하나를 확률적으로 선택하는 방식입니다. 선택한 토큰을 입력 뒤에 붙인 다음 같은 과정을 반복하므로 앞의 작은 차이가 이후 문장 전체의 차이로 이어질 수 있습니다.

temperature는 샘플링 전에 후보 확률의 상대적인 차이를 조정하는 값입니다. 낮은 값에서는 원래 가능성이 높은 후보에 선택이 더 집중되고, 높은 값에서는 낮은 후보도 선택될 여지가 커집니다. 이것은 정확도 조절 손잡이가 아닙니다. 낮춘다고 사실성이 자동으로 높아지지 않고, 높인다고 유용한 창의성이 자동으로 늘어나지 않습니다. 모델, 프롬프트, 후보 분포, 다른 생성 설정이 함께 결과에 영향을 줍니다.

top-p는 누적 확률이 지정값에 이를 때까지 가능성이 높은 후보 집합을 구성하고 그 안에서 샘플링하는 설정입니다. 실습은 0.9로 고정하므로 temperature 비교 중 후보 집합 제한 방식은 바뀌지 않습니다. 난수 시드(random seed)는 난수 생성의 시작 상태를 정하는 정수입니다. 같은 환경과 연산에서 설정 비교를 재현하는 데 도움이 되지만, 라이브러리·하드웨어·알고리즘이 바뀌어도 동일한 문자열을 보장하는 규격은 아닙니다.

최대 생성 토큰 수(max new tokens)는 모델이 입력 뒤에 추가할 토큰의 상한입니다. 이 값은 글자 수나 어절 수가 아닙니다. 실습은 계산 시간을 줄이려고 24로 제한합니다. 모델이 마침표나 종료 토큰을 선택하기 전에 상한에 도달하면 문장이 중간에서 잘립니다. 출력이 짧다는 사실을 지시 준수로 해석하기 전에 문장이 자연스럽게 끝났는지 확인해야 합니다.

도식 읽기

도식은 왼쪽에서 오른쪽으로 동일 프롬프트, T=0.3 / T=1.0, 각 3회 샘플링, 둘 다 3/3 서로 다름을 차례로 놓습니다. 네 상자는 직선 화살표로 이어집니다. top-p, 난수 시드, 최대 생성 길이처럼 실습에서 함께 고정한 조건과 문장 중간 잘림은 아래 실행 결과에서 확인합니다. 마지막 상자는 높은 temperature의 우위를 뜻하지 않고, 이 실행에서는 두 조건 모두 세 문자열이 서로 달랐다는 관찰만 나타냅니다.

5실행 예제

첫 코드 셀은 모델과 tokenizer를 고정 revision으로 불러오고 파라미터 수 494,032,768개를 출력합니다. 파라미터는 학습 과정에서 조정된 수치이며 모델 파일 크기, 메모리 사용량, 생성 속도와 같은 값이 아닙니다. 다음 교재용 최소 예제는 로짓 [2, 1, 0]을 T=0.5와 T=1.0의 확률로 바꾸고 각 합이 1인지 출력합니다. 이 결과를 읽은 뒤 프롬프트·temperature·seed·최대 생성 토큰을 입력받아 답변 문자열을 반환하는 generate() 함수를 정의합니다. return_tensors="pt"는 토큰 ID를 PyTorch 텐서로 만들고, pad_token_id는 길이를 맞추는 위치에 종료 토큰 ID를 사용하게 합니다. 모델 반환값에서 입력 길이까지를 잘라 새 토큰 ID만 고른 뒤 decode()가 특수 토큰을 제외한 문자열로 바꿉니다. 실제 생성에서는 temperature가 0보다 클 때 샘플링을 켜고 top-p 0.9를 사용합니다.

반복 생성 셀은 “오프라인 서점의 가을 행사 이름을 한국어 5어절 이내로 하나 제안하세요”라는 프롬프트를 고정합니다. temperature 0.3에서 시드 11·22·33을 실행한 다음 temperature 1.0에서 같은 세 시드를 실행합니다. 낮은 조건에서도 세 출력이 모두 달랐고 높은 조건에서도 세 출력이 모두 달랐습니다. 일부 결과는 번호 목록을 만들거나 영어를 섞었고, 봄 행사라고 잘못 쓰거나 요청과 관련 없는 사과 문장을 생성했습니다. 생성 결과가 서로 다르다는 사실과 요청을 잘 수행했다는 평가는 별개입니다.

temperature와 샘플링

같은 프롬프트에서 temperature를 바꾸면 반복 출력의 다양성이 어떻게 달라질까요?

Python 3.12와 잠긴 패키지를 사용합니다. 첫 실행에서는 로컬 모델을 다운로드합니다.

로컬 생성 모델 준비

고정 revision의 사전학습 모델을 불러옵니다. AutoTokenizer.from_pretrained()는 문자열과 토큰 ID를 서로 바꾸는 tokenizer 객체를 반환하고, AutoModelForCausalLM.from_pretrained()는 다음 토큰을 생성하는 모델 객체를 반환합니다. 두 객체를 준비한 뒤 로짓과 확률의 관계부터 확인합니다.

In [1]:
# 위 설명의 조건을 실행하고 실제 출력을 확인합니다.
import warnings
warnings.filterwarnings("ignore", message="IProgress not found")

로짓을 확률로 바꾸기

로짓은 모델이 다음 토큰 후보마다 계산한 변환 전 점수입니다. 아래의 세 값은 설명을 위해 정한 예이며 실제 Qwen에서 추출한 값이 아닙니다. torch.tensor([2.0, 1.0, 0.0])는 세 후보 점수를 담은 1차원 PyTorch 숫자 배열을 만듭니다. dim=0은 이 1차원 배열의 후보 축 전체에 softmax를 적용한다는 뜻입니다. 로짓을 temperature로 나눈 뒤 softmax를 적용하면 합이 1인 확률이 반환됩니다. 두 출력에서 가장 큰 후보는 유지되는지, 후보 사이의 확률 차이는 어떻게 달라지는지 읽습니다.

In [2]:
# 위 설명의 조건을 실행하고 실제 출력을 확인합니다.
toy_logits = torch.tensor([2.0, 1.0, 0.0])
for temperature in [0.5, 1.0]:
    probabilities = torch.softmax(toy_logits / temperature, dim=0)
    rounded = []
    for probability in probabilities.tolist():
        rounded.append(round(probability, 4))
    print(f"T={temperature:.1f} probabilities:", rounded)
    print("합계:", round(float(probabilities.sum()), 4))
출력:
T=0.5 probabilities: [0.8668, 0.1173, 0.0159]
합계: 1.0
T=1.0 probabilities: [0.6652, 0.2447, 0.09]
합계: 1.0

생성 도우미의 입력과 반환

generate()는 프롬프트 문자열, temperature, 난수 시드, 최대 생성 토큰 수를 입력받고 새로 생성된 답변 문자열을 반환합니다. messages는 사용자 역할과 프롬프트를 묶습니다. apply_chat_template(..., tokenize=False)는 역할 표시가 포함된 문자열을 반환하고, tokenizer의 return_tensors="pt"는 모델에 전달할 PyTorch 텐서를 반환합니다.

set_seed()는 난수 시작 상태를 정합니다. model.generate()는 입력 텐서와 생성 옵션을 호출 시점에 받아 새 토큰 ID를 만듭니다. do_sample은 temperature가 0보다 클 때만 샘플링을 켭니다. 이 실습은 샘플링 조건에서 top_p=0.9를 고정합니다. pad_token_id는 길이를 맞추는 패딩 위치에 종료 토큰 ID를 사용하도록 지정합니다.

모델 반환값에는 입력 ID와 새 출력 ID가 함께 있습니다. output[0, inputs["input_ids"].shape[1]:]는 입력 길이까지를 제외하고 새 ID만 고릅니다. decode(..., skip_special_tokens=True)는 특수 토큰 표시를 빼고 문자열로 바꾸며, strip()은 문자열 양끝의 공백을 제거합니다.

In [3]:
def generate(prompt: str, *, temperature: float = 0.7, seed: int = 0, max_new_tokens: int = 48) -> str:
    # 채팅 템플릿을 적용한 뒤 새로 생성된 토큰만 복원합니다.
    messages = [{"role": "user", "content": prompt}]
    text = tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tokenizer(text, return_tensors="pt")
    set_seed(seed)
    with torch.inference_mode():
        output = model.generate(
            **inputs,
            max_new_tokens=max_new_tokens,
            do_sample=temperature > 0,
            temperature=temperature if temperature > 0 else None,
            top_p=0.9 if temperature > 0 else None,
            pad_token_id=tokenizer.eos_token_id,
        )
    new_tokens = output[0, inputs["input_ids"].shape[1]:]
    return tokenizer.decode(new_tokens, skip_special_tokens=True).strip()

temperature별 반복 생성

프롬프트, top-p, 최대 생성 길이와 시드 세 개는 고정하고 temperature만 0.3과 1.0으로 바꿉니다. 각 줄은 temperature → seed → 반환 문자열 순서입니다. 같은 시드끼리 두 temperature 결과를 대응해 읽은 뒤, 세 번 전체의 문자열 차이를 확인합니다.

In [4]:
# 위 설명의 조건을 실행하고 실제 출력을 확인합니다.
prompt = "오프라인 서점의 가을 행사 이름을 한국어 5어절 이내로 하나 제안하세요."
records = []
for temperature in [0.3, 1.0]:
    for seed in [11, 22, 33]:
        answer = generate(prompt, temperature=temperature, seed=seed, max_new_tokens=24)
        records.append((temperature, seed, answer))
        print(f"T={temperature:.1f} seed={seed}: {answer}")
출력:
T=0.3 seed=11: "열정과 풍부한 책: 오프라인 서점의 가을 행사를 맞이
출력:
T=0.3 seed=22: 1. "열매와 함께: 가을의 풍경"
2. "오늘의 날

6실험 결과 해석

이번 실행에서 temperature 0.3의 세 답은 모두 서로 달랐습니다. temperature 1.0의 세 답도 모두 서로 달랐습니다. 문자열의 완전 일치 여부만 센 unique 값은 양쪽 모두 3/3입니다. 따라서 이 결과만으로 temperature를 0.3에서 1.0으로 올렸더니 출력 다양성이 증가했다고 말할 수 없습니다. 낮은 조건에서도 이미 세 번 모두 다른 문자열이 나왔기 때문입니다. 더 많은 반복, 다양한 프롬프트, 단어·의미 수준의 거리 지표를 미리 정한 뒤 측정해야 차이를 비교할 수 있습니다.

출력의 품질도 별도로 봐야 합니다. 0.3 조건의 한 답은 가을 질문에 “봄행사”를 포함했고, 1.0 조건의 한 답은 실시간 정보가 없다는 사과로 시작했습니다. 다른 답에는 영어 표현이나 자연스럽지 않은 문자열이 섞였습니다. 문자열이 다르면 unique 수는 늘지만 행사 이름으로 쓸 수 있는지는 알려 주지 않습니다. 실제 작업에서는 어절 수, 계절 관련성, 금지어, 발음 가능성 같은 평가 기준을 만들고 사람이 읽거나 자동 검사로 확인해야 합니다.

여섯 출력 가운데 여러 문장이 인용부호, 단어, 목록의 중간에서 끝났습니다. max_new_tokens=24가 새 토큰 생성을 멈췄기 때문입니다. 이 절단은 temperature 차이라고 해석할 수 없습니다. 두 조건에 동일한 제한이 적용됐고 각 응답이 종료 토큰을 선택하기 전에 한도에 도달할 수 있습니다. 생성 길이를 늘리면 완결성이 나아질 수 있지만 계산 시간과 출력 비용도 늘어납니다. 길이 설정을 바꾼 새 실험은 이번 temperature 비교와 분리해 기록해야 합니다.

7주의할 점과 실무 메모

  • temperature는 샘플링을 사용할 때 확률 분포에 영향을 줍니다. greedy 방식처럼 가장 높은 후보를 고정 선택하는 생성에서는 같은 의미로 비교할 수 없습니다.
  • temperature와 top-p를 동시에 바꾸면 어느 설정이 결과 차이를 만들었는지 분리하기 어렵습니다. 한 비교에서는 바꿀 값을 하나로 제한합니다.
  • 난수 시드를 고정해도 모든 기기와 라이브러리 버전에서 같은 문자열이 나온다고 보장할 수 없습니다. 모델 ID, revision, 패키지와 실행 장치를 함께 기록합니다.
  • 서로 다른 문자열 수는 의미 다양성, 사실성, 문법, 업무 적합성을 측정하지 않습니다. 목적에 맞는 별도 평가 항목이 필요합니다.
  • 짧은 최대 생성 길이는 실행 시간을 줄이지만 답을 중간에서 끊을 수 있습니다. 종료 이유와 잘림 여부를 읽고 결과를 평가합니다.
  • 0.49B 파라미터의 작은 로컬 모델 한 개에서 관찰한 결과를 더 큰 모델이나 상용 API 전체의 특성으로 일반화하지 않습니다.

8정리와 다음 절

  • 샘플링은 다음 토큰의 확률 분포에서 후보를 선택하며 temperature는 후보 확률의 상대적인 집중도를 조정합니다.
  • 이번 세 번의 실행에서는 temperature 0.3과 1.0 모두 서로 다른 문자열이 3개여서 다양성 증가를 관찰하지 못했습니다.
  • 최대 생성 24토큰 때문에 여러 답이 중간에서 끝났고, 문자열 종류 수는 결과 품질을 알려 주지 않았습니다.

다음 학습과 이어지는 지점 — 다음 절에서는 출력이 자연스럽게 이어진다는 성질이 사실 확인과 같은 능력이 아님을 확인합니다. 근거가 없는 고유 정보 질문에서 모델이 추측하거나 불확실성을 표현하는 두 결과를 구분합니다.

9복습 문제

문제와 해설

1. 이번 실험에서 temperature 1.0이 0.3보다 출력 다양성을 높였다고 결론 내릴 수 없는 이유는 무엇입니까?

정답: 문자열 완전 일치로 센 서로 다른 답 수가 두 조건 모두 3/3이었기 때문입니다. 반복도 조건당 세 번뿐이어서 더 넓은 효과를 판단할 근거가 부족합니다.

2. 난수 시드 11·22·33을 두 temperature 조건에서 같게 사용한 이유는 무엇입니까?

정답: 난수 시작 조건을 대응시키고 temperature 외의 비교 조건을 가능한 한 같게 유지하기 위해서입니다.

3. 출력이 따옴표나 단어 중간에서 끝난 가장 직접적인 설정 원인은 무엇입니까?

정답: 최대 생성 길이를 24개의 새 토큰으로 제한해 종료 토큰 전에 생성 상한에 도달했기 때문입니다.

4. unique=3/3이 알려 주는 것과 알려 주지 않는 것을 각각 쓰십시오.

정답: 세 문자열이 정확히 서로 달랐다는 점은 알려 줍니다. 의미 다양성, 계절 관련성, 어절 수 준수, 사실성, 행사 이름의 품질은 알려 주지 않습니다.
