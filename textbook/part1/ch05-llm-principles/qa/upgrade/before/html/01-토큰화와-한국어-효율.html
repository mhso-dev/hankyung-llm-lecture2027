2이 내용을 배우는 이유

대규모 언어 모델(Large Language Model, LLM)은 문장을 글자 단위로 바로 처리하지 않습니다. 문장을 토큰이라는 작은 텍스트 단위로 나눈 뒤 각 토큰을 숫자 ID로 바꾸어 처리합니다. 모델 사용량, 입력 길이, 응답 시간을 이해하려면 먼저 토큰을 세어야 합니다. 한국어는 토큰화기의 어휘와 학습 자료에 따라 한 글자가 여러 토큰으로 나뉠 수 있으므로 실측이 필요합니다.

4핵심 개념

정의와 관찰

토큰(token)은 모델이 처리하는 텍스트 단위입니다. 토큰은 한 단어일 수도 있고 단어의 조각이나 문장부호일 수도 있습니다. 토큰화(tokenization)는 텍스트를 이러한 단위로 나누고 각 단위를 정수 ID에 연결하는 과정입니다. 모델은 ID 열을 입력받으므로 같은 문장도 토큰화기가 다르면 다른 숫자 열이 됩니다.

어휘(vocabulary)는 토큰화기가 알고 있는 토큰과 ID의 목록입니다. 영어 자료를 중심으로 만든 어휘에는 흔한 영어 단어 조각이 많습니다. 한국어 자료를 반영한 어휘는 '확인', '환불'과 같은 조각을 하나의 토큰으로 가질 수 있습니다. 이 차이는 언어의 우열이 아니라 어휘 설계와 학습 자료의 차이입니다.

토큰화기의 입력은 사람이 읽는 문자열이고, 처리는 문자열을 어휘에 있는 조각과 연결하는 일입니다. tokenize(text)는 조각의 문자열 목록을 반환하고, encode(text)는 조각에 대응하는 정수 ID 목록을 반환합니다. 여기서 반환은 함수가 계산을 마친 뒤 호출한 코드에 결과값을 넘긴다는 뜻입니다. len(...)은 반환된 목록에 들어 있는 항목 수를 셉니다.

AutoTokenizer.from_pretrained(model_id, revision=...)는 모델 ID와 고정 revision을 입력받아 해당 파일을 불러오고 tokenizer 객체를 반환합니다. revision은 같은 이름의 모델 파일이 나중에 바뀌어도 실습에서 확인한 버전을 다시 받기 위한 식별자입니다. vocab_size는 어휘에 등록된 토큰 ID 개수를 정수로 반환합니다. 어휘 크기가 크다는 사실만으로 한국어가 더 적은 토큰으로 나뉜다고 판단할 수는 없습니다.

예를 들어 입력 "환불!"이 ["환불", "!"]처럼 나뉘었다면 토큰 수는 2입니다. 실제 분할은 토큰화기마다 다르므로 이 모양을 외우지 않습니다. 노트북에서는 같은 입력을 두 토큰화기에 전달하고, 반환된 목록의 길이와 각 조각을 함께 출력해 차이를 읽습니다.

두 토큰화기는 '오늘 주문 상태를 확인해 주세요.'라는 문장을 각각 39개와 9개의 토큰으로 나눕니다. 반면 영어 번역문은 각각 7개와 15개였습니다. 이 결과는 특정 문장과 두 토큰화기에서 관찰한 값입니다. '한국어는 항상 비효율적이다'라는 보편적 결론을 내릴 수는 없습니다.

토큰 수는 비용만이 아니라 컨텍스트 윈도에도 영향을 줍니다. 같은 내용을 더 많은 토큰으로 표현하면 모델에 넣을 수 있는 원문의 양이 줄어듭니다. 그러므로 프로덕션에서는 문자 수나 단어 수로 사용량을 추정하지 않고 실제 모델의 토큰화기로 측정합니다.

토큰 수를 비교할 때는 원문의 의미와 형식을 함께 기록합니다. 한국어와 영어 번역문은 비슷한 뜻을 담을 수 있지만 문법 구조와 문자 수가 다릅니다. 그러므로 '뜻이 같다'는 것을 자동으로 통제된 실험으로 보면 안 됩니다. 실습의 두 문장 쌍은 분할 모양을 읽는 예시입니다. 업무용 효율을 비교할 때는 실제 서비스의 대화, 문서, 코드 표본을 같은 비율로 구성하고 모델별 토큰 수의 분포를 측정합니다.

토큰화기는 보이는 문자 외에 특수 토큰(special token)을 추가할 수 있습니다. 문장의 시작과 끝, 발화자 역할, 문장 쌍의 경계를 표시하는 토큰이 예입니다. tokenize()의 결과와 실제 모델 입력의 길이가 다를 수 있는 이유입니다. 특히 채팅 모델은 대화 템플릿이 역할 표시와 생성 시작 표시를 덧붙입니다. 다른 절에서 입력 길이를 측정할 때는 이 템플릿을 적용한 후의 토큰 수를 사용합니다.

출력의 'Ġ'나 '##'와 같은 표시는 사용자 문장에 추가된 글자가 아닙니다. 토큰화기가 공백 앞의 조각인지, 앞 조각에 이어지는 부분인지 표시하는 방식입니다. 입문 단계에서는 표시 자체를 외우기보다 원문이 어떤 조각으로 나뉘었는지 확인합니다. 예상보다 많이 나뉜 단어가 있다면 해당 모델의 어휘에서 흔하지 않은 표현일 가능성을 점검합니다.

토큰화와 한국어 효율

같은 뜻을 담은 한국어와 영어 문장은 토큰화 방식에 따라 몇 개의 토큰이 될까요?

Python 3.12와 잠긴 패키지를 사용합니다. 첫 실행에서는 로컬 모델을 다운로드합니다.

두 토큰화기 준비

AutoTokenizer.from_pretrained(model_id, revision=...)는 모델 ID와 고정 revision을 입력받아 해당 파일을 불러오고 tokenizer 객체를 반환합니다. revision은 같은 이름의 모델 파일이 나중에 바뀌어도 이 실습에서 확인한 버전을 다시 받기 위한 식별자입니다. vocab_size는 tokenizer 어휘에 등록된 토큰 ID 개수를 정수로 반환합니다. 어휘 크기가 크다는 사실만으로 한국어가 더 적은 토큰으로 나뉜다고 판단할 수는 없습니다.

토큰화기의 입력은 사람이 읽는 문자열입니다. tokenize(text)는 토큰 문자열 목록을, encode(text)는 토큰 ID의 정수 목록을 반환합니다. 반환은 함수가 계산한 값을 호출한 코드에 넘긴다는 뜻입니다. 아래 셀은 두 tokenizer 객체와 각각의 어휘 크기를 출력합니다.

In [1]:
import warnings
warnings.filterwarnings("ignore", message="IProgress not found")
from transformers import AutoTokenizer

# 모델 ID와 고정 revision에 맞는 두 토큰화기를 로컬에 받아 사용합니다.
gpt2 = AutoTokenizer.from_pretrained("openai-community/gpt2", revision="607a30d783dfa663caf39e06633721c8d4cfcd7e")
ko_tokenizer = AutoTokenizer.from_pretrained("klue/bert-base", revision="77c8b3d707df785034b4e50f2da5d37be5f0f546")
print("GPT-2 어휘 크기:", gpt2.vocab_size)
print("KLUE BERT 어휘 크기:", ko_tokenizer.vocab_size)
출력:
GPT-2 어휘 크기: 50257
KLUE BERT 어휘 크기: 32000

확인할 점 — 첫 한국어 문장에서 GPT-2와 KLUE의 토큰 수와 조각이 어떻게 다른가요? 반복 횟수가 1에서 8로 늘 때 두 토큰 수는 어떤 규칙으로 변하나요?

6실험 결과 해석

짧은 한국어 문장 하나를 1, 2, 4, 8회 반복했을 때 GPT-2의 토큰 수는 37, 75, 151, 303이었고 KLUE의 토큰 수는 8, 16, 32, 64였습니다. 공백이 추가된 GPT-2 결과는 단순히 정확한 배수가 되지 않았습니다. 이 실험은 문장을 반복한 특수한 조건의 분할 결과만 보여 줍니다. 일반적인 한국어 토큰 효율을 평가하려면 대화, 문서, 코드가 섞인 더 넓은 자료를 사용해야 합니다.

7주의할 점과 실무 메모

  • 토큰 ID는 토큰화기마다 다르므로 서로 바꿔 사용할 수 없습니다.
  • 패키지 버전과 모델 revision을 고정해야 분할 결과를 재현하기 쉬워집니다.
  • 첫 실행은 토큰화기 파일을 다운로드합니다. 오프라인 환경에서는 미리 캐시를 준비해야 합니다.

8정리와 다음 절

  • 토큰은 모델이 처리하는 텍스트 단위입니다.
  • 같은 문장도 토큰화기에 따라 분할과 토큰 수가 달라집니다.
  • 사용량은 실제 모델의 토큰화기로 측정합니다.

다음 학습과 이어지는 지점 — 다음 절에서는 토큰 열을 문장의 의미를 담은 숫자 벡터로 바꾸고 비교합니다.

9복습 문제

문제와 해설

1. 토큰은 항상 한 단어와 같은가요?

해설 — 아닙니다. 단어, 단어 조각, 문장부호 등이 토큰이 될 수 있습니다.

2. 문자 수만으로 모델 사용량을 정확히 계산할 수 있나요?

해설 — 계산할 수 없습니다. 모델의 토큰화기로 인코딩한 토큰 수를 확인합니다.

3. 두 토큰화기의 수치로 언어 자체의 효율을 단정할 수 없는 이유는 무엇인가요?

해설 — 어휘, 학습 자료, 분할 규칙이 다르기 때문입니다. 특정 모델과 자료의 결과로 범위를 한정해야 합니다.
