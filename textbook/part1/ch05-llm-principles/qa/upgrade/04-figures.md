# 04 컨텍스트 윈도 — 그림 설계표

| 번호 | 위치 | 종류 | 설명 대상 문장 | 보여 줄 실제 값 | 색 |
|---|---|---|---|---|---|
| 04-5 | 4 핵심 개념 · 비유로 시작하기 | Higgsfield 삽화 | 쟁반의 칸 전체가 컨텍스트 윈도이고, 칸막이 뒤 빈칸이 답을 위해 떼어 둔 출력 몫입니다. 칸보다 많은 블록은 쟁반 밖에 남습니다. | 값 없음(비유). 칸 12개 쟁반, 채운 칸 9개, 칸막이, 빈칸 3개, 쟁반 밖 블록(01-5 블록 쟁반을 이어 씀) | — |
| 04-1 | 4 핵심 개념 · 입력은 세 부분과 표시로 이뤄집니다 (노트북 「오늘 볼 그림」) | Mermaid flowchart TB(위에서 두 갈래가 만남) | 한도에서 답을 위한 칸을 먼저 빼고, 남은 칸을 입력 한도로 씁니다. 한도와 비교할 수는 채팅 템플릿으로 합친 입력 400입니다. | [3절] `시스템 지시 | 12`, [4절] `사용자 메시지 토큰 수: 375`·`실제 입력 토큰 수: 400`·`세 부분의 합보다 늘어난 수: 13`, [6절] `64 | 448 | 48` | 노트북에서 정한 한도·출력 몫(정한 값) tool 초록, 출력으로 확인한 조각 수 measure 노랑, 빼기·합치기는 화살표 라벨 |
| 04-2 | 5 실행 예제 · 문서 길이와 입력 한도 | Mermaid xychart-beta(막대 + 선) | 반복 수가 늘수록 입력 조각 수가 같은 간격으로 늘었고, 448에 들어가는 가장 긴 문서는 22번 이은 문서였습니다. | [7절] `10 | 220 | True`·`20 | 400 | True`·`22 | 436 | True`·`23 | 454 | False`·`40 | 760 | False`·`80 | 1480 | False`, 입력 한도 448 | 막대(입력 토큰 수) 주황, 선(정한 입력 한도) 초록 `plotColorPalette: '#f59e0b, #22c55e'`(03-2 선례) |
| 04-4 | 5 실행 예제 · 출력 몫과 모델의 답 | Mermaid flowchart TB(모델 아래 두 갈래) | 출력 몫 64에서는 18조각을 쓰고 끝 표시로 멈췄고, 출력 몫 8에서는 답이 문장 가운데서 끊겼습니다. | [4절] `실제 입력 토큰 수: 400`, [9절] `새 조각 수: 18`·`끝 표시로 멈췄는가: True`, [10절] `새 조각 수: 8`·`답: 환불은 결제일로부터`·`끝 표시로 멈췄는가: False` | 입력 조각 수·새 조각 수 measure 노랑, 실행한 언어 모델 model 보라(02·03절 규칙), 메서드·출력 몫은 화살표 라벨 |
| 04-3 | 6 실험 결과 해석 | Mermaid flowchart TB(두 갈래 + 점선) | 40번 이은 입력의 한쪽 끝을 잘라 448조각만 남기자, 어느 쪽이든 입력의 중요한 부분이 빠졌습니다. | [8절] `원래 입력 토큰 수: 760`, `앞 448조각 | True | False | False`, `뒤 448조각 | False | True | True` | 입력·확인 결과 measure 노랑, 잘려 나간 부분 회색(클래스 없음). 코드가 멈춘 실패가 아니라 출력으로 확인한 결과라 빨강 없음 |

색 규칙: 01~03절을 이어받아 출력으로 확인한 수는 노랑, 실행한 언어 모델은 보라입니다. 노트북에서 정한 값(연습용 한도 512, 출력 몫 64, 입력 한도 선 448)은 03절 「교재에서 정한 벡터」처럼 초록입니다. 같은 요소는 절 안 모든 그림에서 같은 색입니다(채팅 템플릿 입력 400은 04-1·04-4 모두 노랑). 메서드와 계산 단계는 화살표 라벨로만 적어 파랑 상자는 없습니다. 빨강은 쓰지 않았습니다.
