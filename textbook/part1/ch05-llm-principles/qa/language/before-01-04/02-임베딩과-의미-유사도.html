1학습 목표

  • 문장 임베딩의 입력과 출력을 설명합니다.
  • 정규화된 벡터의 코사인 유사도를 계산합니다.
  • 유사도가 높다는 결과의 해석 범위를 설명합니다.

2이 내용을 배우는 이유

검색이나 문장 군집화에서는 단어가 정확히 같지 않아도 뜻이 가까운 문장을 찾아야 합니다. 임베딩은 문장을 고정된 길이의 숫자 목록으로 바꾸어 이런 비교를 가능하게 합니다. Ch 9에서 검색 증강 생성을 배울 때 문서와 질문을 임베딩하므로, 지금 숫자의 의미와 한계를 알아 둡니다.

3앞에서 배운 내용

앞 절에서 문장이 토큰 ID 열로 바뀌는 과정을 확인했습니다. 임베딩 모델은 이 열을 입력받아 문장 전체를 표현하는 벡터를 만듭니다. Ch 2의 NumPy 배열과 점곱 계산 방법을 사용합니다.

4핵심 개념

정의와 관찰

임베딩(embedding)은 텍스트의 특징을 실수 벡터로 표현한 결과입니다. 실습 모델은 문장 하나를 384개 숫자로 바꾸었습니다. 각 숫자 하나에 '취소'나 '날씨'같은 이름을 붙일 수는 없습니다. 의미는 여러 차원에 분산되어 표현되며, 벡터 전체의 방향과 거리를 사용해 문장을 비교합니다.

코사인 유사도(cosine similarity)는 두 벡터 사이의 각도를 이용한 비교 값입니다. 벡터를 길이 1로 정규화하면 두 벡터의 점곱으로 계산할 수 있습니다. 실습은 normalize_embeddings=True를 사용했으므로 vectors @ vectors.T가 유사도 행렬을 만듭니다.

실습에서 '주문한 상품을 취소하고 싶습니다.'와 영어 문장 'I want to cancel my order.'의 유사도는 0.8987이었습니다. 한국어 표현을 바꾼 '구매를 취소하려면 어떻게 하나요?'는 0.8024, 날씨 문장은 0.1044였습니다. 이 모델은 해당 입력에서 언어 표면보다 주문 취소라는 의미를 더 가깝게 배치했습니다.

유사도는 정답 판정이 아닙니다. '취소'와 '반품'은 관련 있지만 업무 규칙에서 다른 절차일 수 있습니다. 실습의 두 문장 유사도는 0.5931이었습니다. 숫자가 높아도 동일한 정책이나 동일한 사실을 뜻한다고 단정하지 않고, 작업에 맞는 임계값과 평가 자료를 따로 정합니다.

벡터의 차원 수가 많으면 더 많은 정보를 표현할 수는 있지만, 차원 수만으로 품질을 판단할 수는 없습니다. 384차원 모델이 768차원 모델보다 특정 업무에서 더 좋은 검색 결과를 낼 수도 있습니다. 학습 자료, 학습 목표, 입력 길이, 언어 지원이 품질에 함께 영향을 줍니다. 또한 차원이 늘면 벡터 저장 공간과 유사도 계산량이 늘어납니다. 모델 선택은 품질과 자원 제약을 함께 비교하는 문제입니다.

유사도 결과를 읽을 때는 먼저 비교 대상을 확인합니다. 0번 문장과 1, 2, 3번 문장을 각각 비교했으므로 수치는 모두 0번을 기준으로 합니다. 다음으로 순서와 간격을 봅니다. 0.8987과 0.8024는 모두 날씨 문장의 0.1044보다 높았습니다. 이 순서는 취소 의도를 나타내는 작은 표본에서 타당했습니다. 다만 다른 문장 표본에서도 같은 순서인지 재현해야 합니다.

다국어 유사도는 번역 성능과 관련되지만 같은 개념은 아닙니다. 실습은 한국어 문장과 영어 문장을 가깝게 배치했다는 것만 확인했습니다. 모델이 오류가 있는 번역을 감지하는지, 도메인 전문 용어를 유지하는지, 한국어 높임말과 반말의 차이를 어떻게 반영하는지는 알 수 없습니다. 해당 능력이 필요하면 별도의 번역 평가 자료를 준비합니다.

6실험 결과 해석

네 문장 한 번의 결과에서 취소 의도의 한·영 문장이 가장 가까웠고 날씨 문장이 가장 멀었습니다. 이 결과는 다국어 모델이 언어가 다른 문장을 가깝게 배치할 수 있음을 보여 줍니다. 다만 세 예시의 순서가 다른 도메인, 더 긴 문장, 부정문에서도 유지되는지는 알 수 없습니다. 실무 검색은 대표 질문 집합으로 성공률을 측정합니다.

7주의할 점과 실무 메모

  • 코사인 유사도의 절대 기준은 모델과 자료에 따라 달라집니다.
  • 해당 모델은 최대 128토큰을 기준으로 학습된 sentence-transformers 모델입니다. 긴 문서는 분할 전략이 필요합니다.
  • 모델 다운로드와 임베딩 계산은 메모리와 시간을 사용합니다. 배치 크기를 현재 장비에 맞춥니다.

8정리와 다음 절

  • 임베딩은 문장을 고정된 길이의 실수 벡터로 표현합니다.
  • 정규화된 벡터는 점곱으로 코사인 유사도를 계산할 수 있습니다.
  • 유사도는 정답이 아니므로 작업별 평가가 필요합니다.

다음 학습과 이어지는 지점 — 다음 절에서는 모델이 입력의 어느 부분을 관련 있다고 보는지 어텐션 직관으로 이어 갑니다.

9복습 문제

문제와 해설

1. 임베딩 벡터의 각 차원에 일상어 이름을 붙일 수 있나요?

해설 — 보통은 없습니다. 의미가 여러 차원에 분산되어 표현됩니다.

2. 정규화된 벡터에서 코사인 유사도를 어떻게 계산했나요?

해설 — 두 벡터의 점곱을 계산했습니다.

3. 유사도 0.9는 정답을 뜻하나요?

해설 — 아닙니다. 특정 모델이 두 텍스트를 가깝게 배치했다는 뜻이며, 정답은 작업 기준으로 확인합니다.
