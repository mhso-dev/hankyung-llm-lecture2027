## 범위와 보호 항목

`_src/`의 다섯 절, 노트북 다섯 개의 Markdown 셀 30개, `README.md`를 정독했습니다. 코드 셀 30개와 실행 출력은 읽기만 했고 수정하지 않았습니다. `ch03-before.json`은 코드 수정 전 감사 시작 시점의 스냅샷입니다. 뒤이어 집필자가 소유한 코드·출력 수정과 새 커널 실행이 있었으므로, 최종 무결성 기준은 그 handoff 뒤에 고정한 `ch03-after.json`입니다.

## 1차 일반 문체 검토

빈 결론, 과장, 반복적인 접속어, 근거 없는 일반화, 기계적인 열거를 전문 정독으로 확인했습니다. 의미 없는 문장이나 반복된 S1 표현은 찾지 못했습니다. 다만 실행 흐름과 맞지 않는 설명 두 곳을 고쳤습니다.

- 01절은 `.gitignore`만 첫 커밋에 기록하고 `app.py`를 두 번째 커밋에 기록한다는 실제 셀 순서로 바로잡았습니다.
- 01절 노트북의 기본 실행 Markdown도 같은 두 커밋 순서를 말하도록 고치고 `_make_notebooks.py`의 원본 문자열과 동기화했습니다. 코드와 출력 해시는 바뀌지 않았습니다.
- 03절은 기능 브랜치 병합으로 설명하던 부분을 Bob의 로컬 `main`에서 `git pull --no-rebase origin main`으로 원격 이력을 병합하는 실제 실패·해결 흐름으로 고쳤습니다. 학습 목표, 핵심 개념, 도식 캡션, 정리, 복습 문제도 같은 기준으로 맞췄습니다. 해결 문장은 노트북 출력과 같은 14시 이전·이후 출고 기준을 담습니다.
- 도식이 바뀐 뒤에는 다섯 절의 도식 읽기 문단을 새 SVG의 단계와 대조했습니다. 01절의 무시 규칙 분기, 02절의 검토·병합, 03절의 push 거부·pull 충돌, 04절의 독립적인 세 상황, 05절의 실제 유출과 더미 실습 경계가 각각 일치합니다.

## 2차 맞춤법 확인

`korean-spell-check`의 외부 맞춤법 서비스는 개인·비상업적 사용 및 대량 처리 금지 조건 때문에 사용하지 않았습니다. 대신 코드·경로·명령을 제외하고 전문을 다시 읽고, 자주 발생하는 띄어쓰기·활용 오류와 이중 공백을 로컬 검색했습니다. 발견한 오류는 없습니다.

## 3차 정밀 윤문과 메트릭

`korean-humanize` v1.4.0의 산문 기준으로 독자·편집자·낭독 관점에서 전문을 읽었습니다. 수치, 날짜, Git 명령, 경로, 실제 출력은 수정 대상으로 삼지 않았습니다.

| 항목 | 결과 |
|---|---|
| `metrics.py` | 23,543자, risk band `high` |
| `metrics_v2.py` | 기계적 동사 직역 0, 이중 피동 0, 수동태 0 |
| 구조 게이트 | `WARN` (exit 1) |
| P0 | 문자 변경률 0.9%로 저윤문 경고 |
| P1·P2·P3 | 통과: 사전 S1 지표 없음, 대구 7→7, 수치·인용·격식 보존 |
| P5 | 참고 보고: 평균 40.6자, 단문 22.4%, 최장 단문 연속 4개 |

`risk band`와 P5는 다양한 길이의 설명·목록·퀴즈를 한 텍스트로 측정한 참고 신호입니다. 정독 결과에서는 짧은 문장이 실제 명령과 출력 확인을 분리해 초보자의 읽기를 돕고, 같은 종결의 기계적 반복으로 읽히지 않았습니다. P0 경고는 필요한 수정이 0.9%뿐이라는 뜻이며, 고칠 근거가 없는 문장을 늘려 통과 수치에 맞추지 않았습니다.

## Phase 6: 의미·자연스러움 최종 판정

자연스러움: 다섯 절은 상황 설명, 명령의 효과, 실제 출력 확인, 주의 사항을 차례로 제시합니다. 경고 문장이 과장되거나 공포를 유발하지 않으며, 05절은 더미 문자열과 키 폐기·교체의 우선순위를 분명히 구분합니다.

의미 보존: 수정 전후에 학습 목표, Git 명령과 옵션, 버전·날짜·수치, 파일·브랜치·함수 이름, 직접 인용, 코드·출력, 한정어와 인과관계를 대조했습니다. 새 주장을 넣거나 기존 주장을 뺀 곳은 없습니다. 01절과 03절의 수정은 실제 노트북의 커밋·병합 경로를 더 정확히 설명합니다.

최종 판정: `accept`.
