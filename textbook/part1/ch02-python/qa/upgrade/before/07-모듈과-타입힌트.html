1학습 목표

  • 함수를 별도 .py 모듈에 정의하고 필요한 이름을 가져올 수 있습니다.
  • 함수의 매개변수와 반환값에 타입힌트를 작성하고 저장된 정보를 확인할 수 있습니다.
  • 타입힌트가 실행 시 입력을 검증하지 않는다는 사실을 실제 출력으로 설명할 수 있습니다.

2이 내용을 배우는 이유

프로그램이 길어지면 모든 함수와 클래스를 한 파일에서 찾기 어렵습니다. 가격 계산은 가격 모듈에 두고, 주문 출력은 실행 파일에 두면 각 파일의 역할이 분명해집니다. 다른 파일의 기능을 다시 작성하지 않고 가져와 사용할 수도 있습니다. 모듈은 코드의 위치를 나누고 이름의 출처를 표시하는 기본 단위입니다.

함수가 어떤 값을 받고 무엇을 반환하는지도 여러 파일 사이에서 알아볼 수 있어야 합니다. 타입힌트는 price: int와 -> str처럼 예상 타입을 코드에 적는 표기입니다. 편집기와 정적 타입 검사기는 이 정보를 읽어 잘못된 사용을 찾도록 돕습니다. 그러나 Python 실행기는 타입힌트를 보고 호출을 차단하지 않습니다. 외부 입력 검증은 별도의 처리이며, 이 차이를 모르면 표시만 믿고 잘못된 결과를 정상으로 사용할 수 있습니다.

3앞에서 배운 내용

04절에서 함수 이름 뒤의 괄호에 입력을 적고 return으로 결과를 반환하는 방법을 배웠습니다. 05절에서는 Path.write_text()로 문자열을 파일에 저장했습니다. 이번 절은 이 두 내용을 결합해 함수를 pricing.py에 저장하고 다른 파일에서 호출합니다. 06절의 클래스는 이 절의 필수 선행 지식이 아닙니다. 노트북은 임시 폴더에 pricing.py와 run_price.py를 새로 만들며 이전 커널의 값이나 개인 작업 파일을 사용하지 않습니다.

4핵심 개념

쉬운 예

서랍마다 문구류의 종류를 적어 두면 필요한 물건을 찾을 때 모든 서랍을 열지 않아도 됩니다. 모듈(module)은 관련된 Python 정의와 문장을 담는 .py 파일입니다. pricing.py라는 파일은 pricing이라는 모듈 이름으로 읽습니다. from pricing import add_tax는 “pricing 모듈에서 add_tax라는 이름을 현재 파일로 가져온다”라고 읽습니다. 가져온 뒤에는 add_tax(10000, 0.1)처럼 일반 함수와 같은 방식으로 호출합니다.

정의와 표기 읽기

import는 다른 모듈의 코드를 불러와 사용할 수 있게 하는 문장입니다. Python은 실행 파일이 있는 폴더 등 정해진 위치에서 모듈을 찾고, 처음 가져올 때 그 파일의 최상위 문장을 실행한 뒤 정의된 이름을 사용할 수 있게 합니다. 네임스페이스(namespace)는 이름과 값의 대응을 관리하는 범위입니다. import pricing은 모듈 이름을 유지하여 pricing.add_tax()로 호출합니다. from pricing import add_tax는 선택한 이름을 현재 범위에 두어 add_tax()로 호출합니다.

타입힌트(type hint)는 변수, 매개변수, 반환값의 예상 타입을 표시한 정보입니다. def add_tax(price: int, rate: float) -> int:에서 price: int는 price에 정수를 예상하고, rate: float는 rate에 실수를 예상한다는 뜻입니다. 화살표 뒤의 int는 함수가 정수를 반환할 것이라는 표시입니다. 이 표기는 호출할 때 값을 전달하거나 반환하는 동작을 만들지 않습니다. 실제 입력은 괄호 안의 10000과 0.1이고, 본문의 return이 계산한 정수가 호출 위치로 반환됩니다.

정적 타입 검사(static type checking)는 프로그램을 실행하기 전에 타입힌트와 코드 사용이 맞는지 분석하는 과정입니다. 타입힌트는 문서와 도구를 위한 정보이며 런타임 검증(runtime validation)을 자동으로 수행하지 않습니다. 런타임 검증은 실행 중 실제 값이 조건에 맞는지 확인하고, 맞지 않으면 변환하거나 오류를 알리는 별도 동작입니다.

도식 읽기

위쪽 줄은 pricing.py 작성, run_price.py에서 함수 가져오기, 정수 가격과 실수 세율 전달, 정수 11000 반환의 순서입니다. 아래쪽은 타입힌트가 실행 중 입력을 자동으로 검사하지 않는다는 별도의 비교입니다. double_total에 문자열 "1200"을 넣으면 함수 본문은 문자열 곱셈을 실행해 "12001200"을 반환합니다. 호출 전에 정수로 변환하면 같은 본문이 숫자 곱셈을 실행해 2400을 반환합니다.

5실행 예제

첫 셀은 파일을 저장할 임시 폴더를 만듭니다. 다음 셀에서 module_source 문자열을 pricing.py로, runner_source 문자열을 run_price.py로 저장합니다. 실행 시점에는 run_price.py의 import 문이 먼저 pricing.py를 찾고, 이어서 add_tax(10000, 0.1)가 가격 10,000과 세율 0.1을 함수에 전달합니다. 함수는 price * (1 + rate)를 계산하고 반올림한 정수 11000을 반환하며, print()가 그 값을 화면에 표시합니다.

다음 셀의 label_price(price: int) -> str는 정수 가격을 입력받아 "12,000원" 같은 문자열을 반환한다고 읽습니다. __annotations__ 출력은 개발자가 적은 표시가 함수 객체에 저장되었음을 보여 줄 뿐, 호출값을 검사했다는 뜻은 아닙니다. 값 하나 비교에서는 함수와 표시 형식을 그대로 두고 호출 인자만 12000에서 25000으로 바꿉니다. 반환 문자열이 각각 12,000원과 25,000원으로 달라지는지 확인합니다.

모듈과 타입힌트

함수를 별도 모듈로 나누고, 타입힌트의 역할과 한계를 어떻게 확인할까요?

실행 환경 준비

Python 3.12 표준 라이브러리만 사용합니다. 04절에서 배운 함수 호출과 05절에서 배운 파일 저장을 결합합니다. 06절의 클래스는 필요하지 않습니다. 모듈 파일은 임시 폴더에 만들고 하위 프로세스에서 불러옵니다.

In [1]:
# 모듈과 실행 파일을 저장할 실습 전용 임시 폴더를 준비합니다.
from pathlib import Path
from subprocess import run
from sys import executable
from tempfile import TemporaryDirectory

workspace = TemporaryDirectory(prefix="ch02_07_")
module_dir = Path(workspace.name)
print("모듈 실습 폴더 준비 완료")
출력:
모듈 실습 폴더 준비 완료

기본 실행

pricing.py는 함수를 담은 모듈입니다. from pricing import add_tax는 ‘pricing 모듈에서 add_tax라는 이름을 가져온다’라고 읽습니다. 실행 파일이 add_tax(10000, 0.1)을 호출하면 정수 가격과 실수 세율이 매개변수에 전달되고, 함수가 계산한 정수 11000이 호출 위치로 반환됩니다.

In [2]:
# 계산 함수를 모듈에 저장하고 별도 파일에서 import하여 호출합니다.
module_source = '''def add_tax(price: int, rate: float) -> int:
    return round(price * (1 + rate))
'''
runner_source = '''from pricing import add_tax

print(add_tax(10000, 0.1))
'''
(module_dir / "pricing.py").write_text(module_source, encoding="utf-8")
(module_dir / "run_price.py").write_text(runner_source, encoding="utf-8")
completed = run([executable, "run_price.py"], cwd=module_dir, capture_output=True, text=True, check=True)
print("세금 포함 가격:", completed.stdout.strip())
출력:
세금 포함 가격: 11000

중간 결과 관찰

def label_price(price: int) -> str에서 price: int는 정수 입력을 예상한다는 표시이고, 화살표 뒤의 str는 문자열 반환을 예상한다는 표시입니다. 함수의 __annotations__에는 이 정보가 저장됩니다. 표시는 호출 시점의 값을 자동 검사하지 않습니다.

In [3]:
# 타입힌트 정보와 실제 함수 반환값을 함께 확인합니다.
def label_price(price: int) -> str:
    return f"{price:,}원"

print(label_price.__annotations__)
print(label_price(12000))
출력:
{'price': <class 'int'>, 'return': <class 'str'>}
12,000원

값 하나를 바꿔 비교

같은 함수에서 가격 값만 바꾸면 반환 문자열이 어떻게 달라지는지 확인합니다.

In [4]:
# 함수에 전달하는 가격만 바꾸어 표시 결과를 비교합니다.
print("12,000 입력:", label_price(12000))
print("25,000 입력:", label_price(25000))
assert label_price(25000) == "25,000원"
출력:
12,000 입력: 12,000원
25,000 입력: 25,000원

확인할 점 — pricing.py의 입력은 두 숫자이고 반환은 정수 11000입니다. run_price.py의 print()가 반환값을 출력합니다. label_price()는 정수 하나를 받아 문자열을 반환하므로 타입힌트 정보와 실제 반환값을 나누어 읽어야 합니다.

6일부러 실패해 보기

Before의 double_total()은 정수를 받아 정수를 반환한다고 표시합니다. 하지만 호출할 때 문자열 "1200"을 전달해도 Python은 타입힌트를 근거로 예외를 발생시키지 않습니다. 문자열에 2를 곱하는 연산이 적용되어 "12001200"이 반환됩니다. 오류 메시지가 없다는 사실이 올바른 계산을 뜻하지는 않습니다.

After는 같은 입력 문자열 "1200"을 int()로 변환한 뒤 같은 함수에 전달합니다. 출력은 숫자 2400입니다. 바꾼 조건은 함수 호출 전에 외부 입력을 정수로 바꾼 한 단계입니다. 실제 서비스에서는 변환할 수 없는 문자열도 들어올 수 있으므로 예외 처리나 검증 규칙을 추가해야 합니다. 10절에서는 Pydantic으로 여러 입력 필드의 런타임 검증을 구조화하는 방법을 학습합니다.

앞의 실행 예제를 실행한 같은 노트북에서 Before 다음 After 순서로 실행합니다. 출력은 실제 실행 결과입니다.

Before — 실패 코드

실패 재현

타입힌트를 적어도 Python은 호출 시 값을 자동 검사하지 않습니다. 입력은 문자열 "1200", 처리는 함수 본문의 total * 2, 반환은 문자열 "12001200"입니다. 실행 오류가 없더라도 금액 계산으로는 잘못된 결과입니다.

In [5]:
# 타입힌트가 문자열 입력을 자동으로 거부하지 않는지 확인합니다.
def double_total(total: int) -> int:
    return total * 2

wrong = double_total("1200")  # 타입힌트와 다른 입력
print("잘못된 결과:", wrong)
assert wrong == "12001200"
출력:
잘못된 결과: 12001200

After — 수정 코드

수정

외부에서 받은 문자열을 int()에 먼저 전달해 정수 1200을 반환받고, 그 값을 double_total()에 입력합니다. 같은 함수 본문이 숫자 곱셈을 실행하여 정수 2400을 반환합니다. 타입힌트와 실제 변환 코드의 역할을 구분해 확인합니다.

In [6]:
# 입력 문자열을 정수로 바꾸어 숫자 곱셈 결과를 얻습니다.
raw_total = "1200"
validated_total = int(raw_total)
correct = double_total(validated_total)
print("수정된 결과:", correct)
assert correct == 2400
출력:
수정된 결과: 2400

7주의할 점과 실무 메모

  • from module import *는 어느 이름이 들어왔는지 파악하기 어렵고 이름 충돌을 만들 수 있습니다. 사용할 이름을 명시합니다.
  • 모듈을 가져올 때 모듈 최상위 문장이 실행됩니다. 재사용 모듈에는 함수와 클래스 정의를 중심으로 두고, 실행 전용 코드는 역할을 분리합니다.
  • 타입힌트는 값 변환이나 유효성 검사를 자동 수행하지 않습니다. 파일, 사용자 입력, 네트워크 응답처럼 외부에서 받은 값은 프로그램 경계에서 별도로 확인합니다.
  • int("1200")은 성공하지만 int("천이백")은 실패합니다. 변환 가능한 형식과 실패 시 행동을 요구사항으로 정해야 합니다.

8정리와 다음 절

  • 모듈은 관련 Python 정의를 담은 .py 파일이며 import로 재사용합니다.
  • 타입힌트는 코드의 예상 입력과 반환값을 설명하고 검사 도구에 정보를 제공합니다.
  • 타입힌트는 실행 중 값을 자동 검증하지 않으므로 외부 입력을 별도로 확인해야 합니다.

다음 학습과 이어지는 지점 — 다음 절에서는 모듈의 함수가 기대한 결과를 반환하는지 pytest로 반복 확인합니다. 10절에서는 타입힌트로 적은 필드 정보를 실제 입력 검증에 사용하는 방법을 이어서 학습합니다.

9복습 문제

문제와 해설

1. pricing.py에서 add_tax만 가져오는 문장을 작성해 보세요.

정답 from pricing import add_tax입니다. 파일명의 .py는 import 문에 적지 않습니다.

2. label_price.__annotations__ 출력은 무엇을 보여 주나요?

정답 함수에 저장된 매개변수와 반환값의 타입힌트 정보를 보여 줍니다. 호출 시 실제 값이 검증되었다는 증거는 아닙니다.

3. double_total("1200")이 예외 없이 잘못된 문자열을 반환한 이유는 무엇인가요?

정답 Python 실행기가 타입힌트를 강제하지 않고, 문자열에 정수 2를 곱하는 연산은 문자열 반복으로 정의되어 있기 때문입니다.

4. 타입힌트와 런타임 검증의 역할을 한 문장씩 구분해 보세요.

정답 타입힌트는 예상 타입을 설명하고 정적 분석 도구에 제공합니다. 런타임 검증은 실행 중 들어온 실제 값이 조건에 맞는지 확인합니다.
