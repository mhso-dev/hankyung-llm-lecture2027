## 05 파일과 예외

- 학습 질문: UTF-8 텍스트 파일을 읽고 예상한 파일 누락만 처리하려면 어떻게 해야 하는가?
- 입력과 비교 조건: 임시 폴더의 `orders.txt`에 `연필,3`과 `노트,2`를 기록합니다. 값 비교에서는 연필 수량만 3에서 5로 바꿉니다. Before와 After는 같은 `missing.txt` 경로를 사용합니다.
- 실제 연산: cell-03이 임시 폴더와 UTF-8 파일을 준비합니다. cell-05의 `read_items()`가 `Path.read_text()`와 `splitlines()`를 실행합니다. cell-07의 `parse_order()`가 수량을 정수로 바꿉니다. cell-11과 cell-13이 누락 경로를 비교합니다.
- 관찰 결과: 기본 실행은 파일명 `orders.txt`, 주문 줄 수 2, 튜플 `('연필', 3)`을 출력합니다. 값 변경 뒤 첫 수량은 3에서 5로 바뀝니다. Before는 `FileNotFoundError missing.txt`, After는 `누락 파일 결과: []`를 출력합니다.
- 실패와 수정: 파일 누락이라는 실제 표준 예외를 재현했습니다. After는 `FileNotFoundError`만 처리하여 빈 목록을 반환하고 다른 오류를 처리하지 않습니다.
- 해석 범위: 빈 목록은 이 예제에서 선택한 누락 처리 결과입니다. 실제 주문 0건과 누락 상태를 구분해야 하는 서비스 설계까지 검증하지 않았습니다. 큰 파일의 메모리 사용량도 측정하지 않았습니다.
- 본문·그림 대조: HTML은 UTF-8, 경로, 구체 예외 처리와 실제 출력만 설명합니다. 도식의 `연필,3`, `('연필', 3)`, `missing.txt`, 빈 목록은 노트북과 같습니다.

## 06 클래스

- 학습 질문: 같은 클래스에서 만든 주문 객체가 각자의 가변 상태를 따로 유지하게 하려면 어떻게 해야 하는가?
- 입력과 비교 조건: 민지 주문에는 노트, 준호 주문에는 연필을 추가합니다. 상태 비교에서는 민지 주문에만 지우개를 추가합니다. Before와 After는 두 인스턴스를 만들고 첫 인스턴스에 `노트`를 추가하는 순서를 유지합니다.
- 실제 연산: cell-05가 `Order.__init__()`과 `Order.add() -> None`을 정의합니다. cell-07이 두 목록의 객체 동일성을 `is`로 확인합니다. cell-11은 클래스 속성 목록 공유를, cell-13은 인스턴스 속성 분리를 실행합니다.
- 관찰 결과: 정상 객체의 목록 동일성은 `False`입니다. 민지 주문이 `['노트', '지우개']`로 바뀐 뒤 준호 주문은 `['연필']`입니다. Before의 두 번째 주문은 잘못된 `['노트']`, After의 두 번째 주문은 `[]`입니다.
- 실패와 수정: Before는 변경 가능한 목록을 클래스 속성에 둔 잘못된 결과입니다. After는 목록 생성 위치만 `__init__`의 `self.items`로 옮깁니다.
- 해석 범위: 클래스 속성 전체가 잘못되었다고 일반화하지 않습니다. 이 결과는 변경 가능한 목록을 의도하지 않게 공유한 사례만 보여 줍니다. 상속과 고급 생성 패턴은 다루지 않습니다.
- 본문·그림 대조: 본문은 코드와 같이 `add() -> None` 및 별도 호출을 설명합니다. 도식의 두 주문 목록은 실제 출력과 같습니다.

## 07 모듈과 타입힌트

- 학습 질문: 함수를 모듈로 나누고 타입힌트 정보와 실제 런타임 검증을 어떻게 구분하는가?
- 입력과 비교 조건: 임시 폴더에 `pricing.py`와 `run_price.py`를 작성합니다. 가격 비교에서는 `label_price()`의 입력만 12000에서 25000으로 바꿉니다. Before와 After는 원문 문자열 `"1200"`과 같은 `double_total()`을 사용합니다.
- 실제 연산: cell-05가 실제 여러 줄 Python 소스로 모듈과 실행 파일을 만들고, 현재 Python 하위 프로세스에서 일반 import를 수행합니다. cell-07은 `__annotations__`를 읽습니다. cell-11은 타입힌트와 다른 문자열 입력을 실행하고, cell-13은 호출 전 `int()` 변환을 수행합니다.
- 관찰 결과: 모듈 실행은 세금 포함 가격 11000을 출력합니다. 타입힌트 정보에는 `price: int`, `return: str`가 나타납니다. Before는 문자열 `12001200`, After는 정수 2400을 출력합니다.
- 실패와 수정: 타입힌트가 런타임 입력을 자동 검사한다는 잘못된 가정을 실제 잘못된 결과로 확인합니다. After는 외부 문자열을 정수로 변환한 뒤 같은 함수에 전달합니다.
- 해석 범위: `int("1200")`이 성공한 한 사례입니다. 변환 불가능한 문자열의 사용자 안내와 정적 타입 검사 도구 실행은 측정하지 않았습니다. 모듈은 임시 폴더 하위 프로세스에서만 작성하여 프로젝트 파일을 변경하지 않습니다.
- 본문·그림 대조: 본문과 도식은 모듈 작성, 명시적 import, 11000 반환, 타입힌트 확인, 자동 검증 부재, 2400 수정 결과의 실제 순서를 따릅니다.

## 08 pytest

- 학습 질문: 실제 결함을 실패 테스트로 확인하고 구현 수정 뒤 같은 테스트의 통과를 어떻게 증명하는가?
- 입력과 비교 조건: 기본 테스트, 매개변수화 테스트, 할인 테스트를 각각 파일 단위로 실행합니다. 매개변수화 비교에서는 `(900, 3, 2700)` 한 사례만 추가합니다. Before와 After는 입력 10000과 기대값 9000을 유지하고 구현의 `+ 100`만 제거합니다.
- 실제 연산: cell-03이 pytest 9.1.1을 설치합니다. cell-06의 `run_pytest(folder, target)`가 `sys.executable -m pytest -q --tb=short <파일>`을 실행합니다. 환경 플러그인 자동 로드는 하위 프로세스에서 끕니다. cell-12와 cell-14가 할인 테스트를 같은 파일명으로 실행합니다.
- 관찰 결과: 기본 파일은 `1 passed`, 매개변수화는 `3 passed`, 사례 추가 뒤 `4 passed`입니다. Before는 비교식의 실제값 9100과 기대값 9000, `1 failed`, 종료 코드 1을 보여 줍니다. After는 `1 passed`, 종료 코드 0입니다.
- 실패와 수정: 테스트 기대값을 바꾸지 않고 결함이 있는 구현만 수정합니다. 실패 및 통과 반환 코드를 노트북 단언문으로 확인합니다.
- 해석 범위: 10,000원 한 입력과 정수 변환을 사용한 수업 예제입니다. 실제 결제의 반올림, 음수 가격, 통화 정책을 검증하지 않았습니다. 플러그인 자동 로드 비활성화는 개인 환경에 따른 경고와 추가 테스트 수를 줄이기 위한 실행 조건입니다.
- 본문·그림 대조: HTML의 3→4 passed 및 1 failed→1 passed 설명은 대상 파일별 실제 출력과 일치합니다. 도식은 입력과 기대값을 고정하고 구현 한 줄만 바꾼 순서를 나타냅니다.
