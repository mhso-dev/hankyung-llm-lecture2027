1학습 목표

  • 함수를 별도 .py 모듈에 정의하고 필요한 이름을 가져올 수 있습니다.
  • 함수의 매개변수와 반환값에 타입힌트를 작성하고 저장된 정보를 확인할 수 있습니다.
  • 타입힌트가 실행 시 입력을 검증하지 않는다는 사실을 실제 출력으로 설명할 수 있습니다.

2이 내용을 배우는 이유

프로그램이 길어지면 모든 함수와 클래스를 한 파일에서 찾기 어렵습니다. 가격 계산은 가격 모듈에 두고, 주문 출력은 실행 파일에 두면 각 파일의 역할이 분명해집니다. 다른 파일의 기능을 다시 작성하지 않고 가져와 사용할 수도 있습니다. 모듈은 코드의 위치를 나누고 이름의 출처를 표시하는 기본 단위입니다.

함수가 어떤 값을 받고 무엇을 반환하는지도 여러 파일 사이에서 알아볼 수 있어야 합니다. 타입힌트는 price: int와 -> str처럼 예상 타입을 코드에 적는 표기입니다. 편집기와 정적 타입 검사기는 이 정보를 읽어 잘못된 사용을 찾도록 돕습니다. 그러나 Python 실행기는 타입힌트를 보고 호출을 차단하지 않습니다. 외부 입력 검증은 별도 처리이며, 이 차이를 모르면 표시만 믿고 잘못된 결과를 정상으로 사용할 수 있습니다.

04절에서 함수의 매개변수와 반환값을 만들었고, 06절에서 클래스 안의 메서드를 정의했습니다. 이번 절에서는 이미 작성할 수 있는 함수를 파일로 분리합니다. 05절의 Path.write_text()를 사용하여 임시 폴더에 pricing.py와 run_price.py를 준비합니다. 개인 작업 파일을 변경하지 않으며 이전 커널의 값도 사용하지 않습니다.

4핵심 개념

쉬운 예

서랍마다 문구류의 종류를 적어 두면 필요한 물건을 찾을 때 모든 서랍을 열지 않아도 됩니다. 모듈(module)은 관련된 Python 정의와 문장을 담는 .py 파일입니다. 파일명에서 확장자를 뺀 이름으로 가져옵니다. pricing.py에 가격 함수를 두었다면 from pricing import add_tax로 그 이름을 선택할 수 있습니다.

정의

import는 다른 모듈의 코드를 불러와 사용할 수 있게 하는 문장입니다. 네임스페이스(namespace)는 이름과 값의 대응을 관리하는 범위입니다. import pricing은 모듈 이름을 유지하여 pricing.add_tax()로 호출하고, from pricing import add_tax는 선택한 이름을 현재 범위에 둡니다. 출처와 이름 충돌 가능성을 고려하여 방식을 정합니다.

타입힌트(type hint)는 변수, 매개변수, 반환값의 예상 타입을 표시한 정보입니다. 정적 타입 검사(static type checking)는 프로그램을 실행하기 전에 이 표시와 코드 사용이 맞는지 분석하는 과정입니다. 타입힌트는 문서와 도구를 위한 정보이며 런타임 검증(runtime validation)을 자동으로 수행하지 않습니다. 런타임 검증은 실행 중 실제 값이 조건에 맞는지 확인하고, 맞지 않으면 변환하거나 오류를 알리는 별도 동작입니다.

5실행 예제

노트북은 임시 폴더에 두 개의 짧은 Python 파일을 작성합니다. pricing.py는 정수 가격과 실수 세율을 받아 반올림한 정수를 반환하는 add_tax()를 정의합니다. run_price.py는 필요한 함수 이름만 가져와 10,000원과 세율 0.1을 전달합니다. 현재 커널의 Python 실행 파일로 하위 프로세스를 시작하고, 작업 위치를 임시 폴더로 지정하므로 일반적인 모듈 검색 규칙으로 pricing을 찾습니다.

다음 셀의 label_price()에는 입력 int와 반환 str가 표시되어 있습니다. __annotations__를 출력하면 이 정보가 함수 객체에 저장되었음을 볼 수 있습니다. 값 하나 비교에서는 함수와 형식을 그대로 두고 가격만 12000에서 25000으로 바꿉니다. 반환값이 각각 12,000원과 25,000원인지 확인합니다.

6일부러 실패해 보기

Before의 double_total()은 정수를 받아 정수를 반환한다고 표시합니다. 하지만 호출할 때 문자열 "1200"을 전달해도 Python은 타입힌트를 근거로 예외를 발생시키지 않습니다. 문자열에 2를 곱하는 연산이 적용되어 "12001200"이 반환됩니다. 오류 메시지가 없다는 사실이 올바른 계산을 뜻하지는 않습니다.

After는 같은 원문 문자열 "1200"을 int()로 변환한 뒤 같은 함수에 전달합니다. 출력은 숫자 2400입니다. 바꾼 조건은 함수 호출 전에 외부 입력을 정수로 바꾼 한 단계입니다. 실제 서비스에서는 변환할 수 없는 문자열도 들어올 수 있으므로 예외 처리나 검증 규칙을 추가해야 합니다. 10절에서는 Pydantic으로 여러 입력 필드의 런타임 검증을 구조화하는 방법을 학습합니다.

7주의할 점과 실무 메모

  • from module import *는 어느 이름이 들어왔는지 파악하기 어렵고 이름 충돌을 만들 수 있습니다. 사용할 이름을 명시합니다.
  • 모듈을 가져올 때 모듈 최상위 문장이 실행됩니다. 재사용 모듈에는 함수와 클래스 정의를 중심으로 두고, 실행 전용 코드는 역할을 분리합니다.
  • 타입힌트는 값 변환이나 유효성 검사를 자동 수행하지 않습니다. 파일, 사용자 입력, 네트워크 응답처럼 외부에서 받은 값은 프로그램 경계에서 별도로 확인합니다.
  • int("1200")은 성공하지만 int("천이백")은 실패합니다. 변환 가능한 형식과 실패 시 행동을 요구사항으로 정해야 합니다.

8정리와 다음 절

  • 모듈은 관련 Python 정의를 담은 .py 파일이며 import로 재사용합니다.
  • 타입힌트는 코드의 예상 입력과 반환값을 설명하고 검사 도구에 정보를 제공합니다.
  • 타입힌트는 실행 중 값을 자동 검증하지 않으므로 외부 입력을 별도로 확인해야 합니다.

9복습 문제

문제와 해설

1. pricing.py에서 add_tax만 가져오는 문장을 작성해 보세요.

정답 from pricing import add_tax입니다. 파일명의 .py는 import 문에 적지 않습니다.

2. label_price.__annotations__ 출력은 무엇을 보여 주나요?

정답 함수에 저장된 매개변수와 반환값의 타입힌트 정보를 보여 줍니다. 호출 시 실제 값이 검증되었다는 증거는 아닙니다.

3. double_total("1200")이 예외 없이 잘못된 문자열을 반환한 이유는 무엇인가요?

정답 Python 실행기가 타입힌트를 강제하지 않고, 문자열에 정수 2를 곱하는 연산은 문자열 반복으로 정의되어 있기 때문입니다.

4. 타입힌트와 런타임 검증의 역할을 한 문장씩 구분해 보세요.

정답 타입힌트는 예상 타입을 설명하고 정적 분석 도구에 제공합니다. 런타임 검증은 실행 중 들어온 실제 값이 조건에 맞는지 확인합니다.
