A트랙 보충 실습

A트랙은 09~11절의 확장 내용 대신 아래 여섯 과제를 수행합니다. 과제당 약 2시간을 배정한 총 12시간의 연습 범위입니다. 각 과제에서 결과 예측, 구현, 값 변경, 버그 재현, pytest 검증, 설명 기록을 모두 수행합니다. 학습 속도에 따라 걸리는 시간은 달라집니다. 08절까지 학습한 뒤 ch02-a-practice라는 새 폴더를 만들고, 작성할 모듈과 테스트 파일을 이 폴더에 모읍니다. 기존 노트북은 원본으로 보관합니다.

제출할 자료는 수정한 코드, 버그가 있을 때의 실패 출력, 수정 뒤의 통과 출력, 실패 원인을 자신의 말로 설명한 글입니다. 아래의 기대값을 코드 결과에 맞춰 바꾸지 않습니다. 오류를 수정할 때도 같은 테스트를 다시 실행해 확인합니다. 각 과제의 해설은 먼저 예측을 적고 실행한 뒤에 읽습니다.

과제 1. 배송비의 경계값을 테스트합니다

01~02절을 사용해 주문 금액을 받고 배송비를 반환하는 shipping_fee 함수를 작성합니다. 50,000원 이상은 무료, 30,000원 이상 50,000원 미만은 2,000원, 나머지는 3,000원입니다. 입력은 음수가 아닌 정수로 한정합니다. 먼저 0, 29,999, 30,000, 49,999, 50,000, 65,000원의 기대값을 적고 각각 확인합니다.

50,000원 경계의 비교 연산자를 일부러 바꿔 테스트가 실패하는지 확인한 뒤 복구합니다. 여섯 입력을 pytest의 매개변수화 검사에 넣습니다. 완료 기준은 여섯 검사가 모두 통과하고, 버그를 넣었을 때 50,000원 사례가 실패하는 것입니다. 조건의 순서를 바꾸면 무엇이 달라지는지도 설명합니다.

기대값과 해설

배송비는 입력 순서대로 3,000, 3,000, 2,000, 2,000, 0, 0원입니다. 큰 금액의 조건을 먼저 검사해야 50,000원 이상이 30,000원 이상 조건에서 잘못 처리되지 않습니다. 경계값 검사는 바로 아래 값과 경계 자체를 한 쌍으로 확인합니다.

과제 2. 목록 공유 문제를 회귀 테스트로 남깁니다

03절의 목록 복사와 04절의 add_tag 함수를 되짚습니다. 기본 목록을 인자로 사용한 잘못된 함수와 None에서 새 목록을 만드는 수정 함수를 같은 두 호출로 비교합니다. 첫 호출은 신규, 둘째 호출은 배송 태그를 전달합니다. 첫 호출 직후의 목록을 복사해 기록하고, 둘째 호출 후 첫 변수가 가리키는 목록도 기록합니다.

완료 기준은 수정 함수에서 첫 결과가 신규 하나, 둘째 결과가 배송 하나이며 두 결과가 서로 다른 객체인 것입니다. 이 조건을 pytest로 검사합니다. 별도 사례로 검토 태그가 든 목록을 직접 인자로 넘기고 배송을 추가합니다. 호출자가 전달한 목록을 수정하는 현재 함수의 동작과 기본 인자를 생략했을 때의 동작을 구분해 설명합니다.

기대값과 해설

잘못된 함수의 두 결과는 같은 목록이므로 둘째 호출 후 모두 신규와 배송을 담습니다. 수정 함수에서 기본 인자를 생략한 두 결과는 서로 다릅니다. 검토 목록을 직접 전달하면 그 목록에 배송이 추가됩니다. 모든 경우에 입력 목록을 보존해야 한다면 함수 안에서 복사하는 별도 설계가 필요하지만, 이 과제는 현재 함수의 동작을 그대로 테스트합니다.

과제 3. 파일 누락과 잘못된 수량을 구분합니다

05절의 read_items, read_items_or_empty, parse_order를 같은 모듈로 옮깁니다. 실습 폴더에 UTF-8 파일을 만들고 연필 수량 3과 노트 수량 2를 두 줄에 저장합니다. 읽은 줄 수가 2인지, 첫 주문을 변환한 수량이 정수 3인지 검사합니다. 파일이 없는 경로에는 빈 목록을 반환하는 정책을 유지합니다.

새로운 자료로 연필,많이를 변환해 봅니다. 이 자료는 파일 누락과 다른 문제입니다. 정수 변환의 ValueError가 발생하는지 08절의 테스트 방식으로 확인합니다. 완료 기준은 정상 읽기·숫자 변환·누락 파일·잘못된 수량의 네 경우를 구분하는 테스트와, 누락을 빈 목록으로 처리하면 잃는 정보를 설명한 기록입니다.

기대값과 해설

정상 자료의 변환 결과는 연필과 3, 노트와 2의 쌍입니다. 누락 파일의 빈 목록만 보고는 파일이 원래 비어 있었는지 존재하지 않았는지 구분할 수 없습니다. 많이는 정수 표현이 아니므로 변환 오류가 발생합니다. 모든 예외를 빈 목록으로 바꾸면 잘못된 자료까지 정상처럼 처리하게 됩니다.

과제 4. 서로 다른 고객의 주문 상태를 검사합니다

06절의 Order 클래스로 고객 두 명의 주문을 만들고 한 고객에게만 상품을 추가합니다. 두 주문의 목록 내용과 객체가 같은지 확인한 뒤 pytest 검사로 옮깁니다. 이어서 목록을 클래스 속성으로 옮긴 잘못된 구현을 만들고 같은 테스트에서 실패하는지 확인합니다.

완료 기준은 각 고객의 상품이 서로 섞이지 않고, 빈 주문을 새로 만들 때 목록이 비어 있으며, add 호출 뒤 상태는 바뀌지만 반환값은 None인 것을 확인하는 것입니다. 상속이나 메서드 연쇄 호출을 추가하지 않고 초기화 시점과 상태 저장 위치에 집중합니다.

기대값과 해설

상품 목록은 각 인스턴스를 초기화할 때 새로 만들어야 합니다. 클래스에 목록 하나를 두면 해당 목록을 사용하는 인스턴스들이 변경을 공유합니다. add는 현재 예제에서 별도 반환문 없이 상품 목록만 변경하므로 결과는 None입니다.

과제 5. 앞 절의 함수를 모듈과 테스트 파일로 옮깁니다

07절의 add_tax를 pricing.py에 저장하고 test_pricing.py에서 가져와 검사합니다. 가격과 세율이 각각 10,000과 0.1, 0과 0.1, 8,000과 0.25인 세 입력을 사용합니다. 노트북에서 함수 정의 셀을 실행하지 않아도 테스트가 모듈을 가져오는지 새 터미널에서 확인합니다.

08절의 discounted에 잘못된 100원 가산을 넣은 버전과 제거한 버전을 같은 테스트로 비교합니다. 완료 기준은 세금 사례 세 개와 10,000원 할인 사례 하나의 총 네 검사 통과, 수정 전 할인 검사 실패, 함수의 입력·반환 타입힌트와 실제 검증의 차이에 대한 설명입니다. 테스트 실행 대상 파일명을 명시해 다른 연습 파일의 검사 수가 섞이지 않게 합니다.

기대값과 해설

세금 포함 가격은 차례대로 11,000, 0, 10,000원이며 10,000원의 10% 할인 결과는 9,000원입니다. 타입힌트는 어떤 값을 받는지 알려 주지만, 실행 중 잘못된 입력을 자동으로 거부하지 않습니다. 테스트는 작성한 사례를 실제로 실행하여 결과가 맞는지 확인합니다.

과제 6. 주문 합계와 배송비를 함께 검증합니다

앞의 함수를 연결해 상품 목록에서 결제 금액을 계산합니다. 자료는 상품명·단가·수량을 담는 딕셔너리의 목록으로 정합니다. 연필은 단가 1,000원에 수량 3, 노트는 단가 2,500원에 수량 2입니다. 먼저 상품별 금액과 합계를 구합니다. 다음으로 04절의 함수로 합계에 10% 할인을 적용하고 과제 1의 배송비를 더합니다. 배송비 기준에 사용할 금액은 할인 전 상품 합계로 고정합니다.

완료 기준은 상품 합계, 할인 후 금액, 배송비, 최종 결제 금액을 각각 검사하는 것입니다. 추가 입력으로 10,000원 상품 다섯 개를 주문해 할인 전 50,000원의 무료 배송 경계도 검사합니다. 상품 금액을 단가와 수량의 합으로 잘못 계산하는 버그를 넣고 기존 검사에서 발견되는지 확인한 뒤 수정합니다. 어느 함수가 어떤 값을 받는지 파일명·함수명·입력·반환값을 적어 정리합니다.

기대값과 해설

첫 주문은 상품 합계 8,000원, 할인 후 7,200원, 배송비 3,000원, 최종 결제 10,200원입니다. 추가 주문은 상품 합계 50,000원, 할인 후 45,000원, 배송비 0원, 최종 결제 45,000원입니다. 배송비를 할인 후 금액으로 판정하면 둘째 사례가 달라지므로 계산 순서와 기준을 함께 테스트해야 합니다.

여섯 과제를 마쳤다면 12절 async와 await에서 동기 대기와 비동기 대기의 실행 순서를 비교합니다. 위 과제의 함수 구현과 테스트 작성이 불안정하면 해당 절로 돌아가 작은 입력부터 다시 확인합니다.
