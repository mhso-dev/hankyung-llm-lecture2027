1학습 목표

  • 기본 키와 외래 키의 역할을 실제 표에서 구분할 수 있습니다.
  • 고객과 주문을 다대일 관계로 조인할 수 있습니다.
  • 중복 키가 조인 행 수를 늘리는 현상을 발견하고 검사할 수 있습니다.

2이 내용을 배우는 이유

주문에는 고객 이름 대신 고객 번호만 저장되는 경우가 많습니다. 이름과 지역을 매 주문에 반복하면 고객 이름을 고칠 때 여러 행을 수정해야 하고 서로 다른 값이 남을 수 있습니다. 관계형 모델은 정보를 주제별 테이블로 나누고 키로 연결합니다. 조회 도구는 이 연결 규칙을 알아야 주문과 고객 정보를 정확히 함께 반환합니다.

Ch 12에서 벡터 데이터베이스의 스키마를 읽을 때도 어떤 열이 레코드를 구분하고 어떤 열이 다른 테이블을 가리키는지 판단해야 합니다. 이번 절의 목표는 데이터베이스 이론 전체가 아니라 조회 함수를 만들 때 필요한 키, 관계, 최소한의 정규화입니다.

앞 절에서 주문 세 건을 DataFrame으로 표현하고 상태 조건으로 행을 선택했습니다. Ch 2의 사전과 목록으로도 같은 데이터를 나타낼 수 있지만 두 표를 연결하려면 공통 열의 뜻과 값의 유일성을 추가로 확인해야 합니다.

4핵심 개념

키는 행을 찾고 테이블을 연결합니다

도서관 대출표에는 책 제목 전체 대신 도서 번호를 적습니다. 번호 하나가 도서 한 권만 가리키면 번호로 제목과 저자를 찾을 수 있습니다. 고객 표의 기본 키(primary key)인 customer_id도 고객 한 명을 유일하게 구분하며 비어 있지 않아야 합니다. 주문 표의 같은 열은 고객 표의 행을 가리키는 외래 키(foreign key)입니다. 두 열의 이름이 같다는 사실보다 값이 같은 대상을 식별한다는 의미가 중요합니다.

관계의 방향을 왼쪽과 오른쪽에서 읽습니다

관계(relationship)는 두 테이블의 행이 키로 연결되는 방식입니다. 고객 한 명에게 주문 여러 건이 있으므로 고객에서 주문을 보면 일대다(one-to-many)입니다. 조인 코드의 왼쪽에 주문, 오른쪽에 고객을 두면 여러 주문이 고객 한 명을 가리키므로 many_to_one입니다. 같은 데이터를 보더라도 어느 표를 기준으로 읽는지에 따라 표현 순서가 달라집니다.

조인(join)은 키 값이 같은 두 행의 열을 한 결과에 결합합니다. 내부 조인(inner join)은 양쪽에 모두 키가 있는 행만 남깁니다. 왼쪽 조인(left join)은 왼쪽 행을 모두 남기고 오른쪽에서 찾지 못한 열에는 결측값을 둡니다. 데이터베이스에서는 값이 없거나 알려지지 않은 상태를 NULL이라고 하며, pandas에서는 문자열 열의 결측값이 NaN 또는 <NA>처럼 표시될 수 있습니다.

정규화(normalization)는 반복되는 사실을 주제별 테이블로 나누어 한 사실을 한 곳에서 관리하도록 구조를 정리하는 원칙입니다. 고객 이름을 고객 표 한 곳에 저장하면 이름을 바꿀 때 주문 여러 행을 각각 수정하지 않아도 됩니다.

도식 읽기

초록 상자 두 개는 고객 표와 주문 표를 뜻합니다. 파란 화살표는 주문의 외래 키가 고객의 기본 키를 가리키는 흐름이고 노란 상자는 many_to_one 조인 결과 세 행입니다. 빨간 상자는 고객 기본 키가 중복되면 한 주문이 여러 고객 행과 일치해 결과가 다섯 행으로 늘어나는 실패를 나타냅니다.

5실행 예제

orders.merge(customers, on="customer_id", validate="many_to_one")에서 입력은 주문 DataFrame과 고객 DataFrame입니다. DataFrame의 merge() 메서드는 두 표를 조인한 새 DataFrame을 반환합니다. on은 양쪽에서 비교할 키 열을 지정하고, 생략된 how="inner"는 양쪽에 일치하는 키가 있는 행만 남깁니다. validate="many_to_one"은 왼쪽 주문 키의 반복은 허용하면서 오른쪽 고객 키는 유일한지 검사합니다.

pd.concat([표1, 표2])는 표를 지정한 축으로 이어 붙인 DataFrame을 반환합니다. 이 절에서는 새 주문이나 중복 고객 행을 아래에 추가합니다. indicator=True는 각 결과 행의 출처를 나타내는 _merge 열을 추가합니다. O104처럼 왼쪽에만 있는 행은 left_only이고 오른쪽 고객 이름은 NaN입니다.

정규화된 구조는 고객 이름의 중복을 줄이는 대신 조회할 때 조인이 필요합니다. 이 절에서는 고객과 주문을 두 테이블로 나누는 최소 구조만 사용합니다. 주소 이력이나 주문 당시 수령인처럼 시간에 따라 달라지는 값은 별도 요구사항을 확인한 뒤 어느 테이블에 둘지 정해야 합니다.

관계형 테이블과 키

고객과 주문을 키로 연결하고 조인 행 수가 늘어나는 원인을 확인합니다.

실행 환경 준비

In [1]:
# 표 조인과 키 검사를 위해 pandas를 불러옵니다.
import pandas as pd
from pandas.errors import MergeError

print("pandas", pd.__version__)
출력:
pandas 3.0.5

기본 실행

고객 표의 customer_id는 한 고객을 유일하게 구분하는 기본 키입니다. 주문 표의 같은 열은 고객 표를 가리키는 외래 키이며 한 고객에게 여러 주문이 있으므로 반복될 수 있습니다. 두 DataFrame을 입력으로 준비합니다.

In [2]:
# 고객의 기본 키와 주문의 외래 키 역할을 분리해 표를 준비합니다.
customers = pd.DataFrame([
 {"customer_id":"C001", "name":"김하나"},
 {"customer_id":"C002", "name":"이두리"},
])
orders = pd.DataFrame([
 {"order_id":"O101", "customer_id":"C001", "amount":32000},
 {"order_id":"O102", "customer_id":"C002", "amount":18000},
 {"order_id":"O103", "customer_id":"C001", "amount":27000},
])
print(customers.to_string(index=False))
print(orders.to_string(index=False))
출력:
customer_id name
       C001  김하나
       C002  이두리
order_id customer_id  amount
    O101        C001   32000
    O102        C002   18000
    O103        C001   27000

중간 결과 관찰

DataFrame의 merge() 메서드는 두 표를 입력으로 받아 키가 같은 행의 열을 결합한 새 DataFrame을 반환합니다. on은 비교할 키, 기본 내부 조인은 양쪽에 모두 있는 키만 남긴다는 뜻입니다. validate="many_to_one"은 왼쪽 주문 키의 반복은 허용하고 오른쪽 고객 키는 유일한지 검사합니다.

In [3]:
# many_to_one은 오른쪽 고객 키가 유일한지 검사합니다.
joined = orders.merge(customers, on="customer_id", validate="many_to_one")
print(joined[["order_id","name","amount"]].to_string(index=False))
assert len(joined) == len(orders)
출력:
order_id name  amount
    O101  김하나   32000
    O102  이두리   18000
    O103  김하나   27000

값 하나를 바꿔 비교

pd.concat([표1, 표2])는 표2의 행을 표1 아래에 이어 붙인 새 DataFrame을 반환합니다. 이 함수로 고객 표에 없는 C999 주문을 추가하고 how="left"로 왼쪽 조인을 실행합니다. indicator=True가 만든 _merge 열의 left_only와 고객 이름 NaN이 같은 행에 나타나는지 확인합니다.

In [4]:
# 부모 고객이 없는 주문은 왼쪽 조인의 표시 열로 발견합니다.
with_orphan = pd.concat([orders, pd.DataFrame([
    {"order_id":"O104", "customer_id":"C999", "amount":9000}
])])
checked = with_orphan.merge(customers, on="customer_id", how="left", indicator=True)
print(checked.loc[checked["_merge"] == "left_only",
                  ["order_id", "customer_id", "name", "_merge"]].to_string(index=False))
assert checked.loc[checked["_merge"] == "left_only", "order_id"].tolist() == ["O104"]
출력:
order_id customer_id name    _merge
    O104        C999  NaN left_only

확인할 점 — 먼저 조인 키의 의미와 오른쪽 키의 유일성을 확인합니다. 다음으로 내부 조인의 결과 행 수가 주문 수와 같은지 확인합니다. 마지막으로 왼쪽 조인에서 left_only와 고객 이름 NaN이 같은 O104를 가리키는지 확인합니다.

6일부러 실패해 보기

Before는 concat으로 고객 C001을 한 행 더 추가합니다. 일반 merge는 이를 허용하므로 C001 주문 두 건이 각각 두 번 결합되고 전체 결과는 다섯 행이 됩니다. 실제 출력에서 원본 주문 금액 합계 77,000이 중복 조인 뒤 136,000으로 증가합니다. validate="many_to_one"을 추가하면 같은 입력을 MergeError로 거부합니다.

After의 drop_duplicates("customer_id", keep="first")는 고객 번호가 중복된 행 가운데 먼저 나타난 행만 남긴 새 DataFrame을 반환합니다. is_unique는 Series의 값이 모두 유일한지 불리언으로 알려 줍니다. fixed.iloc[0]은 결과의 첫 번째 행을 위치로 선택하고 ["name"]이 그 행의 이름을 읽습니다. 교육용 정리 규칙을 적용한 결과는 다시 3행과 합계 77,000이며 C001 이름은 김하나입니다.

앞의 실행 예제를 실행한 같은 노트북에서 Before 다음 After 순서로 실행합니다. 출력은 실제 실행 결과입니다.

Before — 실패 코드

실패 재현

concat으로 C001 고객을 한 행 더 추가합니다. 일반 조인은 C001 주문을 각각 두 번 결합하므로 행 수뿐 아니라 금액 합계도 증가합니다. 원본 합계와 조인 뒤 합계를 실제 출력으로 비교한 뒤 many_to_one 검사가 같은 입력을 거부하는지 확인합니다.

In [5]:
# 중복 고객 키는 주문을 복제하며 관계 검증에서도 거부됩니다.
duplicated = pd.concat([customers, pd.DataFrame([
    {"customer_id":"C001", "name":"김하나(중복)"}
])], ignore_index=True)
wrong = orders.merge(duplicated, on="customer_id")
original_total = int(orders["amount"].sum())
wrong_total = int(wrong["amount"].sum())
print("주문 행:", len(orders), "조인 행:", len(wrong))
print("원본 합계:", original_total, "중복 조인 합계:", wrong_total)
try:
    orders.merge(duplicated, on="customer_id", validate="many_to_one")
except MergeError as error:
    print(type(error).__name__, "중복 키 거부")
else:
    raise AssertionError("중복 키가 거부되지 않았습니다.")
assert len(wrong) == 5 and original_total == 77000 and wrong_total == 136000
출력:
주문 행: 3 조인 행: 5
원본 합계: 77000 중복 조인 합계: 136000
MergeError 중복 키 거부

After — 수정 코드

수정

drop_duplicates("customer_id", keep="first")는 중복 고객 번호에서 먼저 나타난 행만 남긴 새 DataFrame을 반환합니다. is_unique는 고객 번호가 모두 유일한지 검사합니다. fixed.iloc[0]["name"]은 위치가 첫 번째인 행에서 이름 열을 읽습니다. 수정 뒤 행 수와 금액 합계가 원본과 같아졌는지 확인합니다.

In [6]:
# 교육 데이터는 먼저 온 원본을 유지한다는 규칙으로 중복을 정리합니다.
deduplicated = duplicated.drop_duplicates("customer_id", keep="first")
assert deduplicated["customer_id"].is_unique
fixed = orders.merge(deduplicated, on="customer_id", validate="many_to_one")
fixed_total = int(fixed["amount"].sum())
print("수정 후 조인 행:", len(fixed), "합계:", fixed_total,
      "C001 이름:", fixed.iloc[0]["name"])
assert len(fixed) == 3 and fixed_total == 77000 and fixed.iloc[0]["name"] == "김하나"
출력:
수정 후 조인 행: 3 합계: 77000 C001 이름: 김하나

7주의할 점과 실무 메모

  • 중복 행을 무조건 삭제하기 전에 어느 행이 올바른지 결정할 기준을 확인합니다. 최신 수정일이나 원천 시스템 같은 근거가 필요합니다.
  • 외래 키 값이 고객 표에 없으면 내부 조인에서 주문이 사라질 수 있습니다. 누락을 찾아야 할 때는 왼쪽 조인과 조인 상태 표시를 사용합니다.
  • 정규화는 모든 값을 잘게 나누는 작업이 아닙니다. 함께 수정되어야 하는 사실의 중복과 변경 문제를 줄이는 범위에서 적용합니다.
  • 개인정보가 포함된 고객 표는 필요한 열만 조회하고 접근 권한과 보존 기간을 따로 확인합니다.

8정리와 다음 절

  • 기본 키는 한 테이블의 행을 유일하게 구분합니다.
  • 외래 키는 다른 테이블의 기본 키를 가리킵니다.
  • 조인 전후 행 수와 관계 검증으로 중복 키 문제를 발견합니다.

다음 학습과 이어지는 지점 — 다음 절에서는 같은 관계를 SQLite 테이블로 만들고 SQL의 JOIN과 WHERE로 고객 주문을 조회합니다.

9복습 문제

문제와 해설

1. 고객 표의 customer_id가 갖춰야 할 핵심 조건은 무엇인가요?

정답 각 고객 행을 유일하게 구분해야 하므로 중복되지 않아야 합니다.

2. 주문 표에서 customer_id가 반복되어도 되는 이유는 무엇인가요?

정답 고객 한 명이 여러 주문을 만들 수 있는 일대다 관계이기 때문입니다.

3. 중복 고객 키가 있으면 조인 결과가 어떻게 달라졌나요?

정답 고객 두 행과 연결된 주문이 복제되어 세 주문이 다섯 행으로 늘었습니다.

4. validate="many_to_one"이 검사하는 관계는 무엇인가요?
