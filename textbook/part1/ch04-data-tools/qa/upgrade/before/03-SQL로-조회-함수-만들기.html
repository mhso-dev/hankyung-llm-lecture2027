1학습 목표

  • SELECT·JOIN·WHERE·ORDER BY의 역할을 구분할 수 있습니다.
  • SQLite 조회 행을 사전 목록으로 변환하는 함수를 작성할 수 있습니다.

2이 내용을 배우는 이유

표 파일은 학습과 작은 업무에 편리하지만 여러 사용자가 같은 구조를 반복 조회할 때는 데이터베이스가 더 적합합니다. SQL은 어떤 열을 반환하고 어떤 테이블을 연결하며 어떤 조건과 순서로 결과를 만들지 선언합니다. 에이전트 도구의 함수는 자연어 질문 전체를 SQL로 바꾸기 전에 검증된 조건 조회부터 제공하는 편이 안전합니다.

이번 절의 find_customer_orders(database, customer_id)는 데이터베이스 경로와 고객 번호를 입력으로 받고 사전 목록을 반환합니다. Ch 19에서 이 함수를 도구로 등록할 때는 실행 환경에서 데이터베이스 경로를 정하고 모델이 고객 번호를 전달하도록 입력 범위를 설계합니다. 데이터 접근과 답변 생성을 나누면 어느 단계에서 잘못된 값이 생겼는지 찾기 쉬워집니다.

4핵심 개념

요청 문장을 SQL 절로 나눕니다

“고객 C001의 주문 번호, 이름, 금액을 금액이 큰 순서로 주세요”라는 요청에는 네 가지 결정이 들어 있습니다. SELECT는 반환할 열, FROM과 JOIN은 읽고 연결할 테이블, WHERE는 남길 행의 조건, ORDER BY는 반환 순서를 정합니다. SQL은 보통 SELECT → FROM/JOIN → WHERE → ORDER BY → LIMIT 순서로 작성합니다. LIMIT는 최대 몇 행을 반환할지 정하며 이번 함수에는 사용하지 않습니다.

데이터베이스가 개념적으로 처리하는 순서는 작성 순서와 다릅니다. 먼저 FROM/JOIN으로 행의 원천을 만들고, WHERE로 행을 줄인 뒤, SELECT로 반환 열을 정하고, ORDER BY로 정렬하며, 마지막에 LIMIT로 행 수를 제한합니다.

쿼리와 입력값을 분리합니다

SQL(Structured Query Language)은 관계형 데이터베이스의 구조와 데이터를 다루는 언어입니다. 쿼리(query)는 데이터베이스에 보내는 조회 또는 변경 명령입니다. 매개변수 쿼리(parameterized query)는 SQL 문장과 입력값을 분리해 전달합니다. Python sqlite3에서는 물음표 자리표시자와 값 튜플을 사용하므로 입력 전체가 SQL 문법이 아닌 하나의 값으로 처리됩니다.

db.execute(sql, (customer_id,))에서 첫 번째 인자는 SQL 문자열이고 두 번째 인자는 물음표에 대응하는 값의 튜플입니다. 값이 하나뿐이어도 (customer_id,)처럼 쉼표를 써야 한 원소 튜플이 됩니다. 반환되는 커서는 조회 결과를 순회할 수 있는 객체입니다. 행 팩토리(row factory)는 커서가 각 행을 어떤 Python 객체로 만들지 정합니다. sqlite3.Row를 사용하면 열 이름으로 값에 접근할 수 있고 dict(row)로 사전으로 변환할 수 있습니다.

도식 읽기

초록 상자는 데이터베이스 경로·고객 번호 입력과 반환 사전을 나타냅니다. 파란 상자는 테이블 연결, 행 선택, 열 선택, 정렬의 처리 흐름이고 빨간 상자는 입력을 문자열에 직접 붙여 조건식의 구조가 바뀌는 실패를 보여 줍니다.

5실행 예제

import sqlite3는 Python 표준 라이브러리의 SQLite 기능을 불러옵니다. TemporaryDirectory()는 실습이 끝나면 정리할 임시 폴더 객체를 반환하고, Path(temp_dir.name) / "orders.db"는 그 폴더 안의 데이터베이스 경로를 만듭니다. sqlite3.connect(database)는 해당 파일에 연결한 Connection 객체를 반환합니다. connection.row_factory = sqlite3.Row는 이후 조회 행을 열 이름으로 읽게 설정합니다.

execute()는 SQL 문장 하나를, executescript()는 세미콜론으로 구분한 여러 SQL 문장을 실행합니다. PRAGMA foreign_keys = ON은 현재 연결에서 외래 키 검사를 켭니다. commit()은 테이블 생성과 입력 내용을 파일에 확정하고 close()는 준비용 연결을 닫습니다.

find_customer_orders의 입력은 데이터베이스 경로와 고객 번호입니다. 함수는 새 연결을 열고 with db: 블록에서 조회합니다. 연결 객체의 with 블록은 정상 종료 시 진행 중인 트랜잭션을 커밋하고 예외가 발생하면 롤백하지만 연결을 닫지는 않습니다. 따라서 finally에서 close()를 별도로 호출합니다.

orders o는 orders 테이블에 짧은 별칭 o를, customers c는 customers 테이블에 c를 붙입니다. 그래서 o.order_id와 c.name처럼 어느 테이블의 열인지 표시할 수 있습니다. USING(customer_id)은 양쪽 테이블에 이름이 같은 customer_id 열이 있을 때 그 두 열의 값이 같은 행을 연결합니다.

쿼리는 JOIN으로 주문과 고객을 결합하고, WHERE로 입력 고객만 남기고, ORDER BY amount DESC, order_id로 정렬합니다. 각 sqlite3.Row를 dict로 바꾸므로 사전 목록을 반환합니다. C001은 O101·O103, C002는 O102를 반환합니다.

SQL로 조회 함수 만들기

SQLite에서 매개변수 SQL로 고객 주문을 조회합니다.

실행 환경 준비

import sqlite3는 Python 표준 라이브러리의 SQLite 기능을 불러옵니다. TemporaryDirectory()는 실습 뒤 정리할 임시 폴더 객체를, sqlite3.connect(경로)는 데이터베이스 연결 객체를 반환합니다. row_factory = sqlite3.Row는 조회 행을 열 이름으로 읽게 합니다. execute("PRAGMA foreign_keys = ON")은 이 연결에서 외래 키 검사를 켭니다.

In [1]:
# 임시 SQLite 파일과 행 이름 접근 방식을 준비합니다.
import sqlite3
from pathlib import Path
from tempfile import TemporaryDirectory

temp_dir = TemporaryDirectory()
database = Path(temp_dir.name) / "orders.db"
connection = sqlite3.connect(database)
connection.row_factory = sqlite3.Row
_ = connection.execute("PRAGMA foreign_keys = ON")

기본 실행

execute()는 SQL 문장 하나를 실행하고 executescript()는 세미콜론으로 구분된 여러 문장을 실행합니다. commit()은 준비한 테이블과 행을 파일에 확정하고 close()는 연결을 닫습니다. SQL은 SELECT → FROM/JOIN → WHERE → ORDER BY → LIMIT 순서로 작성하지만 데이터베이스는 개념적으로 원천과 연결을 정한 뒤 행을 거르고 반환 열과 순서를 정합니다.

In [2]:
# 기본 키와 외래 키 제약을 가진 두 테이블을 만듭니다.
connection.executescript("""
CREATE TABLE customers(customer_id TEXT PRIMARY KEY, name TEXT NOT NULL);
CREATE TABLE orders(order_id TEXT PRIMARY KEY, customer_id TEXT NOT NULL, status TEXT NOT NULL,
 amount INTEGER NOT NULL, FOREIGN KEY(customer_id) REFERENCES customers(customer_id));
INSERT INTO customers VALUES ('C001','김하나'),('C002','이두리');
INSERT INTO orders VALUES ('O101','C001','paid',32000),('O102','C002','pending',18000),('O103','C001','paid',27000);
""")
connection.commit()
connection.close()
print("준비된 주문: 3")
출력:
준비된 주문: 3

중간 결과 관찰

함수 입력은 데이터베이스 경로와 고객 번호입니다. orders o와 customers c는 긴 테이블 이름에 각각 o, c라는 짧은 별칭을 붙입니다. 그래서 o.order_id와 c.name처럼 열의 출처를 표시할 수 있습니다. USING(customer_id)은 두 테이블에서 이름이 같은 customer_id 열의 값이 같은 행을 연결합니다. with db:는 정상 종료 시 진행 중인 트랜잭션을 커밋하고 예외가 발생하면 롤백하지만 연결을 닫지는 않습니다. 그래서 finally에서 close()를 따로 호출합니다. 블록 안에서는 JOIN, WHERE, ORDER BY를 적용하고 db.execute(sql, (customer_id,))의 값 튜플을 물음표와 분리해 전달합니다. 반환값은 sqlite3.Row를 사전으로 변환한 목록입니다.

In [3]:
# 경로와 고객 번호를 받아 매개변수 SQL 결과를 사전 목록으로 반환합니다.
def find_customer_orders(database: str | Path, customer_id: str) -> list[dict]:
    sql = """SELECT o.order_id, c.name AS customer_name, o.status, o.amount
             FROM orders o JOIN customers c USING(customer_id)
             WHERE customer_id = ? ORDER BY amount DESC, order_id"""
    db = sqlite3.connect(database)
    try:
        db.row_factory = sqlite3.Row
        with db:
            return [dict(row) for row in db.execute(sql, (customer_id,))]
    finally:
        db.close()
rows = find_customer_orders(database, "C001")
print(rows)
출력:
[{'order_id': 'O101', 'customer_name': '김하나', 'status': 'paid', 'amount': 32000}, {'order_id': 'O103', 'customer_name': '김하나', 'status': 'paid', 'amount': 27000}]

값 하나를 바꿔 비교

SQL 문장과 처리 순서는 유지하고 고객 번호만 C001에서 C002로 바꿉니다. 반환 행이 한 건으로 줄어도 열 이름과 사전 목록이라는 반환 형식은 유지되는지 확인합니다.

In [4]:
# 고객 번호만 바꾸어 반환 행 수와 정렬 규칙을 확인합니다.
assert [row["order_id"] for row in rows] == ["O101", "O103"]
print(find_customer_orders(database, "C002"))
assert len(find_customer_orders(database, "C002")) == 1
출력:
[{'order_id': 'O102', 'customer_name': '이두리', 'status': 'pending', 'amount': 18000}]

확인할 점 — 준비 셀의 연결 설정과 데이터 확정 순서를 먼저 확인합니다. 조회 셀에서는 SQL의 물음표 수와 값의 수, 한 원소 튜플의 쉼표, 테이블 별칭, USING의 연결 열, AS로 정한 반환 키, with의 트랜잭션 처리와 close()의 연결 정리를 구분합니다.

6일부러 실패해 보기

Before는 C001' OR 1=1 --을 문자열 보간으로 SQL에 붙입니다. 입력의 OR 1=1이 조건식으로 해석되어 세 주문이 모두 조회됩니다. 이 결과는 SQL 주입(SQL injection)을 작은 예제로 재현합니다. After는 SQL을 고정하고 입력을 값 튜플로 전달합니다. 같은 문자열 전체가 고객 번호로 비교되므로 일치하는 행이 없습니다. 이어서 부모 고객이 없는 주문도 외래 키 제약으로 거부합니다.

앞의 실행 예제를 실행한 같은 노트북에서 Before 다음 After 순서로 실행합니다. 출력은 실제 실행 결과입니다.

Before — 실패 코드

실패 재현

입력 문자열을 SQL에 직접 붙이면 조건의 뜻이 바뀔 수 있습니다.

In [5]:
# 문자열 결합은 입력 일부를 SQL 조건식으로 해석하게 만듭니다.
unsafe_input = "C001' OR 1=1 --"
db = sqlite3.connect(database)
try:
    unsafe_sql = f"SELECT * FROM orders WHERE customer_id = '{unsafe_input}'"
    unsafe_rows = db.execute(unsafe_sql).fetchall()
finally:
    db.close()
print("문자열 결합 조회 행:", len(unsafe_rows))
assert len(unsafe_rows) == 3
출력:
문자열 결합 조회 행: 3

After — 수정 코드

수정

SQL의 물음표 자리표시자와 값 튜플을 분리해 전달합니다.

In [6]:
# 매개변수 조회와 외래 키 강제를 각각 실제 오류·결과로 확인합니다.
assert find_customer_orders(database, unsafe_input) == []
db = sqlite3.connect(database)
try:
    db.execute("PRAGMA foreign_keys = ON")
    try:
        with db:
            db.execute("INSERT INTO orders VALUES ('O999','C999','paid',1000)")
    except sqlite3.IntegrityError as error:
        print(type(error).__name__, "부모 없는 주문 거부")
    else:
        raise AssertionError("외래 키가 강제되지 않았습니다.")
finally:
    db.close()
print("매개변수 조회 행: 0")
temp_dir.cleanup()
출력:
IntegrityError 부모 없는 주문 거부
매개변수 조회 행: 0

7주의할 점과 실무 메모

  • 값은 매개변수로 전달하지만 테이블명이나 열 이름은 허용 목록에서 고릅니다. 자리표시자는 일반적으로 SQL 식별자를 대신하지 않습니다.
  • 조회 결과가 없다는 사실과 데이터베이스 오류를 같은 빈 목록으로 처리하지 않습니다. 오류는 기록하거나 호출자에게 전달해야 원인을 구분할 수 있습니다.
  • 연결 객체의 with 블록은 트랜잭션의 커밋과 롤백을 관리하며 연결을 자동으로 닫지 않습니다. 사용이 끝난 연결은 close()로 정리합니다.
  • 실제 서비스에서는 읽기 전용 계정, 쿼리 시간 제한, 반환 행 수 제한도 함께 적용합니다.

8정리와 다음 절

  • SQL 절은 반환 열, 연결, 조건, 순서를 각각 명시합니다.
  • 조회 행을 사전 목록으로 변환하면 후속 코드가 열 이름으로 값을 읽을 수 있습니다.
  • 사용자 입력은 SQL 문자열에 붙이지 않고 매개변수로 전달합니다.

9복습 문제

문제와 해설

1. 결과 행을 금액 내림차순으로 정하는 SQL 절은 무엇인가요?

정답 ORDER BY amount DESC입니다.

2. JOIN이 필요한 이유는 무엇인가요?

정답 주문의 고객 번호를 고객 표의 이름과 결합하기 위해서입니다.

3. 입력을 문자열 보간으로 붙였을 때 세 행이 반환된 이유는 무엇인가요?

정답 입력 일부가 SQL 조건식으로 해석되어 OR 1=1이 모든 행에서 참이 되었기 때문입니다.

4. 빈 결과와 실행 오류를 구분해야 하는 이유는 무엇인가요?
