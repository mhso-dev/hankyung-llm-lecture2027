2이 내용을 배우는 이유

에이전트가 주문 상태를 답하려면 먼저 주문 파일에서 필요한 행을 정확히 찾아야 합니다. 파일 전체를 모델에 전달하면 관련 없는 정보까지 입력에 포함되고 금액이 문자열인지 숫자인지 구별하지 못하면 합계도 틀릴 수 있습니다. 이번 절에서는 표를 읽고 조건에 맞는 행만 반환하는 과정을 작은 조회 함수로 구현합니다.

Ch 19에서는 조회 함수를 에이전트 도구로 감쌉니다. 도구 이름과 설명이 좋아도 함수가 잘못된 행을 반환하면 답의 근거가 잘못됩니다. 따라서 모델을 연결하기 전에 입력 열, 선택 조건, 반환 필드를 코드와 테스트로 고정해야 합니다.

4핵심 개념

표에서 한 열을 먼저 읽습니다

import pandas as pd는 pandas 라이브러리를 pd라는 짧은 이름으로 불러옵니다. 점 표기인 pd.DataFrame은 pandas 안에 정의된 DataFrame 생성자를 가리킵니다. pd.DataFrame(사전 목록)처럼 괄호 안에 입력을 전달하면 표 객체를 반환합니다.

주문 장부 전체가 DataFrame입니다. 한 주문은 행(row), 주문 번호·상태·금액은 열(column)입니다. DataFrame에는 행을 구분하는 인덱스(index)도 있습니다. 이 예제에서 화면 왼쪽에 생략된 0, 1, 2가 인덱스이며 주문 번호인 order_id와 역할이 다릅니다. 인덱스는 pandas가 행을 찾고 맞추는 표식이고, 주문 번호는 업무 데이터에 들어 있는 식별자입니다.

pd.read_csv(경로)는 CSV 파일의 첫 줄을 열 이름으로, 다음 줄부터를 행으로 읽어 DataFrame을 반환합니다. orders["status"]처럼 열 이름 하나를 대괄호 안에 쓰면 표 전체가 아니라 Series 하나를 얻습니다. Series는 같은 열의 값과 각 값의 인덱스를 함께 가진 1차원 자료구조입니다. 이 Series를 "paid"와 비교하면 각 행마다 True 또는 False가 만들어집니다. 이 참·거짓 Series가 불리언 마스크(boolean mask)입니다.

loc는 행 조건과 반환 열을 나눠 받습니다

DataFrame.loc[행 조건, 열 선택]은 레이블을 기준으로 행과 열을 선택합니다. 이 절의 함수는 frame.loc[frame["status"] == status]처럼 행 조건만 전달하므로 조건이 참인 행의 모든 열을 반환합니다. 반환 열까지 제한하려면 frame.loc[mask, ["order_id", "amount"]]처럼 쉼표 뒤에 열 이름 목록을 씁니다. loc라는 이름만 외우기보다 입력이 행 조건이고 반환이 선택된 DataFrame이라는 흐름으로 읽어야 합니다.

자료형이 연산의 뜻을 정합니다

자료형(dtype)은 열의 값이 문자열인지 정수인지 나타냅니다. dtypes는 열마다 자료형을 보여 주는 Series입니다. 화면에는 32000처럼 보여도 문자열이면 덧셈 결과가 320001800027000처럼 이어질 수 있습니다. pd.to_numeric(..., errors="raise")는 Series를 입력으로 받아 숫자로 변환한 Series를 반환하며, 변환할 수 없는 값이 있으면 예외를 발생시킵니다. 따라서 잘못된 값을 누락한 채 합계를 계산하지 않습니다.

도식 읽기

초록 상자는 원본 주문 세 행, 파란 상자는 상태 Series를 비교해 마스크를 만들고 loc에 전달하는 흐름, 노란 상자는 O101과 O103의 합계 59,000을 뜻합니다. 아래쪽 빨간 경로는 금액 열이 문자열일 때 잘못된 합계가 만들어지는 과정을 보여 줍니다.

5실행 예제

첫 셀에서 pandas 3.0.5를 확인합니다. 다음 셀의 pd.DataFrame([...])은 사전 세 개를 입력으로 받아 3행 3열 DataFrame을 만듭니다. to_csv(..., index=False)의 index=False는 0, 1, 2 인덱스를 CSV의 별도 열로 저장하지 않는다는 뜻입니다. pd.read_csv는 파일을 읽어 새 DataFrame을 반환하고, dtype={"order_id": "string"}은 주문 번호를 계산용 숫자가 아닌 문자열로 유지합니다.

fetch_orders의 입력은 CSV 경로와 선택할 상태입니다. 함수 안에서는 frame["status"] Series를 상태 문자열과 비교하고, loc가 참인 행만 남깁니다. 마지막 to_dict(orient="records")는 DataFrame의 각 행을 사전 하나로 바꾸어 사전 목록을 반환합니다. records 방향을 사용하면 인덱스 대신 열 이름이 각 사전의 키가 됩니다. paid 입력은 O101과 O103을, 조건만 pending으로 바꾼 입력은 O102를 반환합니다.

DataFrame은 분석 코드에서 열 연산을 이어 가기 좋고 사전 목록은 JSON으로 변환하거나 도구 결과로 전달하기 좋습니다. 함수의 입력, 처리, 반환을 구분하면 호출자는 pandas의 내부 사용 여부를 몰라도 결과를 사용할 수 있습니다.

to_string(index=False)는 행 인덱스를 생략한 표 문자열을 만듭니다. orders.dtypes는 열마다 자료형을 담은 Series이고, 여기에 astype(str)를 적용하면 자료형 이름을 문자열로 바꾼 새 Series를 얻습니다. 마지막 to_dict()는 열 이름과 자료형 이름을 짝지은 사전으로 바꿉니다.

Ch 2의 07절에서 배운 타입 힌트에 여러 허용 형식을 표시합니다. str | Path는 문자열 경로나 Path 객체를 받을 수 있다는 뜻입니다. 홀로 놓인 * 뒤의 status는 status="paid"처럼 이름을 붙여 전달합니다. str | None = None은 문자열 또는 값 없음을 허용하며, 생략하면 None으로 두어 모든 상태를 읽습니다. -> list[dict]는 사전을 항목으로 담은 목록을 반환한다는 표시입니다.

tolist()는 Series의 값들을 Python 목록으로 반환합니다. [row["order_id"] for row in paid]는 paid를 한 항목씩 row로 읽어 주문 번호만 새 목록에 모으는 표기입니다. 대괄호 안의 for를 이렇게 읽으면 검사 대상이 주문 번호 목록임을 알 수 있습니다.

# Series 비교가 행마다 만드는 불리언 마스크를 먼저 확인합니다.
status_series = orders["status"]
paid_mask = status_series == "paid"
print("상태 Series:", status_series.tolist())
print("paid 마스크:", paid_mask.tolist())

# 파일 경로와 선택 상태를 받는 재사용 함수로 반환 형식을 고정합니다.
def fetch_orders(csv_path: str | Path, *, status: str | None = None) -> list[dict]:
    frame = pd.read_csv(csv_path, dtype={"order_id":"string"})
    if status is not None:
        frame = frame.loc[frame["status"] == status]
    return frame.to_dict(orient="records")
paid = fetch_orders(orders_path, status="paid")
print(paid)
assert [row["order_id"] for row in paid] == ["O101", "O103"]
출력:
상태 Series: ['paid', 'pending', 'paid']
paid 마스크: [True, False, True]
[{'order_id': 'O101', 'status': 'paid', 'amount': 32000}, {'order_id': 'O103', 'status': 'paid', 'amount': 27000}]

6일부러 실패해 보기

Before는 금액 열을 문자열로 바꾼 뒤 sum()을 호출합니다. 오류가 발생하지 않지만 결과는 77,000이 아니라 세 문자열을 이어 붙인 값입니다. 프로그램이 멈추지 않았다는 사실만으로 결과가 맞다고 판단할 수 없습니다. After는 to_numeric으로 금액을 정수로 변환하고 같은 세 행의 합계를 다시 계산합니다. 출력 77,000과 assert 문이 변환 결과를 확인합니다.

orders.astype({"amount": "string"})는 amount 열을 문자열로 바꾼 새 DataFrame을 반환합니다. 반환값을 broken에 저장하므로 원래 orders의 숫자 열은 그대로 두고 두 경우를 비교할 수 있습니다.

assign(amount=...)은 오른쪽 계산 결과로 amount 열을 교체한 새 DataFrame을 반환합니다. 먼저 pd.to_numeric이 문자열 금액을 숫자 Series로 변환하고, assign이 그 Series를 금액 열로 사용합니다. 원래 broken을 직접 고친 것이 아니라 새 표를 fixed에 저장합니다.

실패 재현

금액이 문자열이면 합계가 숫자 덧셈이 아닌 문자열 연결이 됩니다.

orders.astype({"amount": "string"})는 amount 열을 문자열로 바꾼 새 DataFrame을 반환합니다. 반환값을 broken에 저장하므로 원래 orders의 숫자 열은 그대로 두고 두 경우를 비교할 수 있습니다.

In [5]:
# 금액을 문자열로 읽으면 sum이 문자열 연결을 수행합니다.
broken = orders.astype({"amount":"string"})
wrong_total = broken["amount"].sum()
print("문자열 합계:", wrong_total)
assert wrong_total == "320001800027000"
출력:
문자열 합계: 320001800027000

After — 수정 코드

수정

숫자로 변환한 새 열을 사용해 합계를 계산합니다.

assign(amount=...)은 오른쪽 계산 결과로 amount 열을 교체한 새 DataFrame을 반환합니다. 먼저 pd.to_numeric이 문자열 금액을 숫자 Series로 변환하고, assign이 그 Series를 금액 열로 사용합니다. 원래 broken을 직접 고친 것이 아니라 새 표를 fixed에 저장합니다.

In [6]:
# 숫자 변환 실패를 드러내고 정수 합계를 다시 계산합니다.
fixed = broken.assign(amount=pd.to_numeric(broken["amount"], errors="raise"))
correct_total = int(fixed["amount"].sum())
print("숫자 합계:", correct_total)
assert correct_total == 77000
temp_dir.cleanup()
출력:
숫자 합계: 77000

7주의할 점과 실무 메모

  • CSV의 주문 번호가 숫자로만 보여도 식별자는 문자열로 읽는 편이 안전합니다. 앞의 0은 수량이 아니라 식별 형식의 일부일 수 있습니다.
  • 결측값을 0으로 바꾸기 전에 0이 실제 금액인지 미수집 값을 대신하는지 확인합니다.
  • 행이 많은 파일은 필요한 열과 조건을 일찍 선택해야 메모리 사용을 줄일 수 있습니다. 이 절의 세 행으로 큰 파일 성능을 일반화할 수 없습니다.
  • 반환값은 화면용 표가 아니라 사전 목록처럼 다음 코드가 처리할 수 있는 형식으로 정합니다.

실제 주문 파일을 함수에 연결할 때는 열 이름과 필수 열 목록도 입력 조건으로 확인합니다. 파일이 열리더라도 status 또는 amount 열이 없으면 조회 결과를 만들 수 없습니다. 값의 범주도 함께 확인해야 합니다. 예를 들어 paid, pending, cancelled 외의 상태가 들어오면 새 업무 상태인지 오타인지 원천 시스템에서 확인합니다. 이러한 검사는 잘못된 행을 조용히 제외하는 것보다 문제를 발견하기 쉽습니다.

8정리와 다음 절

  • DataFrame은 레코드를 행과 열로 표현합니다.
  • 불리언 마스크와 loc는 필요한 행과 열을 선택합니다.
  • 합계 전에 자료형을 확인하고 변환 실패를 드러냅니다.

다음 학습과 이어지는 지점 — 다음 절에서는 주문 표의 고객 번호를 고객 표의 기본 키와 연결합니다. 현재 만든 fetch_orders 형태는 Ch 19에서 조회 도구의 실행 함수가 됩니다.

9복습 문제

문제와 해설

1. 한 주문과 주문 금액은 각각 DataFrame의 무엇에 해당하나요?

정답 한 주문은 행이고 주문 금액은 열입니다.

2. 결제 완료 주문만 고를 때 사용하는 조건은 무엇인가요?

정답 orders["status"] == "paid"입니다. 이 참·거짓 결과를 loc에 전달합니다.

3. 문자열 금액의 합계가 오류 없이 틀릴 수 있는 이유는 무엇인가요?

정답 문자열의 덧셈은 숫자 합산 대신 값을 이어 붙일 수 있기 때문입니다.

4. 조회 함수의 반환 열을 명시해야 하는 이유는 무엇인가요?

정답 후속 코드에 필요한 정보만 전달하고 반환 형식을 예측할 수 있게 하기 위해서입니다.
