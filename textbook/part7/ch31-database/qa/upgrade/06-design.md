## 1. 상황과 한 흐름

상담실 하루의 상담 시간이 정해져 있고, 문의 셋(01절 표 `requests`와 같은 번호·이름 — 1 환불 · 2 배송 · 3 결제)이 차례로 예약을 신청합니다. 문의마다 필요한 상담 시간(10분 · 30분 · 10분)은 이 절에서 실행 전에 정한 값입니다.

1. **하루 열기**(`open_day(start_minutes)` — 01절 이름 공간 지우고 만들기 · 02절 `CHECK` · 05절 `setup()`) — 이름 공간 `ch31_practice`를 지우고 다시 만든 뒤 상담 시간 표 `schedule`(`minutes int CHECK (minutes >= 0)`)·예약 표 `bookings`(`no int PRIMARY KEY`)를 만들고 처음 상담 시간 한 줄을 넣습니다. 이름 공간을 새로 만들었으므로 체크포인터 표 넷도 `setup()`으로 다시 만듭니다.
2. **문의 보내기**(`send_inquiry(inquiry)` — 05절 `invoke`·스레드) — 문의마다 스레드 하나(스레드 이름 = 문의 이름)로 그래프를 한 번 실행합니다.
3. **그래프 노드**(`book_inquiry(state)` — 02절 한 묶음 작업 · 04절 작은 연결 풀과 반납) — `engine.begin()` 블록 하나에서 예약 줄 넣기 + 상담 시간 빼기. 빼기가 `CHECK`를 어기면 `IntegrityError`(`23514`)를 받아 출력하고 `{"booked": 0}`, 아니면 `{"booked": 1}`. 엔진은 풀 크기 1·더 만들 연결 0·대기 제한 0.2초(04절 값)라, 오류로 끝난 블록이 연결을 반납하지 않으면 다음 문의가 연결을 받지 못합니다.
4. **체크포인터**(05절 4절 모양 — `psycopg.connect(…, autocommit=True, row_factory=dict_row)` + `SET search_path TO ch31_practice` + `PostgresSaver`) — 문의마다 상태 `{no, minutes, booked}`를 같은 이름 공간의 표에 저장합니다.
5. **확인**(`read_tables()`) — 남은 상담 시간 · 예약된 문의 번호(`array_agg(no ORDER BY no)` — 03절 모양) · 체크포인트 줄 수 · 빌려 간 연결 수 · 배송 문의의 `get_state` 값. 끝에서 체크포인터 연결을 닫고 **새 연결로** 같은 스레드의 상태를 다시 읽습니다(05절 `restored_state` 모양, 같은 데이터베이스).

## 2. 실행 1과 실행 2 — 값 하나만

| | 실행 1 | 실행 2 |
|---|---|---|
| 처음 상담 시간(분) | `first_start = 50`(= 10 + 30 + 10, 모두 들어가는 값) | **`second_start = 30`** |
| 그 밖 | 문의 셋과 분·그래프·엔진(풀 1·대기 제한 0.2초)·체크포인터 모두 같음 | 같음 |

- 손으로 적은 값은 모두 실행 전에 정함: 문의 셋의 번호·이름(01절 표와 같음) · 문의마다 분 10·30·10과 두 처음 상담 시간 50·30(이 절에서 정함 — 실행 2에서 둘째 문의가 `CHECK`를 넘도록 고른 흐름을 보여 주는 예). 노트북 출력 라벨(「실행 전에 정한 값」)과 b7에 출처를 적음.
- **바꾼 값을 처음 상담 시간으로 고른 까닭**: 02절 값 바꿔 보기는 보낼 금액(600 → 500)을 바꿔 오류 없이 이체되는 것을 봤고, 04절은 대기 제한(0.2 → 1.0)을 바꿔도 반납하지 않으면 여전히 막히는 것을 봤습니다. 이 절은 두 값 모두 바꾸지 않습니다. 02절 After(한 블록 → 오류 뒤 취소)의 모양은 실행 2 둘째 문의에서 다시 나오므로, **b2 「새로 볼 것」은 실행이 보인 만큼만**(Ch 26 05 검토 B-7): ① 셋 가운데 한 문의만 취소되고 흐름은 이어져 다음 문의가 예약됨 ② 풀에 연결이 하나뿐인데 오류로 끝난 블록 뒤에도 다음 문의가 연결을 받았고 끝에 빌려 간 연결 0 ③ 체크포인터는 취소된 문의의 상태(`booked` 0)도 저장했고, 체크포인트 줄 수가 두 실행 모두 아홉 ④ 연결을 닫은 뒤 새 연결로도 같은 상태를 읽음. 다른 후보와 견줌:
  - 풀 크기·대기 제한 하나 — 01절(풀 3 · 차례로 ↔ 함께)과 04절 값 바꿔 보기를 되풀이 · 노드는 문의를 차례로 받아 연결 하나로 충분해 풀 크기를 바꿔도 결과가 같을 것 → 뺌.
  - 문의 하나의 분 하나(배송 30 → 50) — 처음 상담 시간을 바꾸는 것과 같은 모양의 결과이고, 「문의는 그대로, 하루 조건만 다름」이 실무 이야기로 더 자연스러움 → 처음 상담 시간.

## 3. 붙인 앞 절 기능과 뺀 것

- **붙인 것(셋 — 모두 실행 1·2 흐름 안에서 쓰임)**: **02절** 한 묶음 작업(`begin()` 블록 하나에 넣기 + 빼기)·`CHECK` 제약·`except IntegrityError as error`·`error.orig.sqlstate`·`UPDATE` · **04절** 작은 연결 풀(`pool_size=1, max_overflow=0, pool_timeout=0.2`)·반납·`checkedout()`·`timeout()`·`status()` · **05절** 체크포인터 표를 같은 이름 공간에(`SET search_path`·`setup()`)·모델을 쓰지 않는 그래프(노드 하나)·스레드·`get_state`·새 연결로 다시 컴파일해 읽기. 받쳐 주는 것: 01절 이름 공간 지우고 만들기·`to_regnamespace`·`checkedin()`·문의 셋 · 03절 동기 엔진 `create_engine`·`with engine.begin()`·접속 글(`postgresql+psycopg`)·`array_agg(… ORDER BY …)`.
- **동기만 쓰는 까닭(인계 §05 → 실습 절 2 「섞으면 까닭 한 문장」)**: 그래프를 `invoke`로 부르고 체크포인터 `PostgresSaver`가 psycopg 동기 연결을 쓰므로, 노드 안의 한 묶음 작업도 03절처럼 동기 엔진으로 적습니다. `await`를 쓰는 노드·비동기 체크포인터(`AsyncPostgresSaver`)는 01~05절 어디에서도 실행하지 않은 새 API라 쓰지 않습니다. 02·04절의 `engine.begin()` 블록·연결 풀은 동기 엔진에서도 같은 이름으로 씁니다(03절이 동기 `engine.begin()`을 씀). 드라이버는 psycopg 하나 — 접속 글 둘은 드라이버 표시만 다름(03절 글 · 05절 글).
- **뺀 것과 까닭**: 01절 `gather`(노드는 문의를 차례로 받음 — 함께 기다리기는 01의 실험) · 03절 Alembic 판 올리기·내리기(표 구조를 바꾸는 흐름이 아니고, 판 파일 사본·환경 변수·파일 위치 셀까지 더하면 30분을 넘음 · 03은 묶음 실행 검사 절) · 05절 pgvector·HNSW 색인(검색 흐름이 아님) · 05절 백업·복원(명령 `pg_dump`·`pg_restore`를 찾는 셀·환경 변수·임시 폴더가 더해지고, 확장 만들기 실험은 05의 실험 그대로라 되풀이) · 04절 `create_task`·대기 제한 바꾸기(04에서 봄).
