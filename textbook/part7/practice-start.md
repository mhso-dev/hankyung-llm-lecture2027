# Part 7 실습 시작하기

이 묶음은 Ch30–34 서비스화와 배포 실습 자료입니다. 교재 HTML은 설명과 복사를 위한 화면이며, 실행은 Jupyter와 각 챕터 README가 안내하는 터미널에서 합니다.

압축을 푼 뒤 `labs/part7` 아래의 챕터 폴더를 엽니다. 그 폴더에서 `uv sync --locked`를 실행하고, VS Code에서 해당 `.venv`를 노트북 커널로 선택합니다. 노트북 하나를 시작할 때마다 커널을 새로 시작하고 첫 셀부터 순서대로 실행합니다. 데이터 파일과 설정 파일이 서로 연결되므로 묶음의 폴더 구조를 유지합니다.

모델을 호출하는 절에서는 묶음 최상위 `env.example`을 `.env`로 복사하고 본인의 `OPENAI_API_KEY`를 입력합니다. 키는 노트북 셀이나 출력에 넣지 않습니다. 노트북은 현재 폴더부터 상위 폴더에서 환경 파일을 찾습니다. 설치·컨테이너 이미지 다운로드·API 호출에는 인터넷 연결이 필요합니다.

Docker를 사용하는 실습은 Docker 엔진이 실행 중이어야 합니다. README의 준비 명령으로 실습용 서비스만 실행하고 지정한 포트가 이미 사용 중이면 실습 설정의 포트를 변경합니다. 기존 데이터베이스의 접속 정보를 실습에 사용하지 않습니다. 각 챕터에 적힌 종료 명령은 해당 실습용 자원에만 적용합니다.

GitHub Actions와 클라우드 배포를 다룰 때는 로컬에서 확인한 결과와 원격 시스템에서 확인해야 할 결과를 나누어 읽습니다. 저장소·레지스트리·클라우드 계정은 묶음에 포함되지 않습니다. 공개 저장소를 쓰더라도 인증값은 파일에 넣지 않고 GitHub Actions의 저장소 비밀값 등 별도 설정에 보관합니다. 배포 권한은 자신의 환경에서 준비합니다. 실제 외부 실행 여부는 교재와 챕터 검증 기록에 표시합니다.

실행이 막히면 오류가 나타난 절의 README와 준비 셀을 먼저 확인합니다. `ModuleNotFoundError`는 선택한 커널과 설치 환경이 다른 경우가 많습니다. 연결 거부는 대상 서버의 실행 상태와 포트부터 확인합니다. 이전 셀의 변수가 남아 결과가 달라졌다면 커널을 재시작합니다.
