1학습 목표

  • 여러 모델 호출을 대화 단위 비용으로 합칠 수 있습니다.
  • 최근접 순위 방식으로 대화당 비용 p50과 p95를 계산할 수 있습니다.
  • 호출 전에 예상 최대 비용을 검사하는 예산 가드를 작성할 수 있습니다.

2이 내용을 배우는 이유

한 번의 대화는 분류, 검색, 생성, 재시도와 폴백을 포함할 수 있습니다. 한 번의 호출 평균 비용만 보면 여러 단계가 반복된 비싼 대화를 발견하기 어렵습니다. 대화당 비용을 합산하고 p95를 관리하면 대부분의 사용자가 경험하는 상위 비용 구간을 목표치와 비교할 수 있습니다. 평균이 낮아도 일부 대화가 매우 비싸질 수 있습니다.

3앞에서 배운 내용

Ch 15에서는 합성 비용 분포에서 p50·p95·p99를 계산했고, Ch 16에서는 호출 전에 계획 비용 상한을 검사했습니다. 이번 절은 이 두 결과를 실제 서비스 운영 지표로 묶습니다. 각 호출에 conversation 식별자를 남긴 뒤 대화별 합계를 구합니다.

4핵심 개념

평균 뒤에 숨은 비싼 대화

열 명 가운데 아홉 명의 비용이 낮고 한 명의 비용만 매우 높으면 평균만으로는 꼬리 구간을 설명하기 어렵습니다. 백분위수(percentile)는 값을 작은 순서로 정렬했을 때 일정 비율이 그 값 이하에 놓이는 경계를 나타냅니다. p95는 관찰값의 약 95%가 그 값 이하라는 뜻입니다.

대화당 비용
같은 대화 식별자에 속한 모든 모델·도구 호출 비용의 합입니다.
p50
비용 분포의 가운데에 해당하는 값입니다.
p95
비용이 큰 쪽 5%에 들어가기 직전의 경계를 나타내는 값입니다.
예산 가드(budget guard)
현재 사용액과 다음 호출의 예상 최대 비용이 상한을 넘는지 요청 전에 검사하는 코드입니다.
하드 리밋(hard limit)
넘으면 호출을 시작하지 않는 절대 상한입니다.

이 실습은 최근접 순위(nearest rank) 방식을 사용합니다. 정렬한 값이 n개일 때 ceil(0.95 × n)번째 값을 p95로 고릅니다. 도구마다 보간 방식이 다를 수 있으므로 지표 이름과 함께 계산 방식을 기록합니다.

코드 읽기와 개념 경계

대화당 비용은 개별 호출 행을 conversation 식별자로 묶어 합한 값입니다. nearest_rank는 값을 정렬하고 ceil(percentile × n)번째 값을 고릅니다. 표본이 열 개이면 p95가 사실상 가장 큰 관찰값이 되므로 출력의 p95는 한 대화에 민감합니다. 계산 도구마다 보간 방식이 다를 수 있어 지표 이름과 방식을 함께 기록합니다.

allow_call(spent, estimated_max, hard_limit)은 이미 쓴 값과 다음 호출의 예상 최대값을 더해 요청 전에 실행 여부를 반환합니다. 실제 사용량을 사후 집계하는 p95와 호출 전 차단하는 예산 가드는 시점이 다릅니다. 예상치를 너무 낮게 두면 상한을 넘을 수 있고 너무 높게 두면 정상 요청을 막으므로 모델·도구 경로별 상한을 관찰 자료로 갱신합니다.

대화별 호출 기록

각 대화는 한 번 이상의 모델 호출을 포함합니다. 아래 값은 비용 계산을 학습하기 위한 고정 기록입니다.

바로 다음 코드를 읽는 방법

대화당 비용은 개별 호출 행을 conversation 식별자로 묶어 합한 값입니다. nearest_rank는 값을 정렬하고 ceil(percentile × n)번째 값을 고릅니다. 표본이 열 개이면 p95가 사실상 가장 큰 관찰값이 되므로 출력의 p95는 한 대화에 민감합니다. 계산 도구마다 보간 방식이 다를 수 있어 지표 이름과 방식을 함께 기록합니다.

In [2]:
calls = [
 {"conversation":"c1","cost":0.0012}, {"conversation":"c1","cost":0.0008},

출력:

최근접 순위 방식 p95

값을 정렬한 뒤 ceil(0.95 × n)번째 값을 고릅니다. 계산 방식을 대시보드 문서에 함께 기록해야 합니다.

In [3]:
def nearest_rank(values, percentile):
    ordered = sorted(values)
    rank = math.ceil(percentile * len(ordered))
    return ordered[rank - 1]

costs = list(totals.values())
p50 = nearest_rank(costs, 0.50)
p95 = nearest_rank(costs, 0.95)
print(f"대화당 비용 p50=${p50:.4f}, p95=${p95:.4f}")
출력:
대화당 비용 p50=$0.0020, p95=$0.0062

예산 가드 판정

요청 전에 예상 최대 비용을 더해 상한을 넘으면 호출을 시작하지 않습니다.

이 단계에서 구분할 범위

allow_call(spent, estimated_max, hard_limit)은 이미 쓴 값과 다음 호출의 예상 최대값을 더해 요청 전에 실행 여부를 반환합니다. 실제 사용량을 사후 집계하는 p95와 호출 전 차단하는 예산 가드는 시점이 다릅니다. 예상치를 너무 낮게 두면 상한을 넘을 수 있고 너무 높게 두면 정상 요청을 막으므로 모델·도구 경로별 상한을 관찰 자료로 갱신합니다.

In [4]:
def allow_call(spent, estimated_max, hard_limit):
    return spent + estimated_max <= hard_limit

checks = [(0.003, 0.001, 0.005), (0.0045, 0.001, 0.005)]
for values in checks:
    print(values, "허용" if allow_call(*values) else "차단")
출력:
(0.003, 0.001, 0.005) 허용
(0.0045, 0.001, 0.005) 차단

목표치와 비교

목표를 0.005달러로 두고 p95를 판정합니다. 표본이 10개라서 한 개의 큰 값에 민감합니다.

In [5]:
target = 0.005
print("목표:", target, "관찰 p95:", p95, "상태:", "초과" if p95 > target else "충족")
assert p95 == max(costs)
출력:
목표: 0.005 관찰 p95: 0.0062 상태: 초과

확인할 점 — 관찰된 p50은 0.0020달러, p95는 0.0062달러입니다. 0.0045달러를 이미 쓴 대화가 최대 0.001달러인 호출을 시작하려 하면 가드가 차단합니다.

6실험 결과 해석

목표를 0.005달러로 두었을 때 관찰 p95 0.0062달러는 목표를 초과했습니다. 열 개의 표본에서 최근접 순위 p95는 최댓값과 같으므로 한 대화의 변화에 매우 민감합니다. 표본을 늘리고 시간 구간을 고정한 뒤 추세를 함께 봐야 합니다. 이 값은 실제 운영 청구서가 아니라 비용 집계 방법을 확인하기 위한 고정 실습 데이터입니다.

비용을 절반으로 줄이는 과제에서는 어떤 품질과 지연을 포기했는지도 기록합니다. 캐시를 늘리면 접두어 변경 자유도가 줄 수 있고, Batch를 쓰면 완료가 늦어집니다. 작은 모델을 쓰면 어려운 요청의 실패율이 오를 수 있으며, 동시성을 낮추면 대기열이 길어질 수 있습니다. 하나의 비용 숫자만으로 최적화를 완료했다고 판단하지 않습니다.

7주의할 점과 실무 메모

  • 예상 최대 비용은 입력 상한과 출력 상한을 포함해 보수적으로 계산합니다.
  • 요청 후 실제 사용량을 다시 기록해 예약한 예산과 차이를 정산합니다.
  • 예산 초과 시 사용자에게 재시도만 요구하면 요청 폭주가 생길 수 있으므로 대체 모델이나 작업 축소 정책을 둡니다.
  • p95 계산 방식과 표본 기간을 바꾸면 이전 지표와 직접 비교하기 어렵습니다.

8정리와 다음 절

  • 호출 비용은 대화 식별자로 합쳐야 전체 경로의 비용을 볼 수 있습니다.
  • p95는 평균이 숨기는 비싼 꼬리 대화를 보여 줍니다.
  • 예산 가드는 호출 전에 예상 최대 비용을 검사하고 실제 사용량으로 다시 정산합니다.

9복습 문제

문제와 해설

1. 호출당 평균 대신 대화당 비용을 보는 이유는 무엇인가요?

한 대화에서 발생한 여러 호출과 재시도 비용을 모두 포함하기 위해서입니다.

2. 표본이 열 개일 때 최근접 순위 p95가 최댓값과 같은 이유는 무엇인가요?

ceil(0.95 × 10)이 10이므로 정렬한 열 번째 값을 고르기 때문입니다.

3. 예산 가드는 언제 실행해야 하나요?

외부 호출을 시작하기 전에 현재 사용액과 예상 최대 비용을 합쳐 검사해야 합니다.

4. 비용 절감 기록에 함께 남겨야 할 것은 무엇인가요?

품질, 지연, 실패율 가운데 무엇이 달라졌는지와 비교 조건입니다.
