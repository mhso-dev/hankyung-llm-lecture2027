1학습 목표

  • Batch API용 JSONL 입력을 만들 수 있습니다.
  • 각 요청의 식별자와 구조를 제출 전에 검사할 수 있습니다.
  • 즉시 처리와 비동기 배치 처리의 선택 기준을 설명할 수 있습니다.

2이 내용을 배우는 이유

야간 평가, 대량 분류, 임베딩 생성처럼 완료 시각에 여유가 있는 작업은 비동기 배치로 모을 수 있습니다. OpenAI Batch API는 별도 처리 한도와 24시간 완료 창을 제공하며 표준 동기 API 대비 50% 할인된 가격을 안내합니다. 비용을 줄이는 대신 즉시 결과를 받을 수 없다는 조건을 받아들여야 합니다.

3앞에서 배운 내용

Ch 15의 runs/batch-eval-input.jsonl에서는 평가 입력 형식을 준비했습니다. 이번 절은 같은 JSON Lines(JSONL) 원리를 Responses API의 실제 배치 요청 구조에 적용합니다. JSONL은 한 줄마다 하나의 JSON 객체를 저장하는 파일 형식입니다.

4핵심 개념

접수함에 모아 처리하기

창구 직원이 손님 한 명마다 즉시 서류를 처리하는 방식과, 마감 시각까지 접수한 서류를 한꺼번에 처리하는 방식은 기다림과 운영 비용이 다릅니다. Batch API는 두 번째 방식에 해당합니다. 요청자는 custom_id로 각 결과를 원래 업무와 연결합니다.

비동기 처리(asynchronous processing)
요청 제출과 결과 수신이 같은 연결에서 즉시 끝나지 않는 처리 방식입니다.
JSONL
각 줄이 독립된 JSON 객체인 텍스트 형식입니다.
custom_id
배치 결과를 원래 요청과 연결하기 위해 사용자가 정하는 고유 값입니다.
완료 창(completion window)
배치 처리가 완료되어야 하는 시간 범위이며 현재 공식 문서는 24h를 안내합니다.

코드 읽기와 개념 경계

JSONL은 파일 전체가 하나의 JSON 배열인 형식이 아니라 각 줄이 독립된 JSON 객체인 형식입니다. 각 Batch 요청에는 결과를 원래 업무와 연결할 custom_id, HTTP 메서드, 엔드포인트, 요청 본문이 들어갑니다. 예제는 세 객체를 줄 단위로 직렬화하고 다시 읽어 필수 키와 식별자 중복을 검사합니다. 여기까지는 로컬 입력 검증이며 업로드나 배치 생성은 실행하지 않습니다.

Batch는 즉시 응답이 필요한 대화보다 야간 분류·대량 평가처럼 완료를 기다릴 수 있는 작업에 맞습니다. 제출 순서와 결과 순서가 같다고 가정하지 말고 custom_id로 결합해야 합니다. 일부 요청만 실패할 수 있으므로 배치 전체 상태와 각 줄의 오류를 나누어 재처리합니다.

실행 환경 준비

이 준비 셀이 하는 일

준비 셀은 현재 폴더와 부모 폴더에서 ch34-cost-rate-limits 실습 폴더를 찾고, 발견한 .env가 있으면 현재 프로세스에 불러옵니다. 키 값은 출력하지 않으며 준비 결과로 폴더와 환경 파일의 존재 여부만 확인합니다. 이후 파일 기록은 찾은 chapter_root 아래 runs 폴더를 사용합니다.

In [1]:
from pathlib import Path
from dotenv import load_dotenv

here = Path.cwd().resolve()
chapter_root = next((p for p in (here, *here.parents) if p.name == "ch34-cost-rate-limits" and (p / "notebooks").is_dir()), None)
if chapter_root is None:
    raise FileNotFoundError("ch34-cost-rate-limits 실습 폴더 안에서 실행하세요.")
env_path = next((p / ".env" for p in (here, *here.parents) if (p / ".env").exists()), None)
if env_path:
    load_dotenv(env_path)
print("Python 준비 완료", "API 키 파일 확인" if env_path else "API 키 파일 없음")
출력:
Python 준비 완료 API 키 파일 확인

세 요청을 JSONL로 만들기

각 줄은 고유한 custom_id, 메서드, URL, 요청 본문을 가집니다.

바로 다음 코드를 읽는 방법

JSONL은 파일 전체가 하나의 JSON 배열인 형식이 아니라 각 줄이 독립된 JSON 객체인 형식입니다. 각 Batch 요청에는 결과를 원래 업무와 연결할 custom_id, HTTP 메서드, 엔드포인트, 요청 본문이 들어갑니다. 예제는 세 객체를 줄 단위로 직렬화하고 다시 읽어 필수 키와 식별자 중복을 검사합니다. 여기까지는 로컬 입력 검증이며 업로드나 배치 생성은 실행하지 않습니다.

In [2]:
import json

items = ["배송 지연", "환불 요청", "상품 문의"]
rows = [{"custom_id": f"ticket-{i}", "method": "POST", "url": "/v1/responses",
         "body": {"model": "gpt-5-mini", "input": f"다음 문의를 분류하세요: {text}"}}
        for i, text in enumerate(items, 1)]
batch_path = chapter_root / "runs/batch-input.jsonl"
batch_path.parent.mkdir(parents=True, exist_ok=True)
batch_path.write_text("\n".join(json.dumps(r, ensure_ascii=False) for r in rows) + "\n")
print(batch_path, "요청 수:", len(rows))
출력:
[사용자 폴더]/working/claude/projects/한국경제신문/labs/part7/ch34-cost-rate-limits/runs/batch-input.jsonl 요청 수: 3

로컬 구조 검증

파일 업로드와 배치 생성은 비용이 들고 외부 비동기 작업을 시작하므로 이 실습에서는 제출하지 않습니다.

In [3]:
loaded = [json.loads(line) for line in batch_path.read_text().splitlines()]
required = {"custom_id", "method", "url", "body"}
valid = all(required <= row.keys() and row["url"] == "/v1/responses" for row in loaded)
print("JSONL 구조 유효:", valid)
assert valid and len({row["custom_id"] for row in loaded}) == len(loaded)
출력:
JSONL 구조 유효: True

확인할 점 — 실행 결과는 요청 수 3과 JSONL 구조 유효 True를 출력합니다. 실제 업로드나 배치 생성은 수행하지 않습니다.

6일부러 실패해 보기

세 개의 JSON 객체를 하나의 배열로 저장하면 일반 JSON으로는 유효하지만 JSONL 배치 입력은 아닙니다. 실패 셀은 첫 줄을 읽었을 때 목록이 나온다는 사실을 확인합니다. 수정 셀은 객체마다 줄바꿈을 넣고 각 줄이 사전인지 다시 검사합니다.

7주의할 점과 실무 메모

  • custom_id는 배치 안에서 고유해야 하며 결과 순서가 입력 순서와 같다고 가정하지 않습니다.
  • 입력 파일 업로드와 배치 생성은 외부 작업을 시작합니다. 이 교재는 구조를 완성하고 로컬 검증한 뒤 실제 제출은 수행하지 않았습니다.
  • 24시간 완료 창은 즉시 응답이 필요한 사용자 요청에 맞지 않습니다.
  • 할인율과 지원 엔드포인트는 바뀔 수 있으므로 배포 전에 공식 문서를 다시 확인합니다.

8정리와 다음 절

  • Batch API는 완료 시각에 여유가 있는 대량 작업에 사용합니다.
  • 각 요청은 JSONL 한 줄과 고유한 custom_id를 가져야 합니다.
  • 파일 구조 검증과 실제 제출을 별도 단계로 둡니다.

9복습 문제

문제와 해설

1. Batch API가 고객 채팅의 첫 응답에 맞지 않는 이유는 무엇인가요?

결과가 비동기로 처리되며 현재 완료 창이 24시간이기 때문입니다.

2. 결과를 원래 문의와 연결하는 필드는 무엇인가요?

custom_id입니다.

3. JSON 배열 파일과 JSONL의 차이는 무엇인가요?

JSON 배열은 전체가 하나의 값이고, JSONL은 각 줄이 독립된 JSON 객체입니다.
