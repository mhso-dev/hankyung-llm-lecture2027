1학습 목표

  • 요청 특성에 따라 두 모델 가운데 하나를 고르는 규칙을 작성할 수 있습니다.
  • 같은 평가 사례에서 품질과 실제 토큰 비용을 함께 비교할 수 있습니다.
  • 작은 표본의 결과를 서비스 전체 성능으로 일반화할 수 없는 이유를 설명할 수 있습니다.

2이 내용을 배우는 이유

상태 확인과 단일 의도 분류에는 긴 추론이 필요하지 않을 수 있습니다. 반면 여러 규정을 비교하고 근거를 작성하는 요청은 더 높은 성능의 모델이 필요할 수 있습니다. 모델 라우팅(model routing)은 정해 둔 조건에 따라 모델을 선택하는 방법입니다. 비용 절감은 품질 기준을 만족할 때만 의미가 있습니다.

3앞에서 배운 내용

Ch 6에서는 같은 작업을 여러 제공자에 실행해 응답·비용·지연을 비교했습니다. Ch 18에서는 코드가 분기를 고르는 라우팅 패턴을 구현했습니다. 이번 절은 서비스 운영 관점에서 짧은 분류는 gpt-5.4-nano, 복잡한 설명은 gpt-5.4-mini로 보내는 규칙을 만듭니다.

4핵심 개념

업무 난이도에 맞는 담당자 배정

모든 문의를 가장 숙련된 담당자에게 배정하면 쉬운 문의도 비싼 자원을 사용합니다. 반대로 모든 문의를 초급 담당자에게 주면 복잡한 사례의 품질이 낮아질 수 있습니다. 라우터는 요청 길이, 필요한 도구, 위험 수준, 평가 점수처럼 관찰 가능한 조건으로 모델을 고릅니다.

모델 라우팅
요청 조건을 확인한 뒤 사용할 모델을 선택하는 처리입니다.
품질 기준선
배포 가능한 최소 정확도나 평가 점수입니다.
오분류 비용
라우터가 요청 난이도를 잘못 판단했을 때 생기는 재처리와 품질 손실입니다.
폴백(fallback)
작은 모델 결과가 기준을 만족하지 못할 때 상위 모델로 다시 처리하는 경로입니다.

2026년 9월 11일 공식 모델 페이지 기준으로 GPT-5.4 nano 표준 입력은 백만 토큰당 0.20달러, 출력은 1.25달러입니다. GPT-5.4 mini는 입력 0.75달러, 출력 4.50달러입니다. 단가는 변경될 수 있으므로 코드와 함께 기준일을 저장합니다.

코드 읽기와 개념 경계

모델 라우터는 요청을 관찰해 사용할 모델을 선택하는 함수입니다. 이 예제는 먼저 같은 세 분류 사례를 두 모델에 모두 실행하여 정확도와 실제 토큰 사용량을 기록합니다. 그 뒤 route 함수가 문자열 길이와 비교, 근거 포함 여부로 nano와 mini를 고릅니다. 라우팅 규칙의 출력은 모델 이름이며, 실제 모델 답은 선택 뒤 별도 호출에서 얻습니다.

길이가 짧다고 항상 쉬운 요청은 아니고 긴 요청이 항상 어려운 것도 아닙니다. 위험한 업무, 도구 필요 여부, 작은 모델의 확신 부족 같은 신호를 함께 평가하고 폴백 경로를 둡니다. 세 사례에서 두 모델이 모두 맞았더라도 전체 문의 분포의 품질 차이를 증명하지 않으므로 더 큰 고정 평가 세트로 라우터 자체를 검사합니다.

5실행 예제

배송·환불·상품 세 범주를 가진 문의 세 건을 두 모델에 똑같이 실행합니다. 답은 범주 하나로 제한하고 정확 일치로 채점합니다. 실제 입력·출력 토큰에 공식 단가를 적용해 표본 전체 비용을 계산하고, 응답 원문을 정답과 나란히 저장합니다.

확인할 점 — nano는 3문항 중 2문항, mini는 3문항을 맞혔습니다. nano는 상품 문의를 배송으로 잘못 분류했습니다.

6실험 결과 해석

실행된 여섯 번의 API 호출에서 gpt-5.4-nano 정확도는 0.6667, 추정 비용은 0.00003325달러였습니다. gpt-5.4-mini 정확도는 1.0, 추정 비용은 0.00012225달러였습니다. 이 세 사례에서는 nano가 더 저렴했지만 모든 사례를 맞히는 품질 기준을 충족하지 못했습니다. 따라서 “짧은 요청은 모두 nano”라는 규칙을 바로 배포할 수 없습니다. 프롬프트와 구조화 출력 조건을 개선하거나, 실패 검증 뒤 mini로 보내는 폴백을 측정해야 합니다.

비용 계산은 GPT-5.4 nano 입력 0.20달러·출력 1.25달러, GPT-5.4 mini 입력 0.75달러·출력 4.50달러라는 2026년 9월 11일 표준 처리 단가를 반영했습니다. 캐시, Batch, 장문 컨텍스트, 도구 호출 비용은 포함하지 않았습니다. 첫 호출과 재처리 비용을 모두 포함해야 실제 라우팅 비용을 알 수 있습니다.

7주의할 점과 실무 메모

  • 요청 길이만으로 난이도를 완전히 알 수 없습니다. 짧지만 위험이 큰 요청은 상위 경로로 보냅니다.
  • 라우팅 임계값은 실제 서비스 평가셋으로 정하고 정기적으로 다시 측정합니다.
  • 모델 별칭의 동작과 가격이 바뀔 수 있습니다. 재현이 필요하면 지원되는 스냅샷을 검토합니다.
  • 작은 모델의 실패 후 재호출이 많으면 예상한 절감액이 줄어듭니다.

8정리와 다음 절

  • 쉬운 요청에 작은 모델을 사용하되 품질 기준선을 먼저 정합니다.
  • 비용은 실제 토큰과 기준일이 있는 단가로 계산합니다.
  • 라우터의 오분류와 폴백 비용도 전체 비용에 포함합니다.

다음 학습과 이어지는 지점 — 다음 절에서는 선택한 모델이 429를 반환할 때 재시도와 동시성 제한으로 처리량을 안정화합니다.

9복습 문제

문제와 해설

1. mini가 세 분류 문항을 모두 맞혔다는 결과로 어떤 결론까지 낼 수 있나요?

이 세 사례와 출력 조건에서는 mini가 모두 정답이었다고 말할 수 있습니다. 다른 과제의 성능까지 알 수는 없습니다.

2. 작은 모델이 실패할 때 상위 모델로 다시 보내는 경로를 무엇이라고 하나요?

폴백입니다.

3. 라우팅 비용에 첫 호출만 기록하면 무엇이 빠지나요?

검증 실패 후 재처리한 상위 모델 호출 비용이 빠집니다.
