## 1. 상황과 한 흐름 (과정표 과제 「자기 서비스의 대화당 비용을 절반으로 줄이는 과제 · 무엇을 포기했는지 함께 기록」)

책 가게 상담 서비스에 문의 셋(03절 문의 글 셋과 정답 종류 — 배송·환불·결제)이 차례로 옵니다. 문의마다 긴 정책 글(01절 규칙 문장 100번, 6000자)을 앞에 붙여 보냅니다. 대화 하나는 문의 하나이고, 모델에 요청을 한 번 보냅니다.

1. **모델 라우터(03)** — `choose_model(inquiry, length_limit)`가 문의 글의 글자 수로 nano·mini를 고름(모델 배정).
2. **예산 가드(05)** — 대화마다 고른 모델의 예약 금액을 `try_reserve(budget, amount)`로 먼저 예약. 비용 상한에 걸린 대화는 받지 않고 요청도 보내지 않음. 예약 금액은 요청 전에 정한 사용량(입력 3,200 · 캐시 입력 0 · 출력 20)을 05절 `make_usage`로 만들어 모델마다 `estimate_cost`로 셈(할인 없이 어림 — 요청 전에는 캐시 입력이 생길지 모름).
3. **공통 앞부분 + 실험 번호(01)** — 받은 대화만 `make_request(mark, policy_text, inquiry)`로 실험 번호·정책 글을 앞에 붙이고, 03절 `send_inquiry`가 공백과 답 형식 글을 붙여 고른 모델에 보냄. 요청 글은 01절 요청 글과 같은 모양(번호 38자 + 줄바꿈 + 정책 6000자 + 줄바꿈 + 문의 + 공백 + 답 형식 글 → 대화 1은 6097자 = 01절 요청 글 1과 같은 글자 수). **실행마다 새 실험 번호**를 만들어, 실행 2의 첫 요청이 실행 1이 남긴 앞부분과 맞지 않게 함(01절 실험 번호 뜻 그대로).
4. **사용량 → 예상 비용(01·Ch 6 06)** — 01절 `cost_row(label, usage, prices)`로 캐시 입력 할인을 넣은 비용과 할인 없이 센 비용을 한 줄에. 모델마다 그 요금표(03). 받은 대화의 비용 합은 05절 `total_cost`.
5. **기록 장치** — 이 절 새 함수 `print_answer(number, response, expected_type)` 하나(응답한 모델·답·정답 종류와 같은가·입력 토큰·캐시 입력 토큰을 한 줄로 출력하고 같은지를 내놓음). 「포기한 것」은 이 표의 정답 여부(nano로 보낸 대화)와 막힌 대화.

- 예약과 보내기의 차례: 대화마다 예약을 먼저 해 결과 목록을 만들고, 그다음 「예약됨」인 대화만 보냄. 예산 칸은 예약 금액으로만 바뀌고 실제 비용으로 고치지 않으므로(05·Ch 16 04), 대화마다 예약 직후 보내는 흐름과 받는 대화가 같음 — 결과 읽기 한 문장.
- **예약 단위(handoff 6항)**: 05절처럼 **대화마다 한 번** 예약. 이 절은 대화 하나가 요청 한 번이라, 칸 `calls`는 받은 대화 수이자 보낸 요청(`invoke`) 수가 됨. Ch 16 04절은 요청마다 예약했음 — 한 문장. 04절처럼 오류가 나면 SDK가 다시 보낼 수 있어 제공자가 받은 요청 수는 다를 수 있음(설치판 기본 2번, 켜 둔 채) — b7.

## 3. 붙인 앞 절 기능과 뺀 것

- **붙인 것(셋 — 모두 실행 1·2 흐름 안에서 출력으로 보임)**: **01** 공통 앞부분(정책 글)·실험 번호·`make_request`·캐시 입력 할인(`cost_row`의 두 값) · **03** 모델 라우터 `choose_model`·기준 길이·모델 배정·`send_inquiry`·모델마다 요금표·정답 종류 · **05** 예산 가드(`make_budget`·`try_reserve`)·예약 금액·받은 대화·막힌 대화·`make_usage`·`total_cost`. 받쳐 주는 것: Ch 6 06 `estimate_cost`·요금표 키 · Ch 16 04 `reserve`(도구 파일 안에서 `try_reserve`가 부름).
- **뺀 것과 까닭(b3 한 단락)**:
  - **02 일괄 처리(Batch API)** — 결과를 24시간 안에 받는 방법이라 노트북 흐름 안에서 기다리지 않음(02 조건 · 챕터 리드 결정 9 — 실습에서 일괄 작업을 만들지 않음). 할인 50%는 문서 값이라 이 절 셈에 넣지 않음.
  - **04 다시 보내기·한꺼번에 보내는 수** — 요청이 실패(429)하거나 여럿을 함께 보낼 때 드러나는 기능. 요청 다섯은 차례로 하나씩 보내고, 제공자의 요청 제한에 일부러 닿게 할 수 없음. 연습용 서버를 다시 띄우면 모델 요청 흐름과 섞이고 30분을 넘음. SDK 기본 다시 보내기(오류 때 2번)는 켜 둔 채.
  - **05 평균·95 백분위수** — 대화가 셋이라 백분위수가 뜻을 갖기 어려움(05는 스무 개). 예약 금액은 정한 사용량으로 셈.
