## 0. 실행 전에 적은 입력과 판단 규칙 (이 절을 적은 시각은 아래 「§0 저장 시각」 줄 — 이 절의 첫 모델 요청 전에 적음)

공통(노트북과 같은 글·같은 코드로 씀):

- 모델: 과정 표준 셀 `init_chat_model("openai:gpt-5.4-mini", temperature=0, reasoning_effort="none")`(`max_tokens`·`seed`·`max_retries` 없음 — 옛 판의 `seed=34`·`max_tokens=40`·`max_retries=1`은 쓰지 않음). 요청은 글 하나로 `model.invoke(글)`(사용자 메시지 하나 — Ch 6 01 모양).
- 공통 글(긴 정책 글): 규칙 문장 「고객 문의에 답할 때는 확인한 주문 정보만 근거로 삼고, 확인하지 못한 내용은 확인하지 못했다고 적습니다. 」(끝 공백 포함 60자)을 `for`로 **100번** 이어 붙임 → **6000자**(설치판 tiktoken `o200k_base`로 약 3,100토큰 — 모델 없이 셈, 노트북에는 없음).
- 바뀌는 글(문의 둘): Q1 「주문한 책이 일주일째 오지 않습니다. 이 문의의 종류를 배송, 환불, 결제 가운데 한 낱말로 답하세요.」 · Q2 「받은 책이 찢어져 있어 돈을 되찾고 싶습니다. 이 문의의 종류를 배송, 환불, 결제 가운데 한 낱말로 답하세요.」 — 첫 글자부터 다름.
- 실험 번호: `"실험 번호 " + uuid.uuid4().hex`(**38자**, 실행마다 새 값, 출력·기록하지 않음) — 이 실행의 요청이 앞 실행(앞 회차·다른 날 노트북)에 저장된 앞부분과 맞지 않게 하는 장치. 두 실행 모두 맨 앞.
- 요청 글 = `실험 번호 + "\n" + 앞 글 + "\n" + 뒤 글`(함수 `make_request(mark, first_text, second_text)` — 본문 한 줄).
- **실행 1**(바뀌는 글을 뒤에): A = 번호·정책·Q1 → B = 번호·정책·Q2. **실행 2**(값 하나만 바꿈 — 바뀌는 글을 정책 글 앞에): C = 번호·Q1·정책 → D = 번호·Q2·정책. 차례 A → B → C → D, 요청 사이에 기다림 없음.
- 결과를 보고 글·길이·차례·모델 설정을 바꾸지 않습니다.

회차마다 기록: 시작·끝 시각 · 정책 글자 수·번호 글자 수·요청 글자 수 · 요청마다 입력·출력 토큰 · LangChain `usage_metadata["input_token_details"]` 딕셔너리(키와 값) · `cache_read` · 키 `cache_creation`이 있는가 · `response_metadata["token_usage"]["prompt_tokens_details"]`(사용량 원본 안쪽 칸 — 설치판은 `model_dump()`라 값이 없던 칸도 `None`으로 들어감, `chat_models/base.py` 1966~1973·2021행) · 응답한 모델 이름 · 끝난 이유 · 답 글 · `cache_read % 128 == 0` · `cache_read <= 입력` · 오류.

판단 규칙(결론에 쓸 수 있는 관찰):

- **설계로 정한 값 — 5번 모두 같아야 결론·그림에 씀**(맨 앞 실험 번호와 첫 글자부터 다른 문의 때문에 맞는 앞부분이 128토큰보다 훨씬 짧아, 공식 안내의 「128의 배수로 내림」대로면 0이 되는 자리): **A 캐시 입력 0 · C 캐시 입력 0 · D 캐시 입력 0** · 네 요청 모두 `input_token_details` 키가 `['audio', 'cache_read']`(키 `cache_creation` 없음) · 사용량 원본의 `cache_write_tokens`가 `None` · 네 요청 모두 캐시 입력이 128의 배수 `True`·캐시 입력 ≤ 입력 `True` · 응답한 모델 이름 하나. 하나라도 다르면 결론에서 빼고 진단에 적은 뒤, 노트북 결과를 사실대로 둠.
- **서비스 판단 값 — 5번 모두 같고 노트북 새 커널 두 번에서도 같을 때만 결론에 「흔들림 확인 다섯 번과 두 커널에서 모두」 한정어로 씀**: **B 캐시 입력 > 0**(같은 앞부분을 보낸 둘째 요청이 캐시 입력을 받음 — 공식 안내 「A request can reuse a cached prefix only if it reaches a machine holding a matching entry that has not expired」, 보장 아님). 결론 문장의 중심은 설계로 정한 값(바뀌는 글을 앞에 두면 둘째 요청도 0)과 128 배수 성질에 두고, B는 한정어와 함께만. `assert`는 걸지 않음(옛 판 `records[1]["cached_read"] >= 1024` 뺌).
- **B가 5/5가 아니면**: 입력을 고치지 않고(규격 §2-7 10번 끝) 노트북 결과를 사실대로 두고, 원래 관찰(B > 0)일 때의 값을 「…이면 …이 됩니다」 꼴 셈 한 문장으로 덧붙이고, b7에 「같은 요청도 실행한 때에 따라 캐시 입력이 달라질 수 있다」. 원하는 값이 나올 때까지 다시 돌리지 않음.
- **흔들리는 값 — 결론·그림·정리·복습에 쓰지 않음**(결과 읽기 둘째 단락·b6 표·「확인할 점」·b7에만 「이번 실행에서는」·「교재 출력에서는」): B의 캐시 입력 수 · 입력 토큰 수(실험 번호의 토큰 수가 실행마다 조금 다름) · 출력 토큰 · 답 글 · 예상 비용과 그 비교(실행 1 합 ↔ 실행 2 합, 할인 있음 ↔ 없음 — 단 캐시 입력이 0인 요청의 「할인 있음 = 할인 없음」은 식이 정하는 값이라 설계로 정한 값과 같이 다룸). 다섯 번 같아도 서비스 쪽 값·모델 글이라 결론에 쓰지 않음.
- **그림 라벨 규칙**(뒤에서 넓히지 않음): 라벨에는 코드 값(규칙 문장 100번·6000자·번호 38자·요청 글 모양 「번호 · 정책 · 문의」 ↔ 「번호 · 문의 · 정책」·모델 이름 `gpt-5.4-mini`·`temperature=0`·`reasoning_effort="none"`·요금표 0.75·0.075·4.50과 확인일)과 위 「설계로 정한 값」(A·C·D 캐시 입력 0·키 `cache_creation` 없음·128의 배수 `True`)만. B의 「캐시 입력이 0보다 큼」은 5/5 **그리고** 새 커널 두 번에서 같을 때만 「흔들림 확인 다섯 번과 두 커널에서 모두」 한정어를 본문·캡션에 두고 라벨에는 「0보다 큼」까지만(수는 넣지 않음). 입력·출력 토큰 수·캐시 입력 수·요금·답 글·걸린 시간은 라벨·캡션·alt에 넣지 않음.
- 요청 수: **5회차 × 4 = 20번**. SDK 기본 재시도(오류 때 최대 2번 — 설치판 `openai/_constants.py` 7행)는 켜진 채(노트북과 같음). 더 보내지 않습니다. 오류가 나면 기록만 하고 다시 보내지 않습니다(스크립트가 요청마다 받아 적고 다음 요청으로).
