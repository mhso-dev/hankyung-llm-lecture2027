- 색(규격 §5-3 · handoff 「색」 — 01절과 같은 요소는 같은 색): 노트북이 만든 입력 파일·요청 줄과 노트북이 읽는 자료 파일(결과 파일·오류 파일) **초록(tool)** · 우리가 정의한 함수(`pair_by_order`·`answers_by_name`·`pair_by_name`) **파랑(flow)** · 노트북 출력으로 확인한 값(작업 상태·요청 수·상태 코드·받은 오류 코드 `unsupported_value`·After 결과) **노랑(measure)** · 노트북 밖에서 한 번 한 단계(파일 올리기·일괄 작업 만들기)와 두 칸 공통 파일 **회색**(노트북 밖 단계는 점선) · **보라 0장**(노트북은 모델을 부르지 않음) · **빨강은 Before 결함 결과 상자 둘뿐**(02-3의 결과 상자, 02-4 왼쪽 칸 결과 상자 — 결과 줄을 입력 차례대로 짝지어 답이 밀린 결과). 받은 오류(400)는 Before 결함이 아니라 노랑.
- 라벨 규칙: 자료 파일로 정해진 값(매번 같음 — `probe/02-batch.md` §3 5/5·새 커널 두 번 29/29)과 코드 값만. 모델 답 글은 파일에 고정된 값이라 라벨에 넣을 수 있으나 「모델이 쓴 글」임을 본문에 밝힘(02-3의 `환불` 하나만). 걸린 시간(약 2분)·토큰 수·요금은 라벨·캡션·alt에 넣지 않음(시간은 노트북 출력에 없음). 개수는 한글(다섯 줄·네 줄·한 줄·셋·넷·하나).
- 모양: 넷 이상 한 줄은 `flowchart TB` · 나란한 칸은 subgraph 둘 · subgraph 제목 `<br>` 없음 · 라벨 대괄호·따옴표 없음 · 긴 라벨은 처음부터 `<br>` · 노드 id `call`·`end` 안 씀 · `%% classes` 줄 · 노드 7개 이하 · viewBox 폭 868 이하 · 노트북 밖 단계는 점선.
- 차례: 노트북 밖 제출 한 번(23:08:49Z → completed 23:10:57Z) → 자료 파일 셋 → `/tmp` 사본 실행(tryA, PASS) → 게이트 wip-02(G1~G6 0, G7 3 — 그림 전) → 새 커널 A(`run_section.sh`, 23:24:53Z — 첨부 단계에서 멈춤) → 사본 B(`notebooks/` 커널, 23:25:03Z, 29/29 같음) → **이 설계표** → `.mmd` 넷·캡션 → `--src-only` → `run_section.sh … --no-exec` → 삽화(PNG를 본 뒤 alt·그림 읽기) → `--no-exec`.
