# 01절 그림 설계표 (비동기 라우팅과 스키마 · paired)

- 색(규격 §5-3·과정 요약 §8·handoff 「색」): 보낸 요청·실습 폴더 파일 **초록(tool)** · 우리가 만든 앱 객체·처리 함수·함수 호출과 값 바꿔 보기에서 **바꾼 값 파랑(flow)** · 노트북 출력으로 확인한 상태 코드·칸·받은 422 **노랑(measure)** · 라이브러리가 처리 함수 앞뒤에서 하는 일·두 앱 공통 값·두 앱 모두에 해당하는 사실 **회색(클래스 없음)** · **보라 0장**(모델 없음) · **빨강은 01-4 Before 칸의 결과 상자 둘뿐**(Before 결함 결과 — 빈 질문이 몸통까지 들어가 200, 응답 본문에 앱 안쪽 키 messages).
- 라벨 규칙: 모델을 부르지 않아 라벨의 값은 모두 앱과 시험용 클라이언트가 주고받은 값이고, 새 커널 두 번(A 프로젝트 맨 위 커널 06:32:54Z · B `notebooks/` 커널 06:33:07Z) 셀별 출력 22/22 같음(`outputs_sha256`까지). 흔들림 확인(`01-probe.md`)은 모델 판단이 없어 두지 않습니다. 라벨 숫자 200·404·405·422·500은 출력에 있음. 대괄호·따옴표·중괄호는 라벨에서 뺌(`['question', 'thread_id']` → 「question thread_id」, `{'status': 'ok'}` → 「status ok」, `['']` → 「빈 글 하나」, `[' ', ' ']` → 「공백 한 칸 두 번」).
- 차례: 새 커널 A(`run_section.sh`, 그림 첨부 단계에서 멈춤 — 01-1 PNG가 아직 없어서) → 사본 B → **이 설계표** → `.mmd` 다섯·캡션 → `run_section.sh … --no-exec`(렌더·첨부·빌드) → 삽화(PNG를 본 뒤 alt·그림 읽기) → `--no-exec`.
