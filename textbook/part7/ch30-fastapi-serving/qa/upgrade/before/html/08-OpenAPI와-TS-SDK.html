4핵심 개념

건축 도면은 부품의 치수와 연결 위치를 합의합니다. OpenAPI도 경로, 입력, 출력, 오류, 인증을 기계가 읽을 수 있게 기록합니다.

FastAPI의 `.openapi()`는 라우트와 Pydantic 모델에서 OpenAPI 3.1 문서를 만들고 캐시합니다. `/openapi.json`도 같은 문서를 제공합니다. `info.version`은 API 제품 버전이며 FastAPI 패키지 버전과 다릅니다.

요청의 길이와 정규식 제약, 응답 타입은 JSON Schema 참조로 기록됩니다. TypeScript 타입이 빌드 오류를 줄이지만 런타임 검증을 없애지는 못합니다. 서버와 클라이언트 배포 버전이 어긋날 수 있고 SSE 이벤트는 생성기가 완전히 모델링하지 못할 수 있습니다.

SDK 생성기는 OpenAPI를 읽어 타입과 HTTP 호출 코드를 만듭니다. `typescript-fetch` 생성물을 직접 수정하지 말고 스키마를 고쳐 다시 생성합니다. 생성기와 Node 버전을 고정하지 않으면 같은 스키마에서도 파일 구조가 달라질 수 있습니다.

SSE는 일반 JSON보다 생성 지원이 제한적입니다. 생성된 SDK가 POST와 인증 헤더를 만들더라도 ReadableStream 분리와 Last-Event-ID 관리는 실제 출력으로 확인해야 합니다. 이 장은 `client/stream.ts`에 그 처리를 둡니다.

필수 요청 필드 추가, 타입 변경, enum 제거, 경로 삭제는 호환성을 깨울 수 있습니다. 이전 스키마와 새 스키마 차이를 CI에서 검사하고 생성된 SDK로 프런트 테스트를 실행합니다. 공개 함수 이름을 안정화하려면 operationId를 명시적으로 관리합니다.

코드 읽기와 개념 경계

app.openapi()는 현재 라우트와 Pydantic 모델에서 OpenAPI 문서를 파이썬 사전으로 만듭니다. paths에는 URL별 연산이, $ref에는 공통 스키마를 가리키는 참조가 들어갑니다. 예제는 요청이 ChatRequest, 200 응답이 ChatResponse를 참조하는지 검사하고 JSON 파일로 저장합니다. SDK 생성기는 실행 중인 서버를 추측하는 대신 이 문서를 입력으로 사용합니다.

스키마가 같은 문자열로 두 번 생성된다는 검사는 현재 프로세스에서 결정적인 출력을 확인할 뿐, 이전 배포와의 호환성을 증명하지 않습니다. 필수 필드 추가, 타입 축소, 상태 코드 삭제는 기존 클라이언트를 깨뜨릴 수 있습니다. 반대로 선택 필드 추가도 생성된 SDK를 다시 배포해야 소비자가 타입으로 사용할 수 있습니다.

도식 읽기

위쪽의 요청에서 아래쪽의 관찰 결과까지 화살표를 따라 읽습니다. 파란 상자는 데이터, 보라색 상자는 Agent 실행, 초록 상자는 확인할 결과를 나타냅니다.

서비스 설계 판단

계약 검토에서는 이전 OpenAPI와 새 문서를 기계적으로 비교한 뒤 변경 이유를 사람이 읽습니다. 필수 필드 추가나 타입 변경은 명확한 호환성 위험이며, 설명과 예시 변경도 프런트 구현에 영향을 줄 수 있습니다. 생성된 SDK의 함수명은 operationId에 따라 결정되므로 공개 API에서는 안정적인 이름을 지정하고 중복을 검사합니다. 생성물 컴파일은 스키마가 TypeScript 문법으로 변환되었다는 증거입니다. 실제 서버 호출 성공까지 보장하지 않으므로 생성 SDK로 health와 JSON chat을 호출하는 통합 검사도 둡니다. SSE의 itemSchema처럼 생성기가 아직 이해하지 못하는 확장은 경고를 숨기지 않고 버전과 우회 옵션을 기록합니다. 우회 옵션을 계속 사용해야 하는지 생성기 업그레이드 때 다시 확인하고, 경고가 사라졌다면 직접 스트림 코드와 생성물의 역할을 재검토합니다.

OpenAPI와 TS SDK

Pydantic과 FastAPI 선언이 OpenAPI 스키마가 되고 TypeScript 클라이언트 생성 입력이 되는 과정을 확인합니다.

실행 환경 준비

현재 폴더나 상위 폴더에서 labs/part7/ch30-fastapi-serving을 찾아 작업 폴더로 사용합니다. 비밀 키를 출력하지 않습니다.

이 준비 셀이 하는 일

이 준비 셀은 Path.cwd().resolve()로 현재 폴더를 절대 경로로 읽고, 현재 폴더와 부모 폴더에서 agent_service가 있는 첫 위치를 next(..., None)로 찾습니다. 찾지 못하면 assert가 실행을 중단합니다. 찾은 뒤 os.chdir(lab)이 이후 import와 파일 접근의 기준 폴더를 바꾸고, 마지막 출력은 실제 선택된 폴더 이름을 확인합니다.

In [1]:
import os
from pathlib import Path
start = Path.cwd().resolve()
lab = next((p for p in (start, *start.parents)
    if (p / 'agent_service').is_dir()), None)
assert lab is not None, 'agent_service가 있는 Ch30 실습 폴더에서 실행하세요.'
os.chdir(lab)
print('실습 폴더:', Path.cwd().name)
출력:
실습 폴더: ch30-fastapi-serving

스키마 생성

서버 프로세스를 시작하지 않아도 앱 객체에서 같은 OpenAPI 문서를 얻을 수 있습니다.

바로 다음 코드를 읽는 방법

app.openapi()는 현재 라우트와 Pydantic 모델에서 OpenAPI 문서를 파이썬 사전으로 만듭니다. paths에는 URL별 연산이, $ref에는 공통 스키마를 가리키는 참조가 들어갑니다. 예제는 요청이 ChatRequest, 200 응답이 ChatResponse를 참조하는지 검사하고 JSON 파일로 저장합니다. SDK 생성기는 실행 중인 서버를 추측하는 대신 이 문서를 입력으로 사용합니다.

In [2]:
import json
from agent_service.app import app
schema = app.openapi()
path = Path('openapi.json')
path.write_text(json.dumps(schema, ensure_ascii=False, indent=2), encoding='utf-8')
print(schema['openapi'], len(schema['paths']))
assert '/v1/chat' in schema['paths']
출력:
3.1.0 5

타입과 보안 정보 관찰

요청 스키마의 필수 필드와 응답 타입이 계약 문서에 포함됩니다.

In [3]:
chat = schema['paths']['/v1/chat']['post']
request_ref = chat['requestBody']['content']['application/json']['schema']['$ref']
response_ref = chat['responses']['200']['content']['application/json']['schema']['$ref']
print(request_ref, response_ref)
assert request_ref.endswith('/ChatRequest')
assert response_ref.endswith('/ChatResponse')
출력:
#/components/schemas/ChatRequest #/components/schemas/ChatResponse

이 단계에서 구분할 범위

스키마가 같은 문자열로 두 번 생성된다는 검사는 현재 프로세스에서 결정적인 출력을 확인할 뿐, 이전 배포와의 호환성을 증명하지 않습니다. 필수 필드 추가, 타입 축소, 상태 코드 삭제는 기존 클라이언트를 깨뜨릴 수 있습니다. 반대로 선택 필드 추가도 생성된 SDK를 다시 배포해야 소비자가 타입으로 사용할 수 있습니다.

In [4]:
first = json.dumps(app.openapi(), sort_keys=True)
second = json.dumps(app.openapi(), sort_keys=True)
print('동일:', first == second, '문자 수:', len(first))

print('SDK 생성 입력:', path.resolve())
출력:
동일: True 문자 수: 4885

6실험 결과 해석

같은 앱 객체의 두 OpenAPI 직렬화 결과는 같았습니다. 이는 코드 변경 뒤 스키마도 같다는 뜻이 아닙니다. 별도 프로세스에서 기준 파일과 새 파일을 비교해야 변경을 찾을 수 있습니다.

  • SSE 오류와 재연결은 실제 브라우저 통합 테스트를 유지합니다.

9복습 문제

1. OpenAPI 기본 경로는 무엇인가요?

해설 — /openapi.json입니다.

2. 생성물을 직접 고치지 않는 이유는 무엇인가요?

해설 — 재생성 때 사라지므로 서버 선언을 고쳐야 합니다.

3. OpenAPI가 SSE 재연결을 보장하나요?

해설 — 아닙니다. 생성기 범위와 통합 동작을 확인해야 합니다.

4. 호환성을 깨는 변경 예는 무엇인가요?

해설 — 필수 필드 추가나 타입 변경입니다.
