1학습 목표

  • LangChain 1.4의 create_agent와 실제 OpenAI 모델을 FastAPI에 연결할 수 있습니다.
  • 도구를 호출한 Agent의 ainvoke 최종 답을 HTTP JSON으로 받을 수 있습니다.
  • 실제 모델 메시지 청크를 astream으로 읽어 SSE token 이벤트로 전달할 수 있습니다.

2이 내용을 배우는 이유

01절부터 08절까지 사용한 결정적 LangGraph는 입력마다 같은 문자열을 만들기 때문에 라우팅, 재연결, 오류 이벤트를 반복 검사하기 좋습니다. 그러나 공백으로 나눈 문자열은 실제 모델의 토큰 스트림이 아니며 도구 선택도 수행하지 않습니다. 서비스가 Ch21에서 만든 Agent와 Ch25의 모델 스트림을 실제로 전달하는지는 별도의 통합 실행으로 확인해야 합니다.

3앞에서 배운 내용

Ch21에서는 init_chat_model과 create_agent로 도구 호출 Agent를 만들었습니다. Ch25에서는 stream_mode="messages"에서 모델 메시지 청크와 실행 메타데이터를 읽었습니다. 03절의 JSON 라우트와 05절의 네이티브 SSE 라우트에 이 실제 Agent를 연결합니다.

4핵심 개념

무대 장치 점검에서는 배우 없이 조명과 문이 같은 순서로 작동하는지 반복합니다. 최종 공연 전에는 배우가 실제 대사를 말하고 소품을 사용하는지 확인합니다. 결정적 그래프가 전송 장치 점검이라면 실제 모델과 도구의 통합 호출은 최종 공연 점검에 해당합니다.

build_live_agent()는 init_chat_model("openai:gpt-5.4-mini")로 모델을 초기화하고, 요일별 운영 시간을 반환하는 도구와 함께 create_agent를 호출합니다. 시스템 메시지는 운영 시간 질문에 반드시 도구를 사용하도록 요구합니다. 노트북은 월요일 질문의 답에 도구가 반환한 18:00이 포함되는지 검사합니다.

단일 응답 라우트는 runtime.ainvoke()의 마지막 AI 메시지에서 text를 골라 ChatResponse로 반환합니다. 스트림 라우트는 runtime.astream(..., stream_mode="messages")를 반복합니다. 실행 메타데이터의 노드가 model인 메시지에서 텍스트 블록만 골라 token 이벤트로 보냅니다. 도구 호출 인자와 도구 결과를 사용자 문장으로 잘못 표시하지 않도록 스트림 종류를 구분합니다.

실제 모델의 청크 경계는 글자, 단어, 언어 토큰 경계와 일치하지 않을 수 있습니다. 노트북 출력에서도 한글 한 글자와 숫자 일부가 별도 이벤트로 나타날 수 있습니다. 클라이언트는 모든 token 데이터의 문자열을 순서대로 이어 붙이고 done 이벤트를 받은 뒤 완성된 답으로 취급합니다.

API 키는 프로젝트의 .env에서 읽고 존재 여부만 출력합니다. 키 값, 전체 환경 변수, Authorization 헤더 원문은 교재 출력에 남기지 않습니다. 실제 모델 호출은 재실행할 때 표현과 token 이벤트 수가 달라질 수 있으므로 답의 정확한 문장 대신 도구 근거인 18:00과 이벤트 종류를 검증합니다.

코드 읽기와 개념 경계

이 절은 로컬 대체 객체 대신 실제 모델과 도구가 연결된 Agent를 HTTP 경계에서 호출합니다. TestClient.post('/v1/chat/live', ...)가 요청 스키마와 인증을 통과시키고, 내부 Agent는 운영 시간 조회 도구를 선택합니다. 이어서 ToolMessage와 tool_calls를 읽어 모델의 최종 문장만 확인하지 않고, 어떤 도구와 인수가 사용됐는지 검사합니다. 마지막 스트림에서는 SSE의 data JSON에서 token을 꺼내 연결합니다.

답에 18:00이 포함됐다는 한 조건만으로 올바른 도구 실행을 증명할 수 없습니다. 모델이 우연히 같은 숫자를 생성했을 수도 있기 때문입니다. 그래서 HTTP 응답, 도구 호출 인수, 도구 결과, 스트림 완료를 서로 다른 관찰로 남깁니다. 이 검사는 현재 질문 한 건의 통합 경로를 확인하며 다른 요일과 오류 입력의 품질까지 일반화하지 않습니다.

도식 읽기

HTTP 질문이 실제 create_agent에 들어가고, Agent가 운영 시간 도구 결과를 읽은 뒤 최종 문장 또는 모델 token SSE를 반환하는 순서로 읽습니다. 보라색은 실제 모델 실행, 파란색은 입력과 도구 데이터, 초록색은 HTTP에서 관찰한 결과입니다.

서비스 운영 인계

실제 Agent 엔드포인트를 운영으로 넘길 때는 모델 이름, 시스템 메시지 버전, 도구 목록, timeout, 평가셋 버전을 한 실행 기록에 묶습니다. 답이 달라졌을 때 모델 변경인지 도구 데이터 변경인지 찾으려면 이 정보가 필요합니다. 요청 식별자는 HTTP 로그, Agent 실행, 공급자 호출에 같은 값으로 연결하되 질문 원문과 인증 토큰은 공개 로그에 남기지 않습니다.

결정적 그래프 엔드포인트와 실제 모델 엔드포인트를 모두 공개할 필요는 없습니다. 전자는 로컬 교육과 회귀 검사에 사용하고, 운영 라우트는 실제 Agent 제공자만 주입하도록 애플리케이션 구성을 분리합니다. 배포 전에 OpenAPI에서 교육용 경로가 빠졌는지 확인하고, 실제 Agent의 오류율과 첫 token 지연을 별도 계기판에서 측정합니다. 이 장의 한 질문 성공은 배포 승인 기준이 아니라 통합 경로가 연결되었다는 최소 증거입니다.

실제 Agent HTTP 통합

OpenAI 모델과 조회 도구가 있는 LangChain create_agent를 FastAPI에서 실제 호출합니다.

실행 환경 준비

현재 폴더나 상위 폴더에서 labs/part7/ch30-fastapi-serving을 찾아 작업 폴더로 사용합니다. 비밀 키를 출력하지 않습니다.

이 준비 셀이 하는 일

이 준비 셀은 Path.cwd().resolve()로 현재 폴더를 절대 경로로 읽고, 현재 폴더와 부모 폴더에서 agent_service가 있는 첫 위치를 next(..., None)로 찾습니다. 찾지 못하면 assert가 실행을 중단합니다. 찾은 뒤 os.chdir(lab)이 이후 import와 파일 접근의 기준 폴더를 바꾸고, 마지막 출력은 실제 선택된 폴더 이름을 확인합니다.

In [1]:
import os
from pathlib import Path
start = Path.cwd().resolve()
lab = next((p for p in (start, *start.parents)
    if (p / 'agent_service').is_dir()), None)
assert lab is not None, 'agent_service가 있는 Ch30 실습 폴더에서 실행하세요.'
os.chdir(lab)
print('실습 폴더:', Path.cwd().name)
출력:
실습 폴더: ch30-fastapi-serving

키 존재 확인

상위 폴더의 .env를 읽고 키 값은 출력하지 않습니다.

API 연결에 필요한 환경 변수 확인

find_dotenv(usecwd=True)는 현재 폴더부터 상위 폴더에서 .env를 찾고, load_dotenv()는 환경 변수를 읽습니다. os.getenv()로 키 설정 여부를 읽고 bool()로 참·거짓만 출력합니다. assert has_key는 키가 없으면 중단합니다. 이 셀은 모델이나 HTTP 경로를 호출하지 않습니다.

In [2]:
import os
from dotenv import find_dotenv, load_dotenv
load_dotenv(find_dotenv(usecwd=True))
has_key = bool(os.getenv('OPENAI_API_KEY'))
print('OPENAI_API_KEY 설정:', has_key)
assert has_key
출력:
OPENAI_API_KEY 설정: True

실제 ainvoke HTTP 요청

Agent는 운영 시간을 도구로 확인한 뒤 한 문장으로 답합니다.

TestClient(app)는 같은 프로세스 안에서 FastAPI 요청 처리를 시험하는 클라이언트입니다. post()에 경로, 인증 헤더, JSON 본문을 넘기면 해당 경로가 실행됩니다. /v1/chat/live의 내부 Agent는 실제 모델을 호출하므로 외부 모델 API 연결이 필요합니다. 반환된 HTTP 상태 코드와 답 문자열을 함께 확인합니다.

In [3]:
from fastapi.testclient import TestClient
from agent_service.app import app
client = TestClient(app)
headers = {'Authorization': 'Bearer local-demo-token'}
body = {'question': '한빛도서관 월요일 운영 시간은?', 'thread_id': 'live-1'}
response = client.post('/v1/chat/live', headers=headers, json=body)
print(response.status_code, response.json()['answer'])
assert response.status_code == 200
assert '18:00' in response.json()['answer']
출력:
200 한빛도서관 월요일 운영 시간은 09:00~18:00입니다.

도구 호출 궤적 확인

같은 실제 Agent의 메시지에서 도구 이름, 입력, 도구 출력을 확인합니다.

build_live_agent()는 호출 객체를 준비하고 await live_agent.ainvoke(...)가 별도의 실제 실행을 시작합니다. tool_calls에는 모델이 요청한 도구 이름과 인수가 있고, ToolMessage에는 실행한 도구의 결과가 있습니다. 앞 HTTP 호출의 저장 궤적을 읽는 셀이 아니라 같은 질문으로 별도 실행한 궤적을 확인하는 셀입니다.

In [4]:
from langchain_core.messages import ToolMessage
from agent_service.live_agent import build_live_agent
live_agent = build_live_agent()
trace = await live_agent.ainvoke({'messages': [
    {'role': 'user', 'content': body['question']}
]})
tool_call = next(call for message in trace['messages']
    for call in getattr(message, 'tool_calls', [])
    if call['name'] == 'lookup_library_hours')
tool_result = next(message for message in trace['messages']
    if isinstance(message, ToolMessage))
print(tool_call['name'], tool_call['args'], tool_result.content)
assert tool_call['args']['day'] == '월요일'
assert tool_result.content == '09:00~18:00'
출력:
lookup_library_hours {'day': '월요일'} 09:00~18:00

실제 astream HTTP 요청

같은 Agent의 모델 메시지 청크를 SSE token 이벤트로 받습니다.

SSE는 이벤트 이름과 데이터를 텍스트 블록으로 보내는 형식입니다. 아래에서는 event: token 블록을 고르고 data: 뒤의 JSON을 읽어 token 문자열을 연결합니다. TestClient에서 완성된 응답을 받아 해석하므로 화면에 조각이 실시간으로 보이는 지연을 측정하지 않습니다.

In [5]:
import json, re
stream = client.post('/v1/chat/live/stream', headers=headers, json=body)
blocks = [b for b in re.split(r'\r?\n\r?\n', stream.text) if b]
tokens = []
for block in blocks:
    if block.startswith('event: token'):
        data_line = next(line for line in block.splitlines() if line.startswith('data: '))
        tokens.append(json.loads(data_line[6:])['token'])
live_answer = ''.join(tokens)
print(stream.status_code, live_answer)
assert stream.status_code == 200
assert blocks[-1].startswith('event: done')
assert '18:00' in live_answer
출력:
200 한빛도서관 월요일 운영 시간은 09:00~18:00입니다.

실험 결과 해석

결정적 그래프와 실제 모델 Agent의 출력 성질을 구분합니다.

이 단계에서 구분할 범위

답에 18:00이 포함됐다는 한 조건만으로 올바른 도구 실행을 증명할 수 없습니다. 모델이 우연히 같은 숫자를 생성했을 수도 있기 때문입니다. 그래서 HTTP 응답, 도구 호출 인수, 도구 결과, 스트림 완료를 서로 다른 관찰로 남깁니다. 이 검사는 현재 질문 한 건의 통합 경로를 확인하며 다른 요일과 오류 입력의 품질까지 일반화하지 않습니다.

In [6]:
token_events = stream.text.count('event: token')
print('실제 모델 token 이벤트:', token_events)
print('결정적 그래프가 아닌 create_agent 호출: True')
assert token_events > 0
출력:
실제 모델 token 이벤트: 20
결정적 그래프가 아닌 create_agent 호출: True

확인할 점 — 단일 응답과 스트림을 이어 붙인 답에 모두 월요일 운영 종료 시각 18:00이 있는지 확인합니다. 스트림에는 한 개 이상의 token 이벤트와 마지막 done 이벤트가 있는지도 확인합니다.

6실험 결과 해석

새 커널 실행에서 실제 OpenAI 모델이 운영 시간 도구를 사용했고 JSON 응답에 18:00을 포함했습니다. 같은 Agent의 messages 스트림을 SSE로 전달했을 때 token 이벤트가 여러 번 나타났고 이어 붙인 문장에도 18:00이 포함되었습니다. 이는 실제 모델·도구·Agent·FastAPI의 로컬 통합 경로가 실행되었음을 보여 줍니다.

한 질문의 성공은 모든 질문의 도구 선택 정확도나 운영 안정성을 뜻하지 않습니다. 모델 표현과 청크 수는 달라질 수 있습니다. Ch29 평가셋으로 도구 선택과 최종 답을 반복 평가하고, 배포 뒤에는 지연·오류율·비용을 함께 측정해야 합니다.

7주의할 점과 실무 메모

  • 실제 API 호출 횟수와 사용량 메타데이터를 실행 기록에 남기며 키 값은 출력하지 않습니다. 이 절은 응답과 도구 궤적 확인이 목적이므로 비용을 임의로 추정하지 않습니다.
  • 도구 결과를 사용했다는 사실은 Agent 메시지 궤적과 도구 호출 기록으로 확인합니다. 최종 문장에 숫자가 있다는 사실만으로 도구 호출을 단정하지 않습니다.
  • 실제 모델 라우트의 오류 이벤트는 공급자 예외 원문을 숨기고 안정적인 코드와 고정 문구만 보냅니다.

8정리와 다음 절

  • 결정적 그래프는 전송 계약의 반복 검사에 사용합니다.
  • 실제 create_agent 통합은 모델과 도구를 HTTP 경계까지 호출합니다.
  • 모델 token 이벤트를 순서대로 이어 붙이고 done으로 완료를 확인합니다.

다음 학습과 이어지는 지점 — Ch31에서는 실제 Agent 실행과 이벤트를 데이터베이스에 저장해 프로세스 재시작 뒤에도 복구합니다.

9복습 문제

1. 결정적 그래프와 실제 모델 Agent를 모두 실행하는 이유는 무엇인가요?

해설 — 전자는 전송 계약을 반복 검사하고 후자는 모델·도구 통합을 확인하기 때문입니다.

2. 모델 청크를 이어 붙인 뒤 확인한 값은 무엇인가요?

해설 — 도구가 반환한 월요일 종료 시각 18:00입니다.

3. API 키를 어떻게 확인했나요?

해설 — .env를 읽고 키의 존재 여부만 출력했습니다.

4. 한 질문 성공으로 알 수 없는 것은 무엇인가요?

해설 — 전체 질문의 도구 선택 정확도, 지연 분포, 오류율, 비용은 추가 평가가 필요합니다.
