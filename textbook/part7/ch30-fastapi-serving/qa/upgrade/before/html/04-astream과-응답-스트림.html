2이 내용을 배우는 이유

모델 답이 완성될 때까지 빈 화면을 보여 주면 사용자는 서비스가 멈췄다고 느낄 수 있습니다. 스트리밍은 중간 결과를 먼저 전달해 첫 응답 지연을 줄이지만 오류, 취소, 완료를 소비자가 관리해야 합니다.

4핵심 개념

완성된 보고서를 한 번에 받으면 첫 내용을 보기까지 기다려야 합니다. 작성 중인 문장을 조각으로 받으면 빨리 볼 수 있지만 순서와 완료 여부를 관리해야 합니다.

`astream`은 비동기 스트림 실행 메서드입니다. 한 번 `await`하는 값이 아니라 `async for`로 여러 번 꺼내는 비동기 반복자를 반환합니다. `stream_mode='custom'`은 노드가 스트림 작성기에 기록한 사용자 정의 데이터를 전달합니다. 교육용 노드는 답을 공백 단위로 나누어 `{'token': piece}`를 기록합니다.

청크 하나가 한 글자나 실제 모델 토큰 하나와 항상 일치하지는 않습니다. 제공자, 네트워크 버퍼, 프레임워크 설정에 따라 여러 토큰이 묶일 수 있습니다. 클라이언트는 청크 수를 언어 단위로 해석하지 않고 순서대로 내용을 이어 붙입니다. 완료는 마지막 문자열을 추측하지 않고 별도 신호로 전달합니다.

스트리밍 성능은 전체 완료 시간만으로 설명할 수 없습니다. 요청 후 첫 조각까지의 시간, 조각 사이 간격, 완료 시간, 취소 반영 시간을 함께 봅니다. 이 노트북은 로컬 결정적 그래프이므로 네트워크 속도를 측정하지 않습니다. 공백 수가 늘면 교육용 조각 수가 늘어나는 현상만 확인합니다.

비동기 생성기는 취소 요청을 처리할 기회를 가져야 합니다. 긴 반복에 `await`가 없으면 연결이 끊겨도 작업이 계속될 수 있습니다. 교육용 노드는 `await asyncio.sleep(0)`으로 실행권을 넘깁니다. 실제 모델 스트림도 하위 도구가 동기 작업으로 이벤트 루프를 막는지 따로 확인합니다.

코드 읽기와 개념 경계

agent.astream(input, stream_mode='custom')은 최종 사전 하나가 아니라 비동기 반복 가능한 스트림을 반환합니다. async for는 새 조각이 도착할 때마다 반복 본문을 실행하며, 이 예제는 각 조각의 token을 목록에 추가합니다. ''.join(chunks).strip()은 조각을 연결해 최종 문장을 만들지만, 연결 전 목록도 출력하여 경계가 어디였는지 확인합니다. 스트림 조각 수는 답의 의미 단위나 모델 토큰 수와 같다고 가정하지 않습니다.

파일 다운로드처럼 이미 만들어진 큰 바이트를 나누는 스트림과 Agent가 생성하면서 내보내는 스트림은 지연 원인이 다릅니다. 첫 조각까지의 시간, 조각 사이의 시간, 전체 완료 시간을 따로 측정해야 합니다. 또한 소비자가 연결을 끊었을 때 생산 작업을 취소하지 않으면 화면은 닫혔는데 모델 호출은 계속될 수 있습니다.

도식 읽기

위쪽의 요청에서 아래쪽의 관찰 결과까지 화살표를 따라 읽습니다. 파란 상자는 데이터, 보라색 상자는 Agent 실행, 초록 상자는 확인할 결과를 나타냅니다.

서비스 설계 판단

스트림 소비 코드는 세 상태를 구분하면 읽기 쉬워집니다. 시작 전에는 요청 검증과 인증이 실패할 수 있고, 진행 중에는 여러 token 또는 progress 조각이 도착하며, 종료에는 done, error, cancel이 있습니다. 각 상태에서 화면에 무엇을 표시하고 서버 작업을 어떻게 정리할지 정합니다. 받은 문자열을 매번 전체 DOM에 다시 넣으면 답이 길어질수록 렌더링 비용이 커질 수 있습니다. 일정한 간격으로 묶어 반영하되 사용자가 첫 내용을 늦게 보지 않도록 갱신 주기를 측정합니다. 모델 청크에는 텍스트뿐 아니라 도구 호출 조각이나 메타데이터가 들어올 수 있습니다. 사용자 문장으로 표시할 블록만 고르고 나머지는 별도의 진행 표시나 관측 기록으로 보냅니다. 이 구분이 없으면 도구 인자 JSON이 채팅 답에 노출될 수 있습니다.

astream과 응답 스트림

실제 LangGraph astream이 한 번의 최종 응답을 여러 사용자 정의 조각으로 전달하는지 관찰합니다.

실행 환경 준비

현재 폴더나 상위 폴더에서 labs/part7/ch30-fastapi-serving을 찾아 작업 폴더로 사용합니다. 비밀 키를 출력하지 않습니다.

이 준비 셀이 하는 일

이 준비 셀은 Path.cwd().resolve()로 현재 폴더를 절대 경로로 읽고, 현재 폴더와 부모 폴더에서 agent_service가 있는 첫 위치를 next(..., None)로 찾습니다. 찾지 못하면 assert가 실행을 중단합니다. 찾은 뒤 os.chdir(lab)이 이후 import와 파일 접근의 기준 폴더를 바꾸고, 마지막 출력은 실제 선택된 폴더 이름을 확인합니다.

In [1]:
import os
from pathlib import Path
start = Path.cwd().resolve()
lab = next((p for p in (start, *start.parents)
    if (p / 'agent_service').is_dir()), None)
assert lab is not None, 'agent_service가 있는 Ch30 실습 폴더에서 실행하세요.'
os.chdir(lab)
print('실습 폴더:', Path.cwd().name)
출력:
실습 폴더: ch30-fastapi-serving

스트림 수집

stream_mode='custom'은 노드가 기록한 토큰 조각을 받습니다.

바로 다음 코드를 읽는 방법

agent.astream(input, stream_mode='custom')은 최종 사전 하나가 아니라 비동기 반복 가능한 스트림을 반환합니다. async for는 새 조각이 도착할 때마다 반복 본문을 실행하며, 이 예제는 각 조각의 token을 목록에 추가합니다. ''.join(chunks).strip()은 조각을 연결해 최종 문장을 만들지만, 연결 전 목록도 출력하여 경계가 어디였는지 확인합니다. 스트림 조각 수는 답의 의미 단위나 모델 토큰 수와 같다고 가정하지 않습니다.

In [2]:
from agent_service.agent import agent
chunks = []
async for chunk in agent.astream(
    {'messages': ['세 단어 질문']}, stream_mode='custom'
):
    chunks.append(chunk['token'])
print(chunks)
assert len(chunks) >= 4
출력:
['질문을 ', '확인했습니다: ', '세 ', '단어 ', '질문 ']

중간 결과 관찰

마지막 조각을 기다리지 않아도 첫 조각을 먼저 처리할 수 있습니다.

In [3]:
first = chunks[0]
joined = ''.join(chunks).strip()
print('첫 조각:', first)
print('전체:', joined)
assert joined == '질문을 확인했습니다: 세 단어 질문'
출력:
첫 조각: 질문을 
전체: 질문을 확인했습니다: 세 단어 질문

반복 실험과 결과 해석

질문의 단어 수만 바꾸고 생성된 조각 수를 비교합니다.

이 단계에서 구분할 범위

파일 다운로드처럼 이미 만들어진 큰 바이트를 나누는 스트림과 Agent가 생성하면서 내보내는 스트림은 지연 원인이 다릅니다. 첫 조각까지의 시간, 조각 사이의 시간, 전체 완료 시간을 따로 측정해야 합니다. 또한 소비자가 연결을 끊었을 때 생산 작업을 취소하지 않으면 화면은 닫혔는데 모델 호출은 계속될 수 있습니다.

In [4]:
counts = {}
for question in ['짧음', '두 단어', '세 개의 단어']:
    count = 0
    async for _ in agent.astream({'messages': [question]}, stream_mode='custom'):
        count += 1
    counts[question] = count
print(counts)
assert counts['짧음'] < counts['세 개의 단어']
출력:
{'짧음': 3, '두 단어': 4, '세 개의 단어': 5}

확인할 점 — 첫 조각, 이어 붙인 전체 문자열, 질문별 조각 수를 실제 출력에서 확인합니다.

6실험 결과 해석

`짧음`, `두 단어`, `세 개의 단어`로 공백 수만 바꾸어 조각 수를 셉니다. 긴 질문에서 조각 수가 많았지만 이는 교육용 공백 분할의 결과이며 실제 모델의 토큰화나 패킷 수를 예측하지 않습니다.

7주의할 점과 실무 메모

  • 받은 조각을 HTML로 직접 삽입하지 말고 텍스트 노드나 안전한 렌더러를 사용합니다.
  • 연결 종료만으로 성공을 판단하지 않고 done과 error를 구분합니다.
  • 탭을 닫았을 때 Agent와 도구가 취소되는지 통합 환경에서 확인합니다.

9복습 문제

1. `astream`은 어떤 문법으로 반복하나요?

해설 — `async for`로 반복합니다.

2. 청크 하나를 토큰 하나라고 볼 수 있나요?

해설 — 아닙니다. 경계는 제공자와 버퍼 설정에 따라 달라집니다.

3. 완료 신호를 따로 두는 이유는 무엇인가요?

해설 — 빈 답과 오류 종료를 구분하기 위해서입니다.

4. 이 실험이 실제 모델 속도를 증명하나요?

해설 — 아닙니다. 로컬 분할 동작만 확인합니다.
