# 02절 그림 설계표 (의존성으로 Agent 주입 · paired)

- 색(규격 §5-3·과정 요약 §8·handoff 「색」): 보낸 요청·**실습 폴더 앱 파일의 함수**(`get_agent`·`require_token`·`get_timeout`·처리 함수 `chat`) **초록(tool)** · 노트북에서 우리가 만든 제공 함수·처리 함수·재정의에 적은 함수·재정의 딕셔너리에 적은 내용·`clear()`·값 바꿔 보기에서 **바꾼 값 파랑(flow)** · 노트북 출력으로 확인한 상태 코드·값·불린 기록·키 수, 첫 테스트가 일부러 만든 504 **노랑(measure)** · 라이브러리가 요청마다 하는 일·두 출력을 함께 읽은 사실 **회색(클래스 없음)** · **보라 0장**(모델 없음 — 실습 앱 그래프는 모델을 쓰지 않는 그래프) · **빨강은 02-4 Before 칸의 결과 상자 하나뿐**(재정의를 남긴 채 다음 테스트가 받은 504와 키 수 1 — Before 결함 결과).
- 같은 요소는 절 안 모든 그림에서 같은 색: `get_timeout`(초록, 02-3·02-4 라벨), `zero_timeout`·`two_second_timeout`·`get_limit`·`get_short_limit`(파랑).
- 라벨 규칙: 모델을 부르지 않아 라벨 값은 모두 앱과 시험용 클라이언트가 주고받은 값·노트북이 출력한 값입니다. 새 커널 두 번(A 프로젝트 맨 위 커널 07:10:35Z · B `notebooks/` 커널 07:10:45Z) 셀별 출력 24/24 같음(설치 셀 출력이 스트림 둘로 나뉘어 `outputs_sha256`만 다름 — 글자는 같음). 흔들림 확인(`02-probe.md`)은 모델 판단이 없어 두지 않고, 노트북 밖 같은 장면 5/5(`/tmp/ch30-02/exp/p1_scene.py`)만 진단에 적습니다. 라벨 숫자 0.0·0.5·1·2.0·200·401·504·0은 출력에 있음(`0.0`·`2.0`은 셀 [17]·[23]의 「재정의할 함수가 내놓는 초」 줄). 대괄호·따옴표·중괄호는 라벨에서 뺌(`{'limit': 2.0}` → 「limit 2.0」, `['get_limit', 'get_limit']` → 「get_limit 두 번」, `[]` → 「불린 기록 없음」). 응답 글 `Agent 응답 시간이 초과되었습니다`는 라벨에 넣지 않음(「Agent」 본문 금지어 — 상태 코드만).
- 차례: 새 커널 A(`run_section.sh`, 그림 첨부 단계에서 멈춤 — 02-1 PNG가 아직 없어서) → 사본 B → **이 설계표** → `.mmd` 다섯·캡션 → `run_section.sh … --no-exec`(렌더·첨부·빌드) → 삽화(PNG를 본 뒤 alt·그림 읽기) → `--no-exec`.
