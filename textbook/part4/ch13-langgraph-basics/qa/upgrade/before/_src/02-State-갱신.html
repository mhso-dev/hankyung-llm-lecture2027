1학습 목표

  • 상태 스키마가 노드 입력과 출력의 키·값 형식을 정의하는 방식을 설명할 수 있습니다.
  • 기본 덮어쓰기와 리듀서 누적의 차이를 실행 결과로 비교할 수 있습니다.
  • 노드가 일부 키만 반환하는 갱신 방식을 적용할 수 있습니다.

2이 내용을 배우는 이유

검색 단계는 documents를 만들고 생성 단계는 answer를 만듭니다. 모든 함수가 전체 딕셔너리를 다시 만들면 빠진 키나 오래된 값을 섞기 쉽습니다. LangGraph의 노드는 자신이 맡은 키의 갱신값만 반환합니다. 같은 키에 여러 갱신이 모일 때는 리듀서가 합치는 규칙을 담당합니다.

이번 절의 질문은 “노드가 같은 상태 키를 여러 번 반환하면 값은 덮어쓸까요, 누적할까요?”입니다. 노트북 출력과 그래프 그림을 함께 읽어 답합니다.

3앞에서 배운 내용

앞 절에서 StateGraph, 노드, 엣지, compile(), invoke()를 사용했습니다. 이번 절도 같은 순차 그래프를 사용하지만 상태 키별 갱신 규칙에 초점을 맞춥니다.

각 노트북은 Python 3.12 새 커널에서 독립 실행되며 이전 절의 메모리나 개인 경로를 사용하지 않습니다.

4핵심 개념

쉬운 예

공용 화이트보드의 칸마다 쓰기 규칙이 다르다고 생각해 봅니다.

정의

query 키는 새 값으로 교체하고 log 키는 새 항목을 뒤에 붙이도록 선언합니다. TypedDict는 상태에 어떤 키와 값 형식이 있는지 표현합니다. 리듀서(reducer)는 한 상태 키의 기존 값과 새 갱신값을 받아 최종 값을 만드는 함수입니다. Annotated[list[str], operator.add]는 두 목록을 이어 붙이도록 지정하므로 각 노드가 반환한 목록이 누적됩니다. 리듀서가 없는 키는 기본적으로 새 값이 기존 값을 덮어씁니다.

코드에서 읽는 순서

UpdateState에서 query에는 리듀서가 없고 log에는 operator.add가 붙어 있습니다. normalize와 expand는 모두 두 키를 갱신하지만 처리 방식은 키 선언에 따라 달라집니다. query는 두 번째 노드가 반환한 값으로 교체되고 log는 입력의 ['input']과 두 노드의 새 목록이 이어집니다. 이 구조에서는 각 노드가 이전 log 전체를 복사할 필요가 없습니다. 새 기록만 목록으로 반환해야 중복 없이 누적됩니다.

호출 표기와 실행 시점

TypedDict는 실행 중 값을 검사하는 클래스가 아니라 상태 키와 값의 형태를 코드에 표시하는 형식입니다. Annotated[list[str], operator.add]에서 첫 항목은 값의 형식이고 둘째 항목은 갱신을 합칠 함수입니다. 노드가 {'log': ['expand']}를 반환하면 런타임이 기존 log와 새 목록을 operator.add로 결합합니다.

다른 상황에 적용

고객 상담 상태에서는 answer는 최신 답으로 덮어쓰고 evidence는 검색 단계마다 누적할 수 있습니다. 이때 evidence 노드는 전체 증거 목록을 다시 반환하지 않고 새로 찾은 증거만 반환해야 합니다. 그래야 같은 항목이 두 번 더해지지 않습니다.

비교와 경계

리듀서는 여러 값을 무조건 보존하는 기능이 아닙니다. operator.add는 목록 순서를 이어 붙이지만 중복을 제거하거나 최신값을 고르지 않습니다. 집합 병합, 점수 최댓값, ID 기준 교체가 필요하면 그 규칙을 수행하는 별도 리듀서를 정의해야 합니다.

6실험 결과 해석

첫 노드는 query를 '도서 대출 기간'으로 바꾸고 log에 normalize를 보냅니다. 둘째 노드는 query를 '도서 대출 기간 정책'으로 다시 바꾸고 log에 expand를 보냅니다. 최종 query에는 마지막 값만 남지만 log에는 두 항목이 모두 남습니다. 키마다 규칙이 독립적으로 적용된다는 증거입니다.

두 번째 입력에 넣은 input 기록까지 유지되어 최종 log에는 세 항목이 남았습니다. 반면 query에는 expand가 만든 마지막 문자열 하나만 남았습니다.

이번 실행은 두 노드가 순서대로 한 상태를 갱신하는 경우만 확인했습니다. 여러 노드가 동시에 같은 키를 갱신하는 경우에는 해당 키의 리듀서 규칙을 추가로 검토해야 합니다.

7주의할 점과 실무 메모

  • 리듀서는 상태 전체가 아니라 Annotated로 표시한 키 하나에 적용됩니다.
  • 목록을 누적할 때 노드가 기존 목록을 다시 포함하면 항목이 중복될 수 있습니다.
  • 동시에 실행되는 노드가 같은 비리듀서 키를 갱신하면 충돌이 발생할 수 있으므로 병렬 구조에서는 합치는 규칙을 먼저 정합니다.

8정리와 다음 절

  • query 키는 마지막 값으로 교체됐습니다.
  • log 키는 operator.add 리듀서로 세 기록을 누적했습니다.
  • 노드는 자신이 바꿀 키와 새 값만 반환했습니다.

다음 학습과 이어지는 지점 — 다음 절에서는 상태의 점수에 따라 서로 다른 노드로 이동하는 조건부 엣지를 만듭니다.
