## 3. 바꾼 것

### 이름 정리 (handoff 「§02 → §03」 2항의 결정)

- 상태 형식을 02절 `RuleState`에서 넓혀 **`RouteState`**로 씁니다. 칸 `question`·`query`·`trace`는 글자까지 같고 `score`·`answer` 둘을 더했습니다.
- **이름을 `RuleState`로 그냥 두지 않은 까닭**: 02절 `RuleState`는 칸이 셋입니다. 같은 이름에 칸 수가 다르면 02절과 03절 코드를 나란히 놓고 볼 때 어긋납니다(handoff가 02절에 준 「같은 이름을 다른 모양으로 쓰지 않는다」와 같은 판단).
- 옛 노드 `inspect_score`는 두지 않았습니다. 상태를 고치지 않고 이름표만 내놓는 일은 조건 함수 `choose_path`가 하고, 01·02절 노드 `normalize`·`make_query`가 앞의 두 자리를 그대로 맡습니다.
- 옛 노드 `generate`·`request_more`는 **`make_answer`·`ask_more`**로 바꿨습니다. 01·02절 노드 이름이 모두 「동사 + 목적어」(`make_query`)라 결을 맞췄고, `generate`는 07절 모델 호출 자리와 뜻이 겹칩니다.
- **`print_state`를 다섯 줄로 늘렸습니다**(01·02절은 세 줄). 칸이 둘 늘어 `점수 칸 |`과 `답 칸 |`을 더했습니다.
- **`run_row`의 칸을 바꿨습니다**: 01절 `실행`·`검색어 칸`·`실행 흔적`, 02절 `실행`·`실행 흔적`·`흔적 길이`, 03절 **`실행`·`점수 칸`·`지난 노드`·`답 칸`**. 이 절이 견주는 값이 「넣은 점수 → 지난 노드 → 남은 답」이기 때문입니다(handoff 2항이 「그 절이 견줄 값에 맞춰 고르라」고 넘긴 자리).

### 노트북 (코드 셀 5 → 26)

- 제목 셀·「오늘 볼 그림」 셀을 넣고 설명 → 코드 → 결과 읽기를 반복합니다. 준비 셀은 설치·import 둘뿐이고 나머지는 모두 앞뒤에 마크다운이 있습니다.
- 한 셀에 있던 정의 셋을 **상태 형식 / `print_state` / `new_state` / 노드 넷 / 조건 함수**로 나눴습니다(셀당 정의 하나).
- 조건 표현식을 여러 줄 `if`/`return`으로 풀었습니다. 함수 본문은 모두 10줄 이하이고 코드 셀은 4~11줄입니다.
- **`Literal`을 쓰지 않고 `path_map`만 씁니다.** 타입힌트 `Literal`은 과정 요약 §2 「처음 쓰면 한 문장」 목록에 있어, 새 API 하나에 새 문법을 겹치지 않으려고 뺐습니다(handoff 4항). 옛 노트북은 둘을 함께 썼습니다.
- **조건 함수를 그래프 없이 먼저 부릅니다**(5절). 02절이 `operator.add`를 그래프 없이 먼저 부른 차례와 같습니다.
- **이름표 표를 따로 만들어 출력합니다**(6절). 이름표와 노드 이름이 다르다는 사실을 라벨 줄 아래 두 줄로 보입니다.
- **경계 조건을 실행합니다**(9절). 기준값과 똑같은 `0.7`을 넣어 비교 `>=`가 같은 값을 넉넉한 쪽으로 보내는 것을 출력으로 확인했습니다.
- **조건부 엣지를 뺀 그래프도 실행합니다**(10절). 같은 노드 넷을 고정 엣지로만 이어 넷이 모두 지나고 답 칸이 마지막 값으로 덮이는 것을 보였습니다. 02절 덮어쓰기·이어 붙이기를 여기서 한 번 더 씁니다.
- 설치는 `langgraph==1.2.11` 하나이고 **모델 요청 0번**이라 API 키 셀을 두지 않았습니다. 불러오는 이름 여섯 개는 02절과 같습니다.
- `assert`는 두 실행의 실행 흔적 칸 두 줄에만 썼습니다(코드가 정하는 값, 규격 §3).
