## 3. 바꾼 것

### 이름 정리 (handoff 2항의 결정)

01절 이름을 그대로 이어받았습니다. 상태 형식 `FlowState`, 칸 `question`·`query`·`trace`, 노드 `normalize`·`make_query`, 질문 `"  대출 기간은 며칠인가요?  "`, 출력 함수 `print_state`, 기록 함수 `run_row`입니다. 옛 `log` 칸은 `trace`로 맞췄고 옛 노드 `expand`는 쓰지 않았습니다. 규칙을 적은 상태 형식만 새 이름 `RuleState`로 두었습니다. **까닭**: 같은 이름을 다른 모양으로 두 번 쓰면 절 사이 표를 견줄 수 없고(과정 요약 §3), 01절이 「같은 두 노드를 리듀서 판으로 옮긴다」를 약속으로 남겼습니다.

### 노트북 (코드 셀 5 → 22)

- 제목 셀(할 일 4줄·준비물·기준 버전·강의와 실습 범위) + 「오늘 볼 그림」 첨부(`02-1`) + 모든 비준비 셀 뒤 결과 읽기 셀.
- 상태 형식 둘·출력 함수·노드 넷·기록 함수를 **셀 하나에 하나씩** 나눴습니다. 정의 셀과 호출 셀도 갈랐습니다.
- **바꾸는 값을 하나로 좁혔습니다.** 노드 `normalize`·`make_query`를 한 벌만 정의하고 **상태 형식만 바꿔**(`FlowState` → `RuleState`) 두 번 실행합니다. 두 실행의 차이는 칸에 적은 규칙 하나뿐입니다.
- **덮어쓰기를 먼저 실행으로 봅니다**(5절). 규칙이 없는 칸에서 `실행 흔적 칸 | ['make_query']`·`실행 흔적 칸의 길이: 1`이 나옵니다.
- **`operator.add`를 그래프 없이 먼저 부릅니다**(6절). `operator.add가 만든 목록: ['input', 'normalize']`로 「이어 붙이기」를 눈으로 본 뒤 그 함수를 칸의 규칙으로 적습니다. 표시 `Annotated`는 뜻 → 일상 예(짐 상자의 「깨지기 쉬움」 표) → 코드 모습 세 문장으로 풀었습니다.
- **값 바꿔 보기 두 번**. ① 처음 실행 흔적 칸에 `['input']`을 넣어 `['input', 'normalize', 'make_query']`(8절). ② 01절처럼 앞 흔적까지 내놓는 노드로 바꿔 `['normalize', 'normalize', 'make_query']`(9절). ②가 옛 본문의 「중복될 수 있습니다」를 출력으로 바꾼 자리이고, 01절 코드와 02절 코드의 차이를 잇는 자리입니다.
- 기록 한 줄(`run_row`) → 목록 `append` → 끝난 뒤 표 출력(Ch 9~12·01절과 같은 모양). 네 실행을 한 표에서 견줍니다.
- 설치는 `langgraph==1.2.11` 하나입니다. **모델 요청 0번**이라 API 키 셀을 두지 않았습니다(01절·Ch 10 01~05·Ch 12 04 선례).
- `assert`는 코드가 정하는 값 한 곳(`rule_result["trace"] == ["normalize", "make_query"]`)에만 걸었습니다. 모델 답 `assert`는 0건입니다.
- 쓰지 않은 것: `lambda`·내포식·조건 표현식·f-string·`key=`·`reverse=`·세미콜론·한 줄 복합문·`list()`·`enumerate`·`zip`·`join`·numpy·sklearn. 부른 내장 이름은 `len`·`print`·`type`뿐입니다.
