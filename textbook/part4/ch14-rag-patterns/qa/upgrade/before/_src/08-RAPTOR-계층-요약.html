1학습 목표

  • 이 절을 마치면 RAPTOR 축소 계층 요약의 입력과 출력을 설명할 수 있습니다.
  • 이 절을 마치면 RAPTOR, 요약 노드, 계층 검색, 오프라인 색인의 역할을 코드의 입력·처리·출력으로 구분할 수 있습니다.
  • 이 절을 마치면 상위 요약이 잘못된 범주를 선택해 하위 검색까지 어긋난 결과를 설명할 수 있습니다.

2이 내용을 배우는 이유

문서가 길어지면 세부 문단만 검색해서는 여러 부분에 걸친 질문에 답하기 어렵습니다. 상위 요약을 먼저 검색하고 관련 범주의 원문으로 내려가면 전체 주제와 세부 근거를 이어서 찾을 수 있습니다.

Ch9의 기본 RAG는 검색 한 번과 생성 한 번으로 구성되었습니다. Ch14에서는 질문을 바꾸거나 결과를 검사하는 단계를 추가합니다. 모든 선택은 if 문, 수치 임계값, 반복 상한에 적힌 규칙으로 실행합니다. 모델이 다음 행동을 자율적으로 결정하는 에이전트는 아직 사용하지 않습니다.

3앞에서 배운 내용

Ch11에서 정답 문서 ID와 Recall을 분리해 기록했습니다. Ch12에서는 core-documents.json의 문서 12건과 core-queries.json의 질문 8건으로 검색 설정을 비교했습니다. 이 절은 두 파일의 내용을 챕터 폴더에 복제해 같은 문서와 정답을 사용합니다. 전체 제공 PDF와 30문항을 쓰지 않는 축소 표본입니다.

4핵심 개념

RAPTOR

RAPTOR
RAPTOR는 문서 조각을 반복해서 군집화하고 요약하여 트리를 만든 뒤 여러 층에서 검색하는 방법입니다. 이 절은 범주 라벨이 이미 있는 12건을 세 묶음으로 나누고 각 묶음의 요약 노드를 한 번 만드는 축소 구현입니다. 군집화와 반복 트리 구축은 포함하지 않습니다.
흐름을 정하는 규칙
세 범주마다 요약 노드를 한 개씩 만들고 하위 문서 ID를 저장합니다. 질문과 가장 가까운 요약 한 개를 고른 뒤 해당 범주의 원문 세 건만 검색합니다.

호출 표기와 실행 시점

계층 검색은 원문 청크를 묶어 상위 요약 노드를 만들고, 먼저 요약에서 관련 범주를 찾은 뒤 그 범주의 원문으로 내려갑니다. 상위 노드는 하위 문서 ID를 보관해야 최종 답의 출처를 원문까지 추적할 수 있습니다.

다른 상황에 적용

사내 위키를 부서별 요약→문서별 원문 계층으로 만들면 넓은 질문은 부서 요약에서, 세부 규정은 해당 부서 문서에서 찾을 수 있습니다. 요약에 빠진 정보는 하위 원문 검색으로 보완합니다.

비교와 경계

원 논문의 RAPTOR는 임베딩 기반 군집화와 재귀적 요약 트리를 사용합니다. 이 노트북은 기존 category 값으로 한 단계만 묶은 축소 예제입니다. 요약이 짧아졌다는 이유만으로 검색이 좋아졌다고 판단하지 않고 원문 정답 ID로 비교합니다.

도식의 상자를 위에서 아래로 읽습니다. 나란한 상자는 분기하거나 따로 실행한 뒤 다시 합치는 처리입니다. 생성한 질문, 가상 문서, 평가 점수는 검색을 돕는 중간 값이며 출처로 인용하지 않습니다.

6실험 결과 해석

library, facility, account에 각각 네 문서가 묶였습니다. 세 요약 생성에는 680토큰과 약 5.42초가 들었습니다. ‘휴학이나 졸업 뒤 이용 권한’ 질문은 잘못된 facility 요약을 선택했습니다. 하위 문서 ID(child ID)는 FAC-001~004였고 최종 후보도 시설 문서였습니다. 요약 계층이 검색 오류를 만들 수 있음을 확인했습니다.

범주 라벨을 사람이 미리 제공했으므로 RAPTOR 논문의 자동 군집화 성능을 측정한 결과가 아닙니다. 요약에 빠진 사실은 상위 검색에서 사라질 수 있습니다. 요약 생성 비용은 온라인 질문 비용과 구분해 오프라인 색인 비용으로 기록해야 합니다.

코사인 유사도는 질문과 문서 벡터가 같은 방향을 가리키는 정도입니다. 이 값은 정답 확률이 아니며 데이터와 임베딩 모델이 바뀌면 임계값도 다시 정해야 합니다.

7주의할 점과 실무 메모

  • 운영 전에 확인합니다. 요약 생성 비용은 색인 구축 비용으로 따로 기록하고, 상위 요약에서 빠진 사실은 원문 검색 단계까지 전달되지 않을 수 있습니다.
  • 기록할 항목을 정합니다. 요약 노드에 하위 문서 ID를 저장해야 상위 선택 오류를 원문까지 추적할 수 있습니다.

8정리와 다음 절

  • 상위 요약을 잘못 선택하면 올바른 원문이 다른 범주에 있어도 하위 검색에서 찾을 수 없습니다.
  • 이 구현은 수동 범주 한 단계이며 자동 군집과 재귀 트리의 성능을 측정하지 않았습니다.

9복습 문제

문제 4개 · 해설 포함

1. RAPTOR 축소 계층 요약의 입력과 출력은 무엇입니까?

범주별 원문 묶음을 입력하면 하위 문서 ID를 가진 요약 노드와 선택한 범주의 원문 후보를 출력합니다.

2. 이 절의 실제 출력은 패턴 선택에 어떤 근거를 줍니까?

account 질문이 facility 요약을 선택하여 시설 문서만 하위 후보로 남았습니다.

3. 코드에서 호출 수나 후보 수를 제한하는 규칙은 무엇입니까?

요약 한 개를 선택하고 선택 범주의 원문 세 건까지만 검색합니다.

4. 생성한 중간 문장을 최종 답의 출처로 쓰면 안 되는 이유를 설명하세요.

모델이 만든 문장은 원문 자료에서 확인한 사실이 아닙니다. 실제 검색된 문서의 ID와 본문만 근거로 인용합니다.
