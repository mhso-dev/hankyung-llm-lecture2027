## 칸 순서 확인 (PNG를 직접 열어 본 결과)

- 그림은 새 커널 실행 A·B를 마친 **뒤에** 처음 렌더했습니다.
- `09-1` 첫 렌더(폭 406, `.cache/ch15-09/fig09-1-a.png`)는 모양은 맞았지만 라벨이 「08절 lines_for」·「07절 검사 scores_for 뒤」·「06절 예상 비용」처럼 **이 절이 새로 만든 함수(`lines_for`·`scores_for`·`print_costs`)를 앞 절 함수로 읽히게** 적혀 있었습니다. 「lines_for / 08절 요청 식별자로 두 줄 고르기」·「scores_for로 점수 / 07절 check_by_case」·「print_costs 안의 / 06절 estimate_cost」로 고쳐 다시 렌더(폭 466, `fig09-1-b.png`). 본문·노트북 alt와 도식 읽기도 「두 갈래」 대신 「화살표 둘 · 둘 다 실행됩니다」로 맞췄습니다(조건 갈래가 아님).
- `09-2`는 첫 렌더 그대로(폭 382, `fig09-2-a.png`): 맨 위 초록 질문 번호 → 초록 두 줄(왼쪽 old·오른쪽 new) → 보라 모델 → 노랑 두 점수(왼쪽 이전 판·오른쪽 이후 판) → 노랑 검사.
- `09-3`은 첫 렌더 그대로(폭 502, `fig09-3-a.png`): 왼쪽 칸 실행 1, 오른쪽 칸 실행 2, 칸 아래 회색 공통 상자(`~~~`로 두 칸과 나란히, 화살표 없음).
- `09-4`는 첫 렌더 그대로(폭 450, `fig09-4-a.png`)이지만 배치가 설계와 달라 **글을 그림에 맞췄습니다**: 초록 요청 식별자 여섯이 맨 위, 파랑 「두 실행」이 **오른쪽 위**, 파랑 `ids_not_in`이 **왼쪽 아래**, 「두 실행」 → `ids_not_in` 화살표가 있음, 노랑 합친 점수는 오른쪽 아래, 노랑 보내지 않은 요청은 왼쪽 맨 아래. alt와 도식 읽기를 「오른쪽 파란 상자는 두 실행 …, 왼쪽 파란 상자는 08절 `ids_not_in()` …」으로 적었습니다.

## 라벨에 넣은 값과 넣지 않은 값

- 라벨에는 **새 커널 두 번 실행(A 19:02:43·B 19:02:56 UTC 시작)에서 같았던 값만** 넣었습니다: 점수 0·1(`{'Q090': 0}` 등)·검사 `True`·`False`·깨진 사례 `Q002`·보내지 않은 `old-Q006`·`new-Q006`·요청 글 `5093`·`5117`·입력 토큰 `3248`·`3266`·`gpt-5.4-mini`.
- **넣지 않은 값**: 캐시 입력 토큰 수(A·B 모두 2816·1792로 같았지만 06절에서 실행마다 달랐고 확인 실행 첫 요청은 0 — 흔들리는 값으로 봄), 출력 토큰 수(A 38·56·41·47 ↔ B 48·61·45·50), 예상 비용(A 합 0.0015069·0.0009693 ↔ B 0.0015744·0.0010008). 조립도의 노랑 「요청마다 예상 비용」은 이름만 두고 값을 넣지 않았습니다(규격 §5-3 「노랑에는 출력으로 확인한 값만」 — 값이 흔들려 이름만).
- 개수는 「여섯 줄」·「두 줄」·「네 줄」·「두 번」·「여섯」처럼 한글로 적었습니다.
