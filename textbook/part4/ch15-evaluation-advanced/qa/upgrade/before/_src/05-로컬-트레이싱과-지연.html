1학습 목표

  • 질문 재작성·검색·리랭킹·생성을 하위 실행(child run)으로 기록할 수 있습니다.
  • 첫 토큰 도착 시간(TTFT)과 전체 지연(total latency)을 분리해 계산할 수 있습니다.
  • 캐시 읽기(cache read)와 캐시 생성(cache creation) 토큰을 별도 필드로 보존할 수 있습니다.

2이 내용을 배우는 이유

최종 답과 전체 시간만 남기면 어느 단계가 느렸는지, 비용이 어디서 생겼는지 알 수 없습니다. 검색이 늦었는지 생성 첫 토큰이 늦었는지 구분하려면 단계별 시작·종료 시각과 생성의 첫 토큰 시각을 기록해야 합니다. 캐시 사용량도 읽은 토큰과 새로 만든 토큰을 합치면 비용 변화를 설명하기 어렵습니다.

3앞에서 배운 내용

04절에서는 평가 대상과 평가 모델 결과를 레코드로 묶었습니다. 이번 절은 별도의 합성 실행 기록을 만들어 단계별 소요 시간과 부모·자식 관계를 관찰합니다. 앞 절의 파일을 읽어 같은 레코드에 경로를 추가하는 코드는 아닙니다. LangSmith 클라우드 키가 없으므로 기본 실습은 표준 JSON 로컬 실행 추적이며, 클라우드 업로드는 선택 확장으로만 안내합니다.

4핵심 개념

쉬운 예

택배가 늦었을 때 전체 배송 시간만 보면 창고, 간선 운송, 지역 배송 중 어디가 늦었는지 알 수 없습니다. 실행 추적도 재작성·검색·리랭킹·생성 구간을 따로 기록해 지연의 위치를 찾습니다.

정의

실행 추적(trace)은 한 요청의 전체 실행 기록이고 하위 실행(child run)은 그 안의 단계별 기록입니다. 첫 토큰 도착 시간(TTFT, time to first token)은 생성 시작부터 첫 토큰 도착까지의 시간입니다. 전체 지연(total latency)은 요청 시작부터 최종 응답 종료까지의 시간입니다. 스트리밍하지 않은 호출에는 첫 토큰 이벤트가 없으므로 TTFT를 추정해 넣지 않고 null로 남깁니다. 사용량은 input·output·cache_read·cache_creation 토큰을 구분합니다.

호출 표기와 실행 시점

trace는 한 요청의 전체 실행이고 span은 검색·프롬프트·생성처럼 그 안의 한 단계입니다. 각 span에 시작·종료 시각, 입력·출력 요약, 토큰 사용량을 남기면 전체 지연에서 어느 단계가 차지한 시간을 계산할 수 있습니다. 첫 토큰 도착 시간과 전체 완료 시간은 서로 다른 사용자 경험을 나타냅니다.

다른 상황에 적용

검색은 40ms인데 생성이 2초인 요청과 검색이 1.5초인데 생성이 600ms인 요청은 총시간이 비슷해도 수정할 부분이 다릅니다. 단계별 span을 남겨야 모델 교체와 인덱스 조정 중 무엇을 시험할지 정할 수 있습니다.

비교와 경계

이 노트북의 고정 시간값은 추적 구조와 계산법을 배우는 합성 데이터입니다. 실제 네트워크 병목을 측정한 결과가 아닙니다. 평균 지연만 보면 드문 장기 지연을 놓치므로 다음 절의 백분위수와 함께 봅니다.

5실행 예제

노트북은 재작성 12ms, 검색 31ms, 리랭킹 18ms, 생성 240ms인 로컬 실행 추적을 만듭니다. 생성 시작 후 85ms에 첫 토큰이 도착하도록 기록하고 첫 토큰 도착 시간 85ms, 전체 지연 301ms를 계산합니다. 캐시 읽기 420개의 토큰과 캐시 생성 80개의 토큰도 분리합니다. 이 숫자는 계측 구조를 학습하기 위한 고정 실습값이며 실제 API 실행 추적으로 가장하지 않습니다.

확인할 점 — 하위 실행 네 구간, 첫 토큰 도착 시간 85ms, 전체 지연 301ms와 캐시 읽기·생성 토큰을 확인합니다.

6실험 결과 해석

고정 로컬 실행 추적에서 생성은 61ms에 시작했고 첫 텍스트는 146ms에 도착하여 첫 토큰 도착 시간은 85ms였습니다. 전체 요청은 0ms부터 301ms까지여서 전체 지연은 301ms였습니다. 캐시 읽기 420개의 토큰과 캐시 생성 80개의 토큰을 분리해 저장했습니다. 실제 LangSmith 클라우드 실행 추적 업로드는 수행하지 않았습니다.

7주의할 점과 실무 메모

  • TTFT는 스트리밍의 첫 토큰 이벤트가 있을 때만 계산합니다.
  • 서버 처리 시간과 네트워크 왕복 시간이 함께 포함될 수 있으므로 측정 위치를 기록합니다.
  • LangSmith 클라우드에서는 비밀 키나 개인정보를 trace 입력에 넣지 않도록 전송 전 마스킹 정책을 적용합니다.

8정리와 다음 절

  • 실행 추적은 RAG 단계를 하위 실행으로 나눕니다.
  • 첫 토큰 도착 시간 85ms와 전체 지연 301ms는 시작점과 끝점이 다릅니다.
  • 캐시 읽기와 생성 토큰을 별도 필드로 보존했습니다.

다음 학습과 이어지는 지점 — 다음 절에서는 여러 실행 추적을 대화 단위로 묶고 비용의 p50·p95·p99를 계산합니다.
