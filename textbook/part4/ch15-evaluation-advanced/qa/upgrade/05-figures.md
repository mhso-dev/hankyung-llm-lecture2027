## 라벨에 넣지 않은 값

- **잰 초 값**: 교재 코드(`code_sha256` `78551b1f…`)의 새 커널 두 번(실행 C 16:59:41·D 16:59:52 UTC)에서 모델 요청 단계(Q002 `1.079` ↔ `0.993`, Q090 `1.523` ↔ `0.872`), 전체 걸린 초, 첫 토큰 도착 시간(`0.661` ↔ `1.275`), stream 전체 지연(`1.065` ↔ `1.417`)이 모두 달랐습니다(고치기 전 코드의 실행 A·B도 같은 모양 — 진단 §6). 어느 그림에도 초 값을 넣지 않았습니다. 두 실행에서 같았던 `0.0`(요청 글 만들기·JSON 읽기)만 `05-2`에 넣었습니다.
- **뒤바뀐 관계**: invoke와 stream 가운데 먼저 끝난 쪽, Q002와 Q090 가운데 오래 걸린 쪽이 두 실행에서 뒤바뀌었습니다. 그림에는 「새 커널 두 번에서 서로 달랐음」만 회색 상자에 적었습니다.
- **두 실행 모두 같았던 관계만 노랑에**: 가장 긴 단계 모델 요청(두 사례), 첫 토큰 도착 시간 > 전체 지연의 절반(C 0.661/1.065, D 1.275/1.417), invoke 사용량 1995·1792·42, Q090 3248·2816. **2026-09-21 마감(검토 A A-15)에서 `05-3` 회색 상자의 「캐시 입력 1792」를 뺐습니다** — 두 실행 모두 같았지만 본문이 「여러분 실행에서는 0일 수 있다」고 적은 값이라 그림 라벨에서는 빼는 쪽으로 정했습니다(다시 렌더 폭 641). **스트림 청크 수(46·43)와 stream 출력 토큰 수(45·42)는 C·D에서 달라 그림에서 뺐습니다.**
- **까닭 문장**: invoke 판정의 까닭은 C·D에서 글자까지 같았고 stream 판정의 까닭은 C에서 달랐습니다. 모델이 쓴 문장이라 그림에 넣지 않았습니다.

## 새 커널 두 번과 그림

그림은 새 커널 실행 A·B를 마친 **뒤에** 처음 렌더했습니다. 게이트(G2)에 걸린 코드 두 줄을 고쳐 C·D를 다시 실행한 뒤 라벨을 C·D 출력과 다시 대조했고, C·D에서 달라진 두 값(스트림 청크 수·stream 출력 토큰 수)을 `05-3`에서 뺐습니다. 나머지 라벨 값은 A·B·C·D 네 실행에서 모두 같았습니다.
