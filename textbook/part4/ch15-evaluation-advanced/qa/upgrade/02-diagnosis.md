## 3. 결정

### 3-1. 평가 넷을 실제 평가 모델로 부름 — **예**

- `gpt-5.4-mini`, `temperature=0`, `reasoning_effort="none"`(`nbkit.key_and_model_cells("openai:gpt-5.4-mini")`). 사례 세 건 × 평가 넷 = 12번 + 판정 한 번 보기 1번 + 값 바꿔 보기 1번 = **요청 열네 번**(임베딩 0). 준비물에 요청 수·예상 비용(미화 0.05달러 아래, 청구 금액 아님)을 적었습니다.
- **까닭**: (1) 이 챕터 주제가 평가 모델(judge)이고 02절이 판정을 처음 여는 자리입니다(handoff §01→§02 1번). (2) 규격 §3은 실제 모델 호출이 기본입니다. (3) 요청 열네 번은 실행 한 번에 약 0.015달러로 추정되어(아래 §6) 부담이 없습니다. (4) 네 평가를 같은 모델·같은 출력 모양으로 불러야 「견주는 두 칸만 다르다」를 출력으로 보일 수 있습니다.
- **낱말 겹침 근사는 없앴습니다.** 남기면 「근사」와 「모델 판정」을 견주는 셀이 둘 이상 더 필요하고 `re`·`set`을 새로 풀어야 하며(Ch 14까지 0건), 학생이 근사를 평가자 점수로 읽을 위험이 큽니다. 대신 **「글자 그대로 견주기」 한 셀**(`response == reference_answer` → 세 사례 모두 `False`)로 「같은 사실을 다른 말로 적으면 코드로 가를 수 없다 → 글을 읽는 평가 모델을 쓴다」를 보였습니다.

### 3-2. 자료 파일의 판정 글 `judge_raw` — **이번 판정과 나란히 놓되 어느 쪽이 맞다고 정하지 않음**

- 노트북 10절이 `json.loads(case["judge_raw"])`로 세 사례의 근거 충실도 점수를 읽어 이번 점수와 한 줄씩 놓습니다 → **`Q002 | 1 | 1` · `Q006 | 1 | 1` · `Q090 | 0 | 0`(세 줄 모두 같음)**.
- 이어서 두 판정의 조건을 출력으로 나란히 봅니다: 모델 이름은 같고(`gpt-5.4-mini`), 머리글 판은 `groundedness-v1.0.0` ↔ `rag-judge-v1.0.0`, 이번에 넣은 칸 `['답', '근거 문서']`. 본문에는 자료 파일 판정이 **질문·근거·응답 세 칸**을 넣은 머리글로, **추론 설정 없이**(`prepare_runs.py`의 `init_chat_model(..., temperature=0)`) 받은 글이라는 사실을 적었습니다. 그래서 「점수가 같아도 같은 판정을 두 번 받았다고 말할 수 없다」로 한정했습니다(b6·b7·b8·복습 4).
- `prepare_runs.py`는 학생 묶음에서 빠지는 파일이라 학생은 옛 머리글 글을 볼 수 없습니다 → 본문에 사실로만 적고 노트북 코드는 그 파일을 읽지 않습니다(강사 확인 5번).

### 3-3. 01절 인계 「강사 확인 2번」(`Q090` 판정 0점) 해석

- 이번 판정(새 커널 두 번 모두): `Q090`은 **정답 일치도 1 · 답변 관련성 0 · 근거 충실도 0 · 검색 관련성 0**. 정답 일치도 까닭은 두 글이 같은 뜻(입회인 정보가 없어 확인할 수 없음)이라고 적었습니다. 근거 충실도·검색 관련성 까닭은 **문서에 입회인 언급이 없다**는 점을, 답변 관련성 까닭은 **답이 입회인을 직접 대지 않았다**는 점을 짚었습니다(문장은 두 실행에서 조금 다름).
- 자료 파일의 판정(2026-09-10)도 0점이었고 까닭은 「입회인에 대한 별도 기재가 없어 알 수 없습니다」였습니다.
- 본문에 적은 해석(한 번 본 결과로 한정): 「판정 기준 문장에는 모른다고 답한 경우를 어떻게 셀지 적혀 있지 않습니다」(기준 문장 글에서 확인한 사실) · 「이 0점이 기준 문장 때문인지는 이번에 확인하지 않았습니다」 · 「어느 판정이 맞는지도 이 절에서 정하지 않습니다」 · b7 「`Q090`의 근거 충실도 0점을 『답이 틀렸다』로 읽지 않습니다」. 「모델이 매번 0을 준다」로 일반화하지 않았습니다.
- 검색 관련성 0은 `H01`이 **정답 문서**인데도 나왔습니다. 모델이 「질문과 관련된 내용」을 「질문의 답이 있는 내용」으로 읽은 것으로 보이나(까닭 글), 원인은 확인하지 않았고 본문에도 적지 않았습니다(강사 확인 7번, 03절 인계).

### 3-4. 판정 머리글과 출력 모양 — 이 절에서 처음 정함, 판 이름 `rag-judge-v1.0.0`

- 두 칸 짝 `evaluator_pairs`(평가 이름 → {판정 요청 글에 적을 한국어 이름: 사례 칸 이름}) · 기준 문장 `judge_rules`(넷 모두 「…면 1, 아니면 0을 판정하세요.」) · 출력 모양 `output_rule` = `JSON만 출력하세요: {"score": 0 또는 1, "reason": "한 문장"}.`(자료 파일 판정 글과 같은 모양) · `judge_heads` = 기준 문장 + 줄바꿈 + 출력 모양 · `judge_version = "rag-judge-v1.0.0"`.
- 기준 문장은 LangSmith RAG 평가 안내(2026-09-21 확인 — Correctness: Response vs reference answer / Relevance: Response vs input / Groundedness: Response vs retrieved docs / Retrieval relevance: Retrieved docs vs input)의 네 평가를 한국어 한 문장씩으로 줄였습니다. 그 안내의 정답 일치도 예시는 QUESTION도 함께 넣지만 이 절은 견주는 두 칸만 넣었습니다(b7). 근거 충실도 문장은 `groundedness-v1.0.0` 기준 문장과 「응답 → 답」만 다릅니다.
- **기준 문장은 판정을 보기 전에 정했고, 판정을 본 뒤 고치지 않았습니다**(b7).
- 새 함수 셋(노트북에 둠, 전역 이름 없이 인자만 받음 — 03절이 쓰면 그대로 도구 파일로 옮길 수 있음): `build_judge_prompt(judge_head, pair, case)` · `judge_once(judge_model, prompt_text)` · `judge_case(judge_model, heads, pairs, case)`.
