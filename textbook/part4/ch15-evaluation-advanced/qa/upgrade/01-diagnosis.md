## 4. 설계 — 검색 쪽 실패와 답 쪽 실패를 출력으로 가름

1. Ch 12 개발 기록(36줄)·시험 기록(15문항)의 칸 이름을 출력하고 답 칸(`response`·`answer`)이 있는 줄을 셉니다 → **둘 다 0줄**. 그래서 두 기록의 실패는 모두 **검색 쪽 실패**.
2. 기준을 먼저 적습니다: 자르는 자리 `cutoff = 1`. Ch 11 05절 `error_name(gold_rank, cutoff)`가 「앞자리 안」이 아닌 줄이 실패 로그에 들어갑니다.
3. 한 줄 예(개발 첫 설정 줄의 `Q005`)로 `unique_doc_ids` → `find_gold_rank` → `error_name` 차례를 먼저 보입니다.
4. 개발 기록 540줄 → **26줄**(모두 `Q005`, 고르지 않은 설정에서만 — 고른 설정 줄은 0줄), 시험 기록 15줄 → **1줄**(`Q090`). 실패 로그 **27줄**, 정답 자리별 `{2: 17, 3: 10}`.
5. `Q090`의 기록된 nDCG `0.6309` = Ch 11 04절 `rank_weight(2)` `0.6309`(정답 문서가 하나라 가장 좋은 무게 합이 1).
6. 자료 파일의 평가 사례 세 건 → 칸 14개, 기준 답 출처 `교육용 작성자 기준`, 답 글 셋(파일에서 읽기만).
7. 세 사례마다 고른 설정의 검색 기록(개발 15 + 시험 15 = 30)에서 검색 표시를 뽑고, 답이 받은 문서와 견줍니다 → 평가 대상 표: `Q002 | False | True | True`, `Q006 | False | True | True`, `Q090 | True | True | True`.
8. 실패 로그와 사례를 짝지어 `['Q090']`(두 쪽) / `['Q005']`(실패 로그에만 — 답이 없어 답 쪽 평가 대상이 될 수 없음).
9. 값 바꿔 보기: `wide_cutoff = 5`(Ch 11 05절 값) → 실패 로그 **0줄**, 세 사례 모두 `앞자리 안`.
