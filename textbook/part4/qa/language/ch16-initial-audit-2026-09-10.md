## 정독 소견

입력·출력 검증, 개인정보 마스킹, 대화 기록 정리, 호출 제한, 재시도와 폴백, 문서 프롬프트 인젝션을 한 챕터에서 연결한 순서는 분명합니다. 실제 출력도 성공 사례만 보여 주지 않고 거부와 미관찰 결과를 남깁니다. 다만 여섯 절의 비유·도식·확인 문장·요약·참고 자료가 동일하여 각 절의 개념과 실험 결과를 설명하지 못합니다. 03·05·06절에는 저장된 실행 출력과 본문 해석이 어긋나는 부분도 있습니다.

## 작성 담당자에게 전달한 수정 제안

### 챕터 전체

1. 여섯 절의 `쉬운 예`가 모두 공항 보안 검색입니다. 입력 형식과 출처 허용 목록, PII 마스킹, 트리밍과 요약, 계획 비용 예약, 재시도와 폴백, 신뢰 수준이 다른 문서 입력에 각각 맞는 예로 나눕니다.
2. 여섯 SVG가 `입력 → 절 제목 → 검증 결과 → 반환 또는 중단`의 같은 구조입니다. 실제 처리 분기와 관찰값을 보여 주도록 절별로 바꿉니다. 특히 03절은 원본·트리밍·요약 결합 비교, 04절은 계획 비용 예약의 통과·거부, 05절은 두 폴백 경로, 06절은 완화 전후와 통합 경로를 구분해야 합니다.
3. `확인할 점`이 모든 절에서 통과·거부 조건, 호출 횟수, 원문 개인정보를 함께 지시합니다. 출력에서 실제로 확인할 값으로 좁힙니다. 예를 들어 03절은 메시지 수·문자 수·보존된 선호, 04절은 예약 누적액·거부 시점·반환 사용량, 06절은 전후 공격 표지·출처 여부·문서 검사 기록을 확인합니다.
4. `정리와 다음 절`의 세 문장이 여섯 절에서 같습니다. 각 절의 개념, 실제 관찰, 한계를 세 문장으로 요약합니다.
5. 참고 자료 네 건도 여섯 절에서 같습니다. PII, 대화 기록 관리, 비용과 사용량, 재시도·멱등성, 프롬프트 인젝션처럼 실제 절의 주장에 맞는 공식 자료를 연결합니다.
6. 복습 해설의 `4절 핵심 개념과 6절 결과 해석`은 챕터의 네 번째·여섯 번째 절로 읽힐 수 있습니다. `이 페이지의 핵심 개념과 실험 결과 해석`처럼 현재 페이지 안의 블록을 가리킵니다.
7. `labs/part4/ch16-guardrails/README.md`가 없습니다. 검토 요청 범위에 README가 포함되어 있으므로 최종 감사 전에 생성 여부와 학생용 실행 안내를 확인해야 합니다.

### 절별 정의·표현·실행 해석

| 위치 | 현재 설명 | 제안과 이유 |
|---|---|---|
| 01절 배우는 이유 | `입력의 모양`, `지어낸 출처` | `입력 형식`, `검색 결과에 없는 출처`로 씁니다. 기술 동작을 구어 비유 대신 실제 검사 대상으로 설명합니다. |
| 02절 복습 해설 | `솔트를 넣은 해시` | 이 절에서 실제로 솔트를 만드는 구현이 없으면 `원문을 복원하기 어려운 식별값`처럼 범위를 맞추거나 관련 구현을 명시합니다. 05절의 고정 문자열도 무작위 솔트와 구분해야 합니다. |
| 03절 학습 목표 | `문자 수 절감` | 저장 출력은 원본 6개/168자, 트리밍 3개/60자, 요약 결합 4개/261자입니다. 이번 실행에서는 요약 결합의 문자 수가 늘었으므로 `트리밍과 요약 결합 뒤의 문자 수와 정보 보존을 비교`로 바꿉니다. |
| 03절 정의 | `요약 압축은 ... 더 짧은 새 문장` | 이 실행에서 더 짧아지지 않았습니다. `오래된 대화를 새 요약 메시지로 바꾸는 처리`로 정의하고, 압축 여부는 출력에서 따로 판정합니다. |
| 03절 결과 해석 | `같은 압축률` | 이번 요약 결합은 압축되지 않았습니다. `트리밍은 문자 수를 줄였지만 요약 결합은 261자로 늘었고, 두 문장 선호는 남았다`고 실제 수치와 관찰을 밝힙니다. |
| 03절 노트북 | `문자 수 감소와 ... 함께 봅니다` | `문자 수 변화와 ... 함께 확인합니다`로 씁니다. 감소를 전제로 두지 않습니다. |
| 04절 정의와 해설 | `비용 상한`, `예산에서 먼저 차감`, `비용이 발생하기 전에 중단` | 이 예제는 실제 청구액을 차단하는 기능이 아니라 계획 비용의 누적 한도를 검사합니다. `계획 비용 한도`, `계획 비용의 남은 범위에서 예약`, `계획한 한도를 넘는 호출을 요청 전에 거부`로 의미를 고정합니다. 실제 청구액은 별도 사용량·단가로 확인한다고 함께 둡니다. |
| 05절 결과 해석 | 두 시간 초과 뒤 실제 모델 안내 | 첫 실험은 합성 시간 초과 두 번 뒤 고정 문자열 `폴백 답`을 반환하고 총 시도 횟수는 3입니다. 별도 영구 실패 실험은 기본 경로 한 번 뒤 실제 모델 폴백을 호출하고 총 시도 횟수는 2입니다. 두 실험을 분리해 서술합니다. |
| 05절 결과 해석 | `솔트를 포함한 해시` | 코드는 고정 문자열 `ch16-session`과 마스킹한 질문을 합쳐 SHA-256 앞 12자를 씁니다. 무작위 솔트나 비밀 키를 사용한 것처럼 읽히지 않도록 `고정 구분 문자열을 더해 만든 12자리 해시`로 설명하거나 구현을 바꿉니다. |
| 05절 노트북 | `성공·폴백·영구 실패` | 저장 출력은 고정 답 폴백과 실제 모델 폴백을 관찰했습니다. `영구 실패`를 최종 실패로 읽지 않도록 `기본 경로의 영구 오류와 폴백 결과`라고 씁니다. |
| 06절 배우는 이유 | `문서 저장소와 수집 경로가 새로운 신뢰 경계` | 신뢰 경계는 장소나 시스템 이름 자체가 아니라 신뢰 수준이 다른 문서가 모델 입력으로 들어오는 지점입니다. 데이터가 경계를 넘는 행동으로 설명합니다. |
| 06절 정의 | `지시 우선순위를 바꾸게 하는 입력` | `모델이 데이터로 다뤄야 할 문장을 지시로 해석하게 만드는 입력`처럼 관찰 가능한 동작으로 풉니다. 성공한 공격만 프롬프트 인젝션인 것처럼 단정하지 않습니다. |
| 06절 결과 해석 | 완화 전후의 일반 설명 | 저장 출력은 완화 전 공격 표지 `[]`, 완화 후 `[]`로 둘 다 `영향 미관찰`입니다. 완화로 위험이 줄었다는 효과는 관찰하지 못했습니다. 전후 결과를 그대로 쓰고 한 번의 미관찰로 방어 효과나 공격 불가능성을 결론 내리지 않습니다. |
| 06절 완화 후 | XML 모양의 문서 구역 분리 | XML 태그는 모델에 데이터 구역을 알리는 구분자이며 강제로 적용되는 보안 경계가 아닙니다. `분리했다`는 구현 사실과 `방어가 됐다`는 효과 판정을 구분합니다. |
| 06절 문서 검사 | 의심 패턴 기록 | 실제 정규식은 `이전 지시/명령` 뒤 12자 안의 `무시/따르지`, 또는 `시스템 프롬프트/지시` 두 유형만 찾습니다. 이 제한된 범위와 오탐·누락 가능성을 본문에 적습니다. |
| 06절 통합 결과 | 공격 실험과 통합 경로가 한 흐름처럼 보임 | 완화 후 공격 문서 답에는 출처가 없었습니다. 별도 안전 문서 통합 경로에서 `[E01 p.1]`과 PII 미포함을 확인했습니다. 두 결과를 구분해 해석합니다. |

## 보존할 의미

- 04절의 예산은 실제 청구 한도가 아니라 누적 계획 비용의 한도입니다.
- 06절의 프롬프트 공격 영향은 완화 전후 모두 관찰되지 않았습니다.
- 06절의 정규식 탐지는 두 유형의 제한된 문자열 패턴에만 적용됩니다.
- 출처 허용 목록 통과는 문장 전체의 사실성이나 근거 충실도를 증명하지 않습니다.
- 수치, 실행 횟수, 모델 응답, 가능성과 한정어는 실행 출력과 맞춘 뒤 그대로 보존합니다.
