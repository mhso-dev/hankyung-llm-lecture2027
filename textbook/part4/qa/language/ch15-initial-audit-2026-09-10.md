## 진단 요약

교육용 작성자 라벨과 사람 라벨, 고정 로컬 추적과 실제 API 추적, Batch 입력 검증과 실제 제출 완료를 구분한 한정은 정확합니다. 저장 출력과 본문의 주요 수치도 대체로 맞습니다. 다만 여덟 절의 비유·요약·참고 자료가 같고, 각 절의 실행 예제 문단이 실험 결과 해석에서 그대로 반복됩니다. 노트북 마크다운도 제목을 제외하면 공통 골격만 있어 셀의 학습 행동을 설명하지 못합니다.

## 전달한 수정 제안

### 공통 구조

- 같은 병원 비유를 평가 대상, 평가자, 편향, 사람 라벨, 실행 추적, 비용 분포, 회귀, Batch의 서로 다른 상황으로 바꿉니다.
- 실행 예제에는 수행 단계와 출력에서 확인할 값을 두고, 실험 결과 해석에는 실제 수치의 뜻과 일반화 한계를 둡니다.
- 모든 절의 같은 3줄 정리를 각 절의 정의·관찰·한계로 바꿉니다.
- 공통 참고 자료 세 건을 절별 공식 자료로 바꿉니다.
- `실행하지 않은 cloud 작업, 실제 사람 검토, 실제 청구`라는 공통 문장은 `클라우드`로 쓰고 각 절에서 실제로 확인하지 않은 항목만 남깁니다.
- 노트북 공통 소제목 아래에 읽는 자료, 계산, 다음 출력에서 확인할 값을 적습니다.

### 용어와 의미

- 처음 등장할 때 `정답 일치도(Correctness)`, `답변 관련성(Relevance)`, `근거 충실도(Groundedness)`, `검색 관련성(Retrieval relevance)`로 풉니다.
- `평가 모델(LLM judge)`, `실행 추적(trace)`, `하위 실행(child run)`, `첫 토큰 도착 시간(TTFT)`, `전체 지연(total latency)`도 한국어 뜻을 먼저 둡니다.
- `부분적인 근거성`은 `응답의 일부 주장만 문서로 확인되는 경우`로 구체화합니다.
- `북극성 지표`는 `주요 관리 지표`처럼 실제 용도를 드러냅니다.
- 07절의 회귀 스위트는 품질 저하를 자동으로 없애는 기능이 아니라 배포 전에 발견하는 검사입니다. `잘못된 회귀 판정 코드`는 `평균만 보는 불충분한 통과 기준`으로 고쳐 실험 의미를 보존합니다.
