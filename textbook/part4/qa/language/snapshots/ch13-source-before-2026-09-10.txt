
===== textbook/part4/ch13-langgraph-basics/_src/01-StateGraph와-노드-엣지.html =====
1
학습 목표
StateGraph의 상태, 노드, 엣지를 코드에서 구분할 수 있습니다.
START와 END를 포함한 순차 그래프를 컴파일하고 실행할 수 있습니다.
실행 흔적과 Mermaid 문자열을 읽어 실제 실행 순서를 확인할 수 있습니다.
2
이 내용을 배우는 이유
Part 3에서 만든 RAG는 문서 읽기, 검색, 병합, 재정렬, 생성 함수를 차례로 호출했습니다. 단계가 두세 개일 때는 함수 나열도 읽을 수 있습니다. 조건에 따라 건너뛰거나 되돌아가는 단계가 생기면 호출 순서가 여러 곳에 흩어집니다. LangGraph는 상태와 실행 순서를 하나의 그래프로 선언해 이 문제를 다룹니다.
이번 절의 질문은 “파이썬 함수 나열을 상태 그래프로 옮기면 실행 순서를 어떻게 읽을 수 있을까요?”입니다. 노트북 출력과 그래프 그림을 함께 읽어 답합니다.
3
앞에서 배운 내용
Ch12의 통합 실습은 질문을 받고 검색 결과와 출처를 만든 뒤 답변을 생성했습니다. 이번 절은 그 처리 단계에서 모델 호출을 제외하고, 질문 정리와 검색어 작성이라는 두 함수를 그래프에 배치합니다. 앞 노트북의 변수에는 의존하지 않습니다.
각 노트북은 Python 3.12 새 커널에서 독립 실행되며 이전 절의 메모리나 개인 경로를 사용하지 않습니다.
4
핵심 개념
쉬운 예
지하철 노선도에서 역은 작업이고 선은 이동 순서입니다.
정의
지하철 노선도에서 역은 작업이고 선은 이동 순서입니다. 승객이 들고 가는 가방은 각 역에서 읽고 고치는 데이터입니다. LangGraph의 상태(State)는 이 공유 데이터, 노드(node)는 상태를 읽어 일부 값을 반환하는 함수, 엣지(edge)는 다음 노드를 정하는 연결입니다. StateGraph는 이 세 요소를 모아 실행 가능한 그래프를 만드는 빌더입니다. START는 입력이 들어오는 가상 시작점이고 END는 더 실행할 노드가 없음을 나타내는 가상 끝점입니다. compile()은 선언한 노드 이름과 연결을 확인하고 invoke()할 수 있는 실행 객체를 반환합니다.
도식 읽기
{{svg:01-흐름}}
도식은 왼쪽의 입력에서 오른쪽의 출력으로 읽습니다. 파란 상자는 노드, 회색 화살표는 엣지, 노란 상자는 상태에서 관찰할 값을 뜻합니다. 실선은 코드가 선언한 이동이고 갈라지는 화살표는 입력에 따라 선택되는 경로 또는 여러 작업을 나타냅니다. 아래 노트북의 Mermaid 출력은 같은 노드 이름을 사용하므로 정적 도식과 실제 그래프 구조를 대조할 수 있습니다.
5
실행 예제
첫 셀은 LangGraph 1.2.11과 LangChain 1.4.0을 설치하고 실제 설치 버전을 출력합니다. 이어지는 셀은 상태, 노드, 엣지를 정의하고 그래프를 컴파일합니다. 마지막 출력에서는 상태값과 실행 순서를 확인합니다. 코드 셀은 한 가지 학습 행동만 담고 25줄을 넘지 않습니다.
확인할 점
— 출력에 나타난 상태 키, 선택한 경로, 실행 흔적을 코드의 노드 반환값과 대조합니다. Mermaid 문자열에 등록한 노드 이름과 START·END 연결이 나타나는지도 확인합니다.
6
실험 결과 해석
실행 결과의 trace에는 normalize와 make_query가 차례로 남습니다. Mermaid 출력에서도 START에서 normalize, make_query, END로 이어지는 화살표가 나타납니다. 노드를 등록한 순서가 실행 순서를 정하는 것이 아니라 add_edge로 선언한 연결이 실행 순서를 정합니다.
이 관찰은 노트북에 적은 입력과 LangGraph 1.2.11에서 얻은 결과입니다. 입력 데이터, 임계값, 병렬 작업 수, 모델 응답이 달라지면 최종 상태도 달라질 수 있습니다. 실행 성공은 구조와 데이터 전달을 확인하지만 서비스 전체의 검색 품질이나 답변 품질을 보장하지 않습니다.
7
주의할 점과 실무 메모
노드는 전체 상태를 복사해 반환하지 않고 바꿀 키만 반환할 수 있습니다.
compile() 전의 객체는 설계도이며 compile() 결과가 실행 객체입니다.
이 절의 그래프는 모델이 경로를 정하지 않습니다. 코드로 적은 고정 엣지가 경로를 정합니다.
8
정리와 다음 절
상태는 노드 사이에서 공유하는 데이터이고 노드는 필요한 갱신만 반환합니다.
엣지와 제어 객체는 다음 실행 위치를 코드로 표현합니다.
실제 출력과 Mermaid 구조를 함께 읽어 선언한 흐름과 실행 결과가 맞는지 확인했습니다.
다음 학습과 이어지는 지점
— 다음 절에서는 각 노드가 반환한 일부 값이 기존 상태에 어떻게 반영되는지 확인합니다.
9

노드는 상태를 읽고 갱신을 반환하는 함수이며, 엣지는 다음에 실행할 노드를 정하는 연결입니다.

3. 이해 확인

1
학습 목표
상태 스키마가 노드의 공통 입력과 출력을 어떻게 제한하는지 설명할 수 있습니다.

2
이 내용을 배우는 이유
검색 단계는 documents를 만들고 생성 단계는 answer를 만듭니다. 모든 함수가 전체 딕셔너리를 다시 만들면 빠진 키나 오래된 값을 섞기 쉽습니다. LangGraph의 노드는 자신이 맡은 키의 갱신값만 반환합니다. 같은 키에 여러 갱신이 모일 때는 리듀서가 합치는 규칙을 담당합니다.
이번 절의 질문은 “노드가 같은 상태 키를 여러 번 반환하면 값은 덮어쓸까요, 누적할까요?”입니다. 노트북 출력과 그래프 그림을 함께 읽어 답합니다.
3
앞에서 배운 내용
앞 절에서 StateGraph, 노드, 엣지, compile(), invoke()를 사용했습니다. 이번 절도 같은 순차 그래프를 사용하지만 상태 키별 갱신 규칙에 초점을 맞춥니다.
각 노트북은 Python 3.12 새 커널에서 독립 실행되며 이전 절의 메모리나 개인 경로를 사용하지 않습니다.
4
핵심 개념
쉬운 예
공용 화이트보드의 칸마다 쓰기 규칙이 다르다고 생각해 봅니다.
정의
공용 화이트보드의 칸마다 쓰기 규칙이 다르다고 생각해 봅니다. 현재 검색어 칸은 새 값으로 교체하지만 처리 기록 칸은 새 항목을 뒤에 붙입니다. TypedDict는 상태에 어떤 키와 값 형식이 있는지 표현합니다. 리듀서(reducer)는 한 상태 키의 기존 값과 새 갱신값을 받아 최종 값을 만드는 함수입니다. Annotated[list[str], operator.add]는 list 값을 더하므로 각 노드가 반환한 목록이 누적됩니다. 리듀서가 없는 키는 기본적으로 새 값이 기존 값을 덮어씁니다.

===== textbook/part4/ch13-langgraph-basics/_src/03-조건부-엣지.html =====
1
학습 목표
조건 함수와 작업 노드의 역할을 구분할 수 있습니다.
add_conditional_edges로 코드가 정한 분기를 구성할 수 있습니다.
같은 그래프에 두 입력을 넣어 서로 다른 경로를 확인할 수 있습니다.
2
이 내용을 배우는 이유
RAG에서는 검색 결과가 충분할 때 답을 만들고 부족할 때 추가 자료를 요청해야 합니다. if문을 호출 코드 여러 곳에 두면 경로를 한눈에 보기 어렵습니다. 조건부 엣지는 상태를 읽는 조건 함수를 그래프의 연결 규칙으로 등록합니다.
이번 절의 질문은 “검색 점수가 기준을 넘는지에 따라 생성과 확인 요청 중 어느 노드로 이동하게 할까요?”입니다. 노트북 출력과 그래프 그림을 함께 읽어 답합니다.
3
앞에서 배운 내용
Ch11에서 검색 품질을 점수로 측정했고 Ch12에서 후보를 재정렬했습니다. 이번 절은 검색을 다시 구현하지 않고 0과 1 사이의 rerank_score가 이미 상태에 있다고 가정합니다. 경로 판단은 모델이 아니라 코드의 임계값 비교가 담당합니다.
각 노트북은 Python 3.12 새 커널에서 독립 실행되며 이전 절의 메모리나 개인 경로를 사용하지 않습니다.
4
핵심 개념
쉬운 예
택배 분류대는 송장 값을 읽고 상자를 서로 다른 컨베이어로 보냅니다.
정의
택배 분류대는 송장 값을 읽고 상자를 서로 다른 컨베이어로 보냅니다. 조건부 엣지(conditional edge)는 한 노드가 끝난 뒤 상태를 읽어 다음 노드 이름을 반환하는 연결입니다. add_conditional_edges(source, path, path_map)는 source 뒤에서 path 함수를 호출하고 그 반환값을 실제 노드 이름으로 대응시킵니다. Literal 반환형이나 path_map을 적으면 시각화에도 가능한 목적지가 분명하게 표시됩니다.
