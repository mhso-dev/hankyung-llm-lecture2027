1
학습 목표
시스템 메시지와 최근 대화만 남기는 트리밍을 구현할 수 있습니다.

RAG는 사용자가 직접 쓰지 않은 문서도 모델 입력에 넣습니다. 공격자가 문서에 명령문을 숨기면 검색은 관련 문서를 정상적으로 찾았는데 생성 단계가 그 문장을 지시로 해석할 수 있습니다. 이를 간접 프롬프트 인젝션(indirect prompt injection)이라고 합니다. 문서 저장소와 수집 경로가 새로운 신뢰 경계가 됩니다.
3
앞에서 배운 내용
Ch 9의 첫 RAG에서 문서 속 지시문 사례를 남겼고 Ch 12에서 실제 검색 결과의 문서·쪽·청크 ID를 전달했습니다. 이 절은 같은 메타데이터 모양의 로컬 학습 문서를 사용합니다. 외부 공격 사이트나 실제 개인정보에는 접근하지 않습니다.
4
핵심 개념
쉬운 예
공항 보안 검색은 한 번의 검사로 끝나지 않습니다. 탑승권 형식, 수하물 내용, 출입 권한을 서로 다른 단계에서 확인합니다. 모델 기반 애플리케이션도 입력, 모델 호출, 출력, 기록 지점마다 다른 검사가 필요합니다.
정의
프롬프트 인젝션(prompt injection)은 데이터로 처리해야 할 문장이 모델의 지시 우선순위를 바꾸게 하는 입력입니다. 간접 공격은 검색 문서, 웹 페이지, 이메일처럼 외부 자료를 통해 들어옵니다. 신뢰 경계(trust boundary)는 서로 다른 신뢰 수준의 데이터가 만나는 지점입니다. 완화(mitigation)는 위험이나 영향을 줄이는 조치이며 완전 방어를 뜻하지 않습니다.
도식 읽기
{{svg:06-흐름}}
도식은 왼쪽 입력에서 오른쪽 반환까지 읽습니다. 초록은 검증을 통과한 데이터, 파랑은 직접 구현한 처리, 노랑은 관찰 기록, 빨강은 중단 조건입니다. 화살표는 데이터가 전달되는 방향입니다.

6
실험 결과 해석
완화 전에는 질문과 공격 문서를 한 문자열로 결합해 실제 모델 응답의 공격 표지를 확인했습니다. 실행 결과가 표지를 포함하면 ‘영향 관찰’, 포함하지 않으면 ‘영향 미관찰’로 그대로 기록합니다. 완화 후에는 시스템 규칙과 XML 모양의 문서 구역을 분리하고 의심 패턴을 기록했습니다. 이 한 번의 성공이나 실패는 다른 표현과 모델에서도 같은 결과를 보장하지 않습니다.
7
주의할 점과 실무 메모
프롬프트 분리는 한 계층입니다. 입력 필터, 출력 허용 목록, 최소 권한, 사람 승인, 반복 공격 검사를 함께 둡니다.
문서가 의심스럽다는 이유만으로 사실 문장까지 자동 삭제하면 답 품질이 달라질 수 있습니다. 격리·검토·출처 표시 정책을 정합니다.
이 챕터에서는 도구와 에이전트를 연결하지 않아 공격이 외부 행동으로 이어지는 경로를 만들지 않습니다.
실제 모델 호출은 절마다 미화 1달러 미만이 되도록 짧은 입력과 출력을 사용했습니다. 정확한 청구액은 제공자 사용량 화면과 해당 실행 시점 가격표를 확인해야 합니다.
8
정리와 다음 절
가드레일은 모델 앞뒤의 명시적인 파이썬 검사입니다.
통과 결과는 정한 범위의 조건만 확인하며 모델 답 전체의 안전성을 보장하지 않습니다.
거부, 축소, 폴백과 같은 실패 경로도 정상 반환처럼 테스트하고 기록합니다.
