# Part 4 실습 시작하기

Part 4는 Ch 13 → Ch 14 → Ch 15 → Ch 16 순서로 학습합니다. Part 3의 검색·생성 흐름을 그래프로 옮긴 뒤 검색 패턴을 비교하고, 답변 평가와 처리 제한을 추가합니다.

압축을 푼 `part4-practice` 폴더 전체를 보관합니다. Part 4 노트북은 `labs/part4`의 챕터별 `notebooks` 폴더에 있습니다. 앞에서 만든 자료를 읽는 실습을 위해 `labs/part3`과 `labs/data`도 함께 제공합니다. 노트북만 따로 옮기면 자료 경로를 찾지 못할 수 있습니다. 제공 PDF는 가상 기관을 다룬 학습용 문서입니다.

Ch 1에서 준비한 uv와 VS Code를 사용합니다. 지금 학습할 챕터 폴더를 열고 그 폴더의 터미널에서 `uv sync --locked`를 실행합니다. 예를 들어 Ch 13은 `labs/part4/ch13-langgraph-basics`입니다. Python·Jupyter 확장을 준비한 VS Code에서 노트북을 연 뒤 Select Kernel → Python Environments에서 그 챕터의 `.venv`를 선택합니다. `uv run python --version`으로 Python 3.12인지 확인합니다. 다른 챕터에서도 해당 챕터의 환경을 준비하고 선택합니다.

묶음 맨 위의 `env.example`을 `.env`라는 이름으로 복사하고 `OPENAI_API_KEY=` 오른쪽에 본인의 키를 저장합니다. 키를 코드·출력·공유 문서에 붙여 넣지 않습니다. 각 절의 준비 셀은 작업 폴더와 상위 폴더에서 `.env`를 찾습니다. 모델 호출을 포함한 실습은 키와 인터넷 연결이 필요하며 사용량에 따른 비용이 발생합니다. LangSmith나 Batch API 등 외부 서비스를 실제로 호출했는지는 해당 절의 안내를 확인합니다.

각 절은 새 커널에서 첫 셀부터 `Shift+Enter`로 실행합니다. 설치 셀이 마무리될 때까지 기다린 뒤 설명에 나온 문서 ID·점수·답변·처리 순서를 실제 출력과 비교합니다. 기본 실행이 성공한 다음 안내에서 지정한 입력값 하나를 바꾸어 결과를 확인합니다. 수정 전·후(Before/After)를 비교하는 절은 준비 셀과 기본 실행 다음에 두 단계를 순서대로 실행합니다.

`ModuleNotFoundError`가 나오면 해당 챕터에서 잠금 파일에 지정된 패키지 환경을 준비했는지와 커널 선택을 확인합니다. `NameError`는 앞 셀을 실행해 필요한 변수를 만들었는지 확인합니다. `FileNotFoundError`가 나오면 묶음의 폴더 구조와 제공 파일을 확인합니다. 상태를 파악하기 어렵다면 커널을 다시 시작하고 처음부터 실행합니다. API 호출 중 오류가 나면 안내된 재시도 범위와 호출 한도를 확인하고 무제한으로 재실행하지 않습니다.

`labs/part4/continuity-guide.md`는 앞 챕터의 자료와 Part 4 노트북이 만든 결과를 연결하는 안내입니다. 제공 실행 로그는 교재 검증 당시의 기록입니다. 다시 실행해 얻은 값은 별도로 구분하며 저장된 기록을 이번 실행의 결과로 표시하지 않습니다. 검색 실패와 생성 답변의 오류, 사람 라벨과 교육용 기준 라벨도 구분합니다.

`manifest.json`에는 공개 파일별 SHA-256 해시가 기록되어 있습니다. 해시는 파일 내용이 같은지 대조할 때 사용하는 값입니다. 묶음에는 API 키와 가상환경 자체가 들어 있지 않습니다. 패키지 설치·로컬 모델 다운로드·API 호출은 실행 환경에서 수행합니다. 한정된 질문에서 관찰한 성능이나 지시문 방어 결과가 실제 서비스 전체에서도 같다고 보지 않습니다.
