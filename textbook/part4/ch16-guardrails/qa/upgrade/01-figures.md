## 칸 순서 확인 (PNG를 직접 열어 본 결과)

- `01-1`은 위에서 아래로 초록 질문 → 파랑 입력 검사 → 보라 모델 → 노랑 출처 표시 → 파랑 출력 검사 → 노랑 내보낸 답입니다. 노랑 출처 표시 오른쪽에 초록 허용 목록이 나란히 있고 둘이 같은 파랑 출력 검사로 들어갑니다.
- `01-2`는 위 초록 자료 파일 → 초록 이번 검색 결과에서 갈래가 둘로 나뉩니다. 왼쪽은 파랑 허용 목록 만들기 → 노랑 허용 목록, 오른쪽은 보라 모델 요청 → 노랑 모델 답입니다.
- `01-3`은 왼쪽 칸 Before(초록 → **빨강** → **빨강**), 오른쪽 칸 After(초록 → 노랑 → 노랑), 아래 회색 상자(두 칸에 넣은 답 셋이 같음)입니다. 빨강 두 상자는 모두 Before 결함 결과입니다. 칸 안 상자가 모두 **답** 셋이라 오른쪽 칸 제목을 「After · 입력과 출력을 검사」에서 **「After · 출력 검사를 붙인 흐름」**으로 고쳐 다시 렌더했습니다(09:06 UTC, 원본 폭 573 그대로, PNG를 직접 열어 확인).
- `01-4`는 위 초록 합성 답에서 갈래가 둘로 나뉘고, 칸마다 파랑 허용 목록 → 노랑 대조 결과입니다. 왼쪽이 이번 검색 결과로 만든 목록, 오른쪽이 손으로 넓힌 목록입니다.

## 라벨에 넣지 않은 값

- **흔들린 값**: 교재 코드(`code_sha256` `3538ba12…`)의 새 커널 두 번(실행 C 09:06:27·D 09:06:44 UTC)에서 코드 셀 27개 가운데 24개가 같았고, 다른 셋(5·6·9절의 모델 답이 들어간 셀)은 **문장 끝 마침표 하나**만 달랐습니다. 그 앞 코드(`33feddc6…`, 실행 A·B)도 같은 모양이었습니다. 모델 답 문장과 그 글자 수는 어느 그림에도 넣지 않았습니다.
- **두 실행 모두 같았던 값만 라벨에**: 허용 목록 `['[E01 p.1]']`, 막은 답 수 0과 둘, 통과한 답 하나, 질문 글자 수 상한 500, 문서 ID `E01`·`E99`·`E02`.
- **개수는 한글로**: 「문서 둘」·「표시 하나」·「답 셋」·「막은 답 둘」·「통과한 답 하나」. 숫자를 그대로 쓴 라벨은 `500`과 문서 ID뿐입니다.

## 라벨 숫자 대조 (G7)

`figure_numbers()`가 세는 대상은 `500`·`5.4`·`01`·`99`·`02`이고 모두 노트북 출력에 그대로 있습니다(게이트 G7 0건). 한 자리 쪽 번호(1)는 세지 않는 값이며 출력과 같습니다.

## 새 커널 두 번과 그림

그림은 새 커널 실행 A·B를 마친 **뒤에** 처음 렌더했습니다. 코드 두 곳(`repeat_count`·손 확인 셀의 `max_chars`)을 고쳐 다시 돌린 실행 C·D에서도 그림 라벨에 넣은 값(허용 목록·막은 수·통과 수·상한 500·문서 ID)은 모두 같았습니다. 두 실행에서 달랐던 셀 셋의 값은 그림에 넣지 않았습니다.

## 설명 문장에서 고친 말

- `01-2`·`01-4`는 조건에 따라 한쪽만 가는 갈래가 아니라 **두 쪽을 모두 실행한 흐름**이라 실선으로 두고, alt·도식 읽기의 「갈래가 둘로 나뉩니다」를 「화살표가 둘로 나뉩니다」로 고쳤습니다(점선은 갈래·하지 않은 일에만, Ch 15 선례).
- `01-1`은 검사 둘을 붙인 뒤의 차례를 보인 구조 도식입니다. 노트북은 요청을 5절에서 먼저 보내고 검사를 7~9절에서 따로 걸어서, 본문 「두 검사가 맡는 자리」에 그 차이를 한 단락으로 적었습니다.

## 챕터 마감 고침 (2026-09-23, 검토 A-2·A-8·A-9)
