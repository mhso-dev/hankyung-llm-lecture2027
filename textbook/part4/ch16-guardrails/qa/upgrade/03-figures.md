## 칸 순서 확인 (PNG를 직접 열어 본 결과)

- `03-1` 첫 판은 자르기를 먼저 적었는데도 렌더에서 **요약하기 갈래(상자 셋)가 왼쪽, 자르기 갈래(상자 둘)가 오른쪽**에 놓였습니다. 노드·엣지 차례를 바꿔 다시 렌더해도 같은 배치(긴 갈래가 왼쪽)라 그림은 두고 alt·오늘 볼 그림 설명·도식 읽기를 그림대로(왼쪽 요약하기, 오른쪽 자르기) 고쳤습니다. 두 갈래 모두 노트북에서 실행한 흐름이라 실선이고 「화살표가 둘로 나뉩니다」로 썼습니다.
- `03-2`는 위에서 아래로 파랑 둘(먼저 자르기 → 오래된 대화 셋을 글 하나로) → 보라 요약 모델 → 노랑 둘(요약 메시지 → 메시지 넷)입니다. 첫 판 마지막 상자 글이 저절로 세 줄로 꺾여 `<br>`로 미리 나눠 다시 렌더했습니다.
- `03-3`은 왼쪽 칸 자르기(초록 → 노랑), 오른쪽 칸 요약하기(초록 → 보라 → 노랑), 아래 회색 상자입니다.
- `03-4`는 왼쪽 칸 남길 대화 수 둘, 오른쪽 칸 넷(각각 초록 → 노랑), 아래 회색 상자입니다. 첫 판 회색 상자 글이 저절로 꺾여 `<br>`로 세 줄을 미리 나눴습니다. 회색 상자 「두 칸 모두 첫 대화 메시지가 잘림」은 5절 `자른 기록 글:` 아래 세 줄(1번 없음)과 9절 `넷을 남긴 기록의 첫 대화: 네, 그렇게 하겠습니다.`로 두 칸 모두 확인한 값입니다.

## 라벨에 넣지 않은 값

- **흔들린 값**: 요약 글과 요약한 기록의 글자 수. 교재 코드(`code_sha256` `692194ea…`)의 새 커널 두 번(C 10:03:00·D 10:03:18 UTC)은 셀 22개 출력이 모두 같았지만(`outputs_sha256` 두 번 `060ac1dd…`, 요약한 기록 251자), **노트북 밖 확인 다섯 번에서는 246자·248자**로 갈렸습니다(`03-probe.md`). 그래서 글자 수는 어느 그림에도 넣지 않았습니다.
- **라벨에 넣은 값**: 메시지 수(여섯·셋·넷·다섯)와 남은 말(하나 화요일 / 셋 / 둘 작은 정원과 화요일) — 메시지 수와 자르기 결과는 코드가 정하는 값이고, 요약한 기록의 남은 말 셋은 확인 다섯 번 + 노트북 두 번 **일곱 번 모두 같았습니다**.
- **개수는 한글로**: 「대화 다섯」·「메시지 셋·넷·다섯·여섯」·「남은 말 하나·둘·셋」·「남길 대화 수 둘·넷」. 숫자를 그대로 쓴 라벨은 모델 이름 `5.4`, 칸 제목의 절 번호(5절·9절), 「남길 수가 1보다 작으면」의 기준 값 1뿐입니다.
