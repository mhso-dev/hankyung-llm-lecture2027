## 5. 설계 — paired

- 공통 재료(노트북 1~5절, `example`): 설치 → import(`json`·`math`·`os`·`init_chat_model`) → 키 → 모델 → 자리 찾기 → 자료 읽기·`E01` → 01·02절 시스템 메시지 글·문서 한 줄 → **이 절에서 정한 값 셋**(`max_calls = 2`·`max_cost_usd = 0.01`·`estimated_cost = 0.002`) → 질문 셋(손으로 적음, 첫 질문은 01·02절 휴관일 질문) → `build_messages` 정의·모양 보기 → `math.isfinite` 맛보기(nan·inf, `nan > 0.01`이 `False`) → `make_budget` 정의·새 예산 → `reserve` 정의 → 한 번 예약(`calls 1`·`cost_usd 0.002`, 함수에 넘긴 딕셔너리가 바뀜).
- **Before**(`lesson_part="before"`, 6절): 예산을 만들어 두고도 보지 않는 흐름. 질문 셋을 모두 **보낼 목록**에 담고(`보낼 목록의 요청 수: 3`·`…예상 비용 합계(달러): 0.006`) 정한 한도와 견줌(`한도를 넘는 요청 수: 1`, 셋째 질문). **보내기 직전에서 멈춤 — 모델 요청 0번**(02절 Before와 같은 모양). 실제로 보낸 수 0은 셀 코드에 모델 요청이 없다는 것으로 확인하고 본문·결과 읽기 문장으로 적었습니다(0을 그대로 찍는 출력 줄은 두지 않음).
- **After**(`lesson_part="after"`, 7~9절): `ask_with_budget`(첫 줄 `reserve` → 메시지 → `model.invoke`) · `ask_all`(`try` 안에서 예약·요청, `except ValueError`면 멈춘 질문과 까닭을 출력하고 `break`) → 새 예산으로 질문 셋 → `멈춘 질문: 법정 공휴일에도 문을 여나요? | 까닭: 호출 한도를 넘습니다.`·**`모델에 보낸 요청 수: 2`**·`예약한 호출 수: 2`·`예약한 예상 비용 합계(달러): 0.004` → 받은 답 둘 → 첫 응답 `usage_metadata` 토큰 수(따로 출력, 비용으로 바꾸지 않음) → 두 흐름 표(`3 | 0` / `2 | 1`) → 8절 손 확인(nan·inf·-0.1 모두 막힘 + `assert` 둘) → 9절 값 바꿔 보기(비용 상한 0.003 → 둘째 질문 `비용 상한을 넘습니다.`·**`모델에 보낸 요청 수: 1`**).

- **비용 값의 출처 — (가) 이 절에서 정한 값**. 까닭: (1) 이 절의 학습 대상은 한도 동작(몇 번째 요청이 어느 검사에서 막히는지)이라 그 값이 실행마다 같아야 결론·그림에 쓸 수 있습니다.
