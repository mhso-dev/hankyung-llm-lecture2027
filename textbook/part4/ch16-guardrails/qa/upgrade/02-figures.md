## 칸 순서 확인 (PNG를 직접 열어 본 결과)

- `02-1`은 위에서 아래로 초록 받은 질문 → 파랑 입력 검사 → 파랑 가리기 → 노랑 가린 질문이고, 거기서 화살표가 둘로 나뉘어 왼쪽 보라 모델, 오른쪽 초록 기록 한 줄로 갑니다. 두 화살표 모두 실제로 실행한 흐름이라 실선입니다.
- `02-2`는 위에서 아래로 파랑 규칙 다섯(01과 한 글자 → 붙임표 자리 → 숫자 서너 개 → 붙임표 자리 → 숫자 네 개)과 맨 아래 노랑 찾은 전화번호입니다.
- `02-3`은 첫 판에서 공통 질문 상자 하나를 두 칸 밖에 두고 모델 상자까지 넣었더니 **원본 폭 888**(868 초과)이었고 After 칸이 왼쪽에 놓였습니다. 질문 상자를 칸마다 두고 모델 상자를 빼 다시 렌더했습니다 → 폭 807, 왼쪽 칸 Before(초록 → **빨강 둘**), 오른쪽 칸 After(초록 → 파랑 → 노랑 둘), 아래 회색 상자. 모델 요청이 After에서만 한 번 나갔다는 사실은 도식 읽기 문장에 적었습니다.

## 라벨에 넣지 않은 값

- **흔들린 값**: 교재 코드(`code_sha256` `2c752548…`)의 새 커널 두 번(실행 C 09:36:16·D 09:36:33 UTC)에서 코드 셀 26개가 **모두 같았습니다**(`outputs_sha256` 두 번 `fc201702…`). 모델 답도 두 번 같은 문장이었지만 모델이 쓴 글이라 어느 그림에도 넣지 않았습니다.
- **두 실행 모두 같았던 값만 라벨에**: 원문 값 넷·없음, 종류별 개수, 찾은 번호 `010-0000-0000`, 빈칸 번호 `010 0000 0000`, 모델 이름.
- **개수는 한글로**: 「가짜 개인정보 넷」·「원문 값 넷」·「규칙 다섯」·「나머지 세 값」. 숫자를 그대로 쓴 라벨은 번호 값(`010`·`0000`·`016789`)과 모델 이름 `5.4`, 칸 제목의 절 번호뿐입니다.

## 라벨 숫자 대조 (G7)

`figure_numbers()`가 세는 대상은 `5.4`·`01`·`016789`·`010`·`0000`이고 모두 노트북 출력이나 본문(`_src`)에 그대로 있습니다(게이트 G7 0건). `016789`는 출력 줄 `전화번호 정규식: 01[016789]-?\d{3,4}-?\d{4}` 안에 있습니다.

## 새 커널 두 번과 그림

그림은 새 커널 실행 C·D를 마친 **뒤에** 처음 렌더했습니다. 두 실행의 셀별 출력이 26개 모두 같았으므로 라벨 값을 고를 일이 없었습니다.
