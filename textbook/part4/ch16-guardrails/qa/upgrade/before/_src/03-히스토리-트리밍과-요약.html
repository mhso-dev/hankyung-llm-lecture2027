1학습 목표

  • 시스템 메시지와 최근 대화만 남기는 트리밍을 구현할 수 있습니다.
  • 오래된 대화를 실제 모델로 요약해 최근 메시지와 결합할 수 있습니다.
  • 메시지 수와 문자 수 변화를 분리해 정보 손실과 비용을 해석할 수 있습니다.

2이 내용을 배우는 이유

대화를 모두 다시 보내면 호출 비용과 지연이 커지고 오래된 민감 정보가 반복해서 전송됩니다. 최근 대화만 자르면 비용은 줄지만 앞에서 정한 사용자 선호와 핵심 사실도 사라집니다. 트리밍과 요약은 서로 다른 손실을 만들므로 목적에 따라 선택해야 합니다.

3앞에서 배운 내용

Ch 8에서 입력 예산과 Compress를 관찰했습니다. Ch 14에서는 대화형 RAG가 앞선 질문을 검색 가능한 질문으로 바꿨습니다. 이 절은 그 대화 목록을 메시지 단위로 줄이고 실제 요약 결과를 다시 메시지로 넣습니다.

4핵심 개념

쉬운 예

긴 회의록에서 최근 결정 두 개만 남기면 빠르지만 배경이 사라집니다. 앞부분을 짧게 요약하면 배경을 일부 보존하지만 요약이 원문의 뜻을 바꾸지 않았는지 확인해야 합니다.

정의

히스토리(history)는 현재 호출에 함께 전달하는 이전 메시지 목록입니다. 트리밍(trimming)은 정한 개수나 예산 밖의 메시지를 제거합니다. 요약 처리는 오래된 대화를 새 요약 메시지로 바꿉니다. 요약도 모델 출력이므로 원문보다 길어지거나 사실을 빠뜨리고 잘못 합칠 수 있습니다.

호출 표기와 실행 시점

트리밍은 시스템 메시지를 보존한 채 최근 메시지 수만 남깁니다. 요약 방식은 오래된 발화를 모델에 입력해 요약 문자열을 만들고 최근 발화와 결합합니다. 두 방식 모두 최종 프롬프트에 어떤 정보가 남았는지 실제 문자열로 확인해야 합니다.

다른 상황에 적용

프로젝트 상담에서는 오래된 결정은 요약하고 직전 작업 로그는 원문으로 유지할 수 있습니다. 배송 조회처럼 최근 주문 번호만 중요하다면 요약 호출 없이 최근 턴만 남기는 방식이 더 적합합니다.

비교와 경계

트리밍은 정보를 삭제하고 요약은 정보를 압축하면서 왜곡 가능성을 만듭니다. 문자 수가 줄어도 토큰 수가 같은 비율로 줄지는 않으며, 이 실험에서 요약 결합 문자가 늘어난 결과를 비용 절감으로 해석할 수 없습니다.

6실험 결과 해석

트리밍 경로는 메시지 여섯 개를 세 개로 줄였습니다. 요약 경로는 여섯 개를 네 개로 줄이고 오래된 ‘두 문장’ 선호를 남겼지만, 문자 수는 원본 168자보다 늘어 이 실행에서는 문자 수 절감을 관찰하지 못했습니다. 고정 안내문과 길이 제한 없는 요약 때문에 문자 수가 늘 수 있으므로 메시지 수 감소를 비용 감소와 같다고 보지 않습니다.

7주의할 점과 실무 메모

  • 시스템 규칙은 일반 대화와 분리해 보존합니다.
  • 금액·날짜·승인처럼 중요한 사실은 요약문만 믿지 말고 구조화된 상태에도 따로 보존합니다.
  • 요약 호출 자체도 호출 한도와 비용 상한에 포함합니다.

실제 모델 호출은 절마다 미화 1달러 미만이 되도록 짧은 입력과 출력을 사용했습니다. 정확한 청구액은 제공자 사용량 화면과 해당 실행 시점 가격표를 확인해야 합니다.
