1학습 목표

  • 합성 이메일과 전화번호를 모델 호출 전에 마스킹할 수 있습니다.
  • 감사 로그에 원문 개인정보를 남기지 않는 구조를 만들 수 있습니다.
  • 정규 표현식 마스킹의 누락과 오탐 가능성을 설명할 수 있습니다.

2이 내용을 배우는 이유

모델 호출과 관찰 로그는 모두 데이터가 이동하거나 남는 지점입니다. 사용자의 질문을 그대로 보내고 기록하면 답변 생성에 필요하지 않은 개인 식별 정보까지 처리할 수 있습니다. 먼저 필요한 정보인지 판단하고, 필요하지 않으면 값의 종류만 남겨야 합니다.

3앞에서 배운 내용

Ch 2의 문자열 처리와 정규 표현식 기초를 사용합니다. Ch 6에서 invoke()에 메시지를 전달했고 Ch 15에서 트레이스에 남길 필드를 정했습니다. 이 절은 호출과 기록보다 앞에 마스킹 단계를 둡니다.

4핵심 개념

쉬운 예

택배 상자를 분류하는 작업에 전체 전화번호가 필요하지 않다면 ‘연락처 있음’ 표지만 남길 수 있습니다. 모델도 실제 값 대신 정보 종류만 받아 작업할 수 있는지 먼저 판단합니다.

정의

개인 식별 정보(PII)는 한 사람을 직접 또는 다른 정보와 결합해 알아볼 수 있게 하는 정보입니다. 마스킹(masking)은 실제 값을 <EMAIL_MASKED>처럼 의미를 보존한 표지로 바꿉니다. 최소 수집은 작업에 꼭 필요한 정보만 처리하는 원칙입니다.

호출 표기와 실행 시점

탐지 함수는 합성 이메일과 전화번호 패턴의 시작·끝 위치를 찾고, 마스킹 함수는 실제 문자열을 [EMAIL]·[PHONE] 같은 종류 표지로 바꿉니다. 모델 호출과 로그 저장에는 마스킹된 문자열만 전달하고 원문은 출력하지 않습니다.

다른 상황에 적용

주민등록번호가 필요 없는 문의 분류에서는 [ID_NUMBER] 표지만 남겨도 업무 유형을 판단할 수 있습니다. 반대로 배송 연락처럼 실제 번호가 필요한 후속 시스템에는 모델을 거치지 않는 별도 권한 경로를 설계해야 합니다.

비교와 경계

정규식은 알려진 모양을 찾을 뿐 사람 이름·주소·우회 표기를 모두 탐지하지 못합니다. 마스킹은 암호화나 접근 통제를 대신하지 않으며, 이미 외부로 전송한 뒤 적용하면 보호 효과가 없습니다.

도식 읽기

합성 문장에서 정해 둔 전화번호·이메일 등의 형식을 찾아 마스킹합니다. 변경된 문장과 탐지 수를 확인한 뒤, 규칙이 찾지 못하는 형식도 살펴봅니다. 모든 개인정보를 탐지한 결과로 확대하지 않습니다.

6일부러 실패해 보기

합성 이메일과 전화번호가 각각 한 건씩 탐지되어 모델 입력과 감사 로그에서 사라졌습니다. 모델 답에도 원문 이메일이 다시 나타나지 않았습니다. 이 결과는 준비한 패턴에서만 관찰한 것이며 띄어쓰기, 국제 전화번호, 오타, 이미지 속 정보까지 탐지한다고 일반화할 수 없습니다.

7주의할 점과 실무 메모

  • 실제 사람의 개인정보로 테스트하지 않습니다. 문서와 시험 데이터에는 명시적으로 만든 합성값만 둡니다.
  • 마스킹 뒤에도 업무상 필요한 식별자가 사라져 답 품질이 낮아질 수 있습니다. 필드별로 보존 여부를 정합니다.

실제 모델 호출은 절마다 미화 1달러 미만이 되도록 짧은 입력과 출력을 사용했습니다. 정확한 청구액은 제공자 사용량 화면과 해당 실행 시점 가격표를 확인해야 합니다.

8정리와 다음 절

  • 합성 이메일과 전화번호를 모델 호출 전에 마스킹할 수 있습니다.
  • 합성 이메일과 전화번호를 마스킹했고 모델 답과 안전 로그에서 원문이 다시 나타나지 않았음을 확인했습니다.
  • 이 절의 통과 결과는 실행한 입력과 정책 범위에서만 해석합니다.

다음 학습과 이어지는 지점 — 다음 절에서는 대화가 길어질 때 오래된 개인정보가 계속 입력에 남지 않도록 트리밍과 요약을 적용합니다.

1. 이해

마스킹과 삭제의 차이는 무엇인가요?

마스킹은 정보 종류를 표지로 남기고 실제 값을 가리며, 삭제는 해당 문자열을 제거합니다. 오답 시 다시 볼 곳: 이 페이지의 핵심 개념과 실패 확인

2. 적용

감사 로그에 이메일 원문이 꼭 필요하지 않다면 어떤 값을 남겨야 하나요?

마스킹된 질문, 탐지 종류와 개수, 정책 결과를 남깁니다. 운영에서 해시가 필요하면 비밀 솔트 관리 정책을 별도로 정합니다. 오답 시 다시 볼 곳: 이 페이지의 핵심 개념과 실패 확인

3. 분석
