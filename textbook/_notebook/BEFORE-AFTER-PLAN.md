# 실패 예제 Before/After 보완

각 절의 여섯 번째 블록에서 실패 코드·실제 결과·수정 코드·수정 결과를 직접 비교할 수 있도록 보완합니다. 기존 본문과 실행 예제를 보존하고, 노트북의 실행 순서를 HTML과 일치시킵니다.

1. 현재 렌더러·복사 검사의 회귀 테스트를 확인하고 분할 표시 테스트를 먼저 추가합니다.
2. 노트북 셀의 `metadata.lesson_part`를 `before`·`after`로 표시합니다. 표시가 없는 셀은 실행 예제입니다. 전체 순서는 실행 예제 → Before → After입니다.
3. 원본 `_src`는 5번 블록에 `{{notebook:절|example}}`, 6번 블록에 `{{notebook:절|failure}}`를 둡니다. 같은 셀을 두 번 싣지 않습니다.
4. 실패는 실제 예외나 잘못된 결과로 확인하고, 수정은 같은 원인에 대한 코드 변경과 실제 결과·검증으로 보여 줍니다. 의도한 예외만 포착하여 전체 실행을 계속합니다.
5. 바뀐 20개 노트북을 새 커널에서 실행하고 HTML을 빌드합니다. 셀 순서·복사·다운로드 일치, Before/After 배치, PC·모바일 화면, 비밀값 노출을 검증합니다.

실행 예제의 준비 셀을 먼저 실행해야 합니다. Before/After를 별도 노트북에서 실행하려면 전체 노트북을 내려받아 첫 셀부터 실행합니다. 미지원 형식은 안전한 분기와 명시적인 처리 경계를 보여 주며, 실제 변환·OCR·파싱 성공을 꾸미지 않습니다.
