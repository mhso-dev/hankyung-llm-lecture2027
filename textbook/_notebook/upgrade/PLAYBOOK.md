## 2. 절 하나 (NN) — 순서

1. **읽기**: 기존 `_src/NN-*.html`, 노트북, `figures/NN-*`, 챕터 `chapter.json`(없으면 `_build.py`), 앞 절 제목, `labs/.../pyproject.toml`(고정 버전). 챕터에 옛 생성기(`make_*.py`·`_make_notebooks.py`)가 있으면 첫 절 작업 때 첫머리에 설명 주석 + `raise SystemExit(...)`를 넣고, 챕터 마감 때 `mv -n`으로 `qa/upgrade/before/generators/`에 옮깁니다(Ch 5 C-1).
2. **보존과 진단**: `qa/upgrade/before/`에 `_src`·노트북·figures(NN)를 복사하고, 챕터 첫 절 전에 `upgrade_gates.py --label before`를 한 번 실행합니다(이미 있으면 덮어쓰지 않음).
3. **생성기**: `qa/upgrade/author_NN.py`를 만듭니다. 파일 하나가 절 노트북 하나를 씁니다. 기존 노트북의 학습 질문·데이터·형식(paired/experiment)은 유지합니다.
4. **실행**: `run_section.sh <챕터> NN`. 새 커널 PASS까지 고칩니다. 실행 출력을 직접 읽고 결과 읽기·본문 숫자를 거기서 가져옵니다.
5. **본문**: `_src/NN-*.html` 10블록을 블록 단위로 다시 씁니다. `{{notebook:slug}}`(experiment) 또는 `{{notebook:slug|example}}`+`{{notebook:slug|failure}}`(paired) 토큰 위치는 기존 구조를 따릅니다.
6. **그림**: `qa/upgrade/NN-figures.md` 설계표 → `figures/NN-k-이름.mmd`·`.caption.md` 3~5장 → 삽화 1장 `figures/NN-k-이름.prompt.md`·`.caption.md`(생성은 §5). 본문에 `{{mermaid:이름|alt|캡션}}`, 삽화는 `{{img:이름|alt|캡션}}` + 「그림 읽기」 한 단락.
7. **다시 실행·검사**: `run_section.sh ... --no-exec` → G1~G7 0건. 빌드 도구에 `{{mermaid:}}`가 없는 챕터(Ch 8~10 자체 `_build.py`)는 `textbook/_template/builder.py`의 `_inline_mermaid`·`_inline_img`를 가져와 치환을 추가하고 기존 절 빌드 결과가 바뀌지 않는지 확인합니다.
8. **묶음**: `pack.py <챕터> NN`.

## 3. 챕터 끝 실습 절 (QUALITY-UPGRADE.md §7-2)

- 챕터의 모든 절을 끝낸 뒤 만듭니다. 파일 `{마지막+1}-{챕터 이름}-실습`, 제목 「{챕터 이름} 실습: {주제}」, `chapter.json`에 `experiment`로 추가(자체 빌드 챕터는 빌드 목록에 추가).
- 「강사 시연」이라는 이름·문구 금지. 강사와 학생이 함께 따라 실행하는 예제, 따로 과제 없음.
- 그 챕터에서 이미 쓴 이름·API만 씁니다. 챕터 소재와 이어지는 작은 상황 하나에 앞 절 기능 2~3개를 함께 붙입니다.
- 노트북 순서: 준비 → 주제 소개 → 재료 만들기 → 결과를 볼 기록 장치 → 조립(목록에 배운 절을 주석으로) → 실행 1(예상 → 실행 → 출력 확인) → 실행 2(값 하나만 바꿔 예상 → 실행 → 비교) → 정리 3줄.
- 본문: 「앞에서 배운 내용」에 「절 | 배운 것 | 실습에서 쓰는 곳」 표, 「핵심 개념」에 조립도, 「실험 결과 해석」에 실행 1·2 비교. 그림: 조립도·실행 1 순서·실행 1·2 비교 + 삽화 1장. 30분 안팎, 모델 호출 3~5번.
- 서비스 요청이 3~5번을 넘으면 까닭을 진단에 적고 강사 확인 대상에 올립니다(규격 §7-2, Ch 14 10절 — 답 모델 5 + 임베딩 5 = 열 번).
- 3~5번 기준은 **챕터 끝 실습 절** 규칙입니다. 일반 절은 규격 §3의 비용 상한만 지키고 요청 수를 준비물과 진단에 적으며, 요청 수만으로 강사 확인 대상에 올리지 않습니다(규격 §7-2, 2026-09-21 Ch 15 검토 A 「사람이 정해야 할 것」 7).
- 앞 절의 「다음 학습과 이어지는 지점」을 실습 절로 고칩니다.
- 사용자 결정(2026-09-16): Ch 32(Docker)·Ch 33(CI/CD)은 실습 절을 만들지 않습니다.

## 4. Ch 22 검토에서 실제로 걸린 것 — 쓰기 전에 확인

- 라이브러리 동작(훅·콜백 자리, 기본값, 경계 조건 「넘으면/이상이면」)은 설치한 버전 소스(`pip download 패키지==버전 --no-deps`)로 확인합니다.
- 노트북에서 실행하지 않은 동작은 「이번에 실행하지 않았습니다」로 씁니다. 한 번만 본 동작을 결론·정리·복습 해설에 일반화하지 않습니다.
- 결과 읽기 첫 단락의 숫자 인용은 모두 최신 출력에 있어야 합니다. 재실행하면 temperature 0이라도 글자 수·토큰 수가 바뀌므로 본문·캡션·그림 라벨을 다시 대조합니다.
- 그림 설명의 방향 말은 그림 방향과 맞춥니다(`TB`/`TD`에 「왼쪽부터」 금지). 색 이름: flow 파랑, model 보라, tool 초록, measure 노랑, fail 빨강, 클래스 없음 회색, sequenceDiagram 메모 노랑. 실패가 아닌 요소에 빨강 금지. 같은 요소는 절 안 모든 그림에서 같은 색.
- 클래스 정의 셀은 메서드 2개 이하·메서드 본문 3줄 이하면 한 셀에 둡니다(규격 §2-4). 오류 상자는 잡아서 기록한 오류 노랑, 프로그램을 멈춘 실패 빨강(규격 §5-3).
- sequenceDiagram 메모는 그 기록이 남는 시점(호출 전/응답 뒤)에 둡니다. 노드 id에 `call`·`end` 같은 예약어 금지. 원본 폭이 약 860px를 넘으면 `<br>`로 줄입니다.
- 감싸기형 훅이 handler 앞에서 남긴 기록은 「시작」까지만 증명합니다. 실행 여부는 결과 메시지로 확인합니다.
- 문장: 70자 이하, 단락 5문장 이하, 영문 용어·코드 이름+조사로 문장 시작 금지(「`x`는」 → 「인자 `x`는」). 괄호 뒤 마침표 `).`는 문장 끝으로 세지 않으므로 괄호 설명은 문장 가운데에. 금지어: 「돌려주다」 류 게이트 금지어, 사용자가 금지한 표현(「한」「겹」「더」를 이어 쓴 세 어절 — 2026-10 적는 방식만 바꿈), 「쉽게·간단히·당연히」.
- 준비물에 모델 호출 수·실행 시간·예상 비용, 모델 준비 셀 결과 읽기에 실행일(「이 노트북의 출력은 YYYY-MM-DD에 이 모델로 실행한 결과입니다」).
- 외부 도구 챕터(Git·Docker 등)는 준비물에 기준 버전(필수 최소·교재 출력·도구 권장)을 적습니다(규격 §6, Ch 3 검토).
- sequenceDiagram 받아 오기는 실선 요청 → 점선 응답. 라벨이 세로선과 겹치면 `messageAlign: left` + 한 줄 라벨(규격 §5-3). `visual.cjs`는 SVG viewBox 폭 약 868 이하에서 14px를 넘깁니다.

- 실습 절을 붙인 뒤 `textbook/part{N}/_build_index.py` 절 수 검사와 `textbook/qa/check_course_continuity.py` 해시 허용 목록을 고치고, 두 스크립트를 실제로 돌려 멈추는 자리(보통 zip 신선도)를 진단·요약에 적습니다(규격 §7-2, Ch 9 검토 B C-2·R-1).
- 그림을 다시 렌더하면 PNG를 직접 열어 **회색 상자·노란 메모가 어느 칸·어느 시점에 붙었는지** 확인합니다. 한 칸에만 맞는 설명이 공통 상자로 적혀 있으면 라벨에 그 칸을 적습니다(규격 §5-3, Ch 10 검토 B 06-1).

- 시간을 재는 코드가 없으면 빠르고 느림을 본문에 적지 않습니다. 구조 차이만 쓰고 「걸린 시간은 이번에 재지 않았습니다」를 붙입니다(규격 §3, Ch 12 A 07-1).

- 비교 그림의 결과 상자에 질문 하나의 값과 여러 질문 평균을 섞지 않습니다. 줄을 나눠 무엇의 값인지 적습니다(규격 §5-3, Ch 12 B 13-1). 나란한 두 상자는 `-->` 대신 `~~~`로 잇습니다(Ch 12 B 10-1).
- 산출 파일을 다시 쓴 절은 뒤 챕터가 그 파일에서 세는 **값**(조건에 맞는 줄 수 등)까지 돌려 보고, 기대값이 깨지면 파일·행 번호·현재 값·기대값을 챕터 요약과 진행표에 적습니다(규격 §7-2, Ch 12 B C-1).
- 「같은 코드」·「글자까지 같다」는 AST·문자열로 대조한 절만 적습니다. 변수 이름만 달라도 그 말을 쓰지 않습니다(규격 §4, Ch 13 C-3).
- 「같은 코드로 다시 정의합니다」는 코드만 가리킵니다. 옮기며 주석을 줄였으면 진단서와 챕터 요약에 한 줄로 적습니다(규격 §4, Ch 14 A-3).
- 조건 함수처럼 `add_node`로 등록하지 않는 것은 구조 도식에서 노드와 같은 모양·색으로 그리지 않고, 상자 수·갈래 자리를 출력한 구조 문자열과 맞춥니다(규격 §5-3, Ch 13 03-1).
- `chapter.json`의 `objectives`와 Part 목차 스크립트의 챕터 설명은 절 게이트 밖입니다. 챕터 마감 때 절 본문 말과 대조하고 `_build.py`·`_build_index.py`를 다시 돌립니다(규격 §7-2, Ch 13 C-2).
- 새 커널 두 번에서 **달랐던 값**은 결과 읽기 둘째 단락·본문 표·「확인할 점」에만 「이번 실행에서는」·「교재 출력에서는」으로 한정해 둘 수 있습니다. 결과 읽기 둘째 단락은 「이번 실행에서는」으로 그 실행 안의 비교까지 적을 수 있지만, **본문 해석·결론에서는 그 값에서 끌어낸 비교를 쓰지 않습니다**. 그림 라벨·캡션·정리·복습에서는 뺍니다(규격 §2-7 9번 끝, 2026-09-21 Ch 15 검토 A-16·B-2).
- 다시 실행해 핵심 관찰이 뒤집히면 **입력을 고치기 전에 먼저 흔들림을 확인합니다.** 같은 요청을 노트북 밖에서 따로 5번 보내 원래 관찰이 다시 나오는지 보고 결과를 진단에 적습니다. 다시 나오면 입력은 그대로 두고 학생 본문 b7에 「같은 요청도 실행한 때에 따라 판정이 달라질 수 있다」를 적고, 다른 결과를 받은 절은 그 결과를 사실대로 둔 채 원래 관찰일 때의 값을 「…이면 …이 됩니다」 꼴 셈으로 한 문장 덧붙입니다. 원하는 값이 나올 때까지 다시 돌리지 않습니다(규격 §2-7 10번 끝, 2026-09-21 Ch 15 03·04절).
- Mermaid 렌더 도장(`*.render.json`)은 지우지 않습니다. mmd를 고치면 자동으로 다시 렌더되고, 같은 mmd는 `render_mermaid.py --force`를 씁니다(PLAYBOOK §0 삭제 금지, Ch 7 05 C-5).

## 6. 챕터 사이 이어짐 (사용자 요구, 2026-09-16)

- 챕터는 **Ch 1부터 한 챕터씩 순서대로** 진행합니다. 병렬로 여러 챕터를 동시에 고치지 않습니다. 앞 챕터에서 개선한 내용이 다음 챕터에 이어져야 하기 때문입니다.
- 챕터가 끝나면(실습 절·검토까지) 챕터 `qa/upgrade/chapter-summary.md`를 씁니다: 이 챕터가 새로 가르친 문법·API·용어 목록, 반복해 쓴 예제 데이터·비유·함수 이름, 실습 절 주제와 결과, 다음 챕터가 이어받을 것, 아직 가르치지 않은 것(다음 챕터가 전제하면 안 되는 것).
- **앞 내용 읽기**(2026-09-19 갱신, 과정 요약을 세 파일로 나눔): **`textbook/qa/upgrade-course-summary.md`(과정 요약 핵심)는 모든 작업자가 읽습니다.** `runs/`·계약 파일을 읽거나 쓰는 절, 실습 절, 챕터 마감은 **`textbook/qa/upgrade-contracts.md`**(산출 파일·데이터 계약)도 읽습니다. **전체 마감 담당만 `textbook/qa/upgrade-final-checklist.md`**(마감 순서·강사 확인·미결·삭제 승인)를 읽습니다. 이어서 같은 Part 안 앞 챕터의 `chapter-summary.md` + 바로 앞 챕터 요약(다른 Part여도), 이 챕터 안에서는 `qa/upgrade/handoff.md`와 앞 절 완료본. 끝난 Part의 챕터 요약은 세부가 필요할 때만 찾아봅니다(과정 요약과 다르면 챕터 요약이 우선).
- 작업자는 위 자료에 맞춰 「앞에서 배운 내용」과 예제를 씁니다. 앞 내용과 어긋나는 기존 문장은 고칩니다.
- Part가 끝나면(그 Part 마지막 챕터 요약까지) 오케스트레이터가 **세 파일을 함께 갱신합니다**: `upgrade-course-summary.md`는 같은 번호 §(§0~§9)에 합쳐 적되 중복 설명은 최신 Part 기준 한 번만 두고 바뀐 것만 「Part N에서 바뀜」으로 남기고(22KB 이하 유지), 산출 파일·데이터 계약은 `upgrade-contracts.md`에, 마감 순서·뒤 챕터 인계·강사 확인·미결·삭제 승인은 `upgrade-final-checklist.md`에 덧붙입니다.
