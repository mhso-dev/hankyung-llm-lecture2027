처음 실습할 때

처음 개발한다면 Ch 1 개발환경부터 읽습니다. Ch 1 실습에는 API 키가 필요하지 않으며 도구 설치와 가상환경 준비를 안내합니다.

  1. 노트북과 실습 파일 함께 받기를 선택하고 압축을 풉니다. 노트북과 문서가 들어 있는 labs 안의 파일을 다른 폴더로 옮기지 않습니다.
  2. 모델을 호출하는 API 실습에서는 압축을 풀어 생긴 llm-practice 폴더의 env.example을 복사해 .env로 저장하고, OPENAI_API_KEY= 오른쪽에 본인의 키를 넣습니다. 키를 코드나 출력에 붙여 넣지 않습니다.
  3. 지금 학습할 챕터 폴더에서 uv sync --locked로 잠금 파일의 패키지와 커널을 준비합니다. 그 챕터의 .venv를 노트북 커널로 선택하고 원하는 절을 엽니다. 코드 셀을 선택하고 Shift+Enter를 눌러 첫 셀부터 순서대로 실행합니다. 설치 셀이 있는 절에서는 설치가 끝날 때까지 기다립니다. 실행 중 표시가 사라진 뒤 오류 메시지가 없는지 확인합니다.

Ch1에서 uv를 준비한 뒤 VS Code에서 지금 학습할 챕터 폴더를 엽니다. 예를 들어 Ch6은 labs/part2/ch06-langchain-start입니다. Microsoft의 Python·Jupyter 확장을 설치하고 그 폴더의 터미널에서 uv sync --locked를 실행합니다. uv run python --version으로 Python 3.12를 확인한 뒤 Select Kernel → Python Environments에서 같은 챕터의 .venv를 선택합니다. 다음 챕터에서도 그 챕터의 환경을 준비하고 선택합니다. 커널은 코드를 실행하고 변수를 기억하는 프로그램입니다. JupyterLab은 같은 폴더에서 uv run --with jupyterlab==4.4.9 jupyter lab으로 실행할 수 있습니다. 공식 노트북 환경 안내와 묶음의 ‘시작하기.md’에서 단계별 준비 방법을 확인합니다. 최초 설치·모델 다운로드·API 호출에는 인터넷 연결이 필요합니다. 실습 파일 묶음에는 프로그램 자체가 포함되어 있지 않습니다.

한 절을 따라 하는 순서

짧은 설명을 읽고 기본 코드를 실행합니다. 안내에 적힌 본문·문서 수·숫자 목록의 길이·출처 등의 값을 확인한 뒤, 지정한 값 하나만 바꿔 결과를 비교합니다. Before/After가 있는 절은 기본값으로 돌아온 다음 두 단계를 차례대로 실행합니다. 현상을 측정하는 절은 실험 결과와 해석을 확인합니다. ‘원리 더 알아보기’가 표시된 절에서는 먼저 기본 실습을 마친 뒤 해당 설명을 읽습니다.

API 셀을 다시 실행하면 사용량에 따른 비용이 발생하며, 모델이 생성한 문장은 실행마다 달라질 수 있습니다.

실행이 막혔을 때 확인할 점

NameError는 앞에서 만드는 변수가 준비되지 않았을 때 나타날 수 있습니다. 첫 셀부터 실행했는지 확인합니다. ModuleNotFoundError가 나오면 현재 챕터에서 uv sync --locked를 실행했는지와 그 챕터의 .venv를 선택했는지 확인합니다. 설치 셀이 있는 절은 그 셀도 실행합니다.

FileNotFoundError가 나오면 제공 파일이 제자리에 있는지 확인합니다. 노트북만 낱개로 옮겼다면 실습 파일 묶음의 원래 폴더 구조로 되돌립니다. 키 관련 오류는 .env의 파일명과 키 이름을 확인하며, 키 값 자체는 출력하지 않습니다.

변수가 예상과 다르게 남아 있으면 커널을 다시 시작하고 첫 셀부터 실행합니다. 커널을 다시 시작하면 이전 변수는 사라집니다.
