챕터 개요

모델에 같은 질문을 해도 함께 전달한 자료에 따라 답이 달라집니다. 이 챕터에서는 한 번의 호출에 어떤 자료를 얼마나 넣을지 직접 설계합니다. 프롬프트의 표현을 바꾸었던 Ch 7에 이어, 지시문과 모델을 고정하고 자료의 선택·압축·배치가 답에 미치는 영향을 확인합니다.

실습은 Ch 9에서도 사용하는 가상 기관 미르시립도서관의 문서와 연결합니다. 필요한 내용을 사람이 고른 뒤 평범한 파이썬 함수로 메시지를 조립합니다. 같은 자료를 검색으로 선택하는 방법은 Ch 9에서 구현합니다. 이번 챕터의 실험 순서와 문서 선택 규칙은 학생 코드가 정합니다.

이 챕터의 학습 범위Write·Select·Compress·Isolate는 컨텍스트를 관리하는 네 가지 전략입니다. Poisoning·Distraction·Confusion·Clash는 실패 원인을 살펴보는 분류입니다. 모두 실무를 설명하기 위한 틀이며, 네 범주가 모든 상황을 빠짐없이 나누는 표준은 아닙니다.

학습 목표

  • 지시·질문·근거·출력 예약·여유분을 구분해 컨텍스트 예산을 계산할 수 있습니다.
  • 자료를 외부에 저장하고, 이번 질문에 맞게 선택·압축·분리할 수 있습니다.
  • 실패를 유도한 입력과 실제 발생한 오답을 구분하여 기록할 수 있습니다.
  • 동일 과제의 세 가지 컨텍스트 설계를 토큰·품질·비용으로 비교하고, 실험의 한계를 설명할 수 있습니다.

실습 준비

Python 3.12와 uv를 사용합니다. 실행 파일과 고정된 의존성은 labs/part2/ch08-context-engineering/에 있습니다. 해당 폴더의 실습 안내에 준비 과정과 절별 실행 명령을 정리했습니다. API 키는 프로젝트 루트의 .env에서 읽습니다.

02~03절은 모델 호출 없이 파일 읽기·쓰기와 컨텍스트 조립 원리를 확인합니다. 01절과 04~06절은 실제 모델을 호출합니다. 본문에 수록한 실행 결과의 모델과 실행일을 확인하고, 다시 실행했을 때 답이 달라질 수 있다는 점을 고려합니다. 비용은 API가 반환한 사용량에 확인된 표준 단가를 적용한 추정치입니다.

집필본입니다. 프로젝트에서 정한 별도 검토 세션의 한국어 3단 감사는 아직 진행하지 않았습니다. 코드 실행·본문 수치·화면 검증 결과와 남은 제약은 검증 기록에 정리합니다. 노트북은 본문 확정 후 분할하는 후속 산출물입니다.
