1학습 목표

  • 이 절을 마치면 context rot를 입력이 길어질 때 과제 성능이 불균일하게 달라질 수 있는 현상으로 설명할 수 있습니다.
  • 이 절을 마치면 길이, 근거 위치, 반복 조건을 나누어 통제하는 실험표를 설계할 수 있습니다.
  • 이 절을 마치면 같은 과제, 모델, 프롬프트, 근거를 고정해야 비교가 성립하는 이유를 설명할 수 있습니다.
  • 이 절을 마치면 토큰 사용량, 단순 품질 루브릭, 비용 추정치를 기록하고 결과의 한계를 함께 보고할 수 있습니다.

2왜 지금 이것인가

04절에서는 잘못되거나 무관하거나 상충하는 정보가 답에 미치는 영향을 살펴보았습니다. 그렇다면 모든 정보가 정확하고 관련성이 있다면 많이 넣을수록 좋을까요? 컨텍스트 창의 최대 길이는 모델이 처리하는 입력과 출력을 합친 범위의 상한입니다. 창 안의 모든 정보를 같은 정확도로 이용한다는 보장은 아닙니다. 입력이 길어질수록 필요한 근거를 찾거나 적용하는 성능이 과제와 조건에 따라 낮아지는 현상을 context rot라고 부릅니다.

이 절의 목적은 “긴 입력은 나쁘다”는 결론을 미리 정하는 데 있지 않습니다. 길이의 영향을 다른 요인과 분리하여 관찰하는 데 있습니다. 같은 근거라도 입력 앞부분, 가운데, 뒷부분에 놓였을 때 결과가 달라질 수 있습니다. 첫 실행과 다섯 번째 실행의 결과가 다를 수 있습니다. 질문 난이도와 문서 순서가 달라지면 길이가 아니라 다른 변수를 측정하게 됩니다. 그래서 한 번에 한 조건만 바꾸는 실험이 필요합니다.

Chroma의 기술 보고서는 여러 모델과 통제 과제에서 입력 길이가 늘어날수록 성능이 고르게 유지되지 않는 결과를 보고했습니다. 이 보고서는 동료 심사 논문이 아니며 제품별 성능을 보증하지 않습니다. 수업에서는 특정 토큰 수의 임계값을 외우지 않습니다. 현재 사용하는 모델과 과제에서 위험 신호가 나타나는지 직접 측정하고, 나타나지 않은 경우에도 실험 범위 안에서만 해석합니다.

3선수 지식 되짚기

  • 컨텍스트 창 — 한 번의 모델 호출에 들어가는 시스템 지시, 사용자 입력, 대화 이력, 외부 문서 등의 토큰 전체를 담는 공간입니다. 최대 크기와 정보 활용의 정확도는 다른 문제입니다.
  • Distraction — 무관한 정보가 중요한 근거에 집중하는 것을 방해할 수 있습니다. 이 절에서는 방해 문서의 양을 늘리되 정답 근거는 고정합니다.
  • Select — 현재 질문에 필요한 자료만 고르는 전략입니다. 길이 실험의 결과는 다음 06절에서 전체 입력과 선택 입력을 비교하는 근거가 됩니다.
  • 실행 기록 — 모델의 답만 저장해서는 재현하기 어렵습니다. 모델 ID, 프롬프트, 입력 순서, 토큰 사용량, 반복 번호를 함께 남깁니다.

4핵심 개념

비유 — 긴 회의록에서 결정 한 줄 찾기

회의록 두 쪽에서 결정 한 줄을 찾는 일과 회의록 백 쪽에서 같은 줄을 찾는 일은 다릅니다. 결정 문장은 변하지 않았지만 주변 문장이 늘었습니다. 결정 문장이 마지막 쪽에 있는지 가운데에 있는지도 영향을 줄 수 있습니다. 사람이 긴 문서를 읽을 때도 비슷하지만, 모델의 작동을 사람의 기억과 동일하게 설명해서는 안 됩니다. 이 비유가 보여 주는 것은 하나입니다. 수용 가능한 길이와 안정적으로 활용하는 길이는 같다고 가정할 수 없습니다.

실험에서는 정답 근거 문장을 그대로 유지합니다. 주변에 의미가 낮은 문서 조각을 추가하여 길이를 바꾸고, 근거를 앞·가운데·뒤로 옮깁니다. 질문과 채점 규칙도 고정합니다. 이렇게 해야 결과 차이를 입력 길이와 근거 위치의 조합으로 해석할 수 있습니다.

정의

컨텍스트 로트 (context rot)
입력 토큰이 늘어날수록 모델이 필요한 정보를 회상하거나 적용하는 성능이 과제와 조건에 따라 불균일하게 낮아질 수 있는 현상을 가리키는 표현입니다. 모든 모델에서 같은 길이에 시작되는 고정 임계값이 아닙니다.
통제 변수 (controlled variable)
비교하는 실행 사이에서 같게 유지하는 조건입니다. 이 절에서는 질문, 정답 근거, 모델, 시스템 프롬프트, 출력 상한, 채점 기준을 고정합니다.
독립 변수 (independent variable)
영향을 확인하려고 의도적으로 바꾸는 조건입니다. 입력 길이와 근거 위치를 사용하되 한 표에서는 비교할 축을 명확히 표시합니다.
순서 효과 (order effect)
같은 정보라도 배치 순서나 실행 순서에 따라 결과가 달라지는 효과입니다. 근거 위치와 호출 순서를 기록해야 길이 효과와 혼동하지 않습니다.
품질 루브릭 (quality rubric)
출력을 일정한 기준으로 판정하는 간단한 채점표입니다. 이 절에서는 정답 수치 포함, 대상 기관 일치, 근거 밖 주장 없음처럼 사람이 확인할 수 있는 항목을 사용합니다.

도식 — 길이와 근거 위치를 함께 기록하기

실험에서 고정할 것과 바꿀 것

구분항목기록 이유
고정질문과 정답 근거 문장다른 문제의 난이도 차이가 결과에 섞이지 않게 합니다.
고정모델 ID, 시스템 프롬프트, 출력 상한모델이나 지시의 차이를 길이 효과로 잘못 해석하지 않게 합니다.
고정품질 루브릭실행마다 다른 기준으로 답을 평가하지 않게 합니다.
변경주변 문서의 양입력 토큰 수를 단계적으로 늘립니다.
변경정답 근거의 위치앞, 가운데, 뒤에서 활용 차이가 있는지 확인합니다.
반복같은 조건의 호출 번호확률적 변동을 한 번의 결과와 구분합니다.

길이와 위치를 완전히 분리하려면 먼저 위치를 고정하고 길이만 비교한 뒤, 각 길이에서 위치를 바꾸는 방식이 이해하기 쉽습니다. 모든 조합을 한 번에 실행해도 되지만 결과표를 읽을 때 두 효과가 섞일 수 있습니다. 초보자 실습에서는 기준 조건을 하나 두고 한 축씩 확장합니다.

품질, 토큰, 비용을 함께 보는 이유

입력이 길어지면 품질만 달라지는 것이 아닙니다. 입력 토큰 수가 늘고 호출 비용도 늘어납니다. 응답 객체의 usage.input_tokens와 usage.output_tokens를 기록하면 실제 API가 처리한 토큰을 확인할 수 있습니다. 이 실습의 품질 루브릭은 정답인 “월요일”을 포함했는지, 요구한 출처 [E01 p.2]를 표시했는지 두 항목으로 단순화합니다. 두 항목을 모두 충족했는지 조건별로 셉니다. 이 판정은 Ch 11의 검색 평가나 Ch 15의 생성 평가를 대신하지 않습니다. 실험 조건 사이의 큰 차이를 사람이 일관되게 읽기 위한 임시 도구입니다.

비용은 기록된 토큰과 확인 날짜가 있는 단가로 계산한 추정치입니다. 2026-09-08에 확인한 GPT-5.4 mini 표준 단가는 입력 100만 토큰당 0.75달러, 캐시된 입력 0.075달러, 출력 4.50달러입니다. 캐시 입력이 없다면 (input_tokens × 0.75 + output_tokens × 4.50) / 1_000_000으로 계산합니다. 캐시 입력, 지역 처리, 별도 도구 호출이 있으면 실제 청구액과 다를 수 있습니다. 따라서 표의 열 이름은 estimated_cost_usd처럼 추정임을 드러내고, “청구 비용”이라고 쓰지 않습니다.

자동 검사는 월요일과 출처 문자열을 찾는 두 항목입니다. 정독에서는 여기에 대상 기관이 맞는지, 서로 모순된 문장이 없는지, 근거가 있는데 답을 거부하지 않았는지도 확인했습니다. 이 기준은 04절에서 드러난 문자열 검사의 한계를 보완합니다.

확인할 점 — 결과표를 볼 때 먼저 입력 토큰 수가 의도한 순서로 증가했는지 확인합니다. 그다음 같은 길이에서 근거 위치에 따른 점수 차이를 보고, 같은 조건의 반복 결과가 얼마나 달랐는지 확인합니다. 마지막으로 품질 점수와 비용 추정치를 함께 봅니다. 입력이 길어졌는데 현상이 나타나지 않았다면 “이 모델은 context rot가 없다”가 아니라 “이번 과제와 길이 범위에서는 품질 저하를 관찰하지 못했다”고 기록합니다.

6일부러 실패해 보기

실패 실습 1 — 길이와 문제 난이도를 함께 바꿉니다. 짧은 입력에는 한 문장으로 답할 수 있는 질문을, 긴 입력에는 여러 조건을 조합해야 하는 질문을 사용해 보세요. 긴 입력의 점수가 낮아져도 길이 때문인지 난이도 때문인지 알 수 없습니다. 같은 질문과 같은 근거를 사용하도록 표를 고치면 비교가 가능합니다.

실패 실습 2 — 근거 위치를 기록하지 않습니다. 문서 조각을 이어 붙이는 과정에서 정답 근거가 짧은 입력에서는 앞에, 긴 입력에서는 가운데에 놓이게 합니다. 결과가 달라졌을 때 길이 효과와 위치 효과를 구분할 수 없습니다. 조립된 최종 입력에서 근거의 시작 위치나 배치 범주를 함께 저장합니다.

실패 실습 3 — 한 번의 실행으로 결론을 냅니다. 각 조건을 한 번만 실행하고 가장 낮은 점수를 context rot의 증거라고 단정해 보세요. 모델 출력의 확률적 변동과 호출 순서의 영향을 분리할 수 없습니다. 같은 조건을 반복하고 반복 번호와 실행 순서를 남깁니다.

실패 실습 4 — 비용 추정치를 실제 청구액으로 씁니다. 토큰 단가 계산값을 카드 명세의 청구액처럼 보고하면 캐시 입력과 지역 처리, 기타 도구 비용의 차이를 숨기게 됩니다. 계산식, 단가 확인일, 포함 범위를 함께 적고 추정치라고 표시합니다.

7주의할 점과 실무 메모

  • 고정 임계값을 만들지 않습니다. context rot는 정확히 몇 토큰부터 시작된다고 일반화할 수 없습니다. 모델, 과제, 방해 정보, 근거 위치, 출력 형식에 따라 달라집니다.
  • 소표본의 차이를 보편 법칙으로 확대하지 않습니다. 수업 실험의 반복 횟수는 현상을 관찰하고 기록법을 배우기 위한 규모입니다. 제품 전체의 성능 보증이나 모델 순위를 만들 수 없습니다.
  • 순서 효과를 남깁니다. 입력 문서의 배치 순서와 조건 실행 순서를 저장합니다. 가능하면 조건의 실행 순서를 바꾸어 한 방향의 편향이 있는지 확인합니다.
  • 응답이 불완전한지 확인합니다. incomplete_details.reason이 출력 상한과 관련되어 있다면 답을 완결된 응답처럼 채점하지 않습니다. 입력 길이 문제와 출력 상한 문제를 분리합니다.
  • 루브릭은 단순하게 유지합니다. 초보자 실습에서는 정답 핵심어와 출처 표시처럼 사람이 확인할 수 있는 두 항목이면 충분합니다. 검색 평가는 Ch 11, 생성 평가는 Ch 15에서 다룹니다.
  • 공개된 합성 자료를 사용합니다. 긴 입력을 만들기 위해 실제 고객 자료나 사내 문서를 복제하지 않습니다.

8정리와 다음 절

  • context rot는 입력이 길어질 때 필요한 정보를 활용하는 성능이 조건에 따라 불균일하게 낮아질 수 있는 현상입니다.
  • 길이의 영향을 보려면 같은 과제, 모델, 프롬프트, 근거, 루브릭을 고정하고 근거 위치와 반복 조건을 기록해야 합니다.
  • 토큰은 API 사용량으로 측정하고, 품질은 단순 루브릭으로 기록하며, 비용은 단가 확인일과 포함 범위를 명시한 추정치로 다룹니다.

다음 학습과 이어지는 지점 — 다음 06절에서는 이 결과를 바탕으로 전체 자료를 처음부터 넣는 방식과 필요한 본문만 선택하는 단계적 공개를 비교합니다. Ch 11에서는 정답 문서 ID를 바탕으로 검색 결과를 평가하고, Ch 15에서는 답변의 근거 충실성을 포함한 생성 품질을 평가합니다. 이 절의 단순 루브릭과 소표본 결과는 두 챕터의 평가를 대신하지 않습니다.

9복습 문제

문제 4개 · 해설 포함

[하] 1. 모델의 컨텍스트 창이 400,000토큰이라는 사실만으로 모든 위치의 정보를 같은 정확도로 사용할 수 있다고 말할 수 없는 이유는 무엇입니까?

정답·해설 — 창의 크기는 입력과 출력을 처리하는 범위의 상한이며, 긴 입력에서 각 정보를 안정적으로 활용하는 품질 보장이 아닙니다. 활용 성능은 과제, 근거 위치, 방해 정보 등에 따라 달라질 수 있습니다. 오답 학습 연결 — 최대 입력량과 권장 입력량을 같은 것으로 보았다면 context rot 정의를 다시 확인합니다.

[중] 2. 짧은 입력과 긴 입력을 비교할 때 반드시 고정해야 할 조건 네 가지를 쓰세요.

정답·해설 — 같은 질문, 같은 정답 근거, 같은 모델, 같은 시스템 프롬프트를 고정해야 합니다. 출력 상한과 품질 루브릭도 같게 두는 편이 좋습니다. 오답 학습 연결 — 주변 문서의 양을 고정 항목에 넣었다면 독립 변수와 통제 변수 표를 다시 확인합니다.

[중] 3. 긴 입력에서 점수가 한 번 낮게 나왔습니다. 바로 context rot의 증거라고 단정할 수 없는 이유와 추가 기록을 쓰세요.

정답·해설 — 한 번의 결과에는 확률적 변동, 근거 위치, 문서 순서, 호출 순서의 영향이 섞일 수 있습니다. 같은 조건을 반복하고 반복 번호, 근거 위치, 입력 토큰, 실행 순서를 기록해야 합니다. 오답 학습 연결 — 반복만 언급했다면 순서 효과와 위치 조건도 함께 확인합니다.

[상] 4. 세 길이 조건에서 품질 차이가 없었고 입력 토큰과 비용 추정치만 증가했습니다. 타당한 결론과 부당한 결론을 각각 한 문장으로 쓰세요.

정답·해설 — 타당한 결론은 “이번 모델, 과제, 길이 범위, 반복 조건에서는 품질 저하를 관찰하지 못했지만 입력 토큰과 추정 비용은 증가했다”입니다. 부당한 결론은 “context rot는 존재하지 않는다”입니다. 오답 학습 연결 — 현상 미관찰과 보편성 부정을 구분하고, 표본과 실험 범위를 결론에 포함합니다.

10강사 노트

시간 배분 · 시연 순서 · 예상 질문 · 막히는 지점 · A/B 트랙

시간 배분(강의 60분 · 실습 120분) — 강의: context rot의 의미와 근거 수준(15분) · 통제 변수와 독립 변수(15분) · 길이×위치 도식(15분) · 루브릭·토큰·비용 해석(15분). 실습: 기준 조건 구성(20분) · 세 길이 입력 생성(25분) · 세 근거 위치와 반복 실행(35분) · 루브릭 채점과 토큰 기록(25분) · 한계 문장 작성(15분).

시연 순서 — ① 정답 근거 한 줄과 질문을 화면에 고정합니다. ② 주변 문서 조각만 추가하며 사용량의 입력 토큰을 확인합니다. ③ 같은 길이에서 근거를 앞·가운데·뒤로 옮깁니다. ④ 각 조건을 반복하고 결과표에 순서를 기록합니다. ⑤ 품질 저하가 나타난 결과와 나타나지 않은 결과를 모두 보여 주며 결론 문장의 범위를 비교합니다.

예상 질문 — “몇 토큰부터 문제가 생기나요?” → 고정 임계값이 없으며 현재 과제와 모델에서 측정해야 한다고 답합니다. “점수가 같으면 실험이 실패한 것인가요?” → 품질 저하 미관찰도 유효한 결과이며 입력 토큰과 비용 변화는 별도로 남는다고 답합니다. “비용 표와 실제 청구액이 왜 다른가요?” → 단가 계산은 추정이고 캐시, 지역 처리, 별도 도구 비용 등이 실제 청구에 영향을 줄 수 있다고 답합니다.

학생이 자주 막히는 지점 — 문서 조각을 추가하면서 정답 근거를 실수로 수정합니다. 근거 문자열의 해시나 직접 비교로 동일성을 확인하게 합니다. 루브릭을 결과를 본 뒤 바꾸려는 경우에는 실행 전에 기준을 고정한 이유를 다시 설명합니다.

A/B 트랙 — A트랙은 하나의 질문으로 길이 세 조건과 위치 한 조건을 비교합니다. B트랙은 위치 세 조건을 추가하고 실행 순서를 바꾸어 순서 효과를 확인하며, 조건별 평균과 개별 결과를 함께 표시합니다.
