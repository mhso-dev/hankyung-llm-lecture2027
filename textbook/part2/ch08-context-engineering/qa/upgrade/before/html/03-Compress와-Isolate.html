2이 내용을 배우는 이유

02절에서는 긴 자료를 외부 JSON 파일에 기록하고, 질문에 필요한 항목을 선택하여 현재 메시지로 가져왔습니다. 선택한 기록도 여전히 길 수 있습니다. 여러 번 이어진 대화에는 이미 끝난 논의와 반복된 설명이 남습니다. 또한 한 프로그램이 고객 문의와 코드 검토처럼 서로 다른 업무를 처리하면 각 업무의 자료가 한 메시지에 섞일 수 있습니다.

압축(Compress)은 현재 질문에 필요한 사실을 남기고 반복 표현을 줄입니다. 분리(Isolate)는 대출 문의와 휴관 문의처럼 서로 다른 업무의 자료를 나누어, 각 호출에 필요한 묶음만 전달합니다. 두 방법 모두 입력을 줄일 수 있지만 하는 일은 다릅니다. Compress는 한 기록을 짧게 만들고, Isolate는 한 업무의 자료가 다른 업무 메시지에 섞이지 않게 합니다.

이 절에서는 사람이 보존할 항목을 먼저 정한 뒤 요약을 쓰고 원문과 대조합니다. 업무 분리도 사람이 작성한 함수와 메시지 목록으로 수행합니다. 모델이 할 일을 나누거나 다른 모델을 호출하지 않으므로 에이전트나 다중 에이전트 구조가 아닙니다. 모델이 다음 행동을 판단하고 도구를 호출하는 구조는 Ch 20 이후에 배웁니다.

4핵심 개념

비유 — 회의록 요약과 업무별 서류철

긴 회의록을 다음 회의에 그대로 가져가면 결정 사항을 찾는 데 시간이 걸립니다. 결정, 예외, 적용 날짜, 담당 기관, 원문 위치를 한 장에 정리하면 필요한 사실을 빠르게 확인할 수 있습니다. 이것이 Compress에 해당합니다. 한편 인사 문의와 시스템 장애 보고서를 같은 서류철에 넣으면 관련 없는 정보가 판단에 영향을 줄 수 있습니다. 업무별 서류철을 만들고 각 업무에 필요한 문서만 넣는 것이 Isolate에 해당합니다.

정의

Compress (압축)
현재 과업에 필요한 사실을 유지하면서 긴 대화나 문서의 표현을 줄이는 전략입니다. 요약은 원문의 모든 정보를 보존하지 않으므로 원문과 대조할 수 있어야 합니다.
수동 압축 (manual compression)
사람이 보존 항목과 삭제 기준을 먼저 정하고 그 규칙에 따라 요약을 만드는 방식입니다. 이 절에서는 모델에게 자동 요약을 맡기지 않습니다.
정보 손실 (information loss)
압축 과정에서 원문의 사실, 조건, 예외, 관계가 사라지거나 의미가 바뀌는 현상입니다. 짧아진 문장이 자연스럽더라도 중요한 조건이 없어졌다면 잘못된 압축입니다.
Isolate (분리)
서로 다른 작업이나 자료 묶음이 영향을 주지 않도록 컨텍스트를 나누는 전략입니다. 이 절에서는 업무별로 독립된 메시지 목록을 구성합니다.
독립 메시지 (independent message set)
대출 문의라면 대출 지시·질문·근거만 넣는 식으로, 한 업무의 자료만 담아 따로 만든 메시지 목록입니다. 다른 업무의 기록이 필요하면 프로그램 코드가 그 기록을 골라 추가해야 합니다.
경계 (boundary)
어느 자료를 어느 업무 메시지에 넣을지 정하는 규칙입니다. 텍스트 구분선은 사람이 읽기 좋게 나눌 뿐입니다. 사용 권한을 검사하거나 데이터 접근을 막지는 못합니다.

압축에서 반드시 보존할 항목을 먼저 정합니다

압축을 “짧게 다시 쓰기”로만 이해하면 중요한 조건이 사라집니다. 먼저 보존 항목을 정한 뒤 각 항목이 요약에 남았는지 검사해야 합니다. 이 절에서는 결정, 예외, 날짜, 기관, 출처 식별자를 최소 보존 항목으로 사용합니다. 과업에 따라 금액, 단위, 승인자, 버전이 추가될 수 있습니다.

보존 항목삭제될 때 생기는 문제검사 질문
결정무엇을 해야 하는지 알 수 없음최종 결정이 분명한가?
예외일반 규칙을 모든 경우에 잘못 적용규칙이 적용되지 않는 조건이 남았는가?
날짜이전 값과 현재 값을 구분하지 못함결정일과 적용일이 구분되는가?
기관·대상다른 조직이나 대상에 잘못 적용누구에게 적용되는지 분명한가?
출처 식별자원문을 다시 찾아 검증할 수 없음각 핵심 사실을 원문과 연결할 수 있는가?

압축본에는 수동으로 압축한 기록임을 명시합니다. 이 표시는 압축본이 원문과 동일한 문서가 아니며, 누락 가능성을 검토해야 한다는 신호가 됩니다. 원문 식별자도 함께 보존합니다. 중요한 판단을 내릴 때는 압축본만 읽고 끝내지 않고 해당 출처의 원문을 다시 확인할 수 있어야 합니다.

압축 품질은 길이가 아니라 의미 보존으로 확인합니다

압축률이 높다고 좋은 결과가 되는 것은 아닙니다. 핵심 결정 한 줄만 남기고 예외와 적용 날짜를 삭제하면 문장은 짧지만 잘못된 행동을 유도합니다. 반대로 반복 표현을 제거하고 같은 뜻의 문장을 합치면서 조건과 출처를 유지했다면 길이가 조금 길어도 목적에 맞는 압축입니다.

검토는 원문과 압축본을 나란히 놓고 수행합니다. 압축본의 각 주장에 대응하는 원문 위치를 찾습니다. 원문에는 있으나 압축본에서 빠진 예외와 날짜를 찾습니다. 압축본에 원문보다 강한 표현이 추가되지 않았는지도 확인합니다. 예를 들어 “검토를 권장한다”를 “반드시 승인한다”로 바꾸면 요약이 아니라 의미 변경입니다.

Isolate는 업무마다 필요한 자료만 전달합니다

한 프로그램이 두 업무를 순서대로 처리한다고 가정합니다. 고객 문의 메시지에는 고객 정책과 문의 내용이 필요합니다. 코드 검토 메시지에는 코드, 검토 기준, 변경 요구가 필요합니다. 두 자료 묶음을 하나의 긴 메시지에 함께 넣으면 모델은 관련 없는 기관명이나 지시를 답에 반영할 수 있습니다.

Isolate에서는 업무별 입력을 처음부터 별도로 구성합니다. 고객 문의 함수는 고객 문의 자료만 받아 메시지를 만들고, 코드 검토 함수는 코드 검토 자료만 받아 다른 메시지를 만듭니다. 두 함수의 호출 순서는 프로그램에 고정되어 있습니다. 함수가 독립되어 있어도 모델이 실행 순서나 도구 사용을 결정하지 않으므로 에이전트라고 부르지 않습니다.

텍스트 태그는 보안 격리가 아닙니다

메시지 안에 <customer>와 <code_review> 같은 태그를 붙이면 제목표처럼 자료의 종류를 표시할 수 있습니다. 그러나 두 자료는 여전히 같은 호출 입력에 들어가므로 모델이 모두 읽을 수 있습니다. 태그는 한쪽 자료를 읽지 못하게 막는 장치가 아닙니다. 민감한 자료를 보호하려면 프로그램이 사용 권한을 검사하고, 자료를 별도 저장소와 별도 호출로 나누며, 로그에 남길 항목도 제한해야 합니다. 이런 실제 접근 제한을 보안 격리라고 합니다.

따라서 이 절에서 “분리했다”는 말은 독립된 메시지 목록을 구성했다는 뜻입니다. 같은 메시지에 태그만 붙인 상태를 보안 격리라고 설명하지 않습니다. 태그를 사용하더라도 프로그램이 각 업무에 필요하지 않은 자료를 호출 전에 제외해야 합니다.

도식 — 줄이는 일과 나누는 일

요약할 내용을 고르는 판단과 문자열 조립

이 실습의 compress(record)는 긴 원문을 읽어 요약을 생성하는 함수가 아닙니다. 사람이 미리 고른 사실·조건·예외·출처를 담은 딕셔너리를 받아 네 항목을 한 문자열로 연결합니다. loan_original에서 무엇을 남길지는 loan 딕셔너리를 작성한 사람이 결정했습니다. 함수 이름에 압축이라는 말이 있어도 모델 요약 호출이 추가되는 것은 아닙니다.

set(required) - record.keys()는 필요한 키 중 입력에 없는 키를 구합니다. 빈 집합이면 네 키가 있다는 뜻입니다. 값이 빈 문자열인지, 원문을 정확히 옮겼는지까지 검사하지는 않습니다. 아래에서는 문자열 길이와 특정 조건의 포함 여부를 함께 보지만, 의미가 보존되었는지는 원문과 네 항목을 대조해서 확인합니다.

회의 기록의 “금요일 배포, 단 검토가 완료된 경우”를 “금요일 배포”로 줄이면 조건부 계획을 확정 일정처럼 바꾸게 됩니다. 도서관 연장 규정에서 예약 조건을 지우는 문제와 같은 원리입니다. 업무별 입력 목록을 나누어도 요약 자체의 오류는 남을 수 있으므로, 자료 분리와 의미 보존을 각각 확인해야 합니다.

2. 사실·조건·예외·출처를 보존합니다

길이만 줄이면 중요한 예외를 잃을 수 있습니다. 네 필드를 모두 확인한 뒤 한 줄로 압축합니다.

compress(record)의 입력은 사람이 이미 골라 적은 네 항목의 딕셔너리이고 반환값은 이를 연결한 문자열입니다. 원문을 자동 요약하거나 모델을 호출하는 함수가 아닙니다. set(required) - record.keys()는 빠진 키를 찾으며, 각 값의 진실성이나 원문과의 일치까지 검사하지 않습니다.

회의 기록에서 “검토가 완료되면 금요일 배포”를 “금요일 배포”로 줄이면 적용 조건이 사라집니다. 아래 대출 규정도 같은 관점으로 원문과 조건을 비교합니다. 이후 서로 다른 메시지 목록을 만드는 작업은 입력 자료를 나누는 것으로, 운영체제의 접근 권한이나 보안 격리를 설정하지 않습니다.

In [4]:
# record는 사실·조건·예외·출처를 가진 사전입니다.
# required 튜플은 압축 결과의 필드 순서를 고정합니다.
def compress(record: dict[str, str]) -> str:
    required = ("fact", "condition", "exception", "source")
    missing = set(required) - record.keys()

    if missing:
        raise ValueError(f"빠진 필드: {sorted(missing)}")

    parts = []
    for key in required:
        parts.append(f"{key}: {record[key]}")

    return " | ".join(parts)

압축할 원본을 준비합니다

긴 원문을 읽고 답에 필요한 사실·조건·예외·출처를 짧은 사전에 옮깁니다. 다음 셀에서 원문과 압축 결과의 길이를 비교합니다.

In [5]:
# loan_original은 반복 설명이 있는 원문이고 loan은 남길 내용만 정리한 사전입니다.
loan_original = (
    "미르시립도서관 일반 회원 한 명은 일반자료를 모두 합해 7권까지 빌릴 수 있습니다. "
    "기본 대출 기간은 빌린 날부터 14일입니다. "
    "다른 회원의 예약이 들어오지 않은 자료만 1회에 한해 7일 연장할 수 있습니다. "
    "이 규정의 출처는 E01 문서 3쪽입니다."

    "fact": "7권을 14일 대출",
    "condition": "회원 1명 기준",

compressed에는 네 필드가 정해진 순서로 연결됩니다. 원문보다 짧으면서 조건이 남았는지 확인합니다.

7주의할 점과 실무 메모

  • 압축본을 원문으로 취급하지 않습니다. 수동 압축 표시, 생성 날짜, 원문 출처 식별자를 함께 남깁니다.
  • 수치와 단위를 함께 보존합니다. 금액, 기간, 비율을 남기면서 단위를 삭제하면 의미가 달라질 수 있습니다.
  • 날짜의 역할을 구분합니다. 문서 작성일, 결정일, 적용 시작일, 종료일은 서로 다른 값입니다. 압축 과정에서 하나의 ‘날짜’로 합치지 않습니다.
  • 태그를 접근 제어로 사용하지 않습니다. 같은 호출에 포함된 정보는 모델 입력에 전달됩니다. 민감한 정보는 애플리케이션에서 호출 전에 제외합니다.
  • 분리된 함수가 자동으로 에이전트가 되지는 않습니다. 사람이 정한 순서대로 고정 함수가 실행되고 모델이 흐름을 바꾸지 않는다면 일반 프로그램 흐름입니다.
  • 압축과 선택의 순서는 자료에 따라 정합니다. 오래된 대화 기록을 먼저 압축한 뒤 필요한 결정을 선택할 수 있고, 여러 문서 중 필요한 문서를 먼저 선택한 뒤 그 문서만 압축할 수도 있습니다. 어느 순서를 사용했는지 실행 기록에 남깁니다.

8정리와 다음 절

  • Compress는 표현을 줄이되 결정·예외·날짜·기관·출처를 보존하며, 압축본임을 명시합니다.
  • Isolate는 서로 다른 업무마다 독립 메시지를 구성하여 필요한 자료만 전달합니다.
  • 텍스트 태그는 보안 격리가 아니며, 고정 함수의 분리는 에이전트 판단을 뜻하지 않습니다.

다음 학습과 이어지는 지점 — 다음 절에서는 컨텍스트가 잘못된 정보, 과도한 자료, 관련 없는 자료, 서로 맞지 않는 정보 때문에 답에 어떤 문제가 생기는지 비교합니다. Ch 9에서는 Select를 자동 검색으로 확장하지만, 검색 결과가 길면 Compress가 필요하고 서로 다른 질문을 처리할 때는 Isolate로 자료 묶음을 나눕니다.

9복습 문제

문제 4개 · 해설 포함

[하] 1. Compress와 Isolate의 목적을 각각 한 문장으로 쓰세요.

정답과 해설 — Compress는 한 자료 묶음에서 과업에 필요한 사실을 남기며 표현을 줄입니다. Isolate는 서로 다른 작업의 자료 묶음을 나누어 각 호출에 필요한 자료만 전달합니다. 틀렸다면 이 절의 핵심 개념 ‘정의’를 다시 봅니다.

[중] 2. 규정 요약에서 결정만 남기고 예외와 적용 날짜를 삭제했을 때 생길 수 있는 오류를 설명하세요.

정답과 해설 — 일반 규칙을 예외 대상에 잘못 적용하거나, 이전 결정을 현재 규정으로 잘못 사용할 수 있습니다. 압축 전 보존 항목을 정하고 원문과 대조해야 합니다. 틀렸다면 이 절의 핵심 개념 ‘압축에서 반드시 보존할 항목을 먼저 정합니다’를 다시 봅니다.

[중] 3. 한 메시지 안에서 두 자료를 텍스트 태그로 나누었는데도 보안 격리라고 할 수 없는 이유는 무엇입니까?

정답과 해설 — 두 자료가 같은 호출 입력에 포함되어 모델에 함께 전달되기 때문입니다. 태그는 구조를 표시하지만 접근 권한을 강제하지 않습니다. 틀렸다면 이 절의 핵심 개념 ‘텍스트 태그는 보안 격리가 아닙니다’를 다시 봅니다.

[상] 4. 도서관 대출 질문과 휴관 질문을 처리하는 고정 프로그램을 설계할 때, 분리 규칙과 에이전트가 아닌 이유를 함께 설명하세요.

정답과 해설 — 대출 질문 호출에는 대출 규정·질문·해당 출처만 넣고, 휴관 질문 호출에는 휴관 안내·질문·해당 출처만 넣습니다. 두 메시지 목록을 분리하고 호출 전에 허용 자료를 검사합니다. 실행 순서와 자료 선택을 사람이 코드에 고정하며 모델이 흐름이나 도구 사용을 결정하지 않으므로 에이전트가 아닙니다. 틀렸다면 이 절의 핵심 개념 ‘Isolate는 업무마다 필요한 자료만 전달합니다’를 다시 봅니다.
