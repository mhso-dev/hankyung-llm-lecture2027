2이 내용을 배우는 이유

Ch 6에서는 언어 모델에 메시지를 보내고 답을 받는 기본 호출을 배웠고, Ch 7에서는 지시와 예시를 배치하여 프롬프트를 구성했습니다. 이제 자료를 더 많이 넣으면 답이 언제나 좋아지는지 살펴볼 차례입니다. 모델이 한 번에 참고할 수 있는 범위에는 한도가 있습니다. 질문, 지시, 대화 기록, 문서, 도구 결과, 그리고 모델이 작성할 답까지 모두 같은 한도 안에서 자리를 사용합니다.

컨텍스트 엔지니어링은 모델에게 어떤 자료를 얼마나 보낼지 정하는 일입니다. 질문에 필요하다는 이유만으로 자료를 계속 추가할 수는 없습니다. 답에 필요한 자료를 정해진 토큰 수 안에 배치해야 합니다. 이 절에서는 먼저 토큰 예산표를 만듭니다. 다음 절에서는 긴 자료를 저장하고 필요한 부분을 선택하며, 03절에서는 내용을 줄이거나 업무별로 나눕니다. Ch 9에서는 이 장의 선택(Select)을 검색 코드로 확장합니다.

아직 에이전트를 만들지는 않습니다. 이 장의 흐름과 선택 기준은 모두 사람이 코드에 고정합니다. 어떤 자료를 포함할지 모델이 스스로 판단하고 도구를 호출하는 단계는 Ch 20부터 다룹니다.

3앞에서 배운 내용

Ch 6에서는 시스템 역할과 사용자 역할을 구분한 메시지 목록을 모델에 전달했습니다. 이 절에서는 특정 함수 이름을 가정하지 않고, 모델 호출에는 역할이 붙은 메시지가 입력된다는 개념만 사용합니다. Ch 7에서는 지시, 예시, 출력 형식을 프롬프트 안에 배치했습니다. 그 요소들도 모두 입력 공간을 차지합니다.

4핵심 개념

비유 — 작업 전에 책상 자리를 나눕니다

넓이가 정해진 책상에서 자료를 검토한다고 생각해 봅시다. 책상 전체가 모델의 최대 작업 공간입니다. 업무 지시서, 질문지, 참고 문서, 이전 대화 기록이 책상 위에 놓입니다. 마지막에는 답안지를 펼칠 자리도 남아 있어야 합니다. 자료로 책상을 가득 채우면 답안지를 놓을 공간이 부족해집니다. 따라서 자료를 올리기 전에 답안지 자리와 예상하지 못한 추가 자료를 위한 자리를 먼저 확보합니다.

정의

컨텍스트 (context)
모델이 현재 답을 만들 때 참고하도록 전달된 정보 전체입니다. 시스템 지시, 사용자 질문, 대화 기록, 예시, 문서와 도구 결과가 포함될 수 있습니다. 외부 파일에 존재하지만 호출 메시지에 실리지 않은 내용은 현재 컨텍스트가 아닙니다.
컨텍스트 윈도 (context window)
한 번의 모델 호출에서 처리할 수 있는 입력과 출력의 전체 범위입니다. 모델마다 최대 한도가 다를 수 있으며, 같은 모델도 사용하는 API와 설정에 따라 적용 조건을 확인해야 합니다.
토큰 (token)
모델이 텍스트를 처리하는 단위입니다. 토큰은 글자나 단어와 일치하지 않습니다. 같은 글자 수라도 언어, 숫자, 공백, 기호의 구성에 따라 토큰 수가 달라질 수 있습니다.
토큰 예산 (token budget)
이번 작업에서 사용할 수 있도록 사람이 정한 토큰 상한입니다. 모델이 허용하는 최대 한도와 별개이며, 비용·지연 시간·답의 안정성을 고려하여 더 작은 값으로 정할 수 있습니다.
출력 예약분 (output reservation)
모델이 답을 생성할 공간으로 미리 남겨 두는 토큰 수입니다. 추론 과정에 별도 토큰이 사용되는 모델이나 설정에서는 문서에 명시된 계산 방식에 따라 해당 사용분도 함께 고려합니다.
여유분 (safety margin)
토큰 추정 오차, 추가 지시, 도구 결과처럼 실행 중 늘어날 수 있는 내용을 수용하려고 비워 두는 공간입니다.
사용량 메타데이터 (usage metadata)
LangChain 응답 객체의 AIMessage.usage_metadata에 붙는 사용량 정보입니다. 입력, 출력, 전체 토큰 수가 들어갑니다. 모델 제공자가 이 정보를 보내지 않았다면 0토큰을 썼다는 뜻이 아니므로, 값이 없는 상태로 실행 기록을 완료하지 않습니다.

예산은 최대 한도보다 작게 정합니다

모델 최대 한도는 기술적으로 허용되는 범위이고, 수업 예산은 이번 실습에서 지킬 운영 기준입니다. 최대 한도가 크더라도 모든 호출에 그만큼의 입력을 사용할 이유는 없습니다. 긴 입력은 비용과 처리 시간을 늘리고, 서로 관련이 적은 자료가 함께 들어가면 모델이 필요한 근거를 찾기 어려워질 수 있습니다. 수업 예산은 실습 결과를 비교하기 위한 공통 조건이기도 합니다.

입력에 사용할 수 있는 범위는 다음 순서로 정합니다. 먼저 이번 호출의 전체 예산을 정합니다. 그다음 원하는 답의 길이를 고려하여 출력 예약분을 제외합니다. 이 장의 노트북은 init_chat_model()의 max_tokens=300으로 생성 상한을 설정합니다. 모델 제공자가 추론 토큰을 별도로 집계하는지는 반환된 메타데이터와 공식 문서에서 확인합니다. 마지막으로 추정 오차와 실행 중 추가되는 메시지를 위한 여유분을 제외합니다. 남은 범위 안에서 시스템 지시, 질문, 대화 기록, 참고 문서를 배분합니다.

출력 예약분답이 완결되려면 어느 정도의 생성 공간이 필요한가?입력 자료를 넣기 전에 제외

문자 수와 토큰 수는 같은 값이 아닙니다

문자 수는 편집기에서 세기 쉽지만 모델의 처리 단위는 토큰입니다. 따라서 “문서가 2,000자이므로 2,000토큰이다”라고 계산할 수 없습니다. 한국어 조사와 어미, 영문 약어, 숫자, 코드 기호가 섞이면 분할 결과가 달라집니다. Ch 5에서 확인한 텍스트 분할 규칙은 모델마다 다를 수 있으므로 다른 모델의 계산기를 그대로 적용해서도 안 됩니다.

실습에서는 두 값을 따로 기록합니다. 호출 전에는 해당 모델에 맞는 로컬 계산 도구로 추정 토큰 수를 구합니다. 호출 후에는 API 응답의 실제 사용량을 저장합니다. 두 값이 다르다고 계산 오류라고 단정할 수는 없습니다. 로컬 도구는 시스템·사용자 역할 표시처럼 API가 메시지에 덧붙이는 형식과 서비스 내부 처리를 모두 똑같이 계산하지 못할 수 있습니다. 호출 전 예산 검사에는 넉넉하게 계산한 추정값을 사용하고, 비용과 실행 기록에는 API가 반환한 실제 값을 사용합니다.

도식 — 한도 안에서 자리를 먼저 확보합니다

입력 예산 계산과 실제 호출 설정

input_budget(total, output_reserve, safety_margin)는 세 정수를 받아 입력에 배정할 토큰 수 하나를 반환하는 Python 함수입니다. 여기서 total=4096은 실습에서 정한 전체 배정량입니다. 사용 모델의 실제 최대 컨텍스트를 조회한 값이 아닙니다. return은 계산값을 호출한 위치로 반환하고, 음수이면 raise ValueError가 잘못된 배정을 알립니다.

출력 예약량을 300에서 600으로 늘리는 비교는 입력에 남는 공간이 300만큼 줄어드는 산술 관계를 확인합니다. 이 함수의 인자를 바꿔도 앞에서 만든 모델 객체의 max_tokens=300은 바뀌지 않습니다. 모델 출력 상한까지 바꾸어 실험하려면 모델 설정도 별도로 변경해야 합니다.

한 줄 분류 라벨을 받는 과제와 세 문단 설명을 받는 과제는 필요한 출력 공간이 다릅니다. 같은 전체 배정량에서 설명에 공간을 더 주면 입력 자료를 더 선별해야 합니다. 반대로 출력 공간을 너무 작게 정하면 중요한 단서가 입력에 있어도 답이 완성되기 전에 잘릴 수 있습니다. 실제 요청을 설계할 때는 필요한 답의 형태를 먼저 정하고 입력과 출력 배정을 함께 확인합니다.

1. API 연결 준비

아래 셀은 현재 작업 폴더에서 상위 폴더로 올라가며 .env를 찾습니다. 키 값은 화면에 출력하지 않습니다.

In [2]:
# find_dotenv는 현재 폴더부터 상위 폴더를 검색해 .env 경로를 찾습니다.
import os

from dotenv import find_dotenv, load_dotenv

# usecwd=True는 노트북을 실행한 폴더를 검색 시작점으로 지정합니다.
# 키 값은 출력하지 않고 존재 여부만 확인합니다.
env_path = find_dotenv(usecwd=True)
if not env_path:
    raise FileNotFoundError("현재 폴더의 상위 경로에서 .env를 찾지 못했습니다.")
load_dotenv(env_path)
if not os.getenv("OPENAI_API_KEY"):
    raise RuntimeError(".env에 OPENAI_API_KEY가 없습니다.")
print(".env와 API 키 확인 완료")
출력:
.env와 API 키 확인 완료

모델 객체를 만듭니다

.env 확인이 끝난 뒤 모델 이름과 출력 제한을 지정합니다. 이 셀은 아직 API에 질문을 보내지 않습니다.

# init_chat_model은 provider:model 형식으로 채팅 모델 객체를 만듭니다.

2. 출력 공간을 먼저 예약합니다

전체 예산에서 출력 예약분과 안전 여유를 빼면 입력에 사용할 수 있는 범위가 나옵니다.

input_budget()는 직접 작성하는 산술 함수입니다. 세 인자를 빼서 입력 배정량 하나를 반환하며 모델을 호출하지 않습니다. total=4096은 수업에서 정한 배정량입니다. 모델의 최대 컨텍스트를 조회한 결과로 읽지 않습니다.

한 줄 분류와 여러 문단 설명은 필요한 출력 공간이 다릅니다. 뒤에서 출력 예약량을 600으로 바꾸는 셀은 입력 배정량의 감소만 계산합니다. 앞의 모델 객체에 지정한 max_tokens=300을 변경하지는 않습니다.

In [4]:
# total은 전체 한도, output_reserve는 답변용 예약분입니다.
# safety_margin은 토큰 추정 오차를 위한 여유입니다.
def input_budget(total: int, output_reserve: int, safety_margin: int) -> int:
    available = total - output_reserve - safety_margin

    if available < 0:
        raise ValueError("출력 예약분과 여유가 전체 예산보다 큽니다.")

    return available

세 값을 넣어 반환값을 확인합니다

전체 한도 4096에서 출력 예약분 300과 안전 여유 128을 뺍니다. 반환된 숫자는 available에 저장됩니다.

In [5]:
# 세 인자는 함수 정의에 적힌 순서대로 전달합니다.
available = input_budget(4096, 300, 128)
print("입력에 사용할 수 있는 토큰:", available)
출력:
입력에 사용할 수 있는 토큰: 3668

3. 로컬 추정값을 확인합니다

토크나이저는 문장을 모델이 세는 작은 단위인 토큰으로 나누어, 호출 전에 입력 크기를 추정합니다. 실제 호출 뒤에는 응답 객체의 AIMessage.usage_metadata에서 제공자가 센 토큰 수를 확인합니다.

In [6]:
# question은 질문이고 evidence는 답변 근거입니다.
import tiktoken

question = "미르시립도서관의 정기 휴관일은 언제인가요?"
evidence = "[E01 p.2] 정기 휴관일은 매주 월요일입니다."
prompt = f"""근거:
{evidence}

질문: {question}"""
print(prompt)
출력:
근거:
[E01 p.2] 정기 휴관일은 매주 월요일입니다.

질문: 미르시립도서관의 정기 휴관일은 언제인가요?

같은 문자열을 토큰으로 바꿉니다

encode()는 문자열을 토큰 ID 목록으로 반환합니다. 목록 길이를 세어 호출 전 입력 크기를 추정합니다.

get_encoding("o200k_base")는 지정한 토큰화 규칙을 불러오고 encode(prompt)는 문자열을 토큰 ID 목록으로 바꿉니다. 여기서 세는 대상은 prompt 문자열뿐입니다. 뒤의 system 메시지와 메시지 형식까지 포함한 실제 입력 사용량은 응답의 usage_metadata에서 따로 확인합니다.

In [7]:
# 실제 API 입력에는 system 메시지와 채팅 형식용 토큰도 더해집니다.
encoding = tiktoken.get_encoding("o200k_base")
token_ids = encoding.encode(prompt)
estimated = len(token_ids)
print("로컬 추정 입력 토큰:", estimated)
print("예산 안에 있음:", estimated <= available)
출력:
로컬 추정 입력 토큰: 42
예산 안에 있음: True

4. 실제 API 사용량을 비교합니다

AIMessage.text와 usage_metadata를 함께 확인합니다. 출력은 실행마다 달라질 수 있습니다.

모델에 전달할 메시지를 만듭니다

system에는 답변 규칙을, user에는 앞에서 만든 질문을 넣습니다. 셀을 실행한 뒤 역할 순서를 확인합니다.

In [8]:
# messages는 역할과 내용을 짝지은 목록입니다.
# system 지시를 user 질문보다 먼저 둡니다.
messages = [
    ("system", "근거에 있는 정보만 사용하고 출처를 표시하세요."),
    ("user", prompt),
]
roles = []
for role, content in messages:
    roles.append(role)
print("메시지 역할:", roles)
출력:
메시지 역할: ['system', 'user']

모델을 한 번 호출합니다

invoke()의 반환값은 AIMessage입니다. 사용량 정보가 없으면 이후 비교를 할 수 없으므로 즉시 오류를 냅니다.

In [9]:
# response는 모델의 답과 메타데이터를 가진 AIMessage입니다.
response = model.invoke(messages)
usage = response.usage_metadata

if usage is None:
    raise RuntimeError("모델 사용량 메타데이터가 없습니다.")

답과 실제 토큰 수를 관찰합니다

먼저 답변 원문을 읽고, 다음 두 줄에서 API가 보고한 입력·출력 토큰 수를 확인합니다. 답변 문구와 수치는 실행마다 달라질 수 있습니다.

In [10]:
# text는 답변 문자열이고 usage는 실제 호출의 토큰 사용량입니다.
print(response.text)
print("input_tokens:", usage.get("input_tokens"))
print("output_tokens:", usage.get("output_tokens"))
출력:
미르시립도서관의 정기 휴관일은 **매주 월요일**입니다. [E01 p.2]
input_tokens: 66
output_tokens: 32

5. 출력 예약분 한 값만 바꿔 비교합니다

전체 한도와 안전 여유는 유지하고 출력 예약분만 300에서 600으로 늘립니다. 입력 예산이 얼마나 줄어드는지 확인합니다.

In [11]:
# 두 호출은 output_reserve 값 하나만 다릅니다.
base_budget = input_budget(4096, 300, 128)
changed_budget = input_budget(4096, 600, 128)
print("기본 입력 예산:", base_budget)
print("변경 입력 예산:", changed_budget)
print("차이:", changed_budget - base_budget)
출력:
기본 입력 예산: 3668
변경 입력 예산: 3368
차이: -300

정리

출력 공간을 먼저 예약하고, 입력을 로컬에서 추정한 뒤, 실제 사용량은 API 응답에서 확인합니다.

확인할 점 — 실습 파일은 labs/part2/ch08-context-engineering/notebooks/01-컨텍스트와-토큰-예산.ipynb입니다. 새 커널에서 설명과 코드를 번갈아 읽으며 기본 예산, 로컬 추정값, 실제 사용량 순서로 확인합니다. 마지막 비교에서는 출력 예약분만 300에서 600으로 바꿉니다.

6일부러 실패해 보기

왼쪽에서는 수업에서 정한 작업 예산이 너무 작아 준비한 500토큰 입력의 허용량을 계산하지 못합니다. 오른쪽에서는 모델의 최대 한도는 바꾸지 않고 작업 예산만 4,096토큰으로 고칩니다. 출력 예약분과 여유분을 빼고 남은 3,668토큰 안에 같은 입력이 들어가는지 확인합니다.

앞의 실행 예제를 실행한 같은 노트북에서 Before 다음 After 순서로 실행합니다. 출력은 실제 실행 결과입니다.

Before — 실패 코드

실패 재현: 출력 공간을 남기지 않습니다

전체 예산보다 출력 예약분과 여유를 크게 설정하면 준비한 입력을 넣을 공간이 없습니다. 같은 입력 길이를 수정 전후 허용량과 비교합니다.

In [12]:
# planned_input은 모델에 넣으려는 입력의 길이입니다.
# 잘못된 전체 예산에서는 입력 허용량을 계산할 수 없습니다.
planned_input = 500
bad_total = 300
try:
    bad_available = input_budget(bad_total, 300, 128)
except ValueError as error:
    print("관찰한 실패:", error)
    print("준비한 입력 토큰:", planned_input, "> 허용량 없음")
else:
    raise AssertionError("예산 오류가 발생해야 합니다.")
출력:
관찰한 실패: 출력 예약분과 여유가 전체 예산보다 큽니다.
준비한 입력 토큰: 500 > 허용량 없음

After — 수정 코드

수정: 전체 예산을 복원합니다

같은 500토큰 입력은 유지합니다. 모델 한도를 바꾸는 것이 아니라 수업에서 정한 작업 예산을 4,096토큰으로 고친 뒤 입력 허용량 안에 들어가는지 확인합니다.

In [13]:
# 입력 길이는 그대로 두고 전체 예산만 복원합니다.
# 출력 예약분과 여유를 빼도 500토큰 입력을 넣을 수 있어야 합니다.
fixed_total = 4096
fixed_available = input_budget(fixed_total, 300, 128)
assert fixed_available == 3668
assert planned_input <= fixed_available
print("준비한 입력 토큰:", planned_input)
print("수정 후 입력 허용량:", fixed_available)
print("입력 가능:", planned_input <= fixed_available)
출력:
준비한 입력 토큰: 500
수정 후 입력 허용량: 3668
입력 가능: True

7주의할 점과 실무 메모

  • 최대 한도를 운영 목표로 사용하지 않습니다. 모델이 받을 수 있는 최대량과 서비스가 매 호출에 사용하도록 허용할 양은 다릅니다. 팀에서는 비용과 지연 시간 기준을 포함한 별도의 예산을 정합니다.
  • 출력 제한을 나타내는 코드 인자의 뜻을 확인합니다. 사용하는 모델과 API 버전에 따라 출력 토큰과 추론 토큰을 세는 방식이 다를 수 있습니다. 수업 코드에 고정된 SDK 버전의 공식 문서를 기준으로 해석합니다.
  • 사용량 정보가 언제 제공되는지 확인합니다. 일반 응답과 스트리밍 응답은 사용량 정보의 위치나 제공 조건이 다를 수 있습니다. 값이 없을 때 0으로 기록하면 실제 사용량이 없었다는 잘못된 뜻이 됩니다.
  • 한국어와 코드를 각각 측정합니다. 같은 문자 수라는 이유로 같은 토큰 수를 가정하지 않습니다. 실제 서비스 자료의 언어와 형식을 반영한 표본으로 예산을 검증합니다.
  • 민감한 원문은 사용량 기록에 포함하지 않습니다. 운영 로그에는 토큰 수와 문서 식별자 등 필요한 정보만 남기고, 개인 정보나 비밀 값이 포함된 메시지 원문은 별도 정책에 따릅니다.

8정리와 다음 절

  • 컨텍스트는 현재 호출에서 모델에 전달된 정보이며, 외부에 존재하기만 하는 자료는 포함되지 않습니다.
  • 토큰 예산은 모델 최대 한도와 별도로 정하고, 출력 예약분과 여유분을 먼저 확보합니다.
  • 문자 수, 로컬 추정 토큰, API 실제 사용량은 서로 다른 값으로 기록합니다.

9복습 문제

문제 4개 · 해설 포함

[하] 1. 외부 JSON 파일에 저장되어 있지만 호출 메시지에 포함되지 않은 문서는 현재 컨텍스트입니까?

정답과 해설 — 아닙니다. 현재 컨텍스트는 모델이 이번 답을 만들 때 받도록 전달된 정보입니다. 파일은 저장된 자료이며, 읽어서 메시지에 포함해야 컨텍스트가 됩니다. 틀렸다면 이 절의 핵심 개념 ‘정의’를 다시 봅니다.

[중] 2. 전체 예산에서 입력 가용분을 정하는 순서를 설명하세요.

정답과 해설 — 전체 수업 예산을 정한 뒤 출력 예약분을 제외하고, 추정 오차와 추가 메시지를 위한 여유분을 제외합니다. 남은 범위를 지시·질문·기록·문서에 배분합니다. 틀렸다면 이 절의 핵심 개념 ‘예산은 최대 한도보다 작게 정합니다’를 다시 봅니다.

[중] 3. 로컬 토큰 추정값과 API 실제 사용량을 따로 기록해야 하는 이유를 쓰세요.

정답과 해설 — 로컬 계산기는 시스템·사용자 역할 표시처럼 API가 메시지에 덧붙이는 형식과 서비스 내부 처리를 모두 똑같이 계산하지 못할 수 있습니다. 추정값은 호출 전 예산 검사에, API 값은 실행 뒤 사용량 기록에 사용합니다. 틀렸다면 이 절의 핵심 개념 ‘문자 수와 토큰 수는 같은 값이 아닙니다’를 다시 봅니다.

[상] 4. 모델 최대 한도가 충분히 큰데도 팀이 더 작은 수업 예산을 정해야 하는 이유를 세 가지 제시하세요.

정답과 해설 — 비용과 지연 시간을 관리하고, 관련성이 낮은 자료가 함께 들어오는 것을 줄이며, 실습 결과를 같은 조건에서 비교하기 위해서입니다. 답에는 최대 한도와 운영 예산의 역할이 다르다는 설명이 포함되어야 합니다. 틀렸다면 ‘이 내용을 배우는 이유’와 이 절의 핵심 개념 ‘예산은 최대 한도보다 작게 정합니다’를 다시 봅니다.
