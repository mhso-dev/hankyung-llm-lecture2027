작성일: 2026-09-08. 대상: `textbook/part2/ch08-context-engineering/`와 `labs/part2/ch08-context-engineering/`.

## 구성

커리큘럼 v6의 Context Engineering 기초 16시간(강의 6·실습 10)을 6개 절로 나누었습니다. 각 절은 학습 목표부터 참고 자료까지 11개 고정 블록, 해설을 포함한 복습 문제 4개, 접이식 강사 노트를 포함합니다. Ch 9 첫 절과 공통 HTML 빌드·도식 생성 구조를 참고했습니다. Ch 9 파일은 수정하지 않았습니다.

원본은 `_src/*.html`이며 `_build.py`가 완성 HTML을 생성합니다. 교재의 코드는 실습 파일에서 직접 가져오며, 함수 발췌와 실행 결과가 원본과 일치하는지 `checks/content.py`로 확인합니다. 코드 파일과 결과 파일이 없으면 빌드가 실패하도록 구성했습니다.

- 환경: uv·Python 3.12, 챕터별 `pyproject.toml`과 `uv.lock`. 잠금 파일 일치 검사 통과, Ruff 통과, 테스트 16개 통과(2026-09-08).
- 내용 검사: 6절의 고정 블록 11개와 복습 문제 24개, 내부 링크, 미치환 표시, 금지 표현을 검사했습니다. 코드 블록 13개와 실제 실습 파일, 실행 출력 6개와 저장된 표준 출력이 일치합니다. 본문에서 발췌한 모델 응답도 실행 로그와 대조했습니다. 결과: `checks/content-results.json`.
- 실행 기록: 최종 보존 로그의 모델 호출 46건 모두 `completed`입니다. 사용량과 캐시 입력 단가를 반영한 비용 계산을 전수 재계산했습니다. 최종 표본의 사용량 기준 추정 비용 합계는 $0.06123135이며, 재실행을 포함한 전체 집필 세션의 청구액이 아닙니다. 결과: `checks/log-results.json`.
- 응답 정독: 실패 조건 15건·길이/위치 실험 27건·설계 비교 3건을 읽고 사실·출처·응답 내부 모순을 판정했습니다. 기록: `checks/manual-review.json`. 실패 조건 15건은 최종 채점 함수로 다시 판정하여 저장된 결과와 일치함을 확인했습니다.
- 기록 정정: 실패 실험 기준선 3건에 잘못 붙은 합성 자료 식별자를 입력 원문과 대조하여 수정했습니다. 기존 값과 수정 이유를 각 행의 `metadata_correction`에 보존했으며 응답·사용량·평가값은 바꾸지 않았습니다.
- 화면 검사: Chromium에서 목차와 6절을 1280px·390px로 열어 14건 모두 통과했습니다. 본문/보조 글자 크기, 명암 대비, 잘림·컨테이너 밖 텍스트, SVG 경계·글자 크기, 가로 넘침, 이미지 로딩을 검사했습니다. 데스크톱 목차와 모바일 첫 절의 화면도 직접 확인했습니다. 결과: `checks/visual-results.json`과 같은 폴더의 PNG.
- 집필 중 검토: `ai-slop-reviewer`의 산문 기준과 §14-4 어휘 검색을 적용하고 별도 에이전트가 본문·코드 설명을 검토했습니다. 압축 예제의 보존 필드와 실제 동작, 단순 문자열 채점의 한계, 캐시가 비교 비용에 미친 영향, 단계적 공개가 파일 지연 읽기를 구현하지 않는다는 설명을 보완했습니다. 이는 아래의 정식 한국어 3단 감사를 완료했다는 뜻이 아닙니다.

## 실험 해석

네 실패 조건은 실패를 보장하지 않습니다. 이번 표본에서는 poisoning·confusion에서 정답과 출처가 유지됐고 distraction·clash에서 오답 또는 모순을 관찰했습니다. 길이/위치 실험 27건은 정기 휴관일과 출처의 최소 기준을 모두 충족했으므로 이 실험에서 성능 저하를 관찰했다고 쓰지 않았습니다. 예외 조건의 완전성, 다른 모델, 전체 컨텍스트 한도에 대한 결론으로 확대하지 않습니다. 설계 비교는 설계별 1회이며 전체 자료 호출에만 캐시가 적용됐으므로 토큰 감소와 청구 단가 효과를 구분했습니다.

## 확인 필요 항목

- CSS 표시 후속 점검(2026-09-08): 사용자가 Codex와 별도 브라우저 모두에서 CSS 미적용을 보고했습니다. 자체 CSS보다 먼저 외부 스크립트를 동기 로딩하던 구조를 변경했습니다. 자체 CSS를 먼저 포함하고 웹폰트·코드 강조 리소스는 문서 로딩 완료 후 요청합니다. `checks/styles.cjs`로 7개 HTML의 CSS 포함, 초기 외부 리소스 없음, 지연 로딩, 라이브러리 미가용 시 처리를 확인했고 본문·코드·출력 일치 검사도 다시 통과했습니다. 앞의 화면 14건은 이 변경 전 검사입니다. 현재 도구 정책이 앱 화면 확인과 해당 로컬 HTML 브라우저 열기를 차단하여 수정 후 사용자 화면에서 증상이 해소됐는지는 확인하지 못했습니다. 사용자 증상의 원인도 확정하지 않았습니다.
