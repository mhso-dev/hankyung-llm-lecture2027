1학습 목표

  • 자기 일관성의 목적을 독립 표본과 최종 답 집계의 관점에서 설명할 수 있습니다.
  • 허용 라벨을 검사하고 유효하지 않은 응답과 동률을 명시적으로 처리할 수 있습니다.
  • 표본 합의와 개별 응답의 내용 완전성을 구분해 평가할 수 있습니다.

2이 내용을 배우는 이유

생성 모델은 같은 질문에도 실행할 때마다 표현이나 결론이 달라질 수 있습니다. 한 번의 답만 저장하면 그 답이 반복해서 나타나는 경향인지 우연히 나온 표본인지 알기 어렵습니다. 자기 일관성(Self-Consistency)은 하나의 문제에 대해 다양한 추론 경로를 표집한 뒤, 각 경로가 도달한 최종 답을 집계하는 전략입니다. 이 절은 그중 최종 답의 집계 원리를 배우기 위해 분류 라벨만 반복 생성하는 축소 실습을 사용합니다. 추론 경로를 생성·수집하는 원 기법 전체를 구현하지는 않습니다. 그러나 여러 답이 같은 라벨에 모였다고 해서 그 라벨이 사실이라는 보장은 없습니다. 같은 잘못된 전제나 빠진 자료를 모든 호출이 공유하면 같은 오답에 합의할 수도 있습니다.

이번 절에서는 고객 문의의 최종 분류를 세 번 받아 공개된 첫 줄의 라벨만 집계합니다. 내부 추론을 저장하지 않으며 외부 사실 확인을 다수결로 대체하지 않습니다. 또한 라벨 합의와 주문번호·사진 같은 필수 내용의 포함 여부를 별도로 확인합니다.

4핵심 개념

독립 표본과 합의

표본(sample)은 같은 실험 조건에서 얻은 응답 한 건입니다. 이번에는 앞 호출의 답을 다음 호출 메시지에 넣지 않고 같은 모델·프롬프트·질문·생성 설정으로 각각 호출합니다. 응답을 서로 전달하지 않는 구조이며, 이것만으로 표본의 통계적 독립성을 확인한 것은 아닙니다. 표본 수(sample count)는 호출 횟수이며 이번 실습에서는 3입니다. 합의(consensus)는 유효한 최종 라벨의 빈도를 집계한 결과입니다. 세 표본 중 두 개가 ‘교환’이고 하나가 ‘배송’이면 ‘교환’이 엄격 과반을 얻습니다.

유효성 검사(validation)는 첫 줄이 미리 허용한 라벨 중 하나인지 확인하는 단계입니다. 설명이 길어도 첫 줄 형식이 맞지 않으면 집계 대상에서 제외하거나 형식 오류로 기록해야 합니다. 이번 코드의 엄격 과반(strict majority)은 전체 시도 수의 절반보다 많은 유효 표를 얻은 상태입니다. 형식 오류 응답도 전체 시도 수에는 포함합니다. 가장 큰 빈도가 같으면 동률이며, 유효 표본이 없으면 집계 불가입니다. 코드가 동률에서 임의의 첫 라벨을 고르면 실행 순서가 결론에 영향을 주므로 동률 분기를 명시해야 합니다.

합의가 답의 품질을 보장하지 않는 이유

분류 라벨과 응답 내용은 서로 다른 평가 대상입니다. 세 응답이 모두 ‘교환’이라고 써도 한 응답이 주문번호를 빠뜨리거나, 규정에 없는 보상을 약속할 수 있습니다. 그러므로 집계 뒤에는 각 원문을 다시 읽고 필수 사실, 금지 조건, 근거의 정확성을 검사합니다. 다수결은 유효성 검사나 사실 확인을 대신하지 않습니다. 표본 수를 늘리면 호출 비용과 전체 대기 시간도 함께 늘어나므로, 평가 자료에서 얻는 개선과 비용을 함께 측정해야 합니다.

도식 읽기

합의의 분모를 정하고 경계 사례를 계산하기

이 실습은 여러 최종 응답의 라벨 합의를 읽는 축소 예제입니다. 여러 추론 경로를 표집하고 정답을 집계하는 Self-Consistency 연구의 전체 절차를 재현하지는 않습니다. 앞 응답을 다음 입력에 넣지 않는 별도 호출을 사용하지만, 같은 모델과 지시의 오류가 여러 응답에 함께 나타날 수 있으므로 통계적으로 완전히 독립된 판단을 얻었다고 단정하지 않습니다.

코드는 엄격 과반의 분모를 전체 시도 수인 len(samples)로 정합니다. 세 응답 중 형식 오류가 두 건이고 나머지 한 건이 교환이라면 유효 응답 안에서는 교환이 100%여도 전체 세 건의 과반은 아닙니다. count > len(samples) // 2에서 세 건의 절반을 내린 값은 1이므로 교환 표가 2개 이상이어야 합의가 됩니다. 유효 표본만 분모로 쓰는 다른 정책과 구분합니다.

가정한 라벨이 교환·교환·배송이면 교환으로 합의하고, 교환·배송·환불이면 합의 없음입니다. 교환·형식 오류·형식 오류도 합의 없음입니다. 이 계산 예들은 집계 규칙을 읽는 연습이며 실제 저장 출력의 세 표본은 모두 교환입니다. 실제 표본에서 관찰하지 않은 분기를 관찰한 것처럼 기록하지 않습니다.

측정 함수

단어 포함 표시는 원문 정독을 돕는 표시이며 품질 점수가 아닙니다.

run(messages)는 이 노트북에서 작성하는 보조 함수입니다. 역할·내용 목록을 받아 model.invoke()를 한 번 실행하고, 답 문자열·사용량·경과 초를 담은 딕셔너리를 반환합니다. def 셀은 함수를 정의할 뿐이며 뒤에서 run(...)을 호출할 때 모델 요청이 시작됩니다. mention_flags(text)는 지정 단어가 문자열에 있는지 표시한 딕셔너리를 반환합니다. 답의 뜻을 판단하는 모델 호출은 포함하지 않습니다.

In [4]:
# 모델 응답의 원문, 사용량, 경과 시간을 한 레코드로 보존합니다.
def run(messages):
    started = time.perf_counter()
    answer = model.invoke(messages)
    return {"text": answer.text, "usage": answer.usage_metadata,
            "latency_s": round(time.perf_counter() - started, 3)}

def mention_flags(text):
    return {word: word in text for word in MENTIONS}

반복 조건 고정

모델, 질문, 프롬프트와 평가 기준을 유지한 채 세 번 호출합니다.

Self-Consistency는 다양한 추론 경로를 표집한 뒤 각 경로의 최종 답을 집계하는 기법입니다. 이 노트북은 내부 추론을 수집하지 않고 최종 라벨만 반복 생성·집계하는 축소 실습으로, 원 기법의 전체 절차를 재현하지 않습니다.

최종 답에서 분류 추출

공개된 최종 답의 분류 단어만 집계합니다. 내부 추론은 수집하지 않습니다.

splitlines()는 응답 문자열을 줄 목록으로 나누고 [0]은 첫 줄을 선택합니다. startswith("LABEL: ")로 접두어를 검사한 뒤 그 길이 이후의 부분을 슬라이스하여 라벨을 읽습니다. allowed는 허용한 라벨의 집합이며 포함되지 않은 값은 형식 오류로 기록합니다.

이 코드의 과반 기준은 유효 응답 수가 아니라 전체 표본 수입니다. count > len(samples) // 2이므로 세 번 중 같은 유효 라벨이 두 번 이상 있어야 합니다. 교환·형식 오류·형식 오류라면 한 건만 유효해도 합의 없음입니다. next(..., "합의 없음")는 조건을 만족하는 라벨이 없을 때 사용할 값을 지정합니다.

Self-Consistency의 원 기법은 여러 추론 경로를 표집하고 최종 답을 집계합니다. 여기서는 최종 라벨 합의만 읽는 축소 실습이므로 추론 경로 표집을 구현하지 않습니다. 별도 호출이어도 같은 모델의 편향이 반복될 수 있으며 다수결이 사실 확인을 대신하지 않습니다.

In [6]:
# LABEL 접두어와 열거형을 정확히 검사하고 전체 표본의 엄격 과반수만 합의로 인정합니다.
allowed = {"배송", "교환", "환불"}
labels = []
for item in samples:
    first_line = item["text"].splitlines()[0].strip()
    has_prefix = first_line.startswith("LABEL: ")
    label = first_line[len("LABEL: "):].strip() if has_prefix else "형식 오류"
    labels.append(label if label in allowed else "형식 오류")
valid = [label for label in labels if label in allowed]
counts = {label: valid.count(label) for label in sorted(set(valid))}
consensus = next((label for label, count in counts.items()
                  if count > len(samples) // 2), "합의 없음")
print("표본 분류:", labels, "빈도:", counts, "합의:", consensus)
출력:
표본 분류: ['교환', '교환', '교환'] 빈도: {'교환': 3} 합의: 교환

품질과 비용 함께 확인

합의 여부와 별개로 각 원문이 고정 루브릭을 충족했는지 확인합니다.

In [7]:
# 사용량이 하나라도 없으면 0으로 바꾸지 않고 전체 토큰을 None으로 남깁니다.
token_values = [item["usage"].get("total_tokens") if item["usage"] else None

6실험 결과 해석

실행된 세 표본의 유효 라벨은 모두 ‘교환’이었고 빈도는 {'교환': 3}으로 집계되었습니다. 엄격 과반 기준에 따라 합의 결과도 ‘교환’이며, 이번 세 표본에서는 전원 일치가 관찰되었습니다. 세 호출의 전체 토큰 합계는 614토큰이고 지연 합계는 3.467초였습니다. 개별 호출의 전체 토큰은 250, 184, 180토큰으로 달랐습니다. 같은 라벨을 반환해도 설명 길이와 표현이 달라 사용량이 달라질 수 있음을 보여 줍니다.

내용 검사는 합의와 다른 결과를 보여 줍니다. 세 응답 모두 ‘교환’과 ‘사진’을 포함했지만 둘째와 셋째 응답에는 주문번호 ‘A-1042’가 없었습니다. 첫 응답에는 세 단어가 모두 포함되었습니다. 따라서 “분류 라벨은 세 표본이 일치했다”와 “모든 응답이 필요한 세 내용을 포함했다”를 구분해 기록해야 합니다. 세 번의 일치는 이 고객 문의와 현재 모델 실행에서 관찰한 결과이며, 다른 질문의 정답이나 모델 전체의 안정성을 보장하지 않습니다.

7주의할 점과 실무 메모

  • 표본 합의 전에 허용 라벨과 정확한 추출 규칙을 정합니다. 형식 오류를 가장 가까운 라벨로 자동 보정하면 모델의 형식 준수 실패가 기록에서 사라집니다.
  • 동률은 승자를 임의로 정하지 않고 ‘동률’로 반환합니다. 유효 라벨이 하나도 없으면 ‘집계 불가’로 기록하고 원문을 검토합니다.
  • 모델 별칭은 시간이 지나며 다른 스냅샷을 가리킬 수 있습니다. 재현성이 필요한 평가는 접근 가능한 고정 모델 ID와 생성 설정을 함께 기록합니다.
  • 호출을 N번 수행하면 대체로 비용과 전체 처리량도 늘어납니다. 품질 기준의 개선이 추가 비용을 정당화하는지 평가 자료에서 확인합니다.
  • 다수결은 외부 사실 확인, 정책 유효성 검사, 개인정보 검사를 대신하지 않습니다.

8정리와 다음 절

  • 이번 축소 실습은 같은 조건의 별도 호출에서 최종 분류 라벨을 모아 집계했습니다.
  • 유효하지 않은 라벨, 동률, 집계 불가를 명시적으로 구분해야 합니다.
  • 라벨 합의와 응답 내용의 완전성은 별도의 평가 기준으로 확인합니다.

9복습 문제

문제 1

세 표본이 같은 라벨을 반환하면 그 라벨이 정답이라고 보장할 수 있나요?

해설 — 보장할 수 없습니다. 모든 호출이 같은 잘못된 정보나 빠진 자료를 공유하면 같은 오답에 합의할 수 있으므로 외부 기준으로 확인해야 합니다.

문제 2

형식 오류 응답을 유효 라벨 집계와 분리해야 하는 이유는 무엇인가요?

해설 — 임의 보정은 출력 형식 실패를 숨기고 빈도를 바꿀 수 있습니다. 원문과 오류 수를 보존해야 프롬프트를 수정할 근거가 남습니다.

문제 3

이번 결과에서 전원 일치가 참인데도 내용 완전성이 부족한 근거는 무엇인가요?

해설 — 세 라벨은 모두 ‘교환’이지만 둘째와 셋째 응답에는 주문번호 ‘A-1042’가 없습니다. 라벨 일치와 필수 내용 포함은 다른 검사입니다.

문제 4

두 라벨이 같은 최대 빈도를 얻으면 어떻게 기록해야 하나요?

해설 — 임의의 승자를 선택하지 않고 ‘합의 없음’으로 기록합니다. 표본을 추가할지는 비용과 평가 규칙에 따라 별도로 결정합니다.
