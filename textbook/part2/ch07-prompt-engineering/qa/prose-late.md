## 실행 결과 대조

- 05: 최종 답 조건은 115/87/202토큰과 139자, 근거 요청 조건은 134/150/284토큰과 251자입니다. 두 응답 모두 세 확인 단어를 포함했고 근거 요청 응답에는 별도 근거 항목이 나타났습니다. ReAct 도구 반복은 실행하지 않았다고 명시했습니다.
- 06: 세 유효 라벨은 모두 `교환`, 전체 614토큰, 지연 합계 3.467초입니다. 두 번째와 세 번째 원문에 `A-1042`가 없다는 점을 라벨 합의와 분리해 설명했습니다. 엄격 과반, 형식 오류, 합의 없음 분기를 본문과 문제에 반영했습니다.
- 07: 세 원문은 모두 파싱됐습니다. `brief`에는 요구한 영문 필드 세 개가 없고 다음 행동은 두 항목의 목록이며, `fields`와 `schema`에는 세 필드가 있습니다. 전체 토큰 244/199/243을 실제 출력과 맞췄습니다.
- 08: 세 버전은 확인 단어를 모두 포함했습니다. 입력 토큰 95/118/139, 출력 토큰 128/82/70, 지연 1.376/1.024/0.901초를 기록했습니다. `v3`가 `v2` 조건을 유지하고 관련 예시만 추가하는 점과 `prompt-ab-v1.json`에 원문·결과를 실제 저장한 점을 확인했습니다.

## 내용 경계

- CoT는 모든 모델과 과제에서 성능을 높인다고 설명하지 않았습니다. 공개 근거를 내부 추론 전문으로 취급하지 않았습니다.
- ReAct는 개념만 설명하고 `create_agent`, `ToolNode`, 도구 선택·관찰 반복은 Ch 20 이후 범위로 표시했습니다.
- 자기 일관성의 다수결은 정답, 사실성, 내용 완전성을 보장하지 않는다고 설명했습니다.
- JSON 파싱 성공, 필드 존재, 자료형·허용값, 업무 내용의 정확성을 서로 다른 검사로 구분했습니다.
- 프롬프트 버전 이름만으로 영구 기록이 되지 않으며 원문과 실행 결과를 저장해야 한다고 설명했습니다.
