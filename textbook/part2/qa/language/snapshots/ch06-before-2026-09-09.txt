학습 목표
이 절을 마치면 다음을 할 수 있습니다.
프롬프트·컨텍스트·하네스·루프가 각각 무엇을 가리키는지 예를 들어 설명할 수 있습니다.
LangGraph·LangChain·DeepAgents를 역할에 맞게 용어 지도에 배치할 수 있습니다.
모델 객체를 준비하는 코드와 실제 요청을 보내는 코드를 구분하고 응답 객체의 텍스트를 읽을 수 있습니다.
2
이 내용을 배우는 이유
모델을 호출하는 예제를 검색하면 여러 제품 이름이 함께 등장합니다. 모두 설치해야 첫 질문을 보낼 수 있는 것은 아닙니다. 이번에는 LangChain으로 모델 객체 하나를 만들고 질문을 한 번 보냅니다. 다른 이름은 앞으로 배울 기능이 어느 위치에 있는지 표시하는 데 사용합니다.
먼저 용어를 구분하면 오류를 찾을 때도 도움이 됩니다. 질문을 잘못 적은 경우, 모델에 필요한 자료를 빠뜨린 경우, 프로그램이 같은 요청을 계속 반복한 경우는 확인할 코드가 다릅니다. 이 절에서는 전체 위치를 파악한 뒤
입력 준비 → 호출 → 응답 확인
을 직접 실행합니다.
3
앞에서 배운 내용
Ch 2의 목록·튜플·변수와 함수 호출을 사용합니다. 목록은 여러 메시지를 순서대로 담고, 튜플은 메시지의 역할과 내용을 묶습니다. Ch 5에서 배운 언어 모델의 토큰 생성 원리를 직접 구현하지 않고 제공자의 API로 요청합니다. API는 프로그램끼리 정해진 형식으로 요청과 응답을 주고받는 접점입니다.
실습 묶음을 압축 해제한 폴더에서 이 절의 노트북을 엽니다. Python 3.12 커널을 선택하고 첫 설치 셀부터 순서대로 실행합니다. 모델을 호출하려면 인터넷 연결과

4
핵심 개념
질문 한 장과 질문을 처리하는 프로그램
도서관에서 상담을 받는 상황을 생각해 봅니다. 신청서의 질문은 “책을 몇 권 빌릴 수 있나요?”입니다. 상담원이 질문과 함께 회원 유형과 대출 규정을 읽으면 답을 정하는 데 필요한 자료가 늘어납니다. 상담 전에 회원 정보를 준비하고 상담 후 답을 기록하는 절차도 있습니다. 답에 필요한 정보가 빠졌다면 보충 자료를 요청하는 단계가 이어질 수 있습니다.
이 비유에서 직접 적은 질문과 지시에 해당하는 것이
프롬프트(prompt)
입니다. 모델에 “한국어 한 문장으로 답하세요”라고 적는 문장도 프롬프트의 일부입니다.
컨텍스트(context)
는 이번 호출에서 모델이 참고하도록 전달한 전체 정보입니다. 프롬프트와 함께 보낸 규정, 이전 대화, 예시가 여기에 포함됩니다. 로컬 폴더에 규정 파일이 있다는 이유만으로 모델이 그 파일을 읽는 것은 아닙니다. 프로그램이 내용을 요청에 포함해야 합니다.
하네스(harness)
는 모델이 작업을 수행하도록 입력 준비·호출·결과 검사·기록 등을 갖춘 실행 틀을 말합니다.
루프(loop)
는 결과나 상태를 확인하며 다음 단계를 반복하는 흐름입니다. 반복 조건을 Python 코드로 정할 수도 있고, 뒤에서 배울 에이전트에서는 모델이 다음 행동 선택에 참여할 수도 있습니다. 반복문이 있다는 사실만으로 에이전트가 되는 것은 아닙니다.
{{svg:01-layer-map}}
프롬프트에서 실행 흐름까지 설명 범위를 넓힌 학습용 지도와 세 제품의 역할입니다. 포함 관계는 어떤 범위를 설명하는지를 나타내며, 같은 자료형의 객체가 차례로 들어 있다는 뜻은 아닙니다.
도식의 안쪽 프롬프트에서 시작해 바깥쪽으로 읽습니다. 질문의 표현을 바꾸면 프롬프트를 바꾼 것입니다. 대출 규정을 추가하면 컨텍스트를 바꾼 것입니다. 답을 저장하거나 검증하는 코드를 추가하면 하네스의 기능을 늘린 것입니다. 결과를 보고 다시 요청하는 조건까지 정하면 루프를 설계한 것입니다. 색은 도식에 표시된 역할을 구분하는 표지이며, 글자와 경계선을 함께 읽습니다.
세 제품의 이름을 지도에 놓기
LangChain은 모델과 메시지를 공통 방식으로 다루는 프레임워크입니다. LangGraph는 상태를 유지하며 여러 단계를 실행하는 런타임을 제공합니다. DeepAgents는 긴 작업에 필요한 기능을 갖춘 하네스를 제공합니다. 이 세 제품은 서로 다른 역할을 맡으며 함께 사용될 수 있습니다. 제품의 전체 기능을 이번 절에서 외우거나 실행할 필요는 없습니다.
개인 노트에 위 네 범위와 세 제품 이름을 적고, 오늘 실행한
과
를 LangChain 옆에 표시합니다. 이후 새 용어를 만나면 이 지도의 해당 위치에 추가합니다. Ch 13에서 프로그램이 정한 흐름을, Ch 20에서 모델이 도구를 선택하는 흐름을 배우면 두 경우를 서로 다른 표시로 구분할 수 있습니다.

이 내용을 배우는 이유

핵심 개념
같은 문장도 메시지의 역할과 함께 전달합니다
상담원에게 전달하는 업무 지침과 고객이 적은 문의를 서로 다른 칸에 보관한다고 생각해 봅니다. 두 칸을 구분하면 문의가 바뀌어도 공통 지침을 유지할 수 있습니다. 채팅 요청에서도
메시지(message)
는 역할과 내용을 함께 담습니다. 역할은 문장이 요청에서 어떤 위치에 있는지 표시하고, 내용은 실제 지시나 질문입니다.
시스템 메시지(system message)
에는 응답에 적용할 공통 규칙을 둡니다. 이 실습의 “한 문장의 한국어로 답하세요”가 해당합니다.

7
주의할 점과 실무 메모
Pydantic은 설정에 따라 일부 입력을 선언된 타입으로 변환하기도 합니다. 타입 이름을 적었다는 이유만으로 원래 입력의 타입까지 엄격하게 제한했다고 생각하지 않습니다. 이 절에서는 정수의 상한과 하한을 직접 확인합니다. 타입 변환을 금지해야 하는 프로그램은 Pydantic의 엄격한 검증 설정을 별도로 확인합니다.
형식이 맞는 답에도 잘못된 정보가 들어갈 수 있습니다. 필드의 존재·타입·범위 검증과 내용의 사실 확인은 다른 작업입니다. 이 장에서 만든 형식 검증 경험은 Ch 7의 출력 프롬프트 설계와 Ch 11의 평가 기준을 구분하는 데 사용합니다. 에이전트의 자동 출력 전략은 아직 구현하지 않습니다.
8
정리와 다음 절
스키마에 필드·타입·값의 범위를 선언하고 구조화된 객체를 받습니다.
원본 응답, 파싱한 값, 오류를 나누어 읽으면 실패한 위치를 찾을 수 있습니다.
직접 만든 자료의 범위 검증과 실제 모델 응답의 형식 검증은 다른 실험입니다.
다음 절에서는 응답을 다 받을 때까지 기다리는 대신 도착하는 조각을 읽습니다. 조각이 아직 완성되지 않았을 때와 최종 결과를 검사할 때를 구분하는 데 이번 절의 파싱·검증 개념을 사용합니다.

2
이 내용을 배우는 이유
외부 모델 API는 네트워크 상태, 사용량 제한, 서버 상태의 영향을 받습니다. 평소에는 몇 초 안에 끝나는 호출도 늦어질 수 있고, 일시적인 오류로 응답을 받지 못할 수도 있습니다. 아무 제한 없이 기다리면 사용자는 화면이 멈춘 것으로 생각합니다. 같은 요청을 계속 보내면 대기 시간과 비용이 늘어납니다.
오류가 생겼다고 모두 다시 시도해서도 안 됩니다. 잠깐의 연결 문제는 두 번째 요청에서 해결될 수 있지만, 잘못된 API 키나 존재하지 않는 모델 이름은 같은 요청을 반복해도 해결되지 않습니다. 입력 데이터의 형식 오류도 코드를 고치기 전에는 그대로 발생합니다. 어떤 오류를 몇 번까지 다시 시도할지 정해야 합니다.
기본 모델을 사용할 수 없을 때 다른 모델이나 정해진 안내문으로 응답하는 폴백(fallback)도 필요할 수 있습니다. 그러나 대체 경로가 성공했다는 사실이 기본 경로의 오류를 없애지는 않습니다. 실제로 어느 경로가 응답했는지 기록해야 비용, 품질, 장애 원인을 나중에 확인할 수 있습니다.

실제 응답 경로를 기록합니다.
폴백 모델이 답했다면 기본 모델 이름으로 비용과 품질을 기록하지 않습니다. 제공자, 모델, 시도 횟수, 최종 상태를 함께 남깁니다.
오류 원문에서 비밀 값을 제거합니다.
API 키나 전체 요청 헤더를 노트북 출력과 로그에 남기지 않습니다.

주의할 점과 실무 메모
누락된 값은 0으로 바꾸지 않습니다.
0은 측정값이고,
은 확인하지 못한 값입니다. 상태 열과 숫자 열을 분리합니다.
캐시 입력을 일반 입력과 구분합니다.
제공자가 캐시 사용량 세부 정보를 보냈을 때만 할인 단가를 적용합니다. 제공되지 않은 캐시 토큰을 추정하지 않습니다.
비용은 예상값으로 표시합니다.
공식 청구서에는 반올림, 요청 종류, 장기 컨텍스트, 배치 처리 같은 별도 조건이 반영될 수 있습니다.
한 번의 지연값을 평균처럼 사용하지 않습니다.
예열, 네트워크 혼잡, 출력 길이의 영향을 줄이려면 반복 횟수와 중앙값 또는 백분위수를 미리 정합니다.
API 키와 개인정보를 기록하지 않습니다.
키는 존재 여부만 확인하고, 프롬프트 원문을 저장할 때도 공개 가능한 입력인지 확인합니다.
확인 필요 항목
Anthropic과 Google 호출은 API 키가 없어 실행되지 않았습니다. 두 제공자의 실제 사용량·지연·비용은 키가 준비된 환경에서 같은 조건으로 다시 실행해야 합니다. 가격과 모델 접근 권한은 배포 직전에 공식 문서와 계정 화면에서 다시 확인합니다.
