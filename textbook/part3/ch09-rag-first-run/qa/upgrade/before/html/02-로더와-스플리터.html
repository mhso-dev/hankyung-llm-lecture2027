1학습 목표

  • 이 절을 마치면 제공된 합성 PDF 한 쪽을 PdfReader로 읽고 Document로 바꿀 수 있습니다.
  • 이 절을 마치면 page_content와 metadata의 타입·내용을 출력하고, 분할 후 출처 정보가 보존되는지 확인할 수 있습니다.
  • 이 절을 마치면 chunk_overlap을 유지하고 chunk_size만 500에서 300으로 바꾸어 청크 개수와 길이를 비교할 수 있습니다.

2이 내용을 배우는 이유

01절 도식의 첫 두 상자입니다. 검색 결과는 청크 단위로 반환되므로, 청크가 어떻게 생겼는지가 이후 모든 절의 품질을 정합니다. 청크에 답의 앞부분만 들어 있으면 모델은 반쪽 답을 하고, 청크에 page가 없으면 출처를 붙일 수 없습니다. 이 절에서 만든 Document의 모양이 그대로 Ch 10(문서 처리 심화), Ch 11(정답 문서 ID 비교), Ch 12(pgvector에서 데이터를 저장할 열 구조)까지 이어집니다.

커리큘럼이 정한 범위도 확인합니다. 로더·청킹은 통합 패키지를 그대로 쓰는 영역입니다(직접 구현 대상은 Ch 12의 키워드 검색과 의미 검색 결과 합치기·후보 순서 다시 매기기·질문 다시 쓰기입니다). 노트북은 pypdf.PdfReader로 PDF 한 쪽을 읽고, langchain-text-splitters로 나눕니다.

3앞에서 배운 내용

  • Ch 2 자료구조와 값의 종류 표시 — list[Document], dict 기반 metadata, pathlib.Path를 그대로 씁니다.
  • Ch 4 문서 파싱 입문 — HTML에서 필요한 본문을 고르고 추출 결과를 확인했습니다. PDF 파싱은 Ch 9 01절에서 처음 도입했으며, 이 절은 pypdf.PdfReader와 page.extract_text()의 반환값을 쪽별로 자세히 확인합니다.
  • Ch 5 글을 토큰으로 나누는 도구 — 모델이 글을 처리하는 단위인 토큰을 확인했습니다. 이 절 끝에서 청크 하나로 다시 확인합니다.

4핵심 개념

비유 — 책을 색인 카드로 옮기기

도서관 사서가 책 한 권을 색인 카드로 옮긴다고 생각해 보세요. 카드 한 장에는 글이 500자 정도 들어갑니다. 사서는 책을 앞에서부터 500자씩 베껴 쓰되, 문장이 카드 끝에서 잘리지 않도록 문단 경계에서 끊으려 합니다. 그리고 카드마다 구석에 "어느 책, 몇 쪽"을 적어 둡니다. 나중에 카드 한 장만 꺼내 봐도 원래 위치를 확인할 수 있어야 하기 때문입니다. 로더는 책을 쪽 단위로 펼치는 일, 스플리터는 카드에 옮겨 적는 일, metadata는 문서 ID와 쪽 번호 같은 출처 정보를 적은 카드 구석의 메모입니다.

정의

Document
LangChain이 텍스트 조각을 다루는 기본 단위입니다. 본문 page_content(문자열)와 부가 정보 metadata(딕셔너리) 두 칸으로 이루어집니다. 로더의 출력, 스플리터의 입력·출력, 벡터스토어의 저장 단위로 사용됩니다.
로더 (loader)
파일을 읽어 Document 목록으로 바꾸는 함수입니다. PDF는 쪽마다 하나, HTML은 파일당 하나처럼 "무엇을 한 단위로 볼지"를 로더가 정합니다.
스플리터 (text splitter)
Document를 정해진 크기의 청크로 나누는 도구입니다. metadata는 나뉜 청크마다 복사됩니다.
청크 크기 (chunk_size) · 겹침 (chunk_overlap)
청크 하나의 최대 길이와, 이웃 청크가 서로 공유하는 길이입니다. 이 절의 스플리터는 둘 다 글자 수로 셉니다.
구분자 (separators)
어디서 끊을지의 우선순위 목록입니다. ["\n\n", "\n", ". ", " ", ""]이면 문단 경계 → 줄 경계 → 문장 경계 → 단어 경계 → 글자 순으로 시도합니다. "재귀적(Recursive)"이라는 이름은 큰 구분자로 잘라도 크기를 넘으면 다음 구분자로 다시 자른다는 뜻입니다.

도식 — 청크 경계와 겹침

겹침이 왜 필요한지는 이 그림 하나로 충분합니다. 겹침이 0이면 "3일 늦게 반납하면 반납일부터 3일"에서 끊기고, "동안 새로 대출할 수 없습니다"는 다음 청크로 넘어갑니다. 검색이 앞 청크만 가져오면 모델은 "3일 뒤에 무엇이 되는지"를 모른 채 답해야 합니다. 겹침은 이러한 절단을 줄입니다. 다만 겹친 만큼 청크 수가 늘고 임베딩 비용이 늘어납니다.

기본 노트북의 Document

기본 노트북은 제공된 합성 PDF E01.pdf의 2쪽을 읽고 Document로 만듭니다. 본문과 doc_id·page·source가 한 객체에 함께 저장되는지 타입과 내용을 출력해 확인합니다.

기본 노트북의 스플리터

split_documents()는 Document 목록을 받아 Document 목록을 반환합니다. 입력 쪽의 metadata가 출력 청크마다 그대로 복사되므로, 청크 하나만 보고도 "E01의 2쪽"임을 압니다. 여기에 chunk_id를 덧붙여 두면 03절에서 검색 결과를 읽을 때 "#0이 검색되었다"처럼 지칭할 수 있습니다.

호출 표기와 반환값 읽기

reader.pages[1]에서 대괄호는 목록에서 한 항목을 고르는 표기이며, Python의 인덱스가 0부터 시작하므로 두 번째 쪽을 뜻합니다. extract_text()는 그 쪽 객체를 문자열로 바꾸어 반환합니다. 반환 문자열과 문서 ID·쪽 번호를 Document에 넣으면 검색 단계가 본문과 출처를 함께 전달할 수 있습니다.

split_documents([document])는 Document 목록을 입력받아 더 짧은 Document 목록을 반환하며, 이 호출만으로 임베딩이나 검색이 실행되지는 않습니다. split_text(text)가 문자열만 나누는 것과 비교하면, split_documents()는 기존 metadata를 청크에 복사한다는 차이가 있습니다. 계약서처럼 조항 번호가 중요한 문서에서는 쪽 번호 외에 조항 ID도 먼저 메타데이터에 넣어야 분할 뒤 추적할 수 있습니다.

5실행 예제

제공된 합성 PDF E01.pdf의 2쪽을 직접 읽습니다. Document 타입·출처 정보(metadata)·본문을 확인한 뒤 500/50으로 나누고, 겹침 50은 유지한 채 청크 크기만 300으로 바꿉니다. 끝으로 text-embedding-3-small에 대응하는 cl100k_base 토크나이저로 실제 첫 청크의 토큰 수를 출력합니다.

호출 표기와 반환값 읽기

reader.pages[1]은 0부터 세는 목록의 두 번째 쪽을 고르고, extract_text()는 그 쪽을 문자열로 반환합니다. split_documents([document])는 Document 목록을 받아 더 짧은 Document 목록을 반환하며 이때 임베딩이나 검색은 실행되지 않습니다.

4. 값 하나만 바꾸어 비교
chunk_overlap=50은 그대로 두고 chunk_size만 500에서 300으로 줄입니다.

5. 실제 청크의 토큰 수 확인
text-embedding-3-small이 사용하는 cl100k_base 토크나이저로 첫 청크를 인코딩합니다. Ch 5의 GPT-2·KLUE 토크나이저와 계산 단위가 다르므로 그때의 수치와 직접 비교하지 않습니다.


In [6]:
# encoding_for_model()로 임베딩 모델에 맞는 토크나이저를 명시합니다.
# 같은 문자열도 토크나이저가 다르면 토큰 수가 달라질 수 있습니다.
import tiktoken

embedding_tokenizer = tiktoken.encoding_for_model("text-embedding-3-small")
first_chunk_text = chunks[0].page_content
first_chunk_tokens = embedding_tokenizer.encode(first_chunk_text)
print("토크나이저:", embedding_tokenizer.name)
print("첫 청크 글자 수:", len(first_chunk_text))
print("첫 청크 토큰 수:", len(first_chunk_tokens))
assert len(first_chunk_tokens) > 0

정리
Document의 문서 ID와 쪽 번호(metadata)는 나눈 뒤에도 남았습니다. 이웃 청크가 함께 가지는 글자 수는 그대로 두고, 청크 최대 길이만 줄이자 청크 개수와 길이가 바뀌었습니다. 첫 청크의 글자 수와 임베딩 모델 토크나이저의 토큰 수는 서로 다른 값으로 확인했습니다.




확인할 점 — 분할 결과도 Document 리스트이며 모든 청크에 doc_id=E01과 page=2가 남습니다. 청크 크기를 줄이면 반환 개수와 각 청크의 길이가 바뀌어야 합니다.


6일부러 실패해 보기


Before에서 겹침을 0으로 두어 “월요일”이 청크 경계에서 두 조각으로 갈라지는 결과를 확인합니다. After에서 다른 값은 유지하고 chunk_overlap만 5로 늘려, 겹친 청크 안에 “월요일” 전체가 남는지 검사합니다.




앞의 실행 예제를 실행한 같은 노트북에서 Before 다음 After 순서로 실행합니다. 출력은 실제 실행 결과입니다.


Before — 실패 코드


원인 — 겹침이 없으면 청크 경계에 놓인 “월요일”이 두 조각으로 갈라져 어느 청크에도 온전히 남지 않을 수 있습니다.


In [7]:
# 경계 확인용 Document에서 “월요일”이 정확히 청크 경계에 걸리게 만듭니다.
# any()는 어느 청크든 target 전체를 포함하는지 확인합니다.
boundary_text = "가나다라마바사아자차" * 3 + "정기 휴관일은 월요일입니다."
boundary_document = Document(page_content=boundary_text)
target = "월요일"
no_overlap_splitter = RecursiveCharacterTextSplitter(
    chunk_size=40, chunk_overlap=0, separators=[""]
)
before_chunks = no_overlap_splitter.split_documents([boundary_document])
before_texts = [chunk.page_content for chunk in before_chunks]
print("Before 청크:", before_texts)
try:
    assert any(target in text for text in before_texts)
except AssertionError:
    print("예상한 실패: 월요일이 청크 경계에서 갈라졌습니다.")
else:
    raise AssertionError("청크 경계 실패가 재현되어야 합니다.")


출력:
Before 청크: ['가나다라마바사아자차가나다라마바사아자차가나다라마바사아자차정기 휴관일은 월요', '일입니다.']
예상한 실패: 월요일이 청크 경계에서 갈라졌습니다.





After — 수정 코드


수정 — 다른 값은 유지하고 chunk_overlap만 0에서 5로 늘려 경계 양쪽 문자를 함께 보존합니다.


In [8]:
# overlap_splitter는 앞의 설정에서 chunk_overlap만 5로 바꿉니다.
# 겹친 청크 중 하나에 “월요일” 전체가 들어왔는지 확인합니다.
overlap_splitter = RecursiveCharacterTextSplitter(
    chunk_size=40, chunk_overlap=5, separators=[""]
)
after_chunks = overlap_splitter.split_documents([boundary_document])
after_texts = [chunk.page_content for chunk in after_chunks]
print("After 청크:", after_texts)
assert any(target in text for text in after_texts)


출력:
After 청크: ['가나다라마바사아자차가나다라마바사아자차가나다라마바사아자차정기 휴관일은 월요', '일은 월요일입니다.']










7주의할 점과 실무 메모


    

  • 글자 수 vs 토큰 수. RecursiveCharacterTextSplitter는 글자를 셉니다. 노트북은 tiktoken.encoding_for_model("text-embedding-3-small")로 첫 청크의 토큰 수를 별도로 확인합니다. Ch 5에서 관찰한 GPT-2·KLUE 토크나이저와 이번 cl100k_base 토크나이저는 계산 단위가 다르므로 두 결과를 직접 비교하지 않습니다. 토큰 수를 분할 기준으로 쓰려면 RecursiveCharacterTextSplitter.from_tiktoken_encoder(...)나 TokenTextSplitter를 사용합니다(Ch 10).
    • 

  • 전체 PDF 확장의 로더 선택. 기본 노트북은 pypdf를 직접 사용해 제공된 PDF 한 쪽을 읽습니다. 공식 문서 예제의 langchain-community PyPDFLoader는 유지보수 종료가 예고되어 2026-09-07 기준으로 import 경고가 발생했습니다. Ch 10에서는 Docling·Upstage 같은 독립 파서를 비교합니다.
    • 

  • 표의 행과 열 관계가 사라질 수 있습니다. extract_text()는 PDF의 글자를 추출하지만, 어떤 값이 같은 행이나 열에 있었는지 항상 보존하지는 않습니다. 이 절은 E01의 일반 문단만 관찰합니다. 표가 든 문서는 Ch 10에서 여러 PDF 읽기 도구로 비교합니다.
    • 

  • HWP·HWPX. 한국 실무에는 HWP·HWPX 문서도 있으며 pypdf로는 열 수 없습니다. Ch 10의 별도 절입니다.
    • 

  • 표지·머리글. 표지 한 쪽이 45자짜리 Document가 됩니다. 검색에서 제목 단어와 겹치면 높은 점수를 받아 자리를 차지합니다(03절). 실무에서는 표지·목차 쪽을 로더 단계에서 거르거나, 청크 최소 길이를 두는 처리를 흔히 합니다. 이 챕터에서는 일부러 두어 그 현상을 보게 합니다.
    • 




8정리와 다음 절
    

  • PdfReader로 E01 PDF 2쪽의 문자열을 읽고 문서 ID와 쪽 번호를 담은 metadata와 함께 Document로 만들었습니다.
    • 

  • split_documents()는 문서 ID와 쪽 번호를 복사한 청크 Document 리스트를 반환했습니다.
    • 

  • 겹침은 50으로 유지하고 청크 크기만 500에서 300으로 줄여 결과를 비교했습니다.
    •

9복습 문제
문제 4개 · 해설 포함

1. Document의 page_content와 metadata에는 각각 무엇을 저장했습니까?
page_content에는 PDF 2쪽에서 추출한 본문을, metadata에는 문서 ID·쪽 번호·파일명을 저장했습니다.


2. split_documents()의 입력과 반환값은 무엇입니까?
Document 리스트를 입력받아 더 작은 청크 Document 리스트를 반환합니다.


3. 500/50과 300/50 비교에서 변경한 값은 무엇입니까?
chunk_size만 500에서 300으로 변경했고 chunk_overlap=50은 유지했습니다.


4. Before와 After에서 바꾼 값과 확인한 결과는 무엇입니까?
chunk_overlap만 0에서 5로 바꾸었습니다. Before에서는 “월요일”이 경계에서 갈라졌고, After에서는 겹친 청크 하나에 전체 단어가 남았습니다.
