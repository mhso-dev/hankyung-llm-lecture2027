1학습 목표

  • 이 절을 마치면 검색한 Document의 문서 ID(doc_id)·쪽 번호(page)·본문(page_content)를 별도 변수로 확인할 수 있습니다.
  • 이 절을 마치면 출처 태그와 본문을 context로 조립하고 삼중따옴표 프롬프트에 넣을 수 있습니다.
  • 이 절을 마치면 init_chat_model().invoke()의 AIMessage 반환값에서 답과 출처를 검사할 수 있습니다.
  • 이 절을 마치면 k만 1에서 2로 바꾸어 프롬프트 후보 수의 변화를 비교할 수 있습니다.

2이 내용을 배우는 이유

마지막 상자입니다. 두 Document를 색인하고 similarity_search()가 반환한 상위 Document 한 건을 모델에게 전달해 답을 받으면 RAG 한 사이클이 완성됩니다. 이 절을 마치면 "이틀 안에 실행되는 RAG"라는 챕터 목표가 달성됩니다.

이 절에서 정하는 것이 하나 더 있습니다. 출처 표기 형식입니다. 답 뒤에 [doc_id p.페이지]를 붙이기로 정하면, 그 형식이 05절의 실패 분석, Ch 11의 "무엇을 맞다고 볼지" 합의, 중간 프로젝트 요건("출처 인용")까지 이어집니다. Ch 11에서는 답변 판정 기준을 합의하고 검색 문서 ID 지표만 계산합니다. 답이 출처 형식과 근거를 지켰는지 자동 평가하는 방법은 Ch 15에서 다룹니다.

3앞에서 배운 내용

  • Ch 6 init_chat_model — 첫 호출 때 쓴 함수 그대로입니다. 이 절에서는 삼중따옴표로 만든 단일 프롬프트 문자열을 invoke()에 전달합니다.
  • Ch 7 프롬프트 설계 — 근거 범위와 출력 형식을 명시했습니다. 이 절의 단일 프롬프트에는 “다음 문서만 근거로 답하기”와 “출처 태그 붙이기”가 들어갑니다.
  • Ch 8 모델에 넣을 정보량 — 기본 노트북은 k=1로 선택한 짧은 Document 한 건을 문맥으로 보냅니다. 이어서 k만 2로 바꾸어 후보 Document 수가 늘어나는 것을 관찰합니다.
  • 03절의 검색 — 기본 노트북은 독립 실행을 위해 벡터스토어를 다시 만들고 similarity_search()를 직접 호출합니다. 검색이 틀리면 생성은 그 틀린 재료로 답을 만듭니다.

4핵심 개념

비유 — 답안지 규칙

오픈북 시험에서 감독관이 규칙을 정합니다. "책상 위 자료만 보고 답하라. 답의 근거가 된 쪽 번호를 답 옆에 적어라." 규칙이 없으면 학생은 기억으로 답하거나 근거 없이 씁니다. 이 규칙과 검색 문맥, 질문을 합친 단일 프롬프트 문자열을 모델에 전달합니다. [D01 p.1]은 문맥 앞과 답에 사용하는 출처 태그입니다.

정의

문맥 조립 (context assembly)
검색된 Document의 본문과 출처 태그를 모델이 읽을 문자열로 조립하는 것입니다. 기본 노트북은 k=1 Document의 page_content 앞에 [D01 p.1] 태그를 붙여 context를 만듭니다.
프롬프트 (prompt)
모델에 전달하는 입력 문자열입니다. 이 절에서는 “다음 문서만 근거로 답하라”와 “출처를 [doc_id p.페이지]로 붙여라”는 지시, 검색 문맥, 질문을 하나의 삼중따옴표 문자열에 넣습니다.
출처 인용 (citation)
답의 근거가 된 청크의 doc_id·page를 답에 표기하는 것입니다. 모델이 표기한 출처는 검색된 k개 중 하나여야 합니다. 그렇지 않으면 지어낸 출처입니다.
AIMessage
model.invoke(prompt)가 반환하는 LangChain 메시지 객체입니다. 기본 노트북은 객체 타입을 출력하고 .text 속성에서 답 문자열을 읽습니다.

기본 노트북의 조립과 생성

첫째, 검색한 문서의 doc_id와 page로 출처 태그를 만듭니다. 둘째, 태그와 본문을 질문 앞에 놓습니다. 셋째, 모델에 전달한 뒤 답과 출처가 함께 있는지 검사합니다. 기본 노트북은 이 과정을 doc_id·page·source_tag·context 변수로 직접 보여 줍니다.

모델 선택gpt-5.4-mini를 사용하고 temperature=0을 명시합니다. 출력 표현은 실행 시점에 따라 다를 수 있으므로 문장 전체가 같은지보다 휴관일 내용과 [D01 p.1] 태그가 포함되었는지 확인합니다.

검색 결과가 답과 출처가 되는 과정

검색기는 Document를 반환하지만 모델은 그 객체를 자동으로 알지 못합니다. 코드가 각 문서의 page_content와 metadata를 사람이 읽을 수 있는 문맥 문자열로 조합한 뒤 프롬프트에 넣습니다. model.invoke(prompt)를 호출하는 순간에만 생성 요청이 실행되고, 반환된 AIMessage.text가 답 문자열입니다.

출처를 프롬프트에 적는 것, 모델이 답에 출처를 표시하는 것, 표시한 출처가 실제 근거를 포함하는지는 서로 다른 검사입니다. 이 절은 표시된 ID가 검색 결과에 있었는지 확인합니다. 문장 단위 근거가 필요하면 답의 각 주장과 원문 구절을 별도로 대조해야 하며, 단순한 ID 포함 검사만으로 내용의 정확성을 보장할 수 없습니다.

실습 안내

검색 결과가 답과 출처가 되는 과정

검색된 Document는 모델에 자동 전달되지 않습니다. 코드가 page_content와 metadata를 문맥 문자열로 만든 뒤 model.invoke(prompt)를 호출할 때 생성이 실행됩니다. 반환 객체의 text가 답 문자열입니다.

프롬프트에 출처를 넣는 것, 답에 출처가 표시되는 것, 표시한 출처가 실제 주장을 뒷받침하는 것은 서로 다른 검사입니다. 이 절의 ID 포함 검사는 문장 단위 사실 검증을 대신하지 않습니다.

2. 출처가 있는 문서를 색인

각 Document에 문서 ID(doc_id)와 쪽 번호(page)를 넣습니다. 그런 다음 문서를 숫자 벡터로 바꿔 검색할 수 있는 메모리 저장소를 만듭니다.

In [3]:
# documents는 본문과 출처 메타데이터를 가진 Document 리스트입니다.
# from_documents()는 문서를 임베딩해 store를 반환합니다.
from langchain_core.documents import Document
from langchain_core.vectorstores import InMemoryVectorStore
from langchain_openai import OpenAIEmbeddings

documents = [
    Document(page_content="정기 휴관일은 매주 월요일입니다.", metadata={"doc_id": "D01", "page": 1}),
    Document(page_content="대출 기간은 14일입니다.", metadata={"doc_id": "D02", "page": 2}),
]
embedding = OpenAIEmbeddings(model="text-embedding-3-small")
store = InMemoryVectorStore.from_documents(documents, embedding)
print("문서 수:", len(documents), "store:", type(store).__name__)
출력:
문서 수: 2 store: InMemoryVectorStore

3. 관련 문서 한 건 검색

k=1로 가장 가까운 Document 한 건을 가져옵니다. 문서 ID와 쪽 번호를 담은 출처 정보(metadata), 본문을 따로 출력합니다.

In [4]:
# hits는 질문과 가장 관련 높은 Document 한 건을 담은 리스트입니다.
# hit는 hits의 첫 번째 Document를 가리킵니다.
question = "정기 휴관일은 언제인가요?"
hits = store.similarity_search(question, k=1)
hit = hits[0]
print("Document 타입:", type(hit).__name__)
print("metadata:", hit.metadata)
print("content:", hit.page_content)
출력:
Document 타입: Document
metadata: {'doc_id': 'D01', 'page': 1}

4. 출처 태그와 문맥 만들기

검색한 Document의 문서 ID와 쪽 번호로 [D01 p.1] 모양의 출처 태그를 만들고 본문 앞에 붙입니다.

In [5]:
# source_tag는 [문서ID p.쪽] 형식의 문자열입니다.
# f-string은 중괄호 안의 metadata 값과 page_content를 context에 삽입합니다.
doc_id = hit.metadata["doc_id"]
page = hit.metadata["page"]
source_tag = f"[{doc_id} p.{page}]"
context = f"{source_tag} {hit.page_content}"
print("출처:", source_tag)
print("문맥:", context)
출력:
출처: [D01 p.1]
문맥: [D01 p.1] 정기 휴관일은 매주 월요일입니다.

5. 삼중따옴표로 프롬프트 조립

여러 줄 문자열에 문맥과 질문을 삽입하고 모델에 전달되는 전체 프롬프트를 먼저 출력합니다.

In [6]:
# f 삼중 문자열은 여러 줄을 유지하며 context와 question 값을 삽입합니다.
# 생성 전에 prompt를 출력해 모델이 실제로 받는 입력을 확인합니다.

[문서]

6. 생성 모델 호출

init_chat_model로 모델을 만들고 invoke()로 프롬프트를 전달합니다.

In [7]:
# model은 LangChain이 제공하는 OpenAI 대화 모델 객체입니다.
# answer는 AIMessage이고 .text는 생성된 답변 문자열입니다.
from langchain.chat_models import init_chat_model

model = init_chat_model("openai:gpt-5.4-mini", temperature=0)
answer = model.invoke(prompt)
print("answer 타입:", type(answer).__name__)
print(answer.text)
assert "월요일" in answer.text
assert source_tag in answer.text
출력:
answer 타입: AIMessage
정기 휴관일은 매주 월요일입니다. [D01 p.1]

7. k만 2로 바꾸어 문맥 비교

질문과 모델은 유지하고 검색 개수만 늘려 프롬프트에 들어갈 후보가 어떻게 늘어나는지 확인합니다.

In [8]:
# more_hits는 k=2로 가져온 Document 리스트입니다.
# ID와 본문 길이를 모두 출력해 k=1 결과와 비교합니다.
more_hits = store.similarity_search(question, k=2)
print("k=1 문서 수:", len(hits))
print("k=2 문서 수:", len(more_hits))
for document in more_hits:
    print(document.metadata["doc_id"], len(document.page_content))
assert len(more_hits) == 2
출력:
k=1 문서 수: 1
k=2 문서 수: 2
D01 18
D02 14

정리

Document의 문서 ID와 쪽 번호로 출처 태그를 만들었습니다. 태그와 본문을 프롬프트에 넣었고, invoke()가 반환한 AIMessage에서 답과 출처를 읽었습니다.

확인할 점 — Document 타입·출처 정보(metadata)·본문, source_tag, context, 모델에 전달한 전체 프롬프트, AIMessage 타입·본문을 순서대로 확인합니다.

6일부러 실패해 보기

Before에서 실제 검색 결과를 새 Document로 옮기면서 page를 빠뜨려 KeyError가 나는지 확인합니다. After에서는 쪽 번호를 지어내지 않고 원래 검색 결과의 page를 함께 옮겨 같은 출처 태그를 복구합니다. 복구한 태그와 본문으로 같은 질문을 실제 호출해 답의 출처까지 확인합니다.

앞의 실행 예제를 실행한 같은 노트북에서 Before 다음 After 순서로 실행합니다. 출력은 실제 실행 결과입니다.

Before — 실패 코드

원인 — 검색 결과를 새 Document로 옮기면서 page를 빠뜨리면 쪽 번호가 있는 출처 태그를 만들 수 없습니다.

In [9]:
# broken은 실제 검색 결과 hit의 본문과 문서 ID만 옮겨 page를 빠뜨린 경우입니다.
# metadata["page"]를 읽을 때 KeyError가 발생하는지 확인합니다.
broken = Document(
    page_content=hit.page_content,
    metadata={"doc_id": hit.metadata["doc_id"]},
)
try:
    print(f"[{broken.metadata['doc_id']} p.{broken.metadata['page']}]")
except KeyError as error:
    print("예상한 실패: 누락된 메타데이터", error)
출력:
예상한 실패: 누락된 메타데이터 'page'

After — 수정 코드

수정 — 같은 검색 결과에서 실제 page 값도 함께 옮깁니다. 복구한 출처 태그와 본문으로 같은 질문의 프롬프트를 만들고 실제 답까지 확인합니다.

In [10]:
# fixed는 hit에 있던 실제 doc_id와 page를 모두 복사한 Document입니다.
# 복구한 태그와 본문으로 같은 질문을 다시 실행해 출처가 답에 남는지 확인합니다.
fixed = Document(
    page_content=hit.page_content,
    metadata={"doc_id": hit.metadata["doc_id"], "page": hit.metadata["page"]},
)
fixed_tag = f"[{fixed.metadata['doc_id']} p.{fixed.metadata['page']}]"
fixed_context = f"{fixed_tag} {fixed.page_content}"
fixed_prompt = f"""다음 문서만 근거로 답하세요. 답 끝에 출처 태그를 붙이세요.

[문서]
{fixed_context}

[질문]
{question}"""
fixed_answer = model.invoke(fixed_prompt)
print("After 태그:", fixed_tag)
print("After 답:", fixed_answer.text)
assert fixed_tag == source_tag
assert fixed_tag in fixed_answer.text
출력:
After 태그: [D01 p.1]
After 답: 정기 휴관일은 매주 월요일입니다. [D01 p.1]

7주의할 점과 실무 메모

  • 검색 후보와 답의 출처 태그는 다릅니다. hits는 검색이 반환한 Document 리스트이고, 답에 붙은 [D01 p.1]는 모델이 생성한 문자열입니다. 기본 노트북은 k=1 Document의 metadata로 만든 source_tag가 실제 답에 포함되는지 검사합니다.
  • metadata가 먼저 필요합니다. doc_id나 page가 없으면 출처 태그를 만들 수 없습니다. Before는 실제 검색 결과에서 page를 빠뜨렸을 때 발생한 KeyError를 확인하고, After는 원래 검색 결과의 page를 복사해 태그를 완성합니다.
  • 비용. 기본 노트북은 짧은 Document 두 건을 임베딩하고 k=1 문맥으로 생성 모델을 한 번 호출합니다. k=2 셀은 후보 수와 본문 길이만 비교하며 생성 모델을 다시 호출하지 않습니다. 모델 요금은 바뀔 수 있으므로 실행 시점의 공식 요금표를 확인합니다.
  • 출력 언어. 기본 프롬프트에는 별도의 언어 지시를 넣지 않았고 문서와 질문을 한국어로 작성했습니다. 여러 언어의 문서를 함께 사용할 때는 원하는 출력 언어를 프롬프트에 명시하고 실제 응답을 확인합니다.
  • 응답에서 텍스트 읽기. model.invoke()는 AIMessage를 반환합니다. 기본 노트북은 answer.text로 텍스트를 읽습니다. content는 문자열이나 콘텐츠 블록 목록일 수 있으므로 멀티모달 응답을 다루는 Ch 26에서 별도로 확인합니다.

8정리와 다음 절

  • 검색 Document의 문서 ID와 쪽 번호(metadata)가 출처 태그가 되었고, 본문(page_content)은 모델이 참고할 문맥이 되었습니다.
  • 삼중따옴표 프롬프트에 문맥과 질문을 넣고 AIMessage의 .text로 답을 읽었습니다.
  • k만 1에서 2로 바꾸어 모델에 전달할 후보 문서 수가 늘어나는 것을 확인했습니다.

다음 학습과 이어지는 지점 — 05절에서 생성 답만 읽지 않고 검색한 Document ID를 함께 보며 실패 원인을 구분합니다.

9복습 문제

문제 4개 · 해설 포함

1. source_tag에 사용한 출처 정보(metadata) 두 개는 무엇입니까?

doc_id와 page입니다. 두 값으로 [D01 p.1] 형식을 만듭니다.

2. 생성 전에 전체 prompt를 출력하는 이유는 무엇입니까?

모델이 실제로 받은 문맥, 출처 형식, 질문을 확인해 조립 문제와 생성 문제를 구분할 수 있습니다.

3. invoke()의 반환값과 응답 문자열을 읽는 속성은 무엇입니까?

AIMessage를 반환하고 .text로 응답 문자열을 읽습니다.

4. k=2 비교 셀에서 모델을 다시 호출하지 않고도 확인할 수 있는 것은 무엇입니까?

프롬프트 후보로 사용할 Document 개수와 각 Document의 ID·본문 길이를 확인할 수 있습니다.
