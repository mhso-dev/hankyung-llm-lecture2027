# Ch 9 낡은 회귀 검사 갱신 기록

## 수정 전 실패

`pytest`로 Ch 9 실습과 QA 회귀 검사를 함께 실행했을 때 20개 중 3개가 실패했습니다.

1. `test_all_pre_blocks_expand_from_lab_sources`는 `_src`의 과거 `{{code:...}}`·`{{output:...}}` 참조 블록 30개를 기대했습니다. 현재 절은 `{{notebook:...}}`로 노트북을 삽입하므로 `_src`에는 해당 참조 블록이 0개이고, 완성 HTML에는 노트북 렌더러가 만든 코드·출력 블록이 있습니다.
2. `test_existing_chapter_structure_is_complete`는 11개 본문 블록과 학생 페이지의 강사 노트를 요구했습니다. 현재 AUTHORING 고정 구조는 `b1`부터 `b10`까지 10개이며 학생용 HTML에는 강사 노트를 넣지 않습니다.
3. `test_notebooks_are_short_and_self_contained`는 설치 셀의 첫 줄이 바로 `%pip`이고 코드 셀이 15줄 이하여야 한다고 요구했습니다. 현재 AUTHORING은 설치 목적을 설명하는 한국어 주석을 허용하며 코드 셀은 기본 3~15줄, 최대 25줄입니다.

세 검사는 현재 기능의 실패가 아니라 이전 작성 규격의 고정값 때문에 실패했습니다. 노트북 원본·완성 HTML 코드 복사 일치, 새 커널 실행, 출력 검증은 공통 검증기와 화면 검사에서 별도로 확인합니다.

## 수정과 재검증

1. 과거 `code/output` 참조 검사는 남아 있는 참조만 완성 HTML에서 정확히 찾도록 바꾸고, 현재 참조가 0개임을 확인했습니다. 보존 출력 12개와 manifest SHA-256 해시 12개 검사는 그대로 유지했습니다.
2. 구조 검사는 `b1`~`b10`을 모두 요구하고 `b11`과 학생용 강사 노트가 없음을 추가로 확인합니다. 퀴즈·도식·삽화·노트북 삽입 검사는 그대로 유지했습니다.
3. 설치 셀 검사는 `%pip install -q` 앞의 빈 줄과 한국어 주석만 허용하며 설치 명령이 정확히 한 번 있는지 확인합니다. 코드 셀 상한은 AUTHORING의 최대 25줄로 바꾸고 독립 실행·Before/After·실제 출력·금지 import 검사는 그대로 유지했습니다.

재검증 결과는 `20 passed`입니다. `check_content.py`는 과거 참조 0개, 보존 출력 12개, manifest 해시 12개를 통과했습니다. 수정한 Python 검사 파일의 Ruff 검사와 공통 교재 검증 `6 sections / 59 code cells`도 통과했습니다.
