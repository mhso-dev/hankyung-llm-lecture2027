1학습 목표

  • 이 절을 마치면 검색 결과 k개를 하나의 문자열로 조립하는 format_context()와, 그것을 프롬프트에 넣어 답을 받는 generate()를 읽고 고칠 수 있습니다.
  • 이 절을 마치면 모델에게 실제로 보낸 문자열을 출력해 확인하고, 답 뒤에 붙은 [E01 p.2]가 어디서 왔는지 추적할 수 있습니다.
  • 이 절을 마치면 answer() 한 함수로 질문 → 답까지 완주하고, 토큰 수로 호출 비용을 어림할 수 있습니다.

2왜 지금 이것인가

마지막 상자입니다. 03절의 search()가 반환한 (청크, 점수) 4개를 모델에게 전달해 답을 받으면 RAG 한 사이클이 완성됩니다. 이 절을 마치면 "이틀 안에 실행되는 RAG"라는 챕터 목표가 달성됩니다.

이 절에서 정하는 것이 하나 더 있습니다. 출처 표기 형식입니다. 답 뒤에 [doc_id p.페이지]를 붙이기로 정하면, 그 형식이 05절의 실패 분석, Ch 11의 "무엇을 맞다고 볼지" 합의, 중간 프로젝트 요건("출처 인용")까지 이어집니다. 형식은 지금 정하고, 지키는지 측정하는 것은 Ch 11부터입니다.

3선수 지식 되짚기

  • Ch 6 init_chat_model — 첫 호출 때 쓴 함수 그대로입니다. 메시지를 ("system", …), ("user", …) 튜플 목록으로 넘기는 형식도 같습니다.
  • Ch 7 프롬프트 설계 — 역할 지정, 근거 범위 제한, 출력 형식 지정. 세 가지가 이 절의 시스템 프롬프트 세 줄입니다.
  • Ch 8 컨텍스트 예산 — 청크 4개 × 500자가 프롬프트의 대부분을 차지합니다. k를 늘리면 비용이 어떻게 변하는지 이 절의 토큰 수로 확인합니다.
  • 03절 search() — 이 절의 입력입니다. 검색이 틀리면 이 절은 그 틀린 재료로 답을 만듭니다.

4핵심 개념

비유 — 답안지 규칙

오픈북 시험에서 감독관이 규칙을 정합니다. "책상 위 자료만 보고 답하라. 답의 근거가 된 쪽 번호를 답 옆에 적어라." 규칙이 없으면 학생은 기억으로 답하거나 근거 없이 씁니다. 시스템 프롬프트가 이 규칙이고, 검색 결과를 조립한 문자열이 책상 위 자료이며, [E01 p.2]가 답 옆의 쪽 번호입니다. 규칙을 지킬지는 학생(모델)에게 달려 있다는 점도 같습니다. 05절에서 규칙이 어떻게 깨지는지 봅니다.

정의

컨텍스트 조립 (context assembly)
검색된 청크 여러 개를 모델이 읽을 하나의 문자열로 이어 붙이는 것입니다. 청크마다 출처 태그를 앞에 붙이고 구분선으로 나눕니다. 이 형식이 모델의 출처 표기 형식을 결정합니다.
시스템 프롬프트 (system prompt)
모델의 역할과 규칙을 적는 메시지입니다. 이 절에서는 "문서 절만 근거로 답하라"와 "출처를 [doc_id p.페이지]로 붙여라" 두 규칙을 적습니다.
출처 인용 (citation)
답의 근거가 된 청크의 doc_id·page를 답에 표기하는 것입니다. 모델이 표기한 출처는 검색된 k개 중 하나여야 합니다. 그렇지 않으면 지어낸 출처입니다.
사용량 메타데이터 (usage_metadata)
응답 객체에 붙어 오는 입력·출력 토큰 수입니다. 비용 계산과 06절 하네스 로그의 재료입니다.

7주의할 점과 실무 메모

  • 출처 후보와 실제 출처는 다릅니다. Answer.sources는 검색이 가져온 4개이고, 답에 붙은 [E01 p.2]는 모델이 썼다고 주장하는 것입니다. 둘을 나눠 기록해야 Ch 11에서 검색 지표(Recall)와 생성 지표(Groundedness)를 따로 측정할 수 있습니다.
  • 출처 태그 검증은 정규식 한 줄입니다. 답에서 \[([A-Z]\d{2}) p\.(\d+)\]를 추출해 sources 안에 있는지 확인하면 "지어낸 출처"를 걸러 낼 수 있습니다. Ch 16 가드레일의 출력 검증 항목이고, 여기서는 아직 붙이지 않습니다.
  • 비용. gpt-5.4-mini 표준 요금은 입력 미화 0.75달러, 출력 4.50달러 / 100만 토큰입니다(2026-09-07 확인). 위 호출 하나의 약 1,200개의 토큰을 입력·출력별 단가로 계산한 추정 비용은 약 0.001달러입니다. 출력 토큰이 입력보다 6배 비싸므로 "짧게 답하라"는 규칙은 품질 문제이기 전에 비용 문제입니다.
  • 한국어 출력 규칙. 시스템 프롬프트에 "한국어로"를 넣지 않으면 영어 문서가 섞인 코퍼스에서 영어로 답하는 경우가 생깁니다. 이 코퍼스는 전부 한국어라 영향이 없지만 습관으로 넣습니다.
  • response.content의 타입. LangChain 1.x에서 content는 문자열이거나 콘텐츠 블록 목록일 수 있습니다. 이 절은 str()로 감싸 두었습니다. 멀티모달 응답(Ch 26)에서 이 차이가 중요해집니다.

8정리와 다음 절

  • format_context()가 청크 앞에 [doc_id p.페이지] 태그를 붙여 하나의 문자열로 조립하고, generate()가 그것을 시스템 프롬프트와 함께 모델에 보냅니다. 출처 표기는 프롬프트 규칙이 아니라 조립 데이터가 만듭니다.
  • answer()는 검색 한 번 + 생성 한 번, 두 줄입니다. RAG 첫 완주가 여기서 마무리됩니다.
  • 검색이 가져오지 못한 정보는 제공된 문서 근거로 확인할 수 없습니다. 검색 순위 오류는 k개 안에 정답이 있으면 생성이 흡수하지만, k개 밖이면 제공된 문서에 정답 근거가 없습니다.

다음 학습과 이어지는 지점 — 이 절의 SYSTEM_PROMPT는 05절에서 "모르면 모른다" 한 줄이 추가된 strict 버전으로 바뀌며, 06절 하네스의 prompts.py에 이름을 붙여 저장합니다. 출처 태그 정규식 검증은 Ch 16 출력 검증 모듈이 됩니다. Answer의 sources와 답 속 태그의 차이는 Ch 11·15에서 검색 지표와 생성 지표를 나누는 근거입니다. 다음 05절에서 이 완주한 RAG가 어떻게 실패하는지 일부러 봅니다.

9복습 문제

문제 4개 · 해설 포함

1. 모델이 답에 [E01 p.2]를 붙일 수 있는 것은 코드의 어느 줄 때문입니까?

format_context()에서 청크 앞에 tag = f"[{doc_id} p.{page}]"를 붙이는 줄입니다. 시스템 프롬프트는 "붙여라"라고 지시할 뿐이고, 붙일 문자열은 조립 단계가 줍니다.

2. 수습 급여 질문에서 정답 청크는 3위였고 1·2위는 표지와 다른 회사 규정이었습니다. 답이 맞게 나온 것은 누구의 공입니까? 이 방식의 위험은 무엇입니까?

생성(모델)의 공입니다. k=4 안에 정답이 있었고 모델이 그것을 골랐습니다. 위험은 다른 회사(M05) 규정이 같은 프롬프트에 있어 모델이 그쪽 수치를 고를 수도 있다는 점이고, 실제로 06절 로그에서 정답 청크가 빠진 채 누리테크 규정을 근거로 답한 사례(Q007)가 나옵니다.

3. "검색이 가져오지 못한 정보는 제공된 문서 근거로 확인할 수 없다"를 이 절의 실행 결과로 설명하세요.

실패 3의 반납 질문입니다. 검색 결과에 E01 3쪽이 없었고 모델은 "규정이 없다"고 답했습니다. 프롬프트를 아무리 고쳐도 없는 재료로는 답할 수 없습니다.

4. 입력 1,162개의 토큰 중 질문은 30개의 토큰 미만입니다. 나머지는 무엇이며, k를 8로 바꾸면 비용은 어떻게 됩니까?

나머지는 시스템 프롬프트와 청크 4개입니다. 06절의 같은 8문항 실행에서 k를 4에서 8로 바꾸자 입력 토큰 합계는 9,588에서 17,366으로 약 1.8배가 되었습니다. 같은 입력 단가를 적용하면 입력 비용도 약 1.8배입니다. 증가 폭은 청크 길이와 프롬프트에 따라 달라집니다.

시간 배분 · 시연 순서 · 예상 질문 · 막히는 지점 · A/B 트랙

시간 배분(3h) — 강의 60분: 답안지 규칙 비유(10) · 코드 읽기, 특히 태그와 Answer(25) · 실행 결과 읽기(15) · 비용(10). 실습 120분: 완주 실행(20) · 질문 10개로 답·출처 표 만들기(40) · 실패 1~3(40) · SYSTEM_PROMPT 문구를 바꿔 답 길이 변화 관찰(20).

시연 순서 — ① answer() 두 줄을 먼저 보여 주고 "전체 흐름이 이 두 줄에 담겨 있다"고 설명 ② 위로 올라가 format_context()의 태그 줄을 강조 ③ 모델에게 보낸 문자열을 print로 전체를 보여 줌(학생 대부분이 처음 확인하는 내용) ④ 첫 질문 실행 → 출처 확인 ⑤ 실패 3을 실행해 검색 오류가 생성 결과로 이어지는 과정 확인 ⑥ 챕터 목표 달성 선언.

예상 질문 — "temperature=0으로 고정하면 되지 않나요?" → 이 교재에서는 해당 값을 설정하지 않았으며 모델별 지원 여부를 먼저 확인해야 한다고 답하고, 재현성은 Ch 15 회귀 스위트에서 다룬다고 예고. "출처를 두 개 붙이면요?" → 허용되며 정규식이 둘 다 추출한다고 답함. "답이 너무 짧은데 더 길게 하면?" → 출력 토큰이 6배 비싸다는 점을 들어 요건(중간 프로젝트)에 맞춰 정하라고 안내.

학생이 막히는 지점 — _index.get_store()가 처음 실행 때 색인을 새로 만드느라 몇 초 걸리는 것을 오류로 착각. response.content를 바로 문자열 연산해 타입 오류. 시스템 프롬프트를 사용자 메시지에 합쳐 넣는 습관(Ch 7 복습).

A/B 트랙 — A트랙은 출처 태그 추적까지. B트랙은 정규식으로 답 속 태그를 추출해 sources와 대조하는 check_citations(answer) -> bool을 만들고 테스트를 붙이게 합니다(Ch 16 예행).
