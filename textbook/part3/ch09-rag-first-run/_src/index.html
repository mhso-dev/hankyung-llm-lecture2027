생성 모델은 Ch 6에서 배운 init_chat_model로 준비하고 invoke()로 호출합니다. 텍스트는 응답의 text 속성에서 읽으며, 임베딩은 OpenAIEmbeddings를 사용합니다.

Ch 9챕터 개요

이 챕터에서는 수업을 위해 내용을 지어 만든 PDF로 작은 RAG를 처음부터 끝까지 실행합니다. 노트북 안에서 PDF 읽기 → 문서 청크 나누기 → 임베딩 → 벡터스토어 → top-k 검색 → 출처가 있는 답 생성을 순서대로 확인합니다. 06절에서는 실습 폴더의 설정 파일을 읽어 이번 실행 설정을 만들고, 색인 설정으로 만든 색인 이름표를 앞 실행과 비교합니다. 같은 절에서 제공된 디지털 PDF 18건과 Ch 11의 개발 질문 Q001로 검색·답변을 실행해, 실행 기록 한 줄을 JSONL 파일 두 개에 남깁니다. 마지막 07절은 문서 청크 크기만 바꿔 검색부터 답 검사까지 두 번 실행하고 비교하는 실습 절입니다.

커리큘럼 두 규칙① 이 챕터에 에이전트는 없습니다 — 검색 횟수·k·과업 명세는 학생이 코드에 적고, 모델은 답 문장을 만듭니다. ② 측정이 튜닝보다 먼저입니다 — 이 챕터의 실행 기록 한 줄은 품질 지표 없이 설정·검색 결과·생성 답만 적습니다. Ch 11은 이 기록의 검색 결과를 읽어 별도 평가 로그에 품질 지표를 계산합니다.

목표챕터를 마치면

  • 제공된 합성 PDF 한 건의 다섯 쪽을 모두 읽어 문서 청크로 나눈 뒤, 질문 하나에 출처가 붙은 답을 받을 수 있습니다.
  • 검색 결과의 문서 청크와 검색 점수를 읽고 "검색이 틀렸나, 생성이 틀렸나"를 가릴 수 있습니다.
  • 답이 근거를 벗어난 경우를 검색 누락과 답이 없는 질문으로 가르고, 정답 출처와 정답 문서 ID가 왜 필요한지 말할 수 있습니다.
  • 설정 파일에서 검색 개수 k만 바꿔 실행할 수 있습니다. 색인 이름표와 검색한 문서 청크, 출처가 붙은 답을 실행 기록 한 줄로 JSONL 파일에 남길 수 있습니다.
  • 문서 청크 크기만 바꿔 두 번 실행하고, 점검표 한 줄로 검색 결과와 답 검사를 나란히 비교할 수 있습니다.

준비실습 환경

각 절의 노트북을 Jupyter에서 열고 커널 다시 시작 후 모두 실행을 선택합니다. 첫 코드 셀이 필요한 패키지 버전을 설치합니다. OpenAI API를 사용하는 절의 환경 셀은 프로젝트 루트의 .env를 찾으며, API를 사용하지 않는 02절은 패키지 버전만 확인합니다. 터미널에서 별도의 설치 명령을 실행하거나 교재 코드를 모듈 파일로 옮길 필요가 없습니다.
