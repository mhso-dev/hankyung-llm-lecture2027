1학습 목표

  • 후보 수가 검색할 수 있는 범위를 정하고 모델이 그 범위 안의 순서를 바꾸는 실험의 입력과 출력을 설명할 수 있습니다.
  • 개발용 15문항으로 후보 수와 두 모델의 결과를 비교할 수 있습니다.
  • 관찰한 수치가 설명하는 범위와 설명하지 못하는 범위를 구분할 수 있습니다.

2이 내용을 배우는 이유

리랭커가 검토할 후보를 늘리면 정답 문서가 포함될 여지가 커집니다. 또한 모델마다 한국어 문장의 순위를 다르게 계산합니다. 이 실습에서는 같은 상위 20개 후보를 두 모델에 입력하고, 저장한 점수로 후보 수별 검색 지표를 비교합니다. 시간은 후보 수별 값이 아니라 모델별 20개 후보 전체 점수화 시간으로 따로 기록합니다. 후보 수에 따른 추론 시간 변화를 확인하려면 각 후보 수를 따로 입력해 실행해야 합니다.

Ch11에서 만든 질문과 정답 문서 ID를 유지한 채 한 조건씩 바꿉니다. 개발용 15문항에서 같은 후보 목록을 사용해 후보 수와 모델 조건을 비교합니다.

3앞에서 배운 내용

Ch10에서 PDF를 문서와 청크로 나누고 메타데이터에 출처를 보존했습니다. Ch11의 evaluation-queries.jsonl은 질문마다 gold_doc_ids를 제공합니다. 이 절에서는 그 정답 ID에 해당하는 공개 PDF 6건을 다시 추출한 advanced-documents.json과 같은 30문항을 사용합니다. 앞 절의 변수나 실행 상태는 필요하지 않습니다.

4핵심 개념

후보 범위와 순위 모델을 나누어 보기

후보 수는 리랭커가 볼 수 있는 문서의 범위를 정합니다. 리랭커 모델은 그 범위 안에서 순서를 정합니다. 두 요인을 구분하려면 같은 상위 20개 후보와 질문을 두 모델에 주고, 저장한 점수를 후보 5·10·20개 범위로 잘라 비교합니다.

이번 실험의 비교 단위

각 행은 모델 하나와 후보 수 하나의 조합입니다. Recall은 정답 문서가 후보 범위에 들어왔는지, nDCG@5는 정답이 상위 다섯 자리 어디에 놓였는지 보여 줍니다.

비교 격자 읽기

{{svg:08-후보-모델-격자}}

개발 문항 15개에 대해 두 모델이 공통 상위 20개를 각각 한 번 점수화합니다. 그 점수를 재사용해 후보 5·10·20의 여섯 행을 만들므로, 출력 시간은 후보 수별 시간이 아니라 모델별 전체 점수화 시간입니다.

후보 수와 모델 효과를 분리해 비교하기

후보 수 5·10·20은 리랭커가 볼 수 있는 문서 범위를 바꾸고, 두 CrossEncoder는 같은 질문·후보 쌍에 서로 다른 점수를 냅니다. 공정한 비교에서는 먼저 각 모델이 공통 상위 20개 후보를 한 번 점수화하고, 저장한 점수에서 앞 5·10·20개 범위만 잘라 지표를 계산합니다.

후보 수를 늘려 지표가 좋아지면 정답이 작은 후보 밖에 있었을 가능성이 있고, 같은 후보에서 모델별 순위가 다르면 점수화 차이를 조사합니다. 이번 실제 출력은 모든 조합이 1.000으로 포화되어 두 효과를 구분하지 못합니다.

가상 수계산 예제: 차이가 나타나는 경우

다음 표는 실제 API 출력이 아니라 지표의 뜻을 확인하기 위한 가정입니다. 정답 문서 G가 1차 검색 7위라면 후보 5개에서는 G를 볼 수 없어 Recall=0, nDCG@5=0입니다. 후보 10개에서 모델 A가 G를 2위로 올리면 Recall=1, nDCG@5는 1/log2(3) ≈ 0.6309입니다. 같은 후보에서 모델 B가 G를 1위로 올리면 Recall=1, nDCG@5=1입니다.

가정 조건G의 최종 위치RecallnDCG@5
후보 5, 모델 A후보 밖00
후보 10, 모델 A2위10.6309
후보 10, 모델 B1위11.0000

첫째와 둘째 행의 차이는 후보 범위 효과이고, 둘째와 셋째 행의 차이는 같은 후보에서 모델이 만든 순위 효과입니다.

5실행 예제

두 모델이 동일한 상위 20개 후보를 한 번씩 점수화하고, 저장한 점수에서 후보 5·10·20 범위를 잘라 여섯 행을 만듭니다. Recall과 nDCG가 모두 1.000인지 확인해 이 자료에서 차이가 관찰되었는지 판단합니다.

{{notebook:08-후보-수와-리랭커-비교}}

확인할 점 — 여섯 행의 Recall과 nDCG@5가 모두 1.000입니다. 모델별 시간은 후보 수별 시간이 아니라 상위 20개 전체를 점수화한 시간입니다.

6실험 결과 해석

개발 문항 15개에서 두 모델과 후보 수 5·10·20을 비교한 여섯 행의 Recall과 nDCG@5가 모두 1.000이었습니다. 따라서 이 실제 실행에서는 후보 수 효과도 모델별 순위 효과도 관찰하지 못했습니다. 1.000이 반복된 결과로 어느 후보 수나 모델이 더 낫다고 선택할 수 없습니다.

지표가 포화된 까닭은 이 자료에서 정답이 이미 작은 후보 범위의 상위에 놓였기 때문일 수 있습니다. 차이를 측정하려면 정답이 5위 밖에 놓이는 질문이나 오답 후보의 순서가 중요한 등급 라벨을 추가해야 합니다. 앞의 가상 수계산은 지표가 차이를 표현하는 원리만 보여 주며 실제 모델 성능 근거가 아닙니다.

7주의할 점과 실무 메모

  • 모든 행이 같은 최댓값이면 설정 선택 근거가 없다고 기록합니다.
  • 저장한 상위 20개 점수를 잘라 쓴 결과이므로 후보 수별 추론 시간을 비교한 실험이 아닙니다.
  • 평균이 같아도 질문별 순위가 다를 수 있으므로 설정을 고르려면 질문별 결과도 보존합니다.
  • 차이를 보이려고 가정한 표와 실제 모델 출력의 표를 명확히 구분합니다.

8정리와 다음 절

  • 두 리랭커는 동일한 고정 후보를 한 번씩 점수화했습니다.
  • 실제 여섯 행의 Recall과 nDCG@5가 모두 1.000이어서 조건 차이는 관찰되지 않았습니다.
  • 가상 수계산으로 후보 범위 효과와 같은 후보 안의 순위 효과를 구분했습니다.

9복습 문제

1. 이해 — 이번 절에서 고정한 조건은 무엇인가요?

설정 비교에서 바꾸지 않은 입력을 두 가지 적어 보세요.

개발용 15개의 질문과 각 질문의 정답 문서 ID, 공개 PDF에서 추출한 본문을 유지했습니다. 입력을 고정해야 설정 변화와 결과 변화의 관계를 설명할 수 있습니다. 오답 시 다시 볼 곳: 3절 ‘앞에서 배운 내용’

2. 이해 — 여섯 행이 모두 1.000이면 무엇을 선택할 수 있나요?

후보 수와 모델 선택의 근거가 되는지 설명해 보세요.

이 지표만으로는 어느 조건도 선택할 수 없습니다. 실제 실행에서 후보 수와 모델 효과가 모두 포화되어 차이가 관찰되지 않았습니다. 오답 시 다시 볼 곳: 6절 ‘실험 결과 해석’

3. 적용 — 한 문항의 성공을 어떻게 전체 평가로 넓히나요?

작은 성공 예제 다음에 실행할 평가 절차를 적어 보세요.

개발 문항 15개에서 같은 검색 함수를 실행해 설정을 선택합니다. 시험 문항 15개는 선택이 끝난 뒤 12절에서 한 번만 평가합니다. 오답 시 다시 볼 곳: 5절 ‘실행 예제’

4. 분석 — 어느 모델이 항상 더 좋았나요?
