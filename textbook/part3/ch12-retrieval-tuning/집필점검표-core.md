# Ch 12 전반 01~06 집필 점검표

- 실행일: 2026-09-09
- 환경: Python 3.12.13, uv 잠금 환경, OpenAI `text-embedding-3-small` 256차원, PostgreSQL 17.10, pgvector 0.8.2
- 범위: `_src/01`~`06`, 대응 노트북, `core-*` 데이터와 실행 로그

| 절 | 학습 질문 | 입력과 비교 조건 | 실제 연산 | 관찰 결과 | 해석 범위 |
|---|---|---|---|---|---|
| 01 | 모든 벡터를 비교하면 두 거리의 순위가 어떻게 달라지는가? | 문서 12개·질문 8개 고정, cosine/L2만 변경 | OpenAI 임베딩, NumPy 내적·L2, 전체 정렬 | 벡터 `(12,256)`, 두 거리 Recall@3 모두 7/8 | 단위 길이에 가까운 이 입력에서 순위가 같았으며 일반화하지 않음 |
| 02 | HNSW와 타입·차원 설정은 실제 DB에서 어떻게 동작하는가? | 같은 12개 벡터, 정확/HNSW, ef_search 4/40 | `CREATE INDEX ... hnsw`, `<=>`, 차원 제한 색인 | ext 0.8.2, 정확/HNSW top-3 동일, vector(2001) 실패·halfvec(2001) 성공 | 작은 표라 속도와 recall 교환은 관찰하지 못함 |
| 03 | 필터 결과가 k보다 적을 때 iterative scan이 보충하는가? | 3,000 common·12 rare, ef=5·rare·LIMIT5 고정, scan 모드만 변경 | 실제 HNSW SQL과 post-filter | Before 0개, strict_order After 5개 | 합성 8차원 데이터의 실행 순서 검증이며 임베딩 품질 실험이 아님 |
| 04 | 한국어 형태소가 BM25 입력을 어떻게 바꾸는가? | 같은 12개 문서·8개 질문, 공백/Kiwi 토큰 비교 | `Kiwi.tokenize`, `BM25Okapi.get_scores` | ISBN 질문 LIB-003 1위 6.292, Recall@3 8/8 | 수업용 품사 정책과 작은 말뭉치에 한정 |
| 05 | dense와 sparse는 어느 질문에서 성공 여부가 다른가? | 질문·문서·정답·k=3 고정, 검색기만 변경 | cosine dense, Kiwi+BM25 sparse | dense 7/8, sparse 8/8, C02만 성공 여부 다름 | 검색기 전체 우열이 아니라 실패 질문 발견에 사용 |
| 06 | RRF가 두 순위를 합치면 Recall@3가 개선되는가? | 후보 창 6·상수60·동일 가중치, sparse 가중치만 별도 변경 | 1-based rank의 `weight/(60+rank)` 합산 | dense 7/8, sparse 8/8, RRF 7/8 | 이번 입력에서 개선 미관찰; P@5·nDCG@5 추가 필요 |

## 코드와 본문 대조

- 여섯 노트북은 각각 빈 Python 3.12 커널에서 실행 검증 메타데이터와 코드·출력 해시를 새로 기록했습니다.
- 코드 셀은 최대 16줄이며 한 셀에 한 학습 행동을 두었습니다.
- API 비용은 각 OpenAI 임베딩 절에서 미화 0.01달러 미만으로 예상 범위를 밝혔고 실제 키 값은 출력하지 않았습니다.
- 03절의 Before/After는 설명 셀과 코드 셀에 `lesson_part`를 지정했습니다.
- 본문 수치와 `runs/core-*.json` 원자료를 대조했습니다.
