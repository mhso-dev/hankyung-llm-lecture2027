## 수정 내용과 해석

연결을 없애는 대신 실제 데이터 전달을 추가했습니다. Ch9 06의 설정·검색·기록 학습 흐름은 유지하면서 입력을 제공 PDF로 바꿨고, Ch10의 작은 비교 뒤에 같은 PDF를 사용하는 연결 실험을 추가했습니다. 각 노트북은 앞 커널의 변수 없이 실행하며, 이전 산출물은 저장 파일로 읽습니다. Ch11에는 검증 로그를 함께 배포하여 해당 챕터부터 열어도 실행할 수 있습니다.

`doc_id`는 원문 문서, `page`는 첫 쪽을 1로 세는 PDF 쪽, `chunk_id`는 해당 청킹 설정의 청크입니다. 정답 라벨은 검색 설정과 분리합니다. 문서 수준 지표는 근거가 없는 다른 쪽을 찾은 경우도 점수를 줄 수 있으므로, 검색 순위의 쪽·청크와 원문을 함께 확인하도록 설명했습니다. 디지털 PDF 18건은 물리적으로 93쪽이며 빈 텍스트 쪽을 제외한 Ch11 기준선 후보는 90쪽입니다.

다중 정답에서 Recall을 정답 발견 여부의 참·거짓으로 계산하던 부분을 정답 문서 비율로 바꿨습니다. Ch11과 Ch12 모두 정답 문서가 없거나 답할 수 없는 질문을 검색 평균에서 제외하고 제외 수를 따로 확인합니다. Ch11 기준선은 상위 결과 수와 전체 후보 수를 구분하며, 후보 문서 ID를 남겨 저장 로그에서도 Recall@50을 다시 계산할 수 있게 합니다. 로그에 저장되지 않은 순위는 평가한 것으로 처리하지 않습니다. `null`인 미측정 지표와 0점을 구분하고 저장된 후보에 대한 지표를 별도 이름으로 기록합니다. Ch11의 문서 수 제한과 Ch12의 청크 수 제한도 구분합니다.

Ch12는 질문별 순위·쪽·청크·지표와 난이도별 집계를 남기고, 시험 결과가 어느 개발 설정을 확인한 것인지 실행 ID로 연결합니다. 36개 설정의 점수와 통합 RAG 답변 하나를 같은 실험군의 성능으로 합치지 않습니다. 이전 로그는 보존하고 새 실행 기록을 별도 파일에 저장합니다.

## 실행·배포 검증

- 전체 범위 38개 노트북 중 코드가 바뀐 14개는 Python 3.12.13 새 커널에서 실행했습니다. 나머지 24개는 수정 전 코드·출력·실행 횟수·실행 메타데이터와 같습니다. 최신 자동 대조 결과는 [continuity-static-results.json](continuity-evidence/continuity-static-results.json)에 있습니다.
- Ch9 06은 실제 임베딩·생성을 호출하고 Ch10 08은 실제 6개 설정으로 검색했습니다. 학생 안내에 출력한 `nbconvert` 명령도 실행했습니다. Ch11 01은 30문항의 구조와 분할을 확인하고, 지표 계산·조건 비교·오류 분석은 개발용 질문만 사용합니다. 06에서는 Ch9·Ch10의 개발용 Q001 로그를 직접 읽습니다. Ch12 07~12는 로컬 리랭커 추론과 필요한 임베딩·생성 API를 실제 실행했습니다. 구간별 근거는 [upstream-verification.md](continuity-evidence/upstream-verification.md), [evaluation-verification.md](continuity-evidence/evaluation-verification.md), [tuning-verification.md](continuity-evidence/tuning-verification.md)에 있습니다.
- Ch12의 36개 개발 실행 540개 질문 결과와 시험 결과 15개를 원래 검색 순위로 재계산했습니다. Recall·Precision·nDCG, 난이도별 평균, 질문·정답·분할, 쪽·청크와 통합 답변의 출처가 모두 일치합니다. 원래 `labs/**/runs/*` 49개 파일은 수정 전 SHA-256을 유지합니다.
- 실제 Part3 ZIP을 새 폴더에 압축 해제하고 노트북 폴더를 작업 경로로 삼아 Ch9 06 → Ch10 08 → Ch11 06의 27개 코드 셀을 실행했습니다. 새 검색 실행 ID 7개가 그대로 Ch11 평가의 입력이 되었습니다. Ch9의 @5·@50은 미측정이고 Ch10 여섯 실행은 @5만 계산했습니다. [압축 해제 실행 증거](continuity-evidence/bundle-execution-results.json)와 `bundle-execution/`의 새 로그·노트북을 보존했습니다.
- 압축 해제 검증에서 비밀값은 프로세스 환경으로만 전달했습니다. 검증용 커널 실행기는 저장소의 `textbook/_notebook/execute.py`를 사용했으며, 학생 코드·데이터·평가 모듈은 모두 ZIP에서 읽었습니다. 이 실행기는 학생 실행에 필요한 배포 파일이 아닙니다. 학생의 직접 실행 명령은 별도로 검증했습니다.
- Ch11 README의 상대 입력 경로를 바로잡고, 최종 ZIP을 다시 압축 해제한 뒤 챕터 폴더에서 안내 명령 두 개를 그대로 실행했습니다. 기준선 15문항과 앞 챕터 로그 7개를 모두 읽었습니다. [README 명령 검증](continuity-evidence/readme-cli-results.json)은 최종 ZIP 해시와 실제 출력을 담습니다. 이 검증에는 생성·임베딩 API를 호출하지 않았습니다.
- Part2·Part3·전체 ZIP의 파일 해시를 현재 정본과 대조했습니다. Part3에는 32개 노트북을 포함한 자료 83개, 전체 묶음에는 87개 노트북을 포함한 자료 171개가 있습니다. 공통 시작 안내·예시 환경 파일·manifest는 이 자료 수와 별도입니다. 배포 HTML 38개와 로컬 링크 572개에서 누락 링크가 없고, 배포 파일에 실제 인증정보가 없음을 확인했습니다. 최신 해시는 자동 대조 결과에 기록합니다.
- Ch8~Ch12 본문·목차와 Part3 시작 페이지의 44페이지를 1280px·390px에서 검사했습니다. 화면 88건에서 가로 넘침·잘림·대비·글자 크기·SVG 범위·이미지 로딩·코드 복사·내장 노트북 다운로드 검사를 통과했습니다. 변경된 Ch12 08·12 도식은 생성기로 SVG와 편집 원본을 동기화하고 [실제 화면](continuity-evidence/screens/)도 확인했습니다.

공통 실행·렌더 회귀 검사는 38개와 하위 검사 16개가 통과했습니다. 첫 실행의 검증 환경에 `jupyter_client`·`python-dotenv`가 없어 실패했고, 필요한 실행 패키지를 포함한 뒤 같은 검사를 통과했습니다. 프로젝트 의존성과 테스트 단언문은 이 문제 때문에 바꾸지 않았습니다. [공통 검사 출력](continuity-evidence/runtime-tests.txt)과 [Ch9·10 검사 48개 출력](continuity-evidence/upstream-tests.txt)을 보존했습니다. [Ch11 회귀 검사 8개](continuity-evidence/evaluation-tests.txt)와 [Ch12 회귀 검사 4개](continuity-evidence/tuning-tests.txt)도 통과했습니다. 실제 노트북 함수를 읽어 정답 두 개 중 하나를 찾은 경우의 Recall 0.5, 중복 정답·검색 결과, 빈 정답·답할 수 없는 질문의 제외, 5위 밖 정답의 후보 로그 재계산을 확인합니다. Ch12에 검색 평가 대상이 하나도 없으면 평균을 만들지 않고 명시적인 오류로 알립니다.

## 독립 검토와 한국어 감사

본문 작성·코드 수정 담당자와 별도의 검토자가 현재 `_src`·노트북·로그·배포 경로를 검토했습니다. 검색 후보보다 큰 cutoff 계산, 질문별 쪽·청크 누락, 시험 질문 노출, 새 통합 실행의 질문 수 설명을 수정했습니다. 최종 기록은 `continuity-evidence/independent-final-review.md`입니다.

한국어 산문은 일반 슬롭 검토 → 로컬 맞춤법 → 전문 정독·수정 전후 의미 대조 순으로 확인합니다. 코드·출력은 윤문 대상에서 제외합니다. 외부 맞춤법 전송을 생략한 이유와 자동 구조 검사 WARN의 수동 판정은 `continuity-evidence/language/`에 기록합니다. 최종 판정은 `final-phase6-review.md`의 ACCEPT이며, 이전 조건부 기록은 수정 이력으로 보존합니다.
