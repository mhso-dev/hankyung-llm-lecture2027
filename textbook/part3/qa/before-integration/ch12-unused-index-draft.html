챕터 개요

검색 기반 생성(Retrieval-Augmented Generation, RAG)의 답변 품질은 모델에 전달할 문서를 얼마나 정확하게 찾는지에 크게 좌우됩니다. 이 챕터에서는 검색기를 감싼 도구를 바로 사용하지 않고 거리 계산, HNSW, 한국어 BM25, 순위 결합, 리랭킹의 원리를 짧은 코드와 SQL로 직접 구현합니다. 각 설정은 Ch 11의 같은 질문과 지표로 평가하고, 결과가 달라진 이유를 실험 로그에 남깁니다.

학습 범위는 총 40시간이며 강의 12시간과 실습 28시간으로 구성합니다. 01~06절은 정확 검색에서 하이브리드 검색까지 1차 검색기를 구성합니다. 07~12절은 후보를 다시 정렬하고, 부모 문서를 복원하고, 다양성을 조절하고, 질문을 재작성한 뒤 전체 조합을 평가합니다. 실습에서는 한 번에 한 설정을 바꾸어 결과를 비교합니다.

학습 목표

  • 벡터 거리와 정확 검색을 기준선으로 삼아 HNSW 근사 검색의 결과를 비교할 수 있습니다.
  • pgvector의 vector·halfvec, HNSW 설정, 메타데이터 필터와 iterative scan을 실제 SQL로 확인할 수 있습니다.
  • Kiwi 형태소와 BM25로 한국어 sparse 검색을 만들고 dense 검색과 서로 다른 성공 사례를 설명할 수 있습니다.
  • RRF, cross-encoder, Parent-document 검색, MMR, 질문 재작성을 조합하고 실험 로그로 남길 수 있습니다.

준비 자료와 실행 환경

01~06절은 labs/part3/ch12-retrieval-tuning/data/core-documents.json과 core-queries.json을 사용합니다. OpenAI 임베딩은 .env의 OPENAI_API_KEY를 읽으며 키 값은 출력하지 않습니다. pgvector 실습은 127.0.0.1:55432에만 공개한 전용 Docker 컨테이너와 rag_lab 데이터베이스를 사용합니다. 연결 문자열의 비밀번호는 로컬 교육용 값이며 실제 서비스에 재사용하지 않습니다.

docker run --name hankyung-part3-pgvector \
  -e POSTGRES_USER=student \
  -e POSTGRES_PASSWORD=local-practice-only \
  -e POSTGRES_DB=rag_lab \
  -p 127.0.0.1:55432:5432 \
  -d pgvector/pgvector:0.8.2-pg17

실습을 마친 뒤에는 docker stop hankyung-part3-pgvector로 중지합니다. 데이터를 다시 사용할 때는 docker start hankyung-part3-pgvector로 시작할 수 있습니다. 완전히 삭제하려면 필요한 로그를 먼저 보관한 뒤 docker rm hankyung-part3-pgvector를 실행합니다.

다음 학습과 이어지는 지점

12절에서 선택한 검색 설정과 실험 로그는 중간 프로젝트 평가 리포트의 근거가 됩니다. Ch 13부터는 이 검색 단계를 LangGraph의 상태와 노드에 연결합니다. 그래프를 먼저 만들기보다 어떤 검색 설정이 어떤 질문에서 효과가 있었는지 숫자로 확인한 뒤 흐름에 넣습니다.
