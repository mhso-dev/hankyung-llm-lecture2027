## 최소 수정 계획

1. Ch8의 Select 및 평가 예고를 Ch9 검색, Ch11 검색 평가, Ch15 생성 답변 평가와 대조합니다. 현재 학생용 코드에 존재하는 이름으로 연결합니다.
2. Ch9·Ch10의 실제 검색 결과와 설정을 기록하고 Ch11이 읽어 평가하도록 연결합니다. 원본 로그를 덮어쓰지 않고 별도 연결 검증 로그를 남깁니다. 작은 실습과 30문항 기준선의 문서·질문·평가 단위 차이를 설명합니다.
3. Ch12의 작은 자료, 후반 PDF 6건·30문항 평가 사이의 전환과 ID 대응을 확인합니다. 설정 비교 36건과 별도 통합 RAG의 범위를 구분하고 개발·시험 분리를 유지합니다.
4. 변경 코드는 필요한 회귀 검사 후 Python 3.12 새 커널에서 실행합니다. 설명만 변경한 노트북은 코드·출력·실행 메타데이터의 동일성을 검사합니다. `_src`에서 빌드한 HTML의 코드·출력·다운로드를 대조합니다.
5. 배포 목록과 시작 안내를 갱신하고 압축 해제본에서 실제 연결 경로를 실행합니다. PC·모바일 표시·복사와 독립 의미 검토를 완료합니다.

## 독립 초기 검토에서 추가 확인한 항목

- Ch9 `_src/01-RAG-지도.html:19`·`02-로더와-스플리터.html:16`은 Ch4에서 `pypdf.PdfReader`·`extract_text()`를 이미 사용했다고 적습니다. 현재 Ch4의 학생용 파싱 실습은 BeautifulSoup/lxml을 사용하는 HTML 처리입니다. PDF 파싱을 Ch9에서 처음 배우는 것으로 설명해야 합니다. 중요도: 중간.
- Ch9 `_src/04-생성과-출처-인용.html:7`의 Ch11 출처 형식 측정 예고는 현재 Ch11의 판정 기준 합의와 다릅니다. 기준 합의와 자동 생성 답변 평가의 시점을 구분해야 합니다. 중요도: 중간.
- Ch10 `_src/01-문서와-메타데이터.html:77`의 Ch12 `file_type`·`parser` 실패 유형 집계와 `_src/index.html:27`의 청킹·리랭킹 설정 비교 예고는 Ch12의 현재 36건 실행 범위와 맞지 않습니다. 실제 사용 필드와 실행별 범위를 연결해야 합니다. 중요도: 중간.
- Ch11과 Ch12의 30문항은 질문·정답 ID·분할을 포함해 동일하며 개발용·시험용이 15개씩입니다. 독립 검토자는 Ch12 부모 6건·자식 175개를 원 PDF에서 재추출·재청킹해 현재 데이터와 같은지 확인했습니다. Ch11의 `[E02 p.4]` 예시도 실제 출장 숙박비 근거 쪽과 일치합니다. 이 항목은 결함으로 처리하지 않습니다.

## 개발용·시험용 분리의 추가 결함

Ch12 08절의 후보 수·리랭커 비교는 `for item in queries`로 30문항 전체를 사용합니다(수정 전 노트북 셀 6·8). 07·09·11절과 12절 통합 예제는 시험용 `Q009`를 반복해서 사용합니다. 11절의 “별빛제과 자기계발비” 대화도 Q009와 같은 질문 주제입니다. 따라서 12절에서 시험용 15문항을 한 번만 계산하더라도 앞선 학습·설정 비교에서 이미 내용을 관찰했습니다. 중요도: 높음(C08).

최소 수정은 질문셋의 기존 분할을 바꾸지 않고, 07~11절의 설정 비교·예제를 개발용 질문으로 제한하는 것입니다. 재작성 예제의 대화도 개발용 주제로 바꾸고 해당 노트북은 실제로 다시 실행합니다. 기존 시험 질문을 사용한 과거 실행 기록을 미관찰 시험 결과로 해석하지 않으며, 이미 기존 교재로 설정을 조절한 학생은 새로운 시험 질문을 별도로 준비해야 한다는 한계를 설명합니다.

Ch11 02·03절의 설정 비교, 04절의 지표 계산, 05절의 오류 분석 역시 30문항 전체를 순회했습니다. 특히 05절에서 시험용 질문의 실패 원인을 분석한 뒤 Ch12 튜닝에 들어가면 개발/시험 분리의 목적을 지킬 수 없습니다. Ch11 01절의 데이터 구조·분할 개수 확인은 유지하고, 실제 계산·조건 변경·오류 분석은 개발용 15문항으로 제한합니다. 명시적인 시험 실행 경로는 선택한 설정을 확인하는 단계로 구분합니다.

## 수정 과정의 독립 재검토에서 발견한 보완 사항

연결 로그를 구현한 뒤에도 필드의 존재만으로 완료를 판정하지 않았습니다. Ch9의 설정 안에 질문·정답 라벨을 중복 저장한 부분은 검색 설정과 평가 라벨을 분리했습니다. 생성 답변의 `[doc_id p.N]` 출처가 실제 검색 결과의 문서·쪽을 가리키는지도 확인합니다.

Ch11에서는 실제 저장된 후보가 2개인 Ch9 로그에 @5·@50을 모두 적용할 수 없습니다. 후보가 5개인 Ch10 로그도 @50을 확인할 수 없습니다. 범위 밖의 표준 지표는 미측정으로 남기고, 저장된 후보의 검색 결과만 별도 이름으로 계산해야 합니다. 기준선과 외부 로그 모두 문서·쪽·청크·순위를 기록해 평균에서 원래 검색 결과로 돌아갈 수 있어야 합니다.

Ch12의 설정 비교 로그에는 질문별 지표뿐 아니라 실제 상위 결과의 문서·쪽·청크·순위가 필요합니다. `source_chapter`는 실행이 발생한 챕터이고 질문 자료의 출처와 구분합니다. 50개 청크를 먼저 고른 뒤 문서 중복을 제거하는 Ch12의 제한 단위는 Ch11의 문서 제한 단위와 다릅니다. 선택한 개발 실행 ID를 시험 로그에 기록하고, 통합 생성 기록은 별도 실행 종류와 미평가 상태를 유지합니다.

배포 시작 안내의 `uv sync --locked`와 챕터 README의 준비 명령을 맞춥니다. Ch9 01절의 짧은 예제 범위는 실제 PDF로 바뀐 06절과 구분하고, pypdf 버전 표기는 해당 노트북의 설치 셀을 기준으로 수정합니다. 모두 연결성·실행 안내와 직접 관련된 수정이며 무관한 문체 변경은 포함하지 않습니다.
