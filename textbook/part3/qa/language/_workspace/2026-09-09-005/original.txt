# Ch 9 — RAG 첫 완주 + 실험 하네스

기본 학습 경로는 `notebooks/`의 절별 노트북입니다. 01·02절은 제공 PDF를 읽고, 나머지 절은 짧은 문서와 설정을 셀 안에서 준비합니다. API를 사용하는 절은 프로젝트 루트의 `.env`에서 `OPENAI_API_KEY`를 읽습니다. Jupyter에서 노트북을 열고 커널을 다시 시작한 뒤 위에서 아래로 실행합니다.

아래 스크립트와 전체 PDF 말뭉치는 기본 노트북을 마친 뒤 사용하는 선택 확장입니다. 노트북의 작은 실행 결과와 스크립트의 전체 말뭉치 결과는 규모가 다릅니다.


`OPENAI_API_KEY`는 프로젝트 루트 `.env`에서 읽습니다. `.cache/`(색인)와 `runs/`(실험 로그)는 실행하면 생깁니다.


===== labs/part3/ch09-rag-first-run/notebooks/01-RAG-지도.ipynb =====
[markdown cell 1]
<h3>실습 안내</h3>
<p>프로젝트에 제공된 <code>E01.pdf</code>는 수업을 위해 내용을 지어 만든 문서입니다. 파일을 복사할 필요는 없습니다. 코드가 현재 폴더에서 시작해 부모 폴더를 하나씩 확인하고 원본 위치를 찾습니다.</p>

[markdown cell 3]
<h3>1. 제공된 PDF 찾기</h3>
<p>노트북을 어느 폴더에서 열었든 PDF를 찾을 수 있도록 현재 폴더부터 부모 폴더를 하나씩 확인합니다.</p>

[markdown cell 5]
<h3>2. PDF에서 쪽별 텍스트 읽기</h3>
<p><code>PdfReader</code>가 PDF를 읽으면 <code>pages</code>에 쪽별 데이터가 들어갑니다. 각 쪽을 <code>Document</code>로 바꿉니다. Document는 본문과 출처 정보를 한 묶음으로 담는 LangChain 객체입니다.</p>

[markdown cell 7]
<h3>3. 쪽을 검색 단위로 나누기</h3>
<p><code>RecursiveCharacterTextSplitter</code>는 쪽 본문을 검색하기 좋은 작은 조각인 청크로 나눕니다. 문서 ID와 쪽 번호 같은 출처 정보(metadata)도 각 청크에 복사합니다. API 비용을 낮추기 위해 질문과 관련된 2~3쪽만 숫자 벡터로 바꿉니다.</p>

[markdown cell 9]
<h3>4. API 키 준비</h3>
<p>프로젝트 루트의 <code>.env</code>를 읽고 임베딩과 생성 호출을 준비합니다.</p>

[markdown cell 11]
<h3>5. 청크를 임베딩해 저장하기</h3>
<p>임베딩 모델은 청크의 뜻을 비교할 수 있도록 글을 숫자 목록인 벡터로 바꿉니다. <code>InMemoryVectorStore</code>는 이 벡터와 원본 Document를 현재 파이썬 실행 메모리에 보관합니다.</p>

[markdown cell 13]
<h3>6. 질문과 가까운 청크 검색하기</h3>
<p>질문을 임베딩한 뒤 가장 가까운 청크 2개를 가져옵니다. 답을 만들기 전에 문서 ID, 쪽, 본문을 먼저 보여 줍니다.</p>

[markdown cell 15]
<h3>7. k만 1로 바꾸어 비교</h3>
<p>질문·임베딩·문서는 그대로 두고 검색 개수만 2에서 1로 줄입니다. 생성 전에 출처 후보가 어떻게 달라지는지 확인합니다.</p>

[markdown cell 17]
<h3>8. 검색 결과로 프롬프트 만들기</h3>
<p>각 청크 앞에 <code>[문서 ID p.쪽]</code> 모양의 출처 태그를 붙입니다. 그런 다음 모델이 참고할 문맥(<code>context</code>) 문자열 하나로 연결합니다.</p>

[markdown cell 19]
<h3>9. LangChain으로 답변 생성하기</h3>
<p>삼중따옴표 문자열은 여러 줄 프롬프트를 코드 모양 그대로 적을 때 사용합니다. 문서만 근거로 사용하고 출처를 붙이라고 명시합니다.</p>

[markdown cell 21]
<h3>10. 첫 RAG 완주 확인</h3>
<p>출력 문자열에 PDF의 휴관일과 출처 형식이 함께 있는지 검사합니다.</p>

[markdown cell 23]
<h3>정리</h3>
<p>수업용 PDF를 쪽별 Document로 읽고 작은 청크로 나눴습니다. 청크를 벡터스토어에 저장하고 검색한 문맥을 모델에 전달해 출처가 있는 답을 만들었습니다.</p>

[markdown cell 24]
<p><strong>원인</strong> — 질문만 모델에 전달하면 제공 PDF의 본문과 출처를 사용할 수 없습니다.</p>

[markdown cell 26]
<p><strong>수정</strong> — 검색한 PDF 문맥과 출처 형식을 프롬프트에 넣어 같은 질문을 다시 실행합니다.</p>

[markdown cell 14]
<p><strong>수정</strong> — 다른 값은 유지하고 <code>chunk_overlap</code>만 0에서 5로 늘려 경계 양쪽 문자를 함께 보존합니다.</p>

===== labs/part3/ch09-rag-first-run/notebooks/05-첫-실패-보기.ipynb =====
[markdown cell 1]
<h3>실습 안내</h3><p>두 경우를 구분합니다. 첫째, 전체 문서에 답이 없습니다. 둘째, 정답 문서는 있지만 검색 결과에서 빠졌습니다. 모델의 답만 보지 않고 검색된 문서 ID도 함께 확인합니다.</p>

[markdown cell 3]
<h3>1. API 키 준비</h3><p><code>.env</code>를 로드하고 외부 API를 사용할 수 있는지 확인합니다.</p>

[markdown cell 5]
<h3>2. 검색 실패를 보이는 문서 준비</h3><p>첫 문서 <code>DISTRACTOR</code>는 질문과 같은 단어가 많지만 답은 없습니다. 둘째 문서 <code>ANSWER</code>에는 실제 연체 규정이 있습니다.</p>

[markdown cell 7]
<h3>3. k=1 검색 중간값 관찰</h3><p>생성 모델을 호출하기 전에 어느 문서가 선택되었는지 확인합니다.</p>

<h3>4. k=1 문맥으로 엄격한 답 생성</h3><p>검색 문서에 답이 없으면 “찾을 수 없습니다”라고만 답하도록 모델에 지시합니다.</p>

[markdown cell 11]
<h3>5. k만 2로 바꾸어 검색 비교</h3><p>다른 값은 그대로 두고 <code>k</code>만 늘려 정답 문서가 포함되는지 확인합니다.</p>

<h3>6. 수정된 문맥으로 다시 답하기</h3><p>같은 엄격한 지시와 질문을 유지하고 문맥만 <code>context_k2</code>로 바꿉니다.</p>

[markdown cell 15]
<h3>7. 문서 집합에 답이 없는 경우 비교</h3><p>RAG 문서 자체에 정보가 없으면 <code>k</code>를 늘려도 답을 만들 근거가 생기지 않습니다.</p>

[markdown cell 17]
<h3>정리</h3><p>모델이 똑같이 “찾을 수 없습니다”라고 답해도 원인은 다를 수 있습니다. 검색된 문서 ID를 보면 정답 문서가 검색에서 빠졌는지, 전체 문서에 답이 없는지 구분할 수 있습니다.</p>

[markdown cell 18]
<p><strong>원인</strong> — <code>k=1</code>이 DISTRACTOR만 가져와 정답 규정이 프롬프트에 들어가지 않았습니다.</p>

[markdown cell 20]
<p><strong>수정</strong> — 앞에서 k를 2로 바꾸어 실행한 검색 ID와 생성 답을 다시 나란히 보여 줍니다. ANSWER가 포함되고 대출 정지 규정이 답에 있는지 검사하며, 이 셀에서는 모델을 추가로 호출하지 않습니다.</p>


===== labs/part3/ch09-rag-first-run/notebooks/06-실험-하네스.ipynb =====
[markdown cell 1]
<h3>실습 안내</h3>
<p>YAML 설정을 읽고 환경 변수로 검색 개수를 바꿉니다. 실제 임베딩 검색과 답변 생성을 실행한 뒤 설정·검색 결과·답을 JSONL 한 행으로 저장하고 다시 읽습니다.</p>

[markdown cell 3]
<h3>1. API 키와 임시 실험 폴더 준비</h3><p><code>.env</code>에서 키의 존재만 확인하고, 노트북 실행 동안 유지되는 임시 폴더를 만듭니다.</p>

[markdown cell 5]
<h3>2. YAML 설정 파일 만들기</h3><p>바꿀 값을 코드 여러 곳에 흩어 놓지 않고 YAML 한 곳에 모읍니다.</p>

[markdown cell 7]
<h3>3. YAML을 읽고 실행 조건 하나 바꾸기</h3><p><code>RETRIEVAL_K</code> 환경 변수가 있으면 그 값을 사용하고, 없으면 2를 사용합니다. 기본값 1과 변경값을 비교합니다.</p>

[markdown cell 9]

[markdown cell 4]

<p>이 절은 유지보수가 종료된 langchain-experimental 0.4.2의 SemanticChunker로 원리를 학습합니다. 해당 버전에 한정한 실습이며 새 운영 시스템의 기본 선택을 권장하는 예제가 아닙니다.</p>
