챕터 개요

문서에서 글자를 추출했다고 해서 검색에 필요한 정보가 모두 보존되는 것은 아닙니다. 표의 열 제목이 사라지면 숫자의 뜻을 알기 어렵고, 예외 조항이 다음 청크로 분리되면 본문 규정만 검색될 수 있습니다. 이 챕터에서는 원문의 내용과 출처를 함께 보존하는 문서 처리 과정을 만듭니다. Ch 9에서 연결한 로더·스플리터·임베딩의 입력과 출력을 하나씩 확인하고, 처리 방법을 바꾸었을 때 무엇이 달라지는지 기록합니다.

학습 범위는 강의 8시간과 실습 16시간입니다. 각 절은 강의 1시간과 실습 2시간으로 구성하며, 설명·실행 예제·실패 사례·복습 문제·강사 노트를 함께 제공합니다. 문서를 처리하는 순서는 파이썬 함수와 조건문으로 정합니다. 검색 품질 지표는 Ch 11에서 계산하고, 최적 설정은 Ch 12에서 선택합니다.

학습 목표

  • 문서 형식에 맞는 로더를 선택하고, 텍스트·표·쪽 번호가 보존되었는지 원문과 대조할 수 있습니다.
  • 문자·재귀·토큰·구조·시맨틱 청킹의 경계 기준과 한계를 설명할 수 있습니다.
  • 임베딩의 한국어 적합성을 확인할 항목을 정하고, 모델·입력·설정이 다른 캐시를 분리할 수 있습니다.
  • 같은 문서에 청킹 3가지와 임베딩 2가지를 적용한 실험 기록을 Ch 11의 평가 입력으로 준비할 수 있습니다.

준비 자료와 학습 순서

선수 교재는 Ch 9 RAG 첫 완주와 실험 하네스입니다. 실습 코드는 labs/part3/ch10-document-processing/, 실행 방법과 환경 고정 파일은 같은 폴더의 README.md·pyproject.toml·uv.lock에 있습니다. 문서 세트는 labs/data/rag-corpus/를 사용합니다.

현재 제공된 합성 문서는 텍스트 PDF 18건과 스캔 PDF 3건입니다. 스캔 문서는 추출 실패를 확인하는 실습에 사용합니다. 커리큘럼의 도메인 문서 100건 실습은 별도 문서 수집 후 수행하는 확장 과제입니다. 동일 문서를 복사하여 100건으로 세지 않습니다. 임베딩 최종 선정은 [[미정: 임베딩 모델]]로 남겨 두며, 예제에서 사용하는 모델과 선정 기준을 구분합니다.

다음 학습과 이어지는 지점

이 챕터의 처리 결과에는 문서 ID와 청크 ID가 함께 남습니다. Ch 11에서는 이 식별자를 정답 문서 ID와 비교하여 검색 지표를 계산합니다. Ch 12에서는 그 지표를 근거로 청킹·검색·리랭킹 설정을 변경합니다. 처리 시간과 청크 수만으로 검색 품질이 좋아졌다고 결론 내리지 않습니다.

확인 필요 항목

도메인 문서 100건 확보와 최종 임베딩 모델 선정은 남아 있습니다. HWP 변환, 실제 업무 HWPX 문서 검증, OCR 및 상용 파서 실행 범위는 각 절의 실행 결과와 주의할 점에 표시합니다. 실습용 파일에서 확인한 성공 사례를 모든 업무 문서에 일반화하지 않습니다.

이번 집필 환경에는 OPENAI_API_KEY가 없어 실제 OpenAI 임베딩 호출은 실행하지 않았습니다. 3×2 실험의 저장 출력은 교육용 특징 벡터로 청킹·캐시·검색 로그의 동작을 검증한 결과입니다. 두 실제 모델의 성능 비교 결과로 사용하지 않습니다. 실제 API 실행 방법과 필요한 키는 실습 README에 안내합니다.
