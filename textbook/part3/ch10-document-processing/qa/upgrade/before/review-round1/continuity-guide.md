# Ch8–Ch12 실습을 이어서 실행하기

Ch8에서는 필요한 정보를 선택해 질문과 함께 모델에 전달했습니다. Ch9에서는 검색으로 근거를 선택하고 답변을 생성합니다. Ch10에서는 같은 원문을 나누는 방법을 바꾸고, Ch11에서는 검색 결과에 정답 문서가 포함됐는지 계산합니다. 생성 답변의 정확성과 근거 충실도 평가는 Ch15의 후속 학습입니다.

## 실행 순서와 저장 파일

압축을 푼 폴더 전체를 유지합니다. 각 챕터의 `README.md`에 따라 `uv sync --locked`로 패키지를 준비하고 그 환경을 노트북 커널로 선택합니다. 각 노트북은 새 Python 3.12 커널에서 첫 셀부터 실행합니다. 앞 노트북의 변수는 사용하지 않고 저장한 파일을 읽습니다.

1. `labs/part3/ch09-rag-first-run/notebooks/06-실험-하네스.ipynb`를 실행합니다. 제공된 디지털 PDF 18건과 개발용 Q001로 설정에 따라 검색과 답변 생성을 실행하고, 그 기록을 `labs/part3/ch09-rag-first-run/runs/continuity-ch09-search.jsonl`에 저장합니다.
2. `labs/part3/ch10-document-processing/notebooks/08-인덱싱-비교-실험.ipynb`를 실행합니다. 작은 원문의 여섯 조합을 관찰한 뒤, 같은 18개 PDF와 Q001에 적용한 여섯 조합의 검색 결과를 `labs/part3/ch10-document-processing/runs/continuity-ch10-indexing.jsonl`에 저장합니다.
3. `labs/part3/ch11-evaluation/notebooks/06-실험-로그와-자동-실행.ipynb`를 실행합니다. 앞 두 파일을 읽어 검색 지표를 계산하고, 원본 검색 로그와 분리된 평가 결과를 저장합니다.
4. Ch12의 01~06절에서 작은 자료로 검색 원리를 관찰하고 07~12절에서 제공 PDF와 연결된 자료를 사용합니다. 12절에서는 Ch11과 같은 30문항 중 개발용 질문으로 설정을 고른 뒤, 선택에 사용하지 않은 시험용 질문으로 확인합니다.

Ch11을 먼저 열어도 독립 실행할 수 있도록 배포 묶음에 검증 과정에서 생성한 Ch9·Ch10 검색 로그를 포함합니다. 자신의 실행 결과를 평가하려면 위 순서로 앞 두 노트북을 먼저 실행합니다. 저장된 실행 결과와 자신의 새 실행 결과를 구분하고, 노트북에 출력되는 실행 ID와 파일 경로를 확인합니다.

## 식별자와 비교 범위

Ch8의 작은 예제에서는 `E01-p3`를 한 근거 레코드의 복합 ID로 사용하고 출처를 `[E01-p3]`로 적습니다. Ch9부터는 같은 원문 위치를 문서 ID `doc_id="E01"`과 정수 쪽 번호 `page=3`으로 분리하고 `[E01 p.3]`으로 표시합니다. 두 ID 문자열을 같은 필드의 값으로 직접 비교하지 않습니다. Ch8의 요약 근거와 Ch9의 PDF 원문은 자료의 길이가 다르며, 문서와 쪽을 확인해 같은 위치인지 대조합니다.

| 항목 | 뜻과 확인할 점 |
| --- | --- |
| `doc_id` | 원문 문서 ID입니다. PDF의 `E01`과 짧은 예제의 `D01`·`LIB-001`은 서로 다른 문서입니다. |
| `page` | PDF의 첫 쪽을 1로 세는 쪽 번호입니다. 쪽이 없는 작은 예제에 실제 PDF 쪽 번호를 임의로 붙이지 않습니다. |
| `chunk_id` | 한 색인 설정에서 나눈 청크 ID입니다. 청킹 설정이 다르면 같은 원문에서도 ID와 경계가 달라집니다. |
| `qid`·`question` | 질문 ID와 원문입니다. ID가 같아도 질문이 바뀌면 같은 평가로 비교할 수 없습니다. |
| `gold_doc_ids` | 사람이 원문에서 확인한 정답 문서 ID 목록입니다. 검색 결과를 보고 정답 ID를 바꾸지 않습니다. |
| `retrieved` | 실제 순서대로 검색된 결과입니다. 문서·쪽·청크 식별자와 검색 순위를 함께 읽습니다. |
| 출처 표기 | `[E01 p.2]`는 문서와 쪽을 가리킵니다. 해당 출처에 답의 근거가 있는지는 원문으로 확인합니다. |

Ch9·Ch10에서 Ch11으로 전달하는 소규모 기록은 파일 전달과 지표 계산을 확인하는 실습입니다. 이 점수를 Ch11의 전체 PDF 기준선이나 Ch12의 설정 비교 점수와 직접 비교하지 않습니다. 문서 집합, 질문 집합, 청킹, 검색 방법, 반환 개수와 평가 단위가 같아야 변경 효과를 해석할 수 있습니다.

Ch9·Ch10 로그에 기록된 후보 수보다 큰 범위의 지표는 측정하지 않은 것으로 표시합니다. 후보가 2개뿐인 Ch9 로그에서는 @5와 @50 지표를 모두 미측정으로 남깁니다. 후보가 5개인 Ch10 로그에서는 @5 지표를 계산하되 Recall@50은 미측정으로 남깁니다. `recall_at_logged_candidates`는 실제 저장된 후보에서의 정답 문서 포함 비율이며, `null`은 미측정 값으로 0점과 다릅니다.

Ch11은 검색 결과의 문서 ID 중복을 제거한 뒤 문서 단위로 평가합니다. 정답 문서의 다른 쪽이 검색되더라도 문서 수준 점수에는 반영될 수 있으므로, 점수만으로 정답 근거를 찾았다고 단정하지 않습니다. `page`·`chunk_id`와 실제 본문을 함께 읽습니다. 제공 디지털 PDF 18건은 전체 93쪽이며, 텍스트가 있는 쪽은 90쪽입니다. Ch11의 페이지 기준선은 빈 텍스트 쪽을 제외하므로 전체 쪽 수와 검색 후보 수가 다릅니다. Ch11의 단어·두 글자 조각 검색과 Ch12의 TF-IDF 검색은 서로 다른 기준선입니다. Ch11의 후보 제한은 중복을 제거한 문서 수를 기준으로 하고, Ch12의 후보 제한은 청크 수를 기준으로 한 뒤 부모 문서 중복을 제거합니다. 같은 @50 표기라도 후보를 제한하는 단위가 다릅니다.

Ch12 전반의 `core-*.json`은 원리를 관찰하는 별도 짧은 자료입니다. 후반의 `advanced-queries.json`은 Ch11의 `evaluation-queries.jsonl`과 같은 질문·정답·분할을 담습니다. `advanced-documents.json`은 제공 PDF에서 만든 부모·자식 자료입니다. 전반의 작은 예제 점수와 후반 PDF 점수를 이어진 개선율처럼 계산하지 않습니다.

Ch12의 36건은 TF-IDF와 MMR 설정을 바꾼 검색 비교입니다. 하이브리드 검색·리랭킹·부모 문서 전달·생성을 잇는 통합 RAG 실행은 별도 기록입니다. 현재 배포 파일은 Ch12 `runs/advanced-continuity-experiment-log.jsonl`(개발 설정 비교), `advanced-continuity-test-result.json`(선택 설정의 시험 평가), `advanced-continuity-integrated-result.json`(통합 실행)입니다. 세 파일의 결과를 합쳐 36개의 전체 RAG 조합을 평가했다고 해석하지 않습니다. 통합 실행의 한 답변을 30문항 전체의 생성 답변 평가 결과로 쓰지 않습니다.

이전 교재의 전체 30문항 비교나 시험용 Q009 예제를 보고 설정을 조절했다면 기존 시험용 질문은 이미 설정 선택에 사용한 자료입니다. 수정본의 코드로 다시 실행해도 시험 질문의 답이나 검색 결과를 이미 확인한 사실은 바뀌지 않습니다. 그런 경우 최종 성능 확인에는 설정 선택에 사용하지 않은 새 시험 질문을 준비합니다.

## 다음 학습에 보관할 것

실험 설정, 질문·정답 ID·분할, 원본 검색 결과, 계산한 지표와 실제 생성 답변을 구분해 보관합니다. Ch13에서는 검색·병합·재정렬·생성의 입출력을 그래프로 옮기고, Ch15에서는 실제 답변과 근거가 있는 기록을 사용해 생성 답변 평가를 확장합니다. 후속 챕터의 교재와 실행 코드는 이 묶음에 포함되어 있지 않습니다.
