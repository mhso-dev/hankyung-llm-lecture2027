## 3. 바꾼 것

### 학습 질문과 데이터

- 학습 질문(같은 이름의 두 형식이 파일 안에서 얼마나 다른가, 압축 파일 속 XML에서 글을 어떻게 꺼내는가)과 **paired 형식**, 견본 두 개(`fixtures/legacy-signature.hwp`·`minimal-marker.hwpx`)를 유지했습니다. 견본은 01절 2절에서 확장자만 세어 보인 파일입니다.
- **Before/After 주제를 다시 잡았습니다.** 3·4절은 값만 관찰하고(앞 여덟 바이트·압축 묶음 여부), 갈래를 정하는 함수 `recognize_file_kind()`는 After에서 처음 만듭니다. Before는 「확장자 이름만 보고 압축 묶음으로 열기」입니다. 그래서 본문 순서와 Before의 잘못이 어긋나지 않습니다.
- **값 바꿔 보기를 바꿨습니다.** 「모든 XML 대 본문 section XML」(두 값이 모두 1)을 빼고 「고를 요소 이름 `"t"` → `"p"`」로 두었습니다. 요소는 있는데 글이 없어 본문이 0자가 되는 것을 출력으로 보입니다.
- 03절 `make_unit_record()`와 `make_unit_mark()`를 **같은 코드로** 가져왔습니다. 02·03절 `make_cell_text()`·`make_row_text()`는 이 절에 표가 없어 쓰지 않았습니다.

### 쪽 번호가 없는 형식의 자리 칸 (handoff §03 → §04의 결정 항목)

- 03절이 정한 네 칸(`doc_id`·`source`·`file_type`·`parser`)에 **자리 칸 `section` 하나**를 더해 다섯 칸으로 적습니다. 이름은 실습 폴더 `document_processing.py` `load_hwpx()`가 쓰는 것과 같고, `parser` 값은 `zip-xml`입니다.
- **`make_unit_mark()`는 고치지 않았습니다.** 그 함수는 `row` 칸만 읽어서 이 기록에서는 `[minimal-marker hwpx]`까지만 만듭니다. 노트북 9절에서 그 결과를 출력으로 보이고, `section` 칸을 읽는 `make_section_mark()`를 하나 더 만들어 `[minimal-marker hwpx section.1]`을 얻었습니다.
- 같은 이름으로 다시 정의하지 않은 까닭은 05절 이후에도 두 표시를 가려 쓸 수 있게 두려는 것입니다. 실습 폴더 모듈은 문서 청크 이름을 만들 때 `page`·`section`·`row`를 차례로 보고 먼저 있는 칸을 쓰며, 그 사실을 본문 b7에 적었습니다.
- 자리 칸 번호는 1부터 셉니다(실습 폴더 모듈과 같음). 03절 CSV `row`가 2부터인 까닭(첫 줄이 칸 이름 줄)과 다른 점을 노트북 9절 결과 읽기에 적었습니다.

### 새로 실행으로 보인 것

- 견본 두 개의 앞 여덟 바이트가 다릅니다(`d0cf11e0a1b11ae1`·`504b030414000000`, `두 값이 같은가: False`). 압축 묶음 여부도 다릅니다(`False`·`True`).
- HWPX 압축 묶음 안에 항목이 두 개 있습니다(`Contents/content.hpf`·`Contents/section0.xml`). 이름 조건 두 개로 본문 XML 하나를 골랐습니다(`본문 XML 수: 1`).
- 본문 XML은 204바이트이고 맨 위 요소의 태그 이름에 이름 공간이 붙어 있습니다(`{http://www.hancom.co.kr/hwpml/2011/paragraph}section`).
- 요소 나무에 요소가 네 개 있습니다(`요소 이름: ['section', 'p', 'run', 't']`). 글은 맨 안쪽 `t`에만 있어 15자를 얻었고, 이름을 `p`로 바꾸면 0자입니다(`빈 글인가: True`).
- 출처 기록은 다섯 칸입니다(`page 칸이 있는가: False`·`section 칸의 값: 1`). 표시 두 개가 다릅니다(`[minimal-marker hwpx]`·`[minimal-marker hwpx section.1]`).
- Before는 오류를 받아 항목을 하나도 얻지 못했습니다(`읽은 항목 이름 목록: []`·`받은 오류 이름: BadZipFile`·`받은 오류 글: File is not a zip file`). After는 갈래를 먼저 정해 멈추지 않았습니다(`갈래별 결과: {'hwp-후보': '전용 도구가 필요합니다', 'hwpx': '한글 문서 처리 실습입니다.'}`).
- **탐색 실행**(`/tmp/ch10-04/probe/p1.py`, 2026-09-18)에서 미리 확인한 것: 위 값 전부와, 태그 이름을 그대로 `"t"`와 견주면 찾은 요소가 0개이고 글이 0자라는 것, `Contents/content.hpf`의 내용이 `<package/>` 한 줄이라는 것입니다. 마지막 항목은 노트북에서 출력하지 않았으므로 본문에는 「묶음에 무엇이 들어 있는지 적어 둔 항목」까지만 적었습니다.

### 문장

- 70자 초과 13문장을 나누고, 영문·코드 이름으로 시작한 문장에 종류 이름을 붙였습니다(「형식 HWPX는」, 「함수 `zipfile.is_zipfile(경로)`는」, 「메서드 `read(8)`은」, 「문장 `continue`는」).

- 용어를 네 개로 바꿨습니다: **형식 표시**·**이진 파일**·**압축 묶음**·**이름 공간**. 개선 전 네 개(「HWP 네이티브 형식」·「HWPX」·「OWPML」·「ZIP 컨테이너」)는 형식 이름이거나 규격 이름이어서 이 절에서 실행한 것과 짝이 맞지 않았습니다.
- 03절이 「파일 앞 표시(BOM)」를 글자 인코딩 표시로 이미 썼으므로, 이 절의 형식 값은 **「형식 표시」**로 부릅니다. 「ZIP 컨테이너」 대신 **「압축 묶음」**, 「네임스페이스」 대신 **「이름 공간」**을 씁니다.
- 제작 상황 문장과 「강사 시연」류 표현을 뺐습니다. 갈래 이름도 한국어로 두었습니다(`hwp-후보`·`hwpx`·`모름`).
