## 3. 바꾼 것 — 고른 핸드오프 모양과 까닭

- **앞 절반(2~5절, 모델 요청 0 — 키 셀 없이 돎)**: 상태 형식 `DeskState`(문의 글·담당 칸 `active_agent`·답 칸·실행 흔적 칸 `trace`에 이어 붙이기 규칙) · 첫 담당 노드 `loan_desk`가 글에 「다른 도서관」이 있으면 `Command(goto="interlibrary_desk", update={"active_agent": …})`, 없으면 `Command(goto=END, …)` · 상호대차 담당 노드 `interlibrary_desk` · 시작점 뒤 조건 함수 `pick_desk`(저장된 담당 칸으로 첫 노드, Ch 20 04) · `add_node(…, destinations=("interlibrary_desk", END))`(Ch 13 06) · `compile(checkpointer=InMemorySaver())`(Ch 23 01). 3절 같은 스레드 두 차례 + 값 바꿔 보기(새 스레드) · 4절 `goto` 이름 오타(값 바꿔 보기) · 5절 도구가 내놓는 `Command`의 도구 메시지 짝 검사를 손으로 만든 `AIMessage(tool_calls=…)`로(Ch 20 01 선례) — 도구 둘(`hand_off_plain`: 지금 그래프 / `hand_off_parent`: `graph=Command.PARENT`), 작은 그래프(`ToolNode`)를 바깥 그래프의 노드로(하위 그래프), 받는 쪽 노드 `interlibrary_note`(손으로 적은 응답 — 보통 함수).
- **뒤 절반(6~7절, 실제 모델)**: 공식 Handoffs 문서의 **「여러 에이전트 하위 그래프」 모양** — 담당 에이전트 둘(`create_agent`, `name=`), 넘기기 도구 `transfer_to_interlibrary(runtime: ToolRuntime)`가 `ToolMessage(…, tool_call_id=runtime.tool_call_id)`와 `runtime.state["messages"][-1]`(도구 요청 응답)을 갱신에 담아 `Command(goto=…, update={active_agent, messages}, graph=Command.PARENT)` · 바깥 그래프 `StateGraph(TeamState)`는 **2절과 같은 호출**(에이전트 그래프를 바로 노드로, 조건 함수 `pick_desk` 그대로) → 출력 `2절 그래프와 구조 문자열이 같은가: True` · 실행 한도 `{"recursion_limit": 10}`(설정 딕셔너리에 스레드 이름과 함께) · 응답의 칸 `name`을 모으는 새 함수 `writer_names`(노트북) · 요청 수는 이번 차례에 더해진 메시지만 `sum_usage`(01 교훈 — 둘째 차례는 `목록[len(첫 차례 목록):]`).
- **「한 에이전트 + 미들웨어」 모양과 견줘 하위 그래프 모양을 고른 까닭**(챕터 리드 결정의 「더 작은 쪽」): 미들웨어 모양은 `@wrap_model_call` 안에서 단계별 설정 딕셔너리와 `request.override(system_prompt=…, tools=…)`(Ch 22 08은 `override(messages=…)`만 가르침), `AgentState` 확장 칸의 기본값(`current_step: str = "triage"` — 과정 금지 모양), `request.state.get(…)`을 써 함수 본문이 8줄을 넘고, 앞 절반 그래프(Command·START 조건 함수·체크포인터)와 이어지지 않음. 하위 그래프 모양은 앞 절반과 바깥 그래프가 같아 새로 가르칠 것이 `Command.PARENT`·`ToolRuntime`의 `state`·`tool_call_id`·하위 그래프 셋으로 줄고, 챕터 리드 결정의 `graph=Command.PARENT`·`ToolMessage` 검사 장면과 곧바로 이어짐. 문서가 「대부분은 미들웨어 모양이 더 간단하다」고 권하는 사실은 b7에 그대로 적고 미들웨어 모양은 실행하지 않았다고 밝힘.
