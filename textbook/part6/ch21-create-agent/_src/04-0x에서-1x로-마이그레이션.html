1학습 목표

  • 옛 함수 create_react_agent와 새 함수 create_agent가 받는 인자 이름의 차이를 출력으로 확인할 수 있습니다.
  • 같은 모델·도구·시스템 메시지 글로 두 함수가 만든 그래프의 노드·엣지·칸을 견줄 수 있습니다.
  • 양식 클래스를 넘겼을 때 옛 그래프에만 더해지는 노드를 찾고, 옛 코드에서 바꿀 자리를 적을 수 있습니다.

2이 내용을 배우는 이유

01절부터 03절까지는 함수 create_agent로 에이전트 그래프를 만들었습니다. 이 함수가 나오기 전 판에서는 LangGraph의 함수 create_react_agent로 같은 일을 했습니다. 예전 판 문서와 예제 코드에는 이 함수로 쓴 코드가 있습니다.

제목의 마이그레이션(migration)은 옛 판에서 쓴 코드를 새 판에서 돌도록 고쳐 쓰는 일입니다. 함수 이름만 바꾸면 끝나는지, 다른 자리도 고쳐야 하는지 알아야 옮길 수 있습니다. 이 절은 두 함수로 같은 그래프를 만들어, 이름과 모양이 어디서 다른지 출력으로 셉니다.

3앞에서 배운 내용

01절에서는 설계 객체 agent.builder로 노드·엣지·상태 칸을 보았습니다. 구조 문자열에서 되돌아가는 엣지 tools -.-> model이 점선이라는 것도 보았습니다. 02절에서는 양식 클래스 PolicyAnswer를 인자 response_format으로 넘겼고, 조건 함수를 보는 함수 print_branches를 적었습니다.

03절에서는 라이브러리 상태 형식 AgentState의 칸 셋을 보았습니다. Ch 20 01절에서는 모델 노드와 도구 실행 노드를 손으로 이었고, 되돌아가는 엣지가 실선이었습니다. Ch 20 03절에서는 그래프가 지날 수 있는 단계 수인 실행 한도를 보았습니다.

시스템 메시지 글은 Ch 16 03절에서 모델이 따를 규칙을 담은 메시지로 보았습니다. 구조 문자열은 Ch 13 01절에서 처음 보았습니다. 이 절의 블록 with는 Ch 2 05절에서 파일을 열 때 쓴 문법입니다.

4핵심 개념

비유로 시작하기

01절에서는 에이전트 그래프를 버튼 하나로 도는 세탁기에 견주었습니다. 이번에는 옛 세탁기와 새 세탁기를 나란히 둡니다. 두 기계는 같은 수건을 빨지만, 옛 기계에는 빨래가 끝난 뒤 한 번 더 거치는 작은 칸이 옆에 붙어 있습니다. 새 기계는 그 일을 몸통 안에서 마칩니다.

옛 기계가 옛 함수 create_react_agent가 만든 그래프이고, 새 기계가 create_agent가 만든 그래프입니다. 옆에 붙은 칸은 양식을 넘겼을 때 옛 그래프에만 더해지는 노드 generate_structured_response입니다. 같은 수건은 두 함수에 똑같이 넘긴 모델·도구·시스템 메시지 글입니다.

{{img:04-5-같은-빨래를-하는-옛-세탁기와-새-세탁기|옅은 베이지 벽과 회색 바닥이 보이는 방을 그린 그림입니다. 왼쪽에 연녹색 위 뚜껑형 세탁기 한 대가 서 있고, 그 오른쪽 옆에 짧은 관 하나로 이어진 작은 회색 상자 하나가 붙어 있습니다. 오른쪽에는 흰 앞문형 세탁기 한 대가 떨어져 서 있고, 윗면 오른쪽에 둥근 버튼 하나, 앞면에 둥근 유리문 하나가 있으며 옆에 붙은 것은 없습니다. 두 세탁기 앞 바닥에는 똑같이 개어진 연노랑 수건이 한 장씩 놓인 그림|두 세탁기는 같은 수건을 빨지만, 옛 세탁기에만 빨래가 끝난 뒤 한 번 더 거치는 칸이 옆에 붙어 있습니다.}}

그림 읽기 — 왼쪽 연녹색 세탁기는 위 뚜껑형이고, 오른쪽 옆에 짧은 관 하나로 이어진 작은 회색 상자 하나가 붙어 있습니다. 오른쪽 흰 세탁기에는 윗면 오른쪽 둥근 버튼 하나와 앞면 둥근 유리문 하나가 있고, 옆에 붙은 것이 없습니다. 두 기계 앞에는 똑같이 개어진 연노랑 수건이 한 장씩 놓여 있습니다. 옛 기계에만 붙은 회색 상자가, 양식을 넘겼을 때 옛 그래프에만 더해지는 노드 generate_structured_response입니다. 흰 세탁기 윗면 왼쪽의 가로로 긴 칸 모양과 연녹색 세탁기 윗면의 작은 단추는 코드의 무엇과도 짝짓지 않습니다.

말뜻
옮기기(마이그레이션, migration)옛 판에서 쓴 코드를 새 판에서 돌도록 고쳐 쓰는 일입니다. 쓰던 빨래 순서를 새 세탁기의 버튼 자리에 맞춰 다시 익히는 일과 같습니다. 이 절에서는 옛 함수 줄을 새 함수 줄로 바꾸고, 달라진 이름을 찾는 일입니다.
옛 함수(create_react_agent)LangGraph 0.x 판에서 에이전트 그래프를 만들던 함수입니다. 지금 판에도 남아 있지만, 부를 때마다 경고를 냅니다. 비유에서 옆에 칸이 붙은 옛 세탁기와 같습니다.
사용 중단 경고(DeprecationWarning)곧 없앨 기능을 쓸 때 Python이 내는 경고의 종류입니다. 가게에서 곧 팔지 않을 물건에 붙이는 「단종 예정」 안내처럼, 지금은 쓸 수 있지만 곧 없앤다는 표시입니다. 코드는 그대로 실행되고, 경고 글이 새로 쓸 이름을 알려 줍니다. 이 절에서는 옛 함수를 부를 때마다 하나씩 나왔습니다.

새 말을 이 절 코드에서 보면 이렇습니다. 옮기기는 노트북 5절에서 옛 함수 줄 create_react_agent(model, tools=[lookup_policy], prompt=system_text)를 적고, 새 함수 줄로 바꿔 적는 모습입니다. 새 함수 줄은 create_agent(model, tools=[lookup_policy], system_prompt=system_text)입니다. 사용 중단 경고는 5절 출력 경고 종류: LangGraphDeprecatedSinceV10으로 보입니다.

{{mermaid:04-1-두-함수가-만든-그래프|위아래 칸 둘이 있는 그림으로 위 칸 옛 함수 create_react_agent 인자 prompt에는 회색 상자 agent와 tools와 끝점 __end__가 있고 agent에서 tools와 __end__로 should_continue 점선이, tools에서 agent로 고정 엣지 실선이 갑니다. 노란 상자에는 받은 경고 하나 고정 엣지 둘 시작점 엣지 포함이 적혀 있습니다. 아래 칸 새 함수 create_agent 인자 system_prompt에는 회색 상자 model과 tools와 __end__가 있고 model에서 tools와 __end__로 model_to_tools 점선이, tools에서 model로 tools_to_model 점선이 갑니다. 노란 상자에는 받은 경고 없음 고정 엣지 하나 시작점 엣지가 적혀 있는 그림|같은 모델·도구·시스템 메시지 글로 만들어도, 옛 그래프는 되돌아가는 엣지가 실선이고 새 그래프는 점선입니다.}}

도식 읽기 — 위 칸이 옛 함수, 아래 칸이 새 함수가 만든 그래프입니다. 회색 상자는 라이브러리가 만든 노드이고, 노란 상자는 노트북 5·6절에서 출력한 값입니다. 가상 시작점은 두 그래프 모두 첫 노드로 가는 실선 하나라 그리지 않았습니다. 두 칸의 차이는 모델 노드 이름과, tools에서 돌아오는 화살표의 모양입니다.

인자 이름이 바뀐 자리

두 함수 모두 앞 두 자리로 모델과 도구 목록을 받습니다. 시스템 메시지 글을 받는 인자는 옛 함수가 prompt, 새 함수가 system_prompt입니다. 옛 함수의 모델 앞뒤 훅 인자 둘은 새 함수에 없고, 새 함수에는 인자 middleware가 있습니다.

{{mermaid:04-2-인자-이름이-바뀐-자리|맨 위 초록 상자 같은 시스템 메시지 글 system_text에서 칸 둘로 화살표가 갑니다. 왼쪽 칸 옛 함수 create_react_agent에는 파란 상자 prompt=system_text와 노란 상자 견준 여덟 가운데 옛 함수에만 있는 인자 prompt pre_model_hook post_model_hook이 있습니다. 오른쪽 칸 새 함수 create_agent에는 파란 상자 system_prompt=system_text와 노란 상자 견준 여덟 가운데 새 함수에만 있는 인자 system_prompt middleware가 있습니다. 맨 아래 회색 상자에는 견준 여덟 가운데 두 함수 모두 받는 인자 response_format state_schema context_schema가 적힌 그림|같은 시스템 메시지 글을 옛 함수는 인자 prompt로, 새 함수는 system_prompt로 받습니다.}}

도식 읽기 — 맨 위 초록 상자는 두 함수에 똑같이 넘긴 값입니다. 파란 상자는 노트북 5절에서 우리가 적은 인자이고, 노란 상자는 노트북 4절에서 견준 이름 여덟 가운데 한쪽에만 있던 것입니다. 맨 아래 회색 상자는 두 칸 출력에서 모두 True였던 인자입니다. 노란 상자끼리는 이름이 다른 자리이고, 짝을 지은 것은 공식 옮기기 안내입니다.

다른 상황에 적용

인터넷에서 찾은 예제에 create_react_agent(model, tools, prompt=...)가 있다면, 이 절의 순서로 옮깁니다. 가져오는 줄과 함수 이름을 바꾸고, 인자 prompt를 system_prompt로 바꿉니다. 결과에서 노드 이름 agent를 찾는 코드가 있다면 model로 고칩니다. 이 순서로 다른 예제를 옮겨 보지는 않았습니다.

비교와 경계

이 절은 0.x 판을 실행하지 않았습니다. 실습 폴더 잠금 파일에 0.x 판이 없기 때문입니다. 지금 판 langgraph-prebuilt 1.1.0에 남은 옛 함수로 그래프 모양만 보았습니다. 0.x 판에서도 모양이 같았는지는 확인하지 않았습니다.

두 함수 모두 그래프를 만들기만 하고 실행하지 않았습니다. 그래서 두 그래프가 같은 질문에 같은 답을 내는지, 모델 요청 수가 얼마인지는 이 절에서 보지 않았습니다. 새 함수의 실행은 01~03절에서 보았습니다.

5실행 예제

노트북은 먼저 01절과 같은 규정 딕셔너리와 도구, 02절과 같은 양식 클래스를 만듭니다. 두 함수의 인자 이름을 견주고, 옛 함수와 새 함수로 같은 재료의 그래프를 하나씩 만듭니다. 두 그래프의 노드·화살표 줄·조건 함수·상태 칸·입력 칸을 차례로 출력합니다. 값 바꿔 보기로 양식 클래스를 더 넘겨 다시 봅니다.

모델 객체는 01절과 같은 gpt-5.4-mini를 temperature 0과 추론 끔(reasoning_effort="none")으로 만듭니다. 그래프를 실행하지 않아 모델 요청은 0번이고, 요금표로 어림한 예상 비용도 0달러입니다.

도식 읽기 — 위 칸이 옛 그래프, 아래 칸이 새 그래프이고, 두 칸 모두 8절 값 바꿔 보기의 출력입니다. 회색 상자는 라이브러리가 만든 노드이고, 가상 시작점은 그리지 않았습니다. 위 칸 오른쪽 회색 상자만 설치판 소스로 본 동작이라, 화살표로 잇지 않았습니다. 아래 칸 모델 노드의 자기 자신으로 가는 점선은 라벨을 빼고 그렸습니다.

양식을 넘기자 옛 그래프에만 노드 generate_structured_response가 더해졌습니다. 옛 조건 함수는 도구 호출 요청이 없으면 끝 대신 이 노드로 보냈습니다. 설치판 소스로 보면 이 노드는 모델에게 요청을 한 번 더 보내 양식 값을 받지만, 이번에는 실행하지 않았습니다.

새 그래프는 노드가 그대로였고, 갈 수 있는 곳만 늘었습니다. 02절에서 본 두 전략이 양식을 루프 안에서 다루기 때문입니다. 공식 옮기기 안내는 이 차이로 비용과 걸린 시간이 준다고 적지만, 이 절은 요청 수와 걸린 시간을 재지 않았습니다.

아래 표는 옛 코드를 새 함수로 옮길 때 바꾸는 자리입니다. 노트북 출력으로 확인한 자리만 적었습니다.

7주의할 점과 실무 메모

  • 0.x 판은 실행하지 않았습니다. 실습 폴더 잠금 파일에 0.x 판이 없어, 지금 판에 남은 옛 함수로 그래프 모양만 견줬습니다.
  • 두 함수로 만든 그래프는 어느 것도 실행하지 않았고, 모델 요청은 0번입니다. 모델 객체는 키가 있어야 만들어져서 키 셀을 두었습니다.
  • 옛 그래프의 노드 generate_structured_response가 모델에게 한 번 더 요청하는 것은 설치판 소스(chat_agent_executor.py 744~767행)로만 확인했습니다.
  • 옛 모델 노드가 remaining_steps를 읽어 멈추는 글을 남기는 동작도 소스(620~633·684~692행)로만 확인했습니다.
  • 경고를 모으지 않으면 셀 출력에 경고 글이 임시 파일 위치와 함께 찍혔습니다. 이것은 노트북 밖에서 모델 없이 확인했습니다.
  • 공식 옮기기 안내에는 새 함수의 상태 형식이 TypedDict만 받는다는 내용도 있습니다. 옛 함수의 Pydantic 상태 형식은 이 절에서 실행하지 않아 대응표에 넣지 않았습니다.
  • 공식 옮기기 안내는 스트리밍 노드 이름이 agent에서 model로 바뀐 것과, 도구 목록에 ToolNode를 넘기지 못하는 것도 적습니다. 두 가지 모두 이번에 실행하지 않았습니다.
  • 모델 앞뒤 훅을 미들웨어로 옮기는 법은 Ch 22에서 배웁니다. 이 절은 인자 이름이 있는지만 보았습니다.
  • 화살표 줄은 구조 문자열에서 화살표가 든 줄만 골라 출력했습니다. 끝점으로 가는 실선 하나는 고정 엣지로 세어지지 않았습니다.
  • 함수 print_branches는 02절 노트북의 본문을 글자 그대로 도구 파일로 옮긴 것입니다. 함수 print_arrow_lines는 이 절 노트북에서 처음 적었습니다.
  • 걸린 시간은 재지 않았습니다. 교재 출력은 Linux의 Python 3.12.13으로 만들었고, 다른 판과 Windows·macOS에서는 실행하지 않았습니다.

8정리와 다음 절

  • 옛 함수 create_react_agent는 지금 판에도 남아 있지만, 부를 때마다 사용 중단 경고를 냈습니다.
  • 같은 재료로 만든 두 그래프는 모델 노드 이름, 되돌아가는 엣지의 모양, 입력 칸 remaining_steps가 달랐습니다.
  • 양식 클래스를 넘기자 옛 그래프에만 노드 generate_structured_response가 더해졌고, 새 그래프는 노드가 그대로였습니다.

9복습 문제

문제 4개 · 해설 포함

1. 옛 함수로 쓴 코드의 인자 prompt=system_text는 새 함수에서 어떻게 적나요?

인자 system_prompt=system_text로 적습니다. 노트북 4절에서 prompt는 옛 함수에만, system_prompt는 새 함수에만 있었습니다. 틀렸다면 노트북 4절과 5절을 다시 읽습니다.

2. 같은 재료로 만든 두 그래프에서 도구 실행 노드에서 모델 노드로 돌아오는 엣지는 어떻게 달랐나요?

옛 그래프는 고정 엣지라 실선이었고, 새 그래프는 조건부 엣지라 점선이었습니다. 옛 그래프의 고정 엣지 수는 2, 새 그래프는 1이었습니다. 틀렸다면 노트북 6절을 다시 읽습니다.

3. 입력 칸 remaining_steps는 어느 그래프에 있었고, 무엇을 담는 값인가요?

옛 그래프에만 있었습니다. 실행 한도까지 남은 단계 수를 그래프가 채우는 값이고, 이 값으로 멈추는 동작은 소스로만 보았습니다. 틀렸다면 노트북 7절을 다시 읽습니다.

4. 양식 클래스를 넘기자 두 그래프는 어떻게 달라졌나요?

옛 그래프에는 노드 generate_structured_response가 더해졌고, 옛 조건 함수는 끝 대신 그 노드로 보냈습니다. 새 그래프는 노드가 그대로이고 갈 수 있는 곳만 늘었습니다. 틀렸다면 노트북 8절을 다시 읽습니다.
