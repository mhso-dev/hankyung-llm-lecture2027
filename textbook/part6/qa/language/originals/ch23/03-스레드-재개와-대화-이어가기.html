1학습 목표

  • 재개가 저장하거나 제어하는 대상을 설명할 수 있습니다.
  • 노트북의 실제 상태와 실행 기록을 읽을 수 있습니다.
  • 장애 또는 사람의 입력 뒤에 실행할 안전한 재개 방법을 고를 수 있습니다.

2이 내용을 배우는 이유

웹 요청마다 그래프 객체가 새로 만들어져도 사용자는 이전 대화가 이어지기를 기대합니다. 상태가 프로세스 메모리가 아니라 저장소에 있어야 이 요구를 충족합니다.

상태가 있다는 사실만으로 실행이 안전하게 이어지지는 않습니다. 언제 저장됐는지, 어떤 식별자로 다시 찾는지, 이미 실행된 부작용이 있는지를 함께 확인해야 합니다. 이번 절은 이 세 질문을 코드와 실제 출력으로 연결합니다.

3앞에서 배운 내용

앞 절에서 PostgresSaver가 프로세스 밖의 데이터베이스에 체크포인트를 남기는 구조를 확인했습니다. 이번 절은 설치 부담을 줄이기 위해 SQLiteSaver를 사용하지만, 첫 연결을 닫고 새 연결과 새 그래프 객체를 만드는 방식으로 프로세스 경계를 모사합니다.

4핵심 개념

구체적인 상황

사용자가 질문 1을 보낸 요청과 질문 2를 보낸 요청은 서로 다른 웹 요청에서 처리될 수 있습니다. 두 번째 요청의 코드가 첫 번째 graph 변수를 참조하지 않아도 저장 파일과 thread_id가 같으면 앞선 턴을 불러올 수 있어야 합니다.

정의

재개(resume)는 같은 thread_id의 최신 체크포인트를 읽고 새 입력을 기존 상태에 합쳐 다음 실행을 시작하는 동작입니다. 저장소 연결과 그래프 객체가 달라져도 thread_id와 체크포인트가 같으면 상태를 찾을 수 있습니다.

turns 채널에는 operator.add 리듀서를 지정합니다. 새 입력 목록과 노드가 반환한 목록을 기존 목록 뒤에 더하므로 질문과 답변 순서가 보존됩니다. 리듀서가 없으면 새 turns 값이 이전 목록을 덮어씁니다. 첫 번째 연결을 닫는 것은 graph_first라는 Python 객체를 더 이상 사용할 수 없게 만드는 과정입니다. 두 번째 연결은 SQLite 파일에 저장된 채널 값과 다음 노드 정보만으로 실행을 구성합니다.

5실행 예제

실습 폴더를 현재 노트북 위치와 상위 폴더에서 찾아 절대 개인 경로를 사용하지 않습니다. 첫 with 블록에서 질문 1을 동기 저장한 뒤 연결을 닫습니다. 두 번째 with 블록은 새 SqliteSaver와 새 graph_second를 만들고 같은 config에 질문 2를 넣습니다.

6실험 결과 해석

두 번째 결과는 질문 1, 답변 1, 질문 2, 답변 3 순서입니다. 답변 번호 3은 응답 노드가 실행되기 전 상태에 세 항목이 있다는 뜻입니다. saved.next가 빈 튜플이므로 두 번째 호출도 끝까지 완료됐습니다.

첫 연결을 닫은 뒤 새 연결에서 질문 2를 넣었고 질문 1과 답변 1이 그대로 남았습니다.

7주의할 점과 실무 메모

  • SQLite는 이 실습과 단일 프로세스 개발에 알맞지만 다중 서버 운영의 동시성 요구는 별도로 검토합니다.
  • 새 대화를 시작할 때는 이전 thread_id를 재사용하지 않습니다.
  • 메시지 목록이 계속 커지면 요약이나 보존 기간 정책을 별도로 설계합니다.

8정리와 다음 절

  • 재개의 역할을 실제 상태와 출력으로 확인했습니다.
  • 재개는 저장된 상태와 다음 노드 정보를 함께 사용합니다.
  • 외부 부작용은 그래프 상태와 별도의 중복 방지 설계가 필요합니다.

9복습 문제

1. 두 번째 실행이 첫 번째 Python graph 객체 없이도 이어진 근거는 무엇인가요?

해설 — 같은 SQLite 파일과 thread_id에서 최신 체크포인트를 읽었기 때문입니다.

2. turns에 operator.add가 필요한 이유는 무엇인가요?

해설 — 새 질문과 답변을 이전 목록 뒤에 추가하기 위해서입니다.

3. db_path를 상위 폴더에서 찾는 코드는 무엇을 해결하나요?

해설 — 프로젝트 루트와 노트북 폴더 어느 위치에서 실행해도 제공 파일을 찾게 합니다.

4. 질문 2에 새 thread_id를 쓰면 어떤 결과가 예상되나요?

해설 — 질문 1과 답변 1이 없는 새 상태에서 시작합니다.
