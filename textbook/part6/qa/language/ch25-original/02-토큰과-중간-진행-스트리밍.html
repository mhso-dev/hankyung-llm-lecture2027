1학습 목표

  • 토큰과 중간 진행 스트리밍의 핵심 구성 요소를 실제 출력에서 구분할 수 있습니다.
  • 같은 입력을 실행하고 호출 경계와 관찰 지표를 설명할 수 있습니다.
  • 결과가 보여 주는 범위와 추가 측정이 필요한 범위를 나눌 수 있습니다.

2이 내용을 배우는 이유

답변 토큰과 업무 진행률은 서로 다른 사실입니다. 토큰은 모델이 생성한 글의 일부이고, 중간 단계는 그래프 노드가 끝났다는 신호이며, custom 사건은 개발자가 정한 업무 진행 상황입니다. 화면에서 세 신호를 섞으면 ‘30% 완료’라는 표시가 실제보다 앞설 수 있습니다.

3앞에서 배운 내용

Ch23에서 체크포인터와 thread_id가 상태를 저장하는 방법을 배웠고, Ch24에서 interrupt와 재개 사건을 확인했습니다. 이번 챕터는 같은 실행을 사용자 화면과 운영 로그에 어떤 단위로 노출할지 다룹니다.

4핵심 개념

구체적인 상황

배송 안내 화면에서 글자가 나타나는 동안 ‘모델 호출 30%’와 ‘완료 100%’를 함께 표시하려고 합니다. 토큰 조각, 노드 완료, 업무 진행률은 발생 원인과 갱신 시점이 다릅니다.

정의

토큰 스트리밍(token streaming)은 messages 모드로 모델의 메시지 조각을 순서대로 받는 방식입니다. 중간 단계 스트리밍은 updates로 노드가 반환한 변경분을 받습니다. custom 모드는 get_stream_writer()로 ‘문서 2/5 처리’처럼 도메인에 맞는 값을 보냅니다. 도구 호출 진행 상황은 도구 내부에서 custom 사건을 보내야 실제 처리 단계를 나타낼 수 있습니다.

5실행 예제

answer 노드는 모델 호출 앞뒤에 get_stream_writer()로 30과 100을 보냅니다. 같은 실행에서 messages·updates·custom을 구독하고 seen 딕셔너리로 개수를 셉니다. 실제 답변 앞부분도 합쳐 출력하여 토큰 조각이 순서대로 도착했는지 확인합니다.

설치 셀은 Python 3.12 환경에 LangChain 1.4.0, langchain-openai 1.6.0, LangGraph 1.2.11을 고정합니다. 예상 API 비용은 1달러 미만이며 키 값은 출력하지 않습니다.

확인할 점 — 출력과 trace에서 위 설명의 변수와 단계가 실제로 이어지는지 확인합니다. assert는 관찰 결과가 기대한 구조를 만족하는지 확인하는 보조 수단입니다.

6실험 결과 해석

실제 출력에서 messages는 73개 조각, updates는 answer 노드가 끝난 뒤의 변경분 1개, custom은 30%와 100% 진행 사건 2개로 나타났습니다. 메시지 조각의 개수는 공급자와 모델에 따라 달라집니다. 진행률은 개발자가 정의한 값이므로 실제 작업량과 일치하도록 계산 근거를 함께 설계해야 합니다.

이 실험은 한 질문과 한 실행 환경의 결과입니다. 모델 응답 내용과 지연 시간은 실행할 때마다 달라질 수 있습니다. 구조의 품질을 비교하려면 여러 질문, 반복 실행, 오류율, 사용자 수정 횟수를 추가로 측정해야 합니다.

7주의할 점과 실무 메모

  • custom 진행률은 모델 토큰 수에서 자동으로 계산되지 않습니다. 도구가 실제로 완료한 파일 수나 레코드 수처럼 검증 가능한 분모와 분자를 사용합니다. messages의 metadata로 노드 이름과 호출을 필터링할 수 있습니다.
  • 비밀 키는 .env에서 읽고 존재 여부만 확인합니다. 노트북 출력, 예외 메시지, 배포 묶음에 키가 포함되지 않았는지 발행 전에 검사합니다.
  • 외부 모델 호출의 응답과 지연은 공급자 상태에 따라 달라집니다. 운영 기준은 반복 측정의 중앙값과 상위 백분위수로 정합니다.

8정리와 다음 절

  • messages는 답변 조각, updates는 answer 상태 변경, custom은 개발자가 정의한 진행 사건입니다. 사용자 문구도 이 세 의미에 맞춰 나눕니다.
  • 출력값과 상태를 근거로 관찰한 범위를 설명합니다.
  • 반복 측정이 없는 수치를 일반적인 성능으로 확대하지 않습니다.

다음 학습과 이어지는 지점 — 다음 절에서는 같은 에이전트를 세 모드로 각각 실행해 first_event, TTFT, total을 구분해 측정합니다.

9복습 문제

1. custom의 30과 100은 누가 정한 값인가요?

해설 — LangGraph가 자동 계산한 값이 아니라 answer 노드의 개발자가 업무 단계에 맞춰 정한 값입니다.

2. 이 절의 assert가 확인하는 것은 무엇인가요?

해설 — 노트북에서 출력한 사건, trace, 상태, 완료 조건이 의도한 구조와 일치하는지 확인합니다.

3. 한 번의 실행 결과로 평균 성능을 단정할 수 없는 이유는 무엇인가요?

해설 — 네트워크와 모델 출력이 실행할 때마다 달라질 수 있고 입력 종류도 하나뿐이기 때문입니다.

4. API 키를 실습 출력에 표시하면 안 되는 이유는 무엇인가요?

해설 — 노트북과 HTML이 공유될 때 비밀 값도 함께 공개될 수 있기 때문입니다.
