1학습 목표

  • LLM judge로 궤적 평가의 핵심 요소를 실제 코드에서 찾을 수 있습니다.
  • 노트북 출력으로 실행 경로와 결과를 설명할 수 있습니다.
  • 한계와 적용 조건을 구분해 평가할 수 있습니다.

2이 내용을 배우는 이유

정확 일치로 잡기 어려운 합리적 경로를 LLM judge가 어떻게 평가하는가?

도구 이름이 정확히 같아도 질문과 도구 인자의 의미가 어긋날 수 있습니다. 의미와 효율을 함께 읽으려면 루브릭을 받은 judge가 전체 메시지를 평가하는 방법이 필요합니다.

3앞에서 배운 내용

결정적 궤적 매칭를 사용합니다. 필요한 자료와 객체는 노트북에서 다시 선언하므로 앞 노트북의 메모리 상태는 필요하지 않습니다.

4핵심 개념

정의와 구체 예

LLM-as-judge는 다른 언어 모델이 평가 루브릭과 실제 궤적을 읽고 점수와 설명을 반환하는 방식입니다. agentevals의 TRAJECTORY_ACCURACY_PROMPT는 단계의 논리, 진행, 상대적 효율, 기준 궤적과의 의미 동등성을 묻습니다. 결정적 매칭과 함께 쓰면 구조 차이와 의미 차이를 구분할 수 있습니다.

9복습 문제

1. 이번 궤적의 strict 점수는 무엇이었나요?

해설 — True였습니다.

2. judge가 False로 본 핵심 이유는 무엇인가요?

해설 — 질문에서 대출 주제를 뒷받침할 근거가 없었기 때문입니다.

3. judge만으로 권한 순서를 검사하면 안 되는 이유는 무엇인가요?

해설 — 결과가 비결정적이고 필수 규칙을 놓칠 수 있기 때문입니다.
