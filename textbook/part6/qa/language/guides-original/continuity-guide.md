# Part 6 학습 연결 안내

노트북 하나마다 새 커널에서 준비 셀부터 실행합니다. 아래 연결은 앞에서 배운 개념을 짚는 안내입니다. 이전 노트북의 변수를 그대로 사용한다는 뜻은 아닙니다. 파일을 읽는 절은 준비 셀에서 위치와 존재 여부를 확인합니다.

| 앞에서 배운 내용 | 이번 학습 | 이어지는 내용 |
| --- | --- | --- |
| Ch20의 모델·ToolNode 그래프 | Ch21 `create_agent`의 도구 호출 루프와 구조화 출력 | Ch22에서 호출 전후 처리 추가 |
| Ch16의 입력 검사·마스킹·호출 제한 | Ch22 내장·커스텀 미들웨어 | Ch27의 컨텍스트 관리 |
| Ch4의 데이터베이스, Ch13의 상태와 노드 | Ch23 체크포인터와 프로세스 중단 후 복구 | Ch24 승인·상태 기록 |
| Ch23의 스레드와 저장 상태 | Ch24 중단·재개, 과거 상태에서 분기 | 이후 실제 업무의 승인 단계 |
| Ch6의 토큰 스트리밍, Ch2의 비동기 실행 | Ch25 토큰·중간 단계·진행 이벤트와 지연 시간 | Ch30 FastAPI의 응답 스트림 |
| Ch18의 패턴과 Ch21의 에이전트 | Ch26 도구로 위임·활성 담당 변경·라우팅 | Ch27의 서브에이전트, Ch39의 정지 조건 |
| Ch6의 하네스 개념, Ch22의 미들웨어 | Ch27 파일·위임·컨텍스트 관리를 조립한 에이전트 | 최종 프로젝트의 조사 과정 구성 |
| Ch19의 도구 정의와 호출 비용 | Ch28 MCP 서버·클라이언트와 도구 정의 토큰 | Ch37의 비용·컨텍스트 측정 |
| Ch15의 평가 항목과 Ch18의 실행 기록 | Ch29 답변·선택·궤적 평가 | 최종 프로젝트의 평가 설계 |

제공된 작은 자료로 확인한 결과와 실제 서비스 운영 결과를 구분합니다. 예를 들어 로컬 프로세스 중단 실험에서 복구한 범위는 모든 데이터베이스 장애의 복구 범위를 뜻하지 않습니다. 한 질문에서 얻은 도구 선택이나 비용 차이는 같은 조건으로 반복 측정한 뒤 판단합니다.

기본 패키지는 각 챕터의 `pyproject.toml`과 `uv.lock`에 고정합니다. 챕터마다 환경을 준비하고 해당 환경의 커널을 선택합니다. 데이터베이스·MCP 서버 등 별도 실행이 필요한 구성은 해당 README의 준비 절차를 따릅니다.
