1학습 목표

  • 호출 수·비용·종료 조건 비교의 핵심 구성 요소를 실제 출력에서 구분할 수 있습니다.
  • 같은 입력을 실행하고 호출 경계와 관찰 지표를 설명할 수 있습니다.
  • 결과가 보여 주는 범위와 추가 측정이 필요한 범위를 나눌 수 있습니다.

2이 내용을 배우는 이유

위임 구조를 이름만으로 선택하면 비용과 종료 시점을 설명하기 어렵습니다. 같은 고객 문의를 세 구조로 처리하고 실제 모델 호출의 토큰 사용량을 모아 호출 수와 추정 비용을 비교합니다. 마지막에는 ‘무엇이 생기면 끝인가’를 각 구조의 상태로 적습니다.

3앞에서 배운 내용

Ch20에서 ToolNode와 명시적 END 조건을, Ch23에서 thread_id와 체크포인터를 배웠습니다. Ch25에서는 실행 사건을 스트리밍했습니다. 이번 챕터에서는 여러 에이전트 사이의 제어권과 맥락을 어디에 둘지 결정합니다.

4핵심 개념

구체적인 상황

같은 고객 과제를 세 구조에 넣어도 내부 호출 경로는 다릅니다. 이름만 바꾼 고정 호출 목록으로는 차이를 검증할 수 없으므로 각 구조의 도구, 상태 전환, 분류 결과가 실제 다음 호출을 결정해야 합니다.

정의

호출 수는 외부 모델 API가 실제로 실행된 횟수입니다. 비용 추정치는 응답의 usage_metadata에 있는 입력·출력 토큰과 수업에서 고정한 단가 가정을 곱해 계산합니다. 종료 조건(stop condition)은 필요한 전문 결과, 필수 상태, 최종 답변이 모두 존재하는지를 판정하는 규칙입니다. recursion_limit 같은 실행 한도는 비상 경계이며 업무 완료 조건을 대신하지 않습니다.

5실행 예제

Subagent는 policy_tool.invoke의 결과를 supervisor가 사용합니다. Handoff는 active_agent를 shipping에서 refund와 done으로 바꿉니다. Router는 실제 classifier 응답과 요청 핵심어로 destinations를 만들고 선택된 경로만 실행합니다. 모든 모델 응답의 usage_metadata를 records에 모읍니다.

설치 셀은 Python 3.12 환경에 LangChain 1.4.0, langchain-openai 1.6.0, LangGraph 1.2.11을 고정합니다. 예상 API 비용은 1달러 미만이며 키 값은 출력하지 않습니다.

확인할 점 — 출력과 trace에서 위 설명의 변수와 단계가 실제로 이어지는지 확인합니다. assert는 관찰 결과가 기대한 구조를 만족하는지 확인하는 보조 수단입니다.

6실험 결과 해석

실제 제어 흐름에서 Subagent는 create_agent가 policy_tool을 선택했고, Handoff 조건부 엣지는 active_agent를 읽어 shipping→refund→done으로 이동했으며, Router의 구조화 출력은 policy와 shipping을 선택해 두 경로를 실행했습니다. Subagent는 3회·0.005498달러, Handoff는 2회·0.000785달러, Router는 4회·0.001574달러로 추정되었고 세 종료 조건은 모두 참이었습니다. 가격은 2026-09-11 공식 일반·캐시 입력과 출력 단가를 적용했습니다.

이 실험은 한 질문과 한 실행 환경의 결과입니다. 모델 응답 내용과 지연 시간은 실행할 때마다 달라질 수 있습니다. 구조의 품질을 비교하려면 여러 질문, 반복 실행, 오류율, 사용자 수정 횟수를 추가로 측정해야 합니다.

7주의할 점과 실무 메모

  • langgraph-supervisor 저장소는 대부분의 새 사용 사례에서 라이브러리보다 도구를 통한 직접 supervisor 구현을 권고합니다. 이 문구를 swarm 라이브러리 전체의 폐기 권고로 확대하면 안 됩니다. 라이브러리 사용 여부와 관계없이 호출 경계·맥락·종료 조건을 애플리케이션 코드에서 검증합니다.
  • 비밀 키는 .env에서 읽고 존재 여부만 확인합니다. 노트북 출력, 예외 메시지, 배포 묶음에 키가 포함되지 않았는지 발행 전에 검사합니다.
  • 외부 모델 호출의 응답과 지연은 공급자 상태에 따라 달라집니다. 운영 기준은 반복 측정의 중앙값과 상위 백분위수로 정합니다.

8정리와 다음 절

  • 세 구조는 실제 제어 흐름과 완료 조건으로 실행됩니다. 일반 입력·캐시 입력·출력 토큰을 공식 단가에 따로 곱해 비용을 계산합니다.
  • 출력값과 상태를 근거로 관찰한 범위를 설명합니다.
  • 반복 측정이 없는 수치를 일반적인 성능으로 확대하지 않습니다.

9복습 문제

1. 종료 조건이 실제로 검사되었다는 근거는 무엇인가요?

해설 — sub_done·handoff_done·router_done을 각 구조의 반환값과 상태에서 계산하고 마지막 셀에서 모두 참인지 assert로 검사합니다.

2. 이 절의 assert가 확인하는 것은 무엇인가요?

해설 — 노트북에서 출력한 사건, trace, 상태, 완료 조건이 의도한 구조와 일치하는지 확인합니다.

3. 한 번의 실행 결과로 평균 성능을 단정할 수 없는 이유는 무엇인가요?

해설 — 네트워크와 모델 출력이 실행할 때마다 달라질 수 있고 입력 종류도 하나뿐이기 때문입니다.

4. API 키를 실습 출력에 표시하면 안 되는 이유는 무엇인가요?

해설 — 노트북과 HTML이 공유될 때 비밀 값도 함께 공개될 수 있기 때문입니다.
