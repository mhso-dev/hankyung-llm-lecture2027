1학습 목표

  • Router 분류와 병렬 실행의 핵심 구성 요소를 실제 출력에서 구분할 수 있습니다.
  • 같은 입력을 실행하고 호출 경계와 관찰 지표를 설명할 수 있습니다.
  • 결과가 보여 주는 범위와 추가 측정이 필요한 범위를 나눌 수 있습니다.

2이 내용을 배우는 이유

Router는 입력을 한 번 분류한 뒤 선택된 전문 작업을 실행합니다. 여러 독립 분야가 동시에 필요하면 병렬 fan-out을 사용할 수 있습니다. 중앙 에이전트가 매 턴 계획하는 Subagent와 달리 Router는 분류 단계의 결과가 실행 경로를 정합니다.

3앞에서 배운 내용

Ch20에서 ToolNode와 명시적 END 조건을, Ch23에서 thread_id와 체크포인터를 배웠습니다. Ch25에서는 실행 사건을 스트리밍했습니다. 이번 챕터에서는 여러 에이전트 사이의 제어권과 맥락을 어디에 둘지 결정합니다.

4핵심 개념

구체적인 상황

배송 지연 문의에는 환불 규정과 배송 상태라는 두 독립 분야가 함께 들어 있습니다. 한 분야만 고르면 답이 빠지고, 순서대로 호출하면 서로 기다릴 필요가 없는 작업까지 지연됩니다.

정의

라우터(Router)는 입력을 분류하여 하나 이상의 전문 경로로 보냅니다. Command는 한 경로, Send는 여러 경로로 동적 fan-out할 때 사용할 수 있습니다. 이 절에서는 구조화 출력으로 분야를 고르고 ThreadPoolExecutor로 선택된 전문가를 병렬 호출합니다. 병렬 실행은 서로의 결과에 의존하지 않을 때만 가능합니다.

5실행 예제

구조화 출력 Route가 policy와 shipping 목록을 반환합니다. ThreadPoolExecutor는 선택된 이름만 run_specialist에 전달합니다. results의 키와 route.destinations의 집합이 같은지 검사한 뒤 분야 이름을 붙여 combined로 합칩니다.

설치 셀은 Python 3.12 환경에 LangChain 1.4.0, langchain-openai 1.6.0, LangGraph 1.2.11을 고정합니다. 예상 API 비용은 1달러 미만이며 키 값은 출력하지 않습니다.

6실험 결과 해석

모델의 구조화 출력은 policy와 shipping 두 분야를 선택했고 두 전문 함수가 결과를 반환했습니다. 결과 출력 순서는 zip으로 입력 순서에 맞췄지만 실제 완료 시각은 다를 수 있습니다. 분류가 빠뜨린 분야는 실행되지 않으므로 라우터 평가에는 분류 정확도가 포함되어야 합니다.

이 실험은 한 질문과 한 실행 환경의 결과입니다. 모델 응답 내용과 지연 시간은 실행할 때마다 달라질 수 있습니다. 구조의 품질을 비교하려면 여러 질문, 반복 실행, 오류율, 사용자 수정 횟수를 추가로 측정해야 합니다.

7주의할 점과 실무 메모

  • Router는 장기 대화를 스스로 관리하지 않습니다. 다중 턴 대화에서는 Router를 대화형 에이전트의 도구로 감싸거나 active_agent 상태를 추가할 수 있습니다. 분류 결과가 비어 있을 때의 기본 경로도 정해야 합니다.
  • 비밀 키는 .env에서 읽고 존재 여부만 확인합니다. 노트북 출력, 예외 메시지, 배포 묶음에 키가 포함되지 않았는지 발행 전에 검사합니다.
  • 외부 모델 호출의 응답과 지연은 공급자 상태에 따라 달라집니다. 운영 기준은 반복 측정의 중앙값과 상위 백분위수로 정합니다.

8정리와 다음 절

  • Router는 먼저 경로를 정하고 독립 작업을 병렬 실행합니다. 선택 목록, 실행 결과의 키, 종합 문자열을 연결해 빠진 분야가 없는지 확인합니다.
  • 출력값과 상태를 근거로 관찰한 범위를 설명합니다.
  • 반복 측정이 없는 수치를 일반적인 성능으로 확대하지 않습니다.

다음 학습과 이어지는 지점 — 마지막 절에서는 같은 고객 문의를 세 구조로 실행하고 호출 수·토큰·비용·종료 조건을 한 표로 비교합니다.

9복습 문제

1. Router의 분류가 policy를 빠뜨리면 어떤 결과가 생기나요?

해설 — policy 전문 함수가 실행되지 않으므로 환불 규정 근거가 결과에서 빠집니다. 분류 정확도를 별도로 평가해야 합니다.

2. 이 절의 assert가 확인하는 것은 무엇인가요?

해설 — 노트북에서 출력한 사건, trace, 상태, 완료 조건이 의도한 구조와 일치하는지 확인합니다.

3. 한 번의 실행 결과로 평균 성능을 단정할 수 없는 이유는 무엇인가요?

해설 — 네트워크와 모델 출력이 실행할 때마다 달라질 수 있고 입력 종류도 하나뿐이기 때문입니다.

4. API 키를 실습 출력에 표시하면 안 되는 이유는 무엇인가요?

해설 — 노트북과 HTML이 공유될 때 비밀 값도 함께 공개될 수 있기 때문입니다.
