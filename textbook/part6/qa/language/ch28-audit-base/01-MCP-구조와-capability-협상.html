1학습 목표

  • 초기화와 capability 협상의 순서를 설명할 수 있습니다.
  • 도구·리소스·프롬프트의 책임을 구분할 수 있습니다.
  • FastMCP 클라이언트로 세 종류를 발견하고 실제 결과를 읽을 수 있습니다.

2이 내용을 배우는 이유

Ch19에서는 Python 함수를 모델이 읽을 도구 스키마로 바꾸었습니다. 그 함수는 같은 프로그램 안에 있었습니다. Ch28에서는 기능을 별도 프로세스나 원격 서비스로 옮기고 여러 클라이언트가 같은 방식으로 발견하도록 만드는 MCP(Model Context Protocol)를 배웁니다. 먼저 프로토콜이 무엇을 주고받는지 알아야 서버 코드, 전송 방식, 모델 토큰을 서로 다른 층으로 구분할 수 있습니다.

3앞에서 배운 내용

Ch6에서 모델·프레임워크·하네스 계층을 구분했고, Ch19에서 도구 이름·설명·입력 스키마가 모델 선택에 영향을 준다는 사실을 확인했습니다. Ch27에서는 파일시스템과 하위 작업 기능을 미리 조립한 하네스를 사용했습니다. MCP는 이러한 기능을 클라이언트와 서버 사이의 표준 메시지로 제공하지만, 모델의 판단이나 업무 권한을 자동으로 해결하지는 않습니다.

4핵심 개념

쉬운 예

호텔 안내 데스크를 떠올려 봅니다. 손님이 요청할 수 있는 서비스 목록은 도구(tools), 읽을 수 있는 안내서는 리소스(resources), 직원에게 건넬 수 있는 작성 양식은 프롬프트(prompts)에 해당합니다. MCP에서 도구는 서버가 실행하는 호출 가능한 기능입니다. 리소스는 URI로 식별하는 읽을 자료입니다. 프롬프트는 사용자가 명시적으로 선택해 가져오는 재사용 메시지 틀입니다. 연결이 시작되면 클라이언트와 서버는 initialize 요청과 응답으로 프로토콜 버전과 capability를 교환합니다. 서버가 resources capability를 알리지 않았다면 클라이언트는 resources/list를 당연히 사용할 수 있다고 가정해서는 안 됩니다. 협상은 기능 존재를 확인하는 절차이고, 호출 권한을 부여하는 인증 절차와는 다릅니다.

정의와 경계

MCP는 클라이언트와 서버가 JSON-RPC 2.0 메시지로 기능과 데이터를 교환하는 응용 계층 프로토콜입니다. 클라이언트는 호스트 애플리케이션 안에서 서버 연결을 관리하고, 서버는 한정된 기능을 공개합니다. 초기화 요청에는 클라이언트가 지원하는 프로토콜 버전과 capability가 들어가며 서버 응답에도 선택한 버전과 서버 capability가 들어갑니다. 이 왕복이 끝난 뒤 initialized 알림을 보내면 정상 동작 단계로 넘어갑니다. tools/list는 호출 가능한 도구 정의, resources/list는 고정 URI 자료, prompts/list는 재사용 프롬프트 정의를 반환합니다. 목록 조회와 실제 사용은 각각 tools/call, resources/read, prompts/get으로 분리됩니다.

노트북은 다른 절의 변수에 의존하지 않습니다. 첫 셀에서 고정 버전을 확인한 뒤 각 단계의 실제 반환값과 검사식을 함께 실행합니다.

확인할 점 — 실험은 같은 FastMCP 서버를 메모리 안에서 연결합니다. 네트워크와 하위 프로세스의 변동을 제거하고 발견 결과에 집중합니다. list_tools, list_resources, list_prompts는 각각 한 항목을 반환합니다. lookup_policy 도구 호출은 대출 규정 문자열을 반환하고 policy://handbook 리소스는 세 규정을 담습니다. explain_policy 프롬프트는 입력한 주제를 포함하는 사용자 메시지를 반환합니다. 세 목록의 개수가 같다는 사실보다 결과의 역할과 호출 방법이 다르다는 점을 확인합니다.

7주의할 점과 실무 메모

  • MCP의 JSON-RPC 메시지와 모델에게 전달되는 프롬프트는 같은 데이터가 아닙니다. 서버 발견 결과 중 모델에 도구 정의로 넣은 내용만 모델 입력 토큰에 포함됩니다.
  • 서버가 capability를 알렸다는 사실은 해당 사용자가 모든 기능을 호출할 수 있다는 뜻이 아닙니다. 인증 뒤에도 도구별 권한 확인이 필요합니다.
  • 커리큘럼의 MCP 2026-07은 개강 기준 목표 버전입니다. 2026-09-11 공식 사이트에서 확인한 최신 발행 스펙은 2025-11-25이므로 본문은 확인 가능한 스펙을 기준으로 작성했습니다.

8정리와 다음 절

  • MCP의 발견·전송·모델 호출은 서로 다른 층이므로 각 층의 값을 따로 측정합니다.
  • 서버 기능은 클라이언트가 발견할 수 있어도 인증과 인가를 통과한 범위에서만 실행합니다.
  • 실습 결과는 고정 버전과 로컬 읽기 전용 서버의 범위에서 해석합니다.

다음 학습과 이어지는 지점 — 다음 절에서는 한 파일에 도구·리소스·프롬프트를 등록하고 stdio로 실행되는 FastMCP 서버를 완성합니다.

9복습 문제

문제 1

도구와 리소스의 가장 큰 차이는 무엇인가요?

해설 — 도구는 서버가 실행하는 기능이고, 리소스는 URI로 읽는 자료입니다.

문제 2

프롬프트는 언제 사용되나요?

해설 — 클라이언트 사용자가 이름과 인자를 지정해 재사용 메시지 틀을 가져올 때 사용됩니다.

문제 3

capability 협상으로 확인할 수 없는 것은 무엇인가요?

해설 — 사용자의 실제 호출 권한은 별도의 인증·인가 검사로 확인해야 합니다.

문제 4

도구 목록 개수와 모델 입력 토큰을 같은 수치로 볼 수 있나요?

해설 — 아닙니다. 목록 개수는 프로토콜 발견 결과이고 입력 토큰은 모델에 직렬화해 전달한 내용의 토큰화 결과입니다.
