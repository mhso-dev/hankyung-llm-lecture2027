1학습 목표

  • langchain.mcp의 MCPAdapter를 올바른 대상 형식으로 열 수 있습니다.
  • MCP 도구를 LangChain BaseTool로 발견하고 직접 호출할 수 있습니다.
  • 직접 작성한 LangChain 도구와 MCP 어댑터 도구의 경계를 설명할 수 있습니다.

2이 내용을 배우는 이유

서버 호출이 성공해도 기존 LangChain 에이전트가 그 도구를 바로 읽는 것은 아닙니다. 어댑터(adapter)는 MCP의 도구 설명과 호출 방식을 LangChain BaseTool 인터페이스로 바꿉니다. 이 변환을 확인하면 Ch19의 bind_tools 코드와 MCP 서버를 같은 모델 인터페이스에서 다룰 수 있습니다.

3앞에서 배운 내용

Ch19에서 @tool로 만든 BaseTool의 name, description, args_schema를 모델에 연결했습니다. 앞 절에서는 course_server.py를 stdio로 호출했습니다. 이번에는 같은 서버를 MCPAdapter에 넘기고 반환된 도구의 이름·설명·입력 스키마·호출 결과를 읽습니다.

4핵심 개념

쉬운 예

서로 다른 규격의 플러그를 연결하는 변환기를 생각해 봅니다. MCPAdapter는 FastMCP 클라이언트 연결과 프로토콜 협상을 담당하고, list_tools 결과를 LangChain BaseTool 목록으로 바꿉니다. LangChain 1.4.0에서는 from langchain.mcp import MCPAdapter가 공식 문서의 현재 경로이며 beta 경고가 발생합니다. 과거 외부 패키지인 langchain-mcp-adapters의 MultiServerMCPClient 예제가 많이 남아 있지만, 1.4.0 공식 문서는 새 네임스페이스로의 이동을 안내합니다. 커리큘럼의 langchain.mcp 표기는 확인 결과 유효합니다. 다만 모듈 이름만 적는 것으로 충분하지 않고 MCPAdapter 클래스를 사용해야 합니다.

정의와 경계

어댑터는 한 인터페이스의 값을 다른 인터페이스에서 사용할 수 있도록 변환하는 객체입니다. MCPAdapter는 URL, Path, FastMCP 인스턴스 같은 대상을 받고 연결 방법을 정합니다. Path 대상은 stdio 하위 프로세스, http 또는 https URL은 Streamable HTTP, FastMCP 인스턴스는 메모리 연결을 사용합니다. list_tools는 MCP 도구의 이름·설명·입력 스키마와 원격 호출 함수를 LangChain BaseTool로 감쌉니다. 반환 도구는 invoke나 ainvoke로 호출할 수 있고 bind_tools에도 전달할 수 있습니다. 연결 수명과 도구 캐시 정책은 어댑터가 관리하지만 업무 권한 판정은 서버나 호출 전 인터셉터에서 별도로 구현해야 합니다.

5실행 예제

노트북은 다른 절의 변수에 의존하지 않습니다. 첫 셀에서 고정 버전을 확인한 뒤 각 단계의 실제 반환값과 검사식을 함께 실행합니다.

{{notebook:04-LangChain-MCP-클라이언트-연동}}

확인할 점 — 실험은 Path 객체로 서버 파일을 지정합니다. MCPAdapter는 이 파일을 stdio 하위 프로세스로 시작하고 list_tools에서 lookup_policy 하나를 반환합니다. 도구의 args_schema는 topic 문자열을 요구하며 ainvoke에 운영을 전달하면 운영 시간이 반환됩니다. 직접 작성한 LangChain @tool과 비교하면 호출 측 인터페이스는 name과 invoke로 비슷하지만, MCP 도구 실행은 프로토콜을 거쳐 별도 서버로 전달됩니다. 어댑터가 변환한다고 해서 서버 코드를 클라이언트 프로세스 안에서 직접 호출하는 것은 아닙니다.

6실험 결과 해석

실험은 Path 객체로 서버 파일을 지정합니다. MCPAdapter는 이 파일을 stdio 하위 프로세스로 시작하고 list_tools에서 lookup_policy 하나를 반환합니다. 도구의 args_schema는 topic 문자열을 요구하며 ainvoke에 운영을 전달하면 운영 시간이 반환됩니다. 직접 작성한 LangChain @tool과 비교하면 호출 측 인터페이스는 name과 invoke로 비슷하지만, MCP 도구 실행은 프로토콜을 거쳐 별도 서버로 전달됩니다. 어댑터가 변환한다고 해서 서버 코드를 클라이언트 프로세스 안에서 직접 호출하는 것은 아닙니다.

7주의할 점과 실무 메모

  • langchain.mcp는 1.4.0에서 beta입니다. 경고를 숨기기보다 기준 버전과 변경 가능성을 참고 자료에 기록합니다.
  • MCPAdapter의 문자열 대상은 http 또는 https URL이어야 합니다. 로컬 스크립트는 Path 객체로 넘겨 의도를 분명히 합니다.
  • 도구 목록은 연결 시점에 발견한 결과입니다. 서버 구성 요소가 바뀌면 캐시 정책과 재발견 시점을 정해야 합니다.
  • 모델이 도구를 자동 선택하게 하는 호출은 다음 절에서 수행합니다. 이 절은 어댑터 변환과 실제 도구 호출만 분리해 확인합니다.

8정리와 다음 절

  • MCP의 발견·전송·모델 호출은 서로 다른 층이므로 각 층의 값을 따로 측정합니다.
  • 서버 기능은 클라이언트가 발견할 수 있어도 인증과 인가를 통과한 범위에서만 실행합니다.
  • 실습 결과는 고정 버전과 로컬 읽기 전용 서버의 범위에서 해석합니다.

다음 학습과 이어지는 지점 — 마지막 절에서는 직접 도구 한 개, MCP 도구 한 개, MCP 도구 다섯 개를 같은 첫 질문에 연결해 모델 입력 토큰을 측정합니다.

9복습 문제

문제 1

LangChain 1.4.0의 공식 MCP import 경로는 무엇인가요?

해설 — from langchain.mcp import MCPAdapter입니다.

문제 2

로컬 서버 파일을 MCPAdapter에 넘길 때 권장 형식은 무엇인가요?

해설 — 문자열 대신 pathlib.Path 객체로 넘깁니다.

문제 3

어댑터가 반환한 도구는 어떤 공통 인터페이스를 따르나요?

해설 — LangChain BaseTool 인터페이스를 따라 name, description, args_schema와 invoke 계열 메서드를 제공합니다.

문제 4

직접 도구와 MCP 도구의 호출 측 모양이 비슷해도 실행 경계가 다른 이유는 무엇인가요?

해설 — MCP 도구는 어댑터와 전송 계층을 거쳐 별도 서버에서 실행되기 때문입니다.
