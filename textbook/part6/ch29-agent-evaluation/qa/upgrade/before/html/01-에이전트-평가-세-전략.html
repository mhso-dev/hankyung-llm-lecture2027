2이 내용을 배우는 이유

Final Response·Single step·Trajectory는 각각 어떤 실패를 발견하는가?

최종 답이 14일로 맞아도 search_rules를 세 번 반복하면 운영 비용과 장애 가능성이 커집니다. 답과 내부 행동을 서로 다른 평가 단위로 보아야 이런 실패를 찾을 수 있습니다.

4핵심 개념

정의와 구체 예

Final Response는 전체 실행을 블랙박스로 보고 마지막 답을 채점합니다. Single step은 특정 시점의 도구 선택이나 인자를 검사합니다. Trajectory는 시작부터 끝까지의 AIMessage와 ToolMessage 순서를 평가합니다. 세 전략은 서로 대체하지 않으며 발견하려는 실패에 따라 함께 사용합니다.

코드 읽기와 비교 경계

평가 단위는 평가 함수가 입력에서 어느 부분을 읽는지 정합니다. 최종 응답 평가는 마지막 AIMessage.text만 읽고, 한 단계 평가는 지정한 tool_calls의 이름이나 인자를 읽으며, 궤적 평가는 사용자 메시지부터 모든 AI·도구 메시지의 순서를 읽습니다. trace()는 실제 에이전트를 실행하는 함수가 아니라 비교용 메시지 목록을 만드는 보조 함수입니다. 따라서 이 절의 결과는 평가 전략의 차이를 재현하는 고정 예시입니다.

같은 실패도 평가 단위에 따라 보이거나 숨습니다. 도구를 네 번 호출해도 마지막 답이 맞으면 최종 응답 평가는 통과할 수 있습니다. 첫 도구가 맞아도 두 번째 단계에서 권한 없는 도구를 사용하면 한 단계 평가만으로는 놓칩니다. 반대로 궤적이 기준과 같아도 규정 원문이 오래되었다면 사실 오류는 남습니다. 운영 평가에서는 답의 사실성, 필수 단계, 금지 행동, 호출 효율을 각각 측정하고 어느 하나를 전체 품질 점수로 대신하지 않습니다.

도식 읽기

하나의 에이전트 실행에서 세 측정 상자가 나옵니다. Final Response는 마지막 문장, Single step은 첫 tool_calls, Trajectory는 모든 호출 순서를 읽습니다.

In [3]:
# search_rules 다음 check_source가 이어지는 기준 메시지 궤적을 만듭니다.
from langchain.messages import HumanMessage, AIMessage, ToolMessage
def trace(*tools: str) -> list:
    messages=[HumanMessage("규정을 확인해 주세요.")]
    for i,name in enumerate(tools,1):
        messages += [AIMessage("", tool_calls=[{"name":name,"args":{"topic":"대출"},"id":f"c{i}","type":"tool_call"}]), ToolMessage("확인", tool_call_id=f"c{i}")]
    messages.append(AIMessage("일반 도서는 14일입니다."))
    return messages
reference=trace("search_rules", "check_source")

세 종류의 평가 입력 만들기

세 평가 함수에 같은 고정 궤적을 넘긴 뒤 각각 마지막 답, 첫 도구 호출, 전체 호출 순서를 읽는지 비교합니다.

In [4]:
# 같은 메시지 궤적에서 최종 답, 첫 도구 선택, 전체 호출 순서를 각각 추출합니다.
actual=trace("search_rules", "check_source")
final_response = "14일" in actual[-1].text
single_step = actual[1].tool_calls[0]["name"] == "search_rules"
trajectory = [call["name"] for m in actual for call in getattr(m,"tool_calls",[])]
print({"final_response":final_response,"single_step":single_step,"trajectory":trajectory})
출력:
{'final_response': True, 'single_step': True, 'trajectory': ['search_rules', 'check_source']}

최종 답만 맞는 나쁜 경로 비교

나쁜 경로는 최종 답을 같게 유지한 채 도구 호출만 늘립니다. 이 비교로 최종 응답 평가가 내부 낭비를 놓칠 수 있음을 확인합니다.

In [5]:
# 답은 유지하고 검색만 반복해 Final Response 평가가 놓치는 호출 증가를 만듭니다.
wasteful=trace("search_rules","search_rules","search_rules","check_source")
print("final pass:", "14일" in wasteful[-1].text)
print("reference calls:", 2, "wasteful calls:", sum(len(getattr(m,"tool_calls",[])) for m in wasteful))
assert "14일" in wasteful[-1].text and len(wasteful)>len(reference)
출력:
final pass: True
reference calls: 2 wasteful calls: 4

확인할 점 — 정상 예시 궤적은 search_rules→check_source였고 final_response와 single_step이 모두 True였습니다. 낭비 예시 궤적은 같은 14일 답을 반환해 최종 응답 평가는 통과했지만 도구 호출이 기준 2회에서 4회로 늘었습니다.

6실험 결과 해석

정상 궤적은 search_rules→check_source였고 final_response와 single_step이 모두 True였습니다. 낭비 궤적은 같은 14일 답을 반환해 최종 응답 평가는 통과했지만 도구 호출이 기준 2회에서 4회로 늘었습니다.

Single step 통과는 다음 단계가 옳다는 보장이 아니며 Trajectory 통과는 최종 문장의 사실 정확성을 보장하지 않습니다.
