4핵심 개념

비유로 시작하기

공항 보안 절차를 떠올려 봅니다. 탑승 수속 전체의 시작과 끝, 탑승구 진입 전후, 수하물 검사 전후는 서로 다른 검사 지점입니다. 미들웨어도 에이전트 전체에는 before_agent와 after_agent, 각 모델 호출에는 before_model·wrap_model_call·after_model, 각 도구 호출에는 wrap_tool_call을 제공합니다. 노드형 훅은 정해진 지점에서 한 번 실행되고 상태 갱신 딕셔너리를 반환할 수 있습니다. 감싸기형 훅은 handler를 호출하기 전후를 모두 제어하며 재시도하거나 요청을 바꾸거나 호출을 생략할 수도 있습니다.

코드를 읽는 순서

미들웨어는 create_agent가 만든 루프의 약속된 시점에 실행되는 로직입니다. 개발자가 훅 함수를 직접 호출하지 않아도 런타임이 before_agent, before_model, after_model, after_agent를 노드처럼 실행합니다. wrap_model_call과 wrap_tool_call은 대상 호출과 handler를 함께 받아 호출 전후를 감쌉니다. 랩 훅에서 handler를 호출하지 않으면 실제 모델 또는 도구도 실행되지 않으므로 단순한 전후 알림과 제어 로직을 구분해야 합니다.

SixHookTrace는 상태를 바꾸지 않고 TRACE에 이름만 남기는 관찰용 클래스입니다. 첫 모델 응답이 도구 호출을 만들기 때문에 before_model과 모델 랩은 두 번 실행되고, 도구 랩은 한 번 실행됩니다. 반면 before_agent와 after_agent는 한 번의 invoke 경계에서 각각 한 번 나타납니다. 훅의 횟수는 등록 개수가 아니라 실제 루프 반복과 도구 선택에 따라 달라집니다.

도식 읽기

왼쪽의 파란 입력 상태에서 실행을 시작해 파란 before_agent를 한 번 통과합니다. 보라색 모델 호출 상자의 앞뒤에는 before_model·wrap_model_call·after_model이 놓입니다. 모델이 도구를 요청하면 초록색 lookup_hours 앞뒤를 wrap_tool_call이 감싸고 다시 모델 상자로 돌아갑니다. 마지막 파란 after_agent 뒤에서 실행이 끝납니다.

from typing import Any
from langchain.agents import create_agent
from langchain.agents.middleware import AgentMiddleware
from langchain.tools import tool
from langchain_core.language_models.chat_models import BaseChatModel
from langchain_core.messages import AIMessage
from langchain_core.outputs import ChatGeneration, ChatResult
class ScriptedModel(BaseChatModel):
    replies: list[AIMessage]
    index: int = 0
    @property
    def _llm_type(self) -> str: return "scripted-model"
    def _generate(self, messages: Any, stop: Any = None, run_manager: Any = None, **kwargs: Any) -> ChatResult:
        reply = self.replies[min(self.index, len(self.replies) - 1)]
        self.index += 1
        return ChatResult(generations=[ChatGeneration(message=reply)])
    def bind_tools(self, tools: Any, *, tool_choice: Any = None, **kwargs: Any) -> "ScriptedModel":
        return self

도구와 여섯 훅 trace 준비

미들웨어는 create_agent가 만든 루프의 약속된 시점에 실행되는 로직입니다. 개발자가 훅 함수를 직접 호출하지 않아도 런타임이 before_agent, before_model, after_model, after_agent를 노드처럼 실행합니다. wrap_model_call과 wrap_tool_call은 대상 호출과 handler를 함께 받아 호출 전후를 감쌉니다. 랩 훅에서 handler를 호출하지 않으면 실제 모델 또는 도구도 실행되지 않으므로 단순한 전후 알림과 제어 로직을 구분해야 합니다.

SixHookTrace는 상태를 바꾸지 않고 TRACE에 이름만 남기는 관찰용 클래스입니다. 첫 모델 응답이 도구 호출을 만들기 때문에 before_model과 모델 랩은 두 번 실행되고, 도구 랩은 한 번 실행됩니다. 반면 before_agent와 after_agent는 한 번의 invoke 경계에서 각각 한 번 나타납니다. 훅의 횟수는 등록 개수가 아니라 실제 루프 반복과 도구 선택에 따라 달라집니다.

# 이 셀은 도구와 여섯 훅 trace 준비 작업을 수행하고 확인할 값을 출력합니다.
from langchain.agents import create_agent
from langchain.agents.middleware import AgentMiddleware
from langchain.tools import tool

TRACE = []
@tool
def lookup_hours(day: str) -> str:
    """자료실 운영 시간을 요일로 조회합니다."""
    return "평일 09:00~20:00" if day == "평일" else "토요일 10:00~17:00"

class SixHookTrace(AgentMiddleware):
    def before_agent(self, state: Any, runtime: Any) -> None: TRACE.append("before_agent")
    def before_model(self, state: Any, runtime: Any) -> None: TRACE.append("before_model")
    def wrap_model_call(self, request: Any, handler: Any) -> Any:
        TRACE.append("wrap_model:before"); result = handler(request); TRACE.append("wrap_model:after"); return result
    def wrap_tool_call(self, request: Any, handler: Any) -> Any:
        TRACE.append("wrap_tool:before"); result = handler(request); TRACE.append("wrap_tool:after"); return result
    def after_model(self, state: Any, runtime: Any) -> None: TRACE.append("after_model")
    def after_agent(self, state: Any, runtime: Any) -> None: TRACE.append("after_agent")

훅 호출 횟수 집계

모델 입력에 사용자 등급을 추가하는 일은 before_model, 일시 오류를 재시도하는 일은 wrap_model_call, 도구 인자를 검사하는 일은 wrap_tool_call이 자연스럽습니다. 같은 검사를 모든 노드에 복사하면 변경 위치가 늘어나므로 반복되는 횡단 관심사를 미들웨어로 모읍니다.

모든 로직을 미들웨어로 옮길 필요는 없습니다. 주문 금액 계산처럼 업무 자체를 나타내는 단계는 그래프 노드나 도구에 두는 편이 흐름을 읽기 쉽습니다. 이 실습의 TRACE 순서는 한 번의 도구 호출 경로에서 관찰한 값이며, 도구가 없거나 병렬 호출이 있으면 횟수와 순서가 달라질 수 있습니다.

6실험 결과 해석

학습용 모델은 첫 응답에서 lookup_hours 도구를 한 번 요청하고 두 번째 응답에서 종료합니다. 출력 trace에는 before_agent가 한 번, 모델 관련 세 훅이 두 번, wrap_tool_call이 한 번, after_agent가 한 번 나타납니다. 여섯 훅이라는 말은 여섯 개의 독립 오류 이벤트를 뜻하지 않습니다. 오류는 wrap_model_call 또는 wrap_tool_call에서 예외로 관찰하고 종료는 after_agent에서 관찰합니다.

7주의할 점과 실무 메모

  • 공식 LangChain 1.4.0의 여섯 훅은 before_agent, before_model, wrap_model_call, wrap_tool_call, after_model, after_agent입니다.
  • 노드형 훅에서 상태를 바꾸려면 딕셔너리를 반환합니다. 감싸기형 훅은 handler의 반환값을 보존하거나 문서가 허용한 형식으로 바꿉니다.
  • 첫 기능 셀에서 실제 OpenAI API 연결을 확인한 뒤, 훅의 정확한 순서는 정해 둔 응답을 쓰는 검사 모델로 재현합니다. 키 값은 출력하지 않습니다.

실습의 결정적 모델은 미들웨어 실행 경계를 재현하기 위한 검사 도구입니다. 실제 모델 품질, 공급자 장애율, 운영 비용을 대신 측정하지 않습니다. 적용 전에는 사용 중인 모델과 계정의 실제 사용량을 다시 확인합니다.

8정리와 다음 절

  • 훅은 에이전트 전체·모델·도구의 실행 경계에 미들웨어 로직을 연결합니다.
  • 도구를 한 번 쓴 실행에서 모델 훅은 두 번, 도구 훅은 한 번 실행되는 trace를 확인했습니다.
  • 결정적 검사 모델은 훅 경계를 확인하며 실제 모델 품질을 측정하지 않습니다.

다음 학습과 이어지는 지점 — 다음 절에서는 Ch16의 정규식 기반 mask_pii를 LangChain의 PIIMiddleware로 옮기고 입력과 출력 적용 범위를 비교합니다.

문제와 해설

1. 에이전트 실행당 한 번 호출되는 훅 두 개는 무엇인가요?

해설 — before_agent와 after_agent입니다.

2. handler를 여러 번 호출해 재시도를 구현할 수 있는 모델 훅은 무엇인가요?

해설 — wrap_model_call입니다.

3. 도구 오류를 관찰하기에 알맞은 훅은 무엇인가요?

해설 — wrap_tool_call에서 handler 호출 예외를 처리합니다.

4. after_model은 왜 한 실행에서 여러 번 호출될 수 있나요?

해설 — 도구를 사용한 에이전트는 모델을 여러 차례 호출하기 때문입니다.
