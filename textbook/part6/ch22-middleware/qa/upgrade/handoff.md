### 결정: 그대로 — 까닭

1. **훅 다섯 판은 학습 대상이고 옮길 수도 없음**: `record_model_input`·`audit_*`는 이 챕터가 가르치는 미들웨어 훅입니다. 03·08은 요약 압축·컨텍스트 분리를 「모델이 실제로 받은 글」로 확인하려고 02절 훅을 다시 붙이는 자리이고, 09 `audit_*`는 실습에서 06절 훅을 줄여 다시 쓰는 판입니다(사용자가 특히 마음에 들어 한 09 흐름). 게다가 훅 인자는 라이브러리가 `(request, handler)`·`(state, runtime)`로 정해 기록 목록(`seen_by_model`·`events`)을 인자로 받을 수 없습니다. 도구 파일로 옮기려면 목록을 도구 파일 전역에 두거나 함수를 만드는 함수·클래스형 미들웨어로 모양을 바꿔야 하는데, 규격 §2-7 4항(노트북 전역 이름에 기대지 않음)과 어긋나고 새 개념이 됩니다(Ch 13 `choose_path`를 옮기지 않은 까닭과 같음).
2. **남는 후보 `lookup_hours`는 줄어드는 몫이 아주 작음(계산)**: 09는 실습 조립(도구 둘을 나란히 만드는 자리)이라 두고 04·06만 옮기면, 두 노트북에서 도구 셀 7줄씩(−14)과 준비 셀 `from langchain.tools import tool`(04·06은 이 도구 말고 `@tool`이 없음, −2)이 빠지고 `from llm_tools import lookup_hours`(+2)가 들어와 −14, 도구 파일이 `from langchain.tools import tool` + `@tool` + 본문 5줄 = 7줄이라 **챕터 전체 741 → 734줄(−7, −0.9%)·코드 셀 135 → 133**입니다. 09까지 옮겨도 −13줄(−1.8%)입니다.
3. **그 −7줄에 비해 치를 값이 큼**: (가) 04·06은 서비스 모델을 부르는 절이라 새 커널로 두 번씩 다시 실행해야 하고, 04의 호출 한도 관찰(첫 호출에서 모델이 도구를 요청해야 두 번째 호출에서 멈춤)과 06의 사건 순서(`tool_start`·`tool_success`)는 모델이 도구를 부르는지에 기대므로 강사 확인이 끝난 결과 읽기·그림(04-2·04-4·06-1·06-3)을 다시 대조해야 합니다. (나) 이 챕터에서 「도구」는 에이전트 도구(`@tool`·`tools=[…]`·`wrap_tool_call`·`ToolCallRequest`)라는 핵심 용어입니다. 에이전트 도구 객체(`@tool`을 지나면 `StructuredTool`)를 「도구 파일」에서 가져오면 한 문장에 「도구」가 두 뜻으로 나옵니다.
