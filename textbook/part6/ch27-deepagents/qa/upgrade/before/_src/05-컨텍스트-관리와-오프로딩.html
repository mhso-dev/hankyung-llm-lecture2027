1학습 목표

  • 요약과 큰 도구 결과 오프로딩이 컨텍스트 크기를 다루는 위치를 구분합니다.
  • 실행 출력에서 컨텍스트 관리와 오프로딩의 구성과 결과를 구분할 수 있습니다.
  • 이 실험이 확인한 범위를 설명할 수 있습니다.

2이 내용을 배우는 이유

도구가 수만 자를 반환하면 다음 모델 호출의 입력이 급격히 커집니다. DeepAgents는 한도를 넘은 텍스트를 파일로 옮기고 미리보기와 경로만 ToolMessage에 남길 수 있습니다. 이 절은 200토큰이라는 작은 실습 한도로 이 동작을 눈에 보이게 만듭니다.

3앞에서 배운 내용

앞 절에서는 write를 직접 호출해 중간 파일을 만들었습니다. 이번에는 모델이 large_result 도구를 선택하고 FilesystemMiddleware가 결과 크기를 검사합니다. 두 방식 모두 파일을 쓰지만 시작 조건이 다릅니다.

노트북은 앞 절 변수에 의존하지 않으며 Python 3.12, deepagents==0.7.0, langchain==1.4.0을 설치하고 상위 폴더의 .env를 찾습니다.

4핵심 개념

정의와 구체적인 상황

컨텍스트 관리는 두 위치에서 일어납니다. SummarizationMiddleware는 오래된 대화 메시지를 요약하고, FilesystemMiddleware는 큰 도구 결과가 한도를 넘으면 파일로 옮긴 뒤 미리보기와 경로를 남깁니다. 파일을 만들었다는 사실만으로 정보가 정확해지는 것은 아닙니다. 원문 식별자와 출처 URL을 함께 저장해야 이후 요약을 검증할 수 있습니다.

코드 읽기와 비교 경계

오프로딩(offloading)은 큰 도구 결과의 원문을 파일로 옮기고 ToolMessage에는 미리보기와 경로만 남기는 처리입니다. 이 예제의 FilesystemMiddleware 한도는 도구 결과가 어느 크기에서 파일로 이동하는지 정합니다. 모델은 경로를 보고 필요할 때 파일 도구로 일부를 다시 읽습니다. 요약은 여러 메시지의 뜻을 짧게 다시 쓰는 처리이고, 오프로딩은 원문을 다른 저장 위치에 보존한다는 점이 다릅니다.

두 방법은 손실 위험도 다릅니다. 요약은 원문에 있던 조건이나 예외를 생략할 수 있으므로 중요한 수치와 출처를 별도로 유지해야 합니다. 오프로딩은 원문을 보존하지만 모델이 다시 읽지 않은 부분은 현재 판단에 사용되지 않습니다. 이번 출력에서 ToolMessage에 파일 경로가 남고 실제 파일이 존재하는지는 오프로딩을 확인하지만, 오래된 대화가 정확히 요약되는지는 확인하지 않습니다. 장기 대화 요약은 별도의 반복 실행과 사실 보존 평가가 필요합니다.

도식 읽기

{{svg:05-흐름}}

색이 쓰인 곳에서 파란색은 학생 코드와 실행 흐름, 보라색은 모델의 판단, 초록색은 도구와 데이터, 노란색은 측정값, 빨간색은 실패 또는 권한 경계를 뜻합니다. 긴 대화·큰 도구 결과에서 요약 또는 오프로딩으로 갈라진 뒤 요약 메시지·파일 경로가 다음 모델 호출에 전달됩니다. 이 실습은 큰 도구 결과의 오프로딩 경로만 실행하며 오래된 대화 요약 임계점은 별도 장기 실행이 필요합니다.

5실행 예제

large_result는 같은 근거 문장을 3,000번 반환합니다. FilesystemMiddleware의 한도를 200토큰으로 낮추고 모델에 도구를 한 번 호출하게 합니다. ToolMessage 길이, /large_tool_results/ 아래 파일, 최종 답을 차례로 검사합니다.

확인할 점 ToolMessage에 원문 전체가 아닌 안내와 경로가 남고 /large_tool_results/ 아래 파일이 생성됐는지 확인합니다.

6실험 결과 해석

원문 전체 대신 약 1,600자의 안내가 ToolMessage에 남았고, large_tool_results 아래에 호출 ID 이름의 파일이 생성됐습니다. 파일 생성은 확인했지만 자동 요약의 장기 품질이나 원문 전체 다시 읽기 성공률은 측정하지 않았습니다.

7주의할 점과 실무 메모

  • ToolMessage의 미리보기는 원문 파일의 대체물이 아닙니다. 후속 판단에 원문이 필요하면 파일을 다시 읽어야 합니다.
  • 실행별 오프로딩 파일의 보존 기간과 삭제 시점을 정합니다.

8정리와 다음 절

  • 원문 전체 대신 약 1,600자의 안내가 ToolMessage에 남았고, large_tool_results 아래에 호출 ID 이름의 파일이 생성됐습니다.
  • 버전과 측정 범위를 실행 기록에 함께 남깁니다.

9복습 문제

문제 1

이 절에서 200은 무엇의 단위인가요?

해설 FilesystemMiddleware가 큰 도구 결과를 옮길지 판단하는 실습용 토큰 한도입니다.

문제 2

ToolMessage가 1,600자면 원문이 손실된 것인가요?

해설 원문은 파일에 저장되고 ToolMessage에는 미리보기와 다시 읽을 경로가 남습니다.

문제 3

오프로딩과 대화 요약은 같은 처리인가요?

해설 아닙니다. 큰 도구 결과를 파일로 옮기는 처리와 오래된 메시지를 요약하는 처리를 구분합니다.
