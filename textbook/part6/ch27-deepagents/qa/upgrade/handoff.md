### 안전 규칙 (모델을 부르는 02~09 모두 — 01 확인)

- **사실(01 확인)**: ① Deep Agent 그래프의 실행 한도 **9999**(01 2절 출력 · `graph.py` 922~944행) ② **general-purpose 서브에이전트가 늘 붙음**(01 3절 `task` 설명 글 `True` · `graph.py` 750~814행) — 도구는 바깥 `tools=` + 자기 파일 도구, **호출 한도 없음**, 묶인 실행 한도 9999 ③ 서브에이전트는 도구 `task`의 함수 안에서 `invoke` — **묶인 설정이 바깥 설정보다 앞섬**(`subagents.py` 559~565행 — 바깥 `{"recursion_limit": N}`이 안쪽에 닿지 않음, Ch 26 A-2와 같은 문제) ④ **바깥 `middleware=`의 `ModelCallLimitMiddleware`는 general-purpose로 옮겨 가지 않음**(`graph.py` 777행 — 기본 자리 이름과 같은 것만 물려줌) ⑤ 이름이 다른 명세만 넘기면 **기본 general-purpose(한도 없음)가 함께 붙음** ⑥ 같은 이름 `general-purpose` 명세는 기본 자리를 바꾸고, 명세 `middleware`의 한도가 그 서브에이전트 스택에 들어감 — 도구 실행 노드만 든 그래프로 `task`를 부르면 `Model call limits exceeded: run limit (0/0)`(01 6절, 요청 0).
- **규칙**: (가) 바깥 에이전트 `middleware=[ModelCallLimitMiddleware(run_limit=N, exit_behavior="end")]` (나) `subagents=`에 **언제나** 같은 이름 `general-purpose` 명세(키 `name`·`description`·`system_prompt`·`middleware=[ModelCallLimitMiddleware(run_limit=M, exit_behavior="end")]`)를 넣음 — 서브에이전트가 주제가 아닌 02~05도 (다) 사용자 서브에이전트 명세(06·07·09)마다 자기 호출 한도 (라) `invoke` 설정에 작은 실행 한도(`{"recursion_limit": …}`)를 더해도 되지만 **바깥 그래프에만** 걸린다고 적을 것.
- **상한 셈**: 한 번 실행의 모델 요청 ≤ N + (`task`를 부른 횟수) × M(요약이 켜지면 요약 요청 더함 — `gpt-5.4-mini` 400,000의 85% = 340,000토큰 기준이라 수업에서는 켜지지 않음). `run_limit`은 한 번 실행(`invoke`) 안의 수 — `task`는 부를 때마다 서브에이전트를 새로 실행하므로 명세 한도는 `task` 한 번마다. **남는 틈**: 한 응답의 `task` 요청 수는 막지 않음(`task` 설명 글이 「여럿을 함께」 권함) — `ToolCallLimitMiddleware`(langchain 1.4.0)는 과정 0건이라 쓰지 않았음(쓰려면 그 절이 새 API로 풀고 강사 확인). general-purpose를 끄는 `HarnessProfile`/`register_harness_profile`은 전역 등록이라 쓰지 않음.
- 호출 한도에 닿아 끝난 실행은 마지막 글이 한도 글(`Model call limits exceeded: …`)이고 사용량 `None`(Ch 26 04·05와 같음) → Ch 19 `sum_usage`가 멈출 수 있음(Ch 26 01 교훈 — 한도 글 응답·손으로 적은 응답은 빼고 셀 것).
