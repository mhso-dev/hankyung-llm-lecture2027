- 색(규격 §5-3·과정 요약 §8·챕터 공통 「색」): 자료·넣은 값·우리가 만든 서버 객체 **초록(tool)** · 우리가 쓴 함수·데코레이터 줄·도구가 한 일 **파랑(flow)** · 노트북 출력으로 확인한 값과 받아 출력한 오류(Unknown tool·After 거절·「주차」 글) **노랑(measure)** · 두 판·두 도구 공통 값 **회색(클래스 없음)** · **보라 0장**(모델 없음) · **빨강은 02-3 Before 결과 상자 하나뿐**(Before 결함 결과 — 몸통까지 들어간 값 3과 받은 글).
- 라벨 규칙: 모델을 부르지 않아 라벨의 값은 모두 서버·클라이언트가 주고받은 구조 값이고, 새 커널 두 번 셀별 출력 글 24/24 같음(A 20:07:54Z · B 20:08:13Z). 흔들림 확인(`02-probe.md`)은 모델 판단이 없어 두지 않았습니다. 라벨 숫자 0·1·2·3은 출력에 있음. 대괄호·따옴표·중괄호는 라벨에서 뺌(`{'type': 'string'}` → 「topic 칸 type string」, `{}` → 「비어 있음」).
- 차례: 새 커널 A(`run_section.sh`, 그림 첨부 단계에서 멈춤 — 02-1 PNG가 아직 없어서) → 사본 B → **이 설계표** → `.mmd` 넷·캡션 → `author_02.py --src-only` → `run_section.sh … --no-exec`(렌더·첨부·빌드) → 삽화. 01절의 [하] 기록(설계표를 렌더 뒤에 적음)과 달리 이번에는 규격 §5-2 차례대로입니다.
