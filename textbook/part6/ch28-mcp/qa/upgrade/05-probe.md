판단 규칙(결론에 쓸 수 있는 관찰):

- **입력 토큰 — 서비스가 센 값**: 조건마다 **5번 모두 같고**, 노트북 새 커널 두 번(A·B) 값이 서로 같고 흔들림 확인 값과도 같을 때만 결론·정리·복습·그림 라벨에 「흔들림 확인 다섯 번과 두 커널에서 모두 …」 한정어와 함께 씀. 조건 사이 차이(「도구 정의 몫」 = 도구를 알린 요청 − 도구 없는 요청, 직접 ↔ MCP 차이, 하나 ↔ 셋 차이)도 **그 차이를 이루는 두 조건이 모두 위 규칙을 채울 때만** 결론에. 한 조건이라도 흔들리면 그 조건의 입력 토큰과 그 조건이 든 차이는 결과 읽기 둘째 단락·b6 표·「확인할 점」·b7에만 「이번 실행에서는」으로 두고, 결론은 명세 글자 수(구조 값)로만 씀. `assert`는 걸지 않음.
- **흔들리는 값 — 결론·그림·캡션·정리·복습에 쓰지 않음**(결과 읽기 둘째 단락·b6 표·「확인할 점」·b7에만): 도구 호출 요청 이름·인자(모델이 고름 — `tool_choice` 없음) · 출력 토큰 · 답 글 · 예상 비용. 다섯 번 같아도 결론에 쓰지 않음.
- **그림 라벨 규칙**(뒤에서 넓히지 않음): 라벨에는 구조 값(도구 이름·명세 칸 이름·명세 글자 수·`additionalProperties`·참거짓·`convert_to_openai_tool`·`bind_tools`·`usage_metadata`·`input_tokens`)만. 입력 토큰 수·도구 정의 몫은 위 입력 토큰 규칙을 채운 조건만 넣음. 출력 토큰·도구 호출 요청·답 글·예상 비용은 라벨·캡션·alt에 넣지 않음. 모델 상자(보라)는 뒤 절반 그림에만.
