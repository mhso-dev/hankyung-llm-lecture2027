## 3. 반복 셀 모양·코드 관례

계약 값(함수 이름·칸 수·해시)은 `upgrade-contracts.md`, 근거·예시는 챕터 요약.

- **학습 순서** 예상 → 실행 → 출력 확인 → 비교 → 값 하나만 바꿔 다시(Ch1 01). **실습 절**은 부품 → 조립 함수 → 기록장 `print_report()`(도구 파일이 있는 챕터는 가져옴 — Ch3 06·Ch5 09) → 실행 1 → 값 하나 바꾼 실행 2 → `달라진 칸 수`.
- **준비 셀** `mkdtemp(prefix="chNN-MM-")` → `os.chdir()` → `os.listdir()`(출력의 `[사용자 폴더]`는 실행 도구가 가린 표시). **경로 셀**(Ch10~12 공통) `candidates = [".", "../../..", "../../../.."]` + `for`·`break` → `root_path`를 **묶음 맨 위·실습 폴더 맨 위·`notebooks` 세 자리**에서 확인.
- **앞에서 배운 함수는 도구 파일에서 가져옵니다(규격 §2-7, 2026-09-21 사용자 결정)** — 예전 규칙 「준비 셀 묶기 + 앞 절 함수를 같은 코드로 재정의」(Ch12 09절~Ch14)는 **없어졌습니다**. 실습 폴더 `notebooks/`에 도구 파일 하나(Part 2 `llm_tools.py`, Part 3·4 `rag_tools.py`, Ch3 `git_tools.py`)를 두고 준비 셀에서 `from … import …` 한 줄(알파벳 순). 함수를 **처음 가르친 절**은 노트북에 남기고, 도구 파일 판은 노트북 전역 이름 대신 **인자로 받습니다**(인자가 바뀌면 처음 가져오는 절에서 한 문장). 처음 가져오는 절의 고정 세 문장: 「앞에서 배운 함수는 `…_tools.py`에 모아 두었습니다. 파일을 열면 코드를 볼 수 있습니다. 노트북과 같은 폴더(`notebooks/`)에 있는 파일입니다.」 소절 전체가 앞 절 함수 정의뿐이면 인자 설명 소절로 남겨 절 번호를 지킵니다. 도구 파일로 챕터 전체 코드가 줄지 않으면 만들지 않습니다(Ch1·2·4·6·22). `os.chdir()`하는 노트북은 옮기기 전에 가져옵니다(Ch3).
- **키·모델 셀** `nbkit.key_and_model_cells()` = `KEY` → 규격 §3 모델 셀 → 실행일 결과 읽기(+ temperature 0 ≠ `do_sample=False`). Part 3은 `temperature=0, reasoning_effort="none"`, **답 모델을 안 부르는 절은 API 키 셀도 없음**(Ch10 01~05·Ch12 04). **메시지 목록**은 Ch7 02~·Ch8 `[("system", persona_text), ("developer", task_text), ("user", …)]`(틀 안 developer는 `convert_to_messages(...)[0]`, 튜플은 `ValueError`).
- **기록 한 줄** = 요청 한 번·설정 한 벌, 한국어 키 딕셔너리(모르는 값 `None`). 반복 요청은 `append`만 하고 끝난 뒤 한꺼번에 출력. **파일 쓰기**는 `"""…"""` + `with open(…, "w", encoding="utf-8")`, 도구 실행은 `subprocess.run([sys.executable, "-m", 모듈, …])`.
- **try/except**는 그 오류 이름만 받아 셀은 끝까지 실행하고 실제 프로그램은 멈추게 둔다고 적습니다(Ch2 05). **검사 함수**는 말·표시가 있는지만 봅니다(품질 점수 아님). **함수 셀**은 정의 셀(「출력이 없습니다」)과 호출 셀 분리, Before `…_before()`·After 끝 `assert`(모델 답에는 금지 → §6), 본문 10줄·셀 3~12줄(15 상한).

## 6. 확인된 사실과 태도

- **temperature 0은 「같은 답」이 아닙니다.** 로컬은 뽑기를 켠 호출에서만 temperature를 쓰고 켠 채 `0.0`이면 `ValueError`, 「0」은 `do_sample=False` — **API `temperature=0`을 `do_sample=False`와 같다고 쓰지 않습니다.** 서비스 모델은 temperature 0에도 답이 달라졌고(Ch8 06 목록 104 vs 64, 입력 토큰 수는 같음), 뽑기를 끈 로컬 답만 같은 기기·버전에서 글자까지 같았습니다.
- **소스로만 확인한 동작은 출력 근거와 갈라 적고**(Ch10 07·Ch12 07) 설치판 기본값이 서비스 모델에도 있다고 단정하지 않습니다. 지시 효과도 일반화하지 않습니다(Ch5 05·07·09).
- **천장 지표와 「이 조건에서는 가를 수 없다」**(Ch11 §3 → Ch12 §7) 천장에 닿은 값도 **표에서 빼지 않고 그대로 싣고** 그 문장을 b6·b7·복습에 적습니다. Ch11 — 문서 17건이라 자리 50 재현율 `1.0`, 개발 15문항이 모두 정답 한 개라 자리 5 정밀도 최댓값 **0.2**(실측 `0.173`). Ch12 — 부모 6건이라 부모 재현율 자리 1~3이 모두 `1.0`, 12절 36줄 `precision_at_5` 모두 `0.2`. **가르는 값을 따로**: 문서 청크 정밀도(08), 고유 부모 수·조각 수(09), `chunk_precision_at_5`·`ndcg_at_5`(12).
- **흔들리는 값**(임베딩이 호출마다 아주 조금 달라짐) 검색 점수 넷째 자리·받은 개수 13~16·거리 셋째 자리 아래·반복 탐색 줄 수 0~3·문서 청크 정밀도 `0.84↔0.853`·조각 수 평균 `600↔596`·정밀도 `0.72↔0.76`·손잡이별 평균 셋째 자리. **본문 표와 「확인할 점」에는 출력 그대로, 그림 라벨·캡션·정리 세 줄에서는 뺍니다.** 안 흔들린 값 — 입력 가용분 3400·고유 부모 수·재현율·정답 자리·모델이 쓴 답 문장.
- **하지 않는 것** 모델 답에 `assert`(규격 §3, Part 3 전체 0건) · 재실행해 마음에 드는 출력 고르기(Ch8 07·Ch12 09) · 설명만 고칠 때 재실행(Ch6) · 「합치면 좋아진다」·「어느 방법이 낫다」(Ch12) · 재지 않은 시간·속도 단정(**검색 시간은 한 번도 재지 않았음**) · 답 정확성 판정 · 비용·시간 순위.
